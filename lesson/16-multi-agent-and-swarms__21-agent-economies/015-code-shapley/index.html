Пишем shapley

Запусти shapley для трёх агентов и представь, что она вернула одно число. Кому оно принадлежит? Здесь результат должен сохранять вклад каждого участника отдельно: например, словарь, где ключ — агент, а значение — его средний предельный вклад.

Собери функцию из уже знакомых деталей. Она получает список агентов и функцию ценности v, создаёт для каждого агента накопитель с нулём, а затем перебирает все возможные порядки. Для каждого порядка вызови marginal_contributions из шага 13: помощник уже умеет последовательно строить коалицию и возвращать вклады участников.

Теперь главное место, где легко ошибиться. Вклад нужно прибавлять накопителю того агента, которому он принадлежит, независимо от его позиции в текущем порядке. После обработки всех порядков раздели каждый накопитель на количество рассмотренных порядков. Именно усреднение превращает набор вкладов из отдельных сценариев в значения Шепли, описанные в шаге 14.

Проверь результат на маленьком наборе из трёх агентов: для него можно мысленно проследить каждый порядок. Посмотри, что в ответе присутствуют все агенты, а их значения не зависят от порядка исходного списка. Частая ошибка — делить накопитель внутри цикла: тогда ранние суммы многократно уменьшаются, и среднее искажается. Сначала собери полные суммы, потом дели.

🎒 На пальцах. Редакция готовит выпуск газеты, а секретарь раскладывает на столе все варианты очередности работы автора, фотографа и верстальщика. После каждого варианта он записывает прибавку каждого участника в его личную колонку. Лишь когда рассмотрены все варианты, секретарь делит итог каждой колонки на их количество. shapley делает ровно такую бухгалтерию.
