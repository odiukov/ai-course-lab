Воспроизводим DDP без процессов

Ты убираешь процессы и сеть, но хочешь получить то же обновление модели. Простое решение — обучить модель по очереди на четырёх микробатчах — неожиданно ломается, если после каждого вызвать optim.step(): параметры изменятся четыре раза, тогда как DDP меняет их один раз после общей синхронизации.

Дополни reference_single_process, превратив один шаг обучения в последовательный обход данных всех рангов. В начале шага обнули градиенты один раз. Затем для каждого воображаемого ранга выбери его срез общего набора данных, выполни прямой проход и добавь вклад через backward(). Градиенты в PyTorch накапливаются, поэтому повторно обнулять их внутри этого обхода нельзя.

Каждый локальный loss нужно разделить на world_size перед backward(). Тогда накопленная сумма станет тем самым средним, которое DDP получает после правил из шага 4 и шага 5. optim.step() вызывается только после обхода всех рангов.

Для истории сохрани исходный, не уменьшенный loss первого ранга: если ты вызываешь item() уже после деления, верни масштаб умножением на world_size. После последнего шага вычисли общую норму параметров и верни её вместе со списком loss.

Проследи за тремя границами: один zero_grad, несколько backward, один step. Именно они превращают последовательный цикл в независимый эталон из шага 8, а не в другой способ обучения.

🎒 На пальцах. Представь фотолабораторию, где четыре кадра дают поправки к яркости одного снимка. Лаборант записывает четверть каждой поправки на общий лист и проявляет фотографию только после четвёртого кадра. Если проявлять после каждой записи, следующий кадр уже будет исправлять другую фотографию. Последовательность та же, но результат — нет.

Практика: функция reference_single_process. Упражнение к этому уроку не выложено.
