Пишем kv_cache_gb

Ты задаёшь контекст 4K и получаешь небольшой KV-кэш. Меняешь одно число на 32K — и память внезапно заканчивается. Теперь этот пересчёт из шага 25 нужно поручить функции kv_cache_gb, чтобы сравнивать конфигурации без ручной арифметики.

Пусть функция принимает число слоёв, число KV-голов, размер одной головы, длину контекста и количество бит на элемент. Она должна учесть обе части кэша: key и value, поэтому в произведении появляется множитель 2. Затем переведи биты в байты делением на 8, а итоговый объём — в гигабайты делением на 10910^9109.

Обрати внимание на частую ошибку: число KV-голов не всегда совпадает с числом обычных attention-голов. При GQA несколько голов внимания используют общие key и value. Если подставить вместо kv_heads все attention-головы, функция заметно завысит память.

Проверь результат в трёх направлениях: контекст вдвое длиннее должен дать вдвое больший кэш; переход с 16 до 8 бит должен уменьшить его вдвое; нулевой контекст должен дать ноль. Здесь предполагаем batch size 1 — несколько одновременных последовательностей потребуют отдельного множителя.

Так функция превращает длину контекста из красивой характеристики модели в конкретный счёт за RAM.

🎒 На пальцах. Представь архив с двумя папками на каждый токен: в одну кладут key, в другую value. На каждом этаже модели появляется своя пара папок. Ты удлиняешь разговор — архивист добавляет одинаковое число папок на каждом этаже. А если листы хранить в 8 бит вместо 16, каждая папка становится вдвое тоньше.

Практика: kv_cache_gb

Здесь только функция этого шага — остальной файл упражнения подставится при запуске. Код выполняется прямо в твоём браузере: первый запуск качает Python, примерно двенадцать мегабайт, дальше из кэша.
