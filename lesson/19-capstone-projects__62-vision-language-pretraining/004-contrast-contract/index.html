Превращаем батч в задачу классификации

Возьми четыре пары из корпуса, собранного на шаге 3, и перемешай подписи. Для первой картинки модель выдаёт четыре оценки близости. Но что считать правильным ответом: «кот», «велосипед» или какое-то другое понятие?

Здесь классы — не категории объектов, а позиции внутри батча. Если картинки и их подписи уложены в одинаковом порядке, то для картинки с индексом 0 правильный класс — подпись 0, для картинки 1 — подпись 1, и так далее. Поэтому целевые ответы для батча из четырёх пар выглядят как позиции 0, 1, 2, 3.

Каждая строка матрицы оценок становится отдельной задачей классификации: среди всех подписей нужно выбрать одну совпадающую. Оценка на диагонали относится к правильному классу, остальные оценки играют роль неправильных вариантов — негативов. Отдельно придумывать и размечать их не приходится: другие элементы того же батча уже создают выбор.

Затем взгляд разворачивается. Теперь каждая подпись выбирает свою картинку среди четырёх кандидатов. Получаются две классификации над одной матрицей: по строкам и по столбцам. Их потери объединяются по контракту из шага 2. Значит, батч пар превращается в набор взаимных вопросов: «какой элемент с другой стороны мой?»

🎒 На пальцах. Представь гардероб с четырьмя пальто и четырьмя номерками. Для каждого пальто ты выбираешь его номерок: правильная пара стоит на той же позиции, остальные три — отвлекающие варианты. Потом проверяешь наоборот, какое пальто принадлежит каждому номерку. Классы здесь не «зимнее» и «летнее», а просто четыре возможных места в текущей выдаче.
