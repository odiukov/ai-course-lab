Пишем accumulate_stream

У тебя на руках уже есть буфер на каждый id из шага 28 и осторожный try_parse_arguments из шага 21. Теперь их надо свести в одну функцию, которая переваривает весь провод от начала до конца.

accumulate_stream получает поток нормализованных событий и возвращает готовые вызовы: для каждого id — имя инструмента и полная строка аргументов. Внутри всё держится на одном словаре: ключ — id вызова, значение — то, что по нему уже накопилось.

Первая засада ждёт сразу. Событие с id и name приходит один раз, в самом начале вызова, а дальше по проводу летят обрывки вроде {"ci, ty": "Tok, yo"} — и в них id часто уже нет, есть только index. Значит, тебе нужна вторая табличка: index → id. Пришёл первый кусок — запомнил связь; пришёл обрывок с одним index — нашёл по нему id и дописал в нужный буфер.

Дописал — именно дописал, конкатенацией, в порядке прибытия. Никакой сортировки, никакой сборки «по смыслу»: порядок кусков внутри одного вызова — это единственное, что гарантирует стрим.

И ни одного json.loads до сигнала конца. Разбор — только когда провайдер сказал, что вызов закончен (шаг 23).

На что смотреть при проверке: два вызова get_weather с разными id не должны слиться в один буфер (вспомни номерки из шага 4); пустой обрывок "" не должен ломать накопление; и поток, где JSON становится валидным на середине, обязан дождаться конца.

🎒 На пальцах. Бариста подписывает стаканы именами и льёт в них по очереди, малыми порциями: чуть в «Толю», чуть в «Мишу», снова в «Толю». Стакан без подписи — катастрофа: не поймёшь, куда лить. И пока не сказали «готово», пить нельзя: на дне может лежать только половина эспрессо. Подпись — это id, порции — обрывки, «готово» — сигнал конца.
