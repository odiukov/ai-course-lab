Пишем publication_rate

Ты вызываешь publication_rate(180, 527) и получаешь число около 0.34. Оно выглядит непривычно: почему не 34 и не 2.93? Смысл показателя уже разобран в шаге 6: здесь нужны публикации на одного исследователя, поэтому порядок деления менять нельзя.

Функция принимает два числа:

  • publications — количество опубликованных статей;
  • researchers — количество исследователей.

Вернуть она должна результат деления первого числа на второе. Не умножай его на 100: это не процент исследователей с публикациями. По имеющимся данным мы вообще не знаем, сколько разных людей стали авторами этих 180 работ. Результат 0.34 означает лишь среднее количество публикаций на одного участника.

Не округляй значение внутри функции, если задание этого отдельно не требует. Округление удобно для текста на экране, но тест может сравнивать более точный результат. Проследи также, чтобы функция именно возвращала число через return, а не только печатала его: напечатанное значение человек увидит, но другая часть программы использовать его не сможет.

Для самопроверки попробуй мысленно подставить одинаковые числа публикаций и исследователей. Ставка должна получиться равной единице. Если выходит другое число, проверь порядок аргументов и операцию.

🎒 На пальцах. Представь пункт проката с 180 шлемами на 527 велосипедов. Ты считаешь не долю велосипедов, которым точно достанется шлем, а среднее число шлемов на один велосипед: примерно 0.34. Функция делает ровно такой расчёт для статей и исследователей — берёт общий выпуск и распределяет его по размеру группы.

Практика: publication_rate

Здесь только функция этого шага — остальной файл упражнения подставится при запуске. Код выполняется прямо в твоём браузере: первый запуск качает Python, примерно двенадцать мегабайт, дальше из кэша.
