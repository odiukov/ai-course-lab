Пишем decode_naive

Открой пустой файл: decode_naive(prompt, n_steps=100). Ей нужно выдать сто токенов подряд — и при этом честно сыграть роль декодера, который ничего не запоминает между шагами.

Внутри — обычный цикл. На шаге номер t у тебя на руках префикс из t токенов. Функция прогоняет весь этот префикс через проекции и получает K и V для каждого из t токенов заново. Потом зовёт attention_full из шага 8, берёт из выхода последнюю строку — тот самый вектор для последнего токена — превращает её в следующий токен и дописывает в конец. И на следующем витке всё повторяется, только префикс уже длиной t+1.

Теперь главное, ради чего шаг вообще пишется: счётчик. Заведи переменную и на каждом витке прибавляй к ней t — столько токенов ты только что спроецировал. Не «одну проекцию за вызов», а именно число токенов: считать надо работу, а не количество обращений к функции.

Что должно получиться на выходе: список из ста токенов и число 5050. Это та же сумма, что в шаге 2, только до ста, а не до 4096.

Две ловушки. Первая — соблазн вынести проекции за цикл: тогда ты случайно напишешь кэш и получишь 100 вместо 5050. Вторая — веса. Зафиксируй матрицы проекций и seed один раз снаружи: без этого сравнить выход с кэшированной версией потом будет нечем.

Запусти. Если счётчик показал 5050 — ты воспроизвёл ровно ту работу, которую мы собираемся выбросить.

🎒 На пальцах. Ксерокс в офисе. Тебе нужна папка из ста страниц, но копир умеет только одно: принять папку целиком и выплюнуть копию. Добавил страницу — копируй все двадцать заново, потом все двадцать одну. К сотой странице через валик прошло 5050 листов, а новых среди них было ровно сто. Счётчик в твоей функции считает именно листы, а не нажатия на кнопку.

Практика: decode_naive

Здесь только функция этого шага — остальной файл упражнения подставится при запуске. Код выполняется прямо в твоём браузере: первый запуск качает Python, примерно двенадцать мегабайт, дальше из кэша.
