Проверка: забыли user_id — это баг ранжирования?

Ты дописал hybrid_search в шаге 28 и покрутил веса в шаге 29 — тебе уже привычно объяснять странный top-3 через w_recency и w_importance. Здесь эта привычка ломается: когда в выдаче Алисы всплыл факт про проект Боба, крутить веса бесполезно. Запись попала в выборку до всякого ранжирования, потому что user_id в фильтре не было.

Проверь себя на двух вещах: умеешь ли ты отличать «плохо отсортировано» от «взято лишнее», и выбираешь ли область видимости по времени жизни факта — user между сессиями, session внутри треда, agent под конкретный экземпляр.

Обычно спотыкаются там, где хочется положить факт сразу во все области «на всякий случай». Это не запас надёжности, а способ вынести приватное за пределы того, кому оно принадлежит.

  2. Пользователь в текущем чате сказал: «пока обсуждаем только черновик, финальную версию не трогай». Куда логичнее это положить?
