Пишем ui_resource_contents

Хост прислал resources/read с одним аргументом: ui://notes/timeline. У тебя в переменной лежит строка с готовым HTML временной шкалы — весь бандл, от <!doctype html> до закрывающего тега. Что вернуть?

Соблазн — вернуть саму строку. Но хост не умеет принимать голый HTML: он не знает, чей это ресурс и как это трактовать. Поэтому твоя ui_resource_contents собирает конверт.

Внутри конверта — три поля. Первое: uri, и это ровно тот адрес, который у тебя запросили, буква в букву. Не «похожий», не нормализованный, не с добавленным слэшем. Второе: mimeType — та самая строка с профилем из шага 6, целиком, вместе с частью после точки с запятой; потеряешь профиль — хост нарисует обычную страницу без песочницы или откажется рисовать вовсе. Третье: text с HTML.

И эти три поля лежат не сами по себе, а внутри списка contents — списка даже тогда, когда элемент один. Формат рассчитан на несколько частей сразу, так что одиночный ресурс всё равно приходит списком из одного элемента.

Ещё одна вещь: прежде чем что-то собирать, прогони запрошенный URI через is_ui_uri из шага 5. Пришло file:///etc/passwd — это не твоя ветка кода, отдавать HTML-конверт на такой адрес нельзя.

Проверяй результат на глаз так: если из ответа выкинуть text, по оставшимся двум полям всё ещё должно быть понятно, что и для кого приехало.

🎒 На пальцах. Как ответ с цитатой в мессенджере. Ты задал три вопроса подряд, приходит «да» — и попробуй угадать, на который. А с процитированной строкой сверху всё сходится мгновенно. Повторённый uri в конверте — та же цитата: хост запросил несколько ресурсов, ответы вернулись, и ему не надо читать HTML, чтобы понять, где чей.

Практика: ui_resource_contents

Здесь только функция этого шага — остальной файл упражнения подставится при запуске. Код выполняется прямо в твоём браузере: первый запуск качает Python, примерно двенадцать мегабайт, дальше из кэша.
