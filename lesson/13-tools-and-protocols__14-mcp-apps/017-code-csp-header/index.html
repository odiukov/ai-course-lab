Пишем csp_header

Словарь из шага 12 — {"defaultSrc": "'self'", "scriptSrc": "'self' 'unsafe-inline'", "connectSrc": "'self'"} — удобен серверу: обычный JSON, ключи в camelCase, как везде в MCP. А браузер такого не понимает. Ему нужна одна строка в заголовке Content-Security-Policy, и в ней директивы пишутся через дефис: default-src, script-src, connect-src, разделены ; .

Значит, между твоим словарём и iframe нужен переводчик. Это и есть csp_header: на вход словарь, на выход одна строка вида default-src 'self'; script-src 'self' 'unsafe-inline'; connect-src 'self'.

Что тут легко испортить?

Во-первых, ключи. scriptSrc надо превратить в script-src — заглавная буква становится дефисом с маленькой. Соблазн зашить три ветки if велик, но лучше одно правило: тогда imgSrc или styleSrc заработают сами, без правки функции.

Во-вторых, отсутствующие ключи. Сервер может отдать только defaultSrc. Строка script-src None для браузера — мусор, он такую директиву отбросит целиком; пустое значение connect-src — тоже. Пропускай то, чего нет, и то, что пустое.

В-третьих, значения не трогай. Кавычки в 'self' и 'unsafe-inline' — часть синтаксиса CSP, а не оформление Python-строки. Снимешь их — директива перестанет работать.

И держи порядок директив предсказуемым: одинаковый вход должен давать посимвольно одинаковую строку, иначе тест на неё не напишешь.

🎒 На пальцах. Ты говоришь официанту: «суп без соли, стейк средний, воду без газа». Он не несёт эту фразу на кухню — он пишет на бланке короткими пометками в одну строку, в том порядке, который кухня читает. Смысл тот же, форма другая. csp_header — этот бланк: три твоих пожелания превращаются в одну строку на языке браузера, и если пометку смазать, повар просто её проигнорирует.
