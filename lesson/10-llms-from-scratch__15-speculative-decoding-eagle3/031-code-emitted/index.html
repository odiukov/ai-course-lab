Пишем expected_emitted

У тебя уже есть формула из шага 30, и она просится в код почти дословно: одна строка, две переменные. Напиши функцию expected_emitted(alpha, n), которая по доле принятия и длине черновика возвращает ожидаемое число токенов, выходящих из одного прохода verifier.

Прогони её на паре, которую ты уже считал руками: alpha = 0.9, n = 5 должны дать примерно 4.69. Если получилось 4.69 — арифметика собрана верно.

А теперь подставь alpha = 1.0.

Калькулятор отвечает делением на ноль: в знаменателе стоит 1−α1 - \alpha1−α, и при идеальном черновике он обнуляется. Но сама ситуация-то не бессмысленная — наоборот, она самая приятная: черновик угадывает каждый токен, принимаются все n штук плюс бонусный. Ответ известен заранее, это n + 1. Формула ломается не потому, что мир сломался, а потому что короткая запись суммы 1+α+⋯+αN1 + \alpha + \dots + \alpha^N1+α+⋯+αN через дробь работает только при α≠1\alpha \neq 1α=1. Значит, в функции нужна отдельная ветка на этот случай.

На что ещё посмотреть, когда функция готова. При alpha = 0 должна выйти ровно 1: черновик отвергается сразу, остаётся один токен от verifier. Результат никогда не должен превышать n + 1 — больше просто неоткуда взяться. И увеличивай n при фиксированном alpha = 0.8: числа растут, но всё медленнее, упираясь в 5. Это и есть предел, за которым удлинять черновик уже нечем.

Ветка alpha == 1 — не костыль, а место, где формула передаёт слово прямому счёту.

🎒 На пальцах. Кассир считает пачку купюр разного номинала по хитрой формуле — она экономит время. Но если в пачке шесть одинаковых сотен, он не лезет в формулу, а умножает: 6 × 100. Так же и здесь: при alpha = 1 все шесть слагаемых равны единице, и короткая запись через дробь просто не нужна — сумма считается взглядом.

Практика: expected_emitted

Здесь только функция этого шага — остальной файл упражнения подставится при запуске. Код выполняется прямо в твоём браузере: первый запуск качает Python, примерно двенадцать мегабайт, дальше из кэша.
