Пишем batching_steps

Перед тобой четыре запроса: им осталось сгенерировать 2, 6, 1 и 4 токена, а одновременно модель обслуживает только два. На шаге 37 ты спроектировал счётчик; теперь преврати его в функцию batching_steps.

Функция должна получить запросы и размер батча, а затем вернуть число итераций decode для двух стратегий. Для статического батчинга набирай очередную группу и держи её до завершения самого длинного ответа. Освободившиеся раньше места повторно не используются. Только после окончания всей группы можно брать следующую.

Для continuous batching поведение другое: на каждой итерации каждый активный запрос получает ровно один токен. Завершённые запросы удаляются, а свободные места перед следующей итерацией заполняются ожидающими. Если у запросов заданы моменты прибытия, не запускай их раньше времени; когда активных запросов нет, счётчик должен перейти к ближайшему прибытию, а не крутить пустой цикл.

Следи за тремя частыми ошибками: не считай отдельный шаг для уже завершённого запроса, не добавляй новый запрос посреди текущей итерации и не изменяй исходные объекты так, чтобы второй запуск получил их уже завершёнными. Для сравнения стратегий используй независимые копии состояния.

Проверь функцию сначала на одинаковых длинах, а затем на смеси коротких и длинных ответов. Именно второй случай покажет, освобождаются ли места вовремя.

🎒 На пальцах. Представь две кабинки фотостудии. При статическом расписании новая пара входит только после того, как оба посетителя закончили, даже если одному требовалась минута, а другому — десять. При continuous расписании освободившуюся кабинку сразу занимает следующий человек. batching_steps считает не фотографии, а минуты, за которые закончится вся очередь.

Практика: batching_steps

Здесь только функция этого шага — остальной файл упражнения подставится при запуске. Код выполняется прямо в твоём браузере: первый запуск качает Python, примерно двенадцать мегабайт, дальше из кэша.
