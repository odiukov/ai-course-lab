Проверяем контракт целиком

Дальше транспорт будет показывать реестр клиенту модели, а диспетчер — передавать вызовы инструментам. Здесь особенно легко спутать два разных доверия: корректность самой схемы проверяется при регистрации, а соответствие аргументов этой схеме — при вызове. Для вложенных данных важны рекурсивный проход, проверка каждого элемента массива и точный путь ошибки из шагов 8–11.

🎒 На пальцах. Представь прокат велосипедов перед открытием маршрута. Сначала сотрудник проверяет, правильно ли заполнены карточки моделей и не заменяет ли новая карточка старую без разрешения. Позже перед каждой выдачей он сверяет конкретный велосипед с его карточкой, включая каждую деталь комплекта. Хороший реестр так же разделяет исправность правил и проверку конкретного вызова.

  1. В реестр пытаются добавить инструмент с неправильно устроенной схемой аргументов. Когда должна обнаружиться ошибка?

  2. Имя инструмента уже занято. Какое поведение сохраняет контракт реестра явным?

  3. В массиве из четырёх объектов неверное поле находится в третьем элементе. Что должен сделать валидатор?

  4. Объект содержит все обязательные поля и ещё одно поле, которого нет в properties. Что произойдёт в рамках этого урока?
