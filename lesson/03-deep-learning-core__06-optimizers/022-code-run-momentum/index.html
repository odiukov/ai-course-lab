Пишем run_momentum

Ты запускаешь run_sgd и run_momentum из одной точки, но траектории получаются почти одинаковыми. Первая подозреваемая — скорость: если создавать её заново на каждой итерации, momentum каждый раз теряет накопленную память и не успевает разогнаться.

Собери run_momentum по каркасу функции run_sgd из шага 15. В начале создай текущую точку, список траектории и отдельную скорость для каждой координаты. Обе скорости должны начинаться с нуля — до первого градиента у оптимизатора ещё нет истории движения.

Затем на каждой итерации:

  1. получи шумные градиенты той же функцией noisy_grad, которую ты написал в шаге 12;
  2. передай текущие координаты, скорости, градиенты, lr и beta в momentum_step из шага 18;
  3. сохрани новую точку в траекторию.

Скорости создай до цикла и обновляй внутри него. Если перенести их создание в цикл, код выполнится без ошибки, но память momentum исчезнет.

Следи и за честностью сравнения из шага 21: начальная точка, число шагов и последовательность шума должны оставаться теми же, что у SGD. Меняется только способ обновления координат. В результате функция должна вернуть всю траекторию, включая начальную точку: для steps=20 в ней будет 21 позиция.

🎒 На пальцах. Ты снимаешь маршрут тележки камерой: первый кадр сделан до движения, остальные — после каждого толчка. Рядом лежит карточка с текущей скоростью. Карточку не выбрасывают после кадра, иначе каждый толчок снова будет первым. Поэтому траектория растёт внутри цикла, а память о скорости живёт от начала запуска до его конца.

Практика: run_momentum

Здесь только функция этого шага — остальной файл упражнения подставится при запуске. Код выполняется прямо в твоём браузере: первый запуск качает Python, примерно двенадцать мегабайт, дальше из кэша.
