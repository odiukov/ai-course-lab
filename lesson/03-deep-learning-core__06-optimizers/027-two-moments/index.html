Adam объединяет направление momentum и масштаб RMSProp

Представь электровелосипед на извилистой дороге. Тебе мало знать, куда поворачивать: ещё нужно выбрать передачу. Если учитывать только направление прошлых поворотов, можно набрать слишком большую скорость. Если смотреть только на крутизну дороги, легко потерять общее направление.

Adam совмещает эти два решения. Для каждого параметра он хранит две отдельные истории:

  • mtm_tmt​ продолжает идею momentum из шага 17: сглаживает недавние градиенты и показывает устойчивое направление движения;
  • vtv_tvt​ продолжает идею RMSProp из шага 24: сглаживает квадраты градиентов и оценивает их типичный масштаб.

Затем Adam строит обновление вокруг отношения

mtvt+ε.\frac{m_t}{\sqrt{v_t}+\varepsilon}.vt​​+εmt​​.

В числителе mtm_tmt​ задаёт направление с учётом накопленной истории. Знаменатель vt\sqrt{v_t}vt​​ регулирует длину шага отдельно для каждого параметра. Маленькая константа ε\varepsilonε не даёт делить на ноль, если накопленный масштаб почти исчез.

Посмотри, как разделяются роли. Если градиенты долго указывают примерно в одну сторону, mtm_tmt​ поддерживает это движение, даже когда отдельное измерение шумит. Если у другого параметра градиенты обычно огромны, большой vtv_tvt​ уменьшает его обновление. Поэтому один параметр не захватывает всё обучение только из-за более крупных чисел.

Adam не выбирает между momentum и RMSProp: первое отвечает на вопрос «куда двигаться?», второе — «насколько сильно двигаться здесь?».

🎒 На пальцах. На электровелосипеде руль помнит общий изгиб дороги, а автоматическая передача реагирует на крутизну именно текущего участка. Один механизм удерживает курс, другой не даёт слишком резко разгоняться. Adam так же берёт направление из накопленных градиентов, а допустимый масштаб шага — из накопленных квадратов.
