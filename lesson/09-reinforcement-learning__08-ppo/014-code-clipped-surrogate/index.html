Пишем clipped_surrogate

У тебя уже есть ratio, advantage и ширина коридора eps. Осталось собрать из них одно число — вклад конкретного перехода в PPO-цель. Кажется, что достаточно сначала выбрать меньший из обычного и обрезанного ratio, а затем умножить его на advantage. Но для отрицательного advantage такой порядок даст неверный результат: умножение на отрицательное число меняет порядок величин.

Поэтому в clipped_surrogate должны появиться две полноценные ветви из шага 10:

def clipped_surrogate(ratio, advantage, eps):
    clipped_ratio = ...  # ограничь ratio коридором
    ordinary = ...       # обычная ветвь
    clipped = ...        # ветвь с ограниченным ratio
    return ...           # выбери безопасную ветвь

Сначала ограничь только ratio диапазоном от 1 - eps до 1 + eps. Затем отдельно умножь исходный и ограниченный варианты на один и тот же advantage. Лишь после этого выбери меньшее из двух произведений.

Обрати внимание: функция не должна обрезать сам advantage и не должна ограничивать уже готовое произведение. А почему именно минимум корректно работает и с отрицательным advantage, ты разобрал в шаге 13.

На выходе верни одно число для одного перехода. Усреднение по мини-батчу будет происходить снаружи этой функции.

🎒 На пальцах. Представь два ценника на одну поездку: первый рассчитан по текущему тарифу, второй — по тарифу с ограничителем. Сначала каждый тариф превращают в итоговую стоимость поездки, учитывая скидку или доплату, и только потом выбирают меньшую сумму. Если сравнить одни тарифы до применения отрицательной скидки, победитель может поменяться — именно поэтому порядок действий здесь важен.
