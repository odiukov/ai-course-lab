Module задаёт общий интерфейс для разных слоёв

Ты собираешь модель из разных деталей: сначала Linear меняет числа, затем ReLU отсекает часть значений, а Dropout временно отключает некоторые из них. Внутри эти слои устроены по-разному. Если для каждого нужен особый способ запуска, фреймворку придётся постоянно спрашивать: «Это линейный слой? Активация? Dropout?» С добавлением нового типа появится ещё одно исключение.

Здесь и появляется Module. Это общая основа, от которой наследуются разные слои. Она задаёт интерфейс — согласованный набор действий, доступных у каждого модуля. Интерфейс похож на одинаковую форму разъёма: он говорит не о внутреннем устройстве прибора, а о том, как с ним взаимодействовать.

Поэтому фреймворк может работать с цепочкой модулей единообразно: передать данные первому, получить результат, передать следующему. Ему не требуется знать, какие вычисления спрятаны внутри каждого звена. А новый слой достаточно сделать модулем — и он сможет занять место в той же цепочке без нового набора правил.

Важно: общий интерфейс не делает слои одинаковыми. Linear может хранить обучаемые веса, а ReLU — просто преобразовывать значения. Совпадает лишь способ обращения к ним. Именно это превращает набор разных компонентов из шага 3 в детали, которые действительно можно свободно соединять.

🎒 На пальцах. Представь фотоаппарат со стандартным креплением для объективов. Широкоугольный объектив, портретный и телеобъектив дают разные изображения и устроены по-разному, но ставятся на камеру одним движением. Крепление не определяет, что объектив увидит; оно лишь гарантирует, что камера сможет с ним работать. Module играет роль такого крепления для слоёв.
