Кодируем смысл метрики в знак относительного улучшения

Ты открываешь отчёт новой модели: accuracy выросла с 0,80 до 0,84, а loss — с 0,80 до 0,84. В обеих строках кандидат прибавил 0,04. Но выбрать один вердикт по такой разнице нельзя: для accuracy рост хорош, для loss — плох.

Значит, оценщику мало знать величину изменения. Поле direction задаёт смысл движения: higher_is_better означает «больше — лучше», а lower_is_better — «меньше — лучше». Этот смысл кодируется знаком относительного улучшения:

I=c−b∣b∣I=\frac{c-b}{|b|}I=∣b∣c−b​

для метрик, где рост полезен, и

I=b−c∣b∣I=\frac{b-c}{|b|}I=∣b∣b−c​

для метрик, где полезно снижение. Здесь III — улучшение, bbb — значение baseline, ccc — значение candidate, а ∣b∣|b|∣b∣ задаёт масштаб относительно базы.

Для accuracy получаем 0,050{,}050,05, то есть улучшение на 5%. Для loss та же пара чисел даёт −0,05-0{,}05−0,05: кандидат стал хуже. Так знак приобретает единый смысл для любых метрик: плюс всегда поддерживает кандидата, минус всегда поддерживает baseline.

Это не заменяет парный анализ из шагов 6–7: он отвечает, насколько устойчиво наблюдаемое различие. Здесь решается другой вопрос — в какую сторону это различие читать.

🎒 На пальцах. Представь спортивное табло с прыжком в длину и бегом на сто метров. В прыжке прибавить число хорошо, а в беге прибавить секунды плохо. Судья переводит оба результата в одну стрелку: вперёд — плюс, назад — минус. Поэтому дальше можно смотреть на знак, не вспоминая каждый раз правила конкретной дисциплины.
