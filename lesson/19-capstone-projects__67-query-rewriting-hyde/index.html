Query Rewriting Hyde

12 шагов

Начать урок

  1. 1Собираем офлайн-шов: LLM переписывает запрос, общий ретривер ищет, RRF объединяет выдачи
  2. 2Проверяем границу переписывателя и ретривера
  3. 3Генерируем гипотезу детерминированно: точный запрос берётся из таблицы, неизвестный получает синонимический fallback, регистр и конечный вопросительный знак не меняют результат
  4. 4HyDE меняет плотный поисковый вектор, но сохраняет исходный текст как отдельный лексический сигнал
  5. 5Формируем результат HyDE: гипотеза заполнена, исходный запрос остаётся единственным rewrite, а неизвестный запрос безопасно проходит через fallback мока
  6. 6Multi-query расширяет покрытие формулировок: исходный запрос остаётся контрольной веткой, перефразировки дают дополнительные независимые выдачи
  7. 7Собираем multi-query: исходник всегда первый, за ним не более N перефразировок, а при N = 0 сохраняется одна исходная поисковая ветка
  8. 8Декомпозиция разветвляет только многотемный вопрос; атомарный запрос обязан остаться одним самостоятельно отвечаемым вопросом
  9. 9Возвращаем подвопросы без добавления исходника: известная многотемная фикстура делится по таблице, fallback — по and, атомарный запрос остаётся единственным
  10. 10Один исполнитель обслуживает все стратегии: каждая ветка ищется отдельно, HyDE использует готовый вектор, затем списки сходятся в RRF и общий top-K
  11. 11Замыкаем шов поиска: исполняем все rewrites, для HyDE добавляем векторную ветку с исходным BM25-текстом, сливаем RRF и строго ограничиваем k_out; пустой набор веток даёт пустую выдачу
  12. 12Выбираем HyDE, multi-query или декомпозицию по типу разрыва и разбираем скрытые режимы отказа
