Пишем gae_advantages

Ты подаёшь в gae_advantages три награды и три оценки критика, а на выходе получаешь числа в обратном порядке. Ошибка возникает не в математике, а в направлении обхода: преимущество раннего действия зависит от уже посчитанного будущего.

Напиши функцию gae_advantages(rewards, values, gamma=0.99, lam=0.95, last_value=0.0). Здесь rewards[t] — награда, полученная после действия на позиции t, а values[t] — оценка состояния до этого действия. Для последнего перехода следующей оценки в values уже нет, поэтому используй last_value — bootstrap с конца rollout, как в шаге 17.

Создай список преимуществ той же длины, что и rewards, и заведи аккумулятор будущего преимущества, сначала равный нулю. Затем двигайся от последнего индекса к первому. На каждой позиции:

  1. выбери следующую оценку: соседний элемент values или last_value;
  2. вычисли TD residual по правилу из шага 19;
  3. добавь к нему приглушённый аккумулятор будущего согласно рекурсии из шага 25;
  4. сохрани результат именно по текущему индексу.

После обратного прохода построй returns: для каждой позиции сложи найденное преимущество с соответствующим value. Функция должна вернуть пару (advantages, returns).

Проверь себя на простом случае: при rewards = [1, 1, 1], нулевых values, last_value = 0, gamma = 1 и lam = 0.5 преимущества должны получиться примерно [1.75, 1.5, 1.0]. Если вышло наоборот, ты правильно посчитал числа, но неверно разложил их по временным позициям.

🎒 На пальцах. Представь монтаж трёх хлопков с затухающим эхом. Последний хлопок получает только собственное эхо. Средний подхватывает часть уже обработанного последнего, а первый — часть всего хвоста после него. Поэтому монтажёр идёт с конца записи, но сохраняет результат на исходных местах: звук считается назад, а воспроизводится вперёд.
