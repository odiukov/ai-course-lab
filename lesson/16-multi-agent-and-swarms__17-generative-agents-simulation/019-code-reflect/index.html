Пишем reflect

Запусти reflect(stream) на потоке с тремя свежими наблюдениями: агент услышал приглашение, увидел согласие двух соседей и узнал место встречи. Здесь легко получить две ошибки. Если сделать вывод после первой записи, агент начнёт слишком рано обобщать случайность. Если при каждом вызове заново учитывать весь журнал, те же события будут порождать одинаковые рефлексии снова и снова.

В заготовке функции собери свежие записи типа observation и сложи их важность. Порог срабатывания мы разобрали в шаге 18: пока сумма недостаточна, поток нельзя изменять. Когда порог достигнут, выбери среди этих записей недавние и достаточно важные факты, а затем создай предусмотренный сценарием вывод более высокого порядка — например, что встреча действительно собирает людей.

Оформи вывод через написанную в шаге 7 функцию make_memory, но укажи тип reflection. Добавь получившуюся запись в тот же MemoryStream, чтобы позднее её можно было найти обычным retrieve. Сами рефлексии не включай в сумму новых наблюдений: иначе вывод начнёт подтверждать и размножать сам себя.

Проверь два случая: при сумме ниже порога новых записей нет; после срабатывания появляется ровно одна рефлексия. Повторный вызов без новых наблюдений не должен создавать её копию.

🎒 На пальцах. Представь дежурного метеоролога. Один порыв ветра ещё не означает шторм, поэтому он ждёт нескольких значимых показаний. Набрав достаточно данных, он записывает: «приближается шторм». Но эту фразу нельзя считать ещё одним показанием прибора — иначе прогноз сам станет доказательством собственного прогноза.

Практика: reflect

Здесь только функция этого шага — остальной файл упражнения подставится при запуске. Код выполняется прямо в твоём браузере: первый запуск качает Python, примерно двенадцать мегабайт, дальше из кэша.
