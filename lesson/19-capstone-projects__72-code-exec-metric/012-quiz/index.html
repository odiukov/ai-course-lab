Проверяем контракт code-exec метрики

Дальше в курсе тебе понадобится именно этот контракт: извлечь кандидат из ответа модели, ограниченно исполнить его, превратить исход запуска в балл и причину, а затем собрать pass@k по задачам. Чаще всего здесь спотыкаются, смешивая две разные вещи: устойчивую метрику и настоящую защитную песочницу. Ограничения из шагов 2–7 делают запуск предсказуемым, но не превращают чужой код в безопасный.

🎒 На пальцах. Представь испытательный стенд для фейерверков: есть таймер, ограничитель размера заряда и журнал результатов. Он помогает одинаково сравнивать изделия. Но неизвестную коробку с улицы ты не понесёшь на этот стенд — для неё нужен изолированный бункер. Метрика задаёт честные правила испытания; контейнер задаёт уровень защиты.

  1. Кандидат завис, а затем был остановлен по таймауту. Как метрика должна представить этот результат?

  2. У модели есть несколько попыток для одной задачи. Что означает её успех в pass@k?

  3. Для трёх задач уже получены их значения pass@k. Как получить общую оценку?

  4. Ты хочешь проверять код, скачанный из открытого интернета. Достаточно ли подпроцесса, чёрного списка и таймаута?
