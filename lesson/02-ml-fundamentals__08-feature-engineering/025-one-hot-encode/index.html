Пишем one_hot_encode

Ты передаёшь функции список ["синий", "красный", "синий"]. Категория «синий» повторяется, но отдельный столбец для каждого повторения не нужен. Сначала функция должна собрать уникальные категории и отсортировать их, чтобы порядок столбцов не менялся от запуска к запуску.

Затем свяжи каждую категорию с номером её столбца. Для отсортированного списка ["красный", "синий"] у «красного» будет столбец 0, у «синего» — 1.

Теперь обработай исходные значения по одному. Для каждого значения создай строку из нулей длиной по числу категорий, найди нужный столбец и замени в нём ноль на единицу. Так сохраняется принцип из шага 24: одна категория — один независимый флажок.

Проверь себя на том же примере. Результатом должна стать матрица:

[
    [0, 1],
    [1, 0],
    [0, 1]
]

Но одной матрицы недостаточно. Без списка категорий невозможно понять, что означает первый столбец, а что второй. Поэтому one_hot_encode должна вернуть сразу два результата: закодированные строки и отсортированный список категорий.

Обрати внимание на три детали: число строк совпадает с числом исходных значений, число элементов в каждой строке — с числом уникальных категорий, а в каждой строке стоит ровно одна единица.

🎒 На пальцах. Представь гардероб с подписанными крючками: «красный» и «синий». Для каждого посетителя ты заполняешь карточку из двух клеток и отмечаешь единицей только тот крючок, куда повесили его вещь. Повторный синий шарф не создаёт новый крючок — он получает такую же карточку, как предыдущий. Список подписей нужен, чтобы потом не перепутать клетки.
