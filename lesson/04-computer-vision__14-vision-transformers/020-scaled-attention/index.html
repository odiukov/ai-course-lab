Scaled dot-product attention смешивает информацию через Q, K и V

Ты смотришь на токен с фрагментом кошачьего уха. Сам по себе он неоднозначен: рядом может оказаться кошка, лиса или просто треугольный узор. Токену нужно выбрать, чья информация поможет уточнить его смысл.

Для этого одна и та же последовательность токенов получает три представления. Query (Q) описывает, что текущий токен ищет. Key (K) сообщает, по каким признакам можно найти каждый токен. Value (V) содержит информацию, которую тот передаст, если окажется полезным.

Механика записывается так:

Attention⁡(Q,K,V)=softmax⁡(QK⊤dk)V\operatorname{Attention}(Q,K,V)= \operatorname{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right)VAttention(Q,K,V)=softmax(dk​​QK⊤​)V

Здесь произведение QK⊤QK^\topQK⊤ даёт оценки сходства каждого запроса со всеми ключами. dkd_kdk​ — число признаков в одном ключе, а деление на dk\sqrt{d_k}dk​​ уменьшает масштаб оценок. Без него при большом числе признаков скалярные произведения часто становятся слишком крупными: softmax из шага 18 почти весь вес отдаёт одному токену, и небольшие различия перестают влиять на результат.

После softmax оценки превращаются в веса. Умножение на VVV смешивает значения: полезные токены вносят большой вклад, остальные — маленький. Поэтому attention не просто находит связь, а переносит по ней информацию. Для токена уха результатом станет его прежнее представление, дополненное признаками выбранного контекста.

🎒 На пальцах. Представь посетителя книжного магазина. Его вопрос — это Q: «Ищу книгу о выращивании роз». Надписи на полках — K: по ним он решает, куда смотреть. Содержимое найденных книг — V: именно его он унесёт с собой. Совпадение вопроса с надписью определяет веса, а итоговая подборка смешивает сведения из нескольких подходящих книг.
