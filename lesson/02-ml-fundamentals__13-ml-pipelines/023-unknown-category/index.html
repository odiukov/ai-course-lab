Неизвестная категория не должна останавливать продакшен

В понедельник модель обрабатывает тарифы basic, pro и family. Во вторник команда запускает новый тариф student, и первый же клиент получает ошибку вместо предсказания. Данные корректны — просто при обучении такой категории ещё не существовало.

В категориальной ветке из шага 22 OneHotEncoder запоминает известные значения. Например, для трёх тарифов он создаёт три признака: basic превращается в 1, 0, 0, pro — в 0, 1, 0, а family — в 0, 0, 1. Но куда поместить student, если отдельной позиции для него нет?

По умолчанию неизвестное значение может остановить весь пайплайн ошибкой. В продакшене это особенно опасно: новые города, устройства или тарифы появляются независимо от графика переобучения модели.

Параметр handle_unknown="ignore" меняет поведение: для student энкодер выдаст 0, 0, 0. Число признаков останется прежним, поэтому модель сможет сделать предсказание по остальным данным клиента.

Нулевой вектор не означает, что модель поняла новую категорию. Наоборот, он сообщает только: «ни одна из известных категорий не подошла». Такие случаи полезно отслеживать и позднее учитывать при переобучении. Но отдельный незнакомый тариф уже не уронит весь сервис.
