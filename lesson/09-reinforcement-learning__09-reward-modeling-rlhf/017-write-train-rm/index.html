Пишем train_reward_model

У тебя есть десятки карточек с парами ответов, но одно обновление весов обрабатывает лишь одну карточку. Если показать модели каждую пару только однажды, первые примеры могут заметно сдвинуть веса, а до устойчивого ранжирования дело не дойдёт. Значит, теперь нужно собрать отдельные детали в полноценный цикл обучения.

Напиши train_reward_model: функция должна создать начальные веса, несколько раз пройти по всему набору сравнений и для каждой пары выполнить одно обновление. Внутри пригодятся функции из шагов 10, 12 и 14: сначала получить оценки двух ответов, затем вычислить градиент и скорректировать каждый затронутый вес с учётом learning_rate.

Обрати внимание на два уровня повторения. Внешний цикл считает эпохи — полные проходы по набору. Внутренний перебирает пары внутри одной эпохи. Если задано 4 эпохи и 30 сравнений, модель должна выполнить 120 обновлений, а не четыре и не тридцать.

Не перепутай знак: градиент показывает направление роста потери, поэтому при градиентном спуске его нужно вычитать из весов. После завершения всех эпох функция возвращает обученные веса. Пока не пытайся решить по тем же данным, насколько хорошо модель ранжирует ответы: здесь твоя задача — только обучить её.

🎒 На пальцах. Представь реставратора, который подбирает смесь краски по стопке образцов. Один образец подсказывает небольшую поправку оттенка, но после него работа не закончена. Реставратор проходит всю стопку несколько раз: сравнивает, понемногу меняет смесь и снова начинает с первой карточки. train_reward_model организует именно такие проходы, а отдельное обновление делает одну маленькую поправку.

Здесь только функция этого шага — остальной файл упражнения подставится при запуске. Код выполняется прямо в твоём браузере: первый запуск качает Python, примерно двенадцать мегабайт, дальше из кэша.
