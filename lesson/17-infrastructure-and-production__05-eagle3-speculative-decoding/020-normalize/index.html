Пишем normalize

В симулятор попали два набора чисел: [2, 3, 5] и [0.2, 0.3, 0.5]. Они задают одинаковые пропорции, но только второй набор уже можно считать распределением вероятностей: его сумма равна единице. Именно такое представление требуется распределениям target и draft, подготовленным в шаге 19.

Тебе нужно дописать normalize: функция принимает последовательность неотрицательных весов и возвращает новую последовательность той же длины. Относительные пропорции должны сохраниться, а сумма результата — стать равной 1.0.

Проверь себя на трёх случаях:

  • [2, 3, 5] превращается в [0.2, 0.3, 0.5];
  • уже нормализованный набор [0.1, 0.9] по смыслу не меняется;
  • нулевой вес остаётся нулевым: [0, 4] даёт [0, 1].

Сначала найди сумму всех весов, затем используй её как общий масштаб для каждого элемента. Не округляй результат: дробные числа понадобятся симулятору с полной доступной точностью. Из-за особенностей вычислений сумма может получиться вроде 0.9999999999999999, поэтому в проверках сравнивай числа с небольшим допуском, а не требуй побитового равенства.

Отдельно подумай о наборе [0, 0, 0]: у него нет пропорций, которые можно сохранить, а деление на общую сумму невозможно. Функция должна явно отклонить такой ввод, а не тихо вернуть бессмысленные значения.

На этом шаге ты только приводишь веса к вероятностям — выбирать токен по ним будет следующий экран.

🎒 На пальцах. Ты смешиваешь краску из двух пигментов: 20 граммов синего и 30 граммов белого. Для маленького образца можно взять 2 и 3 грамма — оттенок останется тем же. normalize переводит количество пигмента в долю всей смеси: синего 40%, белого 60%. Если обе банки пусты, вычислять оттенок просто не из чего.
