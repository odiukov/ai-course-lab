Переводим классический attention на язык Query, Key и Value

Ты смотришь на состояние энкодера hih_ihi​ и замечаешь странность: одно и то же число сначала участвует в сравнении, а потом попадает во взвешенную сумму. Как назвать эти две роли, чтобы не путать их?

Для этого вводят язык Query, Key и Value. В attention Бахданау состояние декодера st−1s_{t-1}st−1​ становится Query — запросом о том, какая часть входа сейчас полезна. Почему именно предыдущее состояние, разобрано в шаге 29.

Каждое состояние энкодера hih_ihi​ одновременно играет две роли:

  • как Key, оно сравнивается с Query и помогает получить score;
  • как Value, оно участвует в сборке нового context с найденным весом.

Это не три новых вычисления и не три обязательно разных вектора. Мы просто называем участников по их работе. Query спрашивает, Key помогает решить, куда смотреть, Value содержит то, что будет взято. В классическом attention Key и Value численно совпадают: один и тот же hih_ihi​ сначала помогает определить вес своей позиции, а затем умножается на этот вес внутри attend из шага 22.

Поэтому переход к обозначениям Q/K/V ничего не меняет в уже знакомой механике. Он лишь отделяет вопрос «по чему выбираем?» от вопроса «что забираем?». Здесь ответы пока хранятся в одном состоянии энкодера.

🎒 На пальцах. Представь кастинг. Описание роли — Query: кого ты сейчас ищешь. Анкета каждого актёра служит Key, когда ты оцениваешь соответствие роли, и Value, когда учитываешь опыт этого актёра в итоговом решении. В классическом attention отдельного портфолио нет: одна и та же анкета помогает и выбрать кандидата, и взять из неё полезную информацию.
