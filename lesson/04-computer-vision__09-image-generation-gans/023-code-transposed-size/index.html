Пишем conv_transpose_output_size

Ты вводишь размер 4, ожидаешь 8, а функция возвращает 10. Сама транспонированная свёртка ещё даже не запущена — ошибка появилась только из-за неверного порядка вычислений.

Напиши conv_transpose_output_size, которая заранее вычисляет размер одной пространственной стороны выхода. Она должна принимать:

  • input_size — входную высоту или ширину;
  • kernel_size — размер ядра;
  • stride — шаг;
  • padding — отступ.

Правило вычисления уже разобрано в шаге 22. Перенеси его в тело функции и верни одно целое число. Скобки здесь важны: сначала уменьшается input_size, затем результат умножается на stride, после этого учитываются отступы и ядро.

Проверь два характерных случая. Параметры первой транспонированной свёртки должны превращать сторону 1 в 4. Параметры последующих слоёв — сторону 4 в 8, а 8 в 16. Если это выполняется, функция правильно предсказывает рост изображения, не создавая ни слоя, ни тензора.

Не добавляй output_padding: в рассматриваемой архитектуре он равен нулю и пока не нужен. Также не умножай результат сам на себя — функция считает одну сторону. Для квадратного изображения та же операция отдельно подходит и высоте, и ширине.

🎒 На пальцах. Представь раздвижной стол. input_size говорит, сколько секций сложено сейчас, stride — насколько раздвигается каждая секция, padding забирает место с двух краёв, а kernel_size задаёт ширину последней вставки. Твоя функция не раздвигает стол: она лишь по этим настройкам заранее сообщает, поместится ли после раскрытия 4, 8 или 16 мест.

Практика: conv_transpose_output_size

Здесь только функция этого шага — остальной файл упражнения подставится при запуске. Код выполняется прямо в твоём браузере: первый запуск качает Python, примерно двенадцать мегабайт, дальше из кэша.
