Пишем token_f1

Модель отвечает Shakespeare, а эталон содержит William Shakespeare. Функция exact_match из шага 22 поставит ноль, хотя совпадение явно есть. Теперь тебе нужно написать token_f1, которая заметит частично правильный ответ.

Сначала приведи обе строки к нижнему регистру, раздели их по пробелам и преврати получившиеся токены в множества. Множество важно: повтор слова не должен искусственно увеличивать оценку. Затем найди пересечение — токены, присутствующие и в ответе модели, и в эталоне.

Precision и recall вычисляй по правилам из шага 23, после чего объедини их в F1. Предусмотри два защитных случая:

  • если хотя бы одно множество пустое, верни 0.0;
  • если сумма precision и recall равна нулю, тоже верни 0.0, чтобы не делить на ноль.

Проверь функцию на паре Shakespeare и William Shakespeare. Общий токен один: precision получится 1, recall — 0.5, а итоговый F1 — примерно 0.67. Для совершенно разных ответов результат должен быть 0.0, для одинаковых наборов токенов — 1.0.

Обрати внимание: простое разделение по пробелам не удаляет пунктуацию. Поэтому Париж и Париж, станут разными токенами. Сейчас сохрани именно такое поведение — ты реализуешь заданную метрику, а не незаметно меняешь её правила.

🎒 На пальцах. Ты сверяешь две корзины продуктов. В одной лежат яблоко и хлеб, в другой — хлеб и молоко. Полного совпадения нет, но общий продукт есть. token_f1 оценивает сразу две вещи: какую долю первой корзины удалось подтвердить и какую долю второй она покрыла. Поэтому частичное совпадение получает промежуточный балл, а не жёсткий ноль.
