Пишем dfs_order

Перед тобой граф, где у A соседи перечислены как B, затем C. Ты ожидаешь, что обход после A пойдёт в B, но получаешь C. Ошибка не в графе: список работает как стек и отдаёт последнего добавленного кандидата.

Функция dfs_order(graph, start) должна вернуть список узлов в порядке посещения при DFS, описанном на шаге 25. Подготовь три хранилища: множество уже посещённых узлов, итоговый порядок и стек, в котором сначала лежит только start.

На каждой итерации забирай верхний узел операцией pop(). Если он уже посещён, пропускай его. Иначе помечай узел посещённым, добавляй в результат и помещай в стек его ещё не посещённых соседей.

Здесь есть тонкость: соседей нужно добавлять в обратном порядке. Для соседей B, C сначала положи C, затем B — тогда ближайший pop() достанет именно B. Так результат будет соответствовать порядку, в котором graph.neighbors(node) перечисляет соседей.

Проверка посещения нужна и после извлечения из стека: один узел могут заранее добавить туда из разных веток. В итоговый список он всё равно должен попасть только один раз. Если стартовый узел изолирован, результатом будет список только с ним; недостижимые из start части графа обход не затрагивает.

🎒 На пальцах. Представь расследование со стопкой папок. Найдя две новые зацепки, ты кладёшь их сверху и сразу берёшь последнюю. Чтобы первой изучить зацепку B, положи папку C, а поверх неё — B. Метка «изучено» не даст повторно разбирать одну папку, даже если на неё сослались несколько свидетелей.
