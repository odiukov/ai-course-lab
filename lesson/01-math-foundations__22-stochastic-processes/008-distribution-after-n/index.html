Пишем distribution_after_n_steps

Ты запускаешь функцию для двух шагов и ждёшь три возможные позиции. Но если хранить только список позиций, путь «вправо, влево» потеряется среди остальных: функции важно не просто найти конечные точки, а собрать их вероятности.

Твоя distribution_after_n_steps(n) должна вернуть словарь: ключ — конечная позиция, значение — вероятность оказаться в ней. Начни с распределения до первого шага: позиция 0 имеет вероятность 1. Это важный случай и для n = 0, где результат должен остаться {0: 1}.

Затем повтори обновление n раз. На каждом повторе перебирай текущие позиции и два исхода из step_distribution, написанной на шаге 5. Вероятность нового пути получается умножением вероятности текущей позиции на вероятность шага. Если разные пути приводят в одну точку, складывай их вероятности — именно это правило разбиралось на шаге 7.

Есть одна ловушка: не дописывай новые позиции прямо в словарь, который сейчас перебираешь. Создавай для очередного шага новый пустой словарь, а после подсчёта заменяй им текущий.

Проверь себя на n = 2: должны получиться позиции -2, 0, 2 с вероятностями 0.25, 0.5, 0.25. Сумма всех значений должна быть равна 1. Если это так, функция действительно собрала пути, а не просто перечислила точки.

🎒 На пальцах. Представь сортировочный стол с коробками, подписанными конечными позициями. После каждого шага ты раскладываешь содержимое старых коробок по новым и переносишь вместе с ним долю вероятности. Если две порции попали в коробку 0, их нужно объединить. Новый комплект коробок нельзя смешивать со старым до конца раскладки.

Практика: distribution_after_n_steps

Здесь только функция этого шага — остальной файл упражнения подставится при запуске. Код выполняется прямо в твоём браузере: первый запуск качает Python, примерно двенадцать мегабайт, дальше из кэша.
