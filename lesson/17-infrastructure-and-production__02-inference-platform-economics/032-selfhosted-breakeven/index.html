Пишем selfhosted_breakeven_requests

В редакторе тебя ждёт selfhosted_breakeven_requests. Она должна ответить на практический вопрос: сколько запросов за месяц нужно выполнить, чтобы фиксированная стоимость собственной инфраструктуры сравнялась с оплатой внешнего API.

Передай функции два значения: полную месячную стоимость self-hosted-инфраструктуры и стоимость одного запроса у провайдера. Затем примени точку окупаемости из шага 31. Результат — количество запросов за тот же месяц.

Проверь себя на конкретных числах: если инфраструктура стоит 1440вмесяц,азапросчерезAPI—1440 в месяц, а запрос через API — 1440вмесяц,азапросчерезAPI—0,02, граница должна получиться 72 000 запросов. Ниже неё API дешевле; выше неё фиксированная инфраструктура начинает выигрывать. Ровно на границе расходы равны.

Не округляй результат внутри функции. Дробная точка перехода полезна для дальнейших расчётов, а решение вроде «нужно не меньше целого числа запросов» можно принять отдельно. И проследи за единицами: в первый аргумент должна входить вся стоимость за месяц, включая нужное число GPU и обязательные постоянные расходы, а во второй — стоимость одного сопоставимого запроса.

Особый случай — нулевая стоимость запроса. Делить на неё нельзя: бесплатный API не позволит self-hosted-варианту окупиться при положительных расходах. Функция должна обработать такую ситуацию явно, а не вернуть случайное техническое значение.

🎒 На пальцах. Представь бассейн: месячный абонемент стоит €60, а разовый вход — €5. Ты делишь цену абонемента на цену посещения и получаешь границу в 12 походов. До неё выгоднее покупать билеты, после неё — абонемент. selfhosted_breakeven_requests делает тот же расчёт, только вместо походов в бассейн считает запросы к модели.

Практика: selfhosted_breakeven_requests

Здесь только функция этого шага — остальной файл упражнения подставится при запуске. Код выполняется прямо в твоём браузере: первый запуск качает Python, примерно двенадцать мегабайт, дальше из кэша.
