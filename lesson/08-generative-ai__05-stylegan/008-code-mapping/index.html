Пишем mapping_network

Ты передаёшь в функцию набор из 512 чисел и ожидаешь получить другие 512 чисел. Но если случайно каждый слой снова будет брать исходный z, семь предыдущих преобразований окажутся бесполезны. Поэтому здесь особенно важно следить не только за операциями, но и за тем, какие данные переходят к следующему слою.

Создай функцию mapping(z, M). Сначала заведи рабочую переменную и положи в неё z. Затем восемь раз обновляй именно эту переменную — по одному разу для каждого слоя из шага 7.

На слое с номером i нужно:

  1. взять матрицу весов из M по ключу W0, W1 и так далее;
  2. умножить её на текущий вектор;
  3. прибавить смещение с соответствующим ключом b0, b1 и так далее;
  4. передать результат в leaky_relu, которую ты написал на шаге 6.

После последней итерации верни рабочую переменную: теперь в ней находится w.

Обрати внимание на две частые ошибки. Индекс у весов и смещения должен совпадать, иначе один слой соберётся из чужих деталей. А return должен сработать только после завершения цикла — если поставить его внутри, функция выполнит лишь первый слой. Удобная самопроверка: вход и результат должны содержать по 512 чисел, но значения результата обычно уже не совпадают со значениями z.

🎒 На пальцах. Представь чемодан на линии досмотра с восемью постами. Каждый пост получает чемодан после предыдущего, что-то в нём перекладывает и отправляет дальше. Если посты будут каждый раз брать первоначальную фотографию багажа, изменения не накопятся. Рабочая переменная — сам чемодан в движении, а return — выход с линии только после восьмого поста.
