Пишем network_forward

Ты запускаешь сеть на входе [0.2, 0.8]. Первый слой получает эти два числа и выдаёт свой результат. Какой вход должен получить второй слой: исходные [0.2, 0.8] или результат первого? Если снова передать исходные данные, слои будут работать по отдельности, а не образуют сеть.

В network_forward заведи переменную current — в ней будут лежать данные, которые сейчас движутся по сети. Сначала это вход функции. Затем перебери layers в том порядке, в котором они записаны. На каждой итерации передавай current в метод forward очередного слоя и заменяй current полученным результатом. Саму математику повторять не нужно: она уже спрятана внутри прямого прохода слоя из шага 19.

Верни current только после завершения цикла. Если поставить return внутри цикла, функция остановится после первого слоя, и остальные даже не запустятся. Также не создавай отдельные переменные для первого, второго и третьего слоёв: сеть может содержать другое их количество, а цикл должен работать без переписывания функции.

Здесь важно не вычисление, а передача: один результат становится следующим входом.

🎒 На пальцах. Представь эстафету. Первый бегун получает палочку на старте и передаёт её второму, второй — третьему. Переменная current и есть эта палочка. Если каждому бегуну выдавать новую палочку со старта, эстафеты не получится. А если объявить финиш после первого бегуна, остальная команда останется ждать.
