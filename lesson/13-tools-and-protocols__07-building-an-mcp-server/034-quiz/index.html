Итоговая проверка урока

Ты прошёл путь от пустого файла до сервера, который здоровается через initialize, отдаёт список инструментов, читает ресурсы по своей схеме URI и честно помечает опасные операции аннотациями.

Дальше в курсе всё это станет фоном: когда мы возьмём SDK из шага 31, декораторы будут делать ровно то, что ты уже собрал руками, — и ты будешь понимать, что именно они прячут.

Спотыкаются обычно на трёх местах: отладочный print в stdout, ответ на уведомление без id и попытка вернуть ошибку JSON-RPC там, где нужен isError: true. Проверь на этих вопросах, что каждое из трёх для тебя уже не загадка.

  1. Ты добавил в код сервера строку print("дошли до dispatch") для отладки, и хост перестал видеть сервер. Что произошло?

  2. Модель вызвала инструмент read_note с id заметки, которой нет. Как правильно ответить?

  3. Ты объявил в capabilities для ресурсов subscribe: true, но кода подписки не написал. Чем это плохо?

  4. У тебя 200 заметок, и модель обычно ищет среди них по слову. Как это лучше отдать?
