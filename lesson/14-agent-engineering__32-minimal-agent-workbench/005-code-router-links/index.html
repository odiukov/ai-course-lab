Пишем router_links

В AGENTS.md встречаются ссылки вроде [состояние](STATE.md) и [правила](docs/agent-rules.md). Если искать пути простым разделением строки по пробелам, к ним прилипнут скобки, подписи и знаки препинания. Получатся строки, которые нельзя использовать как имена файлов.

Напиши функцию router_links, которая принимает текст роутера и возвращает цели Markdown-ссылок: то, что находится внутри круглых скобок. Для [доска задач](TASKS.md) результатом должен стать TASKS.md, а не вся запись целиком.

Сохрани порядок появления ссылок. Он помогает увидеть роутер так же, как его читает агент: сначала состояние, затем задачи, глубокие правила и команда проверки — роли, обозначенные в шаге 4. Если ссылок нет, функция должна вернуть пустую коллекцию, а не ошибку.

Обрати внимание на границу ответственности: router_links только извлекает адреса. Она пока не решает, существует ли указанный файл, достаточно ли короток роутер и правильный ли документ выбран. Поэтому не добавляй проверки файловой системы и не пытайся интерпретировать содержимое найденных файлов. Сейчас тебе нужен маленький, предсказуемый инструмент: получил текст — отдал найденные цели ссылок.

Проверь себя на строке с несколькими ссылками и на тексте без ссылок. Если результат содержит подписи или скобки, функция захватила лишнее.

🎒 На пальцах. Представь гардеробщика, который собирает с пальто только номерки. Надпись «синее пальто — номер 18» для него содержит один полезный результат: 18. Он не идёт искать пальто и не проверяет, правильный ли номерок. router_links работает так же: отделяет адрес каждой ссылки, а дальнейшие действия оставляет следующему инструменту.

Практика: router_links

Здесь только функция этого шага — остальной файл упражнения подставится при запуске. Код выполняется прямо в твоём браузере: первый запуск качает Python, примерно двенадцать мегабайт, дальше из кэша.
