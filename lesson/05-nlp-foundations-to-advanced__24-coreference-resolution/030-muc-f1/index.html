Пишем muc_f1

Ты передаёшь в muc_f1 два варианта разбиения одних и тех же mention: эталонные gold_clusters и найденные моделью pred_clusters. Например:

  • эталон: [[A, B, C], [D, E]];
  • предсказание: [[A, B], [C], [D, E]].

Формулу MUC мы разобрали в шаге 29. Теперь преврати её в две одинаковые операции с разными ролями кластеров.

Для recall перебери эталонные clusters. Для каждого выясни, на сколько предсказанных частей распались его mention. Кластер [A, B, C] оказался в двух частях — [A, B] и [C], поэтому из двух необходимых связей сохранилась одна. У [D, E] сохранилась единственная связь. После суммирования recall равен 2 / 3.

Для precision поменяй стороны местами: перебирай предсказанные clusters и проверяй, на сколько эталонных сущностей смешаны их mention. Здесь обе созданные связи корректны, поэтому precision равен 2 / 2. Итоговый F1 — 0.8.

Обрати внимание на три детали:

  • сначала суммируй числители и знаменатели по всем clusters, а не усредняй отдельные оценки;
  • singleton-cluster не добавляет возможных связей и не должен приводить к делению на ноль;
  • если знаменатель precision или recall равен нулю, возвращай для этой величины 0; F1 тоже равен 0, если сумма precision и recall нулевая.

Функция должна вернуть три числа: precision, recall и их гармоническое среднее.

🎒 На пальцах. Представь две схемы рассадки гостей по комнатам: правильную и составленную администратором. Для recall ты заходишь в каждую правильную комнату и считаешь, по скольким комнатам администратор раскидал её компанию. Для precision идёшь наоборот: проверяешь, не собрал ли он вместе гостей из разных компаний. Один и тот же обход, только схемы меняются ролями.
