## Как читать блок шага

У каждого шага ниже три части, и путать их нельзя.

**Материал курса** — раздел исходника, который покрывает шаг. Предмет вопросов
берётся ОТСЮДА.

**Шов кода** — эталонная реализация упражнения, к которому привязан шаг.

**Наш текст шага** — это НЕ материал для вопросов. Это наша нарезка урока: по
ней ты понимаешь, какую часть материала покрывает именно этот шаг и какими
словами читатель её видел. Спрашивать про сам этот текст — про наши метафоры,
аналогии и обороты — запрещено.

К этому добавляются существующие вопросы `check` внутри шага (могут быть
пустыми) и замечания к прошлой попытке по этому шагу (пустые — значит попытка
первая).

## Что нужно сделать

На каждый шаг выдай два набора вопросов.

**Первый — `cards`: карточки повторения.** Их показывают через недели и месяцы
на отдельной странице, где текста этого шага рядом нет. Отсюда жёсткие
требования:

0. Главное правило, старше всех остальных: карточка проверяет ПРЕДМЕТ урока, а
   не наше объяснение предмета. Урок про линейную алгебру — значит вопрос про
   векторы, матрицы, скалярное произведение, ранг. Запрещена карточка,
   правильный ответ на которую — наша метафора, аналогия или формулировка из
   текста шага. Пример брака: «Инженер застревает на первой странице формул.
   Какая причина ступора наиболее вероятна?» с ответом «У него нет привычки
   переводить значок в картинку». Это вопрос про наш пересказ, а не про
   линейную алгебру. Проверь себя так: человек, знающий предмет, но не читавший
   наш текст, обязан ответить правильно.
1. Карточка обязана быть понятной человеку, который этот шаг не видит.
   Нельзя оборотов, указывающих на текст рядом: «в примере выше», «см.
   выше», «формула выше», «на графике выше», «в разделе выше», «мы
   получили», «на этом шаге», «см. шаг 12». Обычное сравнение — «вероятность
   B выше вероятности A», «график выше нуля» — не запрещено: «выше»/«ниже»
   сами по себе не дейктика, дейктика — это оборот, указывающий на соседний
   текст.
2. Все числа в карточке обязаны отличаться от чисел в тексте своего шага. Если
   в шаге словарь из 65 символов и loss 4.17 — бери словарь из 1024 токенов и
   считай ответ заново. Проверяется автоматически: совпадение числа
   заворачивает карточку.
3. Карточка проверяет идею, а не память на пример.
4. Поле `concept` — одна фраза о том, какая именно идея проверяется. Ни одна
   из идей, перечисленных выше как занятые, не может быть взята снова — ни
   этой карточкой, ни другой карточкой этого же шага, ни карточкой соседнего
   шага этой же пачки. Проверяй по смыслу: «длина вектора равна корню из суммы
   квадратов координат» и «длина вектора считается по теореме Пифагора» — одна
   идея, а не две.
5. Каждая карточка обязательно несёт три поля: `concept`, `question` и
   `explanation`. Они требуются для всех пяти видов ниже.
6. Разнообразь виды. Пять доступных:
   - `choice` — вопрос и не меньше трёх вариантов, поле `correct` — индекс
     правильного с нуля;
   - `numeric` — числовой ответ, поля `answer` и `tolerance`;
   - `cloze` — строка кода или формула с пропуском `___` в поле `template`,
     правильная подстановка в `answer`, синонимы в `accept`;
   - `order` — поле `items`: не меньше трёх шагов алгоритма в правильном порядке;
   - `open` — вопрос «объясни своими словами», эталон в поле `reference`.
7. На шаг — от одной до трёх карточек. Если шаг не несёт запоминаемой идеи
   (оглавление, переход, приглашение открыть редактор), верни пустой список.
   Сюда же относится шаг, чей раздел исходника целиком мотивационный — «зачем
   это нужно», «почему статьи выглядят страшно», «что мы соберём». Предмета в
   таком разделе нет, и вытягивать карточку из мотивации нельзя: верни пустой
   список. Не подменяй недостающий предмет соседним разделом — про него
   спросит свой шаг.

Пустой список — это решение про конкретный шаг, а не способ разгрузить ответ.
Пачка из шести шагов не повод выдать по одной карточке на шаг: каждый шаг
получает столько же, сколько получил бы, разбирайся он в одиночку.

**Второй — `check`: починенные вопросы внутри шага.** Их задают сразу после
чтения, поэтому опираться на контекст шага им можно. Предмет у них тот же:
материал курса, а не наши обороты. Нельзя другого: чтобы
правильным ответом было число, напечатанное в тексте шага. Вопрос «что значит
4.17» переделай в вопрос «почему стартовый loss равен логарифму размера
словаря». Формат прежний: `question`, `options` (не меньше трёх), `correct`,
`explanation`. Если существующих вопросов не было, верни пустой список — новых
не выдумывай.

У каждой карточки и каждого вопроса обязателен `explanation`: короткий разбор,
который человек читает после ответа. В разборе ссылаться на числа урока можно
и нужно.

## Формат ответа

Ответь одним блоком JSON и ничем больше. В `steps` — ровно по одному объекту
на каждый шаг из списка выше, в том же порядке и с тем же `id`. Шаг, которому
карточки не полагаются, всё равно возвращается — с пустыми списками.

```json
{
  "steps": [
    {
      "id": "046-quiz",
      "cards": [
        {
          "kind": "numeric",
          "concept": "стартовый loss равен натуральному логарифму размера словаря",
          "question": "Языковая модель ещё ничего не выучила и раскладывает вероятность поровну между всеми токенами. В словаре 1024 токена. Чему примерно равен кросс-энтропийный loss?",
          "answer": 6.93,
          "tolerance": 0.05,
          "explanation": "Равномерное распределение по |V| вариантам даёт loss ln(|V|). ln(1024) ≈ 6.93. Стартовый loss, заметно отличающийся от ln(|V|), означает ошибку в прямом проходе или в функции потерь."
        }
      ],
      "check": []
    },
    {
      "id": "047-perehod",
      "cards": [],
      "check": []
    }
  ]
}
```
