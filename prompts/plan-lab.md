- итоговый quiz последним шагом.

Шаг — один экран и одна проверяемая мысль. Не объясняй весь файл подряд:
готовый каркас человек читает как контекст, пишет только перечисленные цели.
В code-шаге назови конкретный эффект, инвариант и крайний случай, который
закрепляют тесты. Между двумя code-шагами обязан быть theory-шаг.

Жёсткие правила:

1. Каждая строка `файл: цель` встречается ровно один раз с `type: "code"`,
   `exercise_file` и `exercise_fn`, записанными дословно. Квалифицированное
   имя вроде `HarnessLoop.resume` — один метод, точку убирать нельзя.
2. Не придумывай новые функции и не превращай готовые части каркаса в задачи.
3. `recall` допустим только для цели из списка, которую человек действительно
   писал раньше; иначе это `code`.
4. `visual` либо с дословным путём из списка, либо с `visual_brief`, но не с
   обоими. Если схема не нужна, не добавляй её ради количества.
5. Один `quiz` стоит последним. Один `check` проверяет понимание контракта до
   первого code-шага; в нём 1–2 вопроса с вариантами, индексом `correct` и
   объяснением.
6. `source_anchor` — существующий заголовок брифа.
