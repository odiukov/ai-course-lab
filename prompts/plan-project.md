Верни только JSON-объект в блоке ```json:

```json
{
  "version": 1,
  "title": "Название по-русски",
  "summary": "Два-три предложения о результате проекта.",
  "time": "35 часов",
  "languages": ["TypeScript / Bun", "Python"],
  "prerequisites": ["Фаза 11", "Фаза 13"],
  "phases": ["P11", "P13"],
  "tracks": ["agent-harness", "evaluation"],
  "brief": {
    "problem": "Связный markdown-текст на 180–260 слов.",
    "concept": "Связный markdown-текст на 180–260 слов.",

    {
      "id": "m01-command-loop",
      "title": "Короткое название",

      "body": "Подробный markdown-бриф этапа на 180–280 слов: границы, инварианты, порядок работы и типичные ошибки. Без готового кода.",

      "contractTargets": ["Budget.exceeded", "run_agent"],
      "evidence": "Что принести из настоящего внешнего прогона: команду, лог, ссылку на PR, метрики или скриншот."
    }
  ],
  "rubric": [
    {"id": "safety", "weight": 20, "criterion": "Безопасность", "measurement": "Как автор предлагает измерять"}
```

Правила:

1. Один элемент `milestones` на каждый нумерованный пункт исходной секции
   Build It, в том же порядке. Ничего не объединяй и не добавляй.
2. `task`, `body` и `doneWhen` описывают реальный проект автора, включая
   облачные сервисы. Локальный Python-код — только проверяемый контракт формы,
   а не замена настоящей реализации.
3. В `contractTargets` указывай 0–2 дословных имени функций или методов из
   приложенного Python-кода. Каждую цель используй не более одного раза во
   всём проекте. Выбирай шов, который действительно соответствует этапу.
   Если соответствующего шва нет, оставь пустой список — не притягивай.
4. `evidence` всегда про реальный прогон вне приложения. Зелёный локальный
   контракт не является доказательством готовности проекта.
5. Перенеси рубрику из Ship It без изменения весов; сумма должна быть 100.
6. В `tracks` используй только id из переданного списка и только релевантные.
7. Не добавляй сведения, версии, метрики и требования, которых нет в исходнике.
