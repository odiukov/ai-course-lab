# Поиск по курсу на опубликованном сайте

Дата: 2026-08-25

## Проблема

На сайте 474 урока и 18198 написанных шагов. Навигация — только каталог по
фазам на главной и оглавление внутри урока. Вопрос «где объяснялась каузальная
маска» решается перебором глазами, а вопрос «в каком уроке впервые появился
softmax» не решается вовсе.

Курс читают месяцами и возвращаются в него за справкой. Без поиска эта половина
пользы недоступна.

## Что уже есть

- `scripts/build-site.mts` — сборка статики в `out/`: страницы уроков, главная,
  страница входа, CSS, `harness.py` для Pyodide, бандлы редактора и входа через
  esbuild, файл `.nojekyll`.
- `scripts/publish-site.mts` — публикация собранного.
- `src/lib/site/render.tsx` — `htmlDocument`, `renderIndexPage`,
  `renderLessonPage`, `renderAuthPage`.
- Корпус: 18198 файлов шагов, около 58 МБ markdown, в среднем 3.2 КБ на файл.
  Текст в основном русский с английскими терминами.
- Заголовков внутри тел шагов практически нет — на весь курс один. Вся
  структура шага это его `title` во фронтматтере.

## Решение

### Выбор: Pagefind

Поиск строится на [Pagefind](https://pagefind.app) (npm `pagefind`, текущая
версия 1.5.2) — библиотеке статического поиска, которая индексирует уже
собранный HTML.

Как это работает: после того как `site:build` разложил страницы в `out/`,
Pagefind проходит по ним, строит шардированный индекс и кладёт рядом загрузчик
на WASM. Браузер качает небольшой корень индекса и подтягивает только те шарды,
которые нужны под конкретный запрос — весь индекс целиком не выкачивается
никогда.

Рассматривались и отвергнуты два своих варианта.

**Свой индекс по заголовкам и первым абзацам.** Корпус сжимается с 58 МБ до
примерно шести, свой инвертированный индекс выходит на пару мегабайт, всё —
чистые функции с тестами. Отвергнут из-за слепой зоны: при отсутствии
заголовков внутри тел шагов слово, стоящее в середине текста, не нашлось бы. У
курса на 58 МБ это большая часть содержания.

**Свой полнотекстовый индекс.** Шарды по префиксу слова, свой стеммер для
русского, своё ранжирование. Отвергнут по цене: это отдельный проект на недели,
и качество ранжирования ещё долго уступало бы готовому решению.

Рассуждение за Pagefind такое: поиск — вспомогательный инструмент навигации, а
не часть учебного содержания курса. Своё качественное ранжирование по 58 МБ
русского текста ничего не добавляет к тому, ради чего курс существует, а плохой
поиск раздражает сильнее, чем его отсутствие.

Цена решения названа прямо: это единственное место в проекте, про которое
нельзя сказать, как оно работает внутри, и юнит-тест на него не пишется.

### Изоляция чужого кода

Вся работа с Pagefind прячется за один свой интерфейс:

```ts
export interface SearchHit {
  title: string;      // заголовок шага
  lesson: string;     // название урока
  url: string;        // адрес с якорем на шаг
  excerpt: string;    // фрагмент с подсветкой совпадения
}

export interface SearchProvider {
  search(query: string): Promise<SearchHit[]>;
}
```

Модалка поиска знает только этот интерфейс. Отсюда два следствия: модалка
тестируется на подставном провайдере обычным тестом, а замена Pagefind на
что-то другое меняет одну реализацию и не трогает интерфейс.

`src/site-search/pagefind-provider.ts` — единственный файл, который знает про
Pagefind. `src/site-search/modal.ts` — модалка, ничего про него не знающая.

### Что попадает в индекс

Здесь сборка сайта уже устроена удачно: `renderStepPage` кладёт **каждый шаг
отдельной страницей** по адресу `/lesson/<slug>/<step-id>/` (`stepPageUrl` в
`src/lib/site/anchors.ts`). Единица страницы для Pagefind и так совпадает с
единицей результата, которая нужна человеку: на запрос «softmax» он получит
ссылку на конкретный шаг, а не на урок из сорока шагов, внутри которого надо
искать заново. Ничего разбивать не требуется.

Разметка сводится к тому, чтобы исключить служебное и назвать мета-поля:

- тело шага получает `data-pagefind-body`;
- заголовок шага — `data-pagefind-meta="title"`;
- название урока — `data-pagefind-meta="lesson"`;
- навигация, оглавление урока, панель упражнения, редактор кода, кнопки прогона
  тестов и блок квиза исключаются через `data-pagefind-ignore`. Без этого в
  индекс попадут подписи кнопок, одинаковые на всех 18198 страницах, и они
  забьют выдачу.

Страница оглавления урока (`renderLessonPage`) из индекса исключается целиком:
её содержание — список заголовков шагов, каждый из которых уже проиндексирован
своей страницей.

Адрес результата — адрес самой страницы шага, никаких якорей не нужно.

Язык индекса задаётся явно русским: Pagefind выбирает стеммер по языку
страницы, и без явного указания на смешанном русско-английском тексте выбор
может оказаться не тот.

### Интерфейс

Модалка по `Cmd+K` (`Ctrl+K` на не-Mac) и по кнопке в шапке — кнопка нужна,
потому что о сочетании клавиш никто не догадывается, и на телефоне его нет.

Поведение: ввод с задержкой, список результатов с заголовком шага, названием
урока и фрагментом с подсветкой, переход по `Enter` и по клику, навигация по
стрелкам, закрытие по `Esc`.

Загрузка Pagefind ленивая — при первом открытии модалки, а не при загрузке
страницы. До первого поиска человек не платит за поиск ничего.

Если загрузка индекса не удалась, модалка честно пишет, что поиск недоступен, и
не притворяется, что ничего не найдено.

### Сборка

`npm run site:build` после раскладки страниц запускает индексацию `out/`.
Pagefind добавляется в `devDependencies`; бинарник ставится вместе с пакетом,
отдельного шага установки нет.

Индексация 18198 страниц занимает заметное время, поэтому она делается отдельным
шагом `site:index` и вызывается из `site:build`. Прогон только сборки страниц,
без индексации, остаётся возможным — это нужно при отладке разметки.

Индекс лежит в `out/pagefind/` и уезжает на Pages вместе с остальным.

### Тесты

- `src/site-search/modal.test.ts` на `happy-dom` с подставным провайдером:
  открытие по сочетанию клавиш, ввод и показ результатов, навигация стрелками,
  переход по `Enter`, закрытие по `Esc`, состояние «поиск недоступен», состояние
  «ничего не найдено».
- `src/lib/site/render.test.ts` дополняется проверками разметки: у тела шага
  есть `data-pagefind-body`, у служебных блоков — `data-pagefind-ignore`, у
  заголовка и названия урока — мета, у страницы оглавления — исключение
  целиком.
- Сам Pagefind тестами не покрывается. Проверка — глазами по собранному сайту,
  на десятке запросов из разных фаз.

## Порядок работ

1. Разметка шагов атрибутами Pagefind в `render.tsx` с тестами.
2. `pagefind` в devDependencies, шаг `site:index`, вызов из `site:build`.
3. Интерфейс `SearchProvider` и реализация на Pagefind.
4. Модалка с тестами на подставном провайдере.
5. Кнопка в шапке, сочетание клавиш, ленивая загрузка.
6. Проверка глазами на собранном сайте.
