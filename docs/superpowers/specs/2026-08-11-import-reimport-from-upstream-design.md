# Импорт и реимпорт уроков из рут-репозитория кнопкой

Дата: 2026-08-11

## Проблема

Импорт урока сегодня — только команда: `npm run import -- <slug>`. Каталог на
главной показывает неимпортированные уроки серой строкой «не импортирован» с
подсказкой в `title`, но нажать там нечего. Чтобы завести урок, нужно уйти в
терминал, вспомнить слаг и набрать его руками.

Вторая половина проблемы — свежесть. `COURSE_REPO` указывает на локальный клон
форка `odiukov/ai-engineering-from-scratch`, а курс развивается в рут-репозитории
`rohitg00/ai-engineering-from-scratch`: правки в текстах уроков, новые уроки,
переводы. Клон форка обновляется руками и потому отстаёт. Импортированный урок
после этого починить нечем: `importLesson` пропускает любой файл, который уже
лежит в `source/`, поэтому повторный запуск не приносит ни строчки.

## Что уже есть

- `src/lib/source/catalog.ts` — `readCatalog(repo)` строит список фаз и уроков из
  `<repo>/phases/**`, `findLesson(repo, slug)` ищет один урок.
- `src/lib/source/import-lesson.ts` — `importLesson(repo, sourceDir, ref)` копирует
  в `source/`: каталог урока `phases/<phase>/<lesson>`, перевод
  `i18n/ru/phases/<phase>/<lesson>`, подходящие по префиксу
  `learning-visuals/*.html`, каталог упражнения из `learning-exercises`. Файл,
  который уже существует в `source/`, попадает в `result.skipped` и не
  копируется. `isImported(sourceDir, ref)` — наличие `docs` у урока в `source/`.
- `src/lib/source/merged-catalog.ts` — склейка каталога `source/` с каталогом
  `courseRepo`, каждому уроку проставляется `imported`.
- `src/lib/config.ts` — `loadConfig()`; `courseRepo` равен `null`, если
  `COURSE_REPO` не задан или указывает в никуда. Это осознанно: чтение уже
  импортированных уроков от исходного репозитория не зависит.
- `src/app/page.tsx` — серверный компонент каталога, рендерит строки уроков.
- `scripts/import-lesson.mjs` — CLI-обёртка над `findLesson` + `importLesson`,
  отказывается работать без валидного `COURSE_REPO`.
- `src/lib/exercise/file.ts` — код учащегося живёт в
  `source/learning-exercises/<slug>/exercise.py`; файл создаётся копированием
  `exercise.template.py` при первом открытии упражнения.

Про локализацию: `i18n/ru/**` приходит из самого рут-репозитория (генерируется
их CI, коммит `7953bfad`). Форк в `i18n/` ничего не менял. Русский есть у 491
урока из 503; без него только 12 уроков фазы `00-setup-and-tooling`. Обновление
от рута переводы не теряет, а подтягивает.

## Решение

Кнопка в каталоге, которая перед импортом сама тянет свежую версию курса с
рут-репозитория — в отдельный клон, принадлежащий лабе.

### 1. Кэш-клон апстрима

Новый модуль `src/lib/source/upstream.ts`.

- Каталог клона: `.cache/course-repo` в корне проекта. Добавляется в
  `.gitignore` строкой `/.cache`.
- Настройки: `UPSTREAM_REPO` (по умолчанию
  `https://github.com/rohitg00/ai-engineering-from-scratch.git`),
  `UPSTREAM_BRANCH` (по умолчанию `main`).
- Метка последнего опроса: файл `.cache/course-repo.fetched`, его `mtime`.
  Отдельный файл, а не `.git/FETCH_HEAD`, потому что после `clone` FETCH_HEAD
  не создаётся, и «только что склонировали» пришлось бы отличать особым случаем.

`ensureUpstream({ maxAgeMs })` делает ровно одно из трёх:

1. каталога нет → `git clone --depth 1 --single-branch --branch <branch> <url> <dir>`;
2. каталог есть, метка старше `maxAgeMs` → `git fetch --depth 1 origin <branch>`,
   затем `git reset --hard FETCH_HEAD`;
3. каталог есть, метка свежая → ничего.

Возвращает `{ dir, head, fetchedAt, fetched }`, где `head` — короткий SHA.

`reset --hard` здесь безопасен по построению: каталог создан лабой, никто в него
не пишет, локальных правок в нём быть не может. Репозиторий пользователя
(`COURSE_REPO`) не участвует ни в одной git-команде — ни `fetch`, ни `merge`, ни
смены ветки. Это главное свойство схемы: грязное рабочее дерево форка и его
ветка `feat/practice-harness` остаются нетронутыми.

Ошибки сети:

- клон существует → работаем на нём, ошибка возвращается в поле `error`, вызов не
  бросает. Устаревший курс лучше, чем неработающая кнопка;
- клона нет → бросает. Вызывающий (роут) откатывается на `COURSE_REPO`.

Git-команды вызываются через инжектируемый раннер `(args: string[], cwd: string)
=> void`, чтобы тесты не ходили в сеть.

### 2. Эффективный репозиторий курса

`loadConfig()` получает три новых поля: `upstreamDir`, `upstreamRemote`,
`upstreamBranch`.

Поле `courseRepo` меняет смысл на «эффективный репозиторий курса» и вычисляется
по порядку: кэш-клон, если это каталог и в нём есть `phases/`; иначе
`COURSE_REPO`, если он валиден; иначе `null`.

Из-за этого `src/app/page.tsx` и `src/app/api/catalog/route.ts` не меняются
вовсе — они уже читают `config.courseRepo`. `COURSE_REPO` остаётся рабочим
запасным вариантом: до первого клона всё ведёт себя ровно как сейчас.

### 3. Импорт с перезаписью

Сигнатура растёт до `importLesson(repo, sourceDir, ref, options?)`, где
`options.overwrite` по умолчанию `false` — поведение первого импорта не меняется.

При `overwrite: true` существующий файл перезаписывается, кроме двух случаев:

- **файл принадлежит учащемуся.** Предикат `isLearnerOwned(rel)`: путь вида
  `learning-exercises/<любой каталог>/exercise.py`. Это единственный файл в
  импортируемом наборе, который лаба создаёт и в который пишет учащийся;
  перезапись стёрла бы решение без возможности отката. Явный предикат, а не
  сравнение с шаблоном: решение, случайно совпавшее с заготовкой, всё равно
  остаётся файлом учащегося;
- **содержимое совпадает байт-в-байт.** Такой файл не пишется и не попадает в
  список обновлённых, иначе отчёт «обновлено 300 файлов» перестаёт что-либо
  значить.

`ImportResult` становится `{ slug, copied: string[], updated: string[], kept:
string[] }`. `copied` — созданные файлы, `updated` — перезаписанные, `kept` —
защищённые и неизменившиеся. Поле `skipped` уходит; его единственный потребитель
кроме тестов — `scripts/import-lesson.mjs`.

Файлы, удалённые в апстриме, из `source/` не удаляются. Удаление — необратимая
операция, а урок с лишним файлом работает.

### 4. Роут

`POST /api/catalog/import`, тело `{ slug: string }`.

1. `ensureUpstream({ maxAgeMs: 5 * 60_000 })`. Если бросил — берём
   `COURSE_REPO`; если и его нет, отвечаем 503 «Курс недоступен: нет ни кэша, ни
   COURSE_REPO».
2. `findLesson(repo, slug)`, иначе 404 «Урок не найден».
3. `overwrite = isImported(config.sourceDir, ref)` — **режим выводится на
   сервере, а не приходит от клиента.** Клиент не может попросить перезапись
   урока, который на диске выглядит иначе, чем на его экране.
4. `importLesson(repo, config.sourceDir, ref, { overwrite })`.

Ответ: `{ slug, mode: "import" | "reimport", pull: { fetched, head, at, error? },
copied, updated, kept }`, где три последних — количества.

Стиль как в `src/app/api/lesson/[slug]/exercise/reset/route.ts`: ручная проверка
тела, `Response.json({ error }, { status })`, без zod — в роутах его нет.

Пять минут кэша выбраны так, чтобы серия импортов подряд («завести четыре урока»)
стоила одного обращения к сети, а возврат к каталогу через полчаса гарантированно
принёс свежий курс.

### 5. UI

Клиентский компонент `src/components/ImportButton.tsx`, принимает `slug` и
`imported`. Вставляется в обе ветки `src/app/page.tsx`.

- Неимпортированный урок: текст «не импортирован» заменяется кнопкой
  **«Импортировать»**.
- Импортированный: кнопка **«Обновить»** справа, рядом со счётчиком шагов.
  Снаружи `<Link>`, а не внутри — вложенный интерактивный элемент.

Состояния кнопки:

- `idle` — обычный вид;
- `running` — «Клонирую курс…» на первом запуске без кэша (полный `clone` идёт
  заметно дольше, и молчащая кнопка выглядела бы зависшей), иначе
  «Импортирую…» / «Обновляю…». Кнопка disabled;
- успех — `router.refresh()` (строка становится ссылкой на урок, счётчик шагов
  пересчитывается) и текст вида `+12 новых, 3 обновлено` на месте кнопки,
  который гаснет через несколько секунд;
- `pull.error` при успешном импорте — жёлтая пометка «апстрим не опрошен, взято
  из кэша» рядом с результатом;
- ошибка — красный текст с сообщением сервера, кнопка возвращается в `idle`.

Запрос идёт через существующий `src/lib/api/fetch-json.ts`.

### 6. CLI

`scripts/import-lesson.mjs` получает флаг `--force` (реимпорт) и берёт репозиторий
через `loadConfig().courseRepo`, то есть тот же кэш-клон, что и кнопка. Иначе CLI
и UI импортировали бы из разных источников и расходились бы в результатах.
Отказ при отсутствии репозитория остаётся: импортёр без исходников бессмысленен.

## Тесты

`src/lib/source/upstream.test.ts` (git-раннер подменён, сети нет):

- каталога нет → выполняется `clone` с нужными аргументами;
- метка старше `maxAgeMs` → `fetch` + `reset --hard FETCH_HEAD`;
- метка свежая → ни одной git-команды;
- `fetch` бросил, клон на месте → результат с `error`, исключения нет;
- `clone` бросил, клона нет → исключение.

`src/lib/source/import-lesson.test.ts` (дополняется):

- `overwrite: true` перезаписывает изменившийся `docs/ru.md`, он попадает в
  `updated`;
- `exercise.py` с решением учащегося переживает реимпорт дословно и попадает в
  `kept`;
- файл с идентичным содержимым уходит в `kept`, не в `updated`;
- поведение по умолчанию (`overwrite` не передан) не изменилось.

`src/app/api/catalog/import/route.test.ts` — только ветка валидации тела, как в
остальных route-тестах проекта: она отвечает до `loadConfig()` и до любого
обращения к диску и сети.

- пустой или отсутствующий `slug` → 400;
- тело, которое не разбирается как JSON, → 400.

`src/lib/source/import-request.test.ts` — всё остальное, без HTTP:

- неизвестный урок → 404;
- неимпортированный урок → импорт без перезаписи, `mode: "import"`;
- импортированный урок → импорт с перезаписью, `mode: "reimport"`;
- апстрим недоступен, `COURSE_REPO` есть → импорт проходит, `pull.error` заполнен;
- нет ни апстрима, ни `COURSE_REPO` → 503;
- в ответе есть `pull.head`.

`src/lib/config.test.ts` (дополняется):

- кэш-клон с `phases/` выигрывает у валидного `COURSE_REPO`;
- кэш-клон без `phases/` игнорируется, берётся `COURSE_REPO`;
- нет ни того, ни другого → `courseRepo === null`;
- `upstreamRemote`/`upstreamBranch` берут значения по умолчанию и переопределяются
  из окружения.

## Что не делается

- Массовый импорт («импортировать всю фазу»). Уроки заводятся по одному, когда до
  них доходит очередь.
- Удаление из `source/` файлов, исчезнувших в апстриме.
- Отдельная кнопка «обновить курс» вне импорта: `pull` вшит в кнопку импорта, два
  пути к одному и тому же действию не нужны.
- Показ диффа перед перезаписью. `source/` под git — что именно изменилось, видно
  в `git diff`, и там же откатывается.
