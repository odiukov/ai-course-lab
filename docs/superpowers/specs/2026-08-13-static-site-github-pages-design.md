# Статический сайт курса на GitHub Pages

Дата: 2026-08-13

## Проблема

Курс читается только на локальной машине автора: `npm run dev`, база прогресса
в `data/`, агент под рукой. Показать написанное кому-то ещё нечем — ссылки не
существует. При этом читательская часть курса самодостаточна: текст шагов лежит
в `content/lessons/<slug>/steps/*.md`, схемы — в `content/lessons/<slug>/visuals/*.html`
и `source/learning-visuals/*.html`, и ни то, ни другое не требует сервера.

Нужен публичный адрес, по которому можно читать текст и смотреть схемы. Без
редактора кода, без агента, без чата, без прогресса — всё это остаётся локальным
приложением.

Второе обстоятельство, которое формирует решение: уроки дописываются прямо
сейчас, параллельно, другим агентом. Сборка и публикация не имеют права трогать
рабочую копию — ни `git stash`, ни `git checkout`, ни перезапись файлов в
`content/`.

## Что уже есть

- `src/lib/content/lesson-plan.ts` — `readLessonPlan(contentDir, slug)` читает и
  валидирует `lesson.json`: список `StepMeta` (`id`, `type`, `title`, `visual`,
  `visual_brief`, `check`, `exercise_fn`).
- `src/lib/content/step-file.ts` — `readStep(contentDir, slug, id)` разбирает
  markdown шага в `Step` (метаданные + `body`). Возвращает `null`, если файла
  нет.
- `src/lib/content/generated-visuals.ts` — `readGeneratedVisualIds` отвечает,
  у каких шагов плана схема действительно нарисована на диске.
- `src/lib/content/step-links.ts` — `linkStepReferences(body, currentStepNumber)`
  превращает упоминания шагов в тексте в ссылки, `stepNumberFromHref` читает
  номер обратно.
- `src/components/StepBody.tsx` — рендер тела шага: `react-markdown` +
  `remark-gfm` + `remark-math` + `rehype-katex`, нормализация `\( \)`/`\[ \]` в
  `$`/`$$`, перевод ссылок на шаги в `?step=N`.
- `src/lib/api/visual-height.ts` — `withHeightReporter(html)` подшивает к схеме
  скрипт, который сообщает наружу свою высоту через `postMessage`.
- `src/lib/api/visual-path.ts` — `resolveVisualPath` и
  `resolveGeneratedVisualPath`: проверки на выход за корень, симлинки и
  расширение.
- `src/components/VisualFrame.tsx` — рамка вокруг схемы: `sandbox="allow-scripts"`,
  высота по сообщению от схемы.
- `src/app/globals.css` — переменные темы, тёмный режим, оформление
  `.lesson-step-body .katex-display`.
- 44 урока в `content/lessons/`, из них два дописываются: `01-…-22-stochastic-processes`
  (8 шагов из 56) и `03-…-02-multi-layer-networks` (3 из 50).

## Решение

Отдельный сборщик — Node-скрипт, который читает контент, рендерит существующий
`StepBody` через `react-dom/server` и раскладывает готовый HTML в `out/`.
Приложение Next не меняется по сути: `output: "export"` на нём невозможен,
потому что `/api/*` route handlers и страницы с `force-dynamic` статический
экспорт не переживают.

Ключ подхода — переиспользование `StepBody`, а не второй конвейер разметки.
Нормализация формул, KaTeX, ссылки на шаги — всё это один код, и статический
сайт не может разойтись с локальным приложением в том, как выглядит текст.

### Форма сайта

```
out/
  index.html                       каталог: фазы → уроки
  lesson/<slug>/index.html         весь урок одной страницей
  visuals/<slug>/<stepId>.html     схемы, нарисованные проектом
  visuals/course/<name>.html       схемы, пришедшие с курсом
  assets/site.css
  assets/katex/katex.min.css
  assets/katex/fonts/*
  .nojekyll
```

Один урок — одна страница. Шаги идут подряд, у каждого якорь
`#step-<stepId>`; слева липкое оглавление из заголовков шагов. Ctrl+F ищет по
всему уроку, ссылкой на конкретный шаг можно поделиться.

`out/` уже в `.gitignore`.

### Модули

Чистая логика уходит в `src/lib/site/`, ввод-вывод остаётся в скриптах.

- **`src/lib/site/anchors.ts`** — `stepAnchor(stepId)` даёт `step-<stepId>`;
  `anchorHrefForStep(stepIds)` возвращает функцию «номер шага → `#step-<id>`»,
  которую сборщик отдаёт `StepBody` пропом `hrefForStep`. Номер вне плана
  отдаётся как есть: такая ссылка и в приложении ведёт в никуда, но текст от
  неё не ломается.
- **`src/lib/site/lesson-page.ts`** — `buildLessonModel(plan, steps, visuals)`:
  из плана, прочитанных шагов и списка существующих схем собирает модель
  страницы — упорядоченный список блоков (`text`, `visual`, `quiz`,
  `practice`), оглавление, счётчики. Отсутствующий на диске шаг в модель не
  попадает; счётчик «написано N из M» это фиксирует. Функция чистая: файлов не
  читает, принимает уже прочитанное.
- **`src/lib/site/quiz.ts`** — `quizPayload(step)` вынимает из шага вопросы,
  индекс верного варианта и объяснение в форму, которую понимает клиентский
  скрипт. Сериализация экранирует `<` и `&`, иначе вопрос, в тексте которого
  встретится закрывающий тег скрипта, разорвал бы страницу.
- **`src/lib/site/visual-refs.ts`** — `collectVisualRefs(plan, …)`: какие файлы
  схем нужны уроку и куда они лягут в `out/`. Схемы курса адресуются через
  `resolveVisualPath`, свои — через `resolveGeneratedVisualPath`; те же
  проверки, что в `/api/visual`, потому что источник путей тот же — файл,
  который написала модель.
- **`src/lib/site/render.tsx`** — сборка HTML-страницы из модели:
  `renderToStaticMarkup(<StepBody …/>)` для тела каждого шага плюс собственная
  разметка оболочки (шапка, оглавление, блоки квиза, рамки схем).
- **`scripts/build-site.mts`** — обход `content/lessons/*`, чтение, вызовы
  выше, копирование схем и ассетов, запись `out/`, итоговая сводка.
- **`scripts/publish-site.mts`** — публикация в `gh-pages`.

### Клиентский JS

Два маленьких скрипта, встроенных в страницу урока. Никаких зависимостей.

1. **Квиз.** Варианты — обычные `<button>`, ответы лежат в
   `<script type="application/json">` рядом. Клик подсвечивает выбранный вариант
   верным или неверным, показывает объяснение. Состояние нигде не сохраняется —
   прогресс остаётся свойством локального приложения.
2. **Высота схем.** Тот же слушатель `postMessage`, что в `VisualFrame`:
   отправитель сверяется по `contentWindow`, высота зажимается в
   `[160, 5200]`. Рамки стоят с `loading="lazy"` — на уроке их бывает до
   десяти.

Шаги `code` и `recall` показывают только текст задания и имя функции
упражнения. Редактора, запуска тестов и карточки «как ты писал это раньше» на
статике нет.

### Схемы и CSP

Схема — это HTML со своим скриптом. В приложении запрет ходить наружу едет
заголовком `Content-Security-Policy` из `/api/visual`; GitHub Pages
произвольные заголовки слать не умеет, поэтому при копировании в каждую схему
подшивается `<meta http-equiv="Content-Security-Policy" content="default-src
'none'; style-src 'unsafe-inline'; script-src 'unsafe-inline'">` — та же
политика, только внутри файла. Плюс `withHeightReporter`, как и в приложении.

Оговорка, которую стоит держать в голове: `<meta>` действует с момента разбора
тега, то есть на ресурсы, запрошенные раньше него, не влияет. Тег ставится
первым в `<head>`, а рамка остаётся с `sandbox="allow-scripts"` без
`allow-same-origin` — то есть в отдельном origin, откуда до страницы урока не
дотянуться в любом случае.

### Стили

Tailwind в статическую сборку не берётся: его CLI строит CSS по сканированию
исходников, а сканировать пришлось бы сгенерированный `out/`, который лежит в
`.gitignore` — то есть ровно то, что автоопределение источников пропускает.
Ради оболочки из десятка блоков это лишняя механика и лишняя зависимость.

Вместо этого `src/styles/site.css` — обычный CSS: оболочка страницы,
типографика статьи (`.lesson-step-body h2/p/ul/code/blockquote/table`), тёмная
тема через `prefers-color-scheme`.

Переменные темы и оформление формул общие с приложением: они переезжают из
`src/app/globals.css` в `src/styles/theme.css`, который импортируют оба входа.
Формулы на сайте и в локальном приложении выглядят одинаково, потому что
правило одно.

Отдельно из `StepBody` убирается `import "katex/dist/katex.min.css"` — он
переезжает в `src/app/layout.tsx`. Причина техническая: скрипт под `tsx`
импортировать `.css` не умеет, и компонент, который тянет стили за собой,
нельзя отрендерить вне Next. По смыслу стили и так принадлежат оболочке
страницы, а не компоненту.

`StepBody` получает необязательный проп `hrefForStep?: (n: number) => string`.
По умолчанию поведение прежнее (`?step=N`), сборщик передаёт функцию,
дающую якорь. Так переписывание ссылок делается в одном месте и не требует
разбора готового HTML регулярками.

### Адреса

Сайт живёт по `https://odiukov.github.io/ai-course-lab/`, то есть в подкаталоге.
Все ссылки и пути к ассетам строятся от префикса, который приходит из
`BASE_PATH` (по умолчанию `/ai-course-lab`). Файл `.nojekyll` рядом с
`index.html` — иначе Pages прогонит вывод через Jekyll.

### Публикация

`npm run site:publish`: сборка, затем копия `out/` во временный каталог, там
`git init`, один коммит и `git push --force <repo> HEAD:gh-pages`.

Рабочая копия не участвует: ни одной git-команды в каталоге проекта. Это не
осторожность вообще, а конкретное требование — уроки дописываются параллельно,
и любой `stash`/`checkout` отобрал бы у соседнего процесса файлы из-под рук.
Ветка `gh-pages` — история из одного коммита каждый раз, `--force`: это
артефакт сборки, а не журнал изменений.

Включение Pages — разово, `gh api -X POST repos/odiukov/ai-course-lab/pages`
с источником «ветка `gh-pages`, корень». Скрипт проверяет, включено ли уже, и
не трогает, если да.

### Обработка ошибок

Сборка не падает от неполноты — она снимает срез того, что есть на диске:

- урок без `lesson.json` или с непроходящим схему планом — пропускается с
  предупреждением, остальные собираются;
- шага нет на диске — в странице его просто нет, в сводке растёт счётчик
  ненаписанных;
- схема заявлена, но файла нет или путь не прошёл проверку — рамка не
  монтируется (смонтированная на 404 рамка даёт пустой прямоугольник посреди
  урока);
- итог печатается сводкой: уроков собрано, шагов отрисовано, шагов не хватает,
  схем скопировано.

Отдельно: `content/` во время сборки может меняться под руками. Гонка
безобидна — прочитанный план и прочитанные шаги дают согласованную страницу,
а урок, дописанный через минуту, приедет следующей публикацией.

### Тесты

Vitest, рядом с модулем, как принято в проекте. Проверяется чистая логика:

- `anchors.test.ts` — `?step=3` превращается в якорь третьего шага плана;
  номер за пределами плана не трогается.
- `lesson-page.test.ts` — план с дыркой посередине: блоки идут в порядке плана,
  ненаписанный шаг отсутствует, следующий за ним не сдвигается на его место;
  `visual`-шаг без файла схемы не даёт рамку.
- `quiz.test.ts` — верный индекс и объяснение доезжают до payload; шаг без
  `check` не даёт блока квиза; текст с `</script>` не разрывает сериализацию.
- `visual-refs.test.ts` — схема курса и своя схема раскладываются по разным
  каталогам `out/`; путь с `../` отклоняется.

## Что остаётся за рамками

Чат, агенты, редактор кода, LSP, запуск тестов упражнений, прогресс чтения,
кнопки импорта — всё это свойства локального приложения и на статику не едут.
Поиска по сайту нет. CI-сборки нет: публикация — команда, которую автор
запускает сам, потому что момент публикации выбирает он, а не пуш.

## Порядок работ

1. Общий CSS: `theme.css`, правка `globals.css`, `katex.min.css` в `layout.tsx`.
2. `hrefForStep` в `StepBody`.
3. Чистые модули `src/lib/site/*` с тестами.
4. `scripts/build-site.mts` и `src/styles/site.css`.
5. `scripts/publish-site.mts`, включение Pages, первая публикация.
6. Отдельным шагом и по явной команде — пуш исходников в `main` того же
   репозитория как резервная копия написанного.
