# Дописать курс: фазы 14–19

Ты продолжаешь работу в репозитории `/Users/oleksandr/ai-course-lab`. Курс
пишется агентом по одному шагу: план урока и текст шагов складываются в
`content/lessons/<slug>/`. Твоя задача — дописать оставшиеся фазы.

## Чем писать

```bash
cd /Users/oleksandr/ai-course-lab
./node_modules/.bin/tsx scripts/write-lesson.mts --phase <NN> --agent codex
```

`--agent codex` обязателен: без него скрипт возьмёт claude из `.env.local`, а
его недельная квота исчерпана.

Скрипт работает своим процессом и своей очередью, dev-сервер ему не нужен.
Импорт уроков из курса уже сделан — все фазы лежат в `source/`, клонировать и
импортировать ничего не надо.

## Как гнать очередь

По возрастанию, фаза за фазой. Внутри фазы скрипт сам идёт по урокам и
пропускает уже написанные шаги — перезапуск ничего не переписывает и ничего не
стоит.

```bash
for ph in 13 14 15 16 17 18 19; do
  echo "=== фаза $ph ==="
  ./node_modules/.bin/tsx scripts/write-lesson.mts --phase $ph --agent codex
  c=$?
  echo "фаза $ph: exit $c"
  [ $c -eq 2 ] && { echo "ЛИМИТ — стоп"; break; }
  [ $c -eq 3 ] && { echo "СЕТЬ — стоп"; break; }
done
```

Гони в фоне с логом в файл: один урок — это 30–60 минут, вся очередь — сутки и
больше.

## Коды выхода

| Код | Что значит | Что делать |
|---|---|---|
| 0 | фаза дописана | дальше по списку |
| 1 | часть уроков упала, остальные написаны | прогнать фазу ещё раз позже |
| 2 | исчерпан лимит агента | ждать восстановления, потом та же команда |
| 3 | три таймаута подряд — сеть легла | проверить связь, потом та же команда |

Скрипт печатает, на каком уроке встал и сколько не начато. Перезапуск с той же
командой продолжает с этого места.

## Чего ждать от поломок

- **529 Overloaded, обрыв потока** — временное, скрипт делает один повтор через
  30 секунд сам. Если урок всё же упал, его подберёт следующий проход по фазе.
- **`claude/codex не ответил за 600 с`** — таймаут одного запуска. Один такой
  бывает и на живой сети; три подряд означают, что сети нет, и очередь встанет
  сама с кодом 3.
- **`Не удалось получить вопросы для шагов-проверок`** — агент дважды вернул
  шаг-проверку без вопросов. Урок не записан намеренно: пустая проверка хуже
  отсутствующей. Помогает повторный проход.
- **Процесс жив, но ничего не пишется.** Сравни время последней записи с
  текущим:
  ```bash
  find content/lessons -path '*steps*' -name '*.md' -newermt '-20 minutes' | wc -l
  ```
  Ноль при живом процессе — он висит на таймаутах, убей и перезапусти:
  ```bash
  pgrep -f write-lesson | xargs kill
  ```
  Так бывает после сна ноутбука: процесс переживает сон, а связь с агентом нет.

## Публикация сайта

Статический сайт живёт в ветке `gh-pages`, собирается из того, что лежит на
диске сию секунду:

```bash
npm run site:publish
```

Безопасно делать в любой момент, даже пока очередь пишет: сборка — срез диска,
писателям она ничего не отбирает. Недописанные шаги показываются в оглавлении
урока как «ещё не написан». Публикуй после каждой закрытой фазы.

## Чего не делать

- Не запускать вторую очередь на ту же фазу: два процесса на одном уроке дёрнут
  агента на один шаг дважды, и один ответ уйдёт впустую. Разные фазы —
  пересечений нет, файлы у них разные.
- Не править `prompts/*.md` во время работы очереди: шаблон читается на каждый
  вызов, и новая переменная в нём обрушит генерацию на полушаге.
- Не трогать ветку `gh-pages` руками — её перезаписывает `site:publish`.
