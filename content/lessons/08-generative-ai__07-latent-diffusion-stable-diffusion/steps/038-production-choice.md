Ты выбираешь модель для генерации карточек товара. Первая красиво рисует, но работает только через чужой сервис. Вторую можно развернуть у себя, зато один результат приходится ждать дольше. Третья быстрая, но её лицензия не разрешает твой коммерческий сценарий. Сравнивать только качество картинок уже бессмысленно.

Сначала определи домен. Для узкой задачи с парными примерами — например, «фото товара → рекламный кадр» — практичнее дообучить SDXL через LoRA или полностью. Для открытых запросов без фиксированной тематики смотри на Flux.1-dev или SD3.5-Large.

Затем проверь лицензию именно выбранного чекпойнта: открытый доступ к весам ещё не означает разрешение продавать сервис на их основе. У разных версий одного семейства условия могут различаться.

Если важна задержка, выбирай дистиллированную модель: Flux.1-schnell или SDXL-Lightning получают изображение за 1–4 шага. Это отдельное преимущество, не следствие перехода к DiT — различие уже разобрано в [шаге 33](#step-33).

Наконец, реши, как ты будешь управлять результатом. Для максимального следования тексту можно взять чужой API — сервис, которому ты отправляешь запрос и получаешь картинку, не владея моделью. Для редактирования исходного изображения нужна модель, принимающая одновременно картинку и инструкцию, например Flux.1-Kontext. А SD 1.5 полезна как изученная исследовательская база, но не как автоматический выбор для продакшена.

> 🎒 **На пальцах.** Представь прокат автомобилей. Для развозки по одному району ты берёшь простой фургон и переоборудуешь его под свои коробки. Для разных маршрутов нужен универсальный автомобиль. Иногда важнее скорость, иногда — право использовать машину в коммерции, иногда — возможность самому сидеть за рулём. Самая дорогая модель в каталоге не обязательно подходит твоей поездке.
