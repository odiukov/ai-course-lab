После одного оптимального прохода клетка рядом с наградой уже выглядит выгодной, а дальние клетки всё ещё имеют нулевую ценность. Если сразу извлечь политику, она будет уверенно принимать решения на основе недосчитанной картины. Значит, одного прохода недостаточно.

Напиши `value_iteration`, которая сначала создаёт нулевую ценность для каждого состояния, а затем повторяет оптимальный проход Беллмана из [шага 22](#step-22). После каждого прохода сравнивай прежние и новые ценности: функция `sup_norm` из [шага 19](#step-19) покажет самое большое изменение среди состояний. Пока оно не меньше `tol`, результат ещё движется — продолжай вычисления.

Обрати внимание на три места, где легко ошибиться:

- сохраняй старую таблицу ценностей до прохода, иначе сравнишь обновлённую таблицу с ней же;
- проверяй условие остановки после полного прохода по состояниям, а не посреди него;
- терминальное состояние должно сохранить ценность, заданную правилами `bellman_sweep`, а не получить жадный максимум как обычная клетка.

Когда изменение станет меньше `tol`, больше не нужно обновлять политику в цикле. Один раз передай сошедшуюся таблицу `V` в `greedy_policy` из [шага 27](#step-27) и верни пару: ценности и найденную политику. Здесь `max` уже спрятан внутри оптимального прохода, поэтому отдельного цикла оценки политики нет.

> 🎒 **На пальцах.** Представь, что ты несколько раз проводишь валиком по стене: после первого прохода краска покрыла поверхность, но местами старый цвет ещё проступает. Ты сравниваешь стену до и после каждого слоя и прекращаешь красить, когда новый слой почти ничего не изменил. Только тогда выбираешь освещение, которое лучше всего подходит уже готовому цвету.
