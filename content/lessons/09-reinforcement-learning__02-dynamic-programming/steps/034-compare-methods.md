Ты запускаешь оба метода на одном стохастическом GridWorld. Итерация по политике завершилась за 4 внешних цикла, а итерация по ценности — за 87 проходов. Кажется, первая победила разгромно.

Но её «цикл» гораздо тяжелее: внутри каждого такого цикла функция `policy_evaluation` из [шага 25](#step-25) может сделать десятки проходов по всем состояниям. Один проход итерации по ценности из [шага 30](#step-30) выполняет лишь одно обновление каждого состояния. Сравнивать 4 и 87 — всё равно что сравнивать коробки, не посмотрев, сколько предметов лежит внутри.

Поэтому запиши несколько метрик. Сначала — число полных проходов по состояниям, включая все внутренние проходы оценки политики. Ещё точнее — общее количество бэкапов отдельных состояний. Затем измерь время по часам: сделай несколько запусков и возьми медиану, потому что единичный замер зависит от случайной нагрузки компьютера.

Условия тоже должны совпадать: одна модель переходов, одинаковые $\gamma$, начальные ценности, обработка терминала и порог остановки по $\Delta$ из [шага 18](#step-18). Наконец, проверь качество результата: сравни итоговое значение выбранного состояния, например $V(0,0)$, и полученные политики. При равных действиях политики могут выглядеть по-разному, оставаясь одинаково хорошими.

Так «быстрее» распадается на два честных вопроса: меньше вычислений или меньше реального времени?

> 🎒 **На пальцах.** Две бригады проверяют архив. Первая говорит: «Мы сделали четыре круга», вторая — «Мы сделали восемьдесят семь». Но в каждом круге первая перечитывала папки по десять раз. Посчитай просмотренные папки, засекни время и проверь число найденных ошибок — только тогда слова «четыре против восьмидесяти семи» приобретают смысл.
