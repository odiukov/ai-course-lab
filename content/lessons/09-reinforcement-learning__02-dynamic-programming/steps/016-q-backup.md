Ты стоишь в клетке GridWorld и рассматриваешь действие «вправо». Из-за скольжения оно не ведёт в одну заранее известную клетку: модель возвращает несколько исходов — например, движение вправо с вероятностью 0,8 и два боковых отклонения по 0,1. Как присвоить одному действию одно число, если будущих исходов несколько?

Для каждого исхода ты берёшь награду сейчас, добавляешь дисконтированную ценность следующей клетки, а затем учитываешь вероятность этого исхода:

$$
Q_V(s,a)=\sum_{s',r}P(s',r\mid s,a)\,[r+\gamma V(s')]
$$

Здесь $Q_V(s,a)$ — оценка действия $a$ в состоянии $s$ по текущей таблице $V$; $s'$ и $r$ — возможные следующая клетка и награда; $P$ берётся прямо из явной модели; $\gamma$ задаёт вес будущего. Это знакомый Q-бэкап, но теперь его результат не приходится оценивать по одному случайному переходу: `transitions(s, a)` перечисляет все исходы, и ты складываешь их вклады.

Важно: такой бэкап пока ничего не меняет ни в $V$, ни в политике. Он лишь отвечает на точный вопрос: «Насколько хорошо выбрать именно это действие при нынешних ценностях клеток?» Затем можно сравнить ответы для четырёх действий. Максимум из них даст выбор, использованный в оптимальном бэкапе из [шага 6](#step-6).

> 🎒 **На пальцах.** Представь страховой калькулятор для поездки: у маршрута есть несколько сценариев — приехать вовремя, задержаться или попасть на платную дорогу. Ты умножаешь итог каждого сценария на его вероятность и складываешь. Получившееся число оценивает один маршрут целиком. Явная модель играет роль таблицы сценариев: она позволяет учесть их все, а не судить о маршруте по одной поездке.
