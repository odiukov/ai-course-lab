Ты диспетчер паромной переправы. Для каждой ситуации у тебя есть несколько действий: отправить машину на паром, оставить ждать или направить к мосту. Текущая таблица ценностей ещё неточна, но уже подсказывает, насколько выгодны ситуации, в которые приведёт каждый выбор.

Можно было бы, как в итерации по политике из [шага 4](#step-4), сначала полностью оценить нынешние правила диспетчера, а затем заменить их. Итерация по ценности не ждёт. Для каждой ситуации она сразу пересчитывает:

$$
V_{\text{new}}(s)=\max_a \sum_{s',r}P(s',r\mid s,a)\,[r+\gamma V(s')]
$$

Здесь $s$ — текущая ситуация, $a$ — возможное действие, $s'$ — следующая ситуация, $r$ — немедленный результат, $P$ — вероятность такого перехода, а $\gamma V(s')$ — ценность продолжения с учётом скидки.

Для каждого действия сначала считается средний результат по всем возможным исходам. Затем максимум оставляет только лучший вариант. Поэтому один пересчёт делает сразу две вещи: уточняет ценность ситуации и неявно улучшает выбор действия.

Но ведь таблица пока неточна? Да — поэтому проходы повторяются. Новые оценки следующих ситуаций постепенно меняют победителей в максимуме. Явную политику можно получить в конце, выбрав действие, которое даёт этот максимум. Именно так два пути из [шага 5](#step-5) превращаются здесь в один повторяющийся шаг.

> 🎒 **На пальцах.** Диспетчер не составляет правило на неделю, чтобы потом долго проверять его целиком. При каждом обновлении он заново сравнивает паром, ожидание и мост по текущим расчётам и записывает результат лучшего выбора. Расчёты уточнились — лучший вариант тоже может смениться. Максимум работает как маленькое улучшение политики внутри каждой записи таблицы.
