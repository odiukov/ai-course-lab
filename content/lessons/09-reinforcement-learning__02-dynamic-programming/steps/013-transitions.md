Ты вызываешь `transitions(state, action)` для действия `down`, но функция не должна выбирать один случайный исход. Иначе получится обычный ход среды, а динамическому программированию нужна вся развилка будущего из [шага 12](#step-12): куда можно попасть, какую награду получить и с какой вероятностью.

Допиши функцию так, чтобы она возвращала список троек `(следующее состояние, награда, вероятность)`. Для обычной клетки перебери направления, которые выдаёт `action_probs(action)`. Каждое направление передай в `apply_move`, поставь награду `-1.0` и сохрани соответствующую вероятность. Например, у `down` появятся три записи: движение вниз с вероятностью `0.9` и два перпендикулярных соскальзывания по `0.05`.

Обрати внимание: здесь не нужны `random`, бросок числа или выбор одной записи. Ты описываешь возможные исходы, а не разыгрываешь один из них.

Для `TERMINAL` сделай отдельную раннюю ветку: единственный исход оставляет агента там же, даёт награду `0.0` и имеет вероятность `1.0`. После этого основной цикл сможет заниматься только обычными клетками. Если движение упирается в границу, не исправляй результат вручную — это уже решает `apply_move`.

В итоге один вызов функции должен отвечать не «что случилось сейчас?», а «что вообще может случиться после этого действия?».

> 🎒 **На пальцах.** Представь справочную аэропорта. Ты спрашиваешь про один рейс, а сотрудник не подбрасывает монету и не называет случайный выход. Он выдаёт полный список: выход A с одной вероятностью, B — с другой, C — с третьей. `transitions` работает так же: это перечень вариантов для расчёта, а не случайный выбор одного варианта.
