check:
  - question: >-
      Есть массив a со значениями 1, 2, 3. Ты выполняешь b = a.at[0].set(9).
      Какие значения останутся в переменных?
    options:
      - 'a содержит 9, 2, 3; b содержит 9, 2, 3'
      - 'a содержит 1, 2, 3; b содержит 9, 2, 3'
      - 'a содержит 1, 2, 3; b содержит 1, 2, 3'
    correct: 1
    explanation: >-
      Метод set не меняет исходный массив a, а возвращает новый массив с
      заменённым элементом.
  - question: 'Что происходит при выполнении a = a.at[0].set(9)?'
    options:
      - Первый элемент исходного массива изменяется на месте
      - 'Создаётся новый массив, а имя a начинает указывать на него'
      - JAX запрещает такую запись из-за неизменяемости массивов
    correct: 1
    explanation: >-
      Правая часть создаёт обновлённый массив, после чего обычное присваивание
      связывает с ним имя a. Сам прежний массив не меняется.
---

Здесь легко спутать изменение массива с изменением того, на что указывает имя. В [шаге 7](#step-7) ты видел, что запись `a[0] = 9` для массива JAX запрещена: она пыталась бы исправить существующий объект на месте.

Запись из [шага 8](#step-8) работает иначе. Выражение `a.at[0].set(9)` создаёт обновлённый результат. Если сохранить его в `b`, исходный `a` останется прежним. Если сохранить обратно в `a`, изменится лишь привязка имени: теперь оно указывает на новый массив. Поэтому одинаковые значения после операции ещё не означают мутацию старого массива.
