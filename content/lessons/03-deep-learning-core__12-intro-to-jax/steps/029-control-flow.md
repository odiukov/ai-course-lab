Ты добавляешь в шаг обучения простое правило: если ошибка больше `1.0`, уменьши параметры сильнее. В обычном Python хочется написать `if loss > 1.0`. Без `jit` это выглядит естественно, но при трассировке из [шага 26](#step-26) конкретного значения `loss` ещё нет — есть только описание будущего вычисления. Python же требует решить, какую ветку выполнять, прямо сейчас.

Здесь выбор становится частью вычислительной программы:

```python
result = jax.lax.cond(
    loss > 1.0,
    strong_update,
    gentle_update,
    params,
)
```

`jax.lax` — набор низкоуровневых операций, которые JAX умеет записывать и компилировать. `cond` сохраняет обе ветки в этой записи, а нужную выбирает позже, когда появится настоящее значение `loss`. Обе ветки должны принимать совместимые входы и возвращать результаты одинаковой структуры, формы и типов — иначе один скомпилированный результат нельзя будет использовать для обоих исходов.

Та же проблема возникает с циклом, если число действий или переносимое состояние зависит от данных. Вместо Python-цикла часто используют `jax.lax.scan`: ты передаёшь ему функцию одного шага, начальное состояние и последовательность элементов. На каждом проходе функция возвращает новое состояние и очередной результат. Состояние не прячется и не изменяется на месте — оно явно переходит из шага в шаг, как параметры в модели из [шага 3](#step-3).

Получается важный сдвиг: ветвление и повторение не исчезают, а переезжают из управления Python внутрь программы, которую видит JAX.

> 🎒 **На пальцах.** Представь сортировочную линию на складе. Рабочий с Python не может заранее решить, в какой контейнер отправить ещё не приехавшую посылку. Поэтому в схему линии встраивают развилку: лёгкая посылка едет налево, тяжёлая — направо. А повторяющиеся станции образуют конвейер, где каждая получает состояние от предыдущей. `cond` задаёт развилку, `scan` — такой конвейер.
