Ты переносишь готовый ноутбук на новую машину: код тот же, но JAX не видит ускоритель, первый замер выглядит медленным, а память GPU почти закончилась ещё до обучения. Здесь важно разделить четыре разные ситуации.

Для CPU достаточно базовой установки:

```bash
pip install jax jaxlib optax flax
```

Для GPU с CUDA 12 или TPU выбирай соответствующий вариант:

```bash
pip install "jax[cuda12]"
pip install "jax[tpu]" -f https://storage.googleapis.com/jax-releases/libtpu_releases.html
```

Если внутри JIT нужно увидеть значение, обычный `print()` покажет данные лишь во время трассировки или поведёт себя неожиданно. Используй `jax.debug.print()`. Для поиска настоящих узких мест подключай `jax.profiler` или TensorBoard: после компиляции отдельные операции могут слиться, поэтому время одной строки Python уже мало что говорит. Первый вызов и ожидание устройства при замерах разобраны в [шаге 57](#step-57).

Почти занятая GPU сразу после запуска не обязательно означает утечку: JAX заранее резервирует около 75% памяти. Если память нужно делить с другой программой, запусти процесс так:

```bash
XLA_PYTHON_CLIENT_PREALLOCATE=false python train.py
```

Наконец, параметры из pytree ([шаг 17](#step-17)) можно сохранить и восстановить через Orbax:

```python
import orbax.checkpoint as ocp

checkpointer = ocp.PyTreeCheckpointer()
checkpointer.save("/tmp/model", params)
restored = checkpointer.restore("/tmp/model")
```

Для точного продолжения обучения сохраняй вместе с параметрами состояние оптимизатора и номер шага.

> 🎒 **На пальцах.** Представь горную экспедицию. Установка под CPU, GPU или TPU — выбор транспорта до базы. `jax.debug.print()` и профилировщик — приборы, показывающие, где группа задержалась. Зарезервированная память — заранее занятый склад, а не пропавшие припасы. Чекпоинт — отмеченный лагерь: после остановки ты продолжаешь маршрут от него, а не идёшь снизу заново.
