У тебя уже есть функция, которая принимает один пример и возвращает один результат. Теперь на вход приходит батч: несколько примеров, сложенных по первой оси. Ручной цикл здесь не нужен — на [шаге 33](#step-33) ты видел, что такую функцию можно автоматически поднять на уровень батча.

В заготовке создай батчевую версию исходной функции с помощью `jax.vmap`. Передай в преобразование саму функцию, а получившуюся функцию вызови на всём массиве примеров сразу.

Обрати внимание на формы данных: если в батче пять примеров, результат тоже должен содержать пять элементов — по одному для каждого примера. Значения должны совпасть с теми, которые получились бы при последовательных вызовах исходной функции. Но писать `for`, вручную выбирать строки массива или собирать список результатов не нужно.

Здесь важно разделить две роли: исходная функция по-прежнему описывает вычисление для одного примера, а `vmap` отвечает за применение этого правила к батчу. Не переписывай внутреннюю математику под дополнительное измерение — именно эту работу JAX берёт на себя.

> 🎒 **На пальцах.** Представь станок с одной формой для печенья: форма описывает, что делать с одним кусочком теста. Тебе принесли целый противень заготовок. Ты не меняешь форму и не вырезаешь печенье вручную по одному — `vmap` превращает тот же приём в работу сразу со всем рядом заготовок. Исходное правило остаётся одиночным, меняется способ его применения.
