title: 'vmap, grad и jit можно собирать в единое вычисление'

Ты обучаешь модель на батче из 128 примеров и хочешь увидеть не один общий градиент, а 128 отдельных: какой вклад внёс каждый пример. Можно написать цикл, 128 раз вызвать `grad`, собрать результаты, а затем отдельно думать, как ускорить всё это. Но такой код дробит одно вычисление на множество мелких действий Python.

В JAX преобразования принимают функцию и возвращают новую функцию. Поэтому результат одного преобразования можно сразу передать следующему:

```python
per_example_grads = jax.jit(
    jax.vmap(
        jax.grad(loss_fn),
        in_axes=(None, 0, 0),
    )
)
```

Читай выражение изнутри наружу. `grad` из [шага 21](#step-21) превращает `loss_fn` одного примера в функцию его градиента. `vmap` из [шага 33](#step-33) поднимает эту функцию до батча: параметры остаются общими, а примеры и ответы берутся по оси 0. Наконец, `jit` из [шага 26](#step-26) трассирует уже всё батчевое вычисление и компилирует его целиком.

Важно, что это не три последовательных прохода по данным. JAX видит составленную функцию как единую программу и может оптимизировать её без промежуточного цикла Python. Порядок оболочек при этом выражает твоё намерение: сначала определить, *что* считать для одного примера, затем распространить это на батч и только после этого скомпилировать готовую операцию.

Так 128 отдельных градиентов остаются одной вычислительной задачей, а не 128 командами из Python.

> 🎒 **На пальцах.** Представь линию на фабрике печатных плат. Сначала ты задаёшь операцию для одной платы: проверить контакт. Затем расширяешь станок до целого поддона плат. После этого фиксируешь всю линию как одну автоматическую программу. Рабочий не носит каждую плату между тремя отдельными мастерскими: собранный процесс выполняется как единое производство.
