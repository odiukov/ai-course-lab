Представь батч из четырёх подделок с разными логитами. Функция `generator_loss` вернула одно среднее число, а для обратного прохода нужно понять, какую поправку получил каждый логит. Одного общего градиента здесь недостаточно: на выходе `generator_loss_grad` должен быть массив той же формы, что и `fake_logits`.

Возьми результат из [шага 18](#step-18): для каждого логита градиент равен `sigmoid(logit) - 1`. Используй функцию `sigmoid`, написанную в [шаге 9](#step-9), и примени её ко всему массиву.

Есть одна деталь, которую легко пропустить. В [шаге 17](#step-17) потеря усредняется по батчу. Значит, градиент каждого элемента тоже нужно разделить на количество логитов. Иначе увеличение батча, например с 16 до 64 изображений, сделает суммарный шаг обучения в четыре раза сильнее, хотя сами изображения не изменились.

Проверь результат по знаку. Значения должны лежать между −1 и 0: плохо распознанная подделка с большим отрицательным логитом получит градиент около −1, а уже убедительная — около 0. Не бери модуль и не меняй знак. При градиентном спуске именно отрицательный знак заставит последующие вычисления сдвинуть логит вверх.

> 🎒 **На пальцах.** Представь четыре посылки, и каждой нужно выписать свою поправку к адресу. Сначала ты определяешь поправку отдельно для каждой посылки, а затем делишь её на четыре, потому что итоговая ошибка была средней по всей партии. Если вернуть одну общую поправку или забыть деление, склад получит неверные команды.
