Перед тобой три найденных элемента: «Открыть», «Скачать» и «Удалить». Агент передаёт число `1` и ожидает получить «Скачать». Именно такое простое поведение нужно собрать в `select_by_index`: функция принимает список элементов и позицию, а возвращает элемент, стоящий на этой позиции.

Помни, что в Python отсчёт начинается с нуля: позиции трёх элементов — `0`, `1` и `2`. Сначала проверь границы. Пустой список, отрицательное число и позиция за концом списка не должны случайно выбирать элемент. Особенно коварен индекс `-1`: сам Python трактует его как «последний элемент», хотя для браузерного агента это недопустимая позиция. В таком случае функция должна вернуть предусмотренное заготовкой значение отсутствия результата.

Проверь себя на коротком списке, а затем поменяй местами первые два элемента. Число останется прежним, но выбранный объект изменится — это и есть ограничение позиционного выбора из [шага 15](#step-15). Здесь ты не исправляешь его, а создаёшь намеренно простую исходную версию, с которой позже можно будет сравнить более устойчивое поведение.

> 🎒 **На пальцах.** Представь конвейер с пронумерованными лотками. Ты говоришь роботу: «Возьми содержимое лотка номер два». Пока порядок не меняется, он приносит нужную деталь. Но если рабочий переставит лотки, робот безошибочно выполнит команду и возьмёт уже другую деталь. `select_by_index` действует так же: число найдено верно, а смысл выбора ничем не защищён.
