Ты запускаешь три страницы и видишь аккуратную таблицу, но в ней легко получить нечестное сравнение: сначала очистить вход, а потом показать этот же очищенный вход как результат «наивного» агента. Тогда защиты будто работают лучше, чем на самом деле.

В `run_agent` собери в один прогон уже написанные детали. Получай страницы через `walk` из [шага 9](#step-9). Для каждой страницы отдельно подготовь видимый текст функцией из [шага 11](#step-11) и полный вход агента функцией из [шага 13](#step-13). Именно исходный полный контекст должен попасть в ветку наивного поведения.

Затем проверь две защитные ветки. В одной примени `sanitize` из [шага 25](#step-25) до выбора действия. В другой передай попытку действия и происхождение данных в `boundary_allows` из [шага 28](#step-28). Эти проверки решают разные задачи, поэтому не подменяй одну другой и не используй результат первой как вход второй.

На выходе сохрани для каждой страницы исходное действие и результаты обеих защит. Отметку промаха выставляй только для вредоносного действия, которое осталось допустимым после обеих проверок. Безобидная страница, на которой защиты не сработали, промахом не считается.

Главная проверка проста: все ветки начинают с одной и той же страницы, но каждая применяет только свой режим обработки.

> 🎒 **На пальцах.** Представь звукорежиссёра, который проверяет одну запись на трёх дорожках: исходной, с шумоподавлением и с ограничителем громкости. Если сначала обработать запись шумоподавлением, а затем назвать её «исходной», сравнение потеряет смысл. `run_agent` так же сохраняет чистый эксперимент: один вход, независимые варианты обработки и отдельный результат для каждого.
