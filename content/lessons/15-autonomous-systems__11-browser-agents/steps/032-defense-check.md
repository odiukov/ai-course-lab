check:
  - question: >-
      Страница убеждает агента перевести деньги, но инструмент оплаты не был
      включён для этой задачи. Какой слой остановит действие первым?
    options:
      - Очистка содержимого страницы
      - Список разрешённых инструментов
      - Изоляция браузерной сессии
      - Канарейка в памяти
    correct: 1
    explanation: >-
      Список разрешённых инструментов не даст агенту вызвать оплату независимо
      от убедительности инструкции. Остальные слои решают другие задачи.
  - question: >-
      Инструкция с недоверенной страницы заставляет агента отправить заполненную
      форму. Какой слой требует свежего согласия человека?
    options:
      - Граница чтение–запись
      - Очистка содержимого страницы
      - Изоляция сессии
      - Канарейка в памяти
    correct: 0
    explanation: >-
      Отправка формы — запись с последствиями, инициированная недоверенным
      содержимым. Граница чтение–запись поэтому не разрешит её без свежего
      подтверждения.
---

Здесь ты сопоставляешь не тип атаки, а конкретное действие с первым подходящим защитным слоем. Частая ошибка — выбирать sanitizer для любого вредоносного текста. Но очистка из [шага 24](#step-24) может пропустить сложную инструкцию; тогда действие остановят граница из [шага 27](#step-27), allowlist или изоляция из [шага 29](#step-29), а последствия для памяти обнаружит канарейка из [шага 30](#step-30).

Смотри на ближайший запрет: отсутствующий инструмент блокирует вызов, запись из недоверенного источника требует подтверждения, а ограниченная сессия уменьшает доступ. Один слой не обязан победить всю атаку — достаточно, чтобы цепочка оборвалась до последствия.
