Перед тобой три страницы, но функция возвращает результат только для первой. Такое легко получить, если поставить `return` прямо внутри цикла: обход начался и тут же закончился.

Дополни `walk` в `code/main.py`, чтобы функция последовательно прошла по всему списку страниц, как задумано в [шаге 8](#step-8). Для каждой страницы она должна вызвать предусмотренную в заготовке обработку и добавить полученный результат в общий список. Возвращай этот список лишь после завершения цикла.

Следи за двумя деталями:

- страницы должны сохранять исходный порядок;
- один результат должен соответствовать ровно одной странице, даже если её содержимое кажется подозрительным.

Пока не пытайся распознавать или удалять prompt injection. `walk` отвечает только за полный обход. Если встроить защиту сюда, позднее будет трудно понять, на каком именно этапе исчезли данные и почему разные защитные меры дали разные результаты.

После запуска проверь не только первый элемент вывода. Ты должен увидеть три обработанных страницы. Если их меньше, ищи преждевременный `return`; если порядок изменился — проверь, куда и когда добавляется очередной результат. Здесь важна скучная надёжность: сначала агент обязан увидеть весь маршрут, и только потом мы сможем честно сравнивать его реакции.

> 🎒 **На пальцах.** Представь кассира с тремя товарами на ленте. Он сканирует каждый товар и складывает чек по строкам, но печатает чек только после последнего. Если нажать «готово» после первой покупки, оставшиеся товары не исчезнут — они просто не попадут в учёт. `walk` делает то же самое: собирает результаты по одному и завершает работу лишь после всей ленты.
