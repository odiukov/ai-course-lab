Ты проверяешь список получателей и видишь ошибку: у третьего человека вместо строки в поле `email` оказалось число.

```text
{
  "recipients": [
    {"email": "anna@example.com"},
    {"email": "boris@example.com"},
    {"email": 17}
  ]
}
```

Сообщить путь `/recipients/email` недостаточно: в массиве три объекта с таким полем. Как понять, какой из них исправлять?

Адрес из [шага 8](#step-8) продолжается не только именами свойств, но и индексами элементов. Когда обход доходит до массива, каждый индекс становится новым сегментом пути. Счёт начинается с нуля, поэтому третий получатель получает индекс `2`. Затем проверка входит в его объект и добавляет `email`. Точный путь ошибки — `/recipients/2/email`.

Важно добавлять индекс **до** проверки самого элемента. Тогда любая ошибка глубже внутри него унаследует правильный адрес. Если же сохранить только путь массива, разные ошибки сольются в расплывчатое `/recipients`: станет известно, где лежит список, но не где именно нарушен контракт.

Это правило работает на любой глубине. Например, если внутри получателя есть массив `phones`, то ошибка во втором телефоне продолжит путь индексом `1`: `/recipients/2/phones/1`. Валидатору не приходится сочинять отдельное описание — он просто несёт текущие сегменты дальше по рекурсивному обходу.

Индекс превращает «ошибка где-то в списке» в координату одного конкретного значения.

> 🎒 **На пальцах.** Представь поезд: номер состава приводит тебя к нужному поезду, но внутри ещё десяток вагонов. Проводник говорит: «вагон 2, место email» — и ты сразу находишь проблему. Индекс массива играет роль номера вагона. Нумерация начинается с нуля, поэтому третий вагон в техническом адресе обозначен числом `2`.
