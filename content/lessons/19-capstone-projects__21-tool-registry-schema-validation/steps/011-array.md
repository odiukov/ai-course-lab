В контейнере лежат три измерения: `12`, `15` и `"много"`. Сам контейнер действительно массив, поэтому внешняя проверка проходит. Но если схема требует числовые элементы, строка внутри не должна остаться незамеченной.

Дополни проверку массива так, чтобы ключ `items` задавал одну схему для **каждого** элемента. Сначала получи схему элементов. Если `items` отсутствует, содержимое массива здесь ничем не ограничено: функция может завершиться без ошибок. Пустой массив тоже допустим — проверять в нём просто нечего.

Если `items` задан, обойди весь список вместе с индексами. Для каждого значения передай в общий рекурсивный обход одну и ту же схему `items`, само значение, список ошибок и путь, дополненный текущим индексом. Как собирать такой адрес, ты подготовил в [шаге 10](#step-10).

Важно не остановиться после первой неудачи. В массиве могут одновременно оказаться неверные элементы под индексами `1` и `4`; обе ошибки должны попасть в общий список. Самой функции не требуется отдельно разбирать числа, строки или вложенные объекты: это уже делает рекурсивный диспетчер из [шага 7](#step-7). Здесь её ответственность уже — применить правило ко всем позициям и правильно передать контекст.

Одна схема, полный обход, отдельный адрес для каждого нарушителя.
