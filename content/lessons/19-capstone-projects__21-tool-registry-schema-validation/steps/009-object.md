Схема объявляет `email` обязательным, а для `email` и `age` задаёт типы. Во входных данных есть `age: "семнадцать"` и незнакомое поле `note`, но нет `email`. Какие ошибки должен собрать валидатор?

Здесь нужны две отдельные проверки. Сначала функция просматривает список `required`. Для каждого обязательного имени она проверяет, присутствует ли оно во входном объекте. Если поля нет, в список ошибок добавляется запись с ключевым словом `required`. Путь должен вести к отсутствующему полю — в нашем примере это `/email`. Собрать такой адрес поможет функция из [шага 8](#step-8).

Затем функция перебирает поля, которые действительно пришли. Если имя есть в `properties`, значение нужно передать обратно в общий рекурсивный обход вместе с продолженным путём. Поэтому строка `"семнадцать"` попадёт на проверку схемы `age`, а возможная ошибка получит путь `/age`.

Важно не смешать два понятия: известное поле не обязательно является обязательным. `properties` говорит, как проверять поле, **если оно пришло**, а `required` — должно ли оно прийти вообще.

Незнакомое поле `note` на этом этапе пропускается: для него нет схемы, которую можно передать в обход. Функция не должна ни придумывать ему правила, ни считать его ошибкой. В итоге один проход замечает отсутствие `/email`, а другой отправляет `/age` на дальнейшую проверку.

> 🎒 **На пальцах.** Представь анкету участника забега. Номер телефона отмечен как обязательный: пустая строка для него сразу становится нарушением. Возраст и название клуба знакомы организатору, поэтому заполненные значения проверяют по своим правилам. А приписку «люблю дождь» просто оставляют без проверки. Знакомое поле получает контролёра, обязательное обязано присутствовать — это разные отметки.
