Ты запускаешь агента в GridWorld: он делает несколько ходов, получает награды — но после завершения функции от этого путешествия ничего не остаётся. Значит, каждый переход нужно сохранить в `trajectory`, а затем вернуть весь список.

Допиши заготовку:

```python
def rollout(env, policy, max_steps=200):
    trajectory = []
    s = env.reset()

    for _ in range(max_steps):
        # 1. Выбери действие по текущему состоянию
        a = ...

        # 2. Сделай один шаг в среде
        s_next, r, done = ...

        # 3. Запиши текущие состояние, действие и награду
        trajectory.append(...)

        # 4. Перейди в следующее состояние
        ...

        # 5. Остановись, если эпизод завершён
        ...

    return trajectory
```

Среда здесь используется только через `reset()` и `step()`: `reset()` даёт начальное состояние, а знакомый по [шагу 8](#step-8) переход возвращает следующее состояние, награду и признак завершения.

Обрати внимание на порядок действий. В запись попадает `s`, то есть состояние **до** перехода: именно в нём политика выбрала `a` и после этого получила `r`. Значение `s_next` понадобится следующей итерации, поэтому лишь после записи оно становится новым `s`.

Если среда сообщает `done=True`, награду последнего перехода всё равно нужно сначала добавить в траекторию и только потом выйти из цикла. А `max_steps`, как обсуждалось в [шаге 6](#step-6), не даёт rollout зависнуть, если агент ходит по кругу и до завершения не добирается.

> 🎒 **На пальцах.** Представь фотографа на аттракционе: после каждого участка пути он сохраняет снимок места отправления, выбранный поворот и полученный жетон. Потом вагонетка переезжает дальше. Даже когда загорается табличка «финиш», последний снимок сначала попадает в альбом — иначе пропадёт переход, который и привёл к финишу.
