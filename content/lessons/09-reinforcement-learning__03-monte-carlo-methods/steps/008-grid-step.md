Ты стоишь у верхней границы сетки и выбираешь действие «вверх». Новая координата получилась бы отрицательной — но такой клетки нет. Именно такие случаи должна аккуратно обрабатывать `grid_step`.

Допиши функцию с интерфейсом:

```python
def grid_step(state, action):
    # вычисли следующее состояние
    # определи награду и завершение эпизода
    return next_state, reward, done
```

`state` — координаты текущей клетки, а `action` задаёт смещение по строке и столбцу. Сначала рассчитай предполагаемую позицию. Если она выходит за границы, агент остаётся на месте. Затем проверь, является ли полученная клетка терминальной: тогда `done` должен стать `True`, иначе — `False`. Награду верни по правилам GridWorld из [шага 7](#step-7).

Обрати внимание на порядок проверок. Терминальность относится к состоянию **после** действия: если ход привёл агента к цели, этот же вызов должен сообщить о завершении эпизода. Отдельно обработай вызов из уже терминальной клетки, чтобы среда не выпускала агента обратно в сетку.

Проверь функцию вручную хотя бы на трёх случаях: обычный ход, попытка выйти за край и вход в терминальную клетку. Результат всегда должен иметь одинаковую форму: новое состояние, одно числовое вознаграждение и логический флаг завершения.

> 🎒 **На пальцах.** Представь лифт с кнопками этажей. Ты нажимаешь допустимый этаж — кабина едет; нажимаешь несуществующий — остаётся на месте. На конечном этаже загорается лампа «поездка завершена». `grid_step` делает ровно эту маленькую проверку для одного хода, не планируя весь маршрут.
