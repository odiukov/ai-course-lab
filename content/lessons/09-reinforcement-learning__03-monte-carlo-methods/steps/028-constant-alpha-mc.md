Ты берёшь `mc_evaluate` из [шага 23](#step-23), заменяешь коэффициент обновления — и неожиданно получаешь почти ту же функцию. Но одно старое действие теперь становится ошибкой: делить поправку на число посещений больше нельзя. Иначе шаг снова будет уменьшаться, хотя `alpha` должен оставаться постоянным.

В `constant_alpha_mc` сохрани знакомый конвейер:

1. Получи полный эпизод через `rollout` из [шага 10](#step-10).
2. Вычисли отдачу для каждого момента функцией `returns_from` из [шага 14](#step-14).
3. Пройди по состояниям эпизода вместе с соответствующими отдачами.
4. Для выбранного визита сдвинь текущую оценку `V[s]` в сторону его отдачи на долю `alpha`.

Если функция использует first-visit MC, создавай новый `seen` для каждого эпизода, как в [шаге 22](#step-22). Состояние, встретившееся повторно в той же траектории, пропускай. Между эпизодами `seen` переносить нельзя: тогда состояние обновилось бы лишь однажды за весь запуск.

Счётчик посещений здесь не участвует в размере поправки. Его можно хранить для диагностики, только если этого требует заготовка функции, но он не должен заменять `alpha`. Также проверь границы: при `alpha = 1` оценка сразу становится равна новой отдаче, а при малом положительном `alpha` движется к ней понемногу.

> 🎒 **На пальцах.** Представь ручку настройки яркости. После каждого эпизода новая отдача показывает желаемый уровень, а `alpha` задаёт, насколько сильно ты повернёшь ручку. При `alpha = 1` сразу выставишь предложенную яркость; при `alpha = 0.1` сделаешь лишь десятую часть пути. Число прежних поворотов силу следующего поворота не меняет.
