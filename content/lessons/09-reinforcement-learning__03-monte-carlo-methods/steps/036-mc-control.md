Ты попал в одну клетку дважды: сначала нажал «вверх», потом «вправо». Если записать обе отдачи только в ценность клетки, алгоритм не поймёт, какое действие оказалось удачным. Поэтому в `mc_control` единицей обучения становится пара `(состояние, действие)`, а таблица `Q` хранит отдельную оценку для каждого действия.

Создай `Q` и `counts` так, чтобы для нового состояния автоматически появлялись записи для всех `ACTIONS`: нулевые оценки и нулевые счётчики. Затем определи внутреннюю политику. С вероятностью `epsilon` она выбирает случайное действие, а иначе — действие с максимальным текущим значением `Q`. Это ε-жадный выбор из [шага 31](#step-31), но теперь он постоянно видит обновляемую таблицу: после каждого эпизода следующее решение уже может измениться.

Для каждого эпизода получи траекторию функцией `rollout` из [шага 10](#step-10), а затем вычисли отдачи через `returns_from` из [шага 14](#step-14). Проходя по траектории вместе с отдачами, учитывай только первое появление каждой пары `(s, a)` в этом эпизоде. Обрати внимание: `seen` нужно создавать заново перед обработкой очередной траектории. Если оставить его между эпизодами или записывать туда только состояние, часть полезных наблюдений исчезнет.

Для принятой пары увеличь `counts[s][a]` и обнови `Q[s][a]` инкрементальным средним из [шага 18](#step-18). В конце верни и таблицу `Q`, и политику. Проверь главное: политика должна обращаться к той же таблице, которую обучение только что обновило. Тогда оценка и улучшение действительно чередуются, а не живут отдельно.

> 🎒 **На пальцах.** Представь зал игровых автоматов: у каждого автомата несколько кнопок. Ты записываешь не просто «этот автомат принёс 20 билетов», а «кнопка B на этом автомате принесла 20 билетов». Иногда ты нажимаешь случайную кнопку, чтобы проверить её, а чаще выбираешь лидера по записям. После каждой партии журнал обновляется — и следующий выбор уже опирается на свежий опыт.
