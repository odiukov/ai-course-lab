В редакторе тебе нужно решить практический спор: можно ли для заданной модели получить плотность именно в том пространстве, о котором спрашивает вызывающий код. Не подменяй этот вопрос проверкой «модель умеет генерировать» — GAN генерирует изображения, но вероятность конкретного изображения не сообщает.

Сначала посмотри на параметры заготовленной функции. По ним определи семейство модели и пространство оценки: исходные данные или токены. Затем верни предусмотренный заготовкой результат для каждого случая из [шага 13](#step-13).

Авторегрессионная модель и нормализующий поток дают вычислимую точную плотность в пространстве, где обучены. Для VAE и DDPM доступна оптимизируемая оценка, а не прямое точное значение. GAN не предоставляет плотность вообще. У score-модели и flow matching плотность можно восстановить интегрированием, поэтому не смешивай этот случай ни с прямым вычислением, ни с полной недоступностью. У токенной авторегрессии ответ зависит от пространства: для токенов плотность вычислима, для исходных пикселей — нет из-за необратимого сжатия.

Обрати внимание на порядок условий. Если сначала признать любую авторегрессию моделью с доступной плотностью, токенная модель ошибочно получит положительный ответ и для пикселей. Проверь функцию хотя бы на двух одинаковых токенных моделях, меняя только запрошенное пространство: результаты должны различаться.

> 🎒 **На пальцах.** Представь турникет с билетами для разных зон метро. Надпись «билет действителен» сама по себе недостаточна: билет может открыть поездки в центре, но не пропустить в аэропорт. Семейство модели — это тип билета, а пространство данных — нужная зона. Проверка считается правильной только тогда, когда она сверила оба условия.
