Ты вызываешь `spatial_out(32, 5, 1, 0)` и ожидаешь `28`. Затем меняешь размер входа на `14` — функция должна вернуть `10`. Эти числа знакомы по маршруту LeNet-5, но теперь считать их вручную неудобно: один неверный размер испортит все следующие слои.

Напиши функцию `spatial_out`, которая принимает четыре величины:

- `n` — размер одной стороны входа;
- `kernel` — размер ядра;
- `stride` — шаг его перемещения;
- `padding` — число добавленных клеток с каждой стороны.

Внутри примени правило из [шага 6](#step-6) и верни одно целое число — размер стороны выхода. Готовую формулу здесь дублировать не нужно: твоя задача как раз перевести её в вычисления.

Проверь функцию на таких случаях:

```python
spatial_out(32, 5, 1, 0)  # ожидается 28
spatial_out(14, 5, 1, 0)  # ожидается 10
spatial_out(7, 3, 2, 1)   # ожидается 4
```

Особенно следи за округлением. Если ядро не укладывается в последний участок целиком, этот участок не считается. Поэтому результат нужно округлять вниз, а не до ближайшего целого. В Python для такого вычисления подходит целочисленное деление.

Если все три проверки проходят, функция умеет отвечать на главный вопрос: сколько допустимых позиций займёт ядро вдоль одной стороны изображения.

> 🎒 **На пальцах.** Представь ряд кресел и фотографа, который снимает сразу несколько соседних мест. Он начинает у первого кресла, затем каждый раз отступает на заданный шаг. Кадр, вышедший за край ряда, фотограф не делает. `spatial_out` считает только те остановки, на которых вся группа кресел целиком помещается в кадр.
