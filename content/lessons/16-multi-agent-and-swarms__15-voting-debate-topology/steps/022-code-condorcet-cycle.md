Перед тобой три варианта маршрута: `A`, `B` и `C`. При попарном сравнении `A` лучше `B`, `B` лучше `C`, а `C` лучше `A`. Выбрать «самый сильный» маршрут не получится, но программа должна хотя бы обнаружить замкнутый круг.

Функция `condorcet_cycle` получает бюллетени и ищет трёх разных кандидатов с таким порядком побед: первый обыгрывает второго, второй — третьего, третий — первого. Сам перевес уже умеет считать `pairwise_margin` из [шага 18](#step-18), поэтому повторять подсчёт голосов внутри новой функции не нужно.

Сначала получи кандидатов с помощью функции из [шага 6](#step-6). Затем перебирай тройки разных имён и проверяй три попарных перевеса. Каждый из них должен быть строго положительным. Ноль означает ничью: такая пара не создаёт направленной победы и не замыкает нужный цикл.

Если подходящая тройка найдена, верни её в порядке побед: `(a, b, c)` означает, что `a` обыгрывает `b`, `b` — `c`, а `c` — `a`. Если ни одна тройка не подходит, верни `None`. Не требуй, чтобы найденный цикл включал всех кандидатов: среди пяти вариантов цикл может образоваться только у трёх. И не ищи внутри функции победителя Кондорсе — это отдельная проверка из [шага 20](#step-20).

> 🎒 **На пальцах.** Представь три односторонние дорожки между остановками. Из `A` стрелка ведёт в `B`, из `B` — в `C`, а из `C` — обратно в `A`. Ты начинаешь движение с любой остановки и возвращаешься к ней, не разворачиваясь. `condorcet_cycle` ищет именно такой замкнутый маршрут среди попарных побед.
