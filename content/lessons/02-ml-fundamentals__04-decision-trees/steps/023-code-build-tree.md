Допустим, в узле осталось шесть строк. `best_split` нашла хороший вопрос и разделила их на группы из четырёх и двух строк. Но вернуть только этот вопрос нельзя: каждая группа может потребовать следующего разбиения. Именно здесь отдельные функции из предыдущих шагов складываются в целое дерево.

Тебе нужно написать `build_tree(X, y, depth)`. Сначала проверь условия остановки из [шага 20](#step-20). Если все значения `y` одинаковы, верни лист с этим классом. Если достигнута максимальная глубина или строк слишком мало для нового разбиения, тоже создай лист — теперь с самым частым классом в текущем `y`.

Если строить ветви ещё можно, вызови `best_split` из [шага 17](#step-17). Она должна вернуть признак, порог и выигрыш. Подходящего разбиения может не оказаться: например, все значения признаков совпадают или выигрыш не положительный. В таком случае текущий узел снова становится листом.

Для найденного вопроса раздели данные через `split_dataset` из [шага 15](#step-15). Затем дважды вызови `build_tree`: отдельно для левой и правой групп, каждый раз увеличивая `depth` на единицу. Получившиеся результаты запиши как `left` и `right` внутреннего узла в формате из [шага 21](#step-21).

Обрати внимание: каждый рекурсивный вызов получает только свою часть строк. Если случайно передать исходные `X` и `y`, функция будет снова находить тот же вопрос и не приблизится к листу.

> 🎒 **На пальцах.** Представь диспетчера, который распределяет туристов по двум маршрутам. Он задаёт группе один вопрос, передаёт каждую половину новому диспетчеру и больше ею не занимается. Новый диспетчер повторяет то же действие только со своими туристами. Когда группа уже однородна или слишком мала, вместо следующего вопроса ей сразу назначают конечный маршрут. Так один вызов создаёт узел, а рекурсивные вызовы достраивают его ветви.
