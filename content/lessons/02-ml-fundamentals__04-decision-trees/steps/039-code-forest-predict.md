Три дерева предсказывают классы для двух строк. Первое возвращает `["кот", "собака"]`, второе — `["кот", "кот"]`, третье — `["собака", "собака"]`. Если сложить все шесть ответов в одну корзину, получится ничья. Но лес должен дать отдельный ответ для каждой строки: `"кот"` для первой и `"собака"` для второй.

В этом задании допиши `forest_predict`. Функция получает обученный лес и набор строк `X`, а возвращает по одной итоговой метке для каждой строки.

Сначала вызови `tree_predict` из [шага 25](#step-25) для каждого дерева. Так ты получишь список списков: внутри каждого лежат предсказания одного дерева для всех строк. Затем перебирай позиции строк. Для позиции `i` собери голоса всех деревьев именно с индексом `i`, подсчитай частоту каждой метки и выбери самую частую — это голосование большинства из [шага 38](#step-38).

Главная ловушка здесь — перепутать два направления перебора. Один цикл проходит по строкам, другой собирает ответы деревьев для текущей строки. Если вместо этого подсчитать частоты всех предсказаний сразу, разные объекты начнут влиять друг на друга.

Проверь результат на маленьком примере вручную: число итоговых меток должно совпадать с `len(X)`, а каждое предсказание должно зависеть только от голосов за соответствующую строку.

> 🎒 **На пальцах.** Представь жюри, которое оценивает несколько выступлений. Для первого номера ты складываешь голоса всех судей в одну стопку и выбираешь победившую оценку, затем заводишь новую стопку для второго номера. Если смешать бюллетени разных выступлений, большинство уже ничего не скажет о конкретном участнике.
