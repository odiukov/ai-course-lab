Ты запускаешь модель на цветках iris и видишь accuracy около 0.95. Но этой цифре можно верить только при правильном порядке действий: сначала спрятать часть данных, затем обучить лес и лишь после этого открыть отложенные примеры.

```python
from sklearn.datasets import load_iris
from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import train_test_split

X, y = load_iris(return_X_y=True)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, random_state=42
)

rf = RandomForestClassifier(
    n_estimators=100,
    random_state=42
)
rf.fit(X_train, y_train)

print(rf.score(X_test, y_test))
print(rf.feature_importances_)
```

`X` содержит четыре измерения каждого цветка, а `y` — его вид. `train_test_split` разделяет строки на обучающую и тестовую части. Если дать модели тестовые ответы во время обучения, проверка превратится в подсматривание.

Параметр `n_estimators=100` просит построить сто деревьев, которые голосуют так, как описано в [шаге 38](#step-38). Одинаковый `random_state` позволяет повторить случайное разделение и построение леса с тем же результатом. Это особенно удобно, когда ты меняешь один параметр и хочешь сравнить модели честно.

Метод `score` для классификатора возвращает accuracy на тестовой части. `feature_importances_` содержит MDI-важности из [шага 42](#step-42), поэтому четыре числа соответствуют четырём признакам iris в исходном порядке. Такой лес — удобная первая рабочая модель для табличных данных: градиентный бустинг нередко точнее, но Random Forest обычно требует меньше настройки.

> 🎒 **На пальцах.** Представь экзамен с тренировочными и запечатанными контрольными билетами. На тренировочных ты готовишь сто независимых экспертов, а контрольные открываешь только в конце. Их accuracy показывает, справились ли эксперты с новыми заданиями, а список важностей — какими подсказками они чаще пользовались.
