title: Дерево выбирает лучший вопрос только для текущего узла

Представь, что в текущем узле есть два возможных вопроса. Первый сразу хорошо разделяет строки по классам. Второй сейчас выглядит чуть слабее, зато после него следующие вопросы могли бы привести к очень чистым группам. Какой вариант выберет дерево?

Оно возьмёт первый. Для каждого признака дерево перебирает допустимые пороги, как в [шаге 16](#step-16), оценивает разбиения через information gain из [шага 11](#step-11) и выбирает победителя. Именно этот поиск выполняла функция из [шага 17](#step-17). Но сравнение охватывает только результат одного ближайшего вопроса. Дерево не строит заранее все возможные продолжения и не проверяет, какое из них окажется лучше через несколько уровней.

После выбора строки расходятся по двум дочерним узлам. В каждом из них всё начинается заново: остаётся уже другая часть данных, поэтому снова перебираются признаки и пороги и снова выбирается лучший вопрос именно для этой части.

Такую стратегию называют **жадной**: на каждом ходе она берёт наибольшее улучшение прямо сейчас. Найти лучшее дерево целиком означало бы сравнить огромное количество комбинаций вопросов и порогов; даже для умеренного набора данных такой поиск быстро становится непрактичным. Поэтому дерево может упустить более удачную длинную последовательность, но зато его реально обучить.

Лучший вопрос в узле — это локальный победитель, а не обещание лучшего дерева целиком.

> 🎒 **На пальцах.** Ты собираешь продукты в большом магазине и каждый раз идёшь к ближайшему товару из списка. На каждом отдельном шаге выбор выглядит самым выгодным. Но весь маршрут может оказаться длиннее: иногда стоило сначала пройти чуть дальше, чтобы потом забрать сразу несколько товаров рядом. Дерево действует так же — выбирает ближайшую выгоду, не просчитывая весь маршрут.
