Лес обучен на признаках «возраст», «доход» и «число покупок», но перед тобой десятки узлов из разных деревьев. В одном узле сработал доход, в другом — возраст. Простого подсчёта разбиений недостаточно: вопрос у корня влияет на большее число строк, чем вопрос у самого листа.

Тебе нужно дописать `feature_importance`, которая соберёт вклады всех признаков в один список. Создай по одному нулевому накопителю на каждый признак, затем обойди все деревья леса. Внутри дерева понадобится рекурсивно посетить каждый узел: лист ничего не разделяет, поэтому его пропускай; для обычного узла вычисляй вклад способом из [шага 42](#step-42) и прибавляй результат признаку, записанному в этом узле. После этого продолжай обход обеих дочерних ветвей.

Следи, чтобы вклад попадал именно по индексу признака, а не по номеру дерева или глубине узла. Если при обучении использовались случайные подмножества столбцов, индекс должен указывать на исходный признак во всём наборе данных.

В конце нормализуй накопленные значения: раздели каждое на их общую сумму. Тогда важности сложатся в единицу, и их удобно сравнивать. Отдельно обработай дерево без полезных разбиений: если сумма равна нулю, верни нули, не выполняя деление. Проверь результат на маленьком дереве вручную: признаки, не встретившиеся ни в одном узле, должны сохранить нулевую важность.

> 🎒 **На пальцах.** Представь редактора, который оценивает авторов коллективной статьи. За каждую удачную правку он начисляет баллы автору, но правка вступления весит больше исправления в сноске, потому что её увидят все читатели. `feature_importance` собирает такие баллы по всем версиям статьи, а затем переводит их в доли общего вклада.
