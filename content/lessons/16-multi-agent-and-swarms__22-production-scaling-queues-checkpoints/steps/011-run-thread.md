Запусти один и тот же `thread_id` дважды. Если `run_thread` каждый раз создаёт пустое состояние, уже завершённые действия повторятся. Если функция считает начатый super-step завершённым, она продолжит с повреждённого места. Тебе нужно соединить сохранение из [шага 5](#step-5) и восстановление из [шага 7](#step-7) так, чтобы подтверждённая граница не размывалась.

Сначала вызови `last_checkpoint` для переданного `thread_id`. Если записей нет, возьми начальное состояние и начни с первого super-step. Если чекпоинт найден, восстанови из него состояние, а выполнять начни следующий номер шага — сам сохранённый шаг уже закончен.

Каждый новый super-step обрабатывай в таком порядке:

1. Получи следующее состояние от агента.
2. Полностью заверши вычисление шага.
3. Запиши результат через `append_checkpoint`.
4. Только после успешной записи считай новое состояние текущим.

Это различие легко пропустить: результат в памяти ещё не означает, что он подтверждён. Если агент выбросил исключение или запись чекпоинта не удалась, частичное состояние сохранять нельзя. Пусть ошибка выйдет из `run_thread` наружу — скрывать её и двигать номер шага вперёд опасно.

Проверь функцию на смоделированном падении. В логе должны остаться только полностью завершённые super-step, а повторный вызов с тем же `thread_id` должен начинать работу после последнего из них. Состояния разных `thread_id` при этом не смешиваются. Детали сериализации и повторяемых внешних действий бери из [шага 8](#step-8), не реализуя их заново внутри функции.

> 🎒 **На пальцах.** Представь реставратора, который восстанавливает мозаику по участкам. После законченного участка он ставит отметку в журнале. Рассыпанные рядом камешки ещё не считаются восстановленной частью: если работа прервётся, их соберут заново. `run_thread` действует так же — продолжает после последней отметки и ставит новую лишь тогда, когда участок действительно закончен.
