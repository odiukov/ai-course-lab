У тебя на руках уже два рабочих куска: [шаг 9](#step-9) считает softmax из списка чисел, а [шаг 10](#step-10) объясняет, откуда берётся оценка $s_i = \frac{q \cdot k_i}{\sqrt{d}}$. А вот мостика между ними пока нет. Если ты сейчас передашь в softmax сырые скалярные произведения, получишь числа, которые при $d = 64$ разъезжаются в разы шире, чем надо, — и один токен съест почти всё внимание.

Значит, нужна функция, которая делает ровно этот переход: берёт один запрос `q` и весь список ключей `K` и возвращает список весов — по одному числу на каждый ключ.

Внутри — три действия по порядку. Для каждого ключа посчитать скалярное произведение с `q` (сумма произведений по координатам, как в [шаге 6](#step-6)). Поделить каждое на $\sqrt{d}$, где $d$ — длина вектора `q`, то есть размерность головы, а не количество ключей. Полученный список отдать в свой softmax.

Вычитать максимум тут не надо: это уже живёт внутри softmax из [шага 8](#step-8).

На что смотреть, когда запустишь. Длина результата равна числу ключей — если она равна 64, ты перепутал $N$ и $d$. Сумма весов даёт единицу с точностью до последних знаков (сравнивай с допуском, а не через `==`). Ни один вес не равен нулю — это то самое свойство из [шага 1](#step-1). И проверь смысл: подай `q`, совпадающий с одним из ключей, — этот ключ обязан получить самый большой вес. Если самый большой достался чужому ключу, ошибка в скалярном произведении, а не в softmax.

> 🎒 **На пальцах.** Представь жюри: каждый ключ получает балл от судьи. Сырые баллы — в разных единицах, поэтому их сначала приводят к общей шкале (деление на $\sqrt{d}$), и только потом переводят в доли призового фонда, который всегда равен ста процентам. Твоя функция — секретарь жюри: собрать баллы, привести к шкале, раздать проценты. Победитель после этого обязан остаться тем же, кем был по баллам.
