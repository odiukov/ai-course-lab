  - question: >-
      Ты выбираешь архитектуру: отдельная небольшая модель создаёт черновик, не

    options:

  - question: >-
      При длине черновика 5, доле принятия 0,5 и накладных расходах 0,1 какое
      ожидаемое ускорение даёт расчётная модель урока?
    options:
      - 'Примерно 1,36 раза'
      - 'Примерно 2,27 раза'
      - 'Примерно 3,18 раза'
      - Ровно 5 раз
    correct: 2
    explanation: >-
      Подстановка параметров в расчётную модель даёт отношение 3,5 к 1,1, то
      есть ускорение примерно в 3,18 раза.
  - question: >-
      При малой нагрузке speculative decoding снижает задержку, но при целевой
      высокой одновременности уменьшает throughput. Как следует поступить?
    options:
      - 'Включить режим для всего трафика, поскольку доля принятия не изменилась'
      - Отказаться от сравнения при высокой одновременности
      - >-
        Использовать режим только там, где он проходит требования по
        производительности
      - Продолжать увеличивать длину черновика до восстановления throughput
    correct: 2
    explanation: >-
      Доля принятия сама по себе не гарантирует выигрыша. Режим следует включать
      только для тех нагрузок или сегментов, где итоговые показатели системы
      лучше baseline.
  - question: >-
      Какие данные позволяют обоснованно решить, стоит ли включать speculative
      decoding в продакшене?
    options:
      - Доля принятия на синтетических промптах и скорость draft-головы
      - Средняя доля принятия по всему трафику без сегментации
      - Throughput при небольшой нагрузке и расчётная точка безубыточности
      - >-
        Сравнение с baseline на собственном трафике при целевой нагрузке,
        включая сегментные результаты, пропускную способность и хвост задержки
    correct: 3
    explanation: >-
      Решение принимают по результатам всей системы на репрезентативном трафике
      и целевой нагрузке. Средних значений недостаточно: необходимо проверить
      сегменты и хвост задержки.

Теперь у тебя есть не просто способ посчитать ускорение, а рамка для инженерного решения: сравнить поколения, измерить alpha на своём трафике, проверить целевую одновременность и поставить воротца на throughput и P99. Чаще всего здесь спотыкаются, принимая высокую alpha за автоматическое разрешение на выкат. Вернись к дереву из [шага 38](#step-38) и плану из [шага 39](#step-39): решение принимается по всей цепочке доказательств.
