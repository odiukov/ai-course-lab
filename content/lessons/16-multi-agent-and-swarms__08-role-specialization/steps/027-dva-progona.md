title: Сравниваем верный код и правдоподобный код с неверным поведением
source_anchor: '## Build It'

Ты запускаешь демонстрацию дважды и получаешь странную пару результатов. В первом прогоне Executor выдаёт код по спецификации. Во втором — аккуратный Python без синтаксических ошибок, с понятным именем функции и правдоподобной операцией, но результат вычисляется не так, как потребовал Planner.

На вид артефакты почти равны. Именно поэтому `critic_review` из [шага 24](#step-24) может принять оба: critic оценивает текст и замечает подозрительные конструкции, явные пропуски или несоответствие замыслу. Однако правдоподобность — не доказательство правильного поведения. Строка `return x + 2` выглядит ничуть не менее «программно», чем `return x * 2`; нужную операцию определяет спецификация, а не внешний вид строки.

Различие появляется только при исполнении. `verifier_run` из [шага 26](#step-26) подставляет тестовое значение, получает фактический результат и сравнивает его с ожидаемым. Для верного кода значения совпадают — `pass`. Для правдоподобного, но неверного кода расходятся — `fail`. Здесь verifier не высказывает более убедительное мнение, чем critic. Он приносит другой тип результата: наблюдаемый факт.

Значит, сравнивать нужно не два текста, а два поведения на одном и том же проверочном примере. Код становится верным не тогда, когда хорошо выглядит, а когда делает обещанное.

> 🎒 **На пальцах.** Представь автомат с двумя одинаково аккуратными кнопками: «чай» и «кофе». Надписи ровные, лампочки горят, внутри ничего не гремит — внешний осмотр пройден. Но после нажатия «кофе» один автомат наливает кофе, а другой чай. Узнать, какой работает правильно, можно лишь нажатием: обещание проверяется выдачей, а не качеством наклейки.
