Возьми строку вроде `«Привет, tokenizer!»` и представь неудачный результат: регулярка нашла все нужные участки, но функция вернула сами объекты совпадений. Дальше конвейеру нужны не служебные объекты Python, а обычные строки — куски исходного текста.

Контракт из [шага 17](#step-17) подсказывает две проверки: функция возвращает список строк, а их склейка без разделителя точно восстанавливает вход. Пробелы и пунктуацию нельзя отбрасывать.

Начни с заготовки:

```python
def pre_tokenize(text):
    chunks = []

    for match in GPT2_PATTERN.finditer(text):
        # Извлеки из match совпавший фрагмент
        # и добавь его в chunks.
        ...

    return chunks
```

`finditer(text)` проходит по совпадениям слева направо. На каждой итерации `match` хранит найденный фрагмент и его координаты. Тебе нужен именно текст совпадения целиком — посмотри, какой метод объекта `match` его возвращает.

После реализации проверь не только содержимое списка, но и сохранность входа:

```python
text = "Привет, tokenizer!  42"
chunks = pre_tokenize(text)

print(chunks)
assert "".join(chunks) == text
assert all(isinstance(chunk, str) for chunk in chunks)
```

Не вызывай здесь `normalize`: порядок стадий уже зафиксирован в [шаге 7](#step-7), а границы их ответственности — в [шаге 4](#step-4). `pre_tokenize` получает готовый текст и занимается только разбиением. Если проверка со склейкой проходит, ни один пробел или знак не потерялся.

> 🎒 **На пальцах.** Представь кассира, который разрезает длинную ленту чеков по напечатанным меткам. Метки задаёт `GPT2_PATTERN`, а `finditer` по очереди показывает каждый участок. Твоя функция должна снять с ленты точную копию каждого участка и сложить копии в стопку. Если разложить их обратно подряд, получится исходная лента — без выброшенных пробелов и обрезанных краёв.
