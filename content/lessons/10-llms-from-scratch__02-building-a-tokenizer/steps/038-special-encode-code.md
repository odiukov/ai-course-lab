Возьми строку `Привет<|im_end|>!`: на выходе должны оказаться ID обычного текста, один фиксированный ID маркера и ID восклицательного знака — строго в таком порядке. Простого вызова `encode` из [шага 30](#step-30) для всей строки здесь уже недостаточно: специальный фрагмент должен попасть в результат напрямую.

```python
def encode_with_specials(text, merges, vocab, special_tokens):
    # TODO
```

Сначала примени ту же нормализацию, что используется при обучении и обычном кодировании. Затем вызови `split_on_specials` из [шага 36](#step-36). Он уже отвечает за поиск маркеров, включая правило самого длинного совпадения, поэтому повторять эту логику не нужно.

Дальше проходи по полученным частям слева направо. Для специальной части добавляй ровно один ID из `special_tokens`. Обычную часть передавай существующему `encode` и добавляй все возвращённые им ID. Здесь важна разница между `append` и `extend`: специальный ID — одно число, а результат `encode` — список чисел.

Проверь три случая: строку без маркеров, строку из одного маркера и строку с несколькими маркерами между обычными фрагментами. Пустые обычные фрагменты не должны добавлять ничего, а порядок ID обязан совпадать с порядком частей исходной строки.

> 🎒 **На пальцах.** Представь рукопись, где среди обычных строк стоят сургучные печати. Текст ты отправляешь наборщику, который разбирает его на мелкие литеры. Печать же не разбирают: по её рисунку сразу записывают один номер. `encode_with_specials` идёт по рукописи слева направо и складывает результаты обоих способов обработки в одну последовательность.
