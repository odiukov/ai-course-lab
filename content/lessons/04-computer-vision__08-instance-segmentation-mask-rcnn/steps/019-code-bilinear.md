Ты передаёшь функции дробную точку, например `x=0.6`, `y=0.25`, а массив принимает только целые индексы. Если просто округлить координаты, получится тот же скачок, от которого мы уходили после RoIPool. Поэтому функция должна прочитать четыре соседние клетки и смешать их значения по расстоянию до точки — именно так, как разобрано в [шаге 18](#step-18).

Заготовка может выглядеть так:

```python
def bilinear_sample(feature, x, y):
    """
    feature: карта признаков формы (C, H, W)
    x, y: дробные координаты на карте
    return: значения всех C каналов в точке (x, y)
    """
    pass
```

Сначала найди целые координаты слева, справа, сверху и снизу. Затем вычисли, какую долю пути точка прошла по горизонтали и вертикали. Эти две доли зададут веса четырёх соседей. Смешивать нужно не отдельное число, а сразу значения всех каналов: результат имеет форму `(C,)`.

Особенно внимательно следи за порядком индексов. Координата `x` выбирает столбец, `y` — строку, но обращение к тензору записывается как `feature[:, y, x]`. Ещё одна ловушка появляется у правой и нижней границ: соседний индекс нельзя выпускать за размеры карты.

Для самопроверки возьми одноканальную карту из примера [шага 18](#step-18). В той же дробной точке функция должна вернуть `15.8`. Проверь также точку с целыми координатами: там результат обязан точно совпасть со значением клетки.

> 🎒 **На пальцах.** Представь курьера между четырьмя пунктами выдачи. Чем ближе он к конкретному пункту, тем сильнее этот пункт влияет на расчёт времени доставки. `bilinear_sample` делает такой расчёт для каждого канала карты одновременно. Курьер не перескакивает в ближайший пункт при малейшем движении — доли меняются плавно, а вместе с ними плавно меняется и результат.
