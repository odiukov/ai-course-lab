check:
  - question: >-
      Классификатор должен возвращать только одну допустимую метку, а любой
      дополнительный текст ломает парсер. Какой подход обеспечивает это
      ограничение непосредственно во время генерации?
    options:
      - Добавить в промпт настойчивую просьбу не писать пояснений
      - Снизить температуру модели
      - Применить constrained decoding с набором допустимых меток
      - Повторять запрос после неудачного разбора
    correct: 2
    explanation: >-
      Constrained decoding оставляет доступными только продолжения,
      соответствующие заданному формату. Просьба, низкая температура и повторные
      попытки могут уменьшить частоту ошибок, но не запрещают их.
  - question: >-
      Модель много раз подряд соблюдала инструкцию «верни только JSON». Какой
      вывод из этого обоснован?
    options:
      - Следующий ответ тоже обязательно будет только JSON
      - >-
        Инструкция хорошо направляет модель, но сама по себе не гарантирует
        формат
      - Формат уже стал техническим ограничением декодера
      - Проверку и обработку ошибок теперь можно удалить
    correct: 1
    explanation: >-
      Даже длинная серия корректных ответов подтверждает лишь высокую
      вероятность соблюдения промпта. Пока недопустимые продолжения доступны
      модели, технической гарантии формата нет.
---

Здесь важно не перепутать высокую вероятность послушания с гарантией. Как показал [шаг 3](#step-3), prompting направляет модель, а constrained decoding ограничивает сам набор возможных продолжений. Поэтому фраза «верни только метку» может сработать тысячу раз подряд — и всё равно остаётся просьбой. Технический запрет означает другое: недопустимый ответ не просто маловероятен, а недоступен.

> 🎒 **На пальцах.** Представь турникет в метро. Табличка «проход только по билету» просит соблюдать правило, но человек может пройти мимо. Закрытые створки действуют иначе: без подходящего билета путь физически не открывается. Prompting — табличка; constrained decoding — створки.
