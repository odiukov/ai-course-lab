Пять названий из [шага 12](#step-12) можно выучить наизусть и всё равно не суметь ответить на простой вопрос: а откуда задача стартует? Список состояний — это как список названий улиц. Названия есть, а куда с какой можно повернуть — неизвестно.

Посмотри на схему рядом. Первое, что стоит найти — точку входа. Она одна: запрос с `_meta.task` из [шага 5](#step-5) возвращает номерок, и рядом с ним написано `state: "working"`. Ни в одно другое состояние задача родиться не может.

Теперь посчитай стрелки. Их пять. Четыре выходят из `working`: одна в `input_required`, три — в `completed`, `failed`, `cancelled`. И только одна стрелка идёт обратно: из `input_required` в `working`. Это и есть та единственная петля — сервер посреди работы спросил у пользователя чего-то ещё, получил ответ и вернулся к делу.

Обрати внимание, чего на схеме нет. Нет стрелки из `completed` в `failed`. Нет из `cancelled` куда-либо. Нет прямого перехода из `input_required` сразу в `completed` — сначала обязательно назад в `working`.

Почему это важно тебе как программисту? Потому что схема — не картинка для запоминания, а список разрешённых переходов. Когда ты сядешь писать функцию, которая меняет состояние задачи, каждая стрелка станет одной допустимой парой «откуда → куда», а всё, чего на схеме нет, кодом должно отвергаться.
