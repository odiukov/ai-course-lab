Четыре функции у тебя уже есть, и каждая по отдельности работает. Но попробуй вызвать их вручную — и сразу выясняется, что порядок не свободный. Передашь в `score` сырой JSON вместо флагов — получишь баллы, посчитанные по пустоте. Посчитаешь баллы раньше, чем отсечёшь кандидатов по жёстким требованиям из [шага 22](#step-22), — и лидером окажется фреймворк, который вообще не умеет то, без чего задача не живёт.

Кто должен помнить этот порядок?

Не тот, кто пользуется твоим скриптом. `pick_framework` — единственная дверь: на входе короткое описание задачи, на выходе одна рекомендация. Внутри — конвейер: `normalize_problem` из [шага 15](#step-15) приводит описание к пяти флагам, `shape_of` из [шага 17](#step-17) превращает флаги в форму задачи, `hard_filter` из [шага 23](#step-23) выкидывает тех, кто не проходит по обязательному, и только выжившие идут в `score` из [шага 28](#step-28).

Дальше — два места, где обычно спотыкаются. Первое: после фильтра не осталось никого. Это не ошибка в коде, это честный ответ «ни один из четырёх не подходит», и его надо уметь вернуть словами, а не пустым списком. Второе: два кандидата набрали одинаково. Решай заранее — по приоритету, по алфавиту, всё равно, но детерминированно, чтобы один и тот же вход не давал разные ответы.

И обоснование. Одно предложение, и в нём должен быть назван флаг, который решил дело: не «подходит лучше всего», а «`needs_resume` отсёк остальных трёх». Проверь на шести случаях, которые придумаешь сам, — и один из них пусть будет таким, где не выживает никто.

> 🎒 **На пальцах.** Медкомиссия на права. Кабинеты идут в жёстком порядке, и последний врач ставит подпись только на бланке, где все предыдущие уже отметились. Придёшь к нему первым — он тебя развернёт. А если окулист написал «не годен», дальше вообще идти незачем: справка выдаётся с одной строкой причины. Твой `pick_framework` — та же регистратура: он знает порядок кабинетов, чтобы ученик его не знал.
