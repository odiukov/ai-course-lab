Внутри `step` у тебя есть соблазн обновить всю модель на каждом ранге — результат будет верным, но смысл ZeRO исчезнет. Другой соблазн опаснее: обновить только локальный кусок и оставить остальные параметры старыми. Тогда ранги начнут следующий forward с разными версиями модели.

Собери градиенты параметров в один плоский буфер и дополни его нулями до длины, которая делится на число рангов. Нули важны: они позволяют получить равные куски, не влияя на градиент. После `reduce_scatter` каждый ранг должен получить сумму только для своего куска. Поскольку обучение усредняет градиенты между рангами, раздели эту сумму на `world_size`.

Теперь обновляется именно локальный шард. Используй порядок Adam из [шага 5](#step-5): сначала увеличь счётчик шага, затем обнови локальные `m_shard` и `v_shard`, вычисли поправки смещения и примени изменение к `master_shard`. Проверь две частые ошибки: квадрат градиента нужен только для второго момента, а `eps` прибавляется к корню из исправленного второго момента.

После обновления все ранги обязаны обменяться мастер-шардами через `all_gather`. Склей полученные части, отбрось добавленный хвост и разложи ровно `total` значений обратно по параметрам модели. Так память оптимизатора остаётся разделённой, но перед следующим forward параметры на всех рангах снова совпадают.

> 🎒 **На пальцах.** Представь типографию, где каждому печатнику поручена своя пачка страниц. Он получает правки только для своей пачки и исправляет её у себя. Но книгу нельзя печатать из четырёх несовпадающих черновиков: после правок все обмениваются готовыми пачками и собирают одинаковый полный макет. Лишние чистые листы помогали делить пачки поровну, а в книгу не попали.
