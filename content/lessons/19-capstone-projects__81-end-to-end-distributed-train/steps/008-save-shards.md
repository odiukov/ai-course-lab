Представь: после сбоя на диске лежат четыре файла, по одному на ранг. Все называются правильно, но один оборвался при записи. По имени и размеру ты не докажешь, что внутри именно сохранённое состояние.

Дополни `save_sharded`: для состояния каждого ранга функция должна получить сериализованные байты и вычислить их SHA-256 — цифровой отпечаток содержимого. Записывай байты сначала во временный файл, затем принудительно передавай их операционной системе на сохранение. Только после этого временный файл можно атомарно переименовать в итоговый.

Для каждого шарда собери запись с номером ранга, итоговым именем файла и хешем. Из этих записей составь манифест: в нём должны быть размер распределённого мира, номер шага и полный список шардов. Сам манифест тоже сначала запиши во временный файл и синхронизируй с диском.

Особенно внимательно посмотри на порядок публикации. Итоговые шарды появляются первыми, а `manifest.json` — последним, согласно контракту из [шага 7](#step-7). Иначе читатель может увидеть манифест и решить, что checkpoint готов, хотя часть файлов ещё временная или отсутствует.

Проверь не только возвращаемый словарь. В каталоге должны остаться итоговые файлы без суффикса `.tmp`, а хеш каждого из них должен совпадать с хешем тех байтов, которые действительно лежат на диске. Тогда повреждение перестаёт быть догадкой: оно обнаруживается сравнением отпечатков.

> 🎒 **На пальцах.** Представь лабораторию: каждый образец сначала кладут в пробирку, пломбируют и записывают номер пломбы. Реестр образцов вывешивают лишь после того, как все пробирки заняли свои места. Если пробирку подменили или недоложили, её пломба не совпадёт с реестром. Хеш играет роль пломбы, а манифест — последнего опубликованного реестра.
