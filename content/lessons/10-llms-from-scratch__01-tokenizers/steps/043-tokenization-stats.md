Ты запускаешь токенизатор на трёх коротких текстах и получаешь списки разной длины. Смотреть на них по отдельности неудобно: нужен один набор чисел, по которому можно сравнивать запуски. Этим и займётся `tokenization_stats`.

Для каждого текста вызови `tokenizer.encode(text)`. Затем накопи общее количество токенов и символов, а каждый встретившийся ID отметь в счётчике использования. Важно считать все появления: если ID `42` встретился пять раз, его частота равна пяти, а не одному.

После обхода функция должна подготовить:

- размер `tokenizer.vocab`;
- суммарное число токенов и символов;
- среднее число токенов на символ;
- десять самых употребительных ID вместе с количеством появлений;
- число ID из vocabulary, которые не встретились ни разу.

Плотность и смысл отношения токенов к длине текста уже разобраны в [шаге 42](#step-42). Здесь твоя задача — аккуратно собрать исходные величины. Не декодируй весь текст обратно: для читаемого вывода достаточно взять байты отдельного токена из `tokenizer.vocab` и вызвать `decode("utf-8", errors="replace")`. Режим `replace` не даст статистике упасть на токене, который сам по себе содержит лишь часть многобайтового символа.

Обрати внимание и на пустой набор текстов: деление на ноль не должно ломать функцию. Сначала добейся правильных итоговых счётчиков, затем проверь сортировку самых частых токенов на маленьком примере, где частоты легко пересчитать вручную.

> 🎒 **На пальцах.** Представь библиотекаря, который вечером разбирает формуляры. Он считает не только общее число выданных книг, но и сколько раз выдавался каждый инвентарный номер. Так одна стопка записей превращается в компактный отчёт: сколько было выдач, какие номера встречались чаще и какие остались на полках.
