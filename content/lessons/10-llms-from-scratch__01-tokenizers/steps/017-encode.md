Допустим, токенизатор уже обучен, а ты передаёшь ему строку `"the"`. На входе это ещё не выученный токен, а три UTF-8-байта: `[116, 104, 101]`. Задача `encode` — превратить их в список ID, применив сохранённые склеивания.

Начни с преобразования текста через `text.encode("utf-8")`, а результат преврати в обычный список. Это важно и для неанглийских символов: один символ может занимать несколько байтов.

Затем пройди по `self.merges`. Каждая запись содержит пару текущих ID и ID нового токена. Для каждого такого правила передавай текущий список в `_merge_pair`, написанную в [шаге 11](#step-11), и сохраняй получившийся список для следующей итерации.

Следи за двумя деталями:

- перебирай `self.merges.items()` в порядке добавления правил — почему порядок нельзя менять, разобрано в [шаге 16](#step-16);
- возвращай именно список числовых ID, а не байты и не строку.

Проверь крайние случаи. При пустом `self.merges` функция должна вернуть исходные байты как числа. Пустая строка должна дать пустой список. А для текста с кириллицей результат может содержать больше начальных ID, чем в тексте символов.

Ты не ищешь новые частые пары и не обучаешь токенизатор заново: `encode` лишь воспроизводит уже записанную последовательность решений.

> 🎒 **На пальцах.** Представь мастерскую гирлянд. Сначала перед тобой лежат отдельные лампочки, а рядом — журнал операций: сначала соединить красную с синей, потом получившийся модуль с зелёной. Ты проходишь журнал сверху вниз и каждый раз обновляешь гирлянду. `encode` делает то же самое с байтами и выученными парами.
