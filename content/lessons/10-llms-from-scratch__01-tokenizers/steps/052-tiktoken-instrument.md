Ты запускаешь токенизатор и получаешь список вроде `[3404, 12509, ...]`. Числа настоящие, но глазами по ним трудно понять, где закончился один кусок текста и начался другой. У `tiktoken` можно посмотреть оба представления рядом:

```python
import tiktoken

enc = tiktoken.get_encoding("cl100k_base")

text = "Tokenizers convert text to integers"
tokens = enc.encode(text)

print(f"Tokens: {tokens}")
print(f"Pieces: {[enc.decode([t]) for t in tokens]}")
print(f"Roundtrip: {enc.decode(tokens)}")
```

`get_encoding("cl100k_base")` загружает готовый токенизатор. Метод `encode` превращает строку в список ID. Затем выражение внутри `Pieces` берёт каждый ID `t`, помещает его в одноэлементный список `[t]` и декодирует отдельно. Так ты замечаешь детали, которые скрывают числа: кусок может быть частью слова, а пробел нередко прикрепляется к следующему фрагменту.

Последняя строка декодирует уже всю последовательность. Это быстрая практическая проверка roundtrip из [шага 20](#step-20): собранный текст должен совпасть с исходным.

Есть тонкость с Unicode. Как показано в [шаге 23](#step-23), символ может занимать несколько байтов. Поэтому отдельный токен иногда содержит лишь часть его байтов, и `decode([t])` покажет `�`. Это не обязательно ошибка: соседние токены при совместном `decode(tokens)` могут восстановить символ правильно. Для точного исследования одного ID используй `enc.decode_single_token_bytes(t)` — он вернёт исходные байты без попытки превратить неполный фрагмент в текст.

> 🎒 **На пальцах.** Представь каталог красок: у каждого образца есть номер, например `3404`, и мазок определённого оттенка. Список ID похож на перечень номеров, а `decode([t])` позволяет вынуть один образец и посмотреть на него. Но некоторые оттенки задуманы как слои: по отдельности выглядят странно, а вместе дают нужный цвет.
