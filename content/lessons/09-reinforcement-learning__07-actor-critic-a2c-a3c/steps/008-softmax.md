У актёра получились логиты `[2, 1, 0]`. Передать их механизму выбора действия нельзя: это не вероятности, а их сумма равна трём. Твоя задача — написать функцию `softmax`, которая превратит такой набор в распределение примерно `[0.665, 0.245, 0.090]`, сохранив порядок предпочтений из [шага 7](#step-7).

На вход функция получает одномерный набор логитов, на выходе даёт набор той же длины. Каждое значение должно быть положительным, а их сумма — равняться единице с учётом небольшой погрешности вычислений. Самый большой логит должен получить самую большую вероятность.

Есть ловушка: если сразу вычислять экспоненты для `[1000, 999, 998]`, компьютер может получить переполнение. Сначала вычти из всех логитов максимальный. Набор станет `[0, -1, -2]`, но итоговые вероятности не изменятся: ты одинаково сдвинул все оценки. Затем вычисли экспоненты и раздели каждую на их общую сумму.

Проверь функцию на трёх случаях: одинаковые логиты дают одинаковые вероятности; добавление одного числа ко всем логитам не меняет результат; даже очень большие значения не порождают `Infinity` или `NaN`. Не округляй числа внутри функции — округление годится только для показа результата.

> 🎒 **На пальцах.** Представь три ценника: 1002, 1001 и 1000 рублей. Для сравнения товаров сами тысячи не важны — важна разница между ценами. Ты вычитаешь 1002 и получаешь 0, −1 и −2. Относительное положение ценников сохранилось, зато числа стали удобными. Softmax делает такой же безопасный сдвиг перед превращением оценок в доли.
