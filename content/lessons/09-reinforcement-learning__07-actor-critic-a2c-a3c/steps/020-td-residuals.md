Перед тобой rollout из нескольких переходов: для каждого уже записаны награда, оценка текущего состояния и оценка следующего. Теперь нужно превратить эти три столбца в один — TD residual для каждого шага.

Напиши `td_residuals`, используя правило из [шага 19](#step-19). Функция должна обработать все элементы поэлементно и вернуть массив той же формы, что и входные данные. Здесь не нужен обратный проход, как в `discounted_returns` из [шага 18](#step-18): residual одного перехода не зависит от вычисленного residual соседнего перехода.

Обрати внимание на три детали:

- `gamma` применяется только к оценке следующего состояния;
- текущая оценка вычитается без дисконтирования;
- порядок элементов сохраняется: результат с индексом `t` относится к переходу с тем же индексом.

Если переход завершает эпизод, будущей ценности после него нет. Обычно вызывающий код уже передаёт для такого перехода нулевую оценку следующего состояния. Не подменяй ненулевые значения нулями внутри функции, если её интерфейс не содержит отдельного признака завершения эпизода.

Проверь себя на формах: один переход должен давать одно число, а батч из нескольких переходов — столько же residuals. Ищи не «итог эпизода», а локальное расхождение прогноза критика с тем, что обнаружилось через один шаг.

> 🎒 **На пальцах.** Представь стопку квитанций курьера. В каждой указаны ожидаемая сумма до поездки, фактическая оплата за этот заказ и новая ожидаемая сумма после него. Ты сверяешь каждую квитанцию отдельно: новая информация может показать, что прежний прогноз был занижен или завышен. `td_residuals` превращает всю стопку в список таких локальных поправок, не смешивая соседние поездки.
