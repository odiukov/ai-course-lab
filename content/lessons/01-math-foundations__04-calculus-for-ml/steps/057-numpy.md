С NumPy тот же спуск помещается в десяток строк и работает на всех точках сразу. Это нужно не для красоты: в реальной задаче примеров не пять, а миллионы, и питоновский цикл по каждому из них считался бы часами.

Идея одна: массив вместо перебора. `w * x + b`, где `x` — массив из пяти чисел, даёт сразу пять предсказаний. `pred - y` — сразу пять ошибок. Формулы для градиента из шага 55 не меняются, меняется только то, что теперь их применяют ко всему массиву одной командой, а результат усредняют:

$$L = \frac{1}{n}\sum_{i=1}^{n}(\hat y_i - y_i)^2$$

Здесь $n$ — сколько точек в данных, $\hat y_i$ — предсказание на $i$-й точке, $y_i$ — правильный ответ на ней. Это `np.mean(error ** 2)`. Так же и `dw = np.mean(2 * error * x)`: средний градиент по всем точкам, а не по одной.

```python
for epoch in range(200):
    pred = w * x + b
    error = pred - y
    dw = np.mean(2 * error * x)
    db = np.mean(2 * error)
    w -= lr * dw
    b -= lr * db
```

Ты только что собрал градиентный спуск с нуля. PyTorch считает `dw` и `db` за тебя, но цикл обновления в нём буквально такой же.

> 🎒 **На пальцах.** Вырезать сто одинаковых деталей можно ножницами — по одной, час работы. А можно положить лист под штамп и продавить все сто за один удар. Результат тот же, форма деталей та же, изменилась только машинка. NumPy — этот штамп: одна команда прожимает весь массив чисел разом, вместо того чтобы обходить его поштучно.
