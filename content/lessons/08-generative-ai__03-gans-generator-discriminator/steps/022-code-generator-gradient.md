Представь, что функция получила вероятности `[0.01, 0.4, 0.9]`. Легко по привычке вызвать `binary_cross_entropy_grad` из [шага 10](#step-10), но он возвращает производную по вероятности. Здесь генератору нужен сигнал по **логиту** дискриминатора — числу до сигмоиды. Именно на этом различии мы остановились в [шаге 21](#step-21).

Напиши `generator_loss_grad(d_fake)` так, чтобы она возвращала по одному градиенту для каждого элемента `d_fake`. Для каждой вероятности `p` используй градиент non-saturating loss по логиту, полученный в [шаге 19](#step-19), и учти усреднение по батчу: каждый элемент нужно разделить на количество вероятностей.

Проверь два свойства результата. Во-первых, его длина должна совпадать с длиной `d_fake`. Во-вторых, все градиенты должны быть отрицательными: при градиентном спуске это подтолкнёт логиты вверх, а вместе с ними вырастет вероятность принять подделку за настоящий образец. Чем меньше `p`, тем ближе сила сигнала к единице до деления на размер батча. Защита логарифма здесь не нужна: функция не вычисляет сам логарифм, а работает с уже полученными вероятностями.

> 🎒 **На пальцах.** Представь репетитора, который получает оценки трёх учеников. Тому, у кого почти ноль, нужна самая сильная подсказка; получившему почти максимум — лишь небольшая поправка. Но урок рассчитан сразу на всю группу, поэтому репетитор делит общий вклад между тремя учениками. Так и функция сохраняет отдельный сигнал для каждого примера, одновременно учитывая среднее по батчу.
