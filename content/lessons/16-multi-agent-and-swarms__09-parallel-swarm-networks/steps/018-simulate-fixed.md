Перед запуском у тебя есть четыре воркера и список задач разной длительности. Попробуй заранее раздать задачи поровну: первую — воркеру 0, вторую — воркеру 1 и так далее по кругу. На бумаге распределение выглядит справедливым. Но будет ли одинаковым время работы?

Реализуй режим жёсткого назначения из [шага 17](#step-17). Сначала сформируй для каждого воркера отдельный список задач. После этого запусти четыре потока: каждый поток должен обрабатывать только свой список и не может забирать чужие задачи, даже если освободился раньше. Длительность обработки имитируй так же, как в последовательном режиме, чтобы сравнение оставалось честным.

Замерь время по стенным часам: запусти таймер перед стартом потоков и останови после завершения последнего. Также сохрани число задач, выполненных каждым воркером. Удобнее выделить каждому воркеру собственную ячейку результата — тогда потоки не будут одновременно изменять один общий счётчик.

Посмотри сразу на два результата. Количество задач у воркеров может оказаться почти одинаковым, а время их занятости — сильно различаться. Общий прогон закончится лишь тогда, когда завершит работу самый медленный поток. Если остальные уже закончили свои списки, они просто ждут.

Именно это противоречие тебе нужно увидеть: равное число задач ещё не означает равномерную нагрузку.

> 🎒 **На пальцах.** Четырём преподавателям заранее выдали по пять контрольных. Троим достались короткие тесты, а четвёртому — пять больших сочинений. Первые быстро освободились, но брать работы из чужой пачки им запрещено. Формально нагрузку разделили поровну — по пять работ. Фактически вся проверка закончится вместе с последним сочинением.
