После уменьшения сетки из [шага 6](#step-6) в одной ячейке может лежать вектор вроде \((0{,}7,\,-0{,}1,\,0{,}4)\). Это не номер и не готовый токен, а набор признаков. Но авторегрессионной модели нужны дискретные варианты: первый, второй, третий — как слова из конечного словаря.

Здесь появляется **квантование**: представь, что ты подбираешь к ткани ближайший образец из каталога. В codebook хранится ограниченный набор векторов-образцов одинаковой длины. Для вектора ячейки токенизатор измеряет расстояние до каждого образца. Допустим, до элементов №12, №47 и №81 получились расстояния \(0{,}6\), \(0{,}2\) и \(0{,}9\). Ближайший — №47, поэтому исходный вектор заменяется индексом 47.

Важно различать две вещи. В сетке токенов сохраняется **индекс**, то есть целое число 47. А когда понадобится восстановить признаки, по этому индексу из codebook достанут сам вектор №47. Он обычно не совпадает с исходным вектором точно — это ближайшее доступное приближение. Чем удачнее обучен codebook, тем меньше такая потеря.

Операция повторяется независимо для каждой ячейки выбранной сетки. В итоге непрерывная сетка признаков превращается в сетку целых чисел, а каждый её элемент получает значение из общего словаря, введённого в [шаге 5](#step-5).

> 🎒 **На пальцах.** Ты приносишь в магазин кусочек ткани необычного бирюзового оттенка. В каталоге нет бесконечного числа цветов, поэтому продавец прикладывает образцы и выбирает ближайший — например, «цвет №47». В заказ записывают не сам оттенок твоего кусочка, а номер 47. Часть точности теряется, зато теперь любой участник процесса понимает один и тот же конечный набор номеров.
