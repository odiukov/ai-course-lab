Ты запускаешь генератор для масштабов \(1 \times 1\), \(2 \times 2\), \(4 \times 4\) и \(8 \times 8\). Легко по привычке написать два вложенных цикла: по масштабам и по каждой позиции сетки. Тогда последний масштаб потребует 64 последовательных сэмплирования — и преимущество VAR исчезнет.

Напиши функцию генерации пирамиды иначе. Она должна обходить только список масштабов. На каждой итерации передавай трансформеру токены всех уже готовых, более грубых сеток. Модель возвращает логиты для каждой позиции текущего масштаба. Преврати их в вероятности, выбери по одному индексу codebook для каждой позиции и сохрани результат как новую двумерную сетку.

Главная деталь: выбор индексов текущей сетки выполняется одной векторной операцией. Например, для масштаба \(8 \times 8\) форма результата должна сразу содержать 64 токена, а не пополняться по одному. Это соответствует блочной причинности из [шага 21](#step-21): позиции одного масштаба не зависят друг от друга, но весь масштаб зависит от предыдущих.

После завершения цикла передай собранный список сеток функции мультимасштабной детокенизации из [шага 16](#step-16), а полученный латент — декодеру VAE. Проверь две вещи: число обращений к трансформеру совпадает с числом масштабов, а формы сохранённых сеток последовательно равны заданным размерам.

Ищи внутренний цикл по строкам или столбцам: если он сэмплирует токены по одному, генератор снова стал растровым.

> 🎒 **На пальцах.** Представь фотолабораторию с четырьмя проявочными ваннами. В первой одновременно появляется один крупный участок снимка, во второй — сразу четыре, затем шестнадцать и шестьдесят четыре. Ты переносишь результат из ванны в ванну, но не проявляешь каждый пиксель отдельно. Поэтому этапов четыре, хотя на последнем этапе возникает сразу целая сетка деталей.
