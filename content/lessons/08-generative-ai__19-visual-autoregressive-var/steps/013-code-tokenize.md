Ты запускаешь токенизацию латента размером \(8 \times 8\) на масштабах \(1 \times 1\), \(2 \times 2\), \(4 \times 4\) и \(8 \times 8\). Если каждый раз квантовать исходный латент, все четыре сетки будут пытаться описать одну и ту же картинку. Детали добавятся, но разделения работы между масштабами не получится.

Функция должна хранить отдельную переменную `residual` — остаток, который ещё не удалось представить. Вначале это весь латент. Затем для каждого масштаба она выполняет один проход:

1. Уменьшает текущий остаток до нужного размера функцией из [шага 7](#step-7).
2. Получает индексы ближайших элементов общей кодовой книги, используя логику из [шага 11](#step-11).
3. Сохраняет эту сетку индексов в результирующий список.
4. По индексам достаёт из codebook векторы, увеличивает их до исходного размера латента функцией из [шага 9](#step-9) и вычитает получившийся вклад из `residual`.

Обрати внимание: вычитать нужно не индексы токенов — это просто номера, — а соответствующие им векторы codebook. И увеличивать вклад каждого масштаба нужно до размера исходного латента, иначе его форма не совпадёт с формой остатка.

На выходе проверь две вещи: размеры сохранённых сеток должны совпадать со списком масштабов, а `residual` после каждого прохода должен содержать именно необъяснённую часть, а не заново исходный латент. Если случайно переинициализировать его внутри цикла, мультимасштабная токенизация незаметно превратится в несколько независимых квантований.

> 🎒 **На пальцах.** Представь художника, который печатает изображение несколькими прозрачными трафаретами. После первого отпечатка ты сравниваешь лист с оригиналом и готовишь следующий трафарет только для недостающих пятен. Если каждый раз смотреть на чистый лист, трафареты начнут дублировать друг друга. Переменная `residual` — это твой постоянно обновляемый список того, что ещё не попало на бумагу.
