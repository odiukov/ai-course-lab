Ты дошёл до сетки \(8 \times 8\): нужно выбрать сразу 64 кода. Можно снова идти по клеткам по очереди, но тогда вернётся проблема растровой авторегрессии из [шага 1](#step-1): первые решения не увидят последующих. VAR поступает иначе — предсказывает весь новый масштаб за один проход.

Перед этим трансформер получает уже сгенерированные более грубые сетки. Например, для масштабов \(1 \times 1\), \(2 \times 2\), \(4 \times 4\) и \(8 \times 8\) последний масштаб опирается на \(1+4+16=21\) предыдущий токен. Каждый из 64 новых токенов видит все эти 21 токен, но не видит ни соседей своего масштаба, ни будущих масштабов.

Получается причинность не «слева направо», а «от грубого к подробному». На первом масштабе контекстом служит специальный стартовый токен. Затем модель выдаёт для каждой клетки следующей сетки распределение вероятностей по кодам общей кодовой книги. При обучении эти распределения сравниваются с правильными токенами \(z_k\) с помощью cross-entropy. При генерации из них выбираются коды, весь готовый масштаб добавляется в контекст — и начинается следующий проход.

Так 64 решения последнего масштаба требуют одного прохода, а не цепочки из 64 зависимых шагов: глобальная структура уже пришла снизу по пирамиде.

> 🎒 **На пальцах.** Представь редакцию, выпускающую всё более подробные версии афиши. Сначала утверждают одну главную тему, затем крупные блоки, потом мелкие подписи. Все авторы подписей работают одновременно: каждый видит утверждённые ранние версии, но не черновики коллег своего этапа. Когда весь комплект подписей готов, он становится основой для следующего, ещё более подробного выпуска.
