  Генерация последовательно обходит масштабы, но сэмплирует все позиции текущей
  сетки параллельно

На экране появляется сетка \(8 \times 8\): 64 новых токена. Можно подумать, что трансформер теперь обязан выбрать их по очереди — сначала левый верхний, затем соседний и так далее. Тогда один этот масштаб потребовал бы 64 вызова сети, и преимущество VAR почти исчезло бы.

Но блочная маска из [шага 21](#step-21) устроена иначе. Каждая из 64 позиций видит все уже созданные, более грубые масштабы — и не видит другие позиции своей сетки. Поэтому ни одной позиции не приходится ждать соседей: трансформер за один вызов сразу выдаёт распределение вероятностей для всех 64 мест. Из каждого распределения сэмплируется токен, и вся сетка возникает параллельно.

Последовательность сохраняется только между масштабами. Сначала модель создаёт сетку из 1 токена, затем из 4, потом из 16, из 64 и так далее. Новый масштаб можно начать лишь после предыдущего, потому что именно предыдущие сетки дают ему глобальный контекст. Если масштабов десять, потребуется десять вызовов трансформера — независимо от того, сколько позиций находится в последней сетке. Для сравнения, обычная растровая авторегрессия потратила бы 64 последовательных вызова только на 64 токена последнего масштаба.

Значит, VAR ждёт не каждую следующую позицию, а только следующий уровень детализации.

> 🎒 **На пальцах.** Представь шахматный турнир из десяти туров. Начать второй тур нельзя, пока не закончился первый: результаты определяют состав следующих партий. Но внутри одного тура все пары играют одновременно — одна партия не ждёт соседнюю. Масштабы похожи на туры, а позиции сетки — на партии: между турами есть очередь, внутри тура её нет.
