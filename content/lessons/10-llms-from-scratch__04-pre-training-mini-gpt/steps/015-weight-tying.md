Ты проверяешь таблицу параметров и замечаешь странность. Для чтения токенов есть матрица эмбеддингов размером 50 257 на 768 — это около 38,6 миллиона чисел. Но в конце модели тоже нужно получить 50 257 логитов, по одному для каждого возможного следующего токена. Неужели там спрятана ещё одна такая же огромная матрица?

В GPT-2 её нет. Одна и та же матрица работает в двух направлениях.

На входе всё происходит как в [шаге 9](#step-9): по ID токена модель берёт соответствующую строку из матрицы. Например, ID 314 выбирает строку 314 — вектор из 768 чисел.

На выходе модель получает итоговый вектор из 768 чисел и сравнивает его со всеми 50 257 строками той же матрицы. Чем лучше он совпадает с вектором конкретного токена, тем выше логит этого токена. Матрицу при этом используют как бы повёрнутой: новых чисел не появляется.

Такой приём называется **weight tying**, то есть связывание весов. Без него отдельная выходная проекция добавила бы ещё примерно 38,6 миллиона параметров. Но дело не только в экономии: токен учится жить в едином пространстве — его строка помогает модели и понять токен на входе, и выбрать его как продолжение на выходе.

> 🎒 **На пальцах.** Представь каталог из 50 257 карточек. Когда посетитель называет номер, ты достаёшь нужную карточку и читаешь описание из 768 признаков. Позже тебе приносят новое описание, и ты прикладываешь его ко всем карточкам, выбирая самые похожие. Второй каталог не нужен: те же карточки служат и для поиска по номеру, и для поиска по сходству.
