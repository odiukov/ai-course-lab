Перед тобой логиты для последней позиции: один высокий, несколько средних и тысячи почти бесперспективных. Взять максимум легко, но тогда одинаковый контекст всегда продолжится одинаково. Твоя функция `sample_next_token` должна уметь провести настоящий розыгрыш среди допустимых кандидатов и вернуть один token ID.

На вход она получает одномерный массив логитов и настройки генерации. Сначала обработай особый случай: при `temperature == 0` сразу верни индекс максимального логита. Делить на ноль нельзя, да и случайный выбор здесь не нужен.

При положительной temperature раздели логиты на неё, как в [шаге 51](#step-51). Затем передай результат в написанную на [шаге 53](#step-53) функцию `top_k_top_p`: она оставит подходящих кандидатов, а исключённым назначит `-inf`. После этого преврати отфильтрованные логиты в вероятности стабильным softmax из [шага 17](#step-17) и выбери один индекс случайно, используя эти вероятности как веса.

Обрати внимание на три детали:

- исходный массив лучше не изменять на месте;
- вероятности перед выбором должны суммироваться примерно в единицу;
- результатом должен быть один целый token ID, а не массив вероятностей или логит.

Для проверки зафиксируй генератор случайных чисел. Тогда повторный запуск с теми же входами даст воспроизводимый результат, и случайность не будет маскировать ошибку в вычислениях.

> 🎒 **На пальцах.** Представь барабан с лотерейными билетами. Логит определяет, сколько копий каждого билета положить внутрь. Temperature меняет разницу между их количествами, фильтрация убирает лишние номера, а softmax переводит оставшиеся веса в доли. `sample_next_token` встряхивает барабан и вытаскивает ровно один билет — token ID.
