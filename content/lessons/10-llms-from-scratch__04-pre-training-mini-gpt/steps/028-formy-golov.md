Ты смотришь на `Q` после проекции: форма `(batch, seq_len, 768)`. Внутри каждого токена уже лежат данные для 12 голов из [шага 27](#step-27), но пока они упакованы в одну длинную строку. Если сразу считать attention, модель не увидит границу между головами.

Первое движение — `reshape`: форма становится `(batch, seq_len, 12, 64)`. Последние 768 чисел не пересчитываются и не исчезают: они лишь делятся на 12 последовательных групп по 64. Теперь у каждого токена явно есть отдельный кусочек для каждой головы.

Но возникает неудобство: рядом по-прежнему сгруппированы токены, а attention должен запускаться независимо для каждой головы. Поэтому `transpose(0, 2, 1, 3)` меняет порядок осей:

`(batch, seq_len, 12, 64)` → `(batch, 12, seq_len, 64)`.

Теперь можно выбрать одну голову и получить для неё цельную матрицу всех токенов формы `(seq_len, 64)`. Именно на таких матрицах параллельно работают 12 голов.

После attention движения повторяются в обратную сторону: `transpose` возвращает порядок `(batch, seq_len, 12, 64)`, а `reshape` склеивает 12 результатов обратно в `(batch, seq_len, 768)`. Количество чисел всё время одинаково — меняется только то, какие оси считаются соседними.

> 🎒 **На пальцах.** Представь длинную ленту из 768 деталей для каждого робота. Сначала ты раскладываешь её по 12 кассетам, по 64 детали в каждой. Затем поворачиваешь стойку так, чтобы перед тобой оказались сразу одинаковые кассеты всех роботов. После работы возвращаешь стойку обратно и соединяешь кассеты каждого робота в одну ленту. Детали те же — изменилась только организация рабочего места.
