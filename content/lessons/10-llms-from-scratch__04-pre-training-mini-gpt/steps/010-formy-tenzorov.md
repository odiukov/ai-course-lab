Ты запускаешь модель на 4 последовательностях по 128 токенов и видишь форму `(4, 128)`. Но после первого слоя появляется `(4, 128, 768)`. Откуда взялась третья ось — и что теперь означает каждое число?

Первые две оси сохраняют понятный адрес: **какая последовательность в батче** и **какая позиция внутри неё**. Сначала по этому адресу лежит один token ID. Затем таблица эмбеддингов заменяет ID вектором из 768 чисел — внутренним представлением токена. Поэтому адрес становится трёхчастным: последовательность, позиция, компонент вектора.

Позиционные эмбеддинги тоже имеют форму `(4, 128, 768)`. Это важно: складывать можно только элементы с совпадающими адресами. После сложения форма не меняется.

Дальше тензор проходит через 12 трансформерных блоков. Каждый блок перерабатывает содержимое 768 чисел для каждой позиции, учитывая предыдущие позиции, но возвращает тензор той же формы. Финальная нормализация тоже сохраняет `(4, 128, 768)`.

Лишь линейная голова заменяет внутренний вектор каждой позиции набором из 50 257 логитов: получается `(4, 128, 50257)`. Как обсуждалось в [шаге 9](#step-9), softmax превращает эти логиты в вероятности, не меняя форму. Значит, по любому адресу «последовательность + позиция» модель выдаёт отдельное распределение по всему словарю.

> 🎒 **На пальцах.** Представь склад с 4 стеллажами, на каждом по 128 ячеек. Сначала в ячейке лежит одна бирка с ID. Затем бирку заменяют папкой из 768 листов. Все 12 отделов переписывают содержимое папки, но не добавляют ячеек. В конце папку заменяют каталогом из 50 257 оценок — по одной для каждого возможного следующего токена.
