Ты запускаешь батч из 4 последовательностей по 128 токенов. На входе это всего 512 token IDs — 512 целых чисел. Но сразу после поиска эмбеддингов каждый ID заменяется вектором из 768 чисел. Теперь модель одновременно держит уже \(4 \times 128 \times 768 = 393\,216\) чисел.

Здесь легко сделать неверный вывод: будто все следующие слои продолжают раздувать данные. Посмотри на визуализацию внимательнее. Двенадцать трансформерных блоков меняют значения, но сохраняют форму \(4 \times 128 \times 768\). Числа проходят сложные преобразования, однако их количество остаётся прежним.

Резкий скачок происходит ближе к выходу. Для каждой из 512 позиций модель создаёт по одному логиту для каждого из 50 257 токенов словаря: получается \(4 \times 128 \times 50\,257 = 25\,731\,584\) числа. Softmax превращает их в вероятности, не меняя количества.

Важно: это не размер модели и не объём обучающих данных. Мы считаем временные числа, возникающие при одном проходе конкретного батча, — их ещё называют активациями. Параметры из [шага 2](#step-2) хранятся в модели постоянно, а эти миллионы значений появляются для вычисления результата и затем освобождают память. Поэтому даже небольшой вход способен потребовать много рабочей памяти.

> 🎒 **На пальцах.** Представь 512 багажных бирок. Сканер превращает каждую бирку в анкету из 768 полей — выходит 393 216 заполненных ячеек. Несколько проверок исправляют содержимое анкет, но не добавляют полей. В финале для каждой бирки печатается лист с 50 257 возможными категориями багажа — и рабочих чисел внезапно становится почти 26 миллионов.
