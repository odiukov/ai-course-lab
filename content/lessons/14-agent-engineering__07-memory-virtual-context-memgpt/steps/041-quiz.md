  - question: >-
      Ты запускаешь агента с большим окном, но без внешней памяти, и агента с
      маленьким окном, у которого есть архив с поиском. Клиент возвращается
      через неделю с продолжением разговора. Кто справится?
    options:
      - 'Тот, у кого большое окно: в него влезает вся прошлая переписка'
      - >-
        Тот, у кого маленькое окно и архив: он достанет прошлую неделю поиском,
        а большое окно всё равно начинает новую сессию с пустого входа
      - >-
        Оба одинаково: размер окна на новую сессию не влияет, а архив только
        замедляет ответ
    correct: 1
    explanation: >-
      Большое окно лечит только переполнение. Новая сессия стартует пустой
      независимо от ёмкости: между вызовами модель не хранит состояния. Достать
      прошлое можно лишь из внешнего хранилища и вставить во вход текущего
      вызова.
  - question: >-
      Агент посреди ответа вызвал archival_search. Что происходит дальше по
      механике подкачки?
    options:
      - >-
        Агент останавливает генерацию, рантайм ищет в архиве, найденное
        приезжает в следующий ход как наблюдение, и агент продолжает уже с ним
      - 'Агент сам читает архив внутри того же хода, ничего не прерывая'
      - 'Найденное дописывается в core memory навсегда, чтобы больше не искать'
    correct: 0
    explanation: >-
      Вызов памяти работает как прерывание: ход обрывается, рантайм выполняет
      операцию, результат вклеивается в следующий ход. Модель ничего не читает
      сама — она умеет только просить.
  - question: >-
      В core memory записано «клиент живёт в Казани». Клиент говорит, что
      переехал в Самару. Что делаешь?
    options:
      - >-
        core_memory_append: добавляешь строку про Самару, старая пусть лежит
        рядом
      - 'archival_insert: кладёшь новый факт в архив, core не трогаешь'
      - >-
        core_memory_replace: меняешь старую строку на новую, чтобы в промпте не
        было двух противоречащих фактов
    correct: 2
    explanation: >-
      Core печатается в каждом промпте целиком. Дописывание оставит там два
      города сразу, и модель будет выбирать между ними непредсказуемо.
      Семантический факт при изменении заменяют, а не дополняют.
  - question: >-
      Через месяц работы выясняется, что кто-то подсунул агенту вредную
      постоянную заметку, и она всплывает при каждом вспоминании. Почему её так
      трудно убрать?
    options:
      - Потому что записи в архиве технически нельзя удалять
      - >-
        Потому что у записей не сохранили происхождение (session_id и номер
        хода) — непонятно, какие именно строки пришли из заражённого разговора
      - >-
        Потому что core memory всегда важнее архива, и заметка перезапишется
        обратно
    correct: 1
    explanation: >-
      Обнаружить отравление можно, а отозвать адресно — нет: без пометок о
      происхождении остаётся либо чистить всё хранилище, либо жить с заражением.
      Поля происхождения проставляются в момент записи, задним числом их не
      восстановить.

Урок начинался с простого наблюдения: окно кончается тремя разными способами — обрезка, размывание, забывание после перезапуска ([шаги 2](#step-2)–[4](#step-4)). Дальше ты сам собрал каркас, который на это отвечает: два уровня, пять инструментов, подкачка через прерывание.

Что понадобится дальше в курсе — не названия из таблицы, а различения. Что кладут в core, а что в архив. Почему прошлые ходы искать отдельно от архива. Почему без session_id заражённую память нечем стереть.

Спотыкаются обычно на двух местах. Первое: путают «больше окно» с «есть память» — это разные болезни и разные лекарства ([шаг 5](#step-5)). Второе: думают, что агент читает архив сам, в том же ходу. Он встаёт, достаёт рантайм, результат приезжает следующим ходом.

Держи в голове одну связку: прерывание — это механизм, инструмент памяти — то, что этим механизмом вызывают. Всё остальное вешается на неё.
