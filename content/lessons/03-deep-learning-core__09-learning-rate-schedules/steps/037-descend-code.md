Ты запускаешь спуск на 100 шагов, но одного значения learning rate теперь нет: на каждом шаге расписание может вернуть новое. Функция `descend` должна связать расписание и обновление параметров в один цикл.

Посмотри на заготовку функции и собери такую последовательность действий:

1. Начни с переданной стартовой точки и сохрани её в историю.
2. Для каждого номера шага вызови расписание и получи текущий learning rate.
3. Вычисли градиент именно в текущей точке.
4. Обнови все координаты по правилу из [шага 36](#step-36).
5. Сохрани новую точку, чтобы после цикла вернуть весь пройденный путь.

Здесь легко допустить сдвиг на один шаг: расписание должно впервые вызываться с номером `0`, а история — содержать стартовую точку ещё до первого обновления. Поэтому после `N` обновлений в ней окажется `N + 1` точек.

Если параметров несколько, сначала вычисли весь градиент в старой точке и только потом меняй координаты. Иначе вторая координата будет обновляться уже с учётом изменённой первой, и это окажется другим алгоритмом.

> 🎒 **На пальцах.** Представь курьера с пачкой из 100 карточек. На каждой карточке указана длина следующего перехода. Курьер отмечает старт на карте, читает карточку №0, определяет направление по текущему месту, делает переход и ставит новую отметку. Если сначала пойти, а потом прочитать карточку, вся нумерация маршрута съедет.
