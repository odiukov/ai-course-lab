Ты запускаешь обучение на 1 000 шагов и выбираешь `lr_0 = 0.01`. Теперь функции будут передавать разные номера шага: `0`, `1`, `250`, `999`. Задача `constant_schedule` — каждый раз возвращать `0.01`, не подстраивая результат под номер шага.

Сделай внешнюю функцию, которая получает `lr_0` и создаёт расписание. Получившееся расписание должно принимать один аргумент — номер текущего шага `t`. Внешняя функция как бы запоминает выбранный learning rate, поэтому позднее расписанию достаточно вернуть сохранённое значение.

Номер шага здесь нужен для общего интерфейса: другие расписания тоже будут получать `t`. В constant schedule этот аргумент намеренно не влияет на ответ — именно такое поведение описано в [шаге 5](#step-5).

Проверь функцию на нескольких далёких друг от друга шагах. Если при `lr_0 = 0.01` вызовы для `t = 0`, `t = 50` и `t = 999` дают одно и то же число, расписание ведёт себя правильно. Частая ошибка — вернуть значение сразу из `constant_schedule`. Тогда получится число, а не функция, которую обучение сможет вызывать на каждом шаге.

Ты строишь не один ответ, а маленький механизм, выдающий этот ответ снова и снова.

> 🎒 **На пальцах.** Представь автомат, который печатает билеты по фиксированной цене. При настройке ты вводишь цену 2 евро, а затем покупатели нажимают кнопку в разное время. Автомат знает номер покупки, но цену по нему не меняет: первый, пятидесятый и тысячный билет стоят одинаково. `constant_schedule` настраивает такой автомат, а созданное расписание печатает очередную неизменную цену.
