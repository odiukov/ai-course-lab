Ты получил первые пять результатов поиска по фотографии кружки:

```text
["cup", "bowl", "cup", "plate", "cup"]
```

Нужно превратить этот список в одно число. Напиши `precision_at_k`, которая принимает ранжированные метки, правильную метку и `k`. Функция должна смотреть только на первые `k` позиций, сравнивать каждую метку с правильной и считать долю совпадений по правилу из [шага 33](#step-33).

Для примера выше при `k = 5` правильны три результата, поэтому функция должна вернуть `0.6`. При `k = 2` правильный только один из двух — результат будет `0.5`. Обрати внимание: один и тот же список даёт разные значения при разных `k`, потому что меняется рассматриваемая верхушка выдачи.

Самое частое место ошибки — случайно посчитать совпадения во всём списке. Сначала ограничь результаты первыми `k`, и лишь затем проверяй метки. Возвращай число с плавающей точкой, а для некорректного `k`, например нуля или отрицательного значения, явно выбрасывай ошибку. Также договорись, что список содержит не меньше `k` результатов: тогда знаменатель остаётся именно `k`, без скрытой подмены.

Проверь функцию хотя бы на трёх случаях: все первые результаты правильные, ни одного правильного и несколько правильных вперемешку. Если они дают соответственно `1.0`, `0.0` и промежуточное значение, подсчёт работает как задумано.

> 🎒 **На пальцах.** Представь витрину пекарни с пятью булочками на верхней полке. Ты ищешь круассаны и видишь там три круассана, слойку и маффин. Чистота этой полки — три из пяти. Булочки на нижних полках сейчас не участвуют: если начать считать и их, ты уже измеряешь не первые пять позиций, а совсем другую выдачу.
