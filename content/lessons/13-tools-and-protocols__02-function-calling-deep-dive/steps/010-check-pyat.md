  - question: >-
      Обёртка уже объявляет инструменты, задаёт режим их выбора, разбирает
      вызовы и возвращает результаты. Какой обязательный элемент общей структуры
      пропущен?
    options:
      - 'Идентификатор, связывающий результат с конкретным вызовом'
      - Отдельное описание температуры для каждого инструмента
      - Повторное объявление входной схемы вместе с результатом
      - 'Системное сообщение, запрещающее обычный текст'
    correct: 0
    explanation: >-
      Пропущен call id. Он позволяет указать, результатом какого именно вызова
      является возвращённое значение.
  - question: >-
      Модель одновременно запросила погоду для нескольких городов, но обёртка
      удалила идентификаторы вызовов. Какова основная проблема?
    options:
      - 'Нельзя надёжно определить, какому вызову соответствует каждый результат'
      - Модель автоматически отменит все вызовы
      - Входные схемы инструментов перестанут проходить проверку
      - Провайдер обязательно выполнит только первый вызов
    correct: 0
    explanation: >-
      Без идентификаторов результаты теряют явную связь с запросами. Порядок
      обработки может измениться, поэтому полагаться только на позицию
      результата небезопасно.

Пять пунктов с бланка из [шага 8](#step-8) выглядят одинаково обязательными, но на практике четыре из них ты напишешь сам, даже не задумываясь: инструменты объявить надо, выбор инструмента задать надо, вызов разобрать надо, результат вернуть надо. А вот пятый легко проглядеть — пока ты гоняешь один инструмент за раз, всё работает и без него.

Спотыкаются обычно там, где вызовов становится два. Проверь себя: сумеешь ли ты, глядя на чужую обёртку, сказать, какой графы не хватает и когда это рванёт.
