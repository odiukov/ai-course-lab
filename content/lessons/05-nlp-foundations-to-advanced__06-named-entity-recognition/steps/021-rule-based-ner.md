Ты подаёшь функции список `["Apple", "launched", "iPhone", "in", "France"]`. На выходе должен появиться список той же длины: `["B-ORG", "O", "B-PRODUCT", "O", "B-GPE"]`. Каждый входной токен получает ровно одну метку на той же позиции.

Дополни `rule_based_ner(tokens)`. Создай пустой список меток и перебери токены по порядку. Для каждого токена проверь точное вхождение сначала в `ORG_GAZETTEER`, затем в `GPE_GAZETTEER`, затем в `PRODUCT_GAZETTEER`. При совпадении добавляй соответственно `B-ORG`, `B-GPE` или `B-PRODUCT`; если совпадения нигде нет — `O`.

Почему везде `B-`, а не `I-`? Здесь каждая найденная запись считается отдельной однословной сущностью, поэтому она сразу начинается и заканчивается. Значение этих префиксов можно освежить в [шаге 6](#step-6).

Следи за двумя деталями: используй исходный регистр токена и добавляй только одну метку за итерацию. В конце верни накопленный список. Проверь себя: для любого входа число меток должно совпадать с числом токенов.

> 🎒 **На пальцах.** Представь сортировщика писем с тремя списками адресатов: компании, страны и продукты. Он берёт очередной конверт, сверяет надпись со списками и ставит один подходящий штамп. Если надписи нигде нет, конверт получает нейтральную отметку `O`. Главное — после каждого конверта на ленте остаётся ровно один штамп.
