title: LLM начинает NER без обучения через схему типов и структурированный ответ

Ты отправляешь модели фразу «Мария Волкова перешла из Альфа Банка в Ozon» и получаешь уверенный ответ: Мария — человек, Альфа Банк — организация, Ozon — компания. Но что делать с типами «организация» и «компания»? Для человека они близки, а для таблицы это два разных значения.

Поэтому перед текстом ты даёшь модели схему типов — небольшой договор о допустимых категориях, например `PER`, `ORG` и `LOC`, с кратким пояснением каждой. Модель не обучается на новых размеченных данных: она получает правила прямо в запросе и выполняет NER в режиме zero-shot, то есть без примеров решения этой конкретной задачи.

Одних названий типов мало. Нужно договориться и о форме ответа. Ты просишь вернуть JSON — стандартизированную запись с полями, похожую на заполненный электронный бланк:

```json
{
  "entities": [
    {"text": "Мария Волкова", "type": "PER"},
    {"text": "Альфа Банк", "type": "ORG"},
    {"text": "Ozon", "type": "ORG"}
  ]
}
```

Границы и тип сущности здесь означают то же, что в [шаге 1](#step-1), но теперь модель сразу укладывает результат в структуру, которую может прочитать программа. Схема ограничивает смысл меток, а формат ограничивает способ их записи. Без первого модель импровизирует с категориями; без второго добавляет пояснения, списки и лишний текст. Хороший zero-shot-запрос фиксирует оба договора.

> 🎒 **На пальцах.** Представь приёмную лаборатории. Ты не просто просишь сотрудника «разобраться с образцами», а выдаёшь бланк: разрешены только типы «кровь», «слюна» и «ткань», для каждого нужны название и тип. Сотрудник уже умеет распознавать образцы; ты не переучиваешь его, а задаёшь словарь и форму, в которой результат попадёт в систему.
