В задаче уже лежит артефакт `report` с первой страницей. Следующее событие приносит вторую страницу с тем же `id` и `append: true`. Если просто добавить весь объект в массив, появятся два артефакта `report`; если заменить старый — исчезнет первая страница. Тебе нужно реализовать `apply_event(task, event)`, которая различает эти случаи.

Сначала проверь, что `event.taskId` совпадает с `task.id`: событие чужой задачи нельзя применять к текущей. Затем учти защиту из [шага 22](#step-22): если статус уже терминальный, функция оставляет задачу неизменной — запоздавшее событие не может «оживить» завершённую работу.

Дальше поведение зависит от `kind`:

- `statusUpdate` заменяет текущий `task.status` значением из события;
- `artifactUpdate` с `append: false` добавляет новый артефакт;
- `artifactUpdate` с `append: true` ищет артефакт с тем же `id` и дописывает новые `parts` в конец его массива.

Обрати внимание на неприятный случай: команда «дописать» не имеет смысла, если артефакта с таким `id` ещё нет. Не создавай его молча — сообщи об ошибке. Иначе потерянный первый фрагмент потока будет незаметно превращаться в якобы целый результат.

Флаг `lastChunk` не означает завершение всей задачи: он относится лишь к текущему артефакту. Терминальность определяется статусом, а не последним куском файла.

> 🎒 **На пальцах.** Ты собираешь журнал по подписанным папкам. Лист с пометкой «добавить в папку №7» можно положить только в уже заведённую папку №7. Если её нет, лист нельзя незаметно объявить началом журнала. А когда журнал опечатан, поздняя посылка уже не меняет его содержимое.
