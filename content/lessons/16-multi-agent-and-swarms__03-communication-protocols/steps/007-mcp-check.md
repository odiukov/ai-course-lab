type: check
title: 'Где нужен MCP, а где вызов другого агента уже требует A2A?'
source_anchor: '### MCP (Recap)'
check:
  - question: >-
      Твой агент запрашивает у сервиса список доступных операций, вызывает поиск
      файла по имени и получает результат. Какая граница здесь важна?
    options:
      - 'Агент — инструмент, поэтому подходит MCP'
      - 'Агент — агент, поэтому нужен A2A'
      - 'Агент — сеть незнакомых агентов, поэтому нужен ANP'
    correct: 0
    explanation: >-
      Сервис выставляет конкретные операции и возвращает их результаты, а
      решение о вызове остаётся у клиента. Это связка «агент — инструмент»,
      которую покрывает MCP.
  - question: >-
      Один агент передаёт другому цель «подбери три маршрута», исполнитель сам
      планирует работу, при нехватке данных запрашивает уточнение и позже
      сообщает итог. Что здесь меняется?
    options:
      - 'Ничего: любой внешний вызов остаётся связкой агент — инструмент'
      - 'Вторая сторона ведёт собственную задачу, поэтому нужна логика A2A'
      - Достаточно переименовать поля в JSON-запросе
    correct: 1
    explanation: >-
      Исполнитель принимает цель, а не заранее заданную операцию: он сам
      выбирает шаги и ведёт задачу до результата. Связка «агент — инструмент»
      перестаёт описывать ситуацию — это уровень A2A.
---

Перед проверкой удерживай не название программы, а её роль. Если внешний участник показывает операции вроде «найди файл» и сразу возвращает результат, перед тобой граница MCP из [шага 6](#step-6). Если ему передают цель, а он сам решает, как её выполнить, и возвращает итог как самостоятельный исполнитель, начинается граница A2A. Частая ловушка — выбирать протокол по тому, есть ли внутри компонента ИИ. Важнее другое: ты вызываешь функцию или поручаешь работу?
