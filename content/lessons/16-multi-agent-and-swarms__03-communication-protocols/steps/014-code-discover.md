В реестре лежат десять карточек. Тебе нужен агент с тегом `risk-analysis`, но имя подходящего агента неизвестно. Затем приходит файл `application/pdf`: теперь имя снова не помогает — нужно проверить, кто действительно примет такой вход.

Допиши в `AgentRegistry` два метода обнаружения. `discoverBySkillTag` должен перебрать зарегистрированные карточки и вернуть только те, где хотя бы один skill содержит переданный тег. Остановиться на первом совпавшем skill можно, но сама карточка должна попасть в результат лишь один раз.

В `discoverByInputMode` проверяй два уровня, которые мы разделили на [шаге 13](#step-13):

- `defaultInputModes` всей карточки;
- `inputModes` каждого отдельного skill.

Карточка подходит, если MIME-тип найден хотя бы в одном из этих мест. Это условие «или», а не «и»: специальный skill может поддерживать формат, которого нет среди режимов по умолчанию.

Для обхода возьми значения из `cards`, затем отфильтруй их. Обрати внимание на три детали: сравнение тегов и MIME-типов должно быть точным, одна карточка не должна дублироваться из-за нескольких совпавших skill’ов, а пустой реестр должен давать пустой массив, а не ошибку. Структуру самой карточки менять не нужно — её уже собирает функция из [шага 11](#step-11).

Проверь себя на карточке, где `text/plain` указан по умолчанию, а `application/pdf` — только у одного skill. Оба соответствующих поиска должны найти эту карточку.

> 🎒 **На пальцах.** Представь библиотекаря, который ищет книгу по двум каталогам. Общий каталог говорит, какие форматы обычно есть у издания, а карточки приложений уточняют, что внутри может лежать отдельная карта или диск. Если нужный носитель отмечен хотя бы в одном каталоге, книгу можно выдать под твой запрос.
