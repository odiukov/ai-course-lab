Представь: подпись математически верна, но сделана ключом из `keyAgreement`. Если принять её, агент сможет выдать ключ согласования шифрования за подтверждение личности. Поэтому простого перебора всех ключей из `verificationMethod` недостаточно.

Допиши метод `verify(did, signature, payload)`. Сначала найди DID-документ через реестр. Если документ не разрешился, сразу верни `false`: без доверенного документа неизвестно, с какими ключами сравнивать подпись.

Затем возьми идентификаторы только из `authentication` и по ним отфильтруй `verificationMethod`. Это практическое продолжение правила из [шага 46](#step-46): расположение ключа в документе ещё не даёт ему права подтверждать личность.

Каждый подходящий публичный ключ нужно:

1. декодировать из Base64;
2. импортировать как DER-ключ формата `spki`;
3. передать в `crypto.verify` вместе с точными байтами `payload`;
4. сравнить с подписью, декодированной из шестнадцатеричной строки.

Для Ed25519 первым аргументом `crypto.verify` будет `null`: отдельный алгоритм хеширования здесь не выбирается. Как только один разрешённый ключ подтвердил подпись, верни `true`. Если ни один не подошёл — `false`.

Обрати внимание: функция не ищет «похожий» payload и не исправляет его. Даже лишний пробел меняет подписанные байты и должен разрушить проверку.

> 🎒 **На пальцах.** На входе в архив охранник видит настоящую печать, но сверяет её не со всеми печатями учреждения. Печать склада подходит для коробок, но не разрешает доступ посетителю. Охранник берёт только список пропускных печатей: совпала хотя бы одна — впускает, не совпала или список недоступен — отказывает.
