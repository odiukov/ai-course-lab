Ты работаешь над активной фичей импорта PDF. Её файловая область — `importer/**`. Для небольшой задачи «исправить определение числа страниц» хочется записать в `allowed_files` сразу два пути:

- `importer/pdf/**`
- `api/uploads.py`

Первый путь уже находится внутри области фичи. Второй выглядит полезным: через API ведь загружают документы. Но полезность изменения не даёт задаче право расширять активную фичу.

Здесь важно не перепутать две высоты из [шага 23](#step-23). Список фич отвечает, над какой частью проекта идёт текущая работа. Контракт отвечает, какую долю этой части разрешено затронуть конкретной задачей. Поэтому контракт может выбрать весь `importer/**`, только `importer/pdf/**` или даже один файл `importer/pdf/pages.py`. А вот добавить `api/uploads.py`, находящийся за границей фичи, он не может.

Что делать, если без этого файла исправление действительно невозможно? Не расширять `allowed_files` молча. Нужно остановиться и пересмотреть объём активной фичи с человеком: возможно, её граница была описана неверно или обнаружилась отдельная задача. До такого решения `api/uploads.py` остаётся вне объёма.

Контракт — не пропуск в соседнюю область проекта. Это ограничитель внутри уже выбранной работы.

> 🎒 **На пальцах.** Представь, что тебе выделили одну грядку в общественном огороде, а на сегодня поручили прополоть её левую половину. Ты можешь взять участок ещё меньше — например, только ряд с помидорами. Но запись «сегодня прополоть ещё соседнюю грядку» не делает соседнюю землю твоей. Сначала владелец огорода должен изменить границы порученной грядки.
