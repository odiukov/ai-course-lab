В заготовке `classify_write` получает путь к изменённому файлу и правила контракта. Представь, что пришёл путь `app/auth/login.py`: функция должна не просто ответить «совпадение есть», а вынести один из трёх вердиктов — запись разрешена, явно запрещена или находится вне заявленного объёма.

Для каждого пути проверь две независимые вещи: совпадает ли он хотя бы с одним глобом `allowed_files` и совпадает ли хотя бы с одним глобом `forbidden_files`. Само сопоставление уже умеет выполнять `path_matches` из [шага 9](#step-9), поэтому не повторяй внутри новой функции логику глобов.

Затруднение появляется, когда оба ответа положительные. Например, `app/**/*.py` разрешает `app/generated/schema.py`, а `app/generated/**` запрещает его. Здесь действует приоритет из [шага 10](#step-10): запрещающее правило сильнее разрешающего.

Проверь свою реализацию минимум на трёх случаях:

- путь совпал с запрещающим глобом — вердикт «запрещено», даже если есть разрешающее совпадение;
- путь совпал только с разрешающим глобом — «разрешено»;
- путь не совпал ни с одним глобом — «вне объёма».

Не объединяй последние два случая: отсутствие запрета ещё не означает разрешение. После этого `classify_write` превращает набор глобов в однозначное решение для каждого изменения.

> 🎒 **На пальцах.** Ты сортируешь посылки по трём лентам в аэропорту: разрешённые к погрузке, запрещённые и не указанные в накладной. Коробка может подходить по размеру для обычной ленты, но наклейка «не перевозить» отправляет её на запрещённую. А коробка без наклейки и без записи в накладной не становится разрешённой сама собой.
