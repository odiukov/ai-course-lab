Пусть роутер уже выдал тебе строчку чисел — по одному баллу на каждого из 256 экспертов для одного токена. Скажем, `[0.4, 2.1, -0.3, 1.7, ...]`. Дальше по логике из [шага 14](#step-14) нужно взять восемь самых больших. Кажется, дел на одну строку: отсортировал, отрезал восемь.

Только вот отсортированный список даст тебе *баллы*: `[2.1, 1.7, ...]`. А блоку MoE баллы не нужны — ему нужны **номера** экспертов, которым отправлять токен. 2.1 сам по себе не говорит, что это эксперт номер 1.

Значит, сортировать надо не сами числа, а пары «балл — номер», а потом выбросить баллы и оставить номера. Это и есть вся работа `route_topk`.

Функция принимает список баллов (индекс в списке = номер эксперта) и число `k`, а возвращает список из `k` номеров — тех, у кого балл выше всех.

На что смотреть, пока пишешь:

Сортировка по убыванию, не по возрастанию. Проверь на маленьком примере руками: если из `[0.1, 5.0, 0.2]` при `k=1` вернулось `[0]` — ты отсортировал не в ту сторону.

Что именно ты сравниваешь. Если сортируешь пары целиком, Python при равных баллах начнёт сравнивать вторым элементом номер, и результат тихо перевернётся. Сравнивай ключом только балл.

И проверь: индексы возвращаются, а не значения. Ошибка выглядит правдоподобно — список из восьми чисел, всё как надо, — но следующий шаг с загрузкой экспертов посчитает по ней полную чушь.

Восемь чисел на выходе. Каждое — от 0 до 255.

> 🎒 **На пальцах.** Фотофиниш забега. Камера выдаёт время каждого участника: 10.1, 9.8, 10.4… Ты сортируешь времена и получаешь тройку лучших результатов — 9.8, 10.1, 10.4. Красиво, но на пьедестал ты приглашаешь не секунды. Тебе нужны стартовые номера тех, кто их показал. Поэтому в сортировку идут пары «время — номер», а на табло уходят только номера.
