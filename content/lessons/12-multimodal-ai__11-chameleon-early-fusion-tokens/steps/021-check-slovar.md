title: 'Проверка: что означает токен с ID 35000'
source_anchor: '### The shared vocabulary'
check:
  - question: >-
      Почему картиночный ID нельзя напрямую использовать как индекс записи в
      codebook?
    options:
      - Потому что картиночные ID сначала нужно преобразовать в текстовые токены
      - >-
        Потому что ID включает смещение диапазона словаря, которое нужно
        вычесть, чтобы получить индекс codebook
      - 'Потому что codebook принимает только логиты, а не целые числа'
    correct: 1
    explanation: >-
      Картиночные ID находятся в общем словаре после смещения. Поэтому из ID
      вычитают начало картиночного диапазона, и только полученный индекс
      используют для обращения к codebook.
  - question: >-
      Почему один и тот же softmax может на одном шаге выдать текстовый токен, а
      на следующем — картиночный?
    options:
      - >-
        Потому что внутри модели два разных выходных слоя, и софт переключает их
        по тегу
      - Потому что после тега <image> модель временно меняет размер словаря
      - >-
        Потому что словарь общий: softmax выбирает наиболее вероятный ID среди
        токенов всех модальностей
    correct: 2
    explanation: >-
      Выходная проекция формирует логиты по единому словарю. Softmax не
      переключает режим, а выбирает ID из общего распределения, в котором есть и
      текстовые, и картиночные токены.

После [шага 19](#step-19) и [шага 20](#step-20) у тебя есть всё, чтобы прочитать любой ID вручную: посмотреть, в какую половину диапазона он попал, и, если это картиночная половина, вычесть смещение и получить номер кисти из [шага 6](#step-6).

Спотыкаются обычно на двух вещах. Первая — забывают вычесть 32000 и лезут в codebook с числом 35000, которого там нет: записей всего 8192. Вторая — думают, что модель «переключается в режим картинки». Никакого режима нет: softmax один и тот же, распределение одно, просто вероятность съезжает в верхнюю часть диапазона.
