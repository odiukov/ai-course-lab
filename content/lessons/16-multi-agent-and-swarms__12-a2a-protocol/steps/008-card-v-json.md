Функция из [шага 7](#step-7) собрала карточку агента в словарь Python. Ты видишь имя, адрес и список навыков — всё выглядит готовым. Но если передать этот словарь в HTTP-запрос напрямую, другая программа не получит понятную карточку: словарь существует только в памяти Python.

Нужен общий дорожный формат. Здесь им становится JSON — текстовое представление данных, которое понимают программы на разных языках. Превращение объекта в такой формат называют сериализацией: внутреннюю структуру записывают по единым правилам, чтобы её можно было сохранить или передать.

Например, фрагмент карточки может выглядеть так:

```json
{
  "name": "Travel Agent",
  "url": "http://localhost:8000",
  "skills": ["find_hotel"]
}
```

Это уже не словарь Python, хотя внешне он похож. В JSON ключи и строки заключаются в двойные кавычки, а значения ограничены общими типами: строки, числа, логические значения, `null`, массивы и объекты. Поэтому принимающей стороне не нужно знать Python или устройство функции `make_agent_card`.

Для HTTP этот JSON-текст кодируется в байты, обычно в UTF-8, и кладётся в тело ответа. Заголовок `Content-Type: application/json` сообщает клиенту, как прочитать полученные байты. Сама Agent Card остаётся контрактом из [шага 6](#step-6), а JSON становится её переносимой записью.

Карточка готова к сети только тогда, когда перестала быть «питоновской».

> 🎒 **На пальцах.** Представь, что ты записал адрес друга в приложении телефона, а курьер принимает только стандартный бланк. Контакт в приложении содержит всё нужное, но курьер не умеет заглядывать внутрь телефона. Ты переносишь те же поля на понятный ему бланк. JSON — такой бланк, а HTTP — способ его доставить.
