Перед тобой два набора логитов: один выдала текущая политика, другой — её SFT-якорь. Сами логиты сравнивать вычитанием нельзя: они ещё не являются вероятностями. Твоя функция `kl_divergence(current_logits, sft_logits)` должна измерить расхождение именно в направлении, заданном в [шаге 16](#step-16).

Сначала преврати оба набора логитов в логарифмы вероятностей по словарю. Для текущей политики дополнительно понадобятся обычные вероятности: именно ими взвешивается вклад каждого токена. Затем для каждого возможного токена найди разность логарифмов вероятностей, умножь её на вероятность токена у текущей политики и сложи результаты. Если на входе несколько примеров, сначала получи отдельную KL-дивергенцию для каждого, а потом усредни их по батчу.

Используй `log_softmax`, а не связку `softmax` и `log`: первый вариант устойчивее при очень больших или маленьких логитах. Вероятности текущей политики можно получить экспонентой из её логарифмов вероятностей.

Проверь функцию тремя наблюдениями:

- одинаковые логиты должны дать значение около нуля;
- сильное предпочтение токена, который SFT считает маловероятным, должно увеличить результат;
- перестановка аргументов обычно меняет число — KL-дивергенция несимметрична.

Частая ошибка здесь — усреднить значения по токенам. По словарю их нужно **суммировать**, потому что вероятности уже задают веса; усреднение требуется только по примерам батча. И не обновляй SFT-политику через эту величину: она остаётся неподвижным якорем.

> 🎒 **На пальцах.** Представь две рулетки с одинаковыми секторами. Текущая политика часто запускает одну рулетку, поэтому именно её вероятности определяют, какие сектора важнее при сравнении. Если она регулярно попадает туда, куда старая рулетка почти никогда не попадала, расхождение становится большим. Поменяешь рулетки местами — изменятся и веса, поэтому получится уже другое число.
