Здесь важно выбирать метод не по названию фичи, а по вопросу, на который ты хочешь ответить. Если проверяешь качество, полезность или безопасность ответа на подготовленных примерах — нужен eval-набор. Если проверяешь, изменилось ли поведение пользователей и продуктовая метрика, — нужен A/B-тест, как различали в [шаге 2](#step-2).

Частая ловушка — считать, что для одной фичи подходит только один метод. На деле сначала можно поймать опасные ошибки с помощью evals, а затем отдельно проверить пользу для пользователей через A/B.
