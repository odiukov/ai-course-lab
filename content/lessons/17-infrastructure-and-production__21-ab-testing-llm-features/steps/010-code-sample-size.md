Ты вводишь базовую конверсию `0.03` и ожидаемый относительный прирост `0.05`. Здесь легко случайно получить 8%: просто сложить числа. Но прирост на 5% означает, что вариант B должен дать `0.03 × 1.05 = 0.0315`, то есть 3,15%. Разница между вариантами — всего 0,15 процентного пункта, поэтому тесту понадобятся сотни тысяч участников.

Допиши `sample_size`, которая принимает базовую конверсию, относительный прирост, уровень значимости и мощность, а возвращает необходимое число пользователей **для каждого варианта**.

Сначала вычисли ожидаемую конверсию B и разницу между A и B. Затем получи два критических значения через `z_quantile` из [шага 8](#step-8): одно соответствует двусторонней проверке, поэтому использует половину уровня значимости в каждом хвосте; второе соответствует заданной мощности. Подставь их вместе с обеими конверсиями в расчёт размера выборки из [шага 9](#step-9).

Результат почти наверняка окажется дробным. Округляй его вверх: часть пользователя пригласить нельзя, а округление вниз незаметно уменьшит запланированную мощность.

Проверь функцию здравым смыслом. Если уменьшить минимальный эффект, выборка должна вырасти. Если потребовать большей мощности или более строгого уровня значимости — тоже. Нулевой прирост нельзя отправлять в расчёт: различия нет, поэтому конечного размера выборки для его обнаружения не существует.

> 🎒 **На пальцах.** Представь два почти одинаковых мешка риса, в одном из которых совсем немного больше тёмных зёрен. Чем меньше эта разница, тем больше горстей тебе придётся перебрать, чтобы уверенно её заметить. `sample_size` заранее оценивает число таких «горстей» для каждого мешка — и всегда округляет вверх, чтобы последней неполной проверки не потерять нужную уверенность.
