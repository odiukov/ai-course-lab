title: Проверяем контракт двух стадий
source_anchor: '## The Concept'
check:
  - question: >-
      Первый этап вернул 20 документов, но нужного среди них нет. Что сможет
      сделать второй этап?
    options:
      - Найти нужный документ во всём корпусе и добавить его
      - Только оценить и переставить полученные 20 документов
      - Создать новый документ из фрагментов кандидатов
    correct: 1
    explanation: >-
      Cross-encoder не обращается ко всему корпусу: он оценивает только пары с
      кандидатами, переданными retriever. Поэтому пропущенный первым этапом
      документ вернуть нельзя.
  - question: Какой контракт правильно соединяет retriever и reranker?
    options:
      - >-
        Retriever передаёт top-N кандидатов, а reranker получает запрос с каждым
        кандидатом и выдаёт отдельный балл для каждой пары
      - >-
        Retriever передаёт единственный готовый ответ, а reranker формулирует
        для него новый запрос
      - >-
        Обе стадии независимо ищут по всему корпусу, после чего их результаты
        объединяются
    correct: 0
    explanation: >-
      Retriever формирует ограниченный список кандидатов. Reranker совместно
      читает запрос и каждый из этих документов, присваивает парам баллы и
      меняет их порядок.
---

Проверь, состыковались ли две стадии из [шага 1](#step-1). Первая обязана передать не готовый ответ, а список из N кандидатов. Вторая получает тот же запрос вместе с каждым кандидатом, выдаёт по одному числу на пару и сортирует список по этим числам.

Чаще всего здесь приписывают reranker лишнюю способность: будто он может вернуть документ, который retriever пропустил. Не может. Он улучшает порядок только внутри полученного списка. Поэтому маленькое N ускоряет работу, но может навсегда оставить правильный ответ за дверью.
