check:
  - question: >-
      Первый этап вернул 20 документов, но нужного среди них нет. Что сможет
      сделать второй этап?
    options:
      - Найти нужный документ во всём корпусе и добавить его
      - Только переставить и оценить эти 20 документов
      - Создать новый документ из частей найденных
    correct: 1
    explanation: >-
      Второй этап работает только с кандидатами первого. Отсутствующий документ
      он вернуть не может.
  - question: Какой контракт правильно соединяет две стадии?
    options:
      - >-
        Первый этап отдаёт top-N кандидатов, второй получает запрос с каждым
        кандидатом и выдаёт по одному баллу
      - >-
        Первый этап отдаёт один итоговый ответ, второй ищет для него новый
        запрос
      - Оба этапа независимо ищут по всему корпусу и объединяют результаты
    correct: 0
    explanation: >-
      Retriever сужает поиск до top-N, а reranker оценивает каждую переданную
      пару и меняет порядок этих кандидатов.
---

Проверь, состыковались ли две стадии из [шага 1](#step-1). Первая обязана передать не готовый ответ, а список из N кандидатов. Вторая получает тот же запрос вместе с каждым кандидатом, выдаёт по одному числу на пару и сортирует список по этим числам.

Чаще всего здесь приписывают reranker лишнюю способность: будто он может вернуть документ, который retriever пропустил. Не может. Он улучшает порядок только внутри полученного списка. Поэтому маленькое N ускоряет работу, но может навсегда оставить правильный ответ за дверью.

> 🎒 **На пальцах.** Представь турнир с отборочным раундом и финалом. Судьи финала могут внимательнее пересмотреть каждого прошедшего участника и поменять их места. Но пригласить выбывшего участника они уже не могут: качество финального выбора ограничено списком, который пришёл из отбора.
