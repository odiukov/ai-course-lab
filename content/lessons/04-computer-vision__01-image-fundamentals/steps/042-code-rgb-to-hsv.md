Три формулы для hue из прошлого шага — это три разных рецепта для одного массива. Нужно применить каждый только к тем пикселям, у которых свой канал оказался максимумом, и при этом не писать цикл по миллиону пикселей: цикл на Python по такой картинке считается минутами, а операции над всем массивом сразу — миллисекунды.

Что должна делать `rgb_to_hsv`:

- перевести вход в float и поделить на 255 — переход в normalized-диапазон из шага 26; иначе целочисленное деление обрежет всё в нули;
- посчитать `cmax`, `cmin`, `delta` вдоль последней оси (`axis=-1`), чтобы результат имел форму (H, W) — по одному числу на пиксель;
- завести массив нулей под hue и заполнять его по частям: отдельно те пиксели, где максимум — красный, где зелёный, где синий. Условие «где» задаётся булевым массивом той же формы, им же можно индексировать;
- домножить hue на 60, чтобы получить градусы круга из шага 40;
- собрать три плоских массива обратно в (H, W, 3).

На что смотреть в выводе: форма совпадает с исходной, hue лежит в [0, 360), saturation и value — в [0, 1]. Если hue вылезает за 360 или уходит в минус — потерялся `% 6` в красной ветке.

> 🎒 **На пальцах.** Булев массив — это трафарет. Вместо того чтобы обходить бланк строчка за строчкой и решать, куда вписать цифру, ты кладёшь поверх листа лист с прорезями и закрашиваешь всё открытое одним движением. Потом второй трафарет, потом третий. Прорези не пересекаются, а вместе покрывают всё, кроме серых пикселей — там оттенка просто нет.
