Когда ты берёшь картинку из одной библиотеки и передаёшь в другую, она может «сломаться»: цвета поедут, размеры не совпадут, код упадёт с ошибкой про shape. Причина почти всегда одна — библиотеки по-разному договорились, в каком порядке хранить оси.

Ось — это одно из измерений массива чисел. У цветной картинки их три: высота (H, сколько строк пикселей), ширина (W, сколько столбцов) и каналы (C — красный, зелёный, синий).

**HWC** значит «сначала высота, потом ширина, потом каналы»: `(128, 192, 3)`. Так устроены PIL, OpenCV, matplotlib и почти любой файл с диска — идёшь по строке пикселей, и у каждого пикселя рядом лежат его три цвета.

**CHW** значит «сначала каналы»: `(3, 128, 192)`. Это три отдельные плоскости — вся красная картинка целиком, потом вся зелёная, потом вся синяя. Так хочет PyTorch (почему именно — следующий шаг).

Переход между ними — одна строка:

```
img_chw = img_hwc.transpose(2, 0, 1)   # NumPy
img_chw = img_hwc.permute(2, 0, 1)     # PyTorch
```

Цифры `2, 0, 1` читаются так: «на первое место поставь ось номер 2 (каналы), потом ось 0 (высоту), потом ось 1 (ширину)». Ни одно число в картинке не изменилось и не пересчиталось — их всё те же 73 728. Изменился только маршрут чтения.

> 🎒 **На пальцах.** Один и тот же класс можно построить двумя способами: по партам (за каждой партой сидят Петя, Маша, Ира) или по колонкам (сначала все первые ряды, потом все вторые). Дети те же, число то же — сменился порядок обхода. `transpose` — это команда «перестроиться», а не «поменяться людьми».
