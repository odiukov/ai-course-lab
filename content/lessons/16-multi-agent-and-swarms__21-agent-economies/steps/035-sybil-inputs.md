  Сибил-атака ломает состав участников, даже когда расчёт Шепли математически

В маркетплейсе работают два независимых редактора. Один из них создаёт ещё девять аккаунтов и поручает им проверять тексты друг друга. Для системы это уже не один оператор, а десять отдельных участников с подтверждённой активностью.

Расчёт из [шага 14](#step-14) может быть выполнен без единой ошибки: для каждого зарегистрированного агента берётся его предельный вклад, затем усредняются все порядки. Децентрализованный расчёт из [шага 32](#step-32) тоже лишь гарантирует, что никто не подменил получившиеся числа.

Где же обман? В список независимых участников попали управляемые одним владельцем клоны. Если проверяющий принимает их взаимные подтверждения за реальный вклад, девять значений Шепли складываются в доход одного оператора. Формула честно отвечает на вопрос «как поделить награду между указанными игроками», но не проверяет, действительно ли это разные игроки.

Важно: простое дробление одного неизменного вклада само по себе не обязано увеличить выплату — сумма Шепли остаётся связана с общей ценностью. Атака срабатывает, когда клоны способны влиять на оценку этой ценности или подтверждать заслуги друг друга.

DID из [шага 5](#step-5) помогает отличать аккаунты, но не доказывает, что за ними стоят независимые владельцы. Защита появляется, когда массовое создание правдоподобных личностей дорого: нужно накопить репутацию, внести залог или пройти независимую проверку. Иначе точная арифметика лишь аккуратно делит награду между поддельными участниками.

> 🎒 **На пальцах.** Представь дегустацию, где каждый член жюри получает долю за полезные оценки. Один владелец приносит девять разных бейджей и девять раз хвалит собственное блюдо. Секретарь безошибочно подсчитывает голоса, но честный подсчёт не спасает: сначала следовало проверить, сколько независимых судей действительно вошло в зал.
