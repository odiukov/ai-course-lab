Ты запускаешь функцию для порядка `A → C → B` и получаешь три числа. Но как проверить, что каждое из них относится именно к моменту добавления нужного агента, а не к его «общей полезности»?

Напиши `marginal_contributions`, которая проходит по заданному порядку слева направо. В начале текущая коалиция пуста, а её оценка равна `v(∅)`. На каждом шаге функция должна:

1. запомнить оценку текущей коалиции;
2. добавить очередного агента;
3. получить новую оценку через `v`;
4. записать разницу оценок как вклад этого агента.

Идею самой разницы ты уже разобрал в [шаге 12](#step-12); здесь задача — аккуратно превратить её в повторяющуюся процедуру.

Следи за двумя деталями. Во-первых, коалиция — это множество: для `v` состав `A, C` не должен отличаться от `C, A`. Во-вторых, не начинай сравнение с нуля автоматически: исходной точкой служит именно `v(∅)`. Она может быть ненулевой, если задача даёт результат даже без агентов.

Полезная проверка после реализации: сумма всех записанных вкладов должна совпасть с разницей между оценкой полной и пустой коалиций. Отрицательный вклад не обязательно означает ошибку — добавление агента действительно может ухудшить результат. А вот несовпадение сумм обычно выдаёт неверное обновление коалиции или предыдущей оценки.

> 🎒 **На пальцах.** Представь, что ты по очереди добавляешь ингредиенты в лимонад и после каждого шага ставишь напитку оценку. Было 3 балла, после мяты стало 5 — вклад мяты здесь равен 2. Затем лёд снизил оценку до 4 — его вклад равен −1. Функция просто ведёт этот журнал: кто вошёл следующим и насколько изменилась оценка именно в этот момент.
