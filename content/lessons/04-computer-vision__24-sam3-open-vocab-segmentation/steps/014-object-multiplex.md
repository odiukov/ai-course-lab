Ты запускаешь трекинг сорока похожих клеток под микроскопом. После каждого нового кадра клетки остаются различимыми, но вычисления неожиданно разрастаются: для каждого экземпляра система ведёт собственный memory bank. Получается сорок почти одинаковых хранилищ, хотя все они смотрят на одну и ту же последовательность кадров.

В [шаге 13](#step-13) память связывала один экземпляр между кадрами. Но обязательно ли копировать её целиком для каждого следующего?

В SAM 3.1 механизм **Object Multiplex** помещает информацию обо всех экземплярах одного концепта в общую память. При этом клетки не сливаются в безымянную массу: у каждой остаётся отдельный запрос — специальная «метка внимания», по которой система извлекает сведения именно о ней. Общая часть хранится один раз, а запросы указывают, какой объект сейчас нужно продолжить на новом кадре.

Посмотри на главное различие: раньше добавление ещё одной клетки означало ещё один memory bank; теперь оно в основном добавляет ещё один запрос к уже существующей памяти. Поэтому объём дублируемой работы перестаёт расти вместе с числом объектов прежним способом. Особенно заметен выигрыш, когда в видео одновременно движутся десятки экземпляров одного концепта.

Объекты остаются раздельными не потому, что у каждого есть копия всей памяти, а потому, что у каждого есть собственный ключ к общей памяти.

> 🎒 **На пальцах.** Представь лабораторию с одной длинной видеозаписью деления клеток. Раньше ассистент создавал сорок копий записи и на каждой следил только за одной клеткой. Теперь запись хранится в одном экземпляре, а поверх неё лежат сорок цветных прозрачных меток. Метки различают клетки, но сам фильм больше не приходится копировать сорок раз.
