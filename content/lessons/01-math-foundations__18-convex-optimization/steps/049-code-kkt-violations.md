Точка-кандидат выглядит правдоподобно: ограничения почти соблюдены, множители неотрицательны, градиент мал. Но одного общего «почти» недостаточно — непонятно, какое именно условие KKT подвело. Собери диагностическую панель из четырёх чисел.

Функция `kkt_violations` получает:

- `grad_f` — градиент целевой функции в проверяемой точке;
- `g_values` — значения всех ограничений;
- `grad_g` — их градиенты, по одному в каждой строке;
- `lambdas` — соответствующие множители.

Используй меры нарушения из [шага 48](#step-48). Для стационарности сложи `grad_f` со взвешенными строками `grad_g` и найди норму результата. Для прямой допустимости учитывай только положительную часть `g_values`: отрицательное значение означает запас, а не ошибку. Для двойственной допустимости аналогично ищи отрицательные `lambdas`. В дополняющей нежёсткости проверь абсолютные значения попарных произведений `lambdas * g_values`.

Верни словарь с ключами `stationarity`, `primal`, `dual` и `complementarity`. Последние три результата удобно свести к максимальному нарушению среди ограничений: тогда каждое число отвечает на простой вопрос — насколько плох худший случай?

Обрати внимание на формы массивов. Если ограничений `m`, то `g_values` и `lambdas` имеют длину `m`, а у `grad_g` должно быть `m` строк. Не складывай все четыре показателя в одно число: большое нарушение иначе спрячется за спокойным средним. В точной KKT-точке вся панель покажет нули; при вычислениях с плавающей точкой — маленькие числа, которые сравнивают с допуском.

> 🎒 **На пальцах.** Представь приборную панель перед запуском ракеты: четыре лампы проверяют разные системы. Надпись «общая готовность — 97%» бесполезна, если ты не знаешь, отказал двигатель или не закрыт люк. `kkt_violations` делает то же самое для решения: не просто говорит «есть ошибка», а показывает, какое из четырёх условий требует внимания.
