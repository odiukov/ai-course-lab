Ты передаёшь функции набор из тысячи шинглов, а получить хочешь всего 128 чисел. Просто взять первые 128 нельзя: множество не хранит полезного порядка, и похожие документы могут начать подпись с совершенно разных элементов. Нужен принцип из [шага 21](#step-21): несколько раз по-разному хешировать все шинглы и каждый раз сохранять только минимальное значение.

Реализуй `minhash_signature(shingles, num_hashes=128)`. Внешний цикл должен сделать `num_hashes` проходов. Его индекс `i` играет роль номера хеш-функции: перед хешированием объедини его с текстом шингла, например в строку вида `i:shingle`. Благодаря этому один шингл получает разные значения в разных компонентах подписи.

Для каждого прохода:

1. Начни с минимального значения `float("inf")`.
2. Перебери все шинглы.
3. Закодируй составную строку в байты и вычисли SHA-256 через `hashlib.sha256`.
4. Преобразуй шестнадцатеричный результат `hexdigest()` в целое число с основанием 16.
5. Оставь меньшее из текущего минимума и нового хеша.
6. После обхода добавь найденный минимум в подпись.

Верни список длины `num_hashes`. Не используй встроенный `hash()`: его результат может меняться между запусками Python, а одинаковые документы должны всегда получать одинаковые подписи. Порядок обхода множества, напротив, не важен — минимум от перестановки элементов не меняется.

Проверь также пустое множество: внутренний цикл ни разу не выполнится, поэтому каждая позиция останется равной бесконечности. Это ожидаемое поведение данной реализации.

> 🎒 **На пальцах.** Представь конкурс из 128 раундов. В каждом раунде всем участникам-шинглам выдают новые номера по одному и тому же строгому правилу, а в протокол записывают только самый маленький. Порядок выхода участников на сцену ничего не меняет. Если зал пуст, судья так и оставляет в протоколе начальную отметку «бесконечность».
