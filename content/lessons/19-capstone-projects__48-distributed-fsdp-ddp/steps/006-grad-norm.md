После `backward()` ты смотришь на градиент одного параметра — и видишь небольшие числа. Но модель может содержать сотни параметров, поэтому по одному тензору нельзя понять общий масштаб обновления. Нужна функция `_grad_norm(module)`, которая соберёт все доступные локальные градиенты этого модуля в одно число.

Здесь «локальные» означает: полученные только текущим рангом. Функция не должна обращаться к другим процессам или выполнять коллективные операции. Она лишь измеряет состояние модели в этой точке программы.

Пройди по всем параметрам модуля. У некоторых `grad` окажется равен `None`: например, параметр не участвовал в вычислении текущего результата. Такой параметр нужно пропустить. Не создавай для него нулевой градиент — измерение не должно менять модель.

Для остальных параметров примени правило из [шага 5](#step-5): сложи квадраты всех элементов их градиентов в общий накопитель. Обрати внимание на два частых промаха: корень берётся один раз, после обхода всех параметров, а не отдельно для каждого тензора; итог должен быть обычным Python-числом `float`, а не тензором PyTorch.

Проверь также крайний случай: если градиентов нет ни у одного параметра, естественный результат — `0.0`. Функция только читает градиенты и возвращает их общий локальный масштаб.

> 🎒 **На пальцах.** Представь тележку с несколькими коробками, а в каждой лежат предметы разного веса. Ты не оцениваешь загрузку по первой коробке и не считаешь пустое место новым предметом. Сначала учитываешь каждый реально лежащий предмет по одному общему правилу, затем один раз получаешь итоговый показатель для всей тележки. Здесь тележка — текущий ранг, а предметы — элементы его градиентов.
