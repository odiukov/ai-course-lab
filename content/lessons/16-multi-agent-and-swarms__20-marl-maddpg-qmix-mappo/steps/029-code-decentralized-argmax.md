Перед тобой локальные оценки двух агентов: у первого `[1.2, 0.4, 1.8]`, у второго `[0.3, 2.1]`. Первый должен выбрать действие с индексом `2`, второй — с индексом `1`. Результат функции — `[2, 1]`.

Напиши `decentralized_argmax(local_qs)`. На вход она получает список строк: каждая строка принадлежит одному агенту, а её элементы — Q-оценки доступных ему действий. Для каждой строки найди наибольшую оценку и сохрани **индекс действия**, а не саму оценку. Затем верни индексы в исходном порядке агентов.

Здесь легко случайно снова устроить совместный поиск из [шага 27](#step-27): перебирать пары действий или вычислять их командную ценность. Не делай этого. Как показано в [шаге 28](#step-28), каждый агент обрабатывает только собственную строку. Поэтому число агентов и количество действий у них могут различаться — функция всё равно проходит по строкам независимо.

Проверь ещё два края: отрицательные оценки не означают выбор действия `0`, а при равенстве максимумов нужен устойчивый результат — выбирай первое действие с максимальной оценкой. Так функция будет вести себя предсказуемо и совпадать с обычным поведением `argmax`.

Главный ориентир: одна входная строка должна давать ровно один индекс в выходном списке.

> 🎒 **На пальцах.** Представь музыкантов в отдельных кабинках. Перед каждым горят несколько кнопок с личными оценками качества звука. Никто не видит панели соседей и не перебирает общие комбинации: каждый нажимает кнопку с самым большим числом. `decentralized_argmax` лишь собирает номера нажатых кнопок, не становясь центральным дирижёром.
