Перед тобой таблица стоимостей: каждая строка относится к одному агенту, каждый столбец — к одной задаче. Например, при строках `[2, 7]` и `[3, 6]` оба агента видят задачу `0` как более дешёвую. Функция `independent_assignment` должна вернуть `[0, 0]`.

Это не ошибка. Ты специально реализуешь независимое решение из [шага 11](#step-11): каждый агент просматривает только свою строку и выбирает индекс с минимальной стоимостью. Уже выбранные задачи не вычёркиваются, а решения других агентов не учитываются. Поэтому один и тот же индекс может встретиться в результате несколько раз.

Собери список назначений длиной по числу агентов. Для каждой строки найди позицию наименьшего элемента и добавь именно её индекс, а не саму стоимость. Если минимумы равны, выбирай первый из них — так результат останется предсказуемым.

Проверь три вещи:

- `[2, 7]` превращается в индекс `0`, а не в число `2`;
- разные строки обрабатываются независимо;
- повторяющиеся индексы сохраняются.

После этого передай полученное назначение в `assignment_cost` из [шага 10](#step-10): функция стоимости должна суммировать выбранные элементы исходной таблицы. Здесь ты пока не исправляешь дублирование — наоборот, строишь чистую независимую базу, с которой дальше можно сравнивать координацию.

> 🎒 **На пальцах.** Два фотографа заходят в зал и по отдельности выбирают ближайшего гостя для портрета. Если обоим ближе Анна, оба записывают «Анна», даже если Борис останется без снимка. `independent_assignment` работает так же: каждый смотрит только на свой список расстояний и никого не спрашивает, кого уже выбрал коллега.
