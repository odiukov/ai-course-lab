title: Dot score измеряет близость query и каждого key

Представь: декодер собирается породить следующее слово и должен выбрать, к какой позиции входа обратиться. Перед ним несколько ключей, но ни на одном не написано «подходит». Есть только наборы чисел: query описывает текущий запрос декодера, а каждый key — содержание одной позиции энкодера.

Как сравнить их без отдельной обучаемой модели? Попарно перемножить координаты и сложить результаты:

$$
s_{t,i}=q_t \cdot k_i=\sum_d q_{t,d}k_{i,d}
$$

Здесь $s_{t,i}$ — score для позиции $i$ на шаге $t$, $q_t$ — query декодера, $k_i$ — key этой позиции, а $d$ перебирает их координаты. Query и keys должны иметь одинаковое число координат.

Допустим, query равен $(1, 2)$. Для key $(1, 2)$ получится score $1\cdot1+2\cdot2=5$: направления хорошо согласуются. Для key $(-1, 0)$ score равен $-1$: первая координата направлена противоположно запросу. Чем сильнее query и key совпадают по направлениям своих координат, тем выше dot score.

Это ещё не доля внимания: различие между score и weight ты видел в [шаге 7](#step-7), а нормализация происходит позже через softmax из [шага 8](#step-8). Dot score лишь расставляет позиции по степени соответствия текущему запросу — без единого нового обучаемого параметра.

> 🎒 **На пальцах.** Представь штекер с несколькими контактами и ряд разъёмов. Query задаёт, на какие контакты сейчас должен прийти сильный сигнал, а каждый key описывает свой разъём. Ты перемножаешь силы совпадающих контактов и складываешь: подходящий разъём получает большой итог, противоположно устроенный — маленький или отрицательный. Dot score и есть такая быстрая проверка совместимости.
