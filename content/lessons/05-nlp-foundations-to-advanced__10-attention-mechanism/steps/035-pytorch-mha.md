Ты запускаешь пример и видишь две формы:

```text
torch.Size([2, 5, 128]) torch.Size([2, 5, 10])
```

Почему первая сохранила `5 × 128`, а во второй вместо `128` появилось `10`?

Параметр `batch_first=True` задаёт порядок измерений: сначала размер пачки, затем число позиций, затем размер представления. Поэтому `query` формы `2 × 5 × 128` содержит два примера, в каждом — пять запросов по 128 чисел. У `key` и `value` десять позиций: каждый запрос выбирает контекст среди них.

`output` имеет форму `2 × 5 × 128`: слой возвращает отдельный результат для каждой из пяти позиций `query`. Число позиций берётся именно у `query`, а не у `key`. Последнее измерение снова равно 128, потому что результаты восьми голов из [шага 32](#step-32) объединяются обратно.

`weights` имеет форму `2 × 5 × 10`. Для каждого из двух примеров это alignment matrix из [шага 26](#step-26): пять строк соответствуют запросам, десять столбцов — позициям `key`. По умолчанию PyTorch усредняет веса восьми голов, поэтому отдельного измерения для голов здесь нет.

Есть важная тонкость: `MultiheadAttention` сам по себе не прибавляет исходный `query` к результату. Такое сложение — residual connection — делается снаружи слоя. Здесь `output` означает новые представления, расположенные напротив тех же пяти query-позиций.

> 🎒 **На пальцах.** Представь двух редакторов. У каждого есть пять вопросов к десяти фрагментам интервью. Таблица `5 × 10` показывает, насколько каждый вопрос опирается на каждый фрагмент. После чтения редактор получает пять новых заметок по 128 чисел — по одной на вопрос. Поэтому вопросов остаётся пять, хотя источников было десять.
