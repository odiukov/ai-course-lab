У тебя есть три шага декодера и четыре позиции входной последовательности. Если передавать каждый query в `attend` из [шага 23](#step-23), функция трижды вернёт веса длины 4. По отдельности они полезны, но сравнивать такие разрозненные векторы неудобно. Хочется собрать их в одну alignment matrix, о которой шла речь в [шаге 26](#step-26).

Твоя функция должна пройти по всем query в порядке шагов декодера. Для каждого query вызови `attend` с теми же состояниями энкодера и маской, затем возьми именно веса — не context. Каждый вектор весов станет одной строкой результата. Если query было 3, а состояний энкодера 4, итоговая форма должна быть `(3, 4)`:

- строки соответствуют шагам декодера;
- столбцы соответствуют позициям входа;
- элемент на пересечении показывает внимание конкретного шага к конкретной позиции.

Обрати внимание на частую ошибку: `attend` возвращает два результата, но alignment matrix строится только из второго. Векторы нужно сложить по новой оси, а не склеить в одну длинную последовательность — иначе вместо `(3, 4)` получится `(12,)`.

Маску передавай при каждом вызове без изменений: padding относится к позициям входа, поэтому одни и те же запрещённые столбцы должны оставаться нулевыми во всех строках. Готовая функция собирает историю внимания, не меняя порядок ни запросов, ни входных позиций.

> 🎒 **На пальцах.** Представь пульт освещения спектакля. Каждая строка — новая сцена, каждый столбец — актёр на сцене, а число показывает яркость направленного на него света. Ты записываешь настройки сцена за сценой и складываешь строки в таблицу. Если склеить все числа в один список, уже не понять, где закончилась одна сцена и началась следующая.
