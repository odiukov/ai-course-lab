Ты запускаешь функцию и получаешь веса внимания, хотя ожидал обычные оценки. Значит, внутри оказалось лишнее действие: `softmax`. Здесь важно остановиться раньше.

Напиши `additive_score`: функция получает `query`, набор `keys` и обучаемые параметры `W_a`, `U_a`, `v_a`, а возвращает только вектор `scores` — по одному числу для каждого key. Формула уже разобрана в [шаге 18](#step-18), поэтому сейчас твоя задача — аккуратно перевести её в операции NumPy.

Сначала отдельно спроецируй `query` через `W_a`, а все `keys` — через `U_a`. Затем сложи результаты и примени `np.tanh`. После этого используй `v_a`, чтобы получить итоговые оценки совместимости.

На что смотреть особенно внимательно:

- `tanh` применяется после сложения двух проекций, а не к каждой из них по отдельности;
- функция должна обработать сразу все keys, без цикла по позициям;
- на выходе должно быть по одному score на каждый key;
- внутри не должно быть ни `softmax`, ни вычисления context vector.

Преобразование оценок в веса — отдельная ответственность функции из [шага 9](#step-9), а исключение padding выполняет `masked_softmax` из [шага 11](#step-11). Сейчас ты строишь только «сырые» оценки: они могут быть отрицательными и не обязаны складываться в единицу.

> 🎒 **На пальцах.** Представь турникет, который сверяет один пропуск сразу с рядом дверей. Сначала данные пропуска и каждой двери переводятся во внутренний формат системы, затем попарно объединяются и проходят нелинейную проверку. `additive_score` лишь выдаёт каждой двери число соответствия. Решать, какую долю внимания получит дверь, будет уже другая функция.
