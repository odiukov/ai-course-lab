Перед тобой 196 токенов патчей формы `(N, 196, 768)`. Хочется добавить и CLS-токен из [шага 12](#step-12), и информацию о расположении из [шага 13](#step-13). Но если считать оба дополнения новыми элементами последовательности, она начнёт бесконтрольно расти. Где именно прибавляется длина?

CLS действительно занимает новое место. Его присоединяют перед патчами, поэтому последовательность становится длиной 197: один CLS и 196 патчей. Форма меняется на `(N, 197, 768)`, где `N` — число изображений в батче.

Позиционные векторы работают иначе: их не вставляют в последовательность как отдельные токены. Для каждого из 197 уже существующих мест берут свой вектор длины 768 и прибавляют его к токену в этом месте. Поэтому таблица позиций имеет форму `(1, 197, 768)`: отдельная позиция предусмотрена и для CLS, и для каждого патча. Первая размерность равна 1, потому что одна таблица используется для всех изображений батча.

После прибавления форма остаётся `(N, 197, 768)`. Меняются значения токенов, а не их количество.

Типичная ошибка — подготовить позиции только для 196 патчей, а затем добавить CLS. Тогда две последовательности уже нельзя сложить поэлементно: у одной 197 мест, у другой 196. Значит, длину увеличивает только присоединение CLS; позиции лишь подписывают получившиеся места.

> 🎒 **На пальцах.** Представь длинный стол с 196 стульями. Ты ставишь ещё один стул во главе стола для ведущего — теперь мест 197. Затем на каждый стул кладёшь именную карточку, включая стул ведущего. Карточки не создают новые места: они лишь сообщают, кто где сидит. Если карточек осталось 196, один стул неизбежно окажется без подписи.
