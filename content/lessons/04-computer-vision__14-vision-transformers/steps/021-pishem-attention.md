Ты запускаешь функцию и получаешь массив правильного размера — но каждый токен почему-то почти не меняется. Такое бывает, если перепутать порядок действий или применить `softmax` не по той оси: программа работает, а внимание — нет.

Напиши `scaled_dot_product_attention(Q, K, V)`, собрав вычисление из [шага 20](#step-20) в четыре операции:

1. Умножь `Q` на транспонированный `K`, чтобы получить оценки связей между всеми парами токенов. Транспонировать нужно только две последние оси: так функция сможет работать и с одним примером, и с целым батчем.
2. Раздели оценки на квадратный корень из размера последней оси `Q`. Масштаб определяется числом признаков ключа, а не количеством токенов.
3. Передай оценки в `softmax` из [шага 19](#step-19). Применяй его по последней оси: для каждого запроса именно ключи должны конкурировать между собой.
4. Умножь полученные веса на `V`. Теперь каждый запрос получает смесь значений остальных токенов.

Полезно вернуть не только результат смешивания, но и сами веса внимания: они понадобятся, чтобы заметить ошибку, которую одна лишь форма результата может скрыть.

Не добавляй циклы по токенам. Матричные операции уже одновременно обрабатывают все пары. И не транспонируй весь массив целиком: при наличии батча это поменяет местами лишние оси.

> 🎒 **На пальцах.** Представь повара, который готовит отдельный соус для каждого блюда. Сначала он оценивает, насколько подходит каждый ингредиент, затем превращает оценки в доли и смешивает ингредиенты в этих пропорциях. Если нормировать доли поперёк блюд, а не ингредиентов, числа останутся аккуратными, но каждый соус окажется составлен по неверному правилу.
