Пусть на вход пришла пачка из 8 изображений: после `patch_embed` из [шага 10](#step-10) у тебя есть тензор формы `(8, 196, 768)`. Теперь функция должна добавить к каждой последовательности CLS-токен и позиционные векторы. Здесь легко случайно склеить данные по неправильной оси или получить несовместимые формы.

Сделай три действия.

Сначала подготовь CLS-токен формы `(1, 1, 768)` для всей пачки. Его значения общие для изображений, но перед объединением нужна форма `(8, 1, 768)`. Для этого увеличь только размер пачки — например, операцией `expand`. Не создавай восемь независимо обучаемых CLS-токенов.

Затем присоедини CLS перед патчами по оси последовательности, то есть по оси с текущей длиной `196`. Результат должен иметь форму `(8, 197, 768)`. Если изменилось последнее измерение или изображения перемешались между собой, выбрана неверная ось.

Наконец, прибавь обучаемый positional embedding. У него должна быть форма, совместимая с полученной последовательностью: обычно `(1, 197, 768)`. Первая единица означает, что одна таблица позиций автоматически применяется ко всем изображениям в пачке. Складываются именно соответствующие токены и позиции; объединять их через конкатенацию не нужно.

Верни новый тензор и проверь две вещи: CLS стоит первым, а форма после сложения осталась `(8, 197, 768)`.

> 🎒 **На пальцах.** Представь состав из 196 вагонов. Перед ними ты прицепляешь один локомотив — CLS, а затем наносишь на каждое место состава свою координатную метку. Для восьми составов локомотив и набор меток устроены одинаково, но содержимое вагонов разное. После разметки вагонов не становится больше: меняются их признаки, а длина состава остаётся 197.
