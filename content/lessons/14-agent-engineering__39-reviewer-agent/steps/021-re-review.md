После первого ревью исполнитель исправил два замечания и передал новую версию. Старый отчёт содержал `hard_fail`, но теперь один ноль исчез. Что должна сделать `re_review`: поправить прежний балл вручную или проверить работу заново?

Выбирай второе. Прошлый отчёт описывает прошлую версию и не должен изменяться. Функция получает обновлённые артефакты и запускает для них тот же путь, который ты уже собрал:

1. создаёт новый `reviewer_view` по правилам из [шага 7](#step-7);
2. заново оценивает все измерения через `score_rubric` из [шага 11](#step-11);
3. вычисляет вердикт функцией из [шага 13](#step-13);
4. собирает новый структурированный отчёт через `review_report` из [шага 16](#step-16).

Не переноси прежние баллы и не усредняй их с новыми. Исправление одного файла может повлиять сразу на несколько измерений, а заодно создать новую проблему. Например, исполнитель устранил лишнее изменение, но ослабил тест: старый высокий балл за корректность уже нельзя считать действующим.

При реализации следи за двумя свойствами. Исходный отчёт должен остаться неизменным, чтобы человек мог сравнить циклы. А результат `re_review` должен иметь ту же форму, что и обычный отчёт: повторное ревью — не особый сокращённый документ, а полная оценка текущей версии.

Старый вердикт объясняет, почему начались правки. Новый — можно ли принимать то, что получилось после них.

> 🎒 **На пальцах.** Представь техосмотр велосипеда после ремонта. В прошлый раз механик записал: тормоз не работает, итог — «не выпускать». Ты заменил трос. Механик не зачёркивает одну строку и не ставит печать: он снова проверяет тормоза, колёса и руль. Старый акт остаётся в папке, а решение принимается по новому состоянию велосипеда.
