Ты уже собирал промпт руками: system-инструкция, три примера, вопрос — [шаг 17](#step-17) и функция из [шага 18](#step-18). Работает. А теперь представь, что через неделю ты меняешь модель, и она начинает съезжать с формата: где-то теряет «The answer is», где-то пишет рассуждение после ответа. Ты лезешь в ту же f-строку, правишь формулировку, гоняешь тесты, правишь снова.

Вопрос: а зачем ты вообще пишешь этот текст руками?

DSPy заходит с другой стороны: ты описываешь не промпт, а контракт. Строка `"question -> answer"` — это и есть сигнатура: на входе вопрос, на выходе ответ. Как именно уговорить модель — забота библиотеки.

```python
import dspy

dspy.configure(lm=dspy.LM("openai/gpt-4o", temperature=0.7))

class MathSolver(dspy.Module):
    def __init__(self):
        self.solve = dspy.ChainOfThought("question -> answer")

    def forward(self, question):
        return self.solve(question=question)

solver = MathSolver()
result = solver(question="Janet's ducks lay 16 eggs per day...")
```

Обрати внимание на `ChainOfThought`: сигнатура осталась та же, «вопрос → ответ», но обёртка сама добавляет к ней поле рассуждения — ровно ту идею, что ты разбирал в [шаге 11](#step-11). А голосование из [шагов 34](#step-34)–[40](#step-40), весь цикл с пятью сэмплами и `Counter`, сжимается до одной строки:

```python
result = dspy.majority(
    [solver(question=q) for _ in range(5)],
    field="answer"
)
```

Промпт перестаёт быть текстом, который ты переписываешь, и становится деталью, которую подбирают под сигнатуру.

> 🎒 **На пальцах.** В ателье ты не диктуешь портному, где класть мел и под каким углом резать. Говоришь: пиджак, вот мои мерки, к пятнице. Раскрой — его работа, и если ткань другая, он перестроит выкройку сам, не спрашивая тебя. Сигнатура `"question -> answer"` — те же мерки: что на входе, что на выходе. Формулировки промпта DSPy кроит под них.
