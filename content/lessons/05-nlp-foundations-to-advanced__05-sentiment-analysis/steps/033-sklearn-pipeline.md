Ты разделил отзывы на обучающие и тестовые, но перед этим построил TF‑IDF по всему набору. Классификатор не видел правильных ответов теста — значит, всё честно?

Не совсем. TF‑IDF учитывает, насколько редко слово встречается во всех переданных текстах. Если среди них были тестовые отзывы, их частоты уже повлияли на веса признаков. Модель получила маленькую подсказку из будущего. Это и есть **утечка данных**: информация из проверки незаметно участвует в обучении.

`Pipeline` связывает два этапа из [шага 2](#step-2) в одну последовательность:

```python
pipe = Pipeline([
    ("tfidf", TfidfVectorizer()),
    ("clf", LogisticRegression()),
])
pipe.fit(X_train, y_train)
pipe.score(X_test, y_test)
```

При `fit` векторизатор изучает словарь и веса IDF только по `X_train`, превращает эти тексты в числа и передаёт их классификатору. При `score` он уже ничего не изучает: лишь применяет сохранённые правила к `X_test`, после чего классификатор делает предсказания.

Особенно важна эта связка при кросс-валидации: для каждого нового разбиения `Pipeline` заново обучает TF‑IDF только на текущей обучающей части. Если векторизовать весь датасет заранее, граница между обучением и проверкой снова исчезнет.

Сам `Pipeline` данные не разделяет. Но после разделения он не даёт одному этапу случайно заглянуть туда, куда следующему этапу смотреть ещё нельзя.

> 🎒 **На пальцах.** Представь фотолабораторию с двумя комнатами. В первой настраивают проявитель по тренировочным снимкам, во второй проверяют результат на запечатанном контрольном снимке. `Pipeline` следит за порядком: сначала настройка, потом проверка. Если настроить проявитель, подсмотрев контрольный снимок, итог получится красивее — но проверка уже будет нечестной.
