Ты запускаешь обучение и получаешь не один ответ, а две таблицы: долю документов каждого класса и вероятность каждого слова внутри этого класса. Задача `train_nb` — собрать эти таблицы из размеченных документов.

Функция принимает:

- `docs_by_class` — словарь, где каждому классу соответствует список уже токенизированных документов;
- `vocab` — признаки, которые модель действительно использует;
- `alpha` — величину сглаживания из [шага 11](#step-11).

Сначала проверь `alpha`: при значении меньше или равном нулю нужно сразу вызвать `ValueError`. Иначе функция создаст нулевые вероятности, которые сломают следующий этап.

Затем посчитай общее число документов. Для каждого класса его доля вычисляется так, как в [шаге 8](#step-8): количество документов класса делится на количество всех документов.

После этого собери `Counter` всех токенов класса. Здесь есть ловушка: счётчик может содержать слова, которых нет в `vocab`. Поэтому знаменатель нужно считать только по словам из `vocab`, а затем добавлять сглаживание для каждого элемента словаря. Если взять сумму всего `Counter`, отброшенные редкие слова попадут в знаменатель, но исчезнут из итоговой таблицы — её вероятности уже не сложатся в единицу.

Для каждого слова из `vocab` сохрани сглаженную вероятность в `class_word_probs[cls]`. В конце верни пару `class_priors, class_word_probs`. Проверь структуру результата: обращение вроде `class_word_probs["positive"]["great"]` должно давать одно число.

> 🎒 **На пальцах.** Представь организатора двух музыкальных фестивалей, который составляет статистику только по трекам из официального каталога. Неизданная запись может встретиться в истории прослушиваний, но в общий объём каталога она не входит. `alpha` заранее выдаёт каждому официальному треку по условному жетону, а затем реальные прослушивания добавляют остальные. Так получается честное распределение по одному и тому же списку треков.
