Ты запускаешь `evaluate` из [шага 27](#step-27), но получаешь F1 только для класса `1`: именно он считается «положительным». Для `macro_f1(y_true, y_pred)` этого недостаточно — классу `0` тоже нужен отдельный подсчёт.

Функция должна дважды посмотреть на одни и те же предсказания: сначала считать целевым классом `0`, затем `1`. Для каждого целевого класса собери свои `tp`, `fp` и `fn`:

- `tp` — истинная и предсказанная метки совпали с целевым классом;
- `fp` — модель выбрала целевой класс ошибочно;
- `fn` — целевой класс был в ответе, но модель его пропустила.

По этим счётчикам вычисли precision, recall и F1 так же, как в [шаге 27](#step-27). Не забудь защитить деления: если знаменатель равен нулю, соответствующая метрика должна стать `0.0`, а не вызвать ошибку.

Сохрани оба значения F1 и верни их среднее — именно это определение было разобрано в [шаге 28](#step-28). Обрати внимание: при подсчёте класса `0` не нужно физически переписывать массивы меток. Достаточно сравнивать каждую метку с текущим целевым классом.

> 🎒 **На пальцах.** Представь двух инспекторов на вокзале. Первый проверяет, насколько хорошо система находит поезда направления `0`, второй — направления `1`. Каждый заполняет собственный акт ошибок, хотя смотрят они на одно расписание. В конце их оценки складывают и делят пополам. Если один инспектор поставил ноль, успешный отчёт второго этот провал не спрячёт.
