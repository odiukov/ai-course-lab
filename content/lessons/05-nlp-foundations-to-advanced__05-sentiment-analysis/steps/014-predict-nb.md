Возьми отзыв `["not", "NOT_good", "plot"]`. Для каждого класса ему нужно выставить отдельный числовой счёт, но начинать с нуля нельзя: ещё до чтения слов у класса есть априорная вероятность из [шага 8](#step-8).

Создай словарь `scores` и перебери классы из `class_priors`. Начальный счёт класса — логарифм его априорной вероятности. Затем пройди по токенам документа и прибавляй логарифм вероятности токена для текущего класса. Почему именно складываем логарифмы, разобрано в [шаге 13](#step-13).

Обрати внимание на две детали:

- Если токена нет в словаре вероятностей класса, пропусти его. Модель не обучалась оценивать слова вне `vocab`, поэтому придумывать для них вероятность здесь не нужно.
- Повторившийся токен должен прибавить свой вклад повторно. Это multinomial Naive Bayes: `great great` даёт два голоса, а не один.

После обработки документа сохрани итоговый счёт класса в `scores`. Когда все классы посчитаны, верни ключ с наибольшим значением — именно метку класса, а не сам счёт и не весь словарь.

Для проверки временно посмотри на `scores`: победивший класс может иметь отрицательный счёт. Это нормально — логарифмы вероятностей меньше единицы отрицательны. Побеждает не «положительное число», а наибольшее из получившихся.

> 🎒 **На пальцах.** Представь забег, где участники стартуют не с одной линии: прежние результаты дают каждому небольшую фору — это априорная вероятность. Затем каждое слово передвигает бегунов согласно статистике обучения. Незнакомое слово не двигает никого, а повторное срабатывает ещё раз. На финише ты выбираешь того, кто оказался впереди, даже если вся шкала размечена отрицательными числами.
