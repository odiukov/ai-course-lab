Тебе приносят новый датасет: короткие отзывы о доставке, русский язык, 20 000 примеров, 90% позитивных. Если просто попросить модель «предложить baseline», она может выдать привычный рецепт — удалить стоп-слова и показать accuracy. Оба решения здесь опасны: отрицания потеряются, а дисбаланс спрячется за красивым числом.

Поэтому сохрани в `outputs/prompt-sentiment-baseline.md` не совет, а контракт для проектировщика:

```markdown
---
name: sentiment-baseline
description: Спроектируй baseline анализа тональности для нового датасета.
phase: 5
lesson: 05
---

Получи описание датасета: домен, язык, размер, классы и допустимую задержку.

Верни:
1. Рецепт признаков: токенизация, n-граммы, стоп-слова, обработка отрицаний.
2. Классификатор: Naive Bayes для первого baseline, логистическая регрессия для практического решения, трансформер — только когда этого требует задача.
3. План оценки: precision, recall, F1, confusion matrix и примеры ошибок каждого класса.
4. Один риск для наблюдения после запуска: например, смена тематики данных или сарказм.

Не рекомендуй удалять стоп-слова без проверки.
Не используй accuracy как единственную метрику при дисбалансе.
Для языков, где слова образуют множество изменяемых частей, отметь преимущество признаков по частям слов или трансформера перед TF-IDF по целым словам.
```

Каждая строка опирается на уже проверенное решение: сохранение отрицаний из [шага 34](#step-34), честные метрики из [шага 30](#step-30) и выбор сложности модели из [шагов 37](#step-37)–[39](#step-39). Главное здесь — последние три запрета: хороший промпт не только предлагает путь, но и закрывает известные аварийные выходы.

> 🎒 **На пальцах.** Представь чек-лист пилота перед взлётом. В нём есть действия: проверить топливо, связь и маршрут. Но особенно важны красные ограничения: не взлетать с открытой дверью и не считать один исправный прибор достаточным. Промпт работает так же: рекомендации направляют проект, а запреты не позволяют привычной ошибке пройти под видом разумного решения.
