У тебя уже есть две работающие детали: `keywords` из [шага 5](#step-5) умеет извлекать ключевые слова, а запись из [шага 6](#step-6) хранит воспоминание. Теперь представь, что при каждом событии ты собираешь эту запись вручную. Стоит один раз забыть ключевые слова или перепутать поле — поиск памяти начнёт пропускать нужные события.

Функция `make_memory` должна стать единой точкой сборки. Посмотри на её сигнатуру и создай внутри экземпляр уже объявленного типа памяти. Передай в него время, тип события, исходный текст и важность. Ключевые слова не проси у вызывающего кода: вычисли их здесь, вызвав `keywords` для текста.

Обрати внимание на три вещи:

- функция должна возвращать именно запись памяти, а не словарь и не отдельный набор ключевых слов;
- исходный текст сохраняется без замены результатом `keywords`;
- ключевые слова вычисляются один раз при создании записи и попадают в соответствующее поле.

Так вызывающему коду достаточно сообщить, что произошло и насколько это важно. Все воспоминания будут создаваться одинаково, а их содержимое уже нельзя будет случайно изменить после добавления.

> 🎒 **На пальцах.** Представь автомат для печати пропусков. Ты вводишь имя гостя, время визита и уровень доступа, а автомат сам добавляет штрихкод для поиска в системе. Если заставить каждого гостя рисовать штрихкод самостоятельно, ошибки неизбежны. `make_memory` играет роль такого автомата: принимает данные события, добавляет ключевые слова и выдаёт готовую неизменяемую запись.
