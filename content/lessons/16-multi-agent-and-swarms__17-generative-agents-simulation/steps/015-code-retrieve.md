Агент собирается решить, идти ли ему в парк вечером. В памяти лежат десятки записей: завтрак, разговор о погоде, приглашение на вечеринку и старое обещание другу. Одного совпадения по слову недостаточно — нужно сравнить все записи в одних и тех же условиях.

В `retrieve` тебе предстоит собрать уже написанные детали в один конвейер. Функция получает поток памяти, текст запроса, текущее время и число `k`. Сначала преврати запрос в ключевые слова с помощью `keywords` из [шага 5](#step-5). Сделай это один раз: набор запроса одинаков для всех воспоминаний.

Затем для каждой записи вызови `retrieval_score` из [шага 13](#step-13). Сохраняй рядом и само воспоминание, и его оценку — иначе после сортировки будет непонятно, какую запись возвращать. Расположи пары по убыванию оценки и возьми первые `k`, как обсуждалось в [шаге 14](#step-14). Результатом должны стать сами записи памяти, а не числа.

Обрати внимание на границы: пустой поток возвращает пустой список, а `k`, равное нулю, не должно случайно отдать всю память из-за особенностей среза. Не изменяй исходный порядок записей внутри потока: поиск читает память, но не переписывает её.

В итоге `retrieve` не придумывает новую логику оценки — оно честно проводит каждое воспоминание через одну процедуру сравнения и забирает лидеров.

> 🎒 **На пальцах.** Представь кастинг, где десять актёров пробуются на одну роль. Ты не отправляешь домой человека только из-за неподходящей шляпы: каждому выставляешь итоговый балл по одинаковым правилам, складываешь анкеты по убыванию и берёшь первые три. `retrieve` делает то же самое с воспоминаниями, не меняя сами анкеты.
