  - question: >-
      Агент уже дошёл до биллинга и собирается вызвать инструмент, который
      удаляет файл с выгрузкой. Какая проверка способна остановить этот вызов?
    options:
      - 'Input guardrail — он проверяет всё, что происходит в разговоре'
      - >-
        Tool guardrail — он стоит на самом вызове инструмента и видит его
        аргументы
      - 'Output guardrail — он поймает удаление, когда агент напишет ответ'
      - 'Любая из трёх: они проверяют одно и то же в разных местах'
    correct: 1
    explanation: >-
      Input guardrail видел только первый запрос пользователя, output — только
      готовый ответ. Аргументы конкретного вызова видит лишь tool guardrail,
      потому что он стоит именно на этой точке.
  - question: >-
      Основной вызов стоит 5000 токенов, guardrail — 200, и срабатывает он на
      одном запросе из двадцати. Что даст режим blocking по сравнению с
      parallel?
    options:
      - >-
        На плохих запросах заплатишь 200 вместо 5200, но каждый хороший ответ
        придёт с задержкой guardrail
      - 'Заплатишь 5200 всегда, зато ответы будут приходить быстрее'
      - >-
        Экономия и по токенам, и по задержке: blocking выгоднее в обоих
        измерениях
      - 'Ничего не изменится: обе LLM всё равно вызываются на каждый запрос'
    correct: 0
    explanation: >-
      В blocking guardrail работает первым, поэтому на плохом запросе основной
      вызов не оплачивается вовсе — но его время добавляется к каждому хорошему
      запросу тоже.

Здесь проверяется одно умение: по описанию ситуации сказать, в какой из трёх точек стоит нужная проверка — и понять, что остальные две её просто не видят. Из [шага 12](#step-12) стоит держать в голове не список названий, а место установки каждого вида.

Спотыкаются обычно на двух местах. Первое: кажется, что input guardrail «охраняет весь разговор» — а он смотрел только на исходный запрос пользователя, до всякой работы агентов. Второе: режимы parallel и blocking путают, потому что blocking выглядит просто «экономнее». Он экономит токены на плохих запросах и добавляет задержку хорошим — это обмен, а не улучшение.
