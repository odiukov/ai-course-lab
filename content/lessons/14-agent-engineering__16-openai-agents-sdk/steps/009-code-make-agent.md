Три агента — triage, billing, tech — тебе сейчас нужно описать записью из [шага 8](#step-8). Можно набрать три словаря руками. Попробуй мысленно: в первом ты пишешь ключ `handoffs`, во втором торопишься и не пишешь — там же нет передач. Рантайм на этом агенте доходит до чтения списка передач и падает на отсутствующем ключе. Ошибка не в логике, а в том, что три записи получились разной формы.

Поэтому запись собирает одна функция. `make_agent` принимает имя, инструкции и — необязательно — список инструментов и список хендоффов, а возвращает всегда один и тот же набор полей. Нет инструментов — поле есть, в нём пустой список. Тогда любой код дальше читает запись, не спрашивая «а этот ключ там вообще есть».

На что смотреть, пока пишешь.

Не ставь `[]` значением по умолчанию у параметра. В Python такой список создаётся один раз при объявлении функции, и все агенты, созданные без явного списка, начнут делить его. Добавишь хендофф к биллингу — он появится у техподдержки. Ставь `None`, а внутри делай новый пустой список.

Хендоффы храни именами других агентов, строками. Не самими записями: triage ссылается на billing, billing умеет вернуть в triage — на объектах это кольцо, из которого не выбраться. По имени рантайм найдёт нужного в общем реестре.

И держи `tools` и `handoffs` разными полями. Имена вида `transfer_to_billing` из [шага 5](#step-5) появятся позже, при сборке списка для модели, — в записи их нет.

> 🎒 **На пальцах.** Как форма для отливки. Заливаешь разный металл — получаешь разные детали, но у всех одинаковые пазы и толщина стенки, потому что форма одна. `make_agent` — эта форма: инструкции у агентов разные, а набор полей у записи всегда тот же. Отливать три детали вручную по эскизу — и одна не встанет на место.
