Ты запускаешь `forward` и получаешь предсказание, но вместо одного числа внезапно видишь массив странной формы. Чаще всего причина не в сигмоиде, а в перепутанных операциях: обычное `*` перемножает элементы по местам, а `@` выполняет матричное умножение.

Напиши функцию `forward(x, params)`. Она принимает вход `x` и словарь параметров, созданный функцией из [шага 17](#step-17). Не создавай веса заново внутри `forward`: иначе один и тот же вход при каждом вызове будет проходить через другую сеть.

Повтори последовательность прямого прохода из [шага 18](#step-18): сначала вычисли скрытый слой, примени `sigmoid` из [шага 13](#step-13), затем так же получи выход сети. Следи за формами данных. Для сети 2–4–1 вектор из двух входных чисел должен превратиться в четыре скрытые активации, а затем — в одно предсказание. Если после первого умножения у тебя не четыре числа, остановись и проверь формы весов, входа и смещений.

Функция должна вернуть не только итоговую активацию, но и `cache` — словарь с результатами вычислений этого конкретного прохода. Пока просто аккуратно складывай туда промежуточные значения по мере их появления. Не округляй их для красоты: обратному проходу понадобятся исходные числа с полной точностью.

Хорошая проверка проста: при одинаковых `x` и `params` два вызова `forward` должны дать одинаковый результат и одинаковые формы. Значит, сеть действительно считает, а не незаметно меняет себя во время расчёта.

> 🎒 **На пальцах.** Представь сборку шкафа по инструкции. Ты не распиливаешь новые детали на каждом этапе: берёшь уже подготовленный комплект, соединяешь детали в заданном порядке и откладываешь рядом замеры после каждой операции. Готовый шкаф — это предсказание, а лист с замерами — `cache`: оба относятся к одной и той же сборке.
