Посмотри на верхнюю половину схемы. Ты подаёшь входное значение \(x\), затем последовательно получаешь \(z\), активацию \(a\) и итоговую ошибку \(L\). Это прямой проход: числа движутся по зависимостям вычислительного графа из [шага 7](#step-7), пока модель не узнает, насколько ошибся её ответ.

Но одного финального числа \(L\) недостаточно. Если выбросить \(z\), \(a\) и входы операций, при поиске влияния весов придётся заново восстанавливать весь путь. Поэтому прямой проход сохраняет промежуточные значения — активации.

Теперь посмотри на нижнюю половину. Обратный проход начинается у ошибки и идёт в противоположную сторону: от \(L\) к \(a\), затем к \(z\), весам и смещению. Назад передаются не прежние значения, а градиенты — числа, показывающие, насколько итоговая ошибка чувствительна к небольшому изменению каждого промежуточного результата. Цепное правило из [шага 4](#step-4) позволяет переносить эту чувствительность дальше по графу.

Получается обмен: модель тратит память на сохранённые активации, зато не повторяет прямой проход отдельно для каждого веса. Один раз записала значения вперёд — один раз прошла по ним с градиентами назад.

> 🎒 **На пальцах.** Представь съёмку сложной сцены с десятком световых настроек. Во время дубля помощник записывает яркость каждой лампы по порядку. Если финальный кадр оказался пересвечен, ты разбираешь записи с конца к началу и выясняешь, какие настройки сильнее повлияли на результат. Записи занимают место, зато переснимать сцену ради проверки каждой лампы не приходится.
