Ты запускаешь `backward()` у узла с итоговой ошибкой. Но если сразу вызывать `_backward()` у встреченных узлов, один из них может передать дальше только часть градиента: второй путь до него ещё не успел добавить свой вклад. Такое сложение из нескольких путей ты разбирал в [шаге 10](#step-10).

Твоя функция должна сначала собрать все узлы, от которых зависит итог. Начинай с `self`, проходи по его `_children` и отмечай посещённые узлы в `visited`. Это важно: один узел может участвовать сразу в нескольких ветках, но добавлять его в список `topo` нужно только один раз. Помещай узел в список после того, как обработаны его дети.

Затем задай `self.grad` значение `1.0`: изменение итоговой ошибки на единицу означает такое же изменение её относительно самой себя. После этого пройди собранный список в обратном порядке и у каждого узла вызови `_backward()`. Сам `backward()` не вычисляет локальные производные — это уже умеют операции, как было показано в [шаге 9](#step-9). Он лишь даёт им правильную последовательность работы.

При проверке смотри на три вещи: общий узел не обрабатывается дважды, градиент результата начинается с `1.0`, а `_backward()` вызывается только после накопления всех входящих вкладов. Тогда один запуск действительно заполнит градиенты всего графа.

> 🎒 **На пальцах.** Представь редактора газеты, который ждёт правки от двух корректоров. Если он отправит статью в печать после первого ответа, замечания второго потеряются. Поэтому сначала составляют список всех участников, собирают ответы от тех, кто работал позже по цепочке, и лишь затем передают объединённые правки назад. `backward()` организует именно такую очередь, а `_backward()` вносит сами правки.
