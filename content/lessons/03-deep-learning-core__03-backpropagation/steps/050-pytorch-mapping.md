Ты запускаешь обучение XOR, видишь падение ошибки, но после нескольких итераций значения начинают странно прыгать. Проверяешь порядок действий — и находишь пропущенную строку:

```python
pred = model(X)
loss = criterion(pred, y)

optimizer.zero_grad()
loss.backward()
optimizer.step()
```

Первые две строки выполняют знакомый цикл из [шага 38](#step-38): сеть получает входы, делает прямой проход и вычисляет ошибку. Во время этого прохода autograd строит вычислительный граф — тот самый механизм обратного обхода из [шага 31](#step-31).

Затем `optimizer.zero_grad()` очищает градиенты параметров, оставшиеся от предыдущей итерации. Это важно: `backward()` не заменяет старые значения в `.grad`, а прибавляет к ним новые. Накопление бывает полезно, когда его делают намеренно, но случайное накопление искажает обновление.

После очистки `loss.backward()` проходит по графу назад и заполняет `.grad` каждого обучаемого параметра. Сами веса пока не меняются. Только `optimizer.step()` читает найденные градиенты и выполняет обновление SGD из [шага 35](#step-35).

Поэтому порядок здесь означает причинность: сначала измерить ошибку, потом найти ответственность каждого параметра и лишь затем изменить параметры.

> 🎒 **На пальцах.** Представь бригаду, которая после каждой смены записывает, насколько каждый станок отклонился от нормы. Перед новой проверкой ты стираешь старые пометки — это `zero_grad`. Затем инспектор расставляет свежие пометки — `backward`. И только после этого мастер подкручивает станки — `step`. Если не стереть лист, вчерашние замечания смешаются с сегодняшними.
