Ты передаёшь сети параметры и один учебный пример, получаешь предсказание — но сравнивать наборы параметров по самому предсказанию неудобно. Нужна одна числовая оценка: насколько этот ответ далёк от правильного.

Дополни функцию `loss_for_params(params, x, y)`. Внутри она должна выполнить прямой проход функцией `forward` из [шага 19](#step-19), взять полученное предсказание и вычислить MSE из [шага 22](#step-22). Возвращать нужно только значение ошибки для этого набора параметров.

Обрати внимание на результат `forward`: кроме предсказания она сохраняет промежуточные значения для будущего обратного прохода. Здесь они не нужны, поэтому отдели предсказание от сохранённого набора и используй только его. Не запускай сеть повторно ради ошибки — одного прямого прохода достаточно.

Ещё одна важная граница: `loss_for_params` оценивает параметры, но не меняет их. Не обновляй веса и смещения внутри функции и не записывай новое состояние сети. Если вызвать её дважды с одинаковыми `params`, `x` и `y`, оба раза должно получиться одинаковое число.

Проверь себя на простом случае: когда предсказание совпадает с целью, функция должна вернуть ноль. Если различие меняет знак, но сохраняет величину, ошибка должна остаться прежней — возведение в квадрат убирает направление промаха.

> 🎒 **На пальцах.** Представь контролёра, который проверяет посылку на весах. Параметры сети — настройки упаковочной машины, `forward` выдаёт фактический вес коробки, а `y` — вес по накладной. Контролёр записывает величину промаха по правилу из [шага 22](#step-22), но не крутит настройки машины. Его задача — только вернуть одну оценку текущей настройки.
