title: Один backward заменяет отдельное возмущение миллионов весов

Ты запускаешь численную проверку для сети с 2 359 296 весами. Для первого веса считаешь loss при небольшом сдвиге, затем переходишь ко второму, третьему… Даже один полный обход параметров требует миллионов новых прямых проходов, как ты видел в [шаге 3](#step-3). А на следующем примере обучения всё придётся начинать заново.

Backward действует иначе. Во время forward сеть уже получила промежуточные значения и сохранила нужные из них, как обсуждалось в [шаге 20](#step-20). Теперь обратный проход начинает с итоговой ошибки и движется по тем же зависимостям назад. Каждая операция передаёт предыдущим операциям информацию о том, насколько их результаты повлияли на loss.

Главный выигрыш появляется благодаря повторному использованию вычислений. Если один промежуточный результат зависит сразу от тысячи весов, backward сначала один раз находит влияние этого результата на ошибку, а затем распределяет его между всеми тысячей весов. Он не пересчитывает всю сеть отдельно ради каждого из них.

«Один backward» не означает одно арифметическое действие: внутри остаются умножения, сложения и обход всех параметров. Но объём работы растёт примерно вместе с размером сети, а не превращается в миллионы полных запусков сети. На выходе ты сразу получаешь набор градиентов той же формы, что и набор параметров, — именно результат функции из [шага 30](#step-30).

> 🎒 **На пальцах.** Представь редактора, который обнаружил ошибку в финальной версии огромной книги с миллионами правок. Можно по очереди отменять каждую правку и заново перечитывать книгу. А можно пройти историю изменений назад: у каждой редакции уже записано, из какой предыдущей она получилась. Один обратный разбор покажет вклад всех правок — без миллиона повторных чтений.
