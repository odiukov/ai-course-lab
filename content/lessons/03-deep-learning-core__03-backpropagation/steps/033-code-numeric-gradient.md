У тебя есть словарь параметров `params`, и нужно получить второй словарь с теми же ключами и формами, но уже с численными градиентами. Функция `numeric_gradient` по очереди проверяет каждый отдельный элемент `W1`, `b1`, `W2` и `b2`.

Для выбранного элемента сохрани его исходное значение. Затем временно прибавь `h`, вызови `loss_for_params` из [шага 23](#step-23) и запомни потерю. После этого временно вычти `h` от исходного значения и снова вычисли потерю. Из этих двух результатов найди оценку наклона способом из [шага 32](#step-32), запиши её на ту же позицию в массиве градиентов и обязательно верни параметру исходное значение.

Последний пункт легко пропустить. Если не восстановить элемент, следующий градиент будет вычисляться уже для немного изменённой сети. Ошибка начнёт накапливаться, и сравнивать результат с `backward` из [шага 30](#step-30) станет бессмысленно.

Для обхода массивов любой размерности подойдёт `np.ndindex`. А массив градиентов удобно заранее создать через `np.zeros_like`: тогда его форма автоматически совпадёт с формой параметра. Проверь три свойства результата: ключи не изменились, формы массивов сохранились, а `params` после вызова остался прежним.

> 🎒 **На пальцах.** Представь оптометриста, который проверяет каждую настройку рецепта для очков. Он ставит линзу чуть сильнее, записывает результат, затем чуть слабее и снова записывает. После сравнения он возвращает исходную линзу и переходит к следующей настройке. Если забыть вернуть её на место, каждый новый тест будет проводиться уже с другим рецептом — и вся проверка потеряет смысл.
