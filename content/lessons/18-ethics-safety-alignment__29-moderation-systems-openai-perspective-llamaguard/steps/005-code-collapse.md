API вернул категорию `self-harm/instructions`, а учебное приложение хранит настройки только для `self-harm`. Если сразу искать исходное название в настройках, совпадения не будет — хотя нужная родительская категория существует. Здесь и понадобится `collapse_openai_category`.

Функция получает одну строку с названием категории и возвращает её учебную версию по правилу из [шага 4](#step-4):

- `self-harm/instructions` превращается в `self-harm`;
- `harassment/threatening` — в `harassment`;
- `violence/graphic` — в `violence`;
- уже родительская категория `sexual` остаётся `sexual`.

Обрати внимание на разделитель: подкатегория начинается после символа `/`. Дефис внутри `self-harm` — часть самого названия, поэтому делить строку по дефису нельзя: иначе вместо `self-harm` получится ошибочное `self`.

Проверь обе ветки поведения. Если `/` есть, результатом должна стать часть слева от него. Если `/` нет, функция должна вернуть исходную строку без изменений. Не нужно составлять длинную цепочку проверок для каждой из 13 категорий: правило одинаково для всех названий из контракта.

После реализации мысленно прогони хотя бы `hate/threatening`, `illicit/violent` и `hate`. Первые два результата должны потерять подкатегорию, последний — сохраниться целиком.

> 🎒 **На пальцах.** Представь гардероб с бирками `верхняя одежда/пальто` и `верхняя одежда/куртка`. Учебный журнал знает только ячейку `верхняя одежда`. `collapse_openai_category` отрезает уточнение после косой черты и находит общую ячейку. Если на бирке уже написано просто `обувь`, отрезать нечего — надпись остаётся прежней.
