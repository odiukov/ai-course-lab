title: 'Проверка: tool, resource или prompt'
source_anchor: '### Three server primitives'
check:
  - question: >-
      Сервер публикует список задач по адресу `tasks://today`. Клиент
      запрашивает этот адрес и получает содержимое списка. Что это за примитив?
    options:
      - 'Tool: клиент отправил серверу запрос'
      - 'Resource: сервер предоставляет доступные только для чтения данные по URI'
      - 'Prompt: сервер возвращает шаблон для диалога'
      - 'Elicitation: сервер запрашивает ввод пользователя'
    correct: 1
    explanation: >-
      Решающие признаки resource — доступ к содержимому по URI и чтение данных.
      Одного лишь отсутствия изменений недостаточно: prompt тоже сам по себе не
      изменяет внешнее состояние.
  - question: >-
      В интерфейсе хоста человек вводит `/review` и получает заготовленный
      чек-лист, куда подставлено имя файла. Кто предоставляет шаблон и кто
      подставляет аргумент?
    options:
      - 'Это tool: сервер выполняет действие над файлом'
      - 'Это resource: клиент читает чек-лист по URI'
      - 'Это prompt: сервер предоставляет шаблон, а клиент подставляет аргумент'
      - 'Это prompt: и шаблон, и подстановку аргумента выполняет сервер'
    correct: 2
    explanation: >-
      MCP prompt — переиспользуемый шаблон, предоставляемый сервером. Клиент
      получает его, подставляет переданные аргументы и показывает пользователю.
---

После [шагов 9](#step-9)–[10](#step-10)–[11](#step-11) и правила из [шага 12](#step-12) ты должен уметь брать любую формулировку задачи и с ходу говорить, каким примитивом её закрывать.

Спотыкаются обычно на двух местах. Первое: «клиент отправил запрос и получил ответ» кажется признаком tool — но обмен сообщениями одинаковый у всех трёх, различает их только то, изменилось ли что-то после вызова. Второе: prompt легко принять за tool, потому что человек его «запускает». Но prompt ничего не выполняет — он отдаёт текст, заготовленный для человека, и дальше решает человек.

Проверь себя на двух вопросах.
