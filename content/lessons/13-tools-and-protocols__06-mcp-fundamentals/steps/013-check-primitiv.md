title: 'Проверка: tool, resource или prompt'
source_anchor: '### Three server primitives'
check:
  - question: >-
      Сервер отдаёт наружу список задач по адресу tasks://today. Клиент
      запрашивает его и получает текст. Что это за примитив?
    options:
      - 'Tool: клиент же вызвал сервер и получил ответ'
      - 'Resource: данные только на чтение, адресуемые по URI'
      - 'Prompt: шаблон, который подставляется в диалог'
      - Ни один — чтение вообще не относится к примитивам
    correct: 1
    explanation: >-
      После запроса мир не изменился: список задач остался прежним, клиент
      просто прочитал содержимое по адресу. Это resource.
  - question: >-
      В интерфейсе хоста человек набирает /review и получает заготовленный текст
      с чек-листом, куда подставляется имя файла. Кто что делает?
    options:
      - 'Это tool: слэш-команда запускает действие на сервере'
      - 'Это resource: текст чек-листа лежит по своему URI'
      - 'Это prompt: шаблон даёт сервер, аргументы подставляет клиент'
      - >-
        Это prompt, и аргументы тоже подставляет сервер, клиент только
        показывает результат
    correct: 2
    explanation: >-
      Prompt — переиспользуемый шаблон для человека: сервер хранит заготовку,
      клиент вставляет в неё аргументы и показывает как слэш-команду.
---

После [шагов 9](#step-9)–[10](#step-10)–[11](#step-11) и правила из [шага 12](#step-12) ты должен уметь брать любую формулировку задачи и с ходу говорить, каким примитивом её закрывать.

Спотыкаются обычно на двух местах. Первое: «клиент отправил запрос и получил ответ» кажется признаком tool — но обмен сообщениями одинаковый у всех трёх, различает их только то, изменилось ли что-то после вызова. Второе: prompt легко принять за tool, потому что человек его «запускает». Но prompt ничего не выполняет — он отдаёт текст, заготовленный для человека, и дальше решает человек.

Проверь себя на двух вопросах.
