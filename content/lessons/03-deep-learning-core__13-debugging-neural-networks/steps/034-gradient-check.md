Теперь собери отдельные детали из [шагов 29](#step-29) и [31](#step-31) в одну проверку модели. Напиши функцию `gradient_check(model, x, y, criterion, eps=1e-4)`, которая сравнивает аналитический градиент из `backward()` с численной оценкой для нескольких параметров каждого слоя.

Сначала переведи модель и входные данные в `double`: изменения loss после сдвига на `eps` малы, поэтому во `float32` округление может замаскироваться под ошибку backprop. Затем перебирай параметры из `named_parameters()`, пропуская те, для которых `requires_grad=False`.

Для каждого тензора параметров:

1. Обнули прежние градиенты, вычисли loss и вызови `backward()`.
2. Сохрани копию аналитического градиента: дальше параметры будут временно меняться.
3. Выбери не более пяти элементов. Плоский номер элемента преобразуй в индекс его тензора с помощью вспомогательной функции `_flat_to_multi_index`.
4. По очереди сдвинь элемент на `+eps` и `-eps`, вычисляя оба loss без построения графа градиентов.
5. Сразу восстанови исходное значение параметра.
6. Получи численный градиент способом из [шага 28](#step-28), а расхождение — способом из [шага 30](#step-30).

Накапливай максимальное относительное расхождение сначала для текущего параметра, затем для всей модели. Для каждого имени напечатай максимум и статус `OK` или `MISMATCH`; в конце выведи число проверенных элементов и общий результат по порогам из [шага 32](#step-32). Перед возвратом результата верни модель в `float`.

Особенно проверь восстановление параметра: если забыть его, следующий тест начнётся уже с изменённой модели, и проверка сама создаст ошибку, которую затем «обнаружит».

> 🎒 **На пальцах.** Представь мастера, проверяющего электронные весы. Прибор утверждает, насколько изменится показание от небольшого груза. Мастер кладёт крошечную гирю, затем снимает такую же величину и сравнивает реальное изменение с прогнозом прибора. После каждой пробы он обязательно возвращает весы в исходное состояние — иначе следующая проверка уже не будет независимой.
