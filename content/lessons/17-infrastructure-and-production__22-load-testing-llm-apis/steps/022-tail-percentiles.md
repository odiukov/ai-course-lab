title: Применяем знакомые перцентили к хвостам TTFT и ITL нагрузочного прогона
source_anchor: '### SLA gate in CI'
---

Ты прогнал два API на одинаковой нагрузке. У обоих медианный TTFT — 0,7 секунды, а средний ITL — 45 миллисекунд. На бумаге ничья. Но у второго API некоторые ответы долго остаются пустыми, а уже начавшийся текст порой замирает. Средние значения спрятали именно те запросы, на которые пожалуется пользователь.

Возьми события из [шага 20](#step-20) и рассматривай две отдельные выборки: TTFT для каждого запроса и промежутки ITL между соседними токенами. Перцентиль показывает границу: например, P95 TTFT = 2,4 секунды означает, что 95% запросов начали отвечать не позже этой отметки, а оставшиеся 5% могли ждать дольше.

Теперь хвост становится видимым. P50 описывает обычный опыт, P95 — редкие, но регулярные задержки, P99 — крайние случаи. Если у двух API одинаковый P50 TTFT, но P95 равен 1,1 и 4,8 секунды, второй API заметно хуже переносит нагрузку. Аналогично высокий P95 ITL обнаруживает паузы уже внутри ответа: первый токен пришёл быстро, однако поток читается рывками.

Не смешивай эти хвосты: TTFT отвечает за ожидание начала, ITL — за плавность продолжения. И помни о размере прогона: при 30–50 запросах P99 почти совпадает с единичным худшим наблюдением. Для CI это годится как грубая сигнализация, но уверенно судить о редком хвосте лучше по более длинному прогону.

Одинаковая середина ещё не означает одинаковый пользовательский опыт — различие часто живёт справа, среди самых медленных наблюдений.

> 🎒 **На пальцах.** Представь гардероб после концерта. Обычно пальто выдают за минуту — это похоже на P50. Но каждый двадцатый зритель ждёт десять минут, пока ищут потерянный номерок. Среднее слегка вырастет и сгладит проблему, а P95 подведёт тебя прямо к границе этой очереди: большинство уже ушло, но неприятный хвост остался.
