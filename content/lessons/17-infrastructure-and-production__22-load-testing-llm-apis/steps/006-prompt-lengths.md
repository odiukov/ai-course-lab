Ты запускаешь тест со средней длиной 800 токенов и замечаешь странность: каждый запрос получается ровно на 800. Среднее соблюдено, но настоящей нагрузки всё равно нет — сервер не встречает ни коротких, ни тяжёлых запросов.

Дополни функцию `prompt_lengths`. Она должна получить количество запросов и параметры распределения из [шага 5](#step-5), а вернуть список целых длин — по одной для каждого будущего промпта. Каждую длину нужно независимо случайно взять из нормального распределения с заданными средним и стандартным отклонением.

Здесь есть две практические ловушки. Во-первых, число токенов не бывает дробным, поэтому результат каждого сэмпла нужно округлить до целого. Во-вторых, нормальное распределение теоретически может дать ноль или отрицательное значение. Такая длина бессмысленна, поэтому установи нижнюю границу в один токен.

После реализации проверь три свойства:

- элементов ровно столько, сколько запросили;
- все значения — положительные целые числа;
- при достаточно большой выборке её среднее и разброс приблизительно совпадают с переданными параметрами.

Именно приблизительно: случайная выборка не обязана попадать в заданные числа до последнего знака. Если тест сравнивает среднее строго с 800, он проверяет случайность неправильно.

Пока функция отвечает только за длины. Содержимое промптов появится позже.

> 🎒 **На пальцах.** Представь экскурсионную группу, которой выдают рюкзаки разного веса. Средний вес — 8 кг, но кому-то достанется 3 кг, а кому-то 13. `prompt_lengths` составляет такой список нагрузок заранее. Рюкзак весом −2 кг невозможен, поэтому случайный результат приходится ограничить снизу — как и длину промпта.
