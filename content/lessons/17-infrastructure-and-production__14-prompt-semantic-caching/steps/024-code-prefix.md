У тебя есть два уже токенизированных промпта: `["Ты", " —", " помощник"]` и `["Ты", " —", " редактор"]`. Первые два токена совпадают, третий — нет. Напиши функцию `common_prefix_tokens`, которая вернёт `2`: длину непрерывного общего начала.

Функция получает две последовательности токенов и сравнивает их попарно слева направо. За каждое совпадение увеличивай счётчик. При первом различии сразу останавливайся: совпадения дальше уже не относятся к общему префиксу. Это важно для provider cache из [шага 23](#step-23): отдельные одинаковые фрагменты в середине запроса не превращаются в оплачиваемые cached tokens.

Обрати внимание и на границы последовательностей. Если одна закончилась, сравнивать больше нечего. Поэтому для двух полностью одинаковых списков ответ равен их длине, для пустого списка — `0`, а для промптов, различающихся первым токеном, — тоже `0`.

Проверь себя на четырёх случаях:

- различие после нескольких совпадений;
- различие в самом начале;
- один список является началом другого;
- оба списка полностью совпадают.

Главная ловушка — посчитать все равные пары, продолжив сравнение после первого расхождения. Тебе нужна не сумма совпадений, а точка, до которой начало оставалось общим без единого разрыва.

> 🎒 **На пальцах.** Представь две мелодии, которые ты слушаешь одновременно. Пока ноты совпадают, ты считаешь общий вступительный фрагмент. На первой же разной ноте вступление заканчивается. Даже если через секунду мелодии снова сыграют одинаковую ноту, она уже не удлинит общее начало. `common_prefix_tokens` считает промпты точно так же.
