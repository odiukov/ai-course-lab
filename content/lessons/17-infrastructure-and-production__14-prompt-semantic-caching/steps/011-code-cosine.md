Ты получил два эмбеддинга — два массива чисел одинаковой длины. Теперь функция `cosine(a, b)` должна превратить их в одно число близости, используя меру из [шага 10](#step-10). Перебирать координаты несколько раз необязательно: за один проход можно вести три накопителя.

Для каждой пары чисел:

- прибавляй их произведение к скалярному произведению;
- прибавляй квадрат первого числа к длине `a`;
- прибавляй квадрат второго числа к длине `b`.

После цикла возьми квадратные корни из двух сумм квадратов и раздели накопленное скалярное произведение на произведение получившихся длин. Готовый код собери сам: здесь важно не перепутать три независимых накопителя и не извлекать корень внутри цикла.

Учти два защитных случая. Массивы разной длины нельзя осмысленно сравнивать покоординатно — функция должна отклонить такой ввод. Если хотя бы один массив состоит только из нулей, его длина равна нулю, а деление даст некорректный результат. Выбери явное поведение: например, вернуть `0` или сообщить об ошибке.

Проверь себя на простых примерах: одинаковые ненулевые векторы дают значение около `1`, противоположные — около `-1`, а перпендикулярные — около `0`. Из-за вычислений с дробями сравнивай результат с небольшой погрешностью, а не требуй точного совпадения.

> 🎒 **На пальцах.** Представь кассира, который одновременно сверяет две длинные квитанции. Для каждой строки он обновляет три итога: совместную сумму и два отдельных размера чеков. Только дочитав квитанции до конца, кассир выполняет финальное деление. Если один чек пустой или строки не совпадают, честного сравнения не получится — это нужно заметить до расчёта.
