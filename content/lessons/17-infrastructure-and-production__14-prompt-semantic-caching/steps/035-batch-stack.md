Ночью тебе нужно классифицировать большой архив документов. Ответы к утру подходят, а длинная инструкция одинакова для каждой записи. Синхронный запуск без кэша стоил бы $2000. Кажется соблазнительным сложить скидку Batch API в 50% и экономию кэшированного ввода примерно в 90% — но тогда получится нелепая «скидка 140%».

Скидки применяются последовательно. Batch API оставляет половину стоимости, а чтение закэшированного ввода — примерно десятую часть входной цены. Поэтому для кэшированной части ввода остаётся:

$0{,}5 \times 0{,}1 = 0{,}05$

То есть около 5% исходной стоимости этих токенов. Это именно умножение коэффициентов, а не сложение процентов.

Но весь счёт не обязательно уменьшится до 5%. Кэш удешевляет только совпавший ввод: свежие токены и выход модели всё ещё оплачиваются. Batch API при этом снижает и их стоимость. Например, если из исходных $2000 около $1800 приходилось на повторяющийся ввод, а $200 — на выход, после обеих скидок получится примерно $90 за ввод и $100 за выход, всего $190. Поэтому ориентир «около 10% исходного счёта» реалистичен для ночной задачи с длинным общим префиксом и короткими ответами, но не является универсальным тарифом.

Сначала посчитай каждую часть счёта отдельно, как в [шаге 28](#step-28), и лишь затем складывай: скидки перемножаются, а разные типы токенов — нет.

> 🎒 **На пальцах.** Представь ночную грузоперевозку: перевозчик берёт половину тарифа за отправку вне часа пик. Товары уже лежат в многоразовых контейнерах, поэтому упаковка стоит лишь десятую часть обычной цены. Упаковка получает обе скидки последовательно и обходится в 5%, но водитель и разгрузка не исчезают. Поэтому вся доставка стоит около 10%, а не обязательно ровно 5%.
