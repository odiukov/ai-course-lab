Возьми токены `["я", "люблю", "чай"]` и мысленно передвигай по ним окно шириной 2. Сначала в окно попадут `("я", "люблю")`, затем `("люблю", "чай")`. Именно такое движение должна выполнять функция `ngrams(tokens, n)`.

Правило построения уже разобрано в [шаге 13](#step-13); теперь тебе нужно выразить его программно. Функция принимает последовательность токенов и размер окна `n`, а возвращает все найденные n-граммы по порядку. Каждую n-грамму удобно представлять кортежем: его впоследствии можно использовать как ключ при подсчёте совпадений.

Проверь себя на нескольких размерах:

- при `n = 1` должны получиться одноэлементные кортежи `("я",)`, `("люблю",)`, `("чай",)`;
- при `n = 2` — две биграммы;
- при `n = 3` — одна триграмма;
- если `n` больше числа токенов, результат должен быть пустым.

Главное место, где легко ошибиться, — правая граница перебора. Окно нельзя начинать там, где для него уже не хватает токенов. При этом последнее окно, которое целиком помещается в последовательность, пропускать нельзя.

Не подсчитывай повторы и не сравнивай перевод с эталоном: сейчас функция только нарезает одну последовательность. Подсчёт с ограничением совпадений появится дальше.

> 🎒 **На пальцах.** Представь экскурсовода, который ведёт группу вдоль витрины и каждый раз фотографирует ровно `n` соседних экспонатов. После снимка он сдвигается на один экспонат вправо. Если до края осталось меньше `n` предметов, новый снимок сделать уже нельзя. Функция должна вернуть все получившиеся фотографии — и ни одной неполной.
