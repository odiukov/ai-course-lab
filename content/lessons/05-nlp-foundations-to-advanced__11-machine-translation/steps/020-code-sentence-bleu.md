Теперь у тебя есть все детали, но их легко соединить в неверном порядке: например, усреднить точности обычным средним или применить штраф к каждой из них отдельно. Функция `sentence_bleu` должна собрать один результат для пары «перевод — эталон».

Начни с такого каркаса:

```python
def sentence_bleu(hypothesis, reference, max_n=4):
    # 1. Обработай пустой перевод.
    # 2. Собери точности для n от 1 до max_n.
    # 3. Найди их геометрическое среднее.
    # 4. Примени штраф за краткость.
    # 5. Переведи результат в шкалу от 0 до 100.
    pass
```

На каждом `n` используй `clipped_ngram_counts` из [шага 16](#step-16): точность равна числу засчитанных совпадений, делённому на общее число n-грамм перевода. Затем объедини точности способом из [шага 19](#step-19), а штраф возьми через `brevity_penalty` из [шага 18](#step-18).

Особенно внимательно обработай нули. Пустой перевод должен сразу получить `0.0`, иначе появится деление на ноль. В нашей версии без сглаживания итог также равен нулю, если хотя бы для одного порядка нет n-грамм или совпадений.

Проверь три характерных случая:

```python
assert sentence_bleu(["я", "вижу", "рыжего", "кота"],
                     ["я", "вижу", "рыжего", "кота"]) == 100.0

assert sentence_bleu([], ["я", "вижу", "кота"]) == 0.0

score = sentence_bleu(
    ["я", "вижу", "рыжего", "кота"],
    ["я", "вижу", "рыжего", "кота", "сегодня"],
)
assert 0.0 < score < 100.0
```

Последняя проверка важна: все фрагменты перевода совпали, но слишком короткая фраза всё равно не должна получить сотню.

> 🎒 **На пальцах.** Представь четыре турникета подряд: первый проверяет отдельные слова, остальные — фрагменты длиной два, три и четыре слова. После них кассир применяет скидку за недостающую длину и переводит результат в сто баллов. Если перевод пуст или не проходит хотя бы один турникет, версия BLEU без сглаживания выдаёт ноль.
