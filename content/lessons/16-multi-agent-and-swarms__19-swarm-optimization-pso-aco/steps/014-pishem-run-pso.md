Ты запускаешь отдельные функции из [шагов 9](#step-9) и [11](#step-11), но пока видишь лишь одно перемещение частиц. Этого мало: удачная позиция могла появиться на пятой итерации, а на шестой рой уже ушёл дальше. Функция `run_pso` должна сохранить такую находку и организовать весь поиск.

Начни с генератора случайных чисел, созданного из `seed`. Через него инициализируй позиции и скорости всех частиц. Позиции должны лежать внутри заданных границ. Затем вычисли начальные значения `rastrigin`, сделай независимую копию позиций для `p_best` и выбери среди них начальный `g_best`. Именно копию: если связать эти массивы, последующее движение частиц незаметно испортит сохранённые рекорды.

Дальше запусти цикл на указанное число итераций. На каждой итерации:

1. передвинь рой с помощью `pso_step`;
2. оцени новые позиции;
3. обнови `p_best` только у частиц, получивших лучший личный результат;
4. при необходимости замени `g_best`;
5. добавь текущий глобальный результат в историю.

Не перепутай направление сравнения: для Rastrigin лучше меньшее значение. Посмотри также, что `g_best` хранит и позицию, и её оценку, а история получает по одному числу после каждой итерации. При одинаковом `seed` два запуска с одинаковыми параметрами должны совпадать — иначе часть случайности проходит мимо общего генератора.

> 🎒 **На пальцах.** Представь диспетчера поисковой экспедиции. Он раздаёт участникам стартовые координаты, после каждого перехода принимает их отчёты и переписывает личные рекорды только при улучшении. Лучший результат всей команды он заносит в отдельный журнал. `run_pso` — именно такой диспетчер: отдельные частицы умеют двигаться, но полный поиск возникает лишь тогда, когда кто-то управляет раундами и бережно хранит лучшие находки.
