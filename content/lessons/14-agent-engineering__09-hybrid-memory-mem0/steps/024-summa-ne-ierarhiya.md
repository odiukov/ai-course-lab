Запрос: «какой у меня номер паспорта». В памяти нашлись два кандидата. Первый — старая запись из анкеты: релевантность 0.6, важность 1.0, свежесть 0.5. Второй — вчерашняя болтовня, где ты вскользь упомянул поездку и документы: релевантность 0.9, важность 0, свежесть 1.0.

Кого выдать?

Если выстроить хранилища и признаки в иерархию — «сначала смотрим релевантность, остальное только при равенстве» — победитель определён сразу: 0.9 больше 0.6, вчерашняя болтовня уезжает в ответ, а важность 1.0 у анкеты вообще не получает права голоса. При жёстком порядке младший признак включается только при точной ничьей, а точных ничьих в вещественных числах почти не бывает.

Формула из [шага 22](#step-22) устроена иначе: три признака складываются, и слабость по одному можно отыграть силой по другому. Подставь веса 0.5 / 0.3 / 0.2. Анкета: 0.5·0.6 + 0.3·1.0 + 0.2·0.5 = 0.3 + 0.3 + 0.1 = **0.7**. Болтовня: 0.5·0.9 + 0.3·0 + 0.2·1.0 = 0.45 + 0 + 0.2 = **0.65**.

Менее релевантный факт выиграл. Посмотри, где именно: болтовня опередила по релевантности на 0.3, но с весом 0.5 это дало ей всего 0.15 форы — а нулевая важность отняла 0.3. Разрыв 0.05 — не случайность и не ошибка, а ровно тот обмен, который ты сам задал весами.

Иерархия отсекает, сумма торгуется.

> 🎒 **На пальцах.** Как лыжное двоеборье. Прыжок с трамплина спортсмен проиграл — отстал заметно. Но за прыжок ему начислили баллы, а не место в очереди, и на гонке он эти баллы отыграл с запасом. Если бы правило было «первым идёт лучший прыгун, гонка решает только при равенстве баллов» — он не выиграл бы никогда. Складывать результаты и сортировать по этапам — два разных вида спорта.
