title: Как склеить три списка результатов в один

Три поиска из [шага 6](#step-6) отработали параллельно и вернули тебе три списка. Вектор: «живёт в Берлине» — 0.71, «любит вело» — 0.64. KV: одна запись, найдена по точному ключу. Граф: сосед на одном шаге, ещё один — на двух.

Ты хочешь сложить их в один рейтинг и взять top-3. И сразу спотыкаешься: какое число поставить рядом с записью из KV? Там нет косинуса, там либо попал в ключ, либо нет. А у графа вместо близости — длина пути.

Пока числа несопоставимы, сортировать нечего.

Значит, первый ход — привести релевантность всех трёх к одной шкале 0..1. Косинус там уже живёт по построению ([шаг 11](#step-11)). Точное попадание в KV — это 1.0, максимальная уверенность: ключ либо тот, либо не тот. Для графа берёшь вес по расстоянию: прямой сосед — 1.0, сосед соседа — 0.5, дальше меньше.

Второй ход — склейка дублей. Факт «живёт в Берлине» пришёл и из вектора (0.68), и из KV (1.0): он же писался трижды, помнишь [шаг 5](#step-5)? Если оставить обе копии, один факт займёт два места в top-3 и вытеснит остальные. Поэтому дубли схлопываешь по идентичности записи, оставляя наибольшую релевантность.

Теперь список один, и к каждой записи применима взвешенная сумма из [шага 22](#step-22): релевантность, важность, свежесть. Сортируешь по итоговому score, отрезаешь k.

Три списка стали одним ровно в тот момент, когда релевантность у всех начала измеряться в одних единицах.

> 🎒 **На пальгах.** Три чека: один в долларах, один в евро, один в рублях. Сложить суммы «как есть» нельзя — получится число ни о чём. Сначала переводишь всё в одну валюту, потом замечаешь, что одну и ту же покупку тебе пробили дважды, и убираешь копию. Только после этого итог по чекам что-то значит. Шкала релевантности — та же валюта.
