Перед тобой список вероятностей действий и номер того действия, которое агент выбрал. Нужно вернуть градиент той же длины: отдельную поправку для каждого логита. Если вернуть только поправку выбранного действия, политика не узнает, как изменить остальные варианты — softmax связывает их между собой.

В [шаге 18](#step-18) мы получили правило: сначала у каждого элемента меняется знак, а затем к элементу выбранного действия прибавляется единица. Теперь перенеси это правило в функцию:

```python
def grad_log_pi(probs, action):
    # Верни градиент log-вероятности выбранного действия
    pass
```

`probs` — список вероятностей всех действий, а `action` — индекс выбранного действия. Результат должен быть новым списком той же длины, что и `probs`.

Обрати внимание на три детали:

- единица прибавляется только по индексу `action`;
- остальные элементы остаются отрицательными вероятностями;
- исходный список `probs` лучше не изменять: он ещё описывает политику, с которой было выбрано действие.

Здесь легко случайно вернуть one-hot-вектор: единицу у выбранного действия и нули у остальных. Но это потеряет влияние softmax. Невыбранные действия тоже получают поправки, потому что увеличение вероятности одного варианта перераспределяет общую единицу вероятности между всеми вариантами.

> 🎒 **На пальцах.** Представь кассу с несколькими банками для монет. Ты хочешь выделить одну банку, но общее число монет фиксировано. Поэтому недостаточно просто положить монету в выбранную банку: нужно учесть доли, уже лежащие во всех банках. Функция записывает именно такое согласованное перераспределение, не трогая исходную ведомость с долями.
