У тебя есть траектория: состояния, выбранные действия, награды и сохранённые вероятности. Теперь нужно превратить весь этот список в одну матрицу поправок. Если складывать числа без учёта их мест, легко получить градиент неправильной формы или случайно изменить `theta` прямо во время расчёта.

Напиши `reinforce_grad`, которая возвращает новую матрицу той же формы, что и `theta`. Сами параметры функция пока не обновляет, а `lr` ей не нужен: здесь мы только собираем градиент.

Сначала получи возвраты функцией из [шага 9](#step-9) и создай матрицу нулей размером как `theta`. Затем одновременно перебирай элементы траектории и соответствующие им возвраты. Для каждого момента:

- вычти `baseline` из возврата;
- получи градиент логарифма вероятности выбранного действия через `grad_log_pi` из [шага 19](#step-19);
- умножь каждый его элемент на каждый признак состояния и на получившееся преимущество;
- прибавь результат в нужную ячейку общей матрицы.

Обрати внимание на индексы: строка соответствует действию, столбец — признаку состояния. Награда из элемента траектории отдельно в расчёте не участвует — она уже учтена в возврате. Сохранённые `probs` используй напрямую: именно с ними было выбрано действие во время rollout из [шага 22](#step-22).

В конце верни накопленную матрицу. Если её форма совпадает с `theta`, каждая запись траектории внесла вклад ровно один раз, а исходные параметры остались неизменными, функция выполнила свою работу.

> 🎒 **На пальцах.** Представь ведомость с рядами для действий и колонками для признаков. Каждый момент траектории приносит отдельную квитанцию: преимущество задаёт её величину, `grad_log_pi` распределяет её между рядами, а состояние — между колонками. Ты не переписываешь исходную ведомость параметров, а складываешь квитанции на чистом листе такого же размера. Этот итоговый лист и есть градиент.
