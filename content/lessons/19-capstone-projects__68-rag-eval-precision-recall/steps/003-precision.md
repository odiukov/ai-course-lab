Ретривер вернул идентификаторы `["doc-7", "doc-2", "doc-9"]`, а в эталонном наборе из [шага 2](#step-2) полезными отмечены `doc-7`, `doc-2` и `doc-4`. Ты видишь два совпадения в первых трёх результатах, значит функция должна получить `2 / 3`, то есть примерно `0.67`.

Твоя задача — реализовать `precision_at_k`. Сначала она берёт из `retrieved` только первые `k` элементов. Затем для каждого из них проверяет принадлежность множеству `gold`, считает совпадения и делит их количество на `k`. Порядок внутри `gold` не важен: это множество идентификаторов, а не рейтинг.

Обрати внимание на границы. При `k <= 0` результат равен `0.0`: корректной верхушки выдачи здесь нет. Пустой список результатов тоже даёт `0.0`. Если запрошено пять документов, а ретривер вернул только три, знаменателем всё равно остаётся `5`, а не `3`: два незаполненных места не становятся полезными автоматически.

Проверь реализацию на трёх случаях: все документы из top-k полезны, полезна только часть, совпадений нет. Число `1.0` означает чистую выдачу, а `0.0` — что ни одно из проверенных мест не принесло пользы.

> 🎒 **На пальцах.** Представь лоток на пять ячеек, куда сортировщик кладёт нужные детали. Три ячейки заняты, и лишь две детали подходят. Полезно заполнены две из пяти ячеек, поэтому доля равна `2/5`. Пустые места не исчезают из лотка: ты заранее попросил пять результатов и оцениваешь именно эти пять мест.
