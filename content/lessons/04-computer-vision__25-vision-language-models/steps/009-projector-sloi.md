title: Projector соединяет два Linear-слоя через GELU

Ты собираешь projector и замечаешь странность: один Linear уже умеет превратить каждый vision-токен из 768 чисел в 4096, как в [шаге 5](#step-5). Зачем тогда ставить второй?

Попробуй мысленно убрать GELU. Первый Linear смешает входные признаки, второй снова смешает получившиеся. Но два таких смешивания подряд всё ещё можно свернуть в одно: итог останется одним линейным преобразованием. Дополнительный слой почти не добавит projector выразительности.

GELU разрывает эту свёртку. После первого Linear каждый токен получает промежуточное представление размерности `hidden`. Затем GELU поэлементно меняет его значения по правилу из [шага 7](#step-7): одни сигналы почти сохраняются, другие ослабляются. Поэтому второй Linear работает уже не просто с очередной смесью исходных чисел, а с преобразованным набором признаков. Теперь projector может выучить более сложное соответствие между визуальными деталями и пространством LLM.

В типичной конфигурации путь одного токена выглядит так: 768 чисел входят в первый Linear, 4096 промежуточных значений проходят через GELU, второй Linear выдаёт 4096 чисел для LLM. Количество токенов при этом не меняется: каждый патч проходит один и тот же маршрут независимо.

Получается, Linear меняет язык признаков, GELU делает перевод нелинейным, а второй Linear собирает окончательную формулировку для LLM.

> 🎒 **На пальцах.** Представь мастерскую мозаики. Первый мастер пересортировывает цветные кусочки по новым коробкам. Если второй лишь пересыплет их ещё раз, обе сортировки можно заменить одной. Но между ними стоит художник: он часть оттенков приглушает, часть оставляет яркими. Теперь второй мастер получает уже изменённый материал и может собрать узор, которого простым пересыпанием не получить.
