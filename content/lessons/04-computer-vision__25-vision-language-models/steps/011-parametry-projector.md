Ты открываешь projector из [шага 9](#step-9) и видишь всего два Linear-слоя. Кажется, что такая маленькая конструкция должна содержать немного настроек. Но у каждого входного признака есть отдельная связь с каждым выходным — и именно эти связи быстро накапливаются.

Первый Linear принимает токен размерности 768 и создаёт 4096 чисел. Значит, ему нужна таблица весов:

$$768 \times 4096 = 3\,145\,728$$

Здесь 768 — число входов, 4096 — число выходов, а результат — количество весов между ними. Ещё у каждого из 4096 выходов есть свой bias, то есть добавочное настраиваемое число.

Второй Linear переводит 4096 признаков в 4096 признаков:

$$4096 \times 4096 = 16\,777\,216$$

И у него тоже есть 4096 bias-параметров. GELU между слоями ничего не хранит: он лишь преобразует полученные числа по правилу из [шага 7](#step-7).

Складываем всё:

$$3\,145\,728 + 4096 + 16\,777\,216 + 4096 = 19\,931\,136$$

Получается примерно 20 миллионов обучаемых параметров. Почти 17 миллионов из них находятся во втором Linear: квадрат размерности 4096 даёт особенно большое число связей. При этом рядом с LLM на 8 миллиардов параметров весь projector занимает около четверти процента её размера. Маленький мост — но внутри него очень плотная сеть соединений.

> 🎒 **На пальцах.** Представь два справочника переводчика. В первом для каждого из 768 исходных оттенков смысла записано, как он влияет на каждый из 4096 новых. Во втором уже 4096 оттенков сопоставляются с другими 4096. Самих справочников всего два, но второй содержит почти 17 миллионов отдельных пометок. Поэтому тонкая книжка по структуре оказывается огромной по числу записей.
