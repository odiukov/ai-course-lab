Перед тобой две трассы. В первой модель читает внешнее письмо, но отвечает только его автору. Во второй — письмо заставляет её найти данные в почте жертвы и отправить результат по внешней ссылке. Слово «письмо» встречается в обеих, поэтому поиск подозрительного источника сам по себе даст ложную тревогу.

Тебе нужно дописать функцию:

```python
def is_scope_violation(events):
    # Проанализируй связанные события одной операции
    pass
```

Она должна вернуть `True`, только если события образуют сквозную цепочку нарушения из [шага 7](#step-7):

1. модель получила инструкцию из недоверенного источника через извлечение;
2. инициированное этой инструкцией действие обратилось к привилегированным данным;
3. полученный результат пересёк границу доверия — например, ушёл во внешнюю сеть.

Смотри не только на наличие трёх событий, но и на их причинную связь. В журнале могут одновременно оказаться внешнее письмо, обычный поиск владельца по своему ящику и несвязанная загрузка картинки. Это ещё не Scope Violation: недоверенный ввод не запускал доступ и вывод.

Не пытайся распознавать атаку по словам вроде «секрет», «отправь» или «срочно». Инструкция может выглядеть безобидно, а легитимное письмо — содержать все эти слова. Функция классифицирует движение данных и полномочий, а не тон текста. Если хотя бы одного звена нет или события относятся к разным операциям, результат должен быть `False`.

> 🎒 **На пальцах.** В фотолабораторию приходит конверт клиента с запиской. Сама записка не опасна. Нарушение появляется, если по ней сотрудник открывает закрытый архив чужих негативов, а затем отправляет скан на указанный внешний адрес. Твоя функция проверяет не три случайные записи в журнале, а один непрерывный маршрут: конверт → закрытый архив → отправка наружу.
