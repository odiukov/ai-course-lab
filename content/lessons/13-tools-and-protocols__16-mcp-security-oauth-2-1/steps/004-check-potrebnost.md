check:
  - question: >-
      Серверу заметок уже разрешено читать данные, но для конкретного действия
      понадобилось право на запись. Какая потребность возникла?
    options:
      - Нужно заново пройти всю авторизацию
      - Нужно запросить недостающий scope через scope escalation
      - Нужно привязать прежний токен к другому resource server
      - Нужно заменить токен постоянным API-ключом
    correct: 1
    explanation: >-
      Пользователь уже авторизовал сервер, но текущего набора прав недостаточно.
      Step-up запрашивает дополнительный scope, не повторяя весь поток с нуля.
  - question: >-
      Токен выпущен для одного resource server, а получивший его сервер пытается
      обратиться с ним к другому. Какая проверка должна остановить запрос?
    options:
      - Проверка соответствия audience целевому resource server
      - Проверка наличия любого scope в токене
      - Повторная аутентификация пользователя по паролю
      - 'Проверка того, что оба сервера принадлежат одному клиенту'
    correct: 0
    explanation: >-
      Resource indicator связывает токен с конкретной аудиторией. Даже
      действительный и неистёкший токен должен быть отклонён сервером, для
      которого он не выпускался.

Все три ситуации из [шага 3](#step-3) звучат похоже — «серверу чего-то не хватает» — и различаются одной деталью. Проверь, что ты ловишь именно её.

Здесь обычно спотыкаются в двух местах. Первое: путают нехватку прав с нехваткой авторизации. Если серверу уже доверяют, но не на это действие — это про объём разрешений, и переигрывать вход целиком не нужно. Второе: думают, что confused deputy — про украденный токен. Нет: токен выдан честно, проблема в том, что его несут не тому получателю, и спасает именно привязка к аудитории.

Держи в голове различение из [шага 2](#step-2): «кто ты» и «что тебе можно» — почти все путаницы растут оттуда.
