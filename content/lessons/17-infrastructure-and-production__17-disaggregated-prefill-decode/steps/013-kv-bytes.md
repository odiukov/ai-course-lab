Ты запускаешь функцию для промпта на 4 096 токенов и ожидаешь большое число из [шага 12](#step-12), а получаешь результат ровно вдвое меньше. Скорее всего, потерялась одна из двух частей кэша: для каждого токена хранятся и ключи, и значения — K и V.

Допиши заготовку:

```python
def kv_bytes(
    prompt_tokens,
    num_layers,
    kv_heads,
    head_dim,
    bytes_per_element,
):
    """Возвращает размер KV-кэша промпта в байтах."""
    # TODO: вычисли число байтов
    raise NotImplementedError
```

Функция должна вернуть целое число байтов. Собери результат из пяти входных параметров: количества токенов, слоёв модели, KV-голов, элементов в одной голове и байтов на элемент. Затем учти две одинаковые по размеру части — K и V.

Особенно внимательно посмотри на `kv_heads`. В моделях с grouped-query attention KV-голов может быть меньше, чем обычных attention-голов. Подставлять сюда общее число attention-голов нельзя: функция завысит объём кэша.

Ещё одна частая ошибка — передать число бит вместо числа байтов. Например, FP8 занимает один байт на элемент, поэтому `bytes_per_element` будет равен `1`, а не `8`.

Проверь себя простым мысленным тестом: если увеличить только `prompt_tokens` вдвое, результат тоже должен удвоиться. То же произойдёт при удвоении числа слоёв. Никаких миллисекунд и сетевой скорости здесь пока нет — функция считает только размер груза.

> 🎒 **На пальцах.** Представь архив, где для каждой записи на каждом этаже кладут две карточки: одну в каталог K, другую в каталог V. Размер архива зависит от числа записей, этажей, ячеек на карточке и размера каждой ячейки. Забудешь второй каталог — получишь аккуратный, но вдвое заниженный ответ.
