Ты передаёшь батч модели и получаешь не одно предсказание, а целый куб чисел: для каждого примера, каждой позиции и каждого токена словаря есть свой логит — необработанная оценка уверенности модели. Например, при батче 4, длине 128 и словаре 50 000 форма логитов будет `(4, 128, 50 000)`.

Но cross-entropy сравнивает список предсказаний со списком правильных ответов. Поэтому внутри `calc_loss_batch` тебе нужно сохранить последнее измерение — размер словаря, — а измерения батча и времени объединить. Получатся 512 строк по 50 000 вариантов. Цели тоже превращаются в плоский список из 512 токенов: по одному правильному индексу для каждой строки.

Следи за двумя вещами. Во-первых, число строк логитов должно совпасть с числом элементов целей. Во-вторых, не выполняй здесь новый сдвиг: `inputs` и `targets` уже обязаны соблюдать контракт next-token loss из [шага 2](#step-2). Эта функция лишь сопоставляет каждую позицию с переданной ей целью.

После прямого прохода модели и изменения форм передай обе плоские структуры в cross-entropy. Результатом функции должен стать один скалярный тензор — средняя ошибка по всем позициям батча, пригодная для дальнейших вычислений градиентов.

> 🎒 **На пальцах.** Представь стопку из четырёх листов, на каждом по 128 заданий с 50 000 вариантами ответа. Проверяющему неудобно обходить листы и строки отдельно, поэтому ты складываешь все 512 заданий в одну длинную ведомость. Рядом кладёшь 512 правильных ответов. Порядок меняется только внешне: каждое задание остаётся напротив своей цели.
