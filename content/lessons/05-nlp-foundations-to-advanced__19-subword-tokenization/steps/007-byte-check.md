check:
  - question: >-
      Ты вводишь редкий эмодзи, которого нет среди готовых токенов. Почему
      byte-level BPE всё равно сможет его записать?
    options:
      - Он заменит эмодзи ближайшим известным символом
      - Он представит эмодзи несколькими базовыми байтовыми токенами

      - Он пропустит эмодзи при обработке

    explanation: >-
      В цифровой кодировке эмодзи представлен последовательностью байтов. Каждый

  - question: 'Что изменится, если в тексте встретится символ из нового для модели языка?'
    options:
      - Понадобится отдельный базовый токен для этого языка
      - Символ обязательно превратится в один байтовый токен
      - >-
        Символ можно собрать из байтов, хотя токенов может понадобиться
        несколько

    correct: 2
    explanation: >-
      Новый символ не требует расширять базовый набор: его кодировка уже состоит
      из байтов. Цена универсальности — иногда более длинная последовательность

Проверь, не перепутал ли ты байты с символами. Набор из 256 токенов не содержит все буквы, иероглифы и эмодзи. Он содержит все возможные значения одного байта — от 0 до 255. Любой цифровой текст записан последовательностью таких значений, поэтому его всегда можно разобрать на базовые токены. Незнакомый символ может занять несколько байтов, но `[UNK]` не потребуется, как показано в [шаге 6](#step-6).

> 🎒 **На пальцах.** Представь ряд кодовых замков, у каждого по восемь переключателей. У одного замка есть ровно 256 возможных положений. Каким бы длинным ни было сообщение, тебе не нужен новый тип замка: ты просто выставляешь нужные положения на нескольких замках подряд.
