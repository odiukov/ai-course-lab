Ты передаёшь функции слово `low` и список слияний, а получаешь неожиданное `["l", "o", "w", "</w>"]`. Значит, список `merges` просто прочитан, но его правила не изменили последовательность символов.

Напиши `encode_bpe(word, merges)`. Сначала преврати слово в начальное представление из [шага 16](#step-16): отдельные символы плюс `"</w>"`. Затем бери слияния строго в порядке обучения, как обсуждалось в [шаге 25](#step-25). Для каждой пары `(a, b)` проходи текущий список слева направо. Если два соседних элемента совпали с парой, замени их одним элементом `a + b`. Остальные элементы сохрани.

Обрати внимание на два места, где легко ошибиться:

- Проверяй соседние **токены**, а не отдельные буквы внутри уже склеенного токена.
- За один проход заменяй все непересекающиеся появления пары. Например, для четырёх `a` и пары `("a", "a")` должны получиться два токена `"aa"`.

Проверь функцию на таком случае:

```python
word = "low"
merges = [
    ("l", "o"),
    ("lo", "w"),
    ("low", "</w>"),
]
```

Ожидаемый результат:

```python
["low</w>"]
```

Если переставить слияния местами, результат может измениться: функция не угадывает удачную последовательность и не начинает список правил заново. Она воспроизводит именно выученный порядок.

> 🎒 **На пальцах.** Представь монтажёра, которому дали плёнку из отдельных кадров и список команд: сначала склеить кадры `l` и `o`, затем получившийся фрагмент `lo` с `w`. Если выполнить вторую команду раньше первой, фрагмента `lo` ещё не существует. Монтажёр идёт по списку сверху вниз — поэтому порядок команд становится частью результата.
