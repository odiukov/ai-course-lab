У тебя есть три вектора токенов запроса и четыре вектора токенов документа. Если сравнить каждый с каждым, получится 12 оценок. Но складывать все 12 нельзя: слабые и случайные пары заглушат хорошие совпадения.

Напиши функцию `maxsim(query_vectors, document_vectors)`. Она должна реализовать правило из [шага 16](#step-16): для каждого вектора запроса найти самое сильное совпадение среди всех векторов документа, а затем сложить найденные максимумы.

Двигайся по векторам запроса. Для текущего вектора вычисли близость со всеми векторами документа через функцию `cosine` из [шага 7](#step-7). Сохрани только наибольшую оценку и добавь её к общей сумме. Затем переходи к следующему токену запроса.

Смотри именно на направление обхода: максимум выбирается отдельно для каждого токена запроса. Если взять один максимум из всей таблицы сравнений или искать лучший запросный токен для каждого токена документа, получится другая метрика.

Для пустого запроса верни `0.0`: складывать нечего. Непустой запрос нельзя сравнить с пустым документом, потому что ни для одного токена не существует максимума — такой ввод лучше отклонить явной ошибкой. Несовпадающие размерности векторов также не маскируй: пусть проверка внутри `cosine` сообщит о нарушенном контракте.

> 🎒 **На пальцах.** Представь связку замков и коробку ключей. Каждый токен запроса — отдельный замок, каждый токен документа — возможный ключ. Для одного замка ты пробуешь всю коробку и записываешь результат лучшего ключа. Потом повторяешь для остальных замков и складываешь результаты. Один идеальный ключ не заменяет проверку всей связки: максимум нужен каждому замку отдельно.
