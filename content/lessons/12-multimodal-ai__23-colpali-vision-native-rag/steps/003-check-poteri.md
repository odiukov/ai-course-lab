check:
  - question: >-
      На странице отчёта число «+18 %» находится внутри изображения диаграммы.
      После извлечения в тексте осталось только «Q3». На какой операции число
      исчезло из доступных для поиска данных?
    options:
      - При разбиении извлечённого текста на чанки
      - При извлечении текста из PDF
      - При ранжировании чанков по косинусной близости
      - При генерации ответа языковой моделью
    correct: 1
    explanation: >-
      Изображение диаграммы не было представлено в извлечённом тексте, поэтому
      «+18 %» не попало ни в чанки, ни в индекс. Ретривер и LLM уже не могли
      получить это число.
  - question: >-
      В индексе нет значения, нарисованного на диаграмме. Какое изменение само
      по себе не поможет системе найти это значение?
    options:
      - Увеличить число возвращаемых текстовых чанков
      - Индексировать визуальное представление страницы
      - Проверить результат извлечения до построения индекса
      - Добавить обработку содержимого диаграмм
    correct: 0
    explanation: >-
      Увеличение top-k расширяет выборку только среди уже проиндексированных
      чанков. Если значение не попало в индекс, изменение числа результатов его
      не восстановит.

После [шага 1](#step-1) и [шага 2](#step-2) ты должен уметь делать одну конкретную вещь: взять сломанный ответ и показать пальцем, на каком именно шаге конвейера пропала информация. Не «RAG плохо работает», а «подпись была картинкой, и её выбросило на извлечении текста».

Спотыкаются обычно на одном месте — путают потерю с ошибкой поиска. Логика соблазнительная: ответа нет, значит ретривер промахнулся, надо крутить top-k и метрику близости. Но если данные не дожили до индекса, поиск честно ищет по тому, что есть, и найти ненайденное не может.
