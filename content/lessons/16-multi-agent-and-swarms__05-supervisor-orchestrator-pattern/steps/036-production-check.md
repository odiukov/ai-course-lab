      В долгом запуске один воркер превысил двойное медианное время, другой

Теперь тебе нужно связать форму задачи с устройством команды и защитными мерами. Опирайся на выбор размера команды из [шага 10](#step-10): простота не требует fan-out, независимые ветви допускают параллельных воркеров, а зависимости задают порядок запуска.

Частая ошибка — пытаться решить любой сбой расширением команды. Но topology отвечает за разделение работы, тогда как таймауты и лимиты из [шага 25](#step-25) ограничивают отдельного воркера, трассировка из [шага 26](#step-26) помогает найти причину, а rainbow rollout из [шага 27](#step-27) защищает переход версий. Сначала определи структуру задачи, затем добавь меру против конкретного риска.
