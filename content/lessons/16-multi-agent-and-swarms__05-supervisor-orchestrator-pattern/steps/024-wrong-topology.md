Ты просишь найти статью, перевести её и сделать краткое изложение. Supervisor может раздать эти три поручения сразу, но переводчику пока нечего переводить, а автору резюме — нечего сокращать. Если же ведущий ждёт завершения каждого этапа, команда превращается в дорогую очередь: свежий контекст и параллелизм из [шагов 5](#step-5) и [8](#step-8) здесь не помогают.

Проверь задачу одним вопросом: можно ли сформулировать все подвопросы одновременно, не зная ответов на остальные? Если нет, перед тобой конвейер — последовательность, где выход одного шага становится входом следующего.

Есть ещё два тревожных сигнала. Первый — запрос настолько прост, что один агент решит его быстрее, чем supervisor составит план и соберёт отчёты. Здесь пригодится оценка масштаба из [шага 10](#step-10): команда должна появляться из сложности задачи, а не по привычке.

Второй — процесс обязан каждый раз идти по строго заданному маршруту. Например, заявка сначала проверяется, затем получает номер, потом отправляется конкретному сотруднику. Supervisor выбирает следующий ход с помощью языковой модели, поэтому маршрут может меняться. Для аудита и точного повторного запуска надёжнее статический граф: заранее зафиксированная цепочка переходов.

Итак, supervisor оправдан там, где независимые ветви действительно требуют выбора и координации; цепочку, мелочь или жёсткий регламент он только утяжелит.

> 🎒 **На пальцах.** Ты ремонтируешь комнату: сначала электрик прокладывает проводку, затем штукатур закрывает каналы, потом маляр красит стену. Отправить всех троих одновременно нельзя — каждый зависит от результата предыдущего. Диспетчер с тремя исполнителями не ускорит ремонт: здесь нужен обычный порядок работ.
