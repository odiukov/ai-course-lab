Дальше в курсе ты почти не будешь считать эти суммы вручную: данные приходят батчами по сотни строк, и питоновский цикл по ним слишком медленный. Поэтому те же формулы записывают через NumPy — одной операцией сразу по всему массиву.

Меняется только форма записи, не смысл. Кросс-энтропия из шага 14 на массивах выглядит так:

```python
def np_cross_entropy(p, q):
    p, q = np.asarray(p, float), np.asarray(q, float)
    mask = p > 0
    return -(p[mask] * np.log(q[mask])).sum()
```

Здесь `p * np.log(q)` перемножает все пары чисел за один шаг, `.sum()` складывает. `mask = p > 0` выбрасывает исходы с нулевой вероятностью: их вклад в сумму нулевой, но `np.log(0)` даёт минус бесконечность и ломает счёт. `np.log` — натуральный логарифм, значит ответ в натах; на биты переводится делением на $\ln 2$, как в шаге 6.

И KL считать заново не надо: `np_cross_entropy(p, q) - np_entropy(p)` — это ровно тождество из шага 18.

Это и есть внутренности `torch.nn.CrossEntropyLoss()`: softmax превращает логиты в $q$, дальше берётся $-\log q$ верного класса (шаг 16) и усредняется по батчу. Когда loss на графике падает, ты видишь, как сокращается число нат, потраченных впустую из-за расхождения $Q$ с $P$.

> 🎒 **На пальцах.** Ты научился шить шов иглой: прокол, протяжка, затяжка — и понимаешь, откуда берётся прочность. Потом садишься за машинку: она делает тот самый шов, только сотню стежков в секунду и ровнее. Стежок не изменился — изменилась скорость. NumPy для этих формул — та же машинка, а `CrossEntropyLoss` — уже готовая фабричная строчка, устройство которой ты теперь знаешь на ощупь.
