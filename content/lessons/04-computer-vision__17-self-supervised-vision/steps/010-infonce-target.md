title: InfoNCE превращает поиск парного вида в классификацию среди 2N − 1 кандидатов

---

Возьми батч из трёх исходных картинок. После двух аугментаций каждой у тебя шесть видов. Теперь выбери один вид — например, обрезанный кадр велосипеда. В матрице сходства из [шага 8](#step-8) для него есть оценки остальных пяти видов.

Как превратить эти числа в задачу обучения? Предложи модели выбрать среди пяти кандидатов тот единственный вид, который получен из той же исходной картинки. Это обычная классификация: есть несколько вариантов ответа и один правильный. Только классами здесь служат не «велосипед», «кошка» и «дом», а конкретные позиции других видов в батче.

Для батча из \(N\) картинок получается \(2N\) видов. Каждый по очереди становится запросом и ищет свою пару среди \(2N-1\) кандидатов: сам себя он не рассматривает. Один кандидат позитивный, остальные \(2N-2\) — негативные.

InfoNCE превращает оценки сходства в вероятности: чем выше сходство кандидата с запросом, тем больше вероятность ему достаётся. Затем функция потерь наказывает модель, если большая вероятность ушла не парному виду. Такое решение считается для каждого из \(2N\) запросов и усредняется. Поэтому ручные названия объектов не нужны: правильный ответ уже известен из того, какие два вида были созданы из одной картинки на [шаге 5](#step-5).

> 🎒 **На пальцах.** Представь корзину с шестью носками — тремя парами после стирки. Ты берёшь один носок и выбираешь его пару среди остальных пяти. На нём нет подписи «пара №2», но правильный ответ существует. InfoNCE устраивает такую проверку для каждого носка: узнаёшь настоящую пару — малая ошибка, путаешь её с похожим чужим носком — большая.
