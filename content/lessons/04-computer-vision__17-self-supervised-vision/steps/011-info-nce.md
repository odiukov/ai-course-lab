Перед тобой два набора embedding: сначала \(N\) первых видов изображений, затем \(N\) парных видов. Например, при \(N=3\) элементы с индексами 0 и 3 относятся к одной картинке, 1 и 4 — к другой, 2 и 5 — к третьей. Твоя `info_nce` должна для каждого из \(2N\) элементов указать правильного партнёра и усреднить ошибки поиска.

Сначала нормализуй embedding с помощью функции из [шага 7](#step-7), затем получи все попарные сходства функцией из [шага 9](#step-9). Матрица будет иметь форму \(2N \times 2N\). Для каждой строки правильный столбец находится со сдвигом на \(N\): если индекс меньше \(N\), прибавь \(N\); иначе вычти \(N\).

Преврати сходства в `logits`, разделив их на переданный `temperature`. Собственное сходство элемента не должно участвовать среди кандидатов. После этого обычная cross-entropy уже умеет сравнить строку `logits` с индексом её правильного партнёра — не вычисляй экспоненты и логарифмы вручную.

Проверь три вещи: результат является одним числом, перестановка целых пар не меняет loss, а увеличение сходства внутри позитивных пар уменьшает его. Особенно внимательно следи за порядком элементов: формула со сдвигом работает только для расположения «все первые виды, затем все вторые».

> 🎒 **На пальцах.** Представь камеру хранения с парными жетонами. Сначала на стол положили левые половинки всех жетонов, затем правые в том же порядке. Для каждой половинки ты составляешь список возможных пар и штрафуешь себя, если правильная оказалась не первой. `info_nce` повторяет эту проверку для каждого жетона и возвращает средний штраф.
