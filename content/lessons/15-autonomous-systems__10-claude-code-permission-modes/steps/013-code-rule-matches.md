У тебя есть действие `Bash("npm test")` и правило, которое разрешает `Read("src/*")`. Оба объекта разобраны правильно, но это ещё не значит, что правило относится к действию. Если сразу вернуть решение правила, команда случайно получит разрешение, предназначенное для чтения файлов.

Напиши `rule_matches`, которая получает действие и результат `parse_rule` из [шага 11](#step-11), а возвращает только `True` или `False`: подходит ли это правило данному действию. Само решение — разрешить или запретить — функция применять не должна.

Сначала сравни вид действия. Правило для `Read` не совпадает с `Bash`, даже если их строки-аргументы одинаковы. Затем проверь ограничение внутри правила. Если оно отсутствует, правило охватывает любое действие этого вида. Если указано конкретное значение, оно должно совпасть с целью действия. Если заготовка поддерживает шаблон со звёздочкой, звёздочка означает переменную часть строки: например, шаблон `npm run test:*` подходит к `npm run test:unit`, но не к `npm run build`.

Обрати внимание на пустые значения и границы шаблона. Отсутствующее ограничение — это «любая цель», а не пустая цель. И совпадение должно следовать правилам шаблона целиком: случайное вхождение подходящего фрагмента в середине строки ещё ничего не разрешает.

Проверь функцию минимум на четырёх случаях: другой вид действия, точное совпадение, несовпадение цели и совпадение по шаблону. Здесь ты отвечаешь только на вопрос «это правило про данное действие?».

> 🎒 **На пальцах.** Представь пропуск на парковку с надписью «въезд, зона B». Шлагбаум сначала сверяет операцию: такой пропуск не разрешает выезд. Потом — зону: с ним нельзя в зону A. `rule_matches` работает как считыватель пропуска: сообщает лишь, подходит ли запись к ситуации, но ещё не решает, поднимать ли шлагбаум.
