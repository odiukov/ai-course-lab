title: Правило действует только на подходящее действие

Ты добавляешь правило «разрешить запуск `npm test`» и затем просишь агента скачать файл через `curl`. Оба действия выполняются командой в терминале — значит, разрешение сработает и для скачивания?

Нет. Правило — не переключатель для всей категории команд. В [шаге 10](#step-10) у него появились две части: описание действия и решение политики. Сначала берётся конкретное действие, которое агент собирается выполнить, и сравнивается с описанием. Лишь при совпадении применяется решение «разрешить» или «запретить».

Поэтому правило для `npm test` разрешит подходящий запуск тестов, но ничего не скажет о `curl`, удалении файла или даже другой команде `npm`. Для них система продолжит проверку по остальной политике и текущему режиму. Например, в `default` неподходящее опасное действие может вызвать вопрос, а в `dontAsk` действие без заранее разрешающего правила будет отклонено — различие этих режимов разобрано в [шаге 9](#step-9).

То же верно для запрета. Правило «запретить отправку через `curl`» не запрещает весь терминал: оно влияет только на действие, которое подходит под его описание.

Значит, после разбора строки функцией из [шага 11](#step-11) недостаточно увидеть решение `allow` или `deny`. Сначала нужно установить применимость правила. Несовпавшее правило не принимает отрицательное решение — оно вообще не участвует в решении.

> 🎒 **На пальцах.** Представь купон «скидка на один яблочный пирог». Кассир сначала смотрит, что лежит у тебя на подносе. Для яблочного пирога купон действует; для кофе он не означает ни скидку, ни запрет покупки. Кофе оплачивается по обычным правилам. Так и политика: решение внутри правила включается только после совпадения действия с условием.
