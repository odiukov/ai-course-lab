title: Явное правило описывает действие и решение политики

Ты отнёс `git push` к высокому риску, и агент как раз собирается отправить изменения в удалённый репозиторий. Что теперь делать: разрешить, остановить или позвать тебя? Сам класс риска из [шага 6](#step-6) ответа не даёт — он лишь наклеивает понятную метку.

Ответ появляется в явном правиле. В нём есть две части: описание действия и решение политики — заранее выбранная реакция на это действие. Например: для запуска `git push` решение `ask`. Значит, агент должен запросить подтверждение. Для чтения обычных файлов можно назначить `allow`, а для удаления секретов — `deny`.

Эти три решения важно не смешивать:

- `allow` — выполнить без вопроса;
- `ask` — остановиться и запросить подтверждение;
- `deny` — не выполнять.

В настройках Claude Code решение может выражаться расположением описания действия в разделе `allow`, `ask` или `deny`. Поэтому правило стоит читать целой фразой: не просто «`git push`», а «про `git push` — спросить».

Именно вторая часть превращает описание риска в исполняемую политику. Без неё ты сообщил системе, *что происходит*, но не сказал, *как поступить*.

> 🎒 **На пальцах.** Представь таблички у дверей телестудии: «гримёрная — вход разрешён», «эфирная аппаратная — позови инженера», «архив оригиналов — вход запрещён». Название помещения описывает действие — куда человек хочет войти. Вторая часть задаёт решение. Табличка без слов «разрешено», «позови» или «запрещено» лишь называет дверь, но не управляет доступом.
