Ты выделил KV-кэшу 0,5 ГБ и знаешь контрольную точку: 32 000 токенов занимают 2 ГБ. Теперь нужен не расчёт на бумаге, а функция, которая вернёт безопасный предел контекста — 8 000 токенов.

Напиши `max_context_tokens` с тремя параметрами:

```python
def max_context_tokens(
    reference_tokens: int,
    reference_kv_gb: float,
    kv_budget_gb: float,
) -> int:
    # Твой код
    pass
```

`reference_tokens` — длина контекста в контрольной точке, `reference_kv_gb` — соответствующий объём KV-кэша, а `kv_budget_gb` — сколько памяти разрешено потратить сейчас. Используй зависимость из [шага 27](#step-27), но результат верни целым числом токенов.

Проверь функцию на таких примерах:

```python
max_context_tokens(32_000, 2.0, 0.5)   # 8_000
max_context_tokens(32_000, 2.0, 0.25)  # 4_000
max_context_tokens(32_000, 2.0, 0.0)   # 0
```

Особенно внимательно посмотри на округление. Если вычисление даст, например, `8191.7`, функция не должна обещать `8192`: последний токен уже выходит за бюджет. Для положительных значений отбрось дробную часть, а `reference_kv_gb`, равный нулю или меньше, считай ошибкой — иначе деление не имеет физического смысла.

Функция отвечает только за KV-кэш. Откуда взялся доступный бюджет памяти, здесь пока не решаем.

> 🎒 **На пальцах.** Представь грядку: 32 000 саженцев занимают два гектара, а тебе выделили только половину гектара. Ты уменьшаешь число саженцев в той же пропорции и получаешь 8 000. Если расчёт обещает часть саженца, округлять вверх нельзя: для него уже не найдётся целого места.
