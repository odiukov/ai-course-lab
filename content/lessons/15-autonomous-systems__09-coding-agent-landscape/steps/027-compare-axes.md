Ты заносишь в два профиля результаты JSON tool calls и CodeAct по четырём осям из [шага 26](#step-26). Например, у каждого профиля есть число ходов, композиция, проверяемость и изоляция. Функция `compare_axes` должна пройти по этим осям и вернуть победителя для каждой отдельно: первую архитектуру, вторую или ничью.

Здесь легко ошибиться, просто выбрав везде большее число. Для композиции, проверяемости и изоляции высокая оценка лучше, а для числа ходов — наоборот: три хода хуже одного при одинаковой работе. Поэтому направление сравнения должно зависеть от оси.

Сначала создай пустой результат, затем перебери названия осей. Для `turns` сравнивай значения как стоимость: выигрывает меньшее. Для остальных характеристик считай более высокую оценку преимуществом. Если значения равны, явно запиши ничью — не отдавай победу тому профилю, который случайно оказался первым в условии.

Обрати внимание и на форму результата: ключом остаётся название оси, а значением становится имя победившей архитектуры либо строка, обозначающая равенство. Так следующий код сможет спросить именно про изоляцию или проверяемость, не разбирая одно общее число.

Не пытайся вычислить «абсолютного победителя» подсчётом выигранных осей. Четыре отдельных ответа сохраняют компромисс, ради которого сравнение и затевалось.

> 🎒 **На пальцах.** Ты выбираешь квартиру по цене, площади, свету и тишине. Для площади больше лучше, но для цены — хуже. `compare_axes` похожа на таблицу риелтора: она отмечает победителя в каждой строке, не объявляя квартиру с тремя галочками автоматически лучшей именно для тебя.
