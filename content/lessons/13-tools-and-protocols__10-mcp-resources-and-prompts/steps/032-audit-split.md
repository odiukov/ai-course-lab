  - question: >-
      `summarize_pr` загружает данные pull request и задаёт модели порядок

    options:
      - >-
        Оставить одним tool, потому что данные и инструкция относятся к одной

      - >-
        Вынести данные pull request в resource, а повторяемый порядок анализа —

      - 'Сделать prompt, который сам загружает данные и изменяет pull request'

    explanation: >-

  - question: >-

      - 'Всё оформить как prompt, поскольку итоговый текст создаёт модель'
      - 'Отделить контекст и сценарий подготовки, а публикацию оставить tool'
    correct: 2
    explanation: >-
      Публикация изменяет внешнее состояние и должна оставаться явным действием.
      Исходные данные и сценарий подготовки имеют самостоятельную ценность.

Теперь проверь проекты из [шага 31](#step-31) правилом из [шага 2](#step-2). Частая ловушка — считать одну пользовательскую цель одной MCP-возможностью. Но `triage_issue` может одновременно читать обращение, вести модель по сценарию разбора и менять метки. Если эти части нужны независимо, раздели их: контекст — в resource, порядок рассуждения — в prompt, изменение состояния — в tool. Оставляй единый tool только там, где ценность действительно состоит в неделимом действии.
