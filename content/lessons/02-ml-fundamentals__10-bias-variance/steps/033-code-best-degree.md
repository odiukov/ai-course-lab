Перед тобой несколько кандидатов: степени 1, 2, 3, 5 и 9. Каждая может хорошо подогнаться под обучающие точки, но это ещё не делает её лучшим выбором. Функция `best_degree` должна устроить им одинаковое испытание на данных, которых обучение не использовало.

Для каждой степени ты:

1. обучаешь полином только на обучающей выборке с помощью функции из [шага 23](#step-23);
2. получаешь его предсказания на валидационных точках через `polyval` из [шага 21](#step-21);
3. вычисляешь MSE функцией из [шага 16](#step-16);
4. сравниваешь результат с лучшей ошибкой, найденной ранее.

В конце функция возвращает степень с наименьшей валидационной ошибкой. Не коэффициенты полинома и не саму ошибку — именно степень, которую затем можно использовать для обучения итоговой модели.

Следи за главным разделением ролей: обучающие данные подбирают коэффициенты, а валидационные только оценивают кандидата. Если случайно обучить модель и на валидационных точках, проверка перестанет показывать качество на новых данных.

Удобно начать с «лучшей ошибки», большей любого возможного результата, и обновлять её вместе с лучшей степенью. Если две степени дали одинаковую MSE, оставь первую встретившуюся: поведение функции будет предсказуемым.

> 🎒 **На пальцах.** Ты выбираешь бумажный самолётик для соревнования. Каждый вариант сначала настраиваешь в одном помещении, а затем запускаешь в другом и измеряешь дальность. Побеждает конструкция, лучше прошедшая отдельный испытательный полёт. Если подкручивать крылья уже во втором помещении, это будет не проверка, а продолжение настройки.
