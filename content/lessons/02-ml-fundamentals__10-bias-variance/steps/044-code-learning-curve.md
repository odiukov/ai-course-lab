Ты запускаешь модель на 10 объектах и получаешь test MSE 0,8. Затем берёшь 20 объектов — и видишь 1,1. Неужели дополнительные данные навредили? Скорее всего, тебе просто попались разные случайные выборки. Поэтому один запуск на каждый размер даст ломаную из случайностей, а не надёжную learning curve.

Напиши функцию `learning_curve`, которая принимает список размеров `sizes`, фиксированную степень полинома `degree` и число повторов `n_runs`. Для каждого размера `n` она должна:

1. Несколько раз создавать новую обучающую выборку из `n` объектов с разными `seed`.
2. Обучать полином той же степени через `fit_polynomial` из [шага 23](#step-23).
3. Получать предсказания на обучающих точках и на одной общей тестовой выборке с помощью `polyval` из [шага 21](#step-21).
4. Считать обе ошибки функцией `mean_squared_error` из [шага 16](#step-16).
5. Усреднять train MSE и test MSE по всем повторам.

Верни три одинаково упорядоченных списка или массива: размеры выборок, средние train-ошибки и средние test-ошибки. Значения с одним индексом должны относиться к одному `n`.

Обрати внимание: степень модели и тестовый набор не меняются. Иначе вместе с количеством данных ты незаметно изменишь ещё одно условие, и сравнение потеряет смысл.

> 🎒 **На пальцах.** Ты проверяешь время поездки на работу по разным маршрутам. Один случайный замер легко испортит пробка или зелёная волна светофоров. Поэтому каждый маршрут ты проезжаешь много раз и сравниваешь среднее время. Здесь размер train — выбранный маршрут, а разные `seed` — разные дорожные дни. Усреднение оставляет общий рисунок вместо случайного скачка.
