В ремонтной заявке три работы: закрепить полку, заменить розетку и подтянуть дверную ручку. Для каждой есть свой список инструментов, но отвёртку ты кладёшь в ящик один раз. С контролями та же задача: выбранные фреймворки могут требовать один и тот же контроль, поэтому простое сложение списков создаст дубликаты.

Напиши функцию `required_controls(frameworks)`. Она получает набор выбранных фреймворков и возвращает все контроли, которые относятся хотя бы к одному из них. Связь между контролем и фреймворками уже умеет находить функция `frameworks_for` из [шага 30](#step-30), а принцип объединения без повторов разобран в [шаге 31](#step-31).

Для каждого известного контроля сравни фреймворки, которые он закрывает, с аргументом `frameworks`. Если у наборов есть хотя бы один общий элемент, контроль нужен. Один общий фреймворк уже достаточен: требовать совпадения со всеми входными фреймворками было бы ошибкой.

Обрати внимание на три случая:

- несколько фреймворков ссылаются на один контроль — в результате он появляется один раз;
- ни один фреймворк не выбран — результат пуст;
- неизвестное имя не должно случайно добавлять контроль.

Сейчас функция определяет только совокупность требований. Не проверяй здесь, какие контроли уже внедрены: это отдельная задача следующего шага.

> 🎒 **На пальцах.** Ты собираешь ящик инструментов для нескольких ремонтных заявок. Берёшь всё, что понадобится хотя бы в одной работе, но не кладёшь три одинаковые отвёртки только потому, что она указана в трёх списках. `required_controls` собирает такой общий ящик: полный по требованиям и без повторов.
