Ты запускаешь модель на маске размером \(2 \times 2\): три пикселя угаданы, один перепутан. Ожидаемый результат — `0.75`. Теперь собери функцию `pixel_accuracy(logits, target)`, которая получает логиты формы `(N, C, H, W)` и правильные классы формы `(N, H, W)` — этот контракт разобран в [шаге 18](#step-18).

Сначала преврати логиты в предсказанные номера классов. Для каждого пикселя нужно выбрать канал с наибольшим значением, поэтому ищи максимум именно по измерению классов `C`. Подумай, какой номер измерения оно имеет. Softmax из [шага 20](#step-20) здесь вычислять необязательно: он меняет значения, но не меняет канал-победитель.

После выбора классов форма предсказания должна совпасть с формой `target`. Сравни их поэлементно: получится булева маска, где `True` означает верный пиксель. Доля значений `True` среди всех изображений и всех пространственных позиций и есть ответ. Перед усреднением понадобится преобразовать булевы значения в вещественные.

Проверь функцию на трёх случаях:

- все пиксели угаданы — результат `1.0`;
- ни один не угадан — `0.0`;
- три из четырёх угаданы — `0.75`.

Если число подозрительно высокое, вспомни ловушку доминирующего фона из [шага 21](#step-21): функция может считать правильно, даже когда сама метрика создаёт слишком радужное впечатление.

> 🎒 **На пальцах.** Представь контролёра, сверяющего четыре посадочных талона со списком пассажиров. Каждое совпадение он отмечает галочкой: три галочки из четырёх дают `0.75`. Контролёр не выясняет, на каком рейсе произошла ошибка, — только считает общую долю совпадений. Поэтому множество правильно обработанных пассажиров одного рейса может скрыть провал на другом.
