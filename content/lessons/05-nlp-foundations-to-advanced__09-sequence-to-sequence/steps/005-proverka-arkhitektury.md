  - question: Модель переводит фразу. Как правильно распределены роли между её частями?

      - >-
        Encoder читает исходную фразу, context vector передаёт её сводку,
        decoder по шагам создаёт перевод.
      - >-
        Context vector читает исходную фразу, encoder выбирает следующее слово,

    correct: 1
    explanation: >-
      Encoder обрабатывает вход, его итоговое состояние служит context vector, а

  - question: >-
      Исходное предложение стало длиннее, но размер context vector не изменился.
      Что это означает?
    options:
      - Decoder автоматически получит больше шагов памяти.
      - Encoder перестанет читать слова после достижения размера вектора.
      - В ту же сводку придётся упаковать больше информации.
    correct: 2
    explanation: >-
      Context vector имеет фиксированный размер, поэтому с ростом входа ему
      приходится вмещать больше деталей в то же количество чисел.

Здесь легко перепутать участника, который понимает вход, с участником, который создаёт выход. Держи в голове направление движения информации из [шага 3](#step-3): encoder читает исходную последовательность, context vector переносит её сжатую сводку, а decoder разворачивает эту сводку в новую последовательность слово за словом.

Особенно внимательно следи за формулировкой «context vector генерирует перевод». Сам вектор ничего не генерирует: это данные, которыми encoder инициализирует decoder. А ограничение из [шага 4](#step-4) возникает именно потому, что размер этой сводки не растёт вместе с предложением.
