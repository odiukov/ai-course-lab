check:
  - question: >-
      Какой результат GRU-энкодера используется как context vector в
      классическом seq2seq без attention?
    options:
      - Полная последовательность outputs
      - Финальный hidden state
      - Embedding последнего входного токена
      - Среднее арифметическое embeddings
    correct: 1
    explanation: >-
      Decoder получает финальный hidden state. В примере с 20 токенами и
      hidden_dim 256 это context vector из 256 чисел, тогда как пошаговые
      outputs напрямую не передаются.
  - question: >-
      Длину входной последовательности увеличили вдвое, не меняя hidden_dim. Что
      произойдёт в fixed-context seq2seq?
    options:
      - Размер context vector удвоится
      - Decoder автоматически получит все новые пошаговые состояния
      - 'Пошаговых outputs станет больше, но размер context vector не изменится'
      - Encoder перестанет учитывать первые токены последовательности
    correct: 2
    explanation: >-
      Число состояний в outputs зависит от длины входа, а размер финального
      hidden state задаётся hidden_dim. Поэтому при переходе от 20 к 40 токенам
      context vector по-прежнему содержит 256 чисел.

Перед тобой два результата encoder из [шага 11](#step-11): состояния всех позиций и отдельное последнее состояние. Проверь, не подменяешь ли ты одно другим. В этой версии seq2seq decoder получает именно последнее состояние — context vector. Пошаговые `outputs` были вычислены, но дальше не используются.

Главная ловушка: «игнорируются» не означает «encoder не обработал предыдущие токены». Последнее состояние складывалось по всей последовательности, как разобрано в [шаге 9](#step-9). Однако при любой длине входа канал к decoder остаётся размером `hidden_dim`. Поэтому длинный вход создаёт больше состояний, но не расширяет передаваемый context vector.
