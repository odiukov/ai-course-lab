У тебя есть реальные значения `[3, 5, 7]` и предсказания модели `[2, 5, 9]`. Одного списка промахов недостаточно: для сравнения моделей нужны сразу четыре числа из [шага 28](#step-28). Считать каждое вручную долго, поэтому ты соберёшь функции `mse`, `rmse`, `mae` и `r_squared`.

```python
def mse(y_true, y_pred):
    pass


def rmse(y_true, y_pred):
    pass


def mae(y_true, y_pred):
    pass


def r_squared(y_true, y_pred):
    pass
```

Во всех функциях `y_true` содержит реальные значения, а `y_pred` — предсказания в том же порядке. В `mse` и `mae` пройди по парам через `zip`, сложи преобразованные промахи и раздели сумму на количество наблюдений. Следи, чтобы деление происходило после суммирования, а не внутри цикла.

`rmse` не должна повторять вычисления `mse`: вызови уже написанную функцию и извлеки квадратный корень с помощью `math.sqrt`.

Для `r_squared` понадобятся среднее реальных значений, сумма квадратов ошибок модели и сумма квадратов отклонений реальных значений от их среднего. Есть особый случай: если все реальные значения одинаковы, последняя сумма равна нулю. Чтобы не делить на ноль, верни `0.0`.

Проверь результат на примере выше:

```python
mse(y_true, y_pred)        # примерно 1.667
rmse(y_true, y_pred)       # примерно 1.291
mae(y_true, y_pred)        # 1.0
r_squared(y_true, y_pred)  # 0.375
```

Если эти числа совпали, четыре функции по-разному обобщают одни и те же три промаха — именно этого мы и добивались.

> 🎒 **На пальцах.** Представь три счета за ремонт и три предварительные оценки мастера. Ты один раз сопоставляешь каждый счёт с его оценкой, а затем четыре бухгалтера обрабатывают найденные расхождения по своим правилам. В коде роли бухгалтеров выполняют четыре функции: данные у них общие, но итоговые показатели разные. Поэтому особенно важно не перепутать порядок реальных значений и предсказаний.
