Ты настраиваешь систему тревог и видишь два требования: хорошо расставить случаи по степени риска и принять решения при конкретной границе. Это разные проверки.

Если рабочий порог уже задан, смотри на результаты именно при нём: precision, recall или F1 из [шага 17](#step-17). Если порог ещё предстоит выбрать и нужно оценить порядок, который создаёт модель, пригодится AUC-ROC из [шага 23](#step-23). При редком положительном классе не забывай о PR-кривой из [шага 25](#step-25).

Частая ошибка — считать высокий AUC гарантией хороших решений при любом выбранном пороге. AUC хвалит ранжирование; пороговые метрики проверяют последствия конкретной границы.
