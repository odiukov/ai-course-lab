check:
  - question: >-
      Рабочий порог уже выбран. Нужно оценить, какая доля тревог ложна и какая
      доля опасных случаев пропущена. Какие метрики следует проверить?
    options:
      - Precision и recall при рабочем пороге
      - Только AUC-ROC
      - Только долю положительных объектов в данных
    correct: 0
    explanation: >-
      Precision отражает надёжность положительных срабатываний, а recall — долю
      обнаруженных положительных объектов. Обе метрики вычисляются для
      конкретного порога.
  - question: >-
      Рабочий порог ещё не выбран. Нужно сравнить, насколько хорошо модели
      ставят положительные примеры выше отрицательных. Какая метрика подходит?
    options:
      - Accuracy при произвольно выбранном пороге
      - Количество положительных предсказаний
      - AUC-ROC
    correct: 2
    explanation: >-
      AUC-ROC оценивает качество ранжирования по множеству порогов и не
      привязана к одной границе принятия решения.
---

Ты настраиваешь систему тревог и видишь два требования: хорошо расставить случаи по степени риска и принять решения при конкретной границе. Это разные проверки.

Если рабочий порог уже задан, смотри на результаты именно при нём: precision, recall или F1 из [шага 17](#step-17). Если порог ещё предстоит выбрать и нужно оценить порядок, который создаёт модель, пригодится AUC-ROC из [шага 23](#step-23). При редком положительном классе не забывай о PR-кривой из [шага 25](#step-25).

Частая ошибка — считать высокий AUC гарантией хороших решений при любом выбранном пороге. AUC хвалит ранжирование; пороговые метрики проверяют последствия конкретной границы.
