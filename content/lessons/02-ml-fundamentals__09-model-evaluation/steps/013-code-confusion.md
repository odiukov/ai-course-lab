Перед тобой две короткие последовательности: правильные ответы и предсказания модели. Например, для шести объектов:

- правильные ответы: `1, 0, 1, 0, 1, 0`;
- предсказания: `1, 1, 0, 0, 1, 0`.

Функция `confusion_matrix(y_true, y_pred)` должна сопоставить элементы на одинаковых позициях и посчитать четыре исхода из [шага 10](#step-10). Первый элемент пары — реальный класс, второй — предсказанный. Не перепутай их: пара `(0, 1)` увеличивает `fp`, а `(1, 0)` — `fn`.

Для перебора удобно использовать `zip(y_true, y_pred)`: он соединит две последовательности в пары. Затем для каждого из четырёх счётчиков нужно проверить своё сочетание нулей и единиц. Подход с `sum` читается буквально: прибавляй единицу за каждую пару, которая соответствует нужному исходу. Можно считать каждый исход отдельно — главное, чтобы условия не пересекались и ни одна пара не потерялась.

Верни четыре числа именно в порядке `tp, tn, fp, fn`. Для примера выше результат должен быть `(2, 2, 1, 1)`: дважды совпали единицы, дважды совпали нули и по одному разу встретились ошибки каждого вида.

Проверь ещё два крайних случая: полностью верные предсказания не должны давать `fp` или `fn`, а пустые входные последовательности должны вернуть четыре нуля. Считай, что обе последовательности имеют одинаковую длину: `zip` иначе незаметно отбросит лишние элементы более длинной.

Здесь функция превращает пары ответов в четыре надёжных счётчика — ровно тот процесс, который ты разобрал в [шаге 12](#step-12).

> 🎒 **На пальцах.** Представь сверку списка гостей с отметками охранника. В каждой строке есть два факта: был ли человек приглашён и пропустил ли его охранник. Ты проходишь строки попарно и ставишь засечки четырёх видов. Если читать сначала решение охранника, а потом список, две разновидности ошибок поменяются местами — поэтому порядок пары здесь критичен.
