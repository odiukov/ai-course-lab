title: 'Проверка: обычное или стратифицированное разбиение'
source_anchor: '### Common Evaluation Mistakes'
check:
  - question: >-
      У тебя 1000 операций, из них только 20 мошеннических. Какое разбиение даст
      более надёжную проверку?
    options:
      - 'Обычное: редкие случаи распределятся сами'
      - >-
        Стратифицированное: доля мошеннических операций сохранится в каждой
        части
      - 'Обычное: все мошеннические операции нужно оставить только для validation'
    correct: 1
    explanation: >-
      Стратификация распределяет редкий класс по частям примерно в исходной
      пропорции. Иначе в некоторых частях мошеннических операций может оказаться
      слишком мало.
  - question: >-
      При обычном разбиении одна validation-часть случайно получила один объект
      редкого класса. Чем это опасно?
    options:
      - Модель не сможет обучиться ни на одном классе
      - Размер validation-части автоматически уменьшится
      - Оценка будет сильно зависеть от единственного предсказания
    correct: 2
    explanation: >-
      Одна ошибка на единственном редком объекте резко изменит метрику, поэтому
      сравнение моделей станет нестабильным.
---

Теперь ты должен уметь выбирать способ разбиения по распределению классов. Обычный K-fold допустим, когда классы представлены достаточно широко и случайные различия между частями не создают проблемы. При редком классе выбирай стратифицированный вариант из [шага 40](#step-40): он сохраняет его долю в каждой части. Частая ловушка — смотреть только на одинаковый размер частей. Равное число объектов ещё не означает одинаковое представительство классов.

> 🎒 **На пальцах.** Ты раскладываешь по пяти конвертам 100 билетов, среди которых лишь 10 красных. Если перемешать их без контроля, один конверт может остаться почти без красных. Если сначала распределить красные, а затем остальные, каждый конверт даст более честное представление всей пачки.
