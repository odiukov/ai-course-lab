После свёртки ты видишь 75 каналов и сталкиваешься со странностью: где среди них клетки, три anchor box и параметры рамок? Они не исчезли — просто пока уложены неудобно.

Возьмём голову с 3 anchor box и 20 классами. Для каждого anchor box нужны 25 значений: четыре параметра рамки, objectness и 20 оценок классов, знакомые по [шагу 7](#step-7). Поэтому свёртка выдаёт в каждой точке карты \(3 \cdot 25 = 75\) каналов. Пространственные измерения при этом сохраняются: если входная карта была размером \(13 \times 13\), выход остаётся сеткой \(13 \times 13\), только у каждой клетки теперь лежат 75 чисел.

Сначала эти каналы группируют: 75 превращаются в 3 группы по 25. Это операция `view` — она ничего не вычисляет и не меняет значений, а лишь по-новому размечает уже существующую последовательность чисел. Получается форма `(N, 3, 25, 13, 13)`.

Затем `permute` переставляет измерения в удобный порядок: `(N, 13, 13, 3, 25)`. Теперь можно естественно читать ответ: выбери изображение, клетку, anchor box — и получишь его 25 предсказаний. Свёртка создала числа, а перестройка дала каждому числу понятный адрес.

> 🎒 **На пальцах.** Представь кухонное табло: для каждого столика принтер выдаёт длинную ленту из 75 отметок. Повар разрезает её на три заказа по 25 отметок — по одному для каждого возможного размера блюда. Затем заказы раскладывают по столикам. Еда от перекладывания не изменилась; просто теперь сразу видно, какой набор отметок относится к какому столику и заказу.
