У тебя есть две группы рамок: например, 3 предсказания и 2 эталона. Сравнивать только рамки с одинаковыми номерами нельзя — каждое предсказание нужно сопоставить с каждым эталоном. Поэтому функция `box_iou(boxes_a, boxes_b)` должна вернуть не одно число, а матрицу размером `3 × 2`.

Обе группы приходят как массивы формы `(N, 4)`, где строка хранит координаты `(x1, y1, x2, y2)`. Сначала раздели каждый массив на четыре столбца координат. Затем добавь к координатам новые измерения: `[:, None]` для первой группы и `[None, :]` для второй. NumPy растянет их навстречу друг другу и сразу выполнит все попарные сравнения.

Для каждой пары найди границы пересечения по правилам из [шага 22](#step-22). Особенно внимательно посмотри на ширину и высоту пересечения: если правая граница оказалась левее левой, разность будет отрицательной. Ограничь её снизу нулём через `np.clip`. То же сделай с высотой — иначе две раздельные рамки неожиданно дадут положительную площадь.

После этого посчитай площади исходных рамок, площадь объединения и IoU по правилу из [шага 21](#step-21). В знаменателе используй `np.clip` с маленькой нижней границей вроде `1e-8`, чтобы вырожденная рамка нулевой площади не вызвала деление на ноль.

Проверь главное: результат должен иметь форму `(N_a, N_b)`, а каждый его элемент — сравнивать одну рамку из первой группы с одной рамкой из второй.

> 🎒 **На пальцах.** Представь турнир, где три игрока встречаются с двумя соперниками. Таблица результатов содержит три строки и два столбца: отдельная ячейка для каждой встречи. `[:, None]` и `[None, :]` устраивают все эти пары автоматически, а `clip` работает как судья: если общей территории у пары нет, он записывает честный ноль, а не отрицательную площадь.
