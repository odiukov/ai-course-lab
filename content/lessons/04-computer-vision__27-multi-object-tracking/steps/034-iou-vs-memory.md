Посмотри на двух людей, которые идут навстречу друг другу: один в рыжей куртке, другой — в синей. До встречи рамки разделены, и IoU-tracker уверенно продолжает оба трека. Затем люди перекрываются, детектор на несколько кадров видит только одну рамку — или не видит ни одной. Когда они расходятся, перед tracker-ом снова две детекции.

Какой старый ID отдать каждой?

Для IoU важнее всего положение рамок. Как в [шаге 27](#step-27), при плотном пересечении геометрия становится неоднозначной: обе новые рамки могут оказаться почти одинаково близки к предсказаниям старых треков. Если перекрытие длится долго, неопределённость растёт, трек стареет и может быть удалён по правилам из [шага 22](#step-22). Поэтому после появления людей tracker способен поменять их ID местами или создать новые.

Memory bank из [шага 33](#step-33) переносит через перекрытие не только последнее положение, но и признаки конкретного объекта. Пока рыжая куртка скрыта, её запись остаётся в памяти. Когда человек появляется с другой стороны, новая область кадра сравнивается с накопленным представлением, и ID можно восстановить вопреки неожиданной позиции.

Память тоже может ошибиться, например если объекты выглядят почти одинаково. Но длинное исчезновение для неё не означает автоматическую потерю личности: координаты пропали, а признаки остались.

> 🎒 **На пальцах.** Представь двух фигуристов — с рыжей и синей лентой — которые одновременно въехали за непрозрачную ширму. Судья, помнящий только точки входа, назначит номера тем, кто вышел ближе к ожидаемой стороне, и ошибётся, если фигуристы поменялись местами. Судья с альбомом деталей костюмов узнает каждого по ленте, даже когда сторона выхода оказалась другой.
