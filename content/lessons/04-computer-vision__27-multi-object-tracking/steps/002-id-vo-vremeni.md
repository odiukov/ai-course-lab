title: Tracking связывает детекции одного объекта общим ID
source_anchor: '## The Problem'
---

На первом кадре ты видишь два одинаковых белых фургона: один у светофора, другой выезжает со двора. Детектор обводит оба рамками. Через секунду он снова находит две рамки — но сами по себе они никак не говорят, где прежний фургон, а где новый результат измерения. Если складывать такие находки, один автомобиль быстро превратится в десятки «объектов» — именно с этой проблемой памяти мы столкнулись на [шаге 1](#step-1).

Tracker добавляет к каждой детекции постоянный **ID** — идентификатор, похожий на номер участника забега. Например, первый фургон получает ID 7, второй — ID 12. На следующем кадре рамки строятся заново, однако tracker сравнивает их с уже известными объектами и решает: эта рамка продолжает историю ID 7, а та — историю ID 12.

Такое сопоставление называют **association**: будто ты раскладываешь новые фотографии по уже заведённым папкам. В папке ID 7 постепенно накапливаются положения одного фургона в разные моменты времени. Если рядом появилась третья машина, для неё открывается новая папка с новым ID.

Важно: ID принадлежит не рамке и не координатам. Рамка может сдвигаться, менять размер или ненадолго исчезать; ID обозначает предполагаемый физический объект. Поэтому вопрос tracker’а звучит не «что найдено здесь?», а «чью историю продолжает эта находка?».

> 🎒 **На пальцах.** Представь гардероб, где каждую минуту фотографируют висящие пальто. Детектор на каждом снимке лишь отмечает: «здесь пальто». Tracker прикрепляет к каждому мысленный номерок и переносит его на следующую фотографию. Положение пальто изменилось — номерок остался. Благодаря этому десять снимков одного пальто не превращаются в десять разных пальто.
