---

На реальном ролике один объект внезапно получает новый ID. Где ошибка: детектор неточно поставил рамку или tracker потерял связь между кадрами? По видео это трудно разделить — обе части работают одновременно.

Убери видео и детектор. Создай 20 наборов рамок для трёх воображаемых объектов: начальная позиция каждого известна, а затем рамка на каждом кадре сдвигается по прямой с постоянной скоростью. Эти готовые наборы можно передать функции из [шага 25](#step-25) так, будто они пришли от детектора. Случайные начальные позиции и скорости фиксируются параметром `seed`, поэтому один и тот же тест всегда можно повторить.

Теперь у тебя есть точное ожидание: каждый из трёх объектов должен сохранить свой ID на всех 20 кадрах. Если ID переключился, обвинять изображение, освещение или качество детектора уже нельзя — проверяются только механика сопоставления, обновление состояния и жизненный цикл треков из [шагов 22](#step-22)–[24](#step-24).

Такой тест не доказывает, что tracker справится с настоящей улицей. Зато он отвечает на более узкий и важный вопрос: правильно ли соединены уже написанные детали. Сначала добейся нуля переключений в предсказуемой среде — тогда ошибки на видео будет легче искать по слоям.

> 🎒 **На пальцах.** Представь три цветные фишки, которые ты двигаешь по разграфленному столу по заранее записанным маршрутам. Ты точно знаешь, где должна оказаться каждая фишка после каждого хода. Если журнал внезапно назвал синюю фишку красной, проблема не в плохом освещении или нечёткой фотографии: ошибся именно тот, кто вёл журнал. Синтетические траектории создают tracker-у такую же честную проверку.
