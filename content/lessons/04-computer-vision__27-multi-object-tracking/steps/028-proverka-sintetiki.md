  - question: >-
      Почему tracker сохранит прежний ID рамки размером 20×20 пикселей после

    options:
      - >-
        Пересечение остаётся достаточно большим, поэтому IoU проходит порог и
        детекция сопоставляется с существующим треком
      - >-
        Любая движущаяся рамка автоматически получает ID ближайшего трека

      - >-
        Tracker сравнивает только размеры рамок, поэтому их положение не влияет

    correct: 0
    explanation: >-
      Область пересечения имеет размер 15×20 пикселей. IoU равен 300 / 500 =
      0,6, что выше порога 0,3, поэтому association сохраняет прежний ID.
  - question: >-
      Почему после горизонтального сдвига рамки 20×20 пикселей на 25 пикселей
      сопоставление только по IoU не сохранит её прежний ID?
    options:
      - >-
        Сдвиг превышает ширину рамки, поэтому пересечения нет и пара не проходит
        IoU-порог
      - >-
        Алгоритм Hungarian запрещает сопоставлять рамки, центры которых изменили

        При большом сдвиге IoU становится отрицательным, поэтому создаётся новый

    correct: 0
    explanation: >-
      Рамки разделены зазором, поэтому площадь пересечения и IoU равны нулю.
      Пара не проходит порог 0,3, и новая детекция не связывается с прежним
      треком.
---

Здесь важно не перепутать величину сдвига с IoU. Для рамки 20×20 сдвиг на 5 пикселей оставляет широкую общую область, поэтому IoU получается около 0,6 — выше порога 0,3 из [шага 16](#step-16). При сдвиге на 25 пикселей рамки уже не соприкасаются: IoU равен нулю, и связь ID разрывается.

> 🎒 **На пальцах.** Представь штамп шириной 20 клеток. Сдвинь второй отпечаток на 5 клеток — большая часть рисунка совпадёт. Сдвинь на 25 — между отпечатками появится зазор, и по наложению их уже не связать.
