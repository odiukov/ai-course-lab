Перед тобой три кадра: в первых двух есть одна рамка, а в третьем детекций нет. Если создать новый tracker для каждого кадра, человек оба раза получит ID `1` — но не потому, что система узнала его. Она просто каждый раз начинала счёт заново. На видео с двумя объектами такая ошибка быстро проявится прыгающими и повторяющимися ID.

В `run_tracker` тебе нужно один раз создать tracker, а затем последовательно передать ему детекции каждого кадра. Номер кадра должен расти на каждой итерации: по нему tracker определяет возраст треков, как разобрано в [шаге 23](#step-23). После каждого вызова сохрани выданные пары из ID и рамки, чтобы результат сохранил покадровую структуру.

Особенно внимательно обработай пустой кадр. Его нельзя пропускать: вызов tracker-а без детекций всё равно старит существующие треки. Если просто перейти к следующему элементу, для tracker-а время будто остановится, и `max_age` перестанет означать число пропущенных кадров.

В результате должна получиться последовательность той же длины, что и вход: один список треков на каждый кадр, включая пустые списки. Не объединяй всё в один плоский список и не пересоздавай состояние внутри цикла. Именно сохранённое между вызовами состояние превращает покадровые рамки в историю с устойчивыми ID, о которой шла речь в [шаге 24](#step-24).

> 🎒 **На пальцах.** Представь контролёра, который каждый вечер записывает жильцов, вошедших в подъезд. У него один журнал на всю неделю: новые люди получают номера, знакомые сохраняют старые, а давно не появлявшиеся вычёркиваются. Если каждое утро выдавать контролёру чистый журнал или не отмечать тихие вечера, история распадётся. `run_tracker` бережно проводит один журнал через все кадры.
