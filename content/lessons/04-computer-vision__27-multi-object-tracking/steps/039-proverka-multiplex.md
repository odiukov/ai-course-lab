check:
  - question: >-
      В сцене число объектов выросло с 5 до 50. Почему общая память выгоднее
      отдельных memory bank?
    options:
      - >-
        Общие признаки кадра обрабатываются совместно, а объекты различаются
        query-токенами
      - >-
        Система перестаёт хранить историю объектов и использует только текущий
        кадр
      - 'Все объекты получают один ID, поэтому сопоставление больше не требуется'
    correct: 0
    explanation: >-
      Общая память не копируется для каждого объекта: её содержимое используется
      совместно, а query-токены сохраняют разделение экземпляров.
  - question: Что означает сублинейный рост стоимости при добавлении объектов?
    options:
      - Стоимость вообще не меняется при любом числе объектов
      - Каждый новый объект делает обработку ровно вдвое дороже
      - 'Стоимость растёт, но медленнее, чем число объектов'
    correct: 2
    explanation: >-
      Новые query-токены требуют ресурсов, однако общую память не приходится
      заново читать и хранить отдельно для каждого объекта.
---

Ты запускаешь tracking сначала для нескольких людей, а затем для плотной толпы. В варианте с отдельными memory bank почти каждый новый человек приносит ещё одну полноценную память. В общей памяти из [шага 38](#step-38) значительная часть работы переиспользуется, а query-токены из [шага 37](#step-37) не дают людям слиться в один объект.

Здесь легко сделать слишком сильный вывод: общая память не превращает 50 объектов в стоимость одного. Query-токены тоже нужно обрабатывать. Выгода в другом — стоимость растёт медленнее числа объектов, потому что общие пространственно-временные признаки не дублируются для каждого экземпляра. Чем плотнее сцена, тем заметнее эта экономия.
