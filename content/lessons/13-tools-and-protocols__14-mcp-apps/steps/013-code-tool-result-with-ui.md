Две функции уже лежат готовые: [`is_ui_uri`](#step-5) отличает `ui://notes/timeline` от обычного URI, [`ui_resource_contents`](#step-7) собирает ответ на `resources/read`. А теперь позови их обе — и заметь, что вызов инструмента всё равно нечего вернуть хосту. Не хватает конверта: той структуры, которую `tools/call` кладёт в ответ.

Её и пишем — `tool_result_with_ui`.

На вход она берёт три вещи: текст для модели, URI интерфейса и, необязательно, список запрашиваемых разрешений. На выходе — обычный словарь Python с двумя ключами: `content` и `_meta`. Никакого HTML внутри, ни единой строчки: адрес и бандл разъехались по разным запросам ещё в [шаге 8](#step-8), и склеивать их обратно тут не надо.

В `content` — два элемента, текстовый первым: разделение ролей разбирал [шаг 11](#step-11). В `_meta.ui` — три поля из [шага 12](#step-12): `resourceUri`, `csp`, `permissions`.

Где обычно ломается. Первое: URI попадает в структуру дважды — в `ui_resource` и в `resourceUri`. Разошлись на один символ — хост прочитает не тот ресурс или не прочитает ничего. Собирай оба из одной переменной. Второе: прогони URI через `is_ui_uri` на входе и падай с внятной ошибкой, а не отдавай наружу битый результат. Третье: `permissions` по умолчанию — пустой список, и не ставь `[]` прямо в сигнатуре: в Python такой список один на все вызовы, и разрешение, добавленное для одного инструмента, тихо всплывёт у следующего.

Проверь себя так: результат функции должен сериализоваться в JSON без единой правки руками.
