  - question: >-
      Инструмент вернул результат, в _meta.ui стоит resourceUri со значением
      ui://notes/timeline. Что клиент увидит в этот момент?
    options:
      - Готовый HTML интерфейса — он уже пришёл вместе с результатом инструмента
      - Только адрес; HTML клиент забирает отдельным запросом resources/read
      - 'Ни адреса, ни HTML: интерфейс собирается из текста в content'
    correct: 1
    explanation: >-
      Результат инструмента отдаёт только ссылку ui://, а сам бандл приходит
      вторым шагом — через resources/read по этому адресу.
  - question: >-
      Ты смотришь CSP интерфейса и видишь connect-src со звёздочкой. Почему это
      плохо, если сам iframe изолирован песочницей?
    options:
      - 'Песочница вообще перестаёт работать, когда в CSP есть звёздочка'
      - 'Изоляция мешает интерфейсу читать данные, а звёздочка это лечит'
      - >-
        Песочница не пускает внутрь, но не мешает скрипту отправить данные
        пользователя на любой чужой сервер
    correct: 2
    explanation: >-
      Данные уже внутри iframe. Открытый connect-src разрешает отослать их куда
      угодно — изоляция от этого не спасает.
  - question: >-
      Интерфейс через postMessage просит хост вызвать инструмент, которого
      сервер не объявлял. Что должно произойти?
    options:
      - >-
        Вызов не проходит: кнопка в UI не даёт больше прав, чем есть у самого
        сервера
      - 'Проходит, если пользователь подтвердил разрешения при отрисовке'
      - 'Проходит: postMessage идёт напрямую в браузере, минуя проверки хоста'
    correct: 0
    explanation: >-
      Хост выполняет только то, что сервер и так может. UI — это ещё один способ
      нажать на уже существующие возможности, а не отдельный канал прав.
  - question: >-
      Что не так с отправкой сообщения хосту через postMessage с targetOrigin,
      равным звёздочке?
    options:
      - Сообщение просто не дойдёт — браузер требует конкретный адрес
      - >-
        Звёздочка означает «любой получатель»: содержимое сообщения может
        прочитать посторонний origin
      - 'Ничего: звёздочка касается только приёма, а на отправке безопасна'
    correct: 1
    explanation: >-
      Звёздочка снимает проверку получателя, поэтому данные могут уйти не тому
      окну. На приёме симметрично нужно сверять event.origin до разбора данных.

Этот урок дальше в курсе работает как чек-лист. Когда ты будешь смотреть на чужой MCP App — свой или из чужого репозитория, — тебе понадобятся ровно те пять пунктов, что мы собрали в [шаге 40](#step-40): адрес `ui://`, MIME с профилем, два шага получения, `_meta.ui`, границы песочницы.

Спотыкаются обычно на трёх местах. Первое: кажется, что инструмент отдаёт HTML — нет, только адрес. Второе: песочницу принимают за полную защиту и не смотрят `connect-src`. Третье: думают, что кнопка в интерфейсе расширяет права.

Проверь себя на вопросах — именно эти три места они и трогают.
