  - question: >-
      Инструмент вернул результат, в _meta.ui стоит resourceUri со значением
      ui://notes/timeline. Что клиент увидит в этот момент?
    options:
      - Готовый HTML интерфейса — он уже пришёл вместе с результатом инструмента
      - Только адрес; HTML клиент забирает отдельным запросом resources/read
      - 'Ни адреса, ни HTML: интерфейс собирается из текста в content'
    correct: 1
    explanation: >-
      Результат инструмента содержит адрес UI-ресурса. Сам HTML-бандл клиент
      получает отдельно через resources/read по этому адресу.
  - question: >-
      Ты смотришь CSP интерфейса и видишь connect-src со звёздочкой. Почему это
      опасно, даже если iframe изолирован песочницей?
    options:
      - Звёздочка полностью отключает песочницу iframe
      - >-
        Песочница ограничивает доступ интерфейса к окружению хоста, но не
        отменяет разрешённую CSP отправку данных на произвольные адреса
      - >-
        Звёздочка запрещает все исходящие запросы, из-за чего интерфейс
        перестаёт работать
    correct: 1
    explanation: >-
      Песочница и CSP решают разные задачи. Изоляция iframe не предотвращает
      утечку уже доступных интерфейсу данных, если connect-src разрешает
      отправлять их куда угодно.
  - question: >-
      Интерфейс через postMessage просит хост вызвать инструмент, которого
      сервер не объявлял. Что должно произойти?
    options:
      - >-
        Вызов не проходит: кнопка в UI не даёт больше прав, чем есть у самого
        сервера
      - 'Вызов проходит, если пользователь подтвердил разрешения при отрисовке'
      - 'Вызов проходит, потому что postMessage позволяет обойти проверки хоста'
    correct: 0
    explanation: >-
      Хост разрешает UI обращаться только к доступным и объявленным
      возможностям. Интерфейс предоставляет другой способ инициировать действие,
      но не расширяет полномочия сервера.
  - question: >-
      Что не так с отправкой сообщения хосту через postMessage с targetOrigin,
      равным звёздочке?
    options:
      - >-
        Сообщение не дойдёт, потому что браузер принимает только конкретный
        origin
      - >-
        Сообщение можно доставить документу неожиданного origin, если он
        оказался в целевом окне
      - 'Ничего: targetOrigin влияет только на приём сообщений'
    correct: 1
    explanation: >-
      Звёздочка отключает проверку origin целевого документа. Конкретный
      targetOrigin позволяет браузеру не отправлять сообщение, если в целевом
      окне находится неожиданный получатель.

Этот урок дальше в курсе работает как чек-лист. Когда ты будешь смотреть на чужой MCP App — свой или из чужого репозитория, — тебе понадобятся ровно те пять пунктов, что мы собрали в [шаге 40](#step-40): адрес `ui://`, MIME с профилем, два шага получения, `_meta.ui`, границы песочницы.

Спотыкаются обычно на трёх местах. Первое: кажется, что инструмент отдаёт HTML — нет, только адрес. Второе: песочницу принимают за полную защиту и не смотрят `connect-src`. Третье: думают, что кнопка в интерфейсе расширяет права.

Проверь себя на вопросах — именно эти три места они и трогают.
