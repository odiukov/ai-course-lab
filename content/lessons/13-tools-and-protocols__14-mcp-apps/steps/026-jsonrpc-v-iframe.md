Ты поставил в свой HTML кнопку «Сохранить». Человек нажимает — и что дальше? Прямого выхода к серверу у iframe нет, [шаг 14](#step-14) и [шаг 15](#step-15) закрыли его наглухо. Остался один провод из [шага 25](#step-25) — `postMessage`. Значит, надо придумать, в каком виде отправить по нему просьбу «обнови заметку note-14»?

Придумывать не нужно. По этому проводу летит тот же конверт JSON-RPC 2.0, которым хост и сервер разговаривают в `tools/call` и `resources/read` из [шага 9](#step-9). Те же четыре поля:

```js
window.parent.postMessage({
  jsonrpc: "2.0",
  id: 1,
  method: "host.callTool",
  params: { name: "notes_update", arguments: { id: "note-14", title: "..." } }
}, HOST_ORIGIN);
```

Хост отвечает конвертом с тем же `id: 1` и полем `result`. По `id` ты и понимаешь, на какой из трёх отправленных запросов пришёл ответ. (Второй аргумент `postMessage` — отдельный разговор, к нему придём вплотную.)

Методов, которые UI может позвать у хоста, ровно четыре: `host.callTool` — вызвать инструмент, `host.readResource` — прочитать ресурс, `host.getPrompt` — забрать шаблон промпта, `host.close` — закрыть интерфейс.

Заметь, чего в этом списке нет: ничего, чего не умеет сам MCP-сервер. Твоя кнопка не получает новых полномочий — она превращается в обычный `tools/call` через хост, с теми же согласованиями. UI — удобная морда к уже знакомым методам, а не второй, тихий канал власти.

> 🎒 **На пальцах.** Как пневмопочта в старой аптеке. Ты кладёшь в капсулу тот же бланк, что заполняют у прилавка, — не новую форму, — и труба уносит её в подсобку. Обратно приезжает капсула с твоим же номером. И привезёт она только то, что вообще есть на полках: труба не добавляет тебе прав, она лишь избавляет от похода в подсобку.
