Ты включил в запросе `response_format: { type: "json_object" }` — одну строчку. И логи стали чистыми: те четыре поломки из [шага 3](#step-3) исчезли. Ни markdown-заборчиков, ни «Конечно, вот ваш JSON:» перед скобкой, ни обрыва на середине. `json.loads()` больше не падает никогда.

А приложение всё равно упало.

Посмотри, что пришло на запрос про чек из кофейни:

```json
{ "итого": "1290 ₽", "позиции": 3, "комментарий": "чек читаемый" }
```

Разобралось идеально. Только код ждал ключ `total` с числом, а получил `итого` со строкой. Дальше `data["total"]` — и `KeyError`. Числа `1290` нет, есть текст «1290 ₽», который не сложить с другими чеками. Плюс лишний `комментарий`, которого никто не просил.

Откуда такой разрыв? JSON mode работает на уровне синтаксиса. Он держит скобки парными, кавычки закрытыми, запятые на местах — то есть гарантирует, что текст **разберётся**. Какие внутри ключи и какого типа значения — вне его ведома. Это принуждение на уровне грамматики, а не на уровне смысла.

Значит, ты перешёл с примерно 90 % на уровень выше по спектру из [шага 7](#step-7), но купил только половину. Синтаксические падения ушли навсегда, а поле, которое модель назвала по-своему, ломает приложение ровно так же — просто на строчку ниже в трассировке.

> 🎒 **На пальцах.** Курьер обещает: коробка дойдёт заклеенной, углы целы, ничего не просыплется по дороге. Он держит слово — коробка приезжает идеальной. Ты открываешь: внутри вместо трёх чашек лежит чайник и записка. Претензий к курьеру нет, он отвечал за упаковку. За содержимое отвечает тот, кто складывал. JSON mode — это курьер.
