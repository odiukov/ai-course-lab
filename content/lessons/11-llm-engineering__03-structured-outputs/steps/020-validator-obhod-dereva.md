У тебя на руках объект: `parse_llm_json` из [шага 19](#step-19) вернул словарь. И есть схема из [шагов 12](#step-12)–[14](#step-14). Осталось свести одно с другим.

Первый порыв — написать проверки подряд: есть ли ключ `title`, строка ли он, есть ли `price`, число ли. Работает ровно до момента, когда в схеме появляется массив объектов, а внутри объекта — ещё один объект. Сколько уровней вложенности заранее? Неизвестно. Значит, столбиком `if` не отделаешься.

Но посмотри на задачу иначе. Проверить массив — это проверить каждый его элемент по схеме `items`. Проверить объект — проверить каждое его поле по своей схеме. То есть большая проверка каждый раз разваливается на такие же проверки поменьше. Одна функция `_validate` смотрит на `type` в схеме, и если внутри есть что-то вложенное, зовёт саму себя. Дерево данных и дерево схемы она обходит параллельно, шаг в шаг.

Второе решение здесь важнее первого. Функция ничего не бросает и ничего не возвращает — она дописывает строку в общий список `errors`. Почему не остановиться на первой ошибке? Потому что модель редко ошибается один раз: пропущенный `required`, лишний вариант вне `enum` и цена `-5` приезжают вместе. Упади ты на первой — увидишь их за три прогона вместо одного.

Пустой список — всё сошлось. Непустой — вот тебе весь перечень претензий сразу.
