check:
  - question: >-
      Схема требует product типа string, price типа number с minimum 0 и
      in_stock типа boolean. Поле categories — необязательный массив строк.
      Какой объект пройдёт валидацию?
    options:
      - '{"product": "Кофемолка", "price": 4990, "in_stock": true}'
      - >-
        {"product": "Кофемолка", "price": 4990, "categories": ["техника",
        "кухня"]}
      - >-
        {"product": "Кофемолка", "price": -5, "in_stock": true, "categories":
        []}
      - '{"product": "Кофемолка", "price": "4990 руб.", "in_stock": true}'
    correct: 0
    explanation: >-
      Первый объект содержит все обязательные поля с допустимыми типами и
      значениями. В остальных отсутствует in_stock, нарушено ограничение minimum
      или вместо числа передана строка.
  - question: >-
      Модель вернула {"price": "199"}, то есть записала значение в кавычках. Что
      произойдёт при проверке поля по схеме {"type": "number", "minimum": 0}?
    options:
      - 'Объект пройдёт проверку, потому что содержимое строки похоже на число'
      - >-
        Объект не пройдёт проверку, потому что строка не соответствует типу
        number
      - Объект пройдёт проверку с предупреждением о преобразовании типа
    correct: 1
    explanation: >-
      JSON Schema проверяет фактический тип значения и не обязана автоматически
      преобразовывать строку в число. Сначала нарушается type: number, поэтому
      minimum к этой строке не применяется.

Теперь у тебя есть схема и есть объект — и нужно за пару секунд сказать, состыкуются они или нет. Это ровно та операция, которую в проде делает валидатор, и ошибаться в ней ты будешь чаще всего в двух местах.

Первое: путать «поле описано в properties» с «поле обязательно». Описано — значит, если пришло, то должно быть нужного типа. Обязательно — только то, что перечислено в `required` ([шаг 13](#step-13)).

Второе: смотреть на значение глазами, а не типом. `"199"` читается как число, но для схемы это строка — и ограничения вроде `minimum` к ней просто неприменимы.
