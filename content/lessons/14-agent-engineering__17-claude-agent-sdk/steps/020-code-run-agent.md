Четыре куска уже лежат на столе: заглушка модели из [шага 6](#step-6), отбор инструментов из [шага 8](#step-8), хуки из [шага 11](#step-11) и обёртка `call_tool` из [шага 14](#step-14). Каждый работает отдельно. Но пока никто не решает, что за чем.

Вот и вопрос: кто скажет «спроси модель», а потом «а теперь позови инструмент»?

Это и есть `run_agent`. На входе — задача и, скажем, `max_steps=6`. Дальше он крутит один и тот же круг: дёрнуть `session_start`, потом на каждом шаге спросить модель, посмотреть на ответ и развилка. Пришёл вызов инструмента — отдать его в `call_tool` (не напрямую в реестр: иначе хуки из [шага 13](#step-13) останутся не у дел), результат дописать в контекст одной строкой наблюдения и пойти по кругу заново. Пришёл готовый текст — выйти из цикла, дёрнуть `session_end`, вернуть ответ.

Зачем счётчик шагов? Потому что заглушка может зациклиться и просить `read_file` вечно. Шесть клеток — шесть попыток, потом выход по лимиту, честно помеченный как «не уложился».

Смотри при запуске на две вещи. Первая: длина контекста после каждой итерации — она обязана расти ровно на одну строку, не на весь файл. Вторая: порядок хуков в трассе — `PreToolUse` строго перед каждым вызовом, `PostToolUse` строго после. Если увидел вызов без пары — значит, инструмент проскочил мимо обёртки.

> 🎒 **На пальцах.** Как администратор в поликлинике. Пациент не бегает между кабинетами сам — после каждого возвращается к стойке с талоном. Администратор смотрит запись в талоне и решает: ещё кабинет или домой. Талон на шесть клеток — значит, шесть кабинетов максимум, дальше выпроводят и без диагноза. И в карту идёт строчка заключения, а не вся распечатка анализов.
