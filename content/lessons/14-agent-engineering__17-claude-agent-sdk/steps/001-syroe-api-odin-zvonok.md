title: Сырое API даёт один звонок

Представь: ты хочешь, чтобы модель нашла ошибку в твоём проекте. Пишешь напрямую в API: «найди баг в файле utils.py». Ответ приходит через секунду — «покажи мне этот файл». Ты открываешь файл, копируешь, вставляешь. Модель: «запусти тесты». Ты запускаешь, копируешь вывод, вставляешь. На шестой раз она просит соседний файл, о котором вы говорили в самом начале, — а история уже не помещается, и ты собираешь её заново вручную.

Кто здесь работает?

Сырое API — это один запрос и один ответ. Оно не умеет само открыть файл, само запустить тест, само вспомнить, что было десять шагов назад. Модель может только сказать словами, что ей нужно. Всё остальное делаешь ты: бегаешь за данными, копируешь, вставляешь, ведёшь учёт.

Вот эту работу и называют харнесс — обвязка вокруг модели. Код, который читает ответ, видит в нём просьбу «прочитай файл», сам её выполняет, кладёт результат назад в разговор и снова зовёт модель. И так по кругу, пока задача не решена. Плюс хранение сессии, чтобы завтра можно было продолжить, а не начинать с нуля.

Заметь, что происходит: ничего нового про интеллект модели тут не добавилось. Добавился цикл вокруг неё. И пока ты сам копируешь файлы в чат — ты и есть этот цикл, только написанный руками и забывающий всё при перезапуске.

> 🎒 **На пальцах.** Ты в роли курьера: бегаешь между моделью и своим компьютером с бумажками в руках. Модель просит файл — ты несёшь. Просит вывод тестов — снова несёшь. Пока курьер ты, скорость агента равна скорости твоих рук, а «память» живёт в открытых вкладках. Харнесс — это нанятый курьер, который бегает сам и ведёт журнал всех рейсов.
