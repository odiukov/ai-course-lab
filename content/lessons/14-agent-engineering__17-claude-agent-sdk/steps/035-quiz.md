  - question: >-
      Ты выбираешь между сырым API и Agent SDK для задачи «прочитай пять файлов
      и собери отчёт». Что меняется в твоём коде при переходе на SDK?
    options:
      - >-
        Модель начинает отвечать точнее, потому что SDK подмешивает свои
        подсказки
      - >-
        Цикл «модель попросила инструмент — ты выполнил — вернул результат»
        перестаёт быть твоей заботой, вместе с готовым набором инструментов
      - 'Ты всё равно пишешь цикл сам, но SDK за тебя считает токены'
      - Исчезает необходимость в системном промпте и описании инструментов
    correct: 1
    explanation: >-
      Сырое API отвечает один раз и ждёт, что бегать между моделью и файлами
      будешь ты. Агентная форма забирает этот цикл себе и приносит инструменты с
      собой.
  - question: >-
      Агент собирается запустить команду, которая удалит папку. Ты хочешь, чтобы
      этого не произошло. Что тут поможет?
    options:
      - 'Субагент: у него свой контекст, опасная команда до него не доедет'
      - 'Хук PreToolUse: он срабатывает до вызова и может запретить его'
      - 'Хук PostToolUse: посмотреть на результат и откатить'
      - 'Хранилище сессий: удалить ход из истории'
    correct: 1
    explanation: >-
      Запретить вызов можно только до того, как он произошёл, и такая точка в
      жизненном цикле одна. После вызова папки уже нет — откатывать нечего.
  - question: >-
      Главный агент отдал субагенту сорок файлов логов и получил ответ на 600
      токенов. Почему это выгодно, если сам запуск субагента стоит около 1500
      токенов накладных?
    options:
      - 'Субагент работает на другой модели, которая дешевле'
      - >-
        Сорок файлов не попадают в контекст главного агента: наверх поднимается
        только вывод, а не сырьё
      - Накладные расходы списываются один раз на всю сессию
      - 'Субагенты работают параллельно, поэтому общий счёт делится между ними'
    correct: 1
    explanation: >-
      Экономия не в цене за токен, а в том, что сырые логи читает чужой
      контекст. 1500 плюс 600 против десятков тысяч — считать имеет смысл только
      когда сырья действительно много.
  - question: >-
      Ты удаляешь сессию, у которой было три субагента со своими подключами. Что
      должно случиться правильно устроенным удалением?
    options:
      - >-
        Удалится только родительская запись, подключи останутся как отдельные
        сессии
      - >-
        Удалится родитель и все его подключи, чтобы не осталось записей без
        владельца
      - 'Удаление заблокируется, пока субагенты не будут удалены вручную'
      - Подключи перепривяжутся к предыдущей сессии в списке
    correct: 1
    explanation: >-
      Каскад именно для этого и нужен: подключ без родителя — мусор, который
      никто уже не найдёт и не удалит.

Урок закончился, и дальше по курсу тебе понадобится не список терминов, а четыре рабочих привычки: понимать, где заканчивается один звонок к API и начинается цикл; знать, что запретить действие можно только до него; отправлять субагента туда, где много сырья и мало нужного результата; и помнить, что у сессии бывают дети.

Спотыкаются обычно на одном месте — путают субагента и хук. Оба звучат как «контроль», но контролируют разное: субагент ограничивает, **сколько агент видит**, хук ограничивает, **что агент может сделать**. Первое считается в токенах, второе — в последствиях. Если на вопросе про удаление папки в голове всплывает субагент, вернись к [шагу 10](#step-10).
