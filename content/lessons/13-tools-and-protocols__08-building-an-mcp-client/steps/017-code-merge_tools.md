Три сессии живут своей жизнью: у `notes` в `session.tools` лежат `search` и `create`, у `files` — `search` и `read`, у `github` — `search` и `create_issue`. Модели нужен один список. Самое очевидное — пробежать по сессиям и слить всё в один массив.

Пробуй мысленно: что получится? Список из шести элементов, три из которых называются `search`. Модель не видит, откуда каждый пришёл ([шаг 13](#step-13)), и выбор становится лотереей. Значит склейка — это не конкатенация, а переименование.

`merge_tools` принимает словарь сессий (имя сервера → сессия из [шага 8](#step-8)) и возвращает плоский список описаний инструментов. Для каждого сервера бери уже сохранённый `session.tools` — заново ничего не спрашиваем, инструменты пришли на хендшейке. Сервер без возможности `tools` пропускай: `supports` из [шага 11](#step-11) вернёт `False`, и это нормальная ситуация, а не ошибка. Каждому инструменту собери новое имя вида `notes/search` — префикс, как в Claude Desktop и VS Code ([шаг 15](#step-15)). Описание и схему параметров переноси как есть: модель по ним решает, что вызывать.

Две вещи, на которых легко порезаться. Первая: не переписывай имя внутри `session.tools` — оригинальное `search` ещё понадобится, когда вызов пойдёт обратно на сервер. Делай копию словаря. Вторая: порядок обхода сессий фиксирован, поэтому список должен быть одинаковым при двух запусках.

Проверь себя на числах: три сервера — шесть имён, все разные; пустой словарь сессий — пустой список, без исключения.

> 🎒 **На пальцах.** Собираешь плейлист из трёх альбомов. В каждом есть трек «Intro». Свалишь всё в одну папку — три файла с одинаковой подписью, и ты не знаешь, какой ставить. Поэтому плеер показывает «Альбом — Intro»: подпись в списке новая, а сам файл на диске остался прежним «Intro». Ровно это и делает `merge_tools`: меняет вывеску для витрины, не трогая оригинал.
