check:
  - question: >-
      После первого примера AND с входом [0, 0] веса остались [0, 0], хотя
      предсказание было ошибочным. Почему веса не сдвинулись?
    options:
      - Ошибка при таком входе автоматически считается нулевой
      - >-
        Поправка каждого веса умножается на соответствующий вход, а оба входа
        равны нулю
      - 'Скорость обучения 0,1 недостаточна, чтобы изменить нулевой вес'
      - Веса обновляются только после полного прохода по всем примерам
    correct: 1
    explanation: >-
      Ошибка равна −1, но Δw_i = 0,1 × (−1) × x_i. При x_i = 0 обе поправки
      равны нулю. Смещение обновляется без множителя x_i, поэтому становится
      −0,1.
  - question: >-
      Перцептрон выдал 1 для объекта с правильной меткой 0. Как правило обучения
      изменит смещение?
    options:
      - 'Увеличит, потому что предсказание превышает правильную метку'
      - 'Уменьшит, потому что ошибка y_true − y_pred отрицательна'
      - >-
        Не изменит, поскольку смещение обновляется только при положительной
        ошибке
    correct: 1
    explanation: >-
      Ошибка равна 0 − 1 = −1. Поправка смещения равна learning rate × error,
      поэтому смещение уменьшается и перцептрону становится труднее снова выдать
      1.
---

Этот шаг нужен, чтобы правило обновления перестало быть строчками псевдокода и стало действием, которое ты можешь проделать на бумаге. Пока ты не прошёл один пример руками, дальше будет непонятно, почему сеть вообще куда-то движется.

После этого куска ты должен уметь взять любой пример, посчитать предсказание, вычесть его из верного ответа и сказать, насколько сдвинется каждый вес и смещение.

Спотыкаются обычно на двух вещах. Первая — знак ошибки: это верный ответ минус предсказание, а не наоборот, и путаница здесь разворачивает всё обучение в другую сторону. Вторая — нулевой вход: вес при нулевом входе не двигается вообще, потому что поправка на него умножается, и меняется только смещение, у которого входа нет.
