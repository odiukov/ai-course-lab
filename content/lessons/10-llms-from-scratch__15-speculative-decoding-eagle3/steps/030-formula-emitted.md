Ты знаешь α из [шага 29](#step-29) — пусть будет 0.9. Черновик пишет N = 5 токенов. Сколько в среднем выйдет за один forward verifier? Первое, что просится на язык: 5 × 0.9 = 4.5.

Число неверное, причём с обеих сторон сразу. Токены не независимы: по [шагу 20](#step-20) ты идёшь слева направо и на первом отказе останавливаешься — четвёртый токен даже не рассматривается, если второй отвергнут. И при этом один токен ты уносишь всегда: либо замену из остатка, либо бонус из [шага 21](#step-21).

Поэтому считай по позициям. Гарантированный токен — это 1. Первый черновой доживает с вероятностью α. Второй — только если принят первый, то есть α². j-й — α^j. Складываешь всё подряд:

$$E[\text{accepted}] = 1 + \alpha + \alpha^2 + \dots + \alpha^N = \frac{1 - \alpha^{N+1}}{1 - \alpha}$$

Здесь α — доля принятия одного чернового токена, N — сколько токенов написал черновик, E[accepted] — сколько токенов в среднем выходит за один проход большой модели. Правая часть — та же сумма, свёрнутая в короткую запись.

Подставь руками. При α = 0.9 и N = 5: 0.9⁶ = 0.531, значит (1 − 0.531) / 0.1 = 4.69. Больше наивных 4.5 — лишнее пришло ровно из гарантированного токена.

Теперь vanilla-черновик, α = 0.6, то же N = 5: 0.6⁶ = 0.047, (1 − 0.047) / 0.4 = 2.38.

Verifier тот же, N тот же, а токенов вдвое меньше. Всю разницу сделала α.

> 🎒 **На пальцах.** Поставь в ряд шесть костяшек домино, но кривовато: каждая роняет следующую только в девяти случаях из десяти. Первую толкаешь ты — она падает всегда. Вторая падает с шансом 0.9, шестая — только если сработали все пять до неё, то есть 0.9⁵. Сложи шансы всех шести — получишь 4.69 упавших костяшек. Ослабь толчок до 0.6 — ряд гаснет на второй-третьей, и падает 2.38.
