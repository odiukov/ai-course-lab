У тебя уже есть две половинки: `expected_emitted` из [шага 31](#step-31) считает, сколько токенов выходит за один проход verifier, а отношение стоимостей `c` из [шага 32](#step-32) говорит, во сколько обходится черновик. Возьми `α = 0.8`, `c = 0.05`, `N = 5`. Токенов на проход получается 3.69. Хорошо это или плохо?

Само по себе — непонятно. 3.69 токена за проход звучит отлично, но ты за них ещё и заплатил: пять черновых forward pass по 0.05 каждый. Сравнивать надо не урожай, а урожай на потраченное время.

Отсюда и функция этого шага. Договоримся о единице измерения: один forward verifier = 1. Тогда полная цена спекулятивного шага — это `N * c` (черновик) плюс `1` (проверка), а делённая на `E[accepted]`, она даёт время на один выданный токен:

$$\text{time\_per\_token} = \frac{N c + 1}{E[\text{accepted}]}$$

Напиши `time_per_token(alpha, N, c)`: посчитай числитель, вызови `expected_emitted`, верни частное. Кода на две строки — вся работа уже сделана раньше.

Смотреть надо вот на что. При `N = 0` черновика нет, `E = 1`, и функция обязана вернуть ровно `1.0` — это обычное декодирование, точка отсчёта. Для `α = 0.8, c = 0.05, N = 5` жди примерно `0.339`: ускорение — это `1 / 0.339 ≈ 2.95`. Для `α = 0.9, c = 0.02, N = 8` выйдет около `0.189`, то есть 5.3 раза.

Теперь у тебя одно число вместо двух, и его наконец можно с чем-то сравнивать.

> 🎒 **На пальцах.** Переезд. Фургон — одна ходка, фиксированная цена, сколько ни грузи. Но перед ней ты гоняешь легковушку по мелочи: каждая поездка дешёвая, а их пять. Спрашивать «сколько стоил фургон?» бессмысленно — считай рубли на коробку: всё, что заплатил, делённое на всё, что довёз. `N * c` — легковушка, `1` — фургон, `E[accepted]` — коробки.
