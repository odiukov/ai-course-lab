Ты запускаешь прогон для 100 целей, в среднем даёшь атаке 15 запросов на цель, а один запрос стоит \$0.01. Вручную получить \$15 нетрудно. Но затем ты меняешь набор на 800 целей — и не хочешь каждый раз пересчитывать бюджет на калькуляторе.

Напиши функцию `estimate_target_cost(num_targets, avg_queries, price_per_query)`. Она должна принять количество целей, среднее число запросов на одну цель и цену одного запроса, а вернуть ожидаемую общую стоимость. Логику расчёта мы уже разобрали в [шаге 10](#step-10): здесь твоя задача — аккуратно перенести её в код, перемножив три входных значения.

Обрати внимание на единицы. `num_targets` — это число целей, `avg_queries` может быть дробным средним, а `price_per_query` задаётся в денежных единицах за один запрос. Поэтому результат тоже может быть дробным: не округляй его внутри функции, если задание явно этого не требует. Иначе маленькая ошибка на одном прогоне превратится в заметную разницу на большом наборе.

Проверь себя на трёх случаях: обычный расчёт для 100 целей, нулевая цена запроса и дробное среднее число запросов. При нулевой цене итог должен быть нулём независимо от масштаба. Функция лишь оценивает расходы по среднему — она не предсказывает точное число запросов конкретной атаки.

> 🎒 **На пальцах.** Представь экскурсию: ты бронируешь автобусы для нескольких групп, каждая группа делает в среднем несколько поездок, а у каждой поездки есть цена. Сложить эти три числа нельзя — у них разные роли. Ты последовательно увеличиваешь стоимость сначала по числу поездок, затем по числу групп. `estimate_target_cost` делает такой же расчёт для запросов к модели.
