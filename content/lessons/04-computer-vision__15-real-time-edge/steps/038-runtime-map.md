Ты берёшь одну модель и пробуешь запустить её на трёх устройствах: Intel-мини-ПК, iPhone и Jetson. В PyTorch всё работало одинаково, но на целевом железе результат расходится: где-то не используется ускоритель, где-то растёт задержка, а где-то модель вообще нельзя запустить в прежнем виде.

Между моделью и процессором нужен рантайм — программа, которая читает вычисления модели и поручает их доступному железу. Это похоже на контроллер станка: чертёж один, но команды для разных станков отличаются.

Хорошая отправная точка — ONNX Runtime. Он не привязан к одному производителю и подключает execution provider — модуль, который направляет вычисления на CPU, CUDA, TensorRT, Core ML или OpenVINO. Поэтому сначала можно получить рабочий нейтральный вариант, а уже затем выяснять, даёт ли специализированный рантайм заметный выигрыш.

Для NVIDIA GPU и Jetson часто выбирают TensorRT; для устройств Apple — Core ML; для Android и ARM — TFLite; для Intel CPU и VPU — OpenVINO. PyTorch eager удобен во время разработки, но обычно не становится финальным вариантом для edge. TorchScript считается устаревающим путём.

Название рантайма само по себе ничего не гарантирует: окончательный выбор подтверждают замеры на целевом устройстве по правилам из [шага 7](#step-7), включая хвосты задержек из [шага 5](#step-5). Сначала совместимость с железом, затем честный benchmark.

> 🎒 **На пальцах.** Представь завод, получивший универсальный чертёж детали. ONNX Runtime — диспетчер, который умеет передать его разным цехам. Но если завод целиком построен на станках NVIDIA, специальный мастер TensorRT может выполнить заказ быстрее. Поэтому ты начинаешь с универсального диспетчера, а узкого специалиста нанимаешь только под конкретное оборудование и после пробного запуска.
