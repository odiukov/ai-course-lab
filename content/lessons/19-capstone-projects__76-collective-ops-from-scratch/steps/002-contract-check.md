check:
  - question: >-
      Почему в каждом проходе кольцевого allreduce достаточно N − 1 обменов, а
      не N?
    options:
      - >-
        Собственный кусок уже находится на ранге, а дополнительный обмен лишь
        замкнул бы полный круг
      - Последний ранг не участвует в коллективной операции
      - Два соседних обмена автоматически объединяются в один
      - Один из кусков всегда отбрасывается перед началом прохода
    correct: 0
    explanation: >-
      Каждому рангу нужно обменяться данными с остальными N − 1 участниками. При
      четырёх рангах каждый проход поэтому занимает три шага; ещё один шаг
      вернул бы кусок к исходной позиции.
  - question: >-
      После reduce-scatter один готовый кусок содержит неверную сумму. Почему
      следующий allgather не исправит ошибку?
    options:
      - >-
        Allgather только распространяет готовые куски и не выполняет
        дополнительное сложение
      - Allgather пересчитывает суммы только на ранге-источнике
      - 'Allgather работает лишь при числе рангов, равном степени двойки'
      - Очереди запрещают повторно отправлять один и тот же кусок
    correct: 0
    explanation: >-
      Во втором проходе готовые куски лишь перемещаются по кольцу и записываются
      в соответствующие позиции. Ошибка редукции поэтому будет скопирована на
      все ранги без исправления.
---

Теперь ты должен уметь проверить контракт кольца по двум контрольным точкам. После первого прохода каждый ранг отвечает ровно за один полностью просуммированный кусок; после второго у каждого собраны все готовые куски. Это и есть разложение из [шага 1](#step-1), применённое к кольцу.

Чаще всего путают промежуточный результат с окончательным или забывают, что оба прохода занимают по \(N-1\) шагов. Для четырёх рангов это три шага сложения и три шага распространения.
