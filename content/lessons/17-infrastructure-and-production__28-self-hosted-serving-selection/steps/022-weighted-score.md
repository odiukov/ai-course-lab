Ты сравниваешь два допустимых движка. Первый получил высокую оценку за масштаб, второй — за нужный тип нагрузки. Простое среднее объявит ничью, даже если для тебя нагрузка втрое важнее. Здесь и появляется `weighted_score`: функция должна превратить несколько оценок в одно число с учётом нормализованных приоритетов из [шага 17](#step-17).

Возьми для каждого критерия его оценку и соответствующий вес, затем сложи получившиеся вклады по правилу из [шага 21](#step-21). Готовую базовую оценку скорректируй множителем сопровождения из [шага 20](#step-20). Так активно развиваемый и замороженный движки не окажутся равными при одинаковой технической пригодности.

Обрати внимание на границы ответственности. `weighted_score` не должна заново проверять железо: несовместимые варианты уже отсеивает `eligible_engines` из [шага 9](#step-9). Она также не выбирает победителя и не сортирует список — это будет задачей следующего этапа. Сейчас один вызов функции оценивает ровно один движок.

Проверь себя на простых случаях: нулевой вес критерия убирает его влияние; более высокая оценка по важному критерию заметно повышает результат; множитель меньше единицы снижает итог, но не меняет исходные оценки. Не округляй число внутри функции: раннее округление способно превратить близкие результаты в искусственную ничью.

> 🎒 **На пальцах.** Представь конкурс короткометражек: жюри отдельно оценивает сюжет и звук, но заранее решило, что сюжет важнее. Сначала каждая оценка вносит вклад согласно своему весу. Затем фестиваль уменьшает итог фильма, автор которого больше не поддерживает доступную копию. Судья не решает, кого допустить, и не объявляет победителя — он лишь аккуратно заполняет одну итоговую строку.
