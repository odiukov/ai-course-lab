check:
  - question: >-
      Для одной модели полный и селективный checkpointing дают одинаковые
      значения `fwd` и `bwd`, но разные `total`. Какое слагаемое создаёт эту
      разницу?
    options:
      - >-
        `recompute`: в селективном варианте повторяется только часть вычислений
        слоя
      - '`fwd`: селективный вариант пропускает часть слоёв в прямом проходе'
      - '`bwd`: селективный вариант не вычисляет часть градиентов'
      - '`segment_size`: он непосредственно прибавляется к общей стоимости'
    correct: 0
    explanation: >-
      В обоих вариантах исходный forward стоит 32 единицы, а backward — 64.
      Различается только пересчёт: 32 при полном checkpointing и 4,8 при
      селективном.
  - question: >-
      Почему `recompute` может равняться 4,8, хотя модель состоит из целого
      числа слоёв?
    options:
      - >-
        Это нормализованная стоимость вычислений, а не количество пересчитанных
        слоёв
      - Функция предполагает существование неполного последнего слоя
      - Часть слоёв выполняет только половину обратного прохода
      - Значение получилось из-за ошибки округления индексов сегментов
    correct: 0
    explanation: >-
      Единицы модели обозначают FLOPs относительно полного forward слоя. Поэтому
      32 слоя, каждый из которых пересчитывает долю 0,15 своей работы, дают
      дробную стоимость 32 × 0,15 = 4,8.

Здесь ты должен уметь взять две функции из [шага 32](#step-32), подставить в них 32 слоя и получить числа руками — не «примерно треть», а 32, 32, 64 и 128 против 96.

Спотыкаются обычно на двух местах. Первое: делят на 128 вместо 96 и получают вместо 33 % какие-то 25 % — база для сравнения всегда шаг без чекпойнтинга. Второе: думают, что `segment_size` влияет на итог. Не влияет: пересчёт — это ровно один лишний forward целиком, разбиение меняет только пиковую память.

И проверь селективный случай: 32 × 0,15 = 4,8, итого 100,8, отсюда те самые 5 % из [шага 31](#step-31).
