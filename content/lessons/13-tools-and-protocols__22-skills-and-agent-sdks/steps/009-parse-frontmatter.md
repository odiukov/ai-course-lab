Открой любой SKILL.md из [шага 5](#step-5) и посмотри на него глазами программы: сверху четыре строки метаданных, снизу инструкция в markdown. Тебе нужна одна функция, которая разрежет эту строку пополам и вернёт два объекта: словарь `{"name": "release-notes-writer", "description": "Write a changelog entry..."}` и тело как обычный текст.

Соблазн очевидный: `text.split("---")`. Не делай так. В теле навыка почти наверняка встретится горизонтальная линия из трёх дефисов — markdown её обожает — и твой сплит развалит файл на четыре куска вместо двух. Граница из [шага 8](#step-8) работает только когда ты идёшь построчно и считаешь дефисы разделителем лишь в двух конкретных местах: самая первая строка файла и первая строка после неё, состоящая ровно из `---`.

Значит, план такой. Разбей текст на строки. Проверь, что первая непустая строка после `strip()` — это `---`. Если нет — фронтматтера тут нет вообще, возвращай пустой словарь и весь текст как тело: файл без метаданных не повод падать. Если да — иди вниз до второй строки `---` и запомни её номер. Не нашёл закрывающую? Это тоже «фронтматтера нет», а не половина словаря.

Строки между границами разбирай по **первому** двоеточию. Именно по первому: description вида `Use when: writing release notes` содержит своё двоеточие, и разбиение по всем сразу превратит значение в мусор. Ключ и значение обрежь по пробелам, пустые строки пропусти.

Тело — всё, что после закрывающей границы, склеенное обратно через `\n`. Проверь себя на файле без метаданных, на файле с `---` внутри тела и на description с двоеточием — если все три возвращают то, что ты ожидаешь, функция готова.

> 🎒 **На пальцах.** Пришла посылка: накладная в прозрачном кармане снаружи, вещи внутри. Ты отклеиваешь карман, читаешь поля — «получатель», «вес» — и отдельно достаёшь содержимое. Если кармана нет, ты не выбрасываешь коробку, а просто отдаёшь вещи без описи. И ты не рвёшь скотч везде, где он попался: только на заводском стыке сверху.
