title: 'description решает, возьмут навык или нет'

У тебя в папке три навыка: один пишет changelog, второй чистит логи, третий готовит релизный тег. Ты просишь: «собери запись в changelog по последним смерженным PR». Агент берёт тот, что про логи.

Почему? Он не открывал файлы. В момент выбора у него на руках только `name` и `description` — по строчке на навык, те самые метаданные из фронтматтера ([шаг 5](#step-5)). Тело SKILL.md он прочитает потом, уже выбрав. То есть выбор случается до чтения инструкции.

Значит `description` — не подпись для красоты. Это единственный крючок, за который навык вообще можно вытащить.

И тут меняется то, что в нём надо писать. Не «что я такое», а «когда меня брать». Сравни две строки. «Утилита для работы с текстом» — подходит ко всему и ни к чему: changelog это текст, логи это текст, тег это текст. А теперь настоящая: `Write a changelog entry for the latest merged PRs following this project's style.` Здесь есть глагол (write), объект (changelog entry), условие (latest merged PRs, style этого проекта). И главное — здесь стоят те же слова, которыми ты сам сформулировал просьбу.

Отсюда простое правило письма: закладывай в `description` формулировку задачи так, как её произнесёт человек, а не так, как ты назвал файл внутри. «Чистка логов» и «убрать шум из вывода тестов» — для тебя одно, для поиска по строчке — разные слова.

Агент не ошибся с логами. Просто твой changelog-навык нигде не сказал, что он про changelog.

> 🎒 **На пальцах.** Домашняя аптечка. На коробочках подписи не «парацетамол, 500 мг, блистер», а «от головы», «от горла», «от живота». Ты ведь ищешь по тому, что болит, а не по химии. Состав и дозировка есть — внутри, на вкладыше, и ты прочитаешь их, когда коробку уже достал. Подпись снаружи решает, достанешь ли вообще.
