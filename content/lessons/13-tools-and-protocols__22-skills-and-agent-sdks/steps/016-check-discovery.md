check:
  - question: >-
      У тебя две папки навыков: ./skills/pdf-tools/SKILL.md в репозитории и
      ~/.claude/skills/my-pdf/SKILL.md у тебя дома. В обоих фронтматтерах
      написано name: pdf-report. Что получится после обхода, если реестр — это
      словарь с полем name в качестве ключа?
    options:
      - 'Оба навыка сохранятся отдельно, потому что папки называются по-разному'
      - >-
        Под ключом pdf-report останется навык, записанный последним, а
        предыдущая запись будет заменена
      - Обход обязательно завершится ошибкой уникальности
      - Тела файлов автоматически объединятся в одну инструкцию
    correct: 1
    explanation: >-
      Обе записи используют один ключ pdf-report. Обычное присваивание в словарь
      по уже существующему ключу заменяет прежнее значение новым.
  - question: >-
      Нужно сохранить в одном реестре оба столкнувшихся навыка. Какое изменение
      устранит конфликт ключей?
    options:
      - Переименовать только каталог одного навыка
      - Изменить поле name во фронтматтере одного навыка
      - 'Перенести один файл в другую область видимости, не меняя фронтматтер'
      - Добавить различия только в description
    correct: 1
    explanation: >-
      Ключ реестра берётся из поля name, поэтому уникальными должны быть именно
      его значения. Другой каталог, путь или description не меняет ключ.
---

Здесь проверяем то, что вы разбирали в [шаге 14](#step-14) и [шаге 15](#step-15) вместе: обход трёх путей даёт плоский реестр, а ключом в нём служит поле `name`, не путь и не имя папки. Значит, два файла из разных областей видимости могут спокойно столкнуться — и без всякой ошибки один тихо вытеснит другой.

Спотыкаются обычно на двух вещах. Первая: кажется, что разные папки — уже разные навыки, ведь пути не совпадают. Вторая: кажется, что дубликат вызовет падение или предупреждение. Ни то, ни другое: перезапись выглядит просто как «навык почему-то делает не то, что я писал».
