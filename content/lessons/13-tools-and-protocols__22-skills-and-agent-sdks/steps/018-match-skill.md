Запрос пришёл такой: «собери релизные заметки за последнюю неделю». В словаре, который вернул `discover_skills` из [шага 14](#step-14), лежат три навыка: `release-notes-writer`, `pdf-form-filler`, `slack-digest`. Человеку очевидно, какой брать. Функции — нет: у неё на входе просто строка и словарь объектов `Skill` из [шага 10](#step-10).

По чему вообще сравнивать?

Тело навыка сравнивать бессмысленно — там сотни слов про шаги, теги и правила стиля, и слово «неделю» может случайно всплыть в любом из трёх. А вот `description` написан ровно для этого ([шаг 6](#step-6)): одна фраза о том, когда навык применяют. Это и есть поисковый индекс.

Значит, `match_skill(query, skills)` делает так: приводит запрос и `description` каждого навыка к нижнему регистру, режет на слова, считает, сколько слов запроса встретилось в описании, и возвращает навык с наибольшим счётом.

Три места, где обычно спотыкаются.

Первое — регистр и пунктуация. «Release Notes» и «release notes,» должны совпасть; без `.lower()` и отсечения запятых счёт будет нулевой.

Второе — порог. Если запрос «какая сегодня погода», лучший счёт может оказаться единицей за слово «какая». Возвращать навык при счёте ноль (а лучше — ниже небольшого порога) нельзя: функция должна вернуть `None`, и агент спокойно ответит без навыка.

Третье — ничья. Два навыка с одинаковым счётом? Реши заранее, кто побеждает — например, первый по алфавиту среди ключей, — иначе один и тот же запрос будет давать разный ответ от запуска к запуску.

Пиши функцию так, чтобы `None` был честным, ожидаемым ответом, а не аварией.
