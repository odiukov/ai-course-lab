Возьми поток из 9 id, контекст длины 4 и шаг 2. Из [шага 2](#step-2) ты помнишь: одному примеру нужны 5 id — четыре для входа и ещё один для сдвинутой цели. Первое окно занимает позиции 0–4, второе — 2–6, третье — 4–8. Следующее началось бы с позиции 6, но для него не хватит данных. Значит, ответ — 3.

Здесь легко перепутать две роли `stride`. Он не меняет размер окна: тот по-прежнему равен `context_length + 1`. Шаг лишь говорит, на сколько позиций сдвинуть начало следующего окна. Поэтому при большем `stride` примеров становится меньше, а не короче.

Твоя реализация `count_windows` должна сначала определить, сколько id остаётся после размещения одного полного окна. Если остаток отрицательный, даже первое окно не помещается — нужно вернуть ноль. Это важно: поток из 4 id при `context_length = 4` ещё слишком короткий, потому что требуются 5 id.

Если первое окно помещается, оно уже даёт один пример. Затем посчитай, сколько полных сдвигов `stride` укладывается в оставшуюся длину. Неполный хвост отбрасывай: округление вверх создало бы пример, для которого нет target. Именно этот граничный контракт ты проверял на [шаге 3](#step-3).

> 🎒 **На пальцах.** Представь фотоаппарат, который снимает панораму через прямоугольное окошко фиксированной ширины. Первый кадр можно сделать сразу, а затем ты каждый раз передвигаешь аппарат на одинаковое расстояние. Если справа видна лишь часть будущего кадра, снимка не получается. А если плёнка короче самого окошка, ты не сделаешь ни одного кадра.
