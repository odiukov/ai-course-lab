check:
  - question: >-
      При T = 4 окно содержит id 8, 3, 5, 2, 9. Какие input и target соблюдают
      контракт?
    options:
      - 'input: 8, 3, 5, 2; target: 3, 5, 2, 9'
      - 'input: 8, 3, 5, 2; target: 8, 3, 5, 2'
      - 'input: 8, 3, 5, 2, 9; target: 3, 5, 2, 9'
    correct: 0
    explanation: >-
      Input берёт первые четыре id, а target — последние четыре. Поэтому target
      сдвинут относительно input на одну позицию.
  - question: >-
      Два окна длиной 5 сырых id начинаются с позиций 0 и 2. Сколько id у них
      общие?
    options:
      - Два
      - Три
      - Четыре
      - Ни одного
    correct: 1
    explanation: >-
      Второе окно сдвинуто на две позиции, поэтому из пяти id первого окна в нём
      остаются последние три.

Перед реализацией проверь, что можешь мысленно разрезать любое окно на две согласованные последовательности. Из [шага 2](#step-2) тебе понадобится контракт: окно содержит на один id больше, чем input и target по отдельности. Частая ошибка — убрать последний id, а затем получить target без ответа для последней позиции.

Ещё одна точка проверки — шаг окна. Он не меняет размер одного примера, а только расстояние между началами соседних окон и, следовательно, их перекрытие. Если обе проверки сходятся на конкретных числах, контракт готов к реализации.
