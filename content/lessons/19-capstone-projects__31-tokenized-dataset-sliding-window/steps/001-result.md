title: Собираем поток батчей для next-token обучения

Представь: корпус уже превращён в несколько гигабайт token id, а модель просит очередную порцию данных фиксированной формы — например, 8 примеров по 256 позиций. Загружать весь корпус в память ради одной такой порции расточительно. Заранее сохранять тысячи готовых батчей тоже неудобно: изменишь размер батча — придётся собирать их заново.

Поэтому данные лучше устроить как поток по требованию. Длинная последовательность id остаётся источником. Dataset играет роль каталога: по номеру он находит нужное окно и возвращает один обучающий пример — пару входа и цели длины $T$, где $T$ означает число позиций в примере. Затем DataLoader берёт $B$ таких примеров и складывает их по строкам. Так появляются два тензора формы $(B, T)$: один подаётся модели, второй используется для проверки её предсказаний.

Важно, что «поток» не означает бесконтрольную случайность. DataLoader может перемешивать номера примеров, но генератор случайных чисел получает известный seed — начальное число, похожее на заранее заданную стартовую точку маршрута. При одинаковом seed порядок батчей повторится. Ты сможешь поменять модель или параметры обучения и сравнить результаты на той же последовательности данных.

Получается аккуратная граница ответственности: Dataset знает, как получить один пример, DataLoader — как собрать и упорядочить много примеров, а цикл обучения просто просит следующий батч.

> 🎒 **На пальцах.** Представь конвейер с карточками. Работник у конвейера вырезает по номеру одну карточку нужного размера — это Dataset. Другой работник собирает несколько карточек в лоток и решает, в каком порядке подавать лотки, — это DataLoader. Модель видит только готовые лотки и не обязана знать, насколько длинным был исходный рулон.
