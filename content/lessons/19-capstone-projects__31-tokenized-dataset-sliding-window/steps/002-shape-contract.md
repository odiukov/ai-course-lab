Возьми пять соседних id из потока: 41, 9, 73, 6, 12. Допустим, длина контекста \(T\) равна 4. Модель получает первые четыре id — 41, 9, 73, 6 — и на каждой позиции пытается предсказать следующий. Значит, правильные ответы для неё — 9, 73, 6, 12.

Посмотри на две последовательности: обе имеют длину 4, но цель сдвинута относительно входа на одну позицию. Id 9, 73 и 6 встречаются в обеих: во входе они дают контекст для дальнейшего предсказания, а в цели показывают правильный ответ для предыдущей позиции.

Что сломается, если вырезать только четыре сырых id? Вход можно заполнить полностью, но для последнего id правильного следующего ответа внутри окна уже нет. Придётся либо укоротить цель до трёх позиций — и тогда формы не состыкуются, — либо взять ещё один id. Поэтому пример с input и target длины \(T\) рождается из окна длины \(T+1\).

Именно такие примеры затем складываются в поток батчей из [шага 1](#step-1). Здесь важен простой контроль: после сдвига обе части сохраняют длину \(T\), а у каждой входной позиции остаётся настоящий следующий id.

> 🎒 **На пальцах.** Представь ряд из пяти костяшек домино. Тебе нужно составить четыре пары соседей: первая со второй, вторая с третьей, третья с четвёртой и четвёртая с пятой. Четырёх костяшек хватило бы только на три пары. Пятая не добавляет новую позицию во вход — она даёт правильное продолжение последней позиции.
