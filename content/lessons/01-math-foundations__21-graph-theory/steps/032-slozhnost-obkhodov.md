title: Почему BFS и DFS работают за O(V + E)
source_anchor: '### Step 2: BFS and DFS'
---

Представь граф из миллиона узлов, где у каждого примерно десять связей. Внутри обхода есть цикл по соседям, поэтому легко испугаться: не придётся ли проверять все связи заново для каждого узла?

Нет. В BFS из [шага 19](#step-19) и DFS из [шага 25](#step-25) список соседей открывается только тогда, когда алгоритм обрабатывает конкретный узел. Каждый узел становится посещённым один раз — на это уходит работа порядка $V$, где $V$ — количество узлов.

Теперь посчитаем проверки соседей. Алгоритм не перебирает все рёбра для каждого узла, а просматривает только рёбра из его списка смежности. В ориентированном графе каждое ребро встретится один раз. В неориентированном — дважды, по одному разу с каждого конца. Но удвоение не меняет порядок роста: работа с рёбрами остаётся порядка $E$, где $E$ — их количество.

Поэтому общая сложность — $O(V + E)$. Очередь BFS и стек DFS меняют порядок выбора следующего узла, но не количество просмотренных узлов и связей.

Это рассуждение предполагает список смежности из [шага 14](#step-14). С матрицей пришлось бы проверять целую строку для каждого узла, даже если связей мало, и время выросло бы до $O(V^2)$.

> 🎒 **На пальцах.** Представь обход квартир с журналом жильцов. В каждую квартиру ты заходишь один раз, а внутри проверяешь только записанные для неё переходы в соседние квартиры. Ты не перечитываешь весь журнал у каждой двери. Квартиры дают вклад $V$, переходы — $E$; очередь или стопка записок решает лишь, куда ты пойдёшь следующим.
