Ты проектируешь карту для приключенческой игры. Между башней и садом есть тропа, а из пещеры в замок — портал, который работает только в одну сторону. Сначала тебе достаточно показать, куда вообще можно попасть. Но затем появляется запас энергии: тропа отнимает 3 единицы, портал — 8.

Какой граф выбрать? Одного ответа «со стрелками» или «с числами» уже мало: это два независимых решения. Направление из [шага 3](#step-3) отвечает на вопрос «можно ли пройти обратно?», а вес из [шага 4](#step-4) — «нужно ли хранить числовое значение связи?».

Поэтому получаются четыре сочетания:

| Направление | Вес | Что хранит модель |
|---|---|---|
| Нет | Нет | Связь существует в обе стороны |
| Есть | Нет | Связь существует только в указанную сторону |
| Нет | Есть | Взаимная связь и её числовое значение |
| Есть | Есть | Направленная связь и её числовое значение |

Попробуй мысленно отключить числа на игровой карте. Портал не перестанет быть односторонним: граф станет ориентированным невзвешенным. Теперь верни расход энергии и замени портал обычным двусторонним тоннелем: получится неориентированный взвешенный граф.

Важно: «невзвешенный» не означает, что все переходы в реальности одинаковы. Это означает лишь, что модель не хранит их различия в виде чисел. Два переключателя дают четыре разных способа описать одну и ту же карту.

> 🎒 **На пальцах.** Представь панель настроек игры с двумя переключателями: «учитывать направление» и «учитывать расход энергии». Каждый можно включить независимо. Выключены оба — остаются только проходы. Включено направление — появляются односторонние порталы. Включён вес — видна цена перехода. Включены оба — ты одновременно знаешь, куда можно двигаться и сколько это стоит.
