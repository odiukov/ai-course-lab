У тебя есть ряд из четырёх значений: 4, 8, 6, 10. При окне 3 функция должна вернуть 4, 6, 6, 8. Первые два результата легко вызывают сомнение: трёх наблюдений там ещё нет — что усреднять?

Используй только доступную часть ряда. Для первого результата это одно значение: 4. Для второго — два: 4 и 8. Начиная с третьего, в расчёт входят последние три значения. Такое поведение совпадает со скользящим средним из [шага 8](#step-8) и сохраняет длину исходного ряда.

Напиши функцию `rolling_mean`, которая принимает:

- `series` — одномерный массив чисел;
- `window` — максимальное количество последних наблюдений для среднего.

Функция должна вернуть NumPy-массив той же длины. Для каждой позиции возьми текущий элемент и предыдущие элементы, но не больше размера окна. Левая граница среза не должна становиться отрицательной, иначе Python начнёт отсчёт с конца массива и первые результаты окажутся неверными.

Особенно внимательно проверь правую границу: в срезах Python она не включается. Если хочешь учесть текущий элемент, правую границу нужно поставить сразу после него. Это типичная ошибка на единицу.

Проверь себя на трёх случаях: окно 1 возвращает исходные значения, окно 3 даёт для примера выше 4, 6, 6, 8, а окно больше длины ряда постепенно накапливает все доступные наблюдения. Если эти случаи сходятся, границы окна выбраны правильно.

> 🎒 **На пальцах.** Представь табло кофейни, которое показывает среднее время ожидания последних трёх заказов. После первого заказа табло использует один результат, после второго — два, а затем всегда берёт не больше трёх последних. Оно не подглядывает в будущие заказы и не достаёт значения с конца журнала: на каждом шаге считает только по уже записанным данным.
