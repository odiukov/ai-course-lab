Ты сравниваешь две модели на пяти временных отрезках. Для каждой приходится вручную выбирать прошлое для обучения, следующий участок для проверки, сохранять оценку — и не перепутать границы. Сам принцип уже знаком по walk-forward из [шага 31](#step-31), но служебного кода становится слишком много.

`TimeSeriesSplit` встраивает такое разбиение в привычные инструменты scikit-learn:

```python
from sklearn.model_selection import TimeSeriesSplit

tscv = TimeSeriesSplit(n_splits=5)

for train_index, test_index in tscv.split(X):
    X_train, X_test = X[train_index], X[test_index]
    y_train, y_test = y[train_index], y[test_index]
```

На каждом проходе `train_index` указывает на более ранние строки, а `test_index` — на следующий за ними отрезок. По умолчанию обучающая часть расширяется: новый проход сохраняет прежнюю историю и добавляет более свежие наблюдения. `n_splits=5` означает, что модель получит пять последовательных проверок, а не одно случайное разбиение.

Есть важная деталь: `TimeSeriesSplit` ориентируется на порядок строк и сам не восстанавливает хронологию. Поэтому перед разбиением данные должны быть отсортированы по времени.

Готовый объект можно передать в `cross_val_score`:

```python
scores = cross_val_score(model, X, y, cv=tscv)
```

Scikit-learn сам пять раз обучит модель и вернёт пять оценок. Значит, временная честность из walk-forward сохраняется, а модель можно проверять тем же интерфейсом, что и другие модели scikit-learn.

> 🎒 **На пальцах.** Представь гастрольный тур с пятью контрольными концертами. Перед каждым концертом музыканты репетируют на всём накопленном опыте, но не используют отзывы из будущих городов. `TimeSeriesSplit` заранее составляет такой маршрут, а `cross_val_score` проводит все пять проверок и складывает оценки в один список. Главное — города уже должны стоять в календарном порядке.
