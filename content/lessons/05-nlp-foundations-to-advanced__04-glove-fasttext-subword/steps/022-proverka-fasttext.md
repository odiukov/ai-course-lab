check:
  - question: >-
      Функция получает слово `кот` и длины кусочков от 3 до 4. Какие кандидаты
      она создаст из строки `<кот>`?
    options:
      - >-
        Триграммы `<ко`, `кот`, `от>`; четырёхграммы `<кот`, `кот>`; отдельную
        запись `<кот>`
      - 'Только `кот`, `<кот` и `кот>`, без отдельной записи `<кот>`'
      - 'Триграммы `<ко`, `кот`, `от>` и отдельную запись `кот` без границ'
    correct: 0
    explanation: >-
      Окна проходят по обёрнутой строке `<кот>` сначала с длиной 3, затем с
      длиной 4. Помимо этих окон функция добавляет отдельный кандидат для полной
      обёрнутой формы `<кот>`.
  - question: >-
      Для незнакомого слова создано десять кандидатов, но в таблице n-грамм есть
      векторы только для трёх из них. Из чего функция fasttext_vector соберёт
      результат?
    options:
      - 'Из векторов всех десяти кандидатов, считая отсутствующие нулевыми'
      - Из суммы векторов трёх найденных кусочков
      - Только из вектора отдельной записи целого слова
    correct: 1
    explanation: >-
      После генерации кандидатов функция оставляет только ключи, присутствующие
      в таблице, и складывает их векторы. Собственной записи незнакомого слова
      для этого не требуется.
---

Здесь важно не смешать два действия из [шага 17](#step-17) и [шага 20](#step-20). Сначала ты оборачиваешь слово границами и выписываешь все допустимые символьные окна, включая отдельную запись целого слова. Затем сверяешь кандидатов с таблицей и складываешь только найденные в ней векторы.

Чаще всего теряются кусочки с `<` и `>` или ошибочно считается, что незнакомое слово обязано иметь собственную запись. Нет: ему достаточно хотя бы одного знакомого фрагмента. Если не найден ни один, функция уже не сможет собрать вектор.
