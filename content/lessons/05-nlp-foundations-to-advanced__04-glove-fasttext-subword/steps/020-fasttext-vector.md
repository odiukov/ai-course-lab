Ты передаёшь функции незнакомое слово `whereupon`, а в таблице есть векторы лишь для нескольких его кусочков. Если обратиться ко всем n-граммам напрямую, первая отсутствующая запись вызовет ошибку. Но отбрасывать всё слово тоже нельзя: знакомых частей уже достаточно, чтобы собрать представление.

Напиши `fasttext_vector(word, ngram_table)`. Сначала получи набор частей с помощью `char_ngrams` из [шага 17](#step-17). Затем перебери их и возьми только те векторы, для которых соответствующий ключ действительно присутствует в `ngram_table`. Не забывай: отдельная запись целого слова вроде `<where>` из [шага 18](#step-18) обрабатывается наравне с остальными n-граммами.

После фильтрации возможны два случая. Если найден хотя бы один вектор, сложи все найденные векторы через `np.sum` по нулевой оси. Например, из трёх векторов длины 4 должна получиться одна сумма длины 4, а не одно число.

Если список пуст, верни `None`. Нулевой вектор здесь был бы обманчивым результатом: он выглядел бы как настоящее представление слова, хотя функция не нашла ни одного знакомого кусочка.

Проверь обе ветки отдельно: слово с несколькими известными n-граммами должно вернуть их покомпонентную сумму, а слово без единого совпадения — `None`. Порядок обхода множества не важен, потому что от перестановки слагаемых сумма не меняется.

> 🎒 **На пальцах.** Представь мастерскую витражей. Для слова ты приносишь список цветных фрагментов, но часть форм ещё не изготовлена. Мастер берёт со склада только найденные стёкла и накладывает их друг на друга — цвета складываются в один рисунок. Если склад не дал ни одного фрагмента, мастер возвращает не прозрачное стекло, а честный ответ: собрать витраж пока не из чего.
