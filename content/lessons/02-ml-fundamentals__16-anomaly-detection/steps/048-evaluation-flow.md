Перед тобой 50 000 операций, и у каждой есть оценка аномальности. Даже самая высокая оценка ещё не означает «нарушение»: модель лишь сообщает, что операция сильнее других не похожа на норму. Если объявить аномалиями всё подозрительное, проверяющие утонут в очереди.

Поэтому оценки сначала превращают в рейтинг: наверху оказываются самые необычные наблюдения. Затем ты выбираешь не отвлечённый порог, а объём реальной проверки. Допустим, команда успевает разобрать 100 операций в день — значит, ей передают первые 100 строк рейтинга.

Теперь результат можно связать с практикой. После проверки этих строк человеком становится видно, сколько настоящих аномалий попало в доступный дневной объём. Для этого подходит Precision@k из [шага 47](#step-47). AUPRC из того же шага помогает сравнить качество ранжирования шире, а не только в одной выбранной точке.

Важно сохранить сами оценки и порядок объектов. Если завтра команда сможет проверить уже 200 операций, модель не придётся обучать заново: граница просто сдвинется ниже по готовому рейтингу. Так числовая оценка превращается не в автоматический приговор, а в управляемую очередь для проверки.

> 🎒 **На пальцах.** Представь редактора, которому за день прислали тысячу фотографий, а внимательно проверить он успеет только двадцать. Помощник сортирует снимки по степени подозрительности и кладёт наверх двадцать самых странных. Он не решает, где подделка, — он помогает редактору потратить ограниченное время там, где шанс найти её выше.
