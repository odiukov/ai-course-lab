Ты подаёшь функции сразу несколько наборов логитов. Например, две строки: `[2, 1, 0]` и `[1001, 1000, 999]`. Если применить экспоненту напрямую, вторая строка может превратиться в переполнение, хотя относительные различия в обеих строках одинаковы.

Твоя задача — написать функцию softmax для батча: она принимает массив логитов и возвращает массив вероятностей той же формы. Как обсуждалось на [шаге 32](#step-32), каждый набор логитов должен стать отдельным распределением.

Для каждой строки нужно выполнить три действия:

1. Вычесть максимальный логит этой же строки.
2. Применить экспоненту к полученным значениям.
3. Разделить каждое значение на сумму экспонент в этой же строке.

В NumPy обрати внимание на `axis=-1`: вычисления должны идти по последней оси, где находятся варианты токенов. Параметр `keepdims=True` сохранит размерность максимума и суммы, чтобы NumPy мог корректно применить их ко всей строке.

Проверь функцию на нескольких свойствах. Форма результата не меняется, все вероятности лежат между 0 и 1, а сумма каждой строки близка к 1. Для логитов `[0, 0]` должны получиться равные вероятности. Строки `[2, 1, 0]` и `[1001, 1000, 999]` тоже должны дать одинаковые распределения: прибавление одной константы ко всем логитам не меняет их относительных шансов.

Главная ловушка — посчитать один максимум или одну сумму на весь батч. Тогда независимые примеры начнут влиять друг на друга.

> 🎒 **На пальцах.** Представь несколько слушателей, каждый из которых распределяет один голос между тремя песнями. Баллы одного слушателя можно превратить в доли его голоса, но нельзя складывать их с баллами остальных. У каждой строки свой «самый высокий балл» и своя сумма долей. Поэтому после softmax каждая строка отдельно даёт ровно один голос.
