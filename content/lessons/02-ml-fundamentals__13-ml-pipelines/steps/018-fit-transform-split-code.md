У тебя есть 1000 строк: первые 800 пойдут в обучение, последние 200 — в тест. Хочется сразу передать всю таблицу в `fit_pipeline`, а разделить уже готовый результат. Но тогда параметры шагов будут рассчитаны и по тестовым строкам — именно эту утечку мы разбирали в [шаге 17](#step-17).

Напиши `fit_transform_split`, которая соединит правильную последовательность действий. Сначала функция должна разделить исходные данные на `train` и `test`. Затем — обучить пайплайн только на `train` с помощью функции из [шага 12](#step-12). Наконец, к `test` нужно применить уже сохранённое состояние через функцию из [шага 14](#step-14).

Обрати внимание на два разных результата обработки:

- для `train` нужен преобразованный набор, полученный во время обучения пайплайна;
- для `test` нужен результат обычного применения обученного пайплайна;
- вместе с ними функция должна вернуть сохранённые параметры шагов — они понадобятся для новых данных.

Главная ловушка здесь не в синтаксисе, а в порядке вызовов. Если хоть один шаг обучается до разделения или повторно обучается на `test`, функция допускает подглядывание. Проверь мысленно каждый вызов: какие строки сейчас доступны операции, вычисляющей параметры?

Тестовая часть может проходить через обученные преобразования, но не может менять их.

Сначала ты убираешь проверочные ключи в закрытый ящик, затем настраиваешь станок и только после этого пропускаешь через него содержимое ящика. Если положить все 1000 ключей на верстак сразу, проверка уже повлияет на настройку.
