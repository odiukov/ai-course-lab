title: Fit шага вычисляет параметры только по обучающим данным

Ты разделил таблицу на обучающую и тестовую, но перед моделью нужно заполнить пропуски. Кажется удобным сначала найти медианы по всей таблице, а уже потом обработать обе части. Однако тогда необычные значения из теста сдвинут медианы — и тест снова повлияет на обучение. Это та самая утечка из [шага 3](#step-3), только спрятанная внутри предобработки.

Поэтому у шага есть отдельное действие `fit` — настройка по примерам. Как при калибровке весов: ты определяешь поправку по контрольным гирям, а не по посылке, вес которой ещё только предстоит проверить.

Для нашего шага `fit` получает **только обучающую таблицу**, вычисляет для каждого столбца медиану с помощью функции из [шага 5](#step-5) и сохраняет результат внутри шага. Эти медианы — его обучаемое состояние, о котором шла речь в [шаге 4](#step-4). Саму таблицу `fit` при этом не обязан изменять: его задача сейчас не заполнить пропуски, а запомнить параметры.

Допустим, в обучающем столбце значения `20, 30, 40`, а в тесте встретилось `1000`. Параметр должен остаться равным `30`. Если учесть тест, получится уже другая настройка, а проверка перестанет быть честной.

Граница простая: сначала отделяешь тест, затем всё, что «учится» на данных — даже медиана, — вычисляешь без него.

> 🎒 **На пальцах.** Представь весы в пункте выдачи. Сотрудник калибрует их по гирям известной массы и фиксирует поправку. Посылку клиента он в калибровку не включает: иначе вес проверяемой посылки сам повлияет на настройку прибора. Обучающие данные — это гири, тестовые — запечатанная посылка.
