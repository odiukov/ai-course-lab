Допустим, в данных сначала заполняются пропуски, а затем значения масштабируются. Параметры второго шага нельзя вычислить по исходным строкам: он должен получить уже заполненные данные. Иначе список шагов есть, но настоящей цепочки, описанной в [шаге 11](#step-11), не получается.

Твоя задача — написать `fit_pipeline`. Функция принимает обучающие строки и описания шагов, а возвращает список их обученных версий с сохранёнными параметрами.

Заведи текущую версию данных и отдельный пустой список для результата. Затем для каждого шага выполни две разные операции:

1. Обучи шаг на текущих данных с помощью `fit_step` из [шага 7](#step-7).
2. Примени именно обученную версию через `apply_step` из [шага 9](#step-9), чтобы следующий шаг получил преобразованные строки.

После этого сохрани обученный шаг в результирующий список. Следи за порядком: сначала обучение, потом применение, затем переход дальше. Исходные строки лучше не изменять — работай с копией, чтобы вызов функции не оставлял неожиданных следов снаружи.

Главная проверка: параметры каждого следующего шага должны зависеть от результата предыдущих шагов, но только в пределах обучающих данных. Возвращать нужно сами обученные шаги, а не последнюю версию строк.

> 🎒 **На пальцах.** Представь мастерскую реставрации книги. Первая станция очищает страницы и передаёт их переплётчику; тот подбирает переплёт уже под очищенный блок, а не под книгу в первоначальном состоянии. `fit_pipeline` так же проводит данные через мастерские по очереди и сохраняет настройки каждого мастера, чтобы вся последовательность осталась воспроизводимой.
