Ты обучил модель на масштабированных признаках, а через неделю подаёшь ей новые данные напрямую. Код выполняется, предсказания появляются — но числа подготовлены не так, как при обучении. Теперь тебе приходится помнить правильный порядок вызовов и каждый раз вручную его повторять.

`sklearn` предлагает собрать всю цепочку в один объект `Pipeline`:

```python
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

pipe = Pipeline([
    ("scaler", StandardScaler()),
    ("model", LogisticRegression()),
])
```

Список читается сверху вниз. Последним ставят модель, а перед ней — преобразования данных. Имена `"scaler"` и `"model"` позволяют позже получить конкретный шаг, например `pipe.named_steps["scaler"]`.

Снаружи цепочка выглядит как одна обычная модель:

```python
pipe.fit(X_train, y_train)
predictions = pipe.predict(X_test)
score = pipe.score(X_test, y_test)
```

Но внутри каждый общий вызов запускает подходящий маршрут. При `fit` масштабировщик вычисляет параметры на `X_train` и сразу преобразует эти данные, после чего модель обучается на результате. При `predict` масштабировщик только применяет сохранённые параметры к `X_test`, а модель строит предсказания. Это те же два режима из [шага 15](#step-15), только порядок действий теперь поддерживает сам `Pipeline`.

Тебе больше не нужно помнить отдельную последовательность команд: единый интерфейс не даёт случайно пропустить подготовку данных или заново обучить её при предсказании.

> 🎒 **На пальцах.** Представь автомойку с одной кнопкой «Старт». Машина сначала проходит мойку, затем сушку — тебе не приходится отдельно включать каждый аппарат и помнить порядок. Для новой машины используются уже настроенные режимы, а не проводится новая настройка оборудования. `Pipeline` так же скрывает несколько согласованных действий за одним вызовом.
