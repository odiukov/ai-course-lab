На входе у тебя батч зашумлённых изображений: одно могло прийти с шага 40, другое — с шага 700. Сеть уже оценила шум для каждого изображения, но просто вычесть это предсказание нельзя: на разных шагах шум и исходный сигнал смешаны в разных пропорциях.

Напиши `predict_x0(x_t, eps_pred, t, alphas_cumprod)`. Она должна применить преобразование из [шага 21](#step-21) и вернуть оценку чистого изображения той же формы, что и `x_t`.

Обрати внимание на четыре детали:

- `x_t` и `eps_pred` имеют одинаковую форму `[B, C, H, W]`;
- `t` имеет форму `[B]`: у каждого изображения свой номер шага;
- из `alphas_cumprod` нужно выбрать по одному значению для каждого элемента батча;
- выбранные коэффициенты нужно превратить в форму `[B, 1, 1, 1]`, чтобы broadcasting из [шага 18](#step-18) применил отдельное число ко всем каналам и пикселям соответствующего изображения.

Не вычисляй накопленные alpha заново внутри функции: готовая таблица уже передана аргументом. Все операции должны оставаться тензорными — так функция сохранит устройство (`CPU` или `GPU`) и сможет обработать весь батч сразу.

Для самопроверки возьми `x_t`, настоящий шум и тот же `t`, которые использовались при вызове `q_sample` из [шага 15](#step-15). Если передать настоящий шум вместо предсказания сети, результат должен почти совпасть с исходным `x_0`; небольшая разница возможна только из-за точности вычислений.

> 🎒 **На пальцах.** Представь несколько стаканов с концентратом и водой: первый разбавили слегка, второй — почти до прозрачности. Тебе сообщили, сколько воды попало в каждый стакан. Чтобы восстановить концентрат, мало просто вылить указанную воду — для каждого стакана нужно учесть собственную степень разбавления. `t` выбирает нужную отметку для каждого стакана, а broadcasting распространяет её на всё его содержимое.
