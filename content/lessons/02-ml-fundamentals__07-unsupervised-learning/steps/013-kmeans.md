У тебя уже есть три рабочие детали: измерение расстояния из [шага 7](#step-7), назначение точек из [шага 9](#step-9) и пересчёт центроидов из [шага 11](#step-11). Но если вызвать каждую функцию только один раз, получится лишь один проход. Нужна функция, которая будет снова и снова соединять эти действия в цикл из [шага 12](#step-12).

Создай `kmeans(data, k, max_iterations=100, seed=42)`. Она получает набор точек `data`, желаемое число кластеров `k` и предельное число проходов. Вернуть нужно две вещи: номер кластера для каждой исходной точки и итоговые координаты центроидов.

Внутри функции собери такой порядок действий:

1. Подготовь `k` начальных центроидов.
2. Перед каждым проходом создай пустые кластеры.
3. Для каждой точки найди ближайший центроид и запомни его номер.
4. Разложи точки по соответствующим кластерам.
5. Пересчитай центроиды по собранным точкам.
6. Повторяй цикл, пока центры продолжают заметно меняться, но не дольше `max_iterations`.

Особенно следи за `assignments`: номера должны записываться в том же порядке, в котором точки лежат в `data`. Иначе результат нельзя будет сопоставить с исходными объектами. Не смешивай также старые и новые центроиды внутри одного прохода: сначала назначь все точки по текущим центрам и только потом пересчитывай центры.

Так три отдельные функции превращаются в один работающий K-Means: назначение меняет группы, а новые группы меняют центроиды.

> 🎒 **На пальцах.** Представь репетицию оркестра: скрипачи, духовые и ударники уже умеют играть свои партии, но музыка не появится, если каждый сыграет один раз когда захочет. Дирижёр задаёт порядок: сыграли вместе, услышали расхождения, поправились и повторили. `kmeans` играет роль такого дирижёра — не выполняет отдельную партию, а согласованно запускает уже готовые действия.
