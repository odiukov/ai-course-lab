Ты сравниваешь две выдачи по запросу «ноутбук не включается». В первой на верхней позиции — общая статья о неполадках, а точная инструкция по твоей модели стоит четвёртой. Во второй сначала идёт бесполезная страница, зато точная инструкция стоит второй. Какая выдача лучше?

Как мы различили в [шаге 34](#step-34), MRR смотрит только на позицию **первого релевантного результата**. Если общую статью считать релевантной, первая система получит за запрос 1: подходящий материал уже наверху. Вторая получит 1/2. Всё, что расположено после первого успеха, на MRR этого запроса уже не влияет. Если релевантного результата нет, вклад запроса равен нулю; затем значения усредняются по запросам.

Но здесь теряется важное различие: общая статья лишь немного помогает, а инструкция для конкретной модели почти наверняка решает проблему. nDCG@k позволяет назначить результатам степени релевантности — например, 0 для бесполезного, 1 для общего, 2 для полезного и 3 для точного ответа. Высокая оценка приносит больший выигрыш, а низкая позиция уменьшает его. Затем результат сравнивается с идеальным порядком, где самые ценные документы стоят первыми.

Поэтому MRR отвечает: «Как быстро встретился первый приемлемый ответ?», а nDCG: «Насколько хорошо по верхним позициям разложены ответы разного качества?»

> 🎒 **На пальцах.** Представь стойку первой помощи с пронумерованными ящиками. MRR радуется, как только ты рано открыл первый ящик, где вообще есть подходящий пластырь. nDCG различает содержимое: набор для нужной травмы ценнее случайного пластыря, особенно если лежит ближе. Первый оценивает скорость первого успеха, второй — качество всей верхней части раскладки.
