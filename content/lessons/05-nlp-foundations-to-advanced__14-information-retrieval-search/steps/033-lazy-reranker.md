title: Ленивая загрузка reranker защищает импорт модуля от тяжёлой инициализации

---

Ты запускаешь быстрый тест для `tokenize`, но вместо результата видишь загрузку модели и ждёшь, пока она займёт память. Хотя reranker тесту вообще не нужен. Причина спрятана в такой записи: `reranker=CrossEncoder(...)`.

При импорте Python выполняет верхний уровень модуля и один раз вычисляет значения аргументов по умолчанию. Значит, `CrossEncoder(...)` создастся не при поиске, а уже при импорте файла. Сборщик тестов, служебный скрипт или ноутбук могут случайно запустить тяжёлую инициализацию, просто попросив одну маленькую функцию.

Ленивая загрузка откладывает эту работу до первого реального обращения. Сначала `_RERANKER` хранит `None` — отметку «модель ещё не создана». `get_reranker()` проверяет её: при первом вызове создаёт cross-encoder из [шага 31](#step-31), сохраняет его в глобальной переменной и возвращает. При следующих вызовах возвращается тот же экземпляр, поэтому модель не загружается заново для каждого запроса.

В `hybrid_search` значение `reranker=None` безопасно: `None` создаётся без затрат, а модель запрашивается уже внутри функции. Если reranker передан явно, `get_reranker()` вообще не вызывается. Это особенно удобно в тестах: можно подставить лёгкую замену без скачивания настоящей модели.

Импорт теперь лишь знакомит Python с функциями; тяжёлая машина включается только тогда, когда ей действительно дают кандидатов.

> 🎒 **На пальцах.** Представь небольшой кинотеатр. Утром кассир открывает двери, но не включает мощный проектор: возможно, ты пришёл только узнать расписание. Проектор запускают перед первым сеансом, а затем оставляют готовым для следующих показов. `None` — табличка «ещё не включён», `get_reranker()` — киномеханик, который запускает аппарат один раз и потом использует уже работающий.
