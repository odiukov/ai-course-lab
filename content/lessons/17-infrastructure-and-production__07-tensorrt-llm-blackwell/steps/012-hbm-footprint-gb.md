У тебя уже есть две функции: `weights_gb` из [шага 6](#step-6) и `kv_cache_gb` из [шага 9](#step-9). Если в основном скрипте каждый раз вызывать их отдельно, а затем вручную прибавлять служебный запас, легко перепутать аргументы или забыть один компонент. Поэтому теперь собери этот расчёт в `hbm_footprint_gb`.

Посмотри на сигнатуру функции в заготовке. Она должна:

1. получить объём весов через `weights_gb`;
2. получить объём KV-кэша через `kv_cache_gb`;
3. прибавить служебный резерв;
4. вернуть общий занятый объём HBM в гигабайтах.

Само сложение описано в [шаге 11](#step-11), поэтому заново выводить его не нужно. Здесь важнее правильно состыковать уже написанные части: передать каждой функции её аргументы и сложить результаты в одинаковых единицах.

Не округляй промежуточные значения внутри функции. Например, потерянные при раннем округлении `0.4 GB` могут исказить последующие сравнения. Округление понадобится только при выводе числа человеку.

После реализации проверь три ситуации: нулевой резерв, увеличение только контекста и увеличение только числа параметров. В первом случае исчезает лишь служебная часть; в остальных меняется ровно тот компонент, от которого зависит изменённый параметр. Если функция ведёт себя иначе, сначала проверь порядок аргументов при вызове помощников.

> 🎒 **На пальцах.** Представь кассира, который закрывает смену по трём чекам: оборудование, расходники и непредвиденные траты. `hbm_footprint_gb` не пересчитывает каждую покупку вручную — для первых двух чеков уже есть отдельные калькуляторы. Его работа проще: запросить их итоги, добавить резерв и вернуть одну честную сумму без преждевременного округления.
