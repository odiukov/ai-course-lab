check:
  - question: >-
      Что определяет объём, который остаётся на каждой из восьми A100 после
      полного шардирования состояния обучения 70B-модели?
    options:
      - >-
        Полное состояние обучения, делённое на число GPU в группе шардирования —
        карта не умеет уменьшить свой шард под собственный лимит
      - >-
        Минимум из размера полного состояния и памяти карты — лишнее
        автоматически вытесняется
      - >-
        Только шард весов: состояние оптимизатора при шардировании всегда уходит
        в память хоста
    correct: 0
    explanation: >-
      FSDP режет все три статьи (веса, градиенты, состояния Adam) на число GPU:
      840 ГБ / 8 = 105 ГБ на карту. Никакого автоматического вытеснения нет —
      если шард больше 80 ГБ, запуск падает по памяти. Нужны либо 16 карт
      (840/16 = 52,5 ГБ), либо activation checkpointing.
  - question: Почему суммарные 640 ГБ памяти восьми A100 не решают задачу?
    options:
      - FSDP может использовать память только одной GPU
      - Каждая GPU обязана хранить полные 840 ГБ
      - Шард каждой GPU превышает её собственный лимит памяти
    correct: 2
    explanation: >-
      Кластер не образует единый накопитель: важен итог на одну карту. Шард в
      105 ГБ не размещается в 80 ГБ конкретной A100, сколько бы карт ни стояло
      рядом.
---

Здесь тебе нужно связать расчёт из [шага 44](#step-44) с ограничением отдельной карты. Частая ошибка — увидеть суммарные 640 ГБ и решить, что этого почти достаточно. Но GPU не образуют единый безразмерный накопитель: каждая получает свой шард, и 105 ГБ нельзя разместить в её 80 ГБ.

> 🎒 **На пальцах.** Представь 840 литров краски и восемь бочек по 80 литров. Равное распределение даст по 105 литров на бочку. Неважно, что бочек много: каждая переполнится на 25 литров. FSDP уменьшил порцию, но восьми ёмкостей всё ещё мало.
