Перед тобой ряд порогов от `0.05` до `0.95`. Для каждого модель выдаёт новые метки, а вместе с ними меняется выбранная метрика. Вручную сравнивать 91 результат неудобно — поручим это функции `best_threshold`.

Функция получает правильные ответы `y_true`, вероятности `y_probs` и название метрики: `f1`, `recall` или `precision`. Она должна перебрать пороги с шагом `0.01` и для каждого выполнить три действия:

1. Превратить вероятности в классы: значение не ниже порога становится `1`, остальные — `0`.
2. Посчитать `TP`, `FP` и `FN`, как в функции из [шага 6](#step-6).
3. Вычислить выбранную метрику, опираясь на логику из [шага 9](#step-9).

Понадобятся две переменные памяти: лучший найденный порог и его оценка. Начальную оценку удобно поставить равной `-1.0`: реальные значения наших метрик не бывают отрицательными, поэтому первый же результат станет текущим победителем.

Обрати внимание на пустые знаменатели. Если модель не предсказала ни одного положительного случая, precision должен стать `0.0`, а не вызвать ошибку деления. Такая же защита нужна для recall и F1.

Обновляй победителя только при строго большей оценке. Тогда при равенстве останется первый встретившийся порог. В конце верни пару: лучший порог и достигнутое значение метрики.

> 🎒 **На пальцах.** Представь настройку фоторедактора: ты последовательно ставишь яркость на 5, 6, 7 и так далее, после каждого значения смотришь оценку снимка и записываешь рекорд. Сам снимок хранить не требуется — достаточно помнить номер настройки и лучшую оценку. `best_threshold` делает тот же перебор, только вместо яркости меняет границу между классами.
