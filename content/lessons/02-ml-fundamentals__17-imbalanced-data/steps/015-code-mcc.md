Ты проверяешь функцию на трёх наборах предсказаний. Идеальные ответы должны дать `1.0`, полностью противоположные — `-1.0`, а постоянный ответ вроде «везде ноль» не должен приводить к делению на ноль.

```python
y_true = np.array([0, 0, 1, 1])

matthews_corrcoef(y_true, np.array([0, 0, 1, 1]))  # 1.0
matthews_corrcoef(y_true, np.array([1, 1, 0, 0]))  # -1.0
matthews_corrcoef(y_true, np.array([0, 0, 0, 0]))  # 0.0
```

Напиши функцию `matthews_corrcoef(y_true, y_pred)`. Сначала получи `tp`, `tn`, `fp` и `fn` с помощью `confusion_counts` из [шага 6](#step-6). Затем отдельно вычисли числитель и знаменатель по формуле из [шага 14](#step-14). Для квадратного корня используй `np.sqrt`, а произведение перед ним преобразуй в `float`.

Особенно внимательно обработай нулевой знаменатель. Такое случается, например, когда модель предсказывает только один класс: один из четырёх множителей становится нулём. Делить в этом случае нельзя, поэтому функция должна вернуть `0.0`. Это договорённость для вырожденной ситуации, а не результат обычного вычисления MCC.

В конце верни отношение числителя к знаменателю, только если знаменатель больше нуля. Три проверки выше сразу покажут, сохранила ли функция смысл знака и не падает ли на постоянных предсказаниях.

> 🎒 **На пальцах.** Представь измерительный стол на четырёх опорах. Пока все опоры на месте, ты можешь сравнить, перевешивают ли согласованные ответы ошибки. Если модель вообще не использует один из классов, одна опора исчезает: измерение становится неустойчивым. Вместо деления на ноль ты спокойно записываешь `0.0` — надёжного свидетельства связи нет.
