title: 'Проверка: F1, AUPRC или MCC для разных целей оценки'
source_anchor: '### Better Metrics'
check:
  - question: >-
      Ты сравниваешь модели до выбора рабочего порога и хочешь понять, насколько
      хорошо они поднимают редкие случаи вверх списка. Что выбрать?
    options:
      - F1 при произвольном фиксированном пороге
      - AUPRC по множеству порогов
      - MCC при стандартном пороге
    correct: 1
    explanation: >-
      AUPRC оценивает качество ранжирования по множеству порогов, поэтому
      подходит для сравнения моделей до выбора рабочего порога.
  - question: >-
      Порог уже выбран. Заказчику важно, чтобы модель правильно работала и с
      редким, и с частым классом. Какая метрика точнее соответствует этой цели?
    options:
      - Только recall
      - F1
      - MCC
    correct: 2
    explanation: >-
      MCC использует все четыре элемента confusion matrix и получает высокий
      результат только при хорошем качестве на обоих классах.
---

Перед тобой три отчёта с разными «лучшими» моделями. Ошибка — выбрать метрику лишь потому, что данные несбалансированы. Сначала уточни цель оценки.

Если решения уже получены при одном пороге и нужен компромисс precision и recall, смотри F1 из [шага 8](#step-8). Если порог ещё предстоит выбрать и сравнивается качество ранжирования, подходит AUPRC из [шага 12](#step-12). Если при фиксированных решениях важна работа на обоих классах, выбирай MCC из [шага 14](#step-14).

Метрика отвечает не на вопрос «какая модель лучше вообще», а на твой конкретный вопрос к модели.
