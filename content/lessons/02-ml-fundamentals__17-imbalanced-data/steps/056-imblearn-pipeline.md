title: Imbalanced-learn Pipeline удерживает SMOTE внутри каждого обучения
source_anchor: '## Use It'
---

Ты запускаешь кросс-валидацию на пяти частях данных и хочешь проверить модель с SMOTE. Кажется естественным сначала создать синтетические точки, а затем разделить получившийся набор на пять частей. Но тогда SMOTE уже видел все исходные примеры — в том числе те, которые позже окажутся в проверочной части. Оценка становится слишком оптимистичной: это та же утечка, от которой мы защищались в [шаге 45](#step-45), только внутри кросс-валидации.

`Pipeline` из `imbalanced-learn` связывает SMOTE и модель в одну обучаемую конструкцию:

```python
pipeline = Pipeline([
    ("smote", SMOTE(random_state=42)),
    ("model", LogisticRegression()),
])
```

Когда очередная часть становится валидационной, `pipeline.fit()` передаёт SMOTE только остальные четыре части. На них создаются синтетические точки, и уже по расширенным данным обучается модель. Для следующего разбиения всё повторяется заново: новый обучающий набор — новый запуск SMOTE.

При `predict()` преобразование не применяется. Валидационные и тестовые строки остаются настоящими: пайплайн сразу передаёт их обученной модели. Это важное отличие от обычных преобразований признаков — SMOTE нужен лишь во время обучения.

Такой пайплайн удобно передавать целиком в кросс-валидацию или подбор параметров. Тогда каждое обучение автоматически соблюдает честную границу из [шага 46](#step-46): синтетические данные рождаются только по эту сторону проверки.

> 🎒 **На пальцах.** Представь пять вариантов контрольной. Перед каждой попыткой репетитор составляет дополнительные тренировочные задачи только по четырём закрытым вариантам, которые ты сейчас изучаешь. Пятый остаётся запечатанным и проверяет тебя как есть. `Pipeline` играет роль строгого организатора: при каждой перестановке он заново отделяет тренировочные материалы от контрольных.
