Перед тобой две последовательности: правильные ответы `y_true` и предсказания модели `y_pred`. Например:

- `y_true`: 1, 0, 1, 0, 1, 0
- `y_pred`: 1, 1, 0, 0, 1, 0

Нужно написать `confusion_counts`, которая сравнит элементы на одинаковых позициях и вернёт четыре числа в порядке `(tp, tn, fp, fn)`. Смысл этих четырёх случаев мы разобрали на [шаге 5](#step-5); здесь задача — научить программу их считать.

Не перебирай элементы вручную. Для каждого случая создай логическое условие сразу для двух массивов. Например, один случай требует, чтобы предсказание было равно `1` **и одновременно** правильный ответ был равен `1`. Результатом станет маска из значений `True` и `False`.

Затем `np.sum` посчитает значения `True`, как единицы. Так маска превратится в количество подходящих наблюдений.

Обрати внимание на две частые ошибки. Каждое сравнение заключай в скобки, а условия объединяй оператором `&`. Обычное Python-слово `and` не умеет поэлементно соединять NumPy-массивы. Кроме того, не перепутай порядок возвращаемых значений: проверка ожидает сначала `tp`, затем `tn`, `fp` и `fn`.

Для примера выше функция должна получить `2, 2, 1, 1`. Их сумма равна шести — числу всех наблюдений. Это простая проверка: если сумма четырёх счётчиков не совпала с длиной массивов, какой-то случай потерян или посчитан дважды.

> 🎒 **На пальцах.** Представь стол с шестью конвертами. На каждом лежат две карточки: правильная метка и ответ модели. Ты четыре раза проходишь вдоль стола, каждый раз отбирая только одну комбинацию карточек. Логическая маска отмечает подходящие конверты, а `np.sum` считает отметки. В конце каждый конверт должен попасть ровно в одну стопку.
