Ты открываешь доску из десяти задач: глазами приходится искать, сколько осталось `todo`, что уже выполняется и где работа остановилась. В [шаге 22](#step-22) мы определили, какой короткий обзор снимает эту нагрузку. Теперь собери его в функции `board_summary`.

Функция получает доску и проходит по списку задач. Для каждого из четырёх допустимых статусов — `todo`, `in_progress`, `done`, `blocked` — она считает количество задач. В результате должны присутствовать все четыре статуса, даже если у одного из них ноль задач. Так форма сводки остаётся предсказуемой: вызывающему коду не придётся угадывать, означает ли отсутствующий ключ ноль или ошибку.

Кроме чисел, сохрани предусмотренные заготовкой сведения о задачах, требующих внимания. Бери их непосредственно из карточек доски: не вычисляй владельца по статусу и не пересказывай критерии приёмки своими словами.

Обрати внимание на границу ответственности: `board_summary` только читает данные. Она не выбирает следующую задачу, не меняет статус и не исправляет доску. После вызова исходный объект должен остаться прежним, а повторный вызов с той же доской — дать тот же результат. Если встретился неизвестный статус, не маскируй его под один из четырёх разрешённых.

Сначала создай счётчики с нулями, затем обработай задачи и собери результат в формате, заданном в упражнении. Так сводка будет одинаково понятна и на пустой доске, и посреди работы.

> 🎒 **На пальцах.** Представь табло в диспетчерской курьерской службы. Оно показывает: три заказа ждут, два в пути, пять доставлены, один задержан. Табло не назначает курьеров и не передвигает посылки — оно лишь точно отражает журнал. Если обновить его дважды без новых записей, цифры не должны измениться.
