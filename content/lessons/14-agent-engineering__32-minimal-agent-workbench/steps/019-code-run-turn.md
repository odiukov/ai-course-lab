Ты запускаешь программу и видишь странность: нужный файл изменился, но `agent_state.json` остался прежним. При следующем запуске агент повторит тот же ход, будто первого не было. Если же записать состояние заранее, журнал сообщит об окончании работы, которая могла даже не начаться.

Собери функцию `run_turn`, которая связывает уже написанные части в строгом порядке. Сначала она читает `agent_state.json`. Если активной задачи нет, использует `pull_task` из [шага 16](#step-16): тот согласованно обновит доску и состояние. Если задача уже активна, брать новую нельзя — ход должен продолжить сохранённую работу.

Затем функция находит разрешённый задачей файл и делает одно небольшое изменение только в нём. Здесь важно проверить границу до записи: путь изменяемого файла должен входить в список файлов задачи. Один ход не означает «закончить всё» — он означает выполнить ровно один наблюдаемый шаг.

Лишь после изменения файла обнови состояние: запиши, что сделано, какие файлы затронуты и какое действие должно быть следующим. Сохрани `agent_state.json` последним. После запуска посмотри на diff: в нём не должно быть посторонних файлов, а новое состояние должно правдиво описывать уже произошедшее изменение.

`run_turn` не придумывает новый процесс. Он скрепляет цикл из [шага 18](#step-18), сохраняя главное правило: журнал не опережает работу и не отстаёт от неё.

> 🎒 **На пальцах.** Представь один ход в настольной игре. Ты сначала смотришь, чья очередь и где стоит фишка, затем передвигаешь только одну разрешённую фишку и лишь после этого отмечаешь новый ход в блокноте. Если поставить отметку раньше, запись может соврать; если забыть её, следующий игрок повторит уже сделанный ход.
