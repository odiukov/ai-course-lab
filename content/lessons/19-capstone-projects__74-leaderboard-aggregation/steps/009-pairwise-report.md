У тебя есть результаты трёх моделей: A решала задачи 1 и 2, B — 2 и 3, C — только 4. Если просто взять все их баллы, сравнение получится нечестным: A и B окажутся рядом благодаря разным наборам задач, а для C вообще не найдётся общего основания.

В `pairwise_diffs` сначала собери модели в стабильном порядке и перебери каждую неупорядоченную пару ровно один раз: A–B нужна, B–A уже нет. Для выбранной пары пройди по задачам и добавляй баллы только тогда, когда задача есть у обеих моделей. Причём добавляй оба балла одновременно: элементы с одинаковым индексом должны относиться к одной задаче. Именно такое выравнивание требуется позадачному бутстрапу из [шага 5](#step-5).

Если общих задач нет, не создавай запись с нулями: такая пара ничего не сообщает и должна быть пропущена. Для непустой пары вызови готовый помощник, сохрани среднюю разность и обе границы интервала. Начальное значение генератора можно детерминированно менять от пары, чтобы повторный запуск оставался воспроизводимым.

Особенно внимательно вычисляй `significant`. По правилу из [шага 8](#step-8) значение истинно лишь для интервала, целиком лежащего справа или слева от нуля. Границы `[0,00; 0,08]` касаются нуля, поэтому значимости нет. Строгое неравенство здесь принципиально.

> 🎒 **На пальцах.** Представь таблицы результатов школьных олимпиад. Сашу и Машу можно сравнить только по предметам, которые сдавали оба: математику кладёшь напротив математики, а не напротив Машиной физики. Если общих предметов нет, строку сравнения не заполняешь. А если диапазон возможного отрыва хотя бы касается ничьей, медаль победителя пока не выдаёшь.
