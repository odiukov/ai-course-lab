Посмотри на дерево спанов из [шага 8](#step-8) глазами человека, которому надо ответить на простой вопрос: сколько раз за сутки мы сходили в модель и сколько из этого пришлось на Anthropic?

Имена спанов не помогут. Один разработчик назвал спан `chat gpt-4o`, второй — `llm-call`, третий — `call_model_v2`, а четвёртый вообще `step-3`. Всё это валидные имена, спаны отлично рисуются деревом, а вот посчитать по ним ничего нельзя: чтобы отфильтровать «только обращения к модели», пришлось бы угадывать подстроки в чужих названиях.

Отсюда и берутся два обязательных атрибута.

`gen_ai.operation.name` отвечает на вопрос «что это вообще было»: `chat`, `text_completion`, `embeddings`, `execute_tool`, `invoke_agent`. `gen_ai.provider.name` отвечает «к чьему API мы ходили»: `openai`, `anthropic`, `google`, `azure_openai`. Ключевое здесь не сами слова, а то, что список закрытый. Не `Anthropic`, не `claude`, не `anthropic-api` — ровно `anthropic`, строчными. Ты не придумываешь значение, ты выбираешь из словаря.

И тогда запрос «`gen_ai.operation.name = chat` и `gen_ai.provider.name = anthropic`» соберёт все нужные спаны из всех сервисов — включая написанные людьми, которых ты никогда не видел.

Имя спана — для человека, который смотрит на дерево. Эти два атрибута — для машины, которая по дереву считает.

> 🎒 **На пальцах.** На посылке два поля: вид отправления и служба доставки. Отправитель может подписать коробку как угодно — «маме», «хрупкое», «не кантовать». Сортировочный центр эти надписи не читает: он смотрит только на два штампа и раскидывает по лентам. Свободная подпись — чтобы курьер понял, штампы — чтобы конвейер не встал. Ровно так же живут имя спана и `operation.name` с `provider.name`.
