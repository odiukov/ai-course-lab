Запусти мысленный тест: у корзины вместимостью 5 токенов сейчас осталось 2. За секунду возвращается 1 токен, а с прошлого обращения прошло 4 секунды. Получится 6, но хранить можно только 5. После разрешённого запроса останется 4.

Теперь реализуй `token_bucket`. Функция должна получить текущее состояние корзины, её вместимость, скорость пополнения и текущее время. Сначала вычисли, сколько токенов накопилось с момента предыдущей проверки, затем ограничь результат вместимостью. Только после этого решай, пропускать ли запрос.

Если доступен хотя бы один токен, запрос разрешён, а запас уменьшается на единицу. Если токенов меньше одного, запрос отклонён — списывать ничего нельзя. Вместе с решением верни обновлённое состояние, чтобы следующий вызов продолжил расчёт с правильного места.

Проверь три момента:

- запас никогда не становится больше вместимости;
- отклонённый запрос не уводит запас в минус;
- время последней проверки обновляется даже при отказе, иначе один и тот же прошедший интервал можно случайно учесть повторно.

Для измерения интервалов лучше монотонное время: оно движется только вперёд и не ломает расчёт, если системные часы перевели. Дробные токены сохраняй. Например, `0.7` ещё не разрешает запрос, но после небольшого ожидания может превратиться в `1.0`.

Смысл проверки из [шага 18](#step-18) теперь превращается в порядок действий: сначала пополнение, затем ограничение вместимостью, потом решение и возможное списание.

> 🎒 **На пальцах.** Представь склад с пятью многоразовыми пропусками. Курьеры постепенно возвращают их на стойку, но больше пяти там всё равно не поместится. При входе курьер забирает один пропуск. Если стойка пуста, он ждёт и ничего не забирает «в долг». `token_bucket` делает ровно этот пересчёт при каждом обращении.
