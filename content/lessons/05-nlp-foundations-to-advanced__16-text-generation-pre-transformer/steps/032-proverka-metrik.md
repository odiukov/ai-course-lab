      - '3'

    explanation: >-
      Perplexity равна двум в степени bits per token, поэтому для 3 битов
      получится 8 эффективных вариантов.
  - question: >-
      Триграммную модель обучили с n равным 3, но при оценке указали n равным 2.

    options:
      - 'Ничего: n влияет только на скорость вычисления'
      - Тест подаёт модели контексты другой длины и использует другой паддинг
      - Perplexity автоматически преобразуется из битов в наты
      - Модель начинает учитывать на одно слово больше
    correct: 1
    explanation: >-
      Порядок n задаёт ширину контекста и число начальных токенов. На обучении и
      проверке они должны совпадать.

Ты видишь две оценки одной модели: 3 bits per token и perplexity 8. Это не два независимых результата, а две шкалы одной средней неожиданности, связанные правилом из [шага 28](#step-28). Поэтому меньшее значение каждой метрики означает более уверенное предсказание.

Но корректное вычисление ещё не гарантирует корректное сравнение. Проверь, что параметр `n` совпадает с порядком модели: иначе изменятся паддинг и ширина передаваемого контекста. А сравнивать perplexity имеет смысл лишь при одинаковых тестовых токенах, как разобрано в [шаге 31](#step-31).

> 🎒 **На пальцах.** Представь веломастерскую: биение колеса можно показать миллиметрами или цветной шкалой — показания разные, неисправность одна. Но если закрепить колесо не в тот стенд, аккуратная цифра уже ничего не говорит. Bits per token и perplexity — две шкалы, а `n` — подходящий размер крепления.
