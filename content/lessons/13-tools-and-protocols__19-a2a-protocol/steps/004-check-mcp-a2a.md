      агент-аналитик: сам решает, какие данные ему нужны, ходит за ними и пишет

    options:
      - И то и другое через A2A — оба ведь внешние
      - >-
        Сервис погоды через MCP как инструмент, агента-аналитика через A2A как

      - И то и другое через MCP — оба ведь просто отдают результат

    explanation: >-
      Погода — предсказуемый вызов с известным ответом, это инструмент, то есть

      второй агент, то есть A2A.
  - question: >-
      Почему собственный REST API между агентом поддержки и агентом-писателем
      плохо масштабируется?
    options:
      - REST слишком медленный для передачи текста отчёта
      - REST не умеет передавать состояние задачи
      - >-
        Каждая новая пара агентов требует ещё одной разовой интеграции, и их

    explanation: >-
      Одна пара — одна договорённость. Пять агентов, каждый зовёт каждого, —
      двадцать интеграций вместо пяти карточек, как в [шаге 3](#step-3).
---

Прежде чем идти дальше, проверь одну вещь: умеешь ли ты сам, глядя на чужой сервис, сказать — это инструмент или это агент. Инструмент делает ровно то, что ты попросил, и ты заранее знаешь форму ответа; такому нужен MCP. Агент сам выбирает шаги, и его внутренние рассуждения остаются для тебя закрытыми — видны только состояния задачи и результат; такому нужен A2A.

Спотыкаются обычно на двух местах. Первое: «A2A вместо MCP» — нет, они про разные вещи и живут рядом. Второе: считают признаком агента сложность кода. Признак другой — кто решает, что делать дальше.
