Вернись к карточке из [шага 7](#step-7) и к неприятности из [шага 11](#step-11): имя `payments-agent` в карточке напишет кто угодно. Значит, рядом с содержимым нужен короткий контрольный код — отпечаток, посчитанный по тексту карточки. Пришла карточка — пересчитал отпечаток сам, сравнил с приложенным. Не сошлось — карточку по дороге правили.

Идея простая, а на практике она сразу ломается.

Смотри. Один сервер отдал `{"name":"writer-agent","version":"1.0"}`. Другой — `{"version":"1.0","name":"writer-agent"}`. Для Python это один и тот же словарь: те же два ключа, те же два значения. А отпечаток считается не по смыслу, а по байтам — и байты тут разные. Отпечатки разойдутся. Добавь ещё `indent=2` для красоты — появятся переносы строк и пробелы, и это уже третьи байты той же карточки.

Получается, проверка падает на честной карточке. Просто потому, что её пересобрала другая библиотека.

Отсюда и берётся каноническая форма: договориться, что у карточки есть ровно один разрешённый способ превратиться в байты. Ключи — строго по алфавиту, на всех уровнях вложенности. Никаких пробелов после запятых и двоеточий, никаких отступов и переносов. Отпечаток считается не по тому, что прилетело по сети, а по этой единственной записи — с обеих сторон.

Одна карточка — одни байты. Тогда несовпадение отпечатка означает подмену содержимого, а не другой порядок ключей.

> 🎒 **На пальцах.** Ты записал один и тот же телефон трижя: `+7 495 123-45-67`, `8(495)1234567`, `84951234567`. Глазами — один номер. А программа сравнивает строки посимвольно и видит три разных. Поэтому перед сравнением номер приводят к одному виду: только цифры, без скобок, дефисов и пробелов. Каноническая форма JSON — тот же приём, только вместо цифр — отсортированные ключи без лишних пробелов.
