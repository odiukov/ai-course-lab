Перед тобой два потока по три токена: первый содержит `4, 7, 2`, второй — `9, 1, 5`. Если просто поставить их рядом, модель увидит токены одного временного кадра одновременно. Но в [шаге 25](#step-25) потоки специально сдвигались, чтобы авторегрессионный предсказатель мог выдавать их параллельно.

Допиши `delay_streams`: функция принимает набор потоков и значение служебного токена `pad_id`, а возвращает новую таблицу. Поток с индексом `0` остаётся на месте, поток `1` сдвигается вправо на одну позицию, поток `2` — на две и так далее. Освободившиеся ячейки заполняются `pad_id`.

Для примера выше результат должен выглядеть так:

```text
4,      7, 2,      pad
pad,    9, 1,      5
```

При `K` потоках длина каждой строки увеличится на `K - 1` позиций. Создай результат нужного размера, сначала целиком заполни его `pad_id`, а затем для каждого потока найди срез, начинающийся с номера этого потока, и перенеси туда исходные токены.

Не используй циклический сдвиг: он перенесёт последние токены в начало строки, хотя там должны находиться служебные позиции. Проверь функцию на двух и трёх потоках, включая один поток без сдвига. Исходная таблица при этом не должна измениться.

> 🎒 **На пальцах.** Представь несколько курьеров у длинной линии ячеек хранения. Первый начинает раскладывать посылки с первой ячейки, второй — со второй, третий — с третьей. Пустые места до их старта отмечены табличками `pad`. Никто не переносит последние посылки обратно в начало: линия просто становится длиннее, чтобы все последовательности сохранились целиком.
