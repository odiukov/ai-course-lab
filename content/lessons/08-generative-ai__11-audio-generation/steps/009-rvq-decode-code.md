Представь, что `rvq_decode` вернул латент правильной формы, но звук потерял детали. Частая причина — функция записывала новый вектор поверх предыдущего. В RVQ каждый индекс выбирает не замену, а очередное слагаемое: эту идею ты разобрал на [шаге 8](#step-8).

В заготовке функции `indices` содержит таблицу формы `(T, K)`: для каждого из `T` временных шагов указано по одному индексу из каждого из `K` кодбуков. Массив `codebooks` имеет форму `(K, M, D)`, где `M` — число векторов в кодбуке, а `D` — размер латента. Результат должен иметь форму `(T, D)`.

Создай накопитель из нулей нужной формы. Затем перебери кодбуки. На итерации `k` возьми столбец индексов `indices[:, k]` и выбери из `codebooks[k]` соответствующий вектор отдельно для каждого временного шага. Такая выборка должна дать массив формы `(T, D)`. Прибавь его к накопителю — именно прибавь, не присвой вместо прежнего значения.

Здесь не нужно снова считать остаток или искать ближайший вектор: это была работа `rvq_encode` из [шага 7](#step-7). Декодирование уже получило готовые адреса и только собирает по ним латент. Проверь мысленно формы после каждой выборки: если исчезла временная ось или появился лишний размер, сложение собирает не те элементы.

> 🎒 **На пальцах.** Представь звукорежиссёра с несколькими дорожками одной песни: на первой бас, на второй ударные, на третьей голос. Индексы говорят, какой фрагмент включить на каждой дорожке в каждый момент. `rvq_decode` не выбирает одну главную дорожку и не стирает предыдущую — он складывает все выбранные партии, получая общий микс.
