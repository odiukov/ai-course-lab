Ты запускаешь функцию для десятисекундного фрагмента и получаешь `750`. Число похоже на правду: столько временных кадров создал кодек. Но генератору предстоит предсказать не кадры, а индексы всех кодбуков, поэтому результат оказался меньше нужного.

Допиши `codec_token_count(duration_s, frame_rate_hz, num_codebooks)`. Она должна принять длительность звука в секундах, количество кадров кодека в секунду и число кодбуков, а затем вернуть общее количество токенов. Правило для расчёта уже разобрано в [шаге 4](#step-4) — здесь тебе нужно аккуратно перенести его в код.

```python
def codec_token_count(duration_s, frame_rate_hz, num_codebooks):
    # Посчитай и верни общее количество codec-токенов
    pass
```

Сначала проверь, что в вычислении участвуют все три аргумента. Частая ошибка — учесть длительность и частоту кадров, но забыть, что каждый кадр даёт отдельный индекс из каждого кодбука. Функция должна именно **возвращать** число через `return`, а не печатать его: возвращённый результат можно передать следующей части программы.

После реализации вызови функцию с параметрами примера из [шага 4](#step-4). Совпадение результата покажет, что ты считаешь токены, а не только временные кадры.

> 🎒 **На пальцах.** Представь гардероб театра: за один вечер приходит несколько групп, и каждому человеку выдают несколько номерков — по одному для пальто, сумки и зонта. Если посчитать только группы и людей, часть номерков потеряется. `codec_token_count` делает полную инвентаризацию: учитывает длительность приёма, темп прихода и число номерков на каждого.
