Ты подаёшь в `rvq_encode` один латентный вектор и несколько кодбуков. Кажется заманчивым просто найти ближайший вектор в каждом кодбуке. Но тогда все слои будут описывать один и тот же исходный латент, хотя в RVQ каждый следующий слой должен исправлять остаток предыдущего — именно это было разобрано в [шаге 6](#step-6).

Функция должна хранить текущий остаток. Для очередного кодбука сравни его со всеми векторами-кандидатами, выбери ближайший по квадрату евклидова расстояния и запиши не сам вектор, а его целочисленный индекс. Затем вычти выбранный вектор из остатка и переходи к следующему кодбуку.

Обрати внимание на три детали:

- расстояние считается по координатам вектора, поэтому результатом сравнения должно быть одно число на каждого кандидата;
- из остатка вычитается вектор кодбука, а не найденный индекс;
- возвращаемый список сохраняет порядок кодбуков: первый индекс относится к первому кодбуку, второй — ко второму.

Проверь себя на маленьких данных, где ближайший кандидат можно определить глазами. После первого выбора посчитай новый остаток вручную и убедись, что второй индекс выбран уже для него. Если второй слой всё ещё сравнивается с исходным латентом, функция превратилась в несколько независимых квантователей и перестала быть residual.

> 🎒 **На пальцах.** Представь реставратора, который подбирает цвет для потёртой стены. Сначала он берёт из первой палитры самый похожий базовый оттенок. Затем смотрит не на исходный цвет заново, а на оставшееся различие — например, стене всё ещё не хватает немного синего. Вторая палитра исправляет именно эту разницу. `rvq_encode` записывает номера выбранных красок по порядку.
