Ты открываешь репозиторий через сорок дней и находишь сохранённую задачу: «исправить оплату перед релизом». Файл корректный, схема проходит проверку — но релиз давно состоялся. После [шага 18](#step-18) ясно, почему такую память нельзя молча принимать за текущую.

Твоя `forget_stale` должна загрузить состояние через `load_state` из [шага 15](#step-15), взять время последнего обновления и сравнить его с контрольным временем. Не прячь текущее время внутри функции: передавай `now` аргументом вместе с допустимым возрастом записи. Тогда в тесте можно зафиксировать, например, полдень 20 августа и проверить границу без случайных падений из-за тикающих часов.

Смотри на три ветки:

- запись моложе предела — ничего не меняется;
- запись старше предела — память очищается до валидного пустого состояния;
- возраст ровно на границе — поведение должно однозначно следовать условию из контракта.

Метки времени сначала разбери как даты с часовым поясом. Сравнение строк здесь ненадёжно: две разные записи могут обозначать один момент, а локальное время без пояса вообще оставляет вопрос, какой это час.

Если состояние пришлось очистить, сохраняй результат через `atomic_write` из [шага 11](#step-11). Для свежей записи не переписывай файл без причины. Повторный вызов после очистки тоже не должен создавать ошибку или новое изменение: забывать уже забытое нечего.

> 🎒 **На пальцах.** Представь доску объявлений в подъезде. Объявление «воду отключат завтра» полезно вечером перед ремонтом, но через месяц только путает жильцов. Ты сверяешь дату с сегодняшним днём: свежее оставляешь на месте, просроченное снимаешь. Если лист уже снят, второй обход ничего не меняет.
