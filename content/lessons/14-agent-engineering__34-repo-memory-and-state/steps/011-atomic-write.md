После [шага 10](#step-10) у тебя есть порядок действий, но теперь его нужно превратить в одну функцию `atomic_write`. Представь, что она получает путь к целевому JSON-файлу и уже подготовленное содержимое. Её обещание вызывающему коду простое: запись либо завершится целиком, либо функция сообщит об ошибке — частично записанный JSON не должен стать новым состоянием.

Сначала создай временный файл в той же папке, где лежит целевой. Это важно: `os.replace` надёжно выполняет подмену, когда оба файла находятся в одной файловой системе. Имя временного файла должно быть уникальным, иначе два запуска могут случайно использовать один черновик.

Дальше запиши всё содержимое во временный файл. Проверь, что текст сохраняется в ожидаемой кодировке, а JSON не превращает русские буквы в нечитаемую россыпь escape-последовательностей. Затем вызови `flush`, чтобы передать данные из буфера Python операционной системе, и `os.fsync`, чтобы потребовать их сохранения на диске. Закрой файл и только после этого выполни `os.replace`: незаконченный черновик не должен попасть на место рабочего состояния.

Особое внимание удели ошибкам. Если запись, синхронизация или подмена сорвались, временный файл нужно аккуратно удалить. При этом нельзя замаскировать первоначальную ошибку новой ошибкой очистки. Удобная проверка результата — вызвать функцию, снова прочитать целевой файл и пропустить его через `validate` из [шага 7](#step-7).

У `atomic_write` нет промежуточного «почти готово»: сначала полноценный черновик, затем подмена.

> 🎒 **На пальцах.** Представь табло с меню у входа в кафе. Ты не исправляешь цены прямо перед посетителями, оставляя половину строк стёртыми. Сначала полностью готовишь новую карточку за стойкой, проверяешь каждую строку и лишь затем одним движением ставишь её вместо старой. Если маркер высох, старая карточка остаётся на месте, а не превращается в недописанное меню.
