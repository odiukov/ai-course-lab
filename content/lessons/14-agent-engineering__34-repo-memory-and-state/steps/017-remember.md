Ты заканчиваешь работу над задачей T-12 и вызываешь `remember`: нужно сохранить выбранный следующий шаг, но не потерять остальные поля состояния. Простое присваивание в словарь здесь обманчиво — оно меняет данные только в памяти процесса. Закроешь программу, и изменения исчезнут.

Собери `remember` как короткую цепочку уже написанных операций. Сначала загрузи текущее состояние через `load_state` из [шага 15](#step-15). Затем измени только поле, указанное вызовом функции: соседние записи должны остаться нетронутыми. Применяй правило отбора из [шага 16](#step-16): в файл попадает лишь то, что пригодится следующей сессии.

Перед сохранением передай получившийся объект валидатору из [шага 7](#step-7). Это важная граница: `remember` не должен превращать корректный файл в состояние, которое потом невозможно загрузить. Если проверка не прошла, функция сообщает об ошибке и оставляет прежний файл как есть.

Последний шаг — запись через `atomic_write` из [шага 11](#step-11), а не обычный `open(..., "w")`. Проверь функцию двумя вызовами: после первого перезагрузи файл, после второго убедись, что новое значение появилось, а первое не пропало. Настоящее «запомнил» означает не изменение переменной, а успешное чтение того же состояния новым процессом.

> 🎒 **На пальцах.** Представь журнал дежурного врача. Ты не вырываешь страницу ради одной новой записи: сначала читаешь текущую, аккуратно добавляешь назначение и проверяешь, что указаны пациент, препарат и дозировка. Только после этого новая страница заменяет прежнюю. Если запись оформлена неверно, старый журнал остаётся доступным следующей смене.
