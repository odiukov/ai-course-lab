Ты открываешь `agent_state.json` и видишь обычный словарь. Но в поле `status` записано `"workingg"`. JSON разобрался без ошибки — кавычки и скобки на месте, — однако использовать такое состояние нельзя. Если `load_state` просто вернёт результат чтения, ошибка незаметно попадёт во всю программу.

Дополни `load_state`, соблюдая порядок из [шага 14](#step-14). Сначала функция должна открыть файл в кодировке UTF-8 и разобрать JSON. Затем передай полученное значение и нужную схему функции `validate`, написанной в [шаге 7](#step-7). Возвращай данные только после успешной проверки.

Обрати внимание на две разные причины отказа:

- повреждённый JSON остановится при разборе;
- корректный JSON с неверной структурой остановится на валидации.

Не перехватывай обе ошибки одним широким `except` и не подменяй результат пустым словарём. Иначе пропавший файл, оборванная запись и неизвестный `status` будут выглядеть как нормальное «пустое состояние». Полезнее сохранить исходную ошибку: она точно показывает, на каком рубеже файл не прошёл проверку.

Проверь функцию на валидном файле, а затем намеренно испорть значение одного поля. Во втором случае данные не должны быть возвращены. Именно здесь чтение превращается из «получить что-то с диска» в «получить состояние, которому можно доверять».

> 🎒 **На пальцах.** Представь механика, которому принесли коробку с деталями велосипеда. Сначала он открывает коробку и убеждается, что внутри вообще детали, а не спутанный мусор. Затем сверяет каждую деталь со списком: два колеса, подходящая цепь, нужные тормоза. Только после обеих проверок набор отправляется в сборку. `load_state` делает то же самое с файлом.
