source_anchor: '### Atomic writes'
check:
  - question: Процесс упал до вызова os.replace. Что останется в целевом файле?
    options:
      - 'Новое состояние, но, возможно, не целиком'
      - Прежнее состояние; рядом может остаться временный файл
      - Целевой файл обязательно исчезнет
    correct: 1
    explanation: >-
      До подмены целевой файл не трогают, поэтому прежняя версия остаётся целой.
      Незавершённая работа затрагивает только временный файл.
  - question: >-
      Неизвестно, случилось падение прямо до или сразу после os.replace. Какой
      результат допустим?
    options:
      - Только смесь старого и нового содержимого
      - Обязательно пустой файл
      - 'Либо целая старая версия, либо целая новая'
    correct: 2
    explanation: >-
      Подмена атомарна: другие операции не видят её промежуточного состояния.
      Граница падения определяет версию, но не создаёт половину файла.
---

Проверь границу операции из [шага 10](#step-10): пока `os.replace` не выполнен, имя целевого файла указывает на прежнюю целую версию. Новый результат находится во временном файле, который после падения может остаться рядом.

Если подмена успела выполниться, по целевому имени доступна уже новая целая версия. Когда точный момент падения неизвестен, допустимы оба исхода — старое или новое состояние, — но не смесь их фрагментов.

> 🎒 **На пальцах.** Ты меняешь ценник в закрытом конверте: сначала готовишь новый отдельно, затем одним движением заменяешь конверт на витрине. Сбой раньше оставит старый конверт, сбой позже — новый. Наполовину заменённого конверта покупатель не увидит.
