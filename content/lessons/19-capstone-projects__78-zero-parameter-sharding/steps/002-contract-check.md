title: Проверяем путь градиента и параметры дополнения

check:
  - question: >-
      Какая лишняя работа с данными возникает, если перед локальным обновлением
      выполнить allreduce градиентов, а затем выбрать принадлежащий рангу срез?
    options:
      - >-
        На каждом ранге материализуется полный свёрнутый градиент, хотя для
        обновления нужен только локальный шард
      - Каждый ранг получает несвёрнутые градиенты только от одного соседа
      - >-
        Параметры автоматически делятся между рангами и перестают быть
        реплицированными
    correct: 0
    explanation: >-
      После allreduce каждый ранг имеет полный градиент и отбрасывает часть,
      которой не владеет. Reduce-scatter объединяет свёртку с распределением и
      возвращает сразу нужный шард.
  - question: >-
      Зачем плоский буфер дополняют перед reduce-scatter и что делают с
      добавленными позициями при восстановлении модели?
    options:
      - >-
        Дополнение создаёт равные по длине шарды; служебные позиции затем
        отбрасывают и не сопоставляют параметрам
      - >-
        Дополнение превращает служебные позиции в обучаемые параметры последнего
        слоя
      - 'Дополнение дублирует крайние градиенты, чтобы Adam обновил их повторно'
      - Дополнение нужно только для изменения dtype градиентов
    correct: 0
    explanation: >-
      Коллективная операция работает с равными частями, поэтому буфер расширяют
      до подходящей длины. Дополнительные элементы не принадлежат модели и
      удаляются перед раскладкой значений по параметрам.
---

После сборки из [шага 1](#step-1) проверь две вещи: градиент приходит именно владельцу соответствующего шарда, а после локального обновления все ранги снова получают одинаковые параметры. Частая ошибка — принять служебное дополнение за настоящие веса. Оно лишь доводит длину плоского буфера до числа, которое делится на количество рангов; при возвращении к параметрам лишние позиции отбрасываются.
