Ты запускаешь функцию на примере, где эталонный ответ содержит три факта, а найденные фрагменты подтверждают только два. Ожидаешь `0.67`, но получаешь `1.0`. Скорее всего, судья проверил контекст целиком одним вопросом: «Он в целом подходит?» Один найденный факт замаскировал пропущенный.

Собери `context_recall` вокруг атомарных утверждений из [шага 13](#step-13):

```python
    которые подтверждаются найденным контекстом.
    """
    # 1. Разбей reference_answer на атомарные утверждения.
    # 2. Объедини contexts в материал для проверки.
    # 3. Попроси judge проверить каждое утверждение отдельно.

    pass
```

Для каждого утверждения судья должен отвечать на узкий вопрос: можно ли подтвердить именно этот факт, используя только переданные фрагменты? Проверяется эталонный ответ, а не ответ генератора. Иначе функция начнёт измерять другую часть RAG.

Обрати внимание на три крайних случая:

- пустые строки после разбиения не считаются фактами;
- пустой `contexts` не может подтвердить непустое утверждение;
- неразобранный ответ судьи нельзя молча выбрасывать из расчёта — выбери явную ошибку или заранее заданный режим отказа, как обсуждалось в [шаге 9](#step-9).

Проверь функцию на трёх наборах: подтверждены все факты, подтверждена часть, не подтверждён ни один. Главная ловушка — посчитать найденные полезные фрагменты вместо покрытых эталонных фактов: тогда получится уже логика `context_precision` из [шага 20](#step-20).

> 🎒 **На пальцах.** Представь съёмочную площадку: в сценарии нужны красный зонт, старые часы и письмо. Ассистент привёз пять коробок реквизита. Ты проверяешь не долю полезных коробок, а каждый пункт сценария: есть ли где-нибудь нужный предмет. Зонт и часы нашлись, письмо — нет. Лишние коробки не уменьшают recall; пропущенное письмо уменьшает.
