Тебе нужно собрать три уже готовых инструмента в одну функцию `solve_cholesky(A, b)`. Она получает матрицу `A` и правую часть `b`, а возвращает найденный вектор `x`.

Сначала вызови `cholesky` из [шага 36](#step-36), чтобы получить нижнюю треугольную матрицу `L`. Дальше не пытайся сразу вычислить `x`: в [шаге 37](#step-37) система была разделена на два последовательных этапа.

На первом этапе передай `L` и `b` в `forward_substitution` из [шага 17](#step-17). Результат сохрани как промежуточный вектор `y`. На втором этапе вызови `back_substitution` из [шага 14](#step-14), но внимательно выбери матрицу: ей нужен верхний треугольник, поэтому передавай `L.T`, а не `L`. Полученный вектор `x` и станет ответом функции.

Обратную матрицу вычислять не нужно. Здесь вся выгода Холецкого именно в двух быстрых треугольных проходах.

Проверь функцию на данных:

```python
A = np.array([[4., 2.],
              [2., 5.]])
b = np.array([8., 12.])
```

Ответ должен быть близок к `[1., 2.]`. Дополнительно вычисли `A @ x` и сравни с `b` через `np.allclose`. Если передать неподходящую матрицу, ошибку должен поднять уже `cholesky` — перехватывать и скрывать её не надо.

> 🎒 **На пальцах.** Представь пункт выдачи с двумя окнами. В первом по номеру заказа находят нужную ячейку — это получение `y`. Во втором по содержимому ячейки собирают посылку — это получение `x`. Если сразу пойти ко второму окну или передать ему список в неправильном порядке, цепочка сломается. `solve_cholesky` лишь правильно проводит данные через оба окна.
