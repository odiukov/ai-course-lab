У тебя есть матрица `A` из 200 наблюдений и 6 признаков. Первая ловушка — попытаться прибавить `lam` прямо к `A`. Но регуляризация относится не к наблюдениям: она изменяет квадратную систему для шести весов. Поэтому единичная матрица должна иметь размер `6 × 6`, то есть число столбцов `A`, а не число строк.

В `ridge_regression(A, b, lam)` сначала найди `n = A.shape[1]`. Затем собери регуляризованную матрицу из `A.T @ A`, `lam` и `np.eye(n)`. Правую часть `A.T @ b` оставь без добавок: штраф меняет коэффициенты системы, но не целевые значения.

Дальше используй маршрут из [шага 53](#step-53): разложи полученную матрицу функцией `cholesky`, а решение получи через две треугольные системы. Для первой подойдёт `forward_substitution` из [шага 17](#step-17). Во второй матрицей будет `L.T`, поэтому воспользуйся `back_substitution` из [шага 14](#step-14).

Обрати внимание на три детали:

- `np.eye` получает `n`, а не `A.shape[0]`;
- `lam` прибавляется только к диагонали `A.T @ A`;
- функция возвращает вектор из `n` весов.

Для самопроверки подставь результат в регуляризованную систему: её левая и правая части должны совпадать с небольшой погрешностью вычислений. Если размеры не сходятся, первым делом проверь, не перепутал ли ты количество наблюдений с количеством признаков.

> 🎒 **На пальцах.** Представь шкаф с шестью тугими регулировочными винтами — по одному на каждый вес модели. `lam` не добавляет новые полки с данными, а одинаково подтягивает именно эти шесть винтов. Поэтому добавка имеет размер `6 × 6`, даже если в шкафу лежат двести наблюдений.
