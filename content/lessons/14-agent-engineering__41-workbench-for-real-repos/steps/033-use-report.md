В понедельник ревьюер спрашивает, зачем PR тащит `agent-rules.md`. Во вторник менеджер предлагает отключить проверочный шлюз ради скорости. В среду поставщик показывает нового агента и обещает «на 40% больше продуктивности». Кажется, для каждого разговора нужен отдельный ответ. Но у тебя уже есть один общий предмет обсуждения — отчёт до и после.

Для PR он связывает правило с наблюдаемым результатом: без контрактного пайплайна появился лишний файл, а с ним границы соблюдены. Это сильнее, чем «правило считается полезным», потому что проверяющий видит, какой исход оно защищает.

Для CI-гейта отчёт превращается в критерий допуска. Например, строка `tests_actually_run` отвечает не на вопрос «агент написал, что тестировал?», а на вопрос «есть ли свидетельство запуска?». Если шлюз хотят временно убрать, команда заранее видит, какую измеримую гарантию она снимает.

При выборе агентного продукта тот же формат становится переносимым бенчмарком из [шага 31](#step-31). Ты меняешь продукт, но сохраняешь задачу, протокол и исходы; вариативность живой LLM учитываешь так, как обсуждалось в [шаге 32](#step-32). Тогда рекламное обещание сталкивается с твоими репозиториями, а не с чужой демонстрацией.

Отчёт не принимает решение за команду. Он делает цену решения видимой — и спор наконец идёт о допустимом риске, а не о впечатлениях.

> 🎒 **На пальцах.** Представь журнал осмотра городского моста. Для инженера запись объясняет, зачем заменили конкретную опору; для диспетчера становится условием открытия движения; для города помогает выбрать подрядчика на следующий ремонт. Один журнал поддерживает три решения, потому что везде предъявляет одни и те же замеры, а не три убедительные истории.
