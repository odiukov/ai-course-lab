Ты открываешь репозиторий после перерыва: last-known-good указывает на проверенный коммит, а текущий коммит ушёл вперёд. Между ними изменены 47 файлов. Старт разрешён. Добавляешь ещё четыре файла — теперь проба должна остановить запуск, потому что бюджет из [шага 22](#step-22) превышен.

В `probe_lkg_diff` сначала получи идентификатор last-known-good из состояния репозитория, описанного в [шаге 13](#step-13). Затем попроси Git перечислить файлы, отличающиеся между этим коммитом и `HEAD` — текущим коммитом. Считать нужно именно файлы, а не строки кода: изменение одной строки и переписывание тысячи строк дают по одному файлу.

Проследи за границей: 50 файлов ещё допустимы, 51 — уже нет. Результат оформи по единому контракту из [шага 5](#step-5): имя пробы, статус и объяснение с фактическим числом, например «изменено 47 из 50 файлов». Так отчёт показывает не только решение, но и насколько близко репозиторий подошёл к пределу.

Есть ещё три важных случая для проверки: LKG совпадает с `HEAD`, записанный коммит не существует, а команда Git завершилась ошибкой. Первый случай даёт ноль изменений и успешный статус. В двух остальных сравнение не состоялось, поэтому успешный результат возвращать нельзя: неизвестный размер diff не равен нулевому.

Незакоммиченные изменения сюда не включай: функция сравнивает коммиты. Проверь её на значениях 0, 50 и 51 — именно на границе чаще всего прячется ошибка.

> 🎒 **На пальцах.** Представь реставратора, который принимает музей после последней утверждённой инвентаризации. Он сверяет список экспонатов и допускает не больше 50 изменений. При 50 музей открывается, при 51 — остаётся закрытым. Если старая опись потеряна, реставратор не пишет «изменений нет»: он честно сообщает, что сверка невозможна.
