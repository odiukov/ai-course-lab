В списке указаны три зависимости. Первая найдена, второй нет — можно сразу вернуть ошибку. Но тогда третья останется непроверенной, и после исправления придётся запускать init ещё раз, чтобы обнаружить следующую пропажу. Полезнее за один проход собрать полный список отсутствующих пакетов.

Напиши `probe_dependencies`, опираясь на способ проверки из [шага 8](#step-8). Функция должна пройти по всем обязательным зависимостям и для каждой вызвать `importlib.util.find_spec`. Сам пакет импортировать не нужно: здесь ты проверяешь его доступность, а не запускаешь его код.

Сохраняй имена, для которых `find_spec` вернул `None`. После обхода возможны два результата:

- список пуст — проба возвращает успешный статус и поясняет, что все зависимости доступны;
- в списке есть имена — проба возвращает блокирующий статус и перечисляет отсутствующие зависимости в `detail`.

В обоих случаях результат должен иметь единый формат `(name, status, detail)` из [шага 5](#step-5). Обрати внимание: одна функция создаёт результат одной пробы, а не отдельную пробу для каждого пакета.

Проверь себя на трёх наборах: все зависимости установлены; отсутствует одна; отсутствуют несколько. Особенно посмотри на последний случай: в объяснении должны появиться все пропуски, а не только первый. Тогда init сразу выдаст полный список того, что нужно исправить.

> 🎒 **На пальцах.** Представь механика, который сверяет инструменты с описью, не включая дрель и не заводя компрессор. Он осматривает все места на стенде и записывает каждое пустое, а не прекращает проверку после первого пропавшего ключа. Так механик получает один полный список недостающего оборудования — именно такой список должна вернуть проба зависимостей.
