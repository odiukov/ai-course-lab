Ты запускаешь скрипт на Python 3 и видишь знакомую строку версии. Но надпись `Python 3` ещё ничего не гарантирует: проекту может требоваться, например, версия не ниже заданной пары `major.minor`. Эту проверку и должна выполнять `probe_runtime`.

Найди заготовку функции в `code/main.py`. Возьми фактическую версию из `sys.version_info`, оставив только первые два числа, и сравни её с минимальной версией, уже заданной в файле. Логику сравнения ты разобрал в [шаге 6](#step-6): Python умеет сопоставлять такие пары по порядку — сначала старшую часть версии, затем младшую.

Функция должна вернуть тройку из [шага 5](#step-5):

- постоянное имя пробы, по которому её можно узнать в отчёте;
- успешный статус, если текущая версия подходит, иначе блокирующий;
- понятное объяснение с фактической и требуемой версиями.

Не ограничивай `detail` фразой «версия неверна». Представь, что отчёт откроют завтра на другой машине: по нему должно быть сразу видно, что обнаружено и какой минимум ожидался.

После реализации запусти `python3 code/main.py` и найди строку проверки рантайма. На подходящей версии она должна пройти. Затем мысленно подними требование выше своей версии: измениться должны статус и объяснение, но форма результата останется прежней.

> 🎒 **На пальцах.** Представь аттракцион с ограничением роста. Контролёр не просто говорит «нельзя», а сверяет две отметки: твой рост — 132 см, минимум — 140 см. `probe_runtime` работает так же: берёт реальную версию, сопоставляет её с порогом и прикрепляет к решению обе цифры. Поэтому отказ можно проверить, а не принимать на веру.
