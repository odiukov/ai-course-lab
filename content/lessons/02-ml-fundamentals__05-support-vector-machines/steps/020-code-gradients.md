Представь, что после проверки мини-батча модель получила несколько замечаний: одна точка просит сдвинуть границу, другая — повернуть её, а третья уже расположена достаточно уверенно и не требует изменений. Функции `hinge_gradients` нужно собрать эти замечания в одну команду для обновления модели.

Функция принимает `X`, `y`, `w` и `b`, а возвращает два результата:

- вектор градиента для `w` той же длины, что и сами веса;
- одно число — градиент для `b`.

Сначала подготовь нулевые накопители. Затем для каждой строки `X[i]` вычисли margin точно так же, как в `hinge_loss` из [шага 16](#step-16). Если margin меньше `1`, прибавь к накопителям вклад этой точки по правилу из [шага 19](#step-19). Векторный вклад нужно добавить покомпонентно: каждому весу соответствует свой признак точки. Если margin больше или равен `1`, ничего добавлять не нужно — hinge loss этой точки уже не меняется.

В конце раздели оба накопленных градиента на число объектов `n`. Это важно: `hinge_loss` возвращает среднюю потерю по батчу, поэтому и её градиент должен быть средним. Иначе один и тот же набор данных, случайно повторённый дважды, даст вдвое больший шаг обновления.

На самой границе `margin == 1` производная неоднозначна. В этой реализации договорись считать вклад нулевым — условие цикла тогда проверяет строго `margin < 1`.

> 🎒 **На пальцах.** Представь бригаду, которая двигает тяжёлый стол. Каждый человек у проблемного края подсказывает направление и силу толчка, а тот, у кого край уже стоит правильно, молчит. Ты складываешь все подсказки и делишь результат на число участников. Так размер бригады не меняет смысл общей команды: получается среднее направление для следующего движения.
