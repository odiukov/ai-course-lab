type: theory
title: Backward обходит ту же цепочку в обратном порядке
source_anchor: '### Step 6: Sequential Container'
---

Ты пропускаешь данные через три слоя: первый меняет вход, второй обрабатывает его результат, третий выдаёт итог модели. После сравнения итога с правильным ответом появляется градиент — сигнал о том, как изменение результата повлияет на ошибку. Но первому слою этот сигнал пока не подходит: между ними стоят ещё два преобразования.

Поэтому первым вызывается `backward` третьего слоя. Он получает градиент относительно своего выхода и, используя сохранённые во время `forward` значения из [шага 10](#step-10), превращает его в градиент относительно своего входа. Для второго слоя этот вход был его выходом — значит, получившийся градиент уже можно передать ему. Второй слой делает такое же преобразование и передаёт результат первому.

В `Sequential` это выражается коротким циклом:

```python
for module in reversed(self.modules):
    grad = module.backward(grad)
```

Здесь `grad` на каждой итерации меняет смысл: сначала он относится к выходу всей цепочки, затем — к выходу предыдущего слоя, и так далее до входа модели. Это тот самый поток градиентов назад из [шага 9](#step-9), только теперь видно, кто организует его передачу.

Если пойти слева направо, первый слой получил бы сигнал, рассчитанный для выхода третьего слоя, и не смог бы корректно связать его со своим преобразованием. Обратный порядок нужен потому, что каждый слой умеет передать сигнал только через собственный участок цепочки.

> 🎒 **На пальцах.** Представь трёх переводчиков: первый переводит с русского на английский, второй — с английского на испанский, третий — с испанского на португальский. Замечание к португальской фразе сначала понимает третий. Он переводит его для второго, второй — для первого. Исправление возвращается по тому же маршруту, но в обратную сторону.
