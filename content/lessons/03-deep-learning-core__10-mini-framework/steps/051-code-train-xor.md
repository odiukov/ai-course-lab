У тебя есть всего четыре примера XOR, но один проход по ним ничего не решит: сеть лишь чуть сдвинет случайные веса. Поэтому в `train_xor` одни и те же примеры должны пройти через модель много раз — каждая такая полная итерация будет эпохой.

Собери модель со скрытым `Linear`-слоем, нелинейной активацией и одним выходом. Форму входа и цели возьми из `xor_dataset`, написанного на [шаге 39](#step-39). Затем организуй два вложенных цикла: внешний — по эпохам, внутренний — по четырём парам `x, target`.

Для каждого примера сохрани строгий порядок из [шага 45](#step-45):

1. Получи `prediction` через `model.forward(x)`.
2. Посчитай ошибку функцией `mse_loss`.
3. Обнули прежние градиенты с помощью `zero_grads`.
4. Получи начальный градиент через `mse_grad`.
5. Передай его в `model.backward`.
6. Обнови параметры вызовом `sgd_step`.

Накапливай ошибки четырёх примеров и после каждой эпохи сохраняй их среднее. Смотри именно на порядок действий: если вызвать обнуление после `backward`, ты сотрёшь только что вычисленные градиенты; если забыть его совсем, градиенты начнут складываться между примерами, как разбиралось на [шаге 27](#step-27).

В конце верни обученную модель и историю средней ошибки — следующий экран использует их для проверки результата. Здесь твоя задача не угадать ответы XOR вручную, а правильно собрать повторяемый цикл обучения.

> 🎒 **На пальцах.** Представь настройку четырёх кнопок игрового автомата. Ты нажимаешь первую комбинацию, замечаешь ошибку и слегка подкручиваешь механизм; затем повторяешь это для остальных трёх. Один круг — эпоха. После каждого нажатия ты стираешь старую пометку регулировщика, иначе новая поправка смешается с предыдущей. Много аккуратных кругов постепенно настраивают весь автомат.
