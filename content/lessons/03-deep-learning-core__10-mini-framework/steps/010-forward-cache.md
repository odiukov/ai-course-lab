title: Forward сохраняет промежуточные значения для обратного прохода

Ты запускаешь данные через несколько слоёв и получаешь ответ. Кажется, промежуточные числа можно сразу выбросить: ведь дальше нужен только результат. Но при обучении последний ответ сообщает лишь, насколько модель ошиблась. Чтобы понять, как изменить конкретный параметр, слою часто нужно вспомнить, что он видел во время прохода вперёд.

Допустим, слой умножил вход `3` на свой вес `2` и передал дальше `6`. Позже к нему приходит градиент `4` — сигнал о влиянии результата слоя на ошибку. Для поправки веса понадобится сохранённый вход `3`: вклад в градиент веса будет `3 × 4 = 12`. Одного числа `6` недостаточно: оно могло получиться множеством способов.

Поэтому во время `forward`, знакомого тебе по [шагу 6](#step-6), модуль кладёт нужные промежуточные значения во временный **кэш** — внутренний «карман памяти». Один слой сохраняет вход, другой — позиции положительных значений, третий — ещё какие-то данные, необходимые именно его вычислению. Наружу он по-прежнему возвращает только свой результат.

Контейнер `Sequential` не обязан знать содержимое этих карманов. Он просто передаёт данные дальше, как в [шаге 9](#step-9), а каждый модуль сам запоминает то, что позже потребуется ему для вычисления градиентов. Значит, `forward` не только строит ответ модели — он ещё оставляет следы, без которых обучение пришлось бы вести вслепую.

> 🎒 **На пальцах.** Представь реставратора, который очищает картину слой за слоем и фотографирует её после каждого действия. Увидев итог, он может понять, где работа пошла не так, только сравнив его с промежуточными снимками. Кэш — это такая папка снимков: зрителю показывают готовую картину, а мастеру сохранённые этапы помогают точно исправить свою работу.
