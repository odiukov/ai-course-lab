title: 'Проверка: append, replace или пересказ'
source_anchor: '### Memory blocks'
check:
  - question: >-
      Пользователь раньше говорил «я работаю в Питере», а сегодня написал:
      «переехал, теперь Казань». В Human block уже лежит строка про Питер. Какой
      инструмент правки тут нужен?
    options:
      - >-
        block_append: дописать снизу «теперь Казань», старая строка про Питер
        пусть остаётся
      - 'block_replace: найти фрагмент про Питер и заменить его на Казань'
      - 'block_summarize: при пересказе неверная строка сама исчезнет'
      - 'Ничего не вызывать: модель разберётся по порядку строк, какая новее'
    correct: 1
    explanation: >-
      Факт не добавился, а изменился. Дозапись оставит в блоке два города сразу,
      и оба уедут в промпт равноправно — в value нет ни дат, ни приоритета по
      порядку. Пересказ сохраняет факты, а не отсеивает опровергнутые, поэтому
      противоречие переживёт и его. Убрать устаревший фрагмент может только
      замена.
  - question: >-
      Инструмент дозаписи вернул near_limit = True: запись прошла, но блок
      подошёл к своему лимиту. Что это значит для следующего шага агента?
    options:
      - >-
        Это предупреждение: текущая запись сохранена, но перед следующей
        дозаписью блок нужно сжать пересказом
      - 'Это ошибка: запись не применилась, её надо повторить после сжатия блока'
      - 'Это сигнал поднять лимит блока, чтобы дозаписи проходили и дальше'
      - >-
        Это сигнал завести второй блок с тем же назначением и писать новые факты
        туда
    correct: 0
    explanation: >-
      Порог срабатывания стоит строго ниже жёсткого лимита, чтобы флаг успел
      загореться раньше, чем запись сорвётся. Поэтому near_limit не отменяет
      сделанную дозапись, а требует освободить место до следующей. Переполнение
      лечится сжатием содержимого на месте: расширение лимита просто отнимает
      контекст у каждого запроса, а параллельный блок с тем же назначением
      ломает маршрутизацию фактов по description.

После [шагов 14](#step-14)–[19](#step-19) у тебя на руках развилка из трёх ходов, и выбрать нужно до того, как ты трогаешь блок. Новый факт, которого раньше не было, — дописывание. Факт, который заменил старый, — замена. Места не осталось — пересказ.

Спотыкаются обычно на втором: изменившийся факт по привычке дописывают снизу. Блок при этом не врёт наполовину — он врёт целиком, потому что в промпт уезжают обе строки сразу, и модель верит первой.

Второе место — `near_limit` из [шага 19](#step-19): его легко прочитать как ошибку. Это не ошибка, а лампочка топлива: запись ещё пройдёт, но следующая может не пройти.
