Ты подставляешь первый эталон из `targets`, запускаешь прогон — и вдруг задача с кодом получает обычную строку, а задача с выбором ответа не распознаёт правильную букву. Содержание верное, но форма не совпала с тем, что ждёт следующий участник цепочки. Детерминированный адаптер из [шага 10](#step-10) должен учитывать не только правильный ответ, но и контракт конкретной задачи.

Доработай метод `generate`. По умолчанию он берёт первый эталонный ответ, а при отсутствии `targets` использует пустой текст. Затем обработай специальные случаи.

Для `code_exec` подготовь ответы именно тех фикстур, которые исполняет оценщик: одна должна определять функцию сложения, другая — функцию проверки чётности. Это должен быть оформленный Python-блок с полноценным определением функции, а не словесное описание результата. Для неизвестной кодовой задачи оставь безопасный исполнимый блок.

Если `post_process` равен `extract_letter` и эталон существует, помести букву в ожидаемый шаблон ответа. Здесь важна оболочка: обработчик должен извлечь букву из текста так же, как при настоящем ответе модели.

После окончательного выбора текста посчитай токены по словам. Даже пустой ответ обязан дать положительный `token_count`, иначе расчёт perplexity получит невозможный нулевой объём. Из этого же количества вычисли `token_nll`, запиши пару в `token_stats` и верни её внутри `Generation` вместе с текстом и фиксированной уверенностью. Статистика и объект ответа должны описывать одну и ту же генерацию.

> 🎒 **На пальцах.** Представь мастерскую ключей. Заготовка верного размера ещё не открывает любой замок: для одного нужна рабочая бороздка-функция, для другого — буква на бирке в установленном формате. А счётчик мастера не может записать «изготовлено ноль», если ключ уже выдан. Форма ответа и положительный счётчик делают эталон пригодным для следующего механизма.
