  - question: >-
      В AGENTS.md написано: «Перед выпуском тщательно проверь результат». Какое

    options:

      - >-
        Указать проверяемые команды, ожидаемые файлы и функцию проверки их

      - Перенести инструкцию в отдельный файл с более заметным названием
      - 'Попросить агента после работы подтвердить, что проверка выполнена'

  - question: >-
      Парсер прочитал полную запись правила, но поле check содержит неизвестное
      имя. Что должен сделать компилятор?
    options:
      - Пропустить правило и продолжить без него
      - Выбрать похожую функцию проверки по названию
      - 'Остановить компиляцию и сообщить, что правило неисполняемо'

    correct: 2
    explanation: >-

      валидным, но проверяет не то, что написал автор.
  - question: >-
      Проверяльщик прогнал набор правил по трейсу: провалено одно правило уровня
      block и одно уровня warn, остальные пройдены. Каким должен быть результат?
    options:
      - >-
        Прогон останавливается, а отчёт сохраняет вердикты по всем правилам

      - >-
        Прогон продолжается, потому что пройденных правил больше, чем

      - >-
        Отчёт содержит только блокирующее нарушение, успешные вердикты

    correct: 0
    explanation: >-

      - Дублировать каждое правило во всех каталогах проекта
      - 'Оставить всё в корневом файле, чтобы избежать переходов между файлами'
      - >-
        Оставить в корне карту-роутер, держать Markdown источником истины и

    explanation: >-

      Markdown остаётся авторским источником с читаемым диффом, а проверки
      достижимости и свежести не дают правилу потеряться за битой ссылкой или
      разойтись с машинным кешем.
---

Дальше тебе понадобится не красивый AGENTS.md, а контракт, которому можно доверять при запуске агента. Собирай его по всей цепочке: наблюдаемое правило, корректная запись, известная функция проверки, полный отчёт и вердикт по severity. Чаще всего спотыкаются в двух местах: принимают уверенную формулировку за проверку и допускают молчаливый пропуск неизвестного check. Слоистая структура, срок годности и rules_lock не украшают контракт — они не дают ему незаметно устареть.
