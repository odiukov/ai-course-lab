У тебя три документа: «Python is fast», «python runs fast», «Fast API guide». Хочешь сравнить их числами — а числа должны стоять в одинаковых ячейках, иначе сравнивать нечего. Из [шага 36](#step-36) ты помнишь: оси вектора задаёт словарь. Значит, первое, что нужно построить, — сам список слов, общий для всего корпуса.

Функция `build_vocabulary` принимает список документов и возвращает этот список слов.

Внутри три решения, и каждое стоит проговорить. Первое: приводим текст к нижнему регистру, иначе «Python» и «python» займут две разные оси, и два предложения про одно и то же окажутся непохожими. Второе: режем текст на слова по пробелам — самый грубый способ, и он честно даст тебе «fast» и «fast,» как два разных слова, если в тексте была запятая. Пока живём с этим. Третье: слова из всех документов складываем в одну кучу без повторов — «fast» встретился трижды, а ось нужна одна.

И вот тонкость, на которой обычно спотыкаются. Куча без повторов не имеет порядка: сегодня Python выдаст тебе слова в одном порядке, завтра в другом. А вектор — это позиции. Поэтому в конце список обязательно упорядочивается по алфавиту: ось номер 0 всегда «api», ось номер 1 всегда «fast», и так навсегда.

Проверь себя на выходе: длина результата — это и есть размерность будущих векторов, и она одна на весь корпус.

> 🎒 **На пальцах.** Учитель делает список класса. Сначала выписывает всех, кто есть, без повторов: Петров записан один раз, даже если его назвали трижды. Потом сортирует по алфавиту и раздаёт копии. Теперь «номер 12» — один и тот же человек у всех. Если бы кто-то оставил список в порядке, как вспоминалось, его двенадцатый был бы чужим двенадцатым, и вся перекличка развалилась бы.
