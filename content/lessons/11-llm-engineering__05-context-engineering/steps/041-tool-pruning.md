Посчитай сам: у агента подключены сорок инструментов — календарь, почта, чтение файлов, git, поиск по базе, конвертер валют, отправка сообщений. По цене из [шага 15](#step-15) это примерно 8 000 токенов. Пользователь пишет: «почему падают тесты в модуле оплаты?». Сколько инструментов из сорока тут пригодятся? Три, может четыре — файлы, git, запуск тестов. Остальные тридцать шесть всё равно поедут в окно, и поедут на каждом ходу, как и весь фиксированный низ из [шага 14](#step-14).

Заманчиво просто отключить лишнее. Но завтра тот же человек спросит про расписание на неделю — и календарь понадобится.

Выход в том, чтобы перестать решать это один раз при настройке. Набор инструментов собирается заново под каждый запрос: сначала прикидываем, о чём вообще спрашивают, потом кладём в окно только то, что подходит под это намерение. Вопрос про код не получает календарных инструментов. Вопрос про встречу не получает файловую систему.

Числа получаются такие: было 8 000, стало около 1 000. Освободилось 7 000 — это ровно та история диалога на десять ходов, которую иначе пришлось бы пересказывать по [шагу 36](#step-36). И заодно работает правило из [шага 6](#step-6): четыре подходящих инструмента модель выбирает увереннее, чем сорок, среди которых тридцать шесть — шум.

Ты не экономишь на возможностях агента. Ты перестаёшь платить за тридцать шесть неподходящих на каждом ходу.

> 🎒 **На пальцах.** Сантехник не заносит в квартиру весь фургон. Он слышит по телефону «течёт кран» и берёт один кейс: разводной ключ, прокладки, лента. Разводка отопления и перфоратор остаются в машине — не выброшены, просто не сегодня. Позвонят про радиатор — соберёт другой кейс. Инструменты никуда не делись, в руках только те, что нужны под эту заявку.
