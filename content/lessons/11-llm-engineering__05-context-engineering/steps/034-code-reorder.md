У тебя на руках два списка. `documents` — сами куски текста, `scores` — их оценки из `score_relevance` ([шаг 32](#step-32)). Лежат параллельно: третья оценка относится к третьему документу, и связь держится только на совпадении индексов. А тебе нужно переставить документы в порядок A C E D B из [шага 33](#step-33) — то есть отсортировать один список по числам из другого.

Вот тут и первая ловушка. Отсортируешь `scores` — документы останутся на местах, и связь порвётся. Значит, перед сортировкой пары надо склеить, причём оценку поставить первым элементом пары: сортировка сравнивает пары по первому значению, и тогда числа сами утянут документы за собой. Сортируем по убыванию — сильнейший вперёд. После этого из пар нужно вынуть обратно только документы, иначе наружу уедут кортежи вида `(0.75, "текст")`, и следующая функция в конвейере на них споткнётся.

Дальше — короткие списки. Один документ, два документа: делить на «начало» и «конец» нечего. Поставь ранний выход и возвращай отсортированное как есть.

А для остальных — те самые срезы через один и разворот второй половины.

На что смотреть, когда запустишь. Длина результата обязана совпасть с длиной входа: ни один документ не потерялся и ни один не удвоился — это первая проверка, которая ловит опечатку в срезах. Потом глазами: первый элемент — самый сильный, последний — второй по силе, а самый слабый сидит где-то посередине. Прогони на пяти документах, потом на шести — на чётной длине половины получаются равными, и порядок хвоста меняется.

Функция ничего не выбрасывает. Она только раздаёт места.

> 🎒 **На пальцах.** Разложи колоду по старшинству и сдавай через одну в две кучки: первая получает 1-ю, 3-ю, 5-ю карты, вторая — 2-ю, 4-ю. Теперь вторую кучку переверни и подложи под первую. Сверху окажется старшая карта, снизу — вторая по старшинству, а самая слабая утонет в середине. Твоя функция делает ровно это: не судит карты, а решает, кто ляжет по краям.
