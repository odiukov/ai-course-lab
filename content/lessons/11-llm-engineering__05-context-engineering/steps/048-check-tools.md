check:
  - question: >-
      Запрос: «Fix the bug in the login function in auth.py». Какие инструменты
      из реестра попадут в контекст при бюджете 2000 токенов?
    options:
      - >-
        Только read_file и search_code — читать файл и искать по коду, остальное
        запросу не нужно
      - >-
        Все пять инструментов с категорией code: read_file, write_file,
        search_code, run_command и query_database — 710 токенов
      - >-
        Весь реестр из десяти инструментов, 1580 токенов: бюджета хватает,
        отсекать нечего
      - >-
        Ни одного: слова auth.py в списке ключевых слов нет, намерение не
        определилось
    correct: 1
    explanation: >-
      Срабатывают bug и function, значит намерение одно — code. Дальше фильтр
      пропускает инструмент, если хотя бы одна его категория совпала с
      намерением, поэтому query_database с категориями code и data тоже
      проезжает внутрь.
  - question: 'Тот же запрос, но бюджет урезали до 600 токенов. Что окажется в контексте?'
    options:
      - 'Ничего: 710 токенов в 600 не влезают, набор целиком отбрасывается'
      - >-
        Первые четыре инструмента на 540 токенов, query_database не помещается и
        пропускается
      - 'Первые четыре инструмента, а пятый обрезается до остатка в 60 токенов'
    correct: 1
    explanation: >-
      Проверка идёт по каждому инструменту отдельно: 120 + 150 + 130 + 140 =
      540, а следующие 170 превысили бы 600, поэтому query_database просто не
      берут. Определение инструмента либо входит целиком, либо не входит вовсе.
---

Здесь проверяется, умеешь ли ты прогнать запрос через обе ступени отбора и получить конкретное число токенов, а не общее «лишнее отсекается».

Спотыкаются обычно на двух местах. Первое: кажется, что раз запрос про починку бага, то нужны только «очевидные» инструменты вроде read_file. Но фильтр не рассуждает о смысле — он сверяет категории, и инструмент с двумя категориями заезжает по любой из них. Второе: бюджет из [шага 45](#step-45) читают как общий предел, после которого перебор останавливается. Он работает иначе — проверяется каждый кандидат по отдельности, и слишком дорогой пропускается целиком, без обрезки.
