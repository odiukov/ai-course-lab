Реестр из [шага 42](#step-42) готов: у каждого инструмента есть цена в токенах и категории. Приходит запрос: «Debug the SQL query in this file and explain the error». Какие категории включать?

Способ дешёвый до неприличия: держим для каждого намерения список слов-маркеров и просто считаем совпадения. У `code` это code, function, bug, error, file, implement, refactor, debug, test. У `data` — data, query, database, chart, sql. У `research` — search, find, explain, how does.

Считаем на нашем запросе. `code`: debug, bug (проверка идёт по подстроке, поэтому «bug» внутри «debug» тоже засчитывается), error, file — четыре очка. `data`: query, sql — два. `research`: explain — одно.

Победитель ясен. Но взять только его — значит выкинуть работу с базой, а запрос явно про SQL.

Поэтому берём не победителя, а всех, кто держится рядом с ним:

$$\text{score} \geq 0.5 \times \text{max\_score}$$

$\text{score}$ — сколько маркеров намерения нашлось в запросе, $\text{max\_score}$ — счёт лидера. Половина от лидера — это и есть порог. У нас лидер набрал 4, порог 2. `code` проходит, `data` проходит ровно по границе (сравнение нестрогое, поэтому попадает), `research` с одним очком отсекается.

А если не сработало ни одно слово? Тогда счётов нет вообще, порог считать не от чего — возвращаем `["code"]` как разумное значение по умолчанию.

Порог 0.5 — это ручка громкости. Поднимешь до 0.8 — останется почти только лидер, опустишь до 0.2 — в контекст полезут случайные категории вместе со своими инструментами. Половина держит второе намерение и режет шум.

> 🎒 **На пальцах.** За стеной разговаривают соседи, слов не разобрать, но повторы слышны: «плитка», «стяжка», «мастер» — раз шесть; «смета», «предоплата» — раза четыре; «Турция» проскочило один раз. Лидер — ремонт, шесть. Половина от шести — три. Деньги проходят, отпуск отваливается. Ты выходишь в коридор, готовый говорить про ремонт и про деньги, — и почти наверняка не промахнёшься.
