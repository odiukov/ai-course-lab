Запусти `kdtree_nearest` для точки, которая лежит совсем рядом с границей двух ветвей. Если функция просто спустится по одной стороне дерева, она может пропустить настоящего ближайшего соседа: тот оказался по другую сторону границы.

Собери поиск из рекурсивного помощника. В каждом узле он должен:

1. Посчитать расстояние от запроса до точки узла функцией из [шага 7](#step-7).
2. Добавить кандидата вместе с его исходным индексом.
3. Оставить только `k` лучших кандидатов.
4. Сначала посетить ветвь, в сторону которой указывает координата запроса.
5. После возврата решить, стоит ли проверять вторую ветвь.

Для последнего решения сравни расстояние от запроса до разделяющей плоскости с расстоянием до худшего из уже найденных соседей. Если плоскость ближе, за ней ещё может скрываться лучший кандидат — вторую ветвь нельзя отбрасывать. Пока найдено меньше `k` точек, посещай её безусловно: радиус поиска ещё не определён.

Следи за двумя частыми ошибками. Во-первых, сравнивай координаты по оси текущего узла, а не по глубине вызова, вычисленной заново. Во-вторых, возвращай исходные индексы точек: положение узла в дереве не совпадает с номером строки во входных данных.

Проверь результат на нескольких запросах, сопоставив его с полным перебором `k_nearest` из [шага 21](#step-21). Соседи и расстояния должны совпасть, даже если порядок равноудалённых точек различается. Если дерево отвечает иначе, чаще всего поиск слишком рано отказался от второй ветви.

> 🎒 **На пальцах.** Представь архив с папками, разделёнными перегородками по году, цене и размеру. Ты сначала идёшь в самый подходящий отсек и собираешь `k` похожих папок. Но перед уходом измеряешь, насколько близка соседняя перегородка. Если она ближе самой неудачной папки в твоей стопке, соседний отсек ещё может улучшить результат — туда стоит заглянуть.
