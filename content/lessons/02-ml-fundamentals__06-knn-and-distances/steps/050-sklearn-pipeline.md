Ты вручную стандартизируешь `X_train`, затем берёшься за `X_test` — и по привычке заново считаешь для него средние и разбросы. Код работает, но проверка уже устроена неправильно: тренировочные и тестовые объекты оказались измерены разными «линейками». Ещё хуже, если параметры масштаба посчитаны сразу по всем данным: тогда сведения о тестовой части просочились в подготовку модели. Это и есть **утечка данных**.

`Pipeline` в scikit-learn похож на конвейер из последовательных станций: объект сначала проходит масштабирование, затем попадает в готовый KNN.

```python
from sklearn.neighbors import KNeighborsClassifier
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import Pipeline

clf = Pipeline([
    ("scaler", StandardScaler()),
    ("knn", KNeighborsClassifier(
        n_neighbors=5,
        metric="euclidean",
    )),
])

clf.fit(X_train, y_train)
print(f"Accuracy: {clf.score(X_test, y_test):.4f}")
```

Когда ты вызываешь `fit`, `StandardScaler` вычисляет параметры только по `X_train`, как требовалось в [шаге 19](#step-19), преобразует тренировочные признаки и передаёт их KNN. При `score` тестовые объекты преобразуются с **теми же сохранёнными параметрами** — ничего по `X_test` не пересчитывается. После этого KNN ищет соседей уже в сопоставимом масштабе.

Главное здесь не сокращение кода. `Pipeline` связывает подготовку данных и модель в одно целое, поэтому при обучении и проверке порядок действий остаётся одинаковым, а тестовая выборка не подсказывает, как настроить масштаб.

> 🎒 **На пальцах.** Представь багажный терминал с двумя постами. На первом чемоданы измеряют линейкой, настроенной только по учебной партии, на втором находят пять самых похожих. Контрольные чемоданы проходят те же посты и ту же линейку, но не участвуют в её настройке. `Pipeline` не даёт незаметно вынести контрольный багаж на первый пост раньше времени.
