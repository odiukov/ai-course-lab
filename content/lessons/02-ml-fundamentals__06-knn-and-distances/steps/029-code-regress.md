Ты оцениваешь время доставки по трём похожим поездкам: 18, 22 и 26 минут. Соседи уже найдены, но сами расстояния — ещё не прогноз. Нужны целевые значения из `y_train`, связанные с найденными индексами.

Допиши `knn_regress`. Функция должна:

1. получить индексы и расстояния до `k` ближайших примеров с помощью `k_nearest` из [шага 21](#step-21);
2. по индексам взять соответствующие числовые ответы из `y_train`;
3. вернуть их обычное среднее, если `weighted=False`;
4. вернуть взвешенное среднее, если `weighted=True`.

Во взвешенном режиме сначала вычисли вес каждого соседа способом из [шага 25](#step-25). Затем умножь каждый ответ на его вес, сложи результаты и раздели на сумму весов. Не дели просто на `k`: веса обычно разные, поэтому такой результат уже не будет корректным средним.

Главная ловушка — усреднить не те числа. Индексы лишь показывают, где лежат соседи, а расстояния говорят, насколько они близки. Предсказываемая величина хранится в `y_train`. Проверь также случай нулевого расстояния: используй ту же защиту с маленьким `epsilon`, что и при вычислении весов.

Для самопроверки возьми несколько соседей с одинаковыми расстояниями. Обычный и взвешенный режимы должны дать одинаковый прогноз. Затем приблизь одного соседа: взвешенный результат должен сдвинуться к его ответу.

> 🎒 **На пальцах.** Представь диспетчера доставки с журналом прошлых заказов. Номера строк помогают ему найти похожие маршруты, расстояния показывают степень сходства, а время в последнем столбце служит ответом. При обычном прогнозе все найденные маршруты равноправны. При взвешенном ближайший маршрут получает более громкий голос — но диспетчер всё равно усредняет времена, а не номера строк и не расстояния.
