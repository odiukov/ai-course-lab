У тебя уже есть две отдельные функции: `l1_distance` из [шага 9](#step-9) и `l2_distance` из [шага 7](#step-7). Теперь попробуй собрать их поведение в одной функции `minkowski_distance(a, b, p=2)`. Параметр `p` будет переключателем: при `p=1` результат должен совпасть с L1, а при `p=2` — с L2.

Для конечного `p` пройди по парам координат через `zip(a, b)`. Для каждой пары найди абсолютную разность и возведи её в степень `p`. Затем сложи получившиеся значения и возведи сумму в степень `1 / p`. Это прямой перевод формулы из [шага 12](#step-12), поэтому здесь особенно полезно проследить порядок операций: сначала степени отдельных разностей, потом сумма, и только в конце общий корень.

Есть один особый случай: `p == float("inf")`. Возводить числа в бесконечную степень буквально не нужно. Для расстояния Чебышёва функция должна вернуть самую большую абсолютную разность среди координат. Поэтому эту проверку поставь до основного вычисления и сразу верни результат.

Проверь себя на `a = [1, 2]` и `b = [4, 6]`: при `p=1` должно получиться `7`, при `p=2` — `5`, а при бесконечном `p` — `4`. Если результаты совпали с уже написанными функциями, переключатель работает правильно.

> 🎒 **На пальцах.** Представь пульт с режимами обработки фотографии. В режиме `p=1` он учитывает каждое отличие яркости, в режиме `p=2` сильнее подчёркивает крупные отличия, а при `p=inf` оставляет только самое заметное. Корпус пульта один — меняется лишь положение переключателя. Так и `minkowski_distance`: общий ход вычисления остаётся тем же, а `p` задаёт, какие различия выйдут на первый план.
