Ты сохранил манифест из [шага 3](#step-3), закрыл программу, а позже прочитал файл. На экране данные выглядят знакомо: `world_size`, `step`, список `shards`. Но для новой программы это уже не прежние объекты из памяти. JSON вернул только универсальные строительные блоки: числа, строки, списки и обычные словари.

Здесь легко попасть в ловушку. Словарь шарда содержит правильные ключи — `rank`, `path`, `sha256` и смещение, — однако сам по себе он ещё не `ShardEntry`. У него нет обещанной структуры типизированной записи. Если пропустить эту границу, дальше код будет работать то со словарями, то с `ShardEntry`, а ошибки проявятся далеко от чтения файла.

Есть и менее заметная проблема: значение, которое по смыслу является числом, может прийти как строка — например, `"1234"` вместо `1234`. Для человека они почти одинаковы, но сравнение, сложение и проверка диапазона дадут разные результаты. Поэтому после чтения манифест проходит нормализацию: числовые поля принимают ожидаемый числовой вид, а каждый словарь из `shards` превращается в отдельный `ShardEntry`.

JSON остаётся долговечным форматом хранения, а внутри программы снова действует строгий контракт. Граница между ними — не формальность, а место, где неоднозначные данные получают точный смысл.

> 🎒 **На пальцах.** Представь паспортный контроль. За границей имя, дата рождения и номер документа могли быть записаны по местным правилам. Сотрудник не пропускает анкету дальше как случайный лист бумаги: он приводит поля к принятому формату и выдаёт стандартную карточку пассажира. JSON — такая внешняя анкета, а `ShardEntry` — карточка, которой уже доверяют внутренние службы.
