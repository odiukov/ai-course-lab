Ты получил два решения одной задачи. Оба выглядят убедительно, но одно правильно удваивает только положительные числа, а на нуле и отрицательных значениях ошибается. По тексту программы победителя выбирать нельзя: функцию нужно прогнать на нескольких заранее подготовленных парах «вход — ожидаемый выход».

В этом шаге дополни `metric_code_exec`. Как и в [шаге 8](#step-8), оценивается поведение кода, но теперь важен точный контракт. Пары лежат в `extras` под ключом `io_pairs`. Если там нет непустого списка, результат сразу равен `0.0`. Пара должна быть списком ровно из двух элементов: первый передаётся функции, второй сравнивается с её результатом.

Сначала исполни `prediction` в маленьком изолированном пространстве с ограниченным набором безопасных встроенных функций. Любая ошибка при исполнении означает `0.0`. Затем найди функцию с именем `f`: отсутствие такой функции или объект, который нельзя вызвать, тоже не заслуживают балла.

Для каждой корректно устроенной пары вызови `f` с её входом. Совпадение результата с ожидаемым значением приносит один зачёт; ошибка внутри отдельного вызова — нет. Неверно оформленную пару пропусти, но помни: итог делится на общее количество переданных пар. Поэтому две успешные проверки из четырёх дают `0.5`, даже если остальные элементы оказались испорчены. Аргумент `targets` здесь не определяет ответы: источником истины служат именно `io_pairs`.

В итоге красивый код ничего не гарантирует: балл показывает долю примеров, на которых функция действительно сработала.

> 🎒 **На пальцах.** Представь мастера у автомата с напитками. В журнале записано: нажать «1» — получить воду, нажать «2» — сок. Мастер проверяет каждую запись и ставит галочку только за верную выдачу. Если кнопка заклинила, галочки нет; если запись порвана, её нельзя проверить, но место в журнале она всё равно занимает. Итог — доля галочек во всём журнале.
