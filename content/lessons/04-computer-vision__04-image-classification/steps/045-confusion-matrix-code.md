У тебя есть истинные метки `[0, 2, 2, 1]` и предсказания `[0, 1, 2, 1]`. Общая accuracy из [шага 43](#step-43) сообщит лишь, что верны три ответа из четырёх. Теперь нужно собрать confusion matrix из [шага 44](#step-44), не потеряв единственную ошибку: объект класса `2` был принят за класс `1`.

Напиши функцию `confusion_matrix`, которая принимает истинные метки, предсказания и число классов `C`, а возвращает целочисленный тензор формы `C × C`. Сначала он заполнен нулями. Затем для каждой пары меток увеличивается ровно одна ячейка: с индексами `[истинный_класс, предсказанный_класс]`.

Главная ловушка — не присваивать ячейке `1`, а прибавлять `1`. Одна и та же пара классов может встретиться сотни раз, и матрица должна накопить все такие случаи. Также проверь, что функция не меняет входные тензоры и сохраняет устройство вычислений: если метки находятся на GPU, результат не должен неожиданно оказаться на CPU.

Для примера выше ожидается матрица формы `3 × 3`, а сумма всех её элементов должна равняться `4` — числу проверенных объектов. Это полезная быстрая проверка: если сумма меньше, какие-то пары потерялись; если больше, ты посчитал объект несколько раз.

> 🎒 **На пальцах.** Представь сортировщика писем с таблицей на планшете. На конверте указан настоящий район, а автомат предлагает район доставки. Для каждого письма сортировщик находит клетку на пересечении этих двух номеров и добавляет одну отметку. Он не стирает предыдущие отметки: именно их накопление показывает, сколько раз повторился каждый исход.
