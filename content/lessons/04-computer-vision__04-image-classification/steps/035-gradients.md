Ты обрабатываешь первый батч из 32 изображений — loss выглядит нормально. На втором он внезапно скачет, хотя данные похожи. Причина может быть не в модели: достаточно очищать градиенты только в начале эпохи, и каждый новый батч начнёт тащить за собой поправки от предыдущих.

Градиенты — это числа, показывающие, в какую сторону нужно изменить каждый вес, чтобы уменьшить текущий loss. В PyTorch `loss.backward()` вычисляет их и **добавляет** в поля `.grad`, а не заменяет прежние значения. Поэтому для каждого батча нужна одна и та же тройка действий:

```python
optimizer.zero_grad()
loss.backward()
optimizer.step()
```

`zero_grad()` удаляет оставшиеся поправки. Затем `backward()` ровно один раз вычисляет поправки по текущему батчу, используя граф прямого прохода из [шага 34](#step-34). Наконец, `step()` ровно один раз применяет их к весам.

Порядок здесь не косметический. Если вызвать `zero_grad()` между `backward()` и `step()`, полезный сигнал исчезнет. Два вызова `backward()` сложат градиенты дважды. Два вызова `step()` применят одну и ту же рассчитанную поправку повторно, хотя модель ещё не увидела новый батч.

Значит, один батч должен оставить после себя ровно одно изменение весов — ни накопленного хвоста, ни повторного толчка.

> 🎒 **На пальцах.** Представь редактора у доски. Перед новой страницей он стирает старые пометки — это `zero_grad()`. Затем один раз отмечает ошибки текущей страницы — `backward()`. После этого один раз вносит исправления в рукопись — `step()`. Если не стереть доску, замечания смешаются; если исправить рукопись дважды по одним пометкам, правка окажется чрезмерной.
