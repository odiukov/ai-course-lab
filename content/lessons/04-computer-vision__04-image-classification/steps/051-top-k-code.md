Ты проверяешь батч из четырёх изображений. Для первого правильный класс оказался вторым по величине логитом, для остальных — первым, третьим и шестым. При `k=3` функция должна засчитать первые три изображения, а четвёртое — нет. Результат: `0.75`.

На вход `top_k_accuracy` получает логиты формы «размер батча × число классов», целевые номера классов и `k`. Превращать логиты в вероятности не нужно: softmax сохраняет их порядок, поэтому достаточно сырых оценок из [шага 6](#step-6).

Сначала найди для каждого изображения индексы `k` самых больших логитов. Получится таблица формы «размер батча × k». Но целевая метка каждого изображения — одно число. Чтобы сравнение сработало построчно, подготовь метки так, чтобы каждый правильный номер сопоставлялся со всеми `k` кандидатами своей строки. Затем проверь: встретился ли он хотя бы один раз? Усреднение таких ответов `True` и `False` даст долю попаданий.

Следи за тремя контрактами: `k` не превышает число классов, метки содержат целочисленные индексы, а поиск лучших классов идёт по измерению классов, не по батчу. При `k=1` результат должен совпасть с обычной accuracy из [шага 38](#step-38). А пример из [шага 50](#step-50) поможет проверить случай, где top-1 ошибается, но top-k засчитывает ответ.

> 🎒 **На пальцах.** Ты ищешь свой поезд на большом табло вокзала. Если смотришь только на первую строку, это top-1. Если проверяешь первые пять строк, это top-5. Для каждого пассажира функция составляет свой короткий список, ищет там нужный поезд, а затем считает, какая доля пассажиров нашла его в списке.
