Представь батч из двух изображений. Для первого цель распределена между классами как `0.8, 0.2, 0.0`, для второго — как `0.1, 0.6, 0.3`. Обычная `cross_entropy` из [шага 10](#step-10) ждёт номер правильного класса, но здесь одного номера уже недостаточно: вклад должны внести все классы.

Допиши функцию:

```python
def soft_cross_entropy(logits, soft_targets):
    # твой код
```

Оба аргумента имеют одинаковую форму: `[размер батча, число классов]`. `logits` содержит сырые оценки модели, а каждая строка `soft_targets` — целевое распределение, сумма которого равна единице.

Сначала получи логарифмы предсказанных вероятностей по последней оси. Используй `torch.log_softmax`, а не отдельные `softmax` и `log`: объединённая операция устойчивее на очень больших и очень маленьких логитах.

Дальше примени cross-entropy с мягкой меткой из [шага 14](#step-14). Для каждого изображения умножь логарифмы вероятностей на соответствующие веса из `soft_targets`, сложи результаты по классам и поменяй знак. Получится по одному значению loss на изображение. Только после этого усредни их по батчу, чтобы функция вернула одно число.

Особенно следи за порядком осей: суммировать нужно классы через `dim=-1`, а усреднять — уже получившиеся потери примеров. Если цель окажется one-hot из [шага 13](#step-13), ненулевой вклад даст ровно один класс, и функция поведёт себя как обычная cross-entropy.

> 🎒 **На пальцах.** Представь счёт жюри: у каждого участника несколько оценок с разными весами. Сначала ты умножаешь каждую оценку на её вес и складываешь — это личный итог участника. Затем усредняешь итоги всех участников. Если усреднить всю таблицу сразу, граница между участниками исчезнет и получится уже не тот результат.
