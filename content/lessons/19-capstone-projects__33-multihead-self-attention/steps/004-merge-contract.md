После внимания у тебя лежат контекстные векторы формы `(B, H, T, d_head)`. Возьмём один объект, две головы, три токена и по два признака. Для первого токена голова 0 выдала `[a₀, a₁]`, а голова 1 — `[b₀, b₁]`. В итоговом векторе этого токена ты ожидаешь увидеть `[a₀, a₁, b₀, b₁]`.

Но сейчас рядом сгруппированы не токены, а головы: сначала идут все три токена головы 0, затем все три токена головы 1. Если сразу превратить последние измерения в `(T, D)`, граница новой строки может пройти между разными токенами. Чисел останется столько же, форма даже будет выглядеть правильной — а смысл позиций окажется испорчен.

Поэтому сначала оси возвращают в порядок `(B, T, H, d_head)`. Теперь для каждого токена рядом лежат головы 0, 1 и далее. Внутри каждой головы признаки сохраняют тот же порядок, который получили при разрезании на [шаге 3](#step-3). Лишь после такой перестановки пару `(H, d_head)` можно рассматривать как одно измерение `D`.

Здесь важен двойной контракт: токен с индексом `t` остаётся токеном `t`, а участок каждой головы занимает своё фиксированное место внутри его вектора. Правильная форма без правильного порядка — всё ещё неправильный тензор.

> 🎒 **На пальцах.** Представь монтажный стол с двумя звуковыми дорожками и тремя моментами времени. Записи лежат дорожками: вся первая, затем вся вторая. Для готового ролика тебе нужны кадры времени: в каждом сначала звук первой дорожки, затем второй. Если просто нарезать исходную ленту равными кусками, моменты перемешаются. Сначала ты перекладываешь записи по времени — и только потом склеиваешь дорожки каждого кадра.
