В журнале действий ты видишь последовательность: `inspect`, `edit`, `run_tests`, `edit`, `run_tests`. Отдельно каждое действие выглядит разумно. Но два повторных запуска могут означать, что агент не сохранил результат или не получил обратную связь — именно этот сигнал мы разбирали в [шаге 13](#step-13).

Напиши функцию `repeated_steps`. Она получает последовательность записей журнала и возвращает названия шагов, которые встретились больше одного раза. Для примера выше результат должен содержать `edit` и `run_tests`.

Проследи за тремя деталями:

- каждый повторяющийся шаг попадает в результат только один раз, даже если выполнен трижды;
- порядок соответствует первому появлению шагов в журнале;
- пустой журнал и журнал без повторов дают пустой результат.

Не считай повтор автоматически доказанной ошибкой. Иногда агент исправляет код после честного результата инструмента — такая обратная связь нужна циклу, как показано в [шаге 12](#step-12). Функция лишь выделяет подозрительные места для последующего разбора.

Сначала заведи учёт уже встреченных названий, затем отдельно собирай те, которые появились снова. Обрати внимание: одного множества повторов недостаточно, если оно не сохраняет нужный порядок. Твоя функция должна отвечать не «агент провалился», а более узко: «вот шаги, к которым он возвращался».

> 🎒 **На пальцах.** Представь багажную ленту в аэропорту. Ты записываешь номера чемоданов по мере их появления. Если один чемодан проехал второй круг, достаточно один раз добавить его номер в список повторов — неважно, сколько ещё кругов он сделает. Список не объясняет причину, но точно показывает, какой багаж застрял в цикле.
