Ты запускаешь обучение и видишь странность: ошибка по данным уменьшается, но веса полиномиальной модели снова разрастаются. Значит, обычного цикла из [`fit_gradient_descent`](#step-20) недостаточно — теперь при каждом обновлении нужно учитывать L2-штраф из [шага 46](#step-46).

Напиши метод `fit_ridge(X, y, epochs, learning_rate, alpha)`. Начни веса и свободный член с нулей. На каждой эпохе получай предсказания для всех объектов и один раз вычисляй ошибки. Эти же ошибки должны использоваться при обновлении каждого веса: так все веса опираются на одно и то же состояние модели.

Для каждого признака найди обычную часть градиента по данным, а затем прибавь регуляризационную часть, зависящую от текущего веса и `alpha`. После этого обнови вес шагом градиентного спуска. Свободный член обновляй только по ошибкам предсказаний, без добавления L2-части.

Отдельно вычисляй MSE, величину штрафа и их сумму `cost`. Это удобно для наблюдения за обучением: MSE показывает качество совпадения с данными, а `cost` — цель, которую действительно уменьшает Ridge. Печатать значения можно раз в несколько эпох, чтобы не перегружать вывод.

Проверь три детали: число весов совпадает с числом признаков, регуляризационная добавка применяется к каждому весу, а метод возвращает обученные параметры. Если убрать добавку к градиенту, получится обычная множественная регрессия; если оставить — крупным весам станет труднее расти бесконтрольно.

> 🎒 **На пальцах.** Представь редактора, который сокращает слишком длинные подписи под фотографиями. Сначала он проверяет, точно ли подпись описывает снимок, а затем отдельно убирает лишнюю многословность. `fit_ridge` делает похожее: ошибка требует точных предсказаний, а L2-добавка не даёт весам раздуваться без необходимости. Оба замечания учитываются при одной правке веса.
