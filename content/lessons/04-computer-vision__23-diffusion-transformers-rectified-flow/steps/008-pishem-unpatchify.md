После `head` у тебя ещё не изображение: тензор имеет форму `[n, 64, 12]`. Если просто вызвать `reshape(n, 3, 16, 16)`, количество чисел совпадёт, но пиксели перемешаются. `reshape` не знает, какие значения относятся к каналам, строкам патча и его положению в сетке.

Твоя задача — написать обратную операцию к `patchify` из [шага 6](#step-6), соблюдая порядок сборки из [шага 7](#step-7):

```python
def _unpatchify(self, x, n):
    p = self.patch_size
    h = w = int(self.num_patches ** 0.5)

    # 1. Раскрой каждый токен в патч:
    #    [n, h, w, p, p, channels]

    # 2. Переставь оси так, чтобы channels стоял сразу после n,
    #    а строки и столбцы сетки чередовались со строками
    #    и столбцами внутри патча.

    # 3. Склей пары пространственных осей:
    #    [n, channels, h * p, w * p]

    return x
```

Для текущих параметров путь форм должен быть таким: `[n, 64, 12]` превращается в `[n, 8, 8, 2, 2, 3]`, а затем — в `[n, 3, 16, 16]`.

Особенно внимательно выбери порядок осей перед последним `reshape`. Сначала должны идти пакет и канал, затем строка патча рядом со строкой внутри него, а столбец патча — рядом со столбцом внутри него. Тогда соседние числа действительно станут соседними пикселями, а не просто займут подходящий по размеру контейнер.

> 🎒 **На пальцах.** Представь типографию: из станка выходят 64 пачки по 12 цветовых значений. Ты раскладываешь пачки на столе сеткой 8×8, внутри каждой отделяешь квадрат 2×2 и три краски. Если сначала собрать все краски, затем строки больших и маленьких квадратов, лист получится цельным. Если лишь высыпать числа в рамку 16×16, цвета и фрагменты окажутся не на своих местах.
