Тебе передают результаты двух задач. В первой выполнены две вехи из трёх, во второй — одна из двух:

```text
[
  [true, true, false],
  [true, false]
]
```

Функция `milestone_score` должна вернуть среднее достижение вех по задачам. Сначала найди долю выполненных вех внутри каждой задачи: здесь это `2 / 3` и `1 / 2`. Затем усредни эти две доли. Получится примерно `0.583`, то есть `58.3%`.

Почему нельзя просто посчитать все `true` сразу? Тогда вышло бы `3 / 5 = 0.6`, а задача с более длинным списком получила бы больший вес. KPI из [шага 6](#step-6) устроен иначе: каждая задача влияет на итог одинаково, даже если число вех различается.

При реализации следи за двумя уровнями:

1. Для каждого внутреннего списка посчитай долю значений `true`.
2. Сложи полученные доли и раздели на число задач.

Отдельно обработай пустой набор задач: разумный результат для него — `0`, а не деление на ноль. Можно считать, что каждая переданная задача содержит хотя бы одну веху.

Главная ловушка здесь не в подсчёте `true`, а в порядке усреднения: сначала внутри задачи, потом между задачами.

> 🎒 **На пальцах.** Ты проверяешь ремонт в двух комнатах: в большой выполнено 8 пунктов из 10, в маленькой — 1 из 2. Если считать все пункты одной кучей, большая комната почти определит итог. Но тебе важно состояние каждой комнаты, поэтому ты сначала ставишь им оценки 80% и 50%, а затем усредняешь: получается 65%.
