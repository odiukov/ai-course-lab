Ты запускаешь команду агентов и одну LLM на одинаковых заданиях. Команда набирает `0.72`, одиночная модель — `0.61`. Прибавка равна `0.11`: именно это должна вернуть `coordination_gain`.

Функция получает два числа: результат команды и результат одиночной модели. Используй разность из [шага 15](#step-15), сохраняя её знак. Это важно: если команда набрала `0.58`, а одна LLM — `0.64`, правильный результат равен `-0.06`. Отрицательное значение не ошибка — оно показывает, что координация помешала. Поэтому не применяй модуль и не заменяй отрицательный ответ нулём.

Проследи ещё за двумя деталями. Оба результата должны относиться к одному набору задач и одной метрике: нельзя вычитать точность одиночной модели из командного KPI по вехам. И не умножай результат на `100`, если функция работает с долями. Разность `0.11` соответствует 11 процентным пунктам, но возвращаемое значение остаётся `0.11`.

Для самопроверки возьми три случая: команда лучше, результаты равны и одиночная модель лучше. Ты должен получить соответственно положительное число, ноль и отрицательное число. Знак здесь и есть часть ответа.

> 🎒 **На пальцах.** Представь двух участников одного квеста: сначала человек проходит комнаты один и получает 61 балл, затем команда — 72. Ты записываешь не второй результат сам по себе, а дополнительные 11 баллов. Если команда начнёт спорить и наберёт 58, запись станет отрицательной: совместная работа отняла результат, а не добавила его.
