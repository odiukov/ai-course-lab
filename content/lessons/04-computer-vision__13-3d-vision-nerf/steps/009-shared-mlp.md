Ты подаёшь облако из 1024 точек и ожидаешь, что сеть обработает каждую отдельно. Но обычный полносвязный слой легко смешает координаты разных точек — получится зависимость от их количества и расположения в тензоре.

Напиши функцию `shared_mlp`, которая собирает одинаковую цепочку преобразований для всех точек. На вход ей приходит список размеров каналов, например `3 → 64 → 64`. Для каждой соседней пары добавь три операции: `Conv1d` с ядром размера `1`, затем `BatchNorm1d`, затем `ReLU`.

Почему именно `Conv1d`, хотя облако точек — не линия? Здесь свёртка с ядром `1` не заглядывает в соседние точки. Она берёт признаки одной точки, преобразует их и переходит к следующей с теми же весами. Это и есть общий MLP из [шага 8](#step-8), только записанный удобными средствами PyTorch.

Следи за формой тензора: `Conv1d` ожидает `(batch, channels, points)`. Поэтому вход `(4, 3, 1024)` после цепочки `3 → 64 → 64` должен стать `(4, 64, 1024)`. Число точек остаётся прежним — меняется лишь описание каждой точки.

Проверь ещё два места: у всех свёрток ядро действительно равно `1`, а нормализация получает число выходных каналов соответствующей свёртки. Функция должна возвращать собранный модуль, но сама данные пока не обрабатывает.

> 🎒 **На пальцах.** Представь фотобудку с одной настройкой ретуши. В неё по очереди входят 1024 человека, и к каждому применяется один и тот же набор действий: поправить свет, выровнять цвет, убрать отрицательные значения. Люди не смешиваются и не исчезают — меняется только набор признаков, описывающих каждого. `shared_mlp` собирает именно такую общую фотобудку.
