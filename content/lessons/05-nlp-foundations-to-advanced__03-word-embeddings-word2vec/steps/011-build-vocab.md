Возьми два уже разбитых на слова документа:

```python
docs = [
    ["кот", "спит"],
    ["кот", "ест"],
]
```

Если выдавать новый номер при каждой встрече, слово `"кот"` получит сразу два индекса. Тогда одна и та же кнопка из [шага 10](#step-10) будет вести к разным строкам embeddings. Нужен единый список уникальных слов для всего корпуса.

Напиши `build_vocab(docs)`. Функция должна пройти по всем документам, собрать каждое слово ровно один раз и назначить словам последовательные индексы от `0` до `V - 1`, где `V` — размер словаря. Повторения не создают новых записей.

Верни два отображения:

- `word2idx`: по слову находит его индекс;
- `idx2word`: по индексу восстанавливает слово.

Для примера выше допустим такой результат:

```python
word2idx = {"ест": 0, "кот": 1, "спит": 2}
idx2word = {0: "ест", 1: "кот", 2: "спит"}
```

Чтобы результат не зависел от порядка обхода, сначала упорядочь уникальные слова, а уже затем нумеруй их. Проверь три свойства: количество записей равно числу уникальных слов, индексы идут без пропусков, а обратное отображение возвращает исходное слово:

```python
idx2word[word2idx["кот"]] == "кот"
```

Не меняй регистр и не удаляй знаки препинания внутри `build_vocab`: на вход уже приходят готовые токены. Здесь задача только в стабильной нумерации.

> 🎒 **На пальцах.** Представь фестиваль, где каждому музыканту печатают именной пропуск с номером. Если «кот» трижды появляется в программе, ему не нужны три пропуска: все выступления относятся к одному участнику. Список сначала очищают от повторов, упорядочивают и лишь потом нумеруют. По имени можно найти номер пропуска, а по номеру — имя владельца.
