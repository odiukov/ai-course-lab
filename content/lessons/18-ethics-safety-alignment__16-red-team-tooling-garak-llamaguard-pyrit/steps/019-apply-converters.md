У тебя есть два исходных промпта. Первый конвертер создаёт по три перефразировки, второй — по две кодировки. После всей цепочки должно получиться 12 вариантов. Но если каждый конвертер запускать только на исходных промптах, варианты не перемножатся: второй этап не увидит результаты первого.

Напиши `apply_converter_chain`, которая принимает исходные промпты и упорядоченный список конвертеров. Начни с текущего набора вариантов, равного исходным промптам. Затем для каждого конвертера обработай **каждый** текущий вариант, собери полученные результаты в один плоский список и передай именно его следующему конвертеру. Это практическая реализация композиции из [шага 18](#step-18).

Следи за тремя краевыми случаями:

- пустая цепочка должна вернуть исходные промпты без преобразований;
- если конвертер не создал вариантов для одной ветки, исчезает только эта ветка;
- строку нельзя случайно развернуть посимвольно при объединении результатов.

Не изменяй входной список на месте: промежуточный набор лучше создавать заново на каждом этапе. Порядок тоже важен — кодирование перефразированного текста и перефразирование кодировки дают разные результаты. Поэтому конвертеры применяются слева направо, строго в переданной последовательности.

Главная проверка проста: каждый новый этап работает не с началом цепочки, а со всем результатом предыдущего.

> 🎒 **На пальцах.** Представь типографию открыток. Один макет печатают на трёх видах бумаги, а затем каждый отпечаток покрывают двумя видами лака. Получается шесть открыток. Если лакировщик возьмёт исходный цифровой макет вместо отпечатков, цепочка развалится: лак не применится к трём бумажным вариантам. В `apply_converter_chain` следующий конвертер всегда получает всю стопку, созданную предыдущим.
