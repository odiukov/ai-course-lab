Ты запускаешь две пробы против одной модели. Первая получает отказ, вторая добивается опасного ответа, но детектор его пропускает. Если сохранить только число срабатываний детектора, отчёт покажет один и тот же результат для двух совершенно разных ситуаций.

Дополни `run_garak_harness`, используя параметры и заготовленные компоненты упражнения. Функция должна последовательно провести каждый пример через всю связку из [шага 12](#step-12):

1. Получить атакующий промпт от пробы.
2. Передать этот промпт целевой модели.
3. Отправить **ответ модели**, а не исходный промпт, независимому детектору.
4. Сохранить отдельную запись о попытке.
5. Вернуть все записи после завершения кампании.

В каждой записи удерживай происхождение результата: какая проба запускалась, какой промпт она создала, что ответила модель и какую оценку дал детектор. Не прекращай кампанию после первого обнаруженного нарушения — harness нужен именно для повторяемого прогона всего набора.

Особенно внимательно проверь порядок вызовов. Проба создаёт воздействие, модель отвечает, и лишь затем детектор оценивает ответ. Если передать детектору промпт, получится проверка намерения атакующего вместо проверки поведения модели. Не смешивай также «детектор ничего не нашёл» с «атака не удалась»: одинаковая метка ещё не доказывает одинаковую причину.

Хороший результат функции — не один итоговый счётчик, а журнал, по которому можно восстановить судьбу каждой попытки.

> 🎒 **На пальцах.** Представь кондитерский цех: технолог выдаёт каждому пекарю сложное задание, пекарь готовит изделие, а дегустатор проверяет именно готовый торт. Журнал хранит задание, получившийся торт и вердикт дегустатора. Если записать только число забракованных тортов, ты не поймёшь, пекарь справился с заданием или дегустатор пропустил дефект.
