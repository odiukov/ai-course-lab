Ты проверяешь ответ `red red` против эталона `red red red`. Если превратить токены в множества, останется одно слово `red`, и подсчёт сломается: повторения тоже должны учитываться. Поэтому функция `token_f1(prediction, ground_truth)` работает с мультимножествами токенов, как разобрано в [шаге 31](#step-31).

Сначала пропусти обе строки через `normalize_answer` из [шага 28](#step-28), затем разбей результат по пробелам. Для подсчёта повторений удобно использовать `Counter`. Пересечение двух счётчиков оставит для каждого слова минимальное число вхождений: в примере выше общими будут два `red`, а не одно и не три. Сумма значений пересечения даст количество общих токенов.

Дальше вычисли precision относительно длины предсказания и recall относительно длины эталона, а затем их гармоническое среднее. Обрати внимание на пустые ответы: если после нормализации оба списка пусты, верни `1.0`; если пуст только один — `0.0`. Когда общих токенов нет, тоже сразу возвращай `0.0`, чтобы не делить на ноль.

Проверь функцию на полном совпадении, частичном совпадении, повторяющихся словах и двух разных ответах. Главная ловушка здесь — написать пересечение `set` и незаметно потерять повторы.

> 🎒 **На пальцах.** Представь две коробки с цветными бусинами. В первой две красные, во второй три. Составить можно только две совпадающие пары: третьей красной из второй коробки не хватает партнёра. `Counter` сохраняет количество бусин каждого цвета, а пересечение берёт столько пар, сколько реально можно собрать. Множество увидело бы лишь сам цвет и потеряло бы количество.
