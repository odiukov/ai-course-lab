Ты сравниваешь эталон «очень очень холодно» с ответом модели «очень холодно холодно». По правилу Exact Match из [шага 29](#step-29) оценка равна нулю: строки не совпали. Но модель всё-таки угадала два слова из трёх. Как дать ей частичный зачёт и при этом не посчитать одно удачное слово несколько раз?

После нормализации из [шага 27](#step-27) ответы разбиваются на токены. Их рассматривают как **мультимножества**: это словно мешки с карточками, где две карточки «очень» считаются двумя отдельными предметами. Для каждого слова число совпадений ограничено меньшим количеством карточек в двух мешках.

В нашем примере общими будут одно «очень» и одно «холодно» — всего два токена. Второе «очень» из эталона и второе «холодно» из предсказания остаются без пары.

Теперь считаются две доли:

- precision — какая часть токенов предсказания нашла пару в эталоне: $2/3$;
- recall — какая часть токенов эталона нашлась в предсказании: тоже $2/3$.

Их объединяет $F1 = 2PR/(P+R)$, где $P$ — precision, а $R$ — recall. Здесь F1 равен примерно $0{,}67$. Если общих токенов нет, результат равен нулю.

Так один токен нельзя «предъявить» метрике дважды, зато каждый действительно совпавший фрагмент приносит частичный зачёт.

> 🎒 **На пальцах.** Представь два мешка с магнитными буквами. Ты попарно выкладываешь одинаковые слова: одна карточка из ответа модели напротив одной карточки из эталона. Если в первом мешке три «да», а во втором одно, получится только одна пара. Мультимножество помнит повторы, а пересечение считает лишь реально составленные пары.
