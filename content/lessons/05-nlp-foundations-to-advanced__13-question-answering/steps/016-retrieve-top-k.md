Перед тобой четыре пассажa и вопрос про дату выхода iPhone. Сходства получились такими: `0.82`, `0.67`, `0.14`, `0.09`. Если взять первые две строки корпуса, результат случайно окажется удачным — но функция должна выбирать по оценкам, а не по исходному порядку.

Напиши `retrieve_top_k`: она получает вопрос и число `top_k`, а возвращает список из `top_k` наиболее близких пассажей. Сами оценки строятся скалярным произведением нормализованных embeddings, как в [шаге 15](#step-15).

Проследи за четырьмя действиями:

1. Закодируй вопрос через тот же `encoder`, что использовался для корпуса. Передай `[question]`, то есть список из одного вопроса: так результат сохранит форму матрицы.
2. Умножь `corpus_embeddings` на транспонированный embedding вопроса. После `squeeze()` должен остаться одномерный массив: одна оценка на каждый пассаж.
3. Получи индексы в порядке убывания оценок. `np.argsort` по умолчанию ставит меньшие значения первыми, поэтому знак оценок нужно развернуть.
4. Оставь первые `top_k` индексов и по ним собери тексты из `corpus`.

Проверь не только длину результата. На вопрос про первый iPhone выше должны подняться предложения про выпуск и анонс, причём первым — пассаж с большей оценкой. Иначе функция вернула нужное количество строк, но выполнила поиск неверно.

> 🎒 **На пальцах.** Представь стопку фотографий и программу, которая подписала на каждой степень сходства с запросом «красный велосипед». Тебе нужны три лучшие фотографии. Ты не берёшь первые три из стопки: сначала располагаешь номера по убыванию оценки, оставляешь три номера и только затем достаёшь соответствующие снимки. `retrieve_top_k` делает то же самое с пассажами.
