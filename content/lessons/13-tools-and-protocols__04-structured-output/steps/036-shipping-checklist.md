Тебе передают задачу: «Извлекай из резюме имя, опыт и навыки». Можно вернуть одну JSON Schema и считать работу законченной. Но разработчик затем вручную напишет модель Python, немного иначе назовёт поле, забудет ограничение — и система получит две несовместимые версии одного контракта.

Поэтому результат проектировщика — не отдельная схема, а готовый комплект для внедрения. В файле `outputs/skill-structured-output-designer.md` должны появиться:

- JSON Schema 2020-12, приведённая к требованиям strict mode из [шага 10](#step-10);
- модель Pydantic, зеркальная схеме поле в поле, как обсуждалось в [шаге 28](#step-28);
- заготовка типизированных исходов, чтобы отказ модели не смешивался с ошибкой разбора или нарушением схемы из [шага 17](#step-17);
- заготовка повторной попытки, которая использует конкретную ошибку валидации и соблюдает ограничение числа попыток из [шага 23](#step-23).

«Зеркальная» здесь означает не просто похожая. Совпасть должны названия полей, типы, обязательность, допустимость `null`, ограничения и вложенность. Если JSON Schema разрешает значение, а Pydantic его отвергает, контракт уже раздвоился.

Такой файл можно передать разработчику без устных уточнений: нормальный результат проходит один и тот же договор на каждом слое, отказ идёт по отдельной ветке, а исправление не превращается в бесконечное «попробуй ещё раз».

> 🎒 **На пальцах.** Представь партитуру и отдельные партии музыкантов. Если в партитуре у скрипки пауза, а в её партии записана нота, оркестр сыграет ошибку, хотя оба листа выглядят профессионально. Проектировщик отдаёт согласованный комплект: общую партитуру, точные партии, знак остановки и пометку, откуда продолжить после сбоя.
