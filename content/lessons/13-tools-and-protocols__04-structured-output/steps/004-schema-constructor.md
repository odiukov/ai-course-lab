Ты извлекаешь из счёта четыре поля: номер, сумму, статус и комментарий. В описании всё выглядит однозначно: «сумма не бывает отрицательной», «статус — paid, unpaid или void», «комментария может не быть». Но для модели это пока пожелания на человеческом языке. Контракт должен превратить каждое из них в проверяемое правило.

Таким контрактом служит JSON Schema 2020-12. Сначала ты задаёшь форму данных: `object` для всего результата, `properties` для его полей, `array` и `items` для списков. Затем уточняешь ограничения: `enum` закрывает набор статусов, `minimum: 0` запрещает отрицательную сумму, а `minLength`, `maxLength` и `pattern` управляют строками. Правило, оставленное только в текстовом описании, остаётся подсказкой; записанное в схеме становится частью гарантии из [шага 3](#step-3).

Есть необычная деталь strict mode OpenAI: каждое объявленное свойство должно входить в `required`. Как тогда оставить комментарий необязательным? Не разрешать его пропуск, а разрешить честное отсутствие значения: `"type": ["string", "null"]`. Модель всё равно вернёт ключ `comment`, но поставит `null`.

Кроме того, у каждого объекта нужен `additionalProperties: false`, включая объекты внутри массивов и других объектов. Лишние ключи тогда запрещены. Неразрешённых `$ref` тоже остаться не должно — иначе API отклонит сам запрос с ошибкой 400.

Так расплывчатое «извлеки нужное» превращается в точный перечень допустимых результатов.

> 🎒 **На пальцах.** Представь бланк таможенной декларации. Для суммы есть числовая клетка с нижней границей ноль, для статуса — три готовых флажка, для комментария — отдельная клетка, где разрешено написать «нет». Новые графы от руки запрещены. Описание говорит, что хотел составитель; устройство бланка не даёт заполнить его иначе.
