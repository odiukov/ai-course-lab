title: 'Проверка: посчитайте KV cache для 1:3 и для чистого SSM'
source_anchor: '### The memory budget'
check:
  - question: >-
      В модели из 32 слоёв пропорцию одного attention-слоя к семи SSM-слоям
      заменили пропорцией один к трём. Почему KV cache увеличится?
    options:
      - >-
        При прежнем общем числе слоёв attention-слоёв станет больше, а каждый из
        них хранит собственные ключи и значения
      - SSM-слои начнут хранить ключи и значения для каждого токена
      - >-
        Уменьшение числа SSM-слоёв автоматически увеличит размер каждой
        attention-головы
      - KV cache зависит от квадрата доли attention-слоёв
    correct: 0
    explanation: >-
      При пропорции 1:7 среди 32 слоёв было 4 attention-слоя, а при 1:3 их
      становится 8. Остальные множители не меняются, поэтому кеш удваивается:
      примерно с 16 до 32 ГБ.
  - question: >-
      Почему у чистой SSM-модели исчезает KV cache, а память её рекуррентных
      состояний не растёт при удлинении контекста?
    options:
      - >-
        KV cache создают только attention-слои, а SSM хранит по одному состоянию
        фиксированного размера на слой
      - SSM сохраняет ключи и значения только для последнего токена
      - В чистой SSM-модели история полностью удаляется после каждого такта
      - >-
        Длина контекста влияет на состояние SSM, но этот рост компенсируется
        отсутствием attention-голов
    correct: 0
    explanation: >-
      Без attention-слоёв нет ни ключей, ни значений для прошлых токенов. Для 32
      SSM-слоёв состояние занимает 32 × 4096 × 16 × 2 байта, около 4.2 МБ,
      независимо от контекста в 256k или 512k токенов.
---

Здесь проверяется одно умение: взять формулу кеша из [шага 24](#step-24) и подставить в неё другую форму модели, не пересчитывая всё заново. Пропорция поменялась — меняется ровно один множитель.

Спотыкаются обычно на двух местах. Первое: в формулу подставляют все 32 слоя вместо четырёх слоёв attention — тогда получается число чистого трансформера из [шага 31](#step-31), а не Jamba. Второе: к состоянию SSM мысленно дописывают «на 256k токенов», хотя длина в его расчёт ([шаг 26](#step-26)) вообще не входит.

Если у тебя в ответе для чистого SSM появились гигабайты — ты посчитал не то.
