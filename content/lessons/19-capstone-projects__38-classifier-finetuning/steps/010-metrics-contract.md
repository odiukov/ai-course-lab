Ты запускаешь модель на 100 письмах и получаешь для каждого два сырых логита — два произвольных числовых балла: один за «не спам», другой за «спам». Сам по себе логит ещё не ответ. Выбираешь класс с большим баллом, а затем сравниваешь предсказание с правильной меткой.

Каждое письмо попадает ровно в одну из четырёх категорий:

- **TP**: модель сказала «спам», и письмо действительно спам;
- **FP**: модель сказала «спам», но письмо обычное;
- **FN**: модель пропустила настоящий спам;
- **TN**: модель правильно оставила обычное письмо.

Почему недостаточно просто посчитать правильные ответы? Модель может почти всегда говорить «не спам» и выглядеть убедительно, если спама мало. Поэтому F1, упомянутый на [шаге 1](#step-1), собирается из двух разных взглядов на ошибки.

$precision = TP / (TP + FP)$ показывает, какая доля тревог была верной. $recall = TP / (TP + FN)$ показывает, какую долю настоящего спама удалось поймать. Здесь TP, FP и FN — накопленные количества писем. Наконец, $F1 = 2PR / (P + R)$, где $P$ — precision, а $R$ — recall. Гармоническое среднее резко падает, если хотя бы одна сторона слаба: при precision 1,0 и recall 0,1 F1 будет лишь около 0,18.

Теперь одна цифра не маскирует характер ошибки.

> 🎒 **На пальцах.** Представь охранника у входа на концерт. TP — он остановил человека с поддельным билетом, FP — задержал честного зрителя, FN — пропустил подделку, TN — спокойно впустил владельца настоящего билета. Precision отвечает, насколько обоснованны задержания, recall — сколько подделок вообще поймано. F1 не даст назвать охранника отличным, если он силён только в одном из этих двух умений.
