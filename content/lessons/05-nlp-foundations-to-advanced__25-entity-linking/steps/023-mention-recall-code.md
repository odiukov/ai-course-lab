Возьми три эталонных упоминания. Для каждого известен правильный ID: например, строке «Jordan» в конкретном тексте соответствует сущность баскетболиста. Функция `candidates` из [шага 11](#step-11) возвращает короткий список, но сейчас тебя не интересует, кто стоит первым. Нужно проверить только одно: присутствует ли правильный ID где-нибудь в этом списке.

В `mention_recall` пройди по всем эталонным примерам. Для каждого вызови генератор кандидатов с тем же `K`, найди среди результатов правильную сущность и засчитай попадание. Затем раздели число попаданий на общее число примеров. Если из четырёх правильный ID нашёлся для трёх, функция должна вернуть `0.75`.

Смотри именно на ID, а не на имя, алиас или позицию кандидата. Два разных объекта могут называться одинаково, а кандидат на последнем месте всё равно считается найденным. Здесь также не нужно запускать `disambiguate`: [шаг 22](#step-22) отделил качество генерации от качества окончательного выбора.

Обработай и пустой набор примеров: верни `0.0`, чтобы не делить на ноль. В итоге функция отвечает на узкий вопрос: какую долю правильных сущностей следующий этап вообще получил на рассмотрение?

> 🎒 **На пальцах.** Представь диспетчера аэропорта, который передал грузчикам четыре тележки с чемоданами. Ты пока не проверяешь, какой чемодан они возьмут первым. Ты лишь сверяешь бирки: нужный чемодан оказался на трёх тележках из четырёх. Значит, полнота доставки — 75%; четвёртый чемодан грузчики уже не выберут при любой внимательности.
