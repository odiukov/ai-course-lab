      У тебя нет обучающей выборки, систему нужно запустить быстро, а частоты
      сущностей и простой контекст уже доступны. Какой подход разумно

    options:
      - Prior в сочетании с контекстной совместимостью
      - Обучаемое сравнение embeddings
      - Неограниченную генерацию названия сущности
    correct: 0
    explanation: >-
      Prior с контекстом работает быстро и не требует обучения: частота задаёт

      подходящего кандидата.
  - question: >-
      Система обязана возвращать только существующий ID из базы знаний. Какой
      подход обеспечивает это самим механизмом формирования ответа?
    options:
      - Prior с увеличенным весом популярности
      - Выбор максимального косинусного сходства embeddings
      - 'Генерация с декодированием, ограниченным допустимыми именами сущностей'
    correct: 2
    explanation: >-
      При ограниченном декодировании следующий токен выбирается только среди
      продолжений допустимых имён из базы знаний. Поэтому сформированный
      результат всегда соответствует разрешённой записи KB, хотя это само по
      себе не гарантирует правильный выбор по контексту.

Перед тобой три инструмента, и выбирать нужно по ограничению задачи. Если важны скорость и отсутствие обучения, начинай с prior и контекста из [шага 18](#step-18). Если смысл контекста сложный и есть описания сущностей, embeddings из [шага 27](#step-27) позволяют сравнивать их содержательно. Если критично не получить несуществующий ID, выбирай ограниченную генерацию из [шага 29](#step-29).

> 🎒 **На пальцах.** Ты подбираешь актёра на роль. Prior зовёт самого известного, embeddings сравнивают сценарий с опытом каждого кандидата, а ограниченная генерация разрешает назвать только человека из утверждённого списка. Лучший способ зависит не от моды, а от того, что для постановки нельзя нарушить.
