title: Generative linking декодирует имя только из белого списка KB

---

Ты просишь модель связать упоминание «Jordan» из текста о нейросетях. Обычная генеративная модель может уверенно ответить: `Michael Jordan (computer scientist)`. Строка выглядит правдоподобно, но такой записи в базе знаний может не существовать. Получается не просто неверный выбор, а битая ссылка.

GENRE решает эту проблему необычно: он генерирует название сущности последовательно, но не может написать произвольную строку. Перед декодированием все допустимые названия из KB складывают в префиксное дерево — каталог продолжений. После каждого сгенерированного фрагмента модель получает только те варианты следующего фрагмента, которые ещё ведут к существующему названию.

Допустим, белый список содержит `Michael Jordan`, `Michael I. Jordan` и `Jordan River`. Начав с `Michael`, модель уже не сможет продолжить строкой, которой нет ни в одном из этих названий. Когда название закончено, его можно однозначно сопоставить с канонической записью KB — той самой целью entity linking из [шага 2](#step-2).

Это ограничение гарантирует **валидность**, но не правильность: модель всё ещё способна выбрать баскетболиста вместо исследователя. Зато она не изобретёт четвёртую сущность. Белый список превращает свободное сочинение ответа в управляемый выбор существующего имени.

> 🎒 **На пальцах.** Представь автомат с набором букв, который печатает названия станций. После каждой буквы кнопки с невозможными продолжениями гаснут: набрав «Лис», ты можешь закончить только названием станции из расписания. Автомат ещё может выбрать не ту станцию с похожим названием, но напечатать несуществующую и отправить тебя по битому адресу он уже не позволит.
