У тебя три кандидата для упоминания «Jordan». Сходство их описаний с контекстом дало оценки 0,06, 0,31 и 0,18. Можно остановиться на первом ненулевом результате — но тогда победит слабое совпадение 0,06, хотя дальше есть гораздо более убедительное 0,31.

Поэтому disambiguation проходит по всему короткому списку из [шага 10](#step-10). Для каждого кандидата он одинаково сравнивает контекст с описанием сущности — например, с помощью коэффициента Жаккара из [шага 14](#step-14) — и запоминает наибольший score. В нашем примере будет выбран второй кандидат с оценкой 0,31.

Важно: score не означает «вероятность правильного ответа 31%». Это число нужно прежде всего для сравнения кандидатов между собой. Победитель — лучший в данном списке, а не гарантированно правильная сущность во всей knowledge base. Если нужного ID среди кандидатов нет, возникает промах, разобранный в [шаге 12](#step-12).

Выбор должен быть детерминированным: одинаковые кандидаты, контекст, описания и их порядок каждый раз дают один результат. Если два score равны, действует заранее установленное правило — например, остаётся кандидат, встретившийся первым. Без такого правила ответ мог бы случайно меняться между запусками.

Значит, disambiguator не ищет «достаточно хороший» вариант. Он устраивает полное сравнение и выбирает одного победителя по неизменным правилам.

> 🎒 **На пальцах.** Представь конкурс трёх пирогов. Судья не вручает приз первому пирогу, получившему больше нуля баллов: он пробует все три, записывает 6, 31 и 18 и выбирает 31. Если два пирога набрали поровну, заранее оговорённое правило — например, меньший номер участника — не даёт победителю зависеть от настроения судьи.
