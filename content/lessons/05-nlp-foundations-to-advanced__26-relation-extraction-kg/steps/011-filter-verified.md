В список пришли три triple. У первого подтверждены оба участника, у второго спан subject верен, а object сдвинут на один символ, у третьего ошибочны оба. Если оставить triple только по удачной проверке subject, второй незаметно пройдёт дальше с неподтверждённым object.

В `filter_verified` тебе нужно применить `verify_span` из [шага 9](#step-9) отдельно к subject и object каждого triple. Сохраняй запись лишь тогда, когда обе проверки вернули `True`. Здесь важно условие «и», а не «или»: triple считается единым фактом, поэтому одного подтверждённого конца недостаточно — это правило из [шага 10](#step-10).

Функция получает исходный `text` и список `triples`, а возвращает новый список только с прошедшими проверку элементами. Не исправляй границы, не ищи похожий фрагмент и не запускай извлечение заново. Если спан неверен, весь triple просто не попадает в результат. Поле relation отдельно не сверяется: в заданном формате у него нет собственного символьного спана.

Проверь себя на трёх случаях: оба спана верны — triple остаётся; неверен только object — удаляется; список пуст — возвращается пустой список. Ещё убедись, что порядок сохранившихся triple не меняется. Так `filter_verified` становится строгим турникетом: дальше проходит только факт, у которого оба участника буквально найдены в исходном тексте.

> 🎒 **На пальцах.** Представь комплект из двух деталей на сборочной линии: корпус и крышка. Контролёр сверяет маркировку на каждой детали с заказом. Совпавший корпус не спасает чужую крышку — весь комплект отправляют в сторону. `filter_verified` действует так же: subject и object проходят контроль вместе, а одного совпадения для допуска недостаточно.
