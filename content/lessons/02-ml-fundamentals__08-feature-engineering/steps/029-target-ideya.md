Допустим, ты предсказываешь, отменят ли заказ, а в данных есть район доставки. После [шага 26](#step-26) ты знаешь проблему: если районов сотни, one-hot создаст сотни столбцов. Но присвоить районам номера тоже нельзя — получится ложный порядок из [шага 27](#step-27).

Посмотри на прошлые заказы. В районе «Центр» было четыре заказа с ответами `1, 1, 0, 1`, где `1` означает отмену. Средний ответ равен `0,75`. В районе «Порт» ответы `0, 0, 1`, поэтому среднее равно примерно `0,33`. Теперь вместо названия района можно подставлять это число:

- «Центр» превращается в `0,75`;
- «Порт» — в `0,33`.

Это и есть **target encoding**: категория заменяется средним значением целевого признака — того ответа, который модель учится предсказывать. Для ответа `0` или `1` среднее показывает долю единиц. Если модель предсказывает числовую сумму покупки, кодом категории станет средняя сумма для неё.

Вместо сотен флажков получается один числовой столбец, причём число несёт полезный исторический сигнал: модель видит не условный номер района, а связь района с отменами.

Есть важная граница: для проверочных и будущих заказов средние берут только из обучающих данных. Иначе в признак незаметно попадёт ответ, который модель должна была предсказать.

> 🎒 **На пальцах.** Представь диспетчера, который заменяет названия районов наклейками с исторической долей отмен. Наклейка `0,75` не означает, что «Центр» больше «Порта» по порядку. Она говорит другое: раньше здесь отменяли примерно три заказа из четырёх. Название превратилось не в номер, а в краткую репутацию категории.
