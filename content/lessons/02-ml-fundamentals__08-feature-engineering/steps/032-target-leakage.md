title: Target encoding может подсмотреть правильный ответ
source_anchor: '### Categorical Features'
---

Ты строишь модель, которая предсказывает опоздание доставки. Для службы «Ветер» есть три заказа: два опоздали, один приехал вовремя. Как в [шаге 29](#step-29), категория превращается в средний ответ — здесь в число 0,67.

Теперь ты откладываешь один из опоздавших заказов для проверки модели. Но среднее 0,67 было посчитано заранее, по всем трём заказам. Значит, правильный ответ отложенного заказа уже повлиял на его признак. Модель получила маленькую подсказку: признак как будто описывает службу доставки, хотя частично он описывает именно тот заказ, который модель должна угадать.

Это и есть **утечка данных**: информация из будущей проверки незаметно попадает в обучение. Оценка модели получается слишком хорошей, а после запуска качество неожиданно падает — у новых заказов правильные ответы ещё неизвестны.

Поэтому сначала разделяют данные. Средние по категориям считают только на обучающей части, а затем без пересчёта применяют к проверочной и тестовой. Для строк внутри обучения используют более строгий приём: значение для каждой строки получают по другим строкам, не включая её собственный ответ. Сглаживание из [шага 31](#step-31) сдерживает редкие категории, но само по себе утечку не устраняет.

> 🎒 **На пальцах.** Представь пробный экзамен, где на парту кладут средний балл ученика, вычисленный уже после проверки всех его работ — включая нынешнюю. По этой подсказке легко предсказать результат, но она появилась благодаря ответу. Честная проверка устроена иначе: подсказку составляют только по прошлым работам, а новую работу оставляют действительно неизвестной.
