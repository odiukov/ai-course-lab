После прогона у тебя лежит список результатов: в одном кейсе есть оценки `exact_match` и `token_f1`, в другом — только `token_f1`. Если просто усреднить все числа вместе, получится бессмысленная смесь разных метрик. Функция `summarize_results` должна сначала разложить оценки по отдельным «корзинам», а уже затем посчитать статистику для каждой корзины.

На вход функция получает `results` из [шага 32](#step-32) и порог `threshold`. Пройди по результатам, затем по словарю `scores` каждого результата и собери для каждой метрики собственный список чисел. Учти: метрика может присутствовать не во всех кейсах, поэтому списки могут иметь разную длину.

Для каждого списка верни отдельный словарь с `mean`, `median`, `std`, `min`, `max`, `pass_rate` и `n`. Смысл этих показателей разобран в [шаге 34](#step-34), а доли прохождения — в [шаге 33](#step-33). Здесь важно аккуратно реализовать расчёт: `pass_rate` — это доля оценок, которые **не меньше** порога, а `n` — число оценок именно этой метрики, не общее число кейсов. Числовые результаты округли до трёх знаков.

Затем напиши `print_summary`, которая читает готовую сводку и печатает по одному компактному блоку на метрику. Проверь, что показываемый порог совпадает с тем, который участвовал в расчёте: иначе отчёт будет выглядеть убедительно, но объяснять другие числа.

> 🎒 **На пальцах.** Представь стол после настольного турнира: на карточках записаны очки за скорость, точность и стратегию, но не на каждой карточке есть все три оценки. Ты сначала складываешь скорость к скорости, а точность к точности. Потом для каждой стопки считаешь свою статистику и указываешь её размер — иначе три оценки легко принять за результат всех участников.
