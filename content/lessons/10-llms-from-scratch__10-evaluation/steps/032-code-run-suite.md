Ты запускаешь два кейса с двумя скорерами и ожидаешь четыре оценки, но легко получить странный результат: модель вызывается повторно для каждого скорера или функция возвращает данные уже после первого кейса. Именно такие ошибки должен исключить `run_suite`.

Используй разделение из [шага 30](#step-30) и единый прогон из [шага 31](#step-31). Функция получает список кейсов, словарь скореров и `model_fn`. Для каждого кейса она должна:

1. Один раз передать `input_text` в `model_fn` и сохранить предсказание.
2. Создать новый пустой словарь оценок именно для этого кейса.
3. Вызвать каждый скорер с двумя аргументами: предсказанием модели и `expected`.
4. Записать оценку под именем скорера.
5. Добавить в общий список словарь с полями `input`, `expected`, `prediction` и `scores`.

После обработки всех кейсов функция возвращает весь список результатов. Проверь отступ `return`: если он оказался внутри внешнего цикла, прогон молча остановится после первого примера.

Для быстрой самопроверки возьми два кейса и два простых скорера. В результате должны появиться два словаря, а в `scores` каждого — по две оценки. Ещё посмотри, сколько раз была вызвана модель: ровно два, а не четыре. Пока ничего не усредняй и не выноси вердикт о качестве — сейчас ты собираешь подробный журнал прогона, из которого позже можно будет считать сводные показатели.

> 🎒 **На пальцах.** Представь стол проверки документов. Для каждого посетителя сотрудник один раз фотографирует паспорт, затем две службы независимо проверяют снимок и записывают свои отметки в одну карточку. Только после этого карточка отправляется в общую папку. `run_suite` делает то же самое: один ответ модели, несколько оценок и отдельная запись для каждого кейса.
