Посмотри на батч из четырёх примеров. Каждый пример занимает строку, а три признака — столбцы. Например, первый столбец хранит активацию «контур», второй — «яркость», третий — «текстура». Значения в соседних столбцах означают разные вещи, даже если стоят в одной строке.

На [шаге 27](#step-27) ты видел: BatchNorm нормализует каждый признак по примерам батча. Значит, он движется **вниз по столбцу**: собирает значения одного признака у всех четырёх примеров и приводит именно их к общей шкале. Затем отдельно делает то же со следующим столбцом. Форма таблицы при этом не меняется — каждое преобразованное число возвращается на своё место.

Легко по ошибке пойти поперёк строки: взять три признака одного примера и нормализовать их вместе. Но тогда «контур» начнёт влиять на шкалу «яркости», а примеры перестанут сравниваться по одному и тому же признаку. Это уже другая операция.

В записи батча формы `B × F` BatchNorm считает статистики вдоль оси `B`, оставляя отдельный результат для каждого из `F` признаков. В свёрточной сети идея та же, только роль признака играет канал: каждый канал нормализуется отдельно, а значения собираются по примерам и пространственным позициям.

Ищи ось, вдоль которой лежат разные примеры одного признака, — именно по ней работает BatchNorm.

> 🎒 **На пальцах.** Представь журнал соревнований: строки — спортсмены, столбцы — бег, прыжок и метание. Чтобы понять результат в беге, ты сравниваешь всех спортсменов по столбцу «бег». Смешивать бег, прыжок и метание одного человека бессмысленно: это разные дисциплины. BatchNorm тоже сравнивает одинаковый признак у разных примеров, а не разные признаки внутри одного примера.
