У тебя есть активации `[2, -4, 6]` и маска `[1, 0, 1]`. Простое умножение даст `[2, 0, 6]`, но при `p = 0.5` общий масштаб станет меньше. Поэтому `apply_dropout` должна соединить две уже подготовленные части: маску из [шага 12](#step-12) и inverted scaling из [шага 13](#step-13).

Функция получает:

- список активаций `x`;
- маску той же длины;
- вероятность отключения `p`;
- признак `training`, показывающий режим работы.

Во время обучения пройди по парам «активация — элемент маски». Если маска содержит `0`, результат в этой позиции тоже должен быть нулём. Если содержит `1`, сохрани активацию, увеличив её в `1 / (1 - p)` раза. Для примера выше результатом будет `[4, 0, 12]`.

Вне обучения верни значения без отключения и без дополнительного масштабирования. Лучше создать новый список, чтобы вызывающий код не получил неожиданно изменённый `x`.

Обрати внимание на три частые ошибки: применять `p` вместо `1 - p`, усиливать даже отключённые значения и повторно генерировать маску внутри функции. Маска уже определяет, кто выключен; задача `apply_dropout` — только правильно её применить. Можно считать, что `0 <= p < 1` и длины списков совпадают.

> 🎒 **На пальцах.** Представь кассу с несколькими товарами и купонами напротив каждого. Купон `0` полностью убирает товар из чека, а купон `1` оставляет его, но корректирует цену с учётом доли убранных товаров. `apply_dropout` не печатает новые купоны — она берёт готовую ленту и аккуратно рассчитывает итоговый чек.
