title: Как большинство превращает мнения в один ответ
source_anchor: '### Society of Minds (Du et al., ICML 2024)'
---

После раундов дебатов три агента отвечают на вопрос: двое выбирают маршрут A, один — маршрут B. Критика уже закончилась, ответы пересмотрены по протоколу из [шага 2](#step-2), но системе всё равно нужно вернуть один результат. Чей именно?

Самый простой способ — голосование большинством. Ты собираешь финальные ответы, считаешь, сколько раз встретился каждый вариант, и выбираешь самый частый. Для конфигурации с тремя агентами из [шага 3](#step-3) голоса `A, A, B` превращаются в один ответ `A`: два голоса перевешивают один.

Это не доказывает, что `A` верен. Большинство лишь превращает несколько мнений в единое решение. Если агенты независимо заметили разные стороны задачи, совпадение двух ответов может быть полезным сигналом. Но если все повторили одну и ту же ошибку, голосование только уверенно закрепит её.

Есть ещё две тонкости. Во-первых, ответы должны быть сопоставимы: `Париж` и `Ответ: Париж` выглядят для человека одинаково, а при буквальном сравнении могут считаться разными вариантами. Во-вторых, нечётное число агентов не гарантирует победителя: при ответах `A, B, C` каждый получает по одному голосу. Поэтому правило ничьей нужно определить заранее — например, выбрать первый из вариантов с максимальным числом голосов.

Голосование не продолжает дебаты: оно ставит точку после них.

> 🎒 **На пальцах.** Ты сверяешь маршрут по трём навигаторам. Два ведут через мост, один — через тоннель, поэтому выбираешь мост. Но если каждый предлагает свою дорогу, «мнение большинства» не возникает. Тогда тебе нужно заранее установленное правило выбора, иначе одинаковые результаты голосования могут каждый раз давать разный итог.
