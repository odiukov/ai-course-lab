Ты сравниваешь два резолвера. Первый получает по трём метрикам 88, 70 и 72 балла, второй — 78, 78 и 78. Если посмотреть только на первый столбец, победитель будто бы найден. Но высокая оценка там может скрывать ошибки другого рода.

MUC из [шага 29](#step-29) смотрит, сколько связей между частями кластеров нужно добавить или удалить. Он хорошо замечает разрывы и ошибочные объединения, но оценивает структуру именно через связи.

B³ меняет точку зрения: для каждого mention он сравнивает его предсказанный кластер с эталонным. Так становятся заметны и лишние «соседи», и потерянные упоминания той же сущности. Итог складывается из качества окружения каждого mention.

CEAF-φ4 рассматривает уже целые кластеры. Сначала она подбирает наилучшее взаимно-однозначное соответствие: один предсказанный кластер сопоставляется только с одним эталонным. Затем оценивается их сходство. Поэтому один расплывчатый кластер не может одновременно получить полный зачёт за несколько разных сущностей.

CoNLL F1 берёт среднее арифметическое F1 этих трёх метрик. В нашем примере первый резолвер получает 76,7, а второй — 78. Среднее не объявляет одну метрику главной: хороший результат должен выдержать три разных способа посмотреть на одни и те же кластеры.

> 🎒 **На пальцах.** Представь конкурс по сборке пазлов с тремя судьями. Первый проверяет, соединены ли нужные куски. Второй осматривает каждый кусок и его соседей. Третий сопоставляет готовые картинки с образцами, причём каждому образцу разрешена только одна работа. Итоговая оценка — среднее трёх голосов: один удачный трюк не перекроет остальные ошибки.
