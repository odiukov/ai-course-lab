После `resolve_pronouns` из [шага 16](#step-16) у тебя есть отдельные связи между mention. Если сразу превратить каждую пару в cluster, одна сущность может оказаться сразу в нескольких группах: связи пересекаются, но сами себя не объединяют.

В `build_clusters` тебе нужно собрать **компоненты связности** — группы mention, между которыми существует цепочка связей. Идею транзитивности мы разобрали в [шаге 17](#step-17); теперь перенеси её в функцию.

Удобно дать каждому mention «представителя». В начале каждый представляет только себя. Затем перебирай связи:

- найди представителя каждого конца связи;
- если представители разные, объедини их группы;
- после обработки всех связей снова найди представителя каждого mention и собери mention с одинаковым представителем вместе.

Обрати внимание на три детали. Связь можно хранить как `mention → antecedent`, но при объединении её направление уже не важно. Mention без связей должен остаться отдельным cluster, а не исчезнуть. Наконец, сохрани исходный порядок mention внутри каждого cluster — так результат легче читать и проверять.

Не пытайся дописывать готовый cluster при встрече каждой пары: позже может появиться связь, которая соединит две уже созданные группы. Сначала закончи все объединения, и только потом формируй результат.

> 🎒 **На пальцах.** Представь столы на фестивале, по одному человеку за каждым. Между знакомыми протягивают шнуры. Если новый шнур соединяет людей из разных компаний, две компании становятся одной — даже если крайние участники лично не знакомы. Когда все шнуры натянуты, ты обходишь столы и записываешь каждую связанную компанию отдельно. Стол без шнуров всё равно образует компанию из одного человека.
