Ты запускаешь резолвер на предложении с двумя именами и местоимением — и пока получаешь только отдельные оценки. Один кандидат лучше согласуется, другой стоит ближе, третий был подлежащим. Теперь эти сигналы нужно собрать в одно решение: к какому предыдущему mention относится местоимение?

Функция `resolve_pronouns` проходит по mention слева направо. Обычные имена и описания она пропускает: искать antecedent нужно только для местоимений. Для каждого такого mention функция берёт не весь текст, а не более `K` предыдущих mention — то самое ограниченное окно из [шага 9](#step-9). Будущие упоминания сюда попасть не могут, даже если человеку связь кажется понятной.

Каждого кандидата ты оцениваешь тремя уже подготовленными сигналами: вызываешь `agreement_score` из [шага 11](#step-11), `recency_score` из [шага 13](#step-13) и учитываешь предпочтение подлежащего. Затем применяешь взвешенный скоринг из [шага 15](#step-15) и запоминаешь кандидата с наибольшим итогом.

Обрати внимание на пограничные случаи. Если перед местоимением нет mention, связь создавать не с чем. Кандидат с несовместимым родом или числом не должен победить только из-за близости. А при равных итоговых оценках правило выбора должно быть стабильным — например, преимущество получает более близкий кандидат. Иначе один и тот же текст может давать разные результаты.

Результат функции — отдельные направленные связи вида «местоимение → выбранный antecedent». На этом этапе достаточно честно выбрать лучшую предыдущую опору для каждого местоимения.

> 🎒 **На пальцах.** Представь редактора, который прикрепляет к местоимению стикер с именем. Перед ним лежат только `K` последних карточек персонажей. Он вычёркивает несовместимые, ставит оставшимся баллы за близость и заметную роль в предложении, а затем клеит стикер победителя. `resolve_pronouns` делает ровно это: один проход, одно сравнение кандидатов и одна ссылка для каждого местоимения.
