На одном запуске swarm ответил за 800 мс, а supervisor-worker — за 1,1 секунды. Хочется сразу назвать swarm победителем, но одна удачная заявка ничего не доказывает: следующая может потребовать больше передач или закончиться ошибкой.

Напиши `compare_patterns`, которая сопоставляет результаты четырёх паттернов на одной и той же нагрузке. Формат профиля уже задан: для каждого паттерна есть значения задержки, стоимости, точности и отлаживаемости из [шага 26](#step-26). Функция должна выбрать лучший паттерн отдельно по каждой метрике:

- для задержки и стоимости лучше меньшее значение;
- для точности и отлаживаемости — большее;
- исходный список профилей менять нельзя.

Не пытайся получить одного «абсолютного чемпиона». Если supervisor-worker лучше отлаживается, swarm быстрее, а debate точнее, это нормальный результат сравнения, а не ошибка функции. Верни структуру, в которой рядом с каждой метрикой указаны название победителя и его значение. Так вызывающий код сможет применить собственные приоритеты: например, сначала отсеять варианты, не проходящие SLA, а затем выбрать самый точный из оставшихся.

Обрати внимание на равные значения. Используй предсказуемое правило: при ничьей побеждает профиль, который встретился раньше. Не сортируй весь список ради одного минимума или максимума — достаточно один раз пройти по профилям и обновлять текущих лидеров только при строгом улучшении.

> 🎒 **На пальцах.** Ты отправляешь один и тот же набор фотографий в четыре печатных салона. Один печатает быстрее, другой расходует меньше бумаги, третий точнее передаёт цвета, а в четвёртом проще выяснить причину брака. Таблица победителей по отдельным критериям честнее, чем медаль «лучший салон»: выбор зависит от того, что тебе важнее именно сейчас.
