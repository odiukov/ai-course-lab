Ты запускаешь `pick_pattern` для трёх специалистов и получаешь `supervisor_worker`. Затем включаешь требование минимальной задержки — а результат не меняется. Каждая ветка по отдельности выглядит разумно, но порядок проверок спрятал более важное ограничение.

Тебе нужно превратить лестницу из [шага 23](#step-23) в функцию выбора. `pick_pattern` должна вернуть название самого простого паттерна, который справляется с переданными условиями:

- для одного исполнителя достаточно `single_agent`;
- для 2–4 специалистов базовый выбор — `supervisor_worker`;
- если критична задержка, выбирай `swarm`;
- если супервизор уже не помещает нужный контекст, выбирай `hierarchical`;
- если точность важнее дополнительных расходов, выбирай `debate`.

Сложность здесь не в пяти возвратах, а в пересечении условий. Например, четыре специалиста подходят супервизору по числу, но требование низкой задержки должно переопределить этот базовый вариант. А один исполнитель не превращается в иерархию только потому, что случайно передан лишний флаг.

Сначала выпиши случаи от самых жёстких ограничений к запасному варианту, затем собери условные ветки. После этого проверь не только по одному примеру на паттерн, но и конфликтующие комбинации: именно они показывают, действительно ли функция выбирает топологию, а не первое совпавшее слово.

> 🎒 **На пальцах.** Ты выбираешь транспорт для поездки. Обычно одного человека везёт велосипед, компанию — автомобиль. Но флаг «нужно пересечь море» важнее числа пассажиров: автомобиль уже не подходит, нужен паром. `pick_pattern` рассуждает так же — сначала замечает ограничение, которое ломает простой вариант, и лишь затем использует вариант по умолчанию.
