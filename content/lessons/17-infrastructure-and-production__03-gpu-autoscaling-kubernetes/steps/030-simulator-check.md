check:
  - question: >-
      На коротком всплеске duty cycle почти не изменился, но очередь быстро
      выросла. Какой вывод верен?
    options:
      - 'Реплик достаточно, поскольку duty cycle важнее очереди'
      - >-
        Запросы поступают быстрее, чем обрабатываются, а duty cycle ещё не
        отразил кратковременную перегрузку
      - Gang scheduling автоматически увеличит число реплик
    correct: 1
    explanation: >-
      Рост очереди прямо показывает накопление необработанных запросов. Duty
      cycle измеряется за интервал и может слабо отреагировать на короткий
      всплеск.
  - question: >-
      Автоскейлер запросил группу новых подов для распределённой задачи. Какую
      роль выполняет gang scheduling?
    options:
      - Определяет необходимое число реплик по глубине очереди
      - Увеличивает вычислительную загрузку каждой GPU
      - >-
        Запускает всю группу целиком либо оставляет её ждать полного набора
        ресурсов
    correct: 2
    explanation: >-
      Gang scheduling не выбирает размер сервиса и не меняет метрики GPU. Оно
      обеспечивает совместное размещение взаимозависимых подов и не допускает
      бесполезного частичного запуска группы.
---

На рваной нагрузке сравнивай не высоту одного показателя, а его смысл. Duty cycle из [шага 16](#step-16) сообщает, как часто GPU была занята, поэтому короткий наплыв может затеряться при усреднении. Очередь из [шага 18](#step-18) сразу показывает, что работа копится. Но она лишь помогает выбрать число реплик. Gang scheduling из [шага 11](#step-11) решает другую задачу: можно ли запустить требуемую группу целиком.
