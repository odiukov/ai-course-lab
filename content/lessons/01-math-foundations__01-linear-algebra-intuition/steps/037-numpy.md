Ты уже считал скалярное произведение и длину вектора руками — по элементам, в цикле. В реальной работе так никто не делает: данные бывают не из трёх чисел, а из тысячи, и цикл на Python будет ползти. NumPy — библиотека, которая берёт весь вектор целиком и считает одной командой, внутри на быстром коде.

Главная вещь тут — **массив** (`np.array`). Это не список Python, а плотная полоска чисел одного типа, которую можно двигать целиком.

```python
import numpy as np

a = np.array([1, 2, 3], dtype=float)
b = np.array([4, 5, 6], dtype=float)

a + b                                    # сложение по элементам
np.dot(a, b)                             # скалярное произведение
np.linalg.norm(a)                        # длина
np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))   # косинус угла
```

Ни одного цикла. `a + b` складывает первый с первым, второй со вторым и так далее — это называется поэлементной операцией.

Отдельно стоит `@` — умножение матрицы на вектор:

```python
W = np.random.randn(2, 3) * 0.1
x = np.array([1.0, 0.5, -0.3])
W @ x            # результат: 3 числа на входе, 2 на выходе
```

Матрица `W` размера 2×3 берёт вектор из 3 чисел и выдаёт вектор из 2. Размеры обязаны стыковаться: внутреннее число столбцов слева должно совпасть с длиной вектора справа, иначе NumPy честно ругнётся.

> 🎒 **На пальцах.** Ручной цикл — это когда ты диктуешь кассиру каждый товар по одному. NumPy — когда ты ставишь всю корзину на ленту, и она проезжает сканер разом. Итог тот же, но время не растёт с числом товаров так больно. И заодно лента не даст сложить корзину на 3 позиции с корзиной на 5 — размеры должны совпадать.
