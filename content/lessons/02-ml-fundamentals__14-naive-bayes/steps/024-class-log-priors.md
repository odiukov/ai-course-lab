В обучающей выборке 8 писем: метки шести равны `normal`, двух — `spam`. Тебе нужно сохранить этот перевес, чтобы модель до чтения слов считала обычное письмо более вероятным. Доли классов мы получили в [шаге 23](#step-23); теперь функция `class_log_priors` должна превратить их в числа, удобные для дальнейших вычислений.

Сначала найди уникальные классы и сохрани их порядок. Это важно: первый вычисленный prior должен относиться к первому классу, второй — ко второму. Позже модель будет сопоставлять результаты именно по этим позициям.

Затем для каждого класса:

1. посчитай, сколько раз его метка встречается в `y`;
2. раздели это количество на общее число примеров;
3. возьми натуральный логарифм полученной доли;
4. запиши результат в массив.

Для выборки из шести `normal` и двух `spam` до логарифма получатся доли `0.75` и `0.25`. После логарифма оба числа станут отрицательными — это нормально: логарифм вероятности от нуля до единицы отрицателен. Более частому классу всё равно соответствует большее значение, то есть число ближе к нулю.

Проверь две вещи: длина результата должна совпадать с числом классов, а порядок значений — с порядком классов. Функция считает только частоты меток; матрица признаков `X` ей для этого не нужна.

> 🎒 **На пальцах.** Представь стойку регистрации с двумя очередями: в первой шесть человек, во второй два. Сотрудник записывает долю каждой очереди, а затем переводит её в логарифмическую шкалу. Записи меняются с `0.75` и `0.25` на отрицательные числа, но длинная очередь всё равно получает большее значение. Шкала изменилась, порядок — нет.
