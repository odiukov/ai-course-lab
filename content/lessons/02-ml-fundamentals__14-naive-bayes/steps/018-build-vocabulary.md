У тебя есть три токенизированных сообщения:

```text
["купи", "курс", "сегодня"]
["курс", "по", "рисованию"]
["купи", "кисти"]
```

Если просто собрать слова подряд, `купи` и `курс` попадут в список дважды. Тогда одному слову достанутся разные колонки, а закреплённое на [шаге 17](#step-17) соответствие сломается.

Функция `build_vocabulary` должна принять коллекцию документов, где каждый документ уже разбит на токены, и вернуть словарь вида «токен → уникальный индекс». Для примера результат может выглядеть так:

```text
{
  "купи": 0,
  "курс": 1,
  "сегодня": 2,
  "по": 3,
  "рисованию": 4,
  "кисти": 5
}
```

Точные номера могут отличаться — важны три свойства:

- каждое уникальное слово встречается в словаре ровно один раз;
- индексы не повторяются;
- индексы идут подряд от `0` до `размер словаря − 1`.

Внутри функции тебе понадобятся пустой словарь и два прохода: внешний — по документам, внутренний — по токенам. Встретив токен, проверь, зарегистрирован ли он. Если нет, назначь ему следующий свободный индекс. Если да, ничего не меняй: первое назначение должно сохраниться.

Обрати внимание на пустые документы и повторения внутри одного сообщения: они не должны создавать лишние записи. А вот очистку текста, смену регистра и удаление знаков препинания здесь выполнять не нужно — функция работает с уже подготовленными токенами.

Проверь результат на маленьком примере вручную: число записей должно совпасть с числом уникальных токенов. Теперь у каждого известного слова есть постоянный адрес.

> 🎒 **На пальцах.** Представь организатора фестиваля, который выдаёт каждому новому участнику бейдж с очередным номером. Если Анна подошла второй раз, новый бейдж ей не нужен — она остаётся участником №0. После обхода списков номера уникальны и идут без пропусков, а повторные появления никого не размножают. `build_vocabulary` делает то же самое со словами.
