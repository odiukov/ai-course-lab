Перед тобой матрица писем: строки — документы, столбцы — слова из словаря. Допустим, в спаме слово «скидка» встретилось 12 раз, но не в двенадцати письмах: возможно, одно письмо повторило его несколько раз. Для Multinomial NB важна именно сумма счётчиков из bag-of-words, который ты написал в [шаге 20](#step-20).

Функция `feature_log_probs` должна собрать отдельное распределение слов для каждого класса. Двигайся по классам в том же порядке, который использует `class_log_priors` из [шага 24](#step-24). Для каждого класса:

1. выбери строки матрицы, принадлежащие этому классу;
2. сложи их по столбцам — получишь общий счётчик каждого слова;
3. прибавь `alpha` к каждому столбцу;
4. раздели каждый сглаженный счётчик на сумму всей сглаженной строки;
5. возьми логарифм результатов.

Вернуть нужно матрицу размера «число классов × размер словаря». Одна строка описывает один класс, а значение в её столбце — логарифм условной вероятности соответствующего слова.

Особенно внимательно следи за направлением суммирования. Если сложить по неправильной оси, ты получишь число слов в каждом документе, а не число употреблений каждого слова в классе. Ещё одна частая ошибка — добавить `alpha` только к встретившимся словам. По правилу из [шага 26](#step-26) авансовый счётчик получает каждый столбец, включая нулевые.

Проверь себя: после возврата из логарифмов через экспоненту каждая строка должна суммироваться примерно в 1. Значит, у каждого класса получилось полноценное распределение по словарю.

> 🎒 **На пальцах.** Представь две банки со смесью специй: одна для спама, другая для обычной почты. Ты отдельно считаешь, сколько в каждой банке соли, перца и паприки, затем досыпаешь по щепотке каждой специи и вычисляешь её долю именно в этой банке. Нельзя делить соль из первой банки на общий вес обеих: тогда классы перестанут быть самостоятельными смесями.
