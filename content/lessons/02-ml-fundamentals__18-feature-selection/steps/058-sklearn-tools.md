Ты собрал отбор в три команды: сначала убрал почти постоянные колонки, затем оставил десять лучших по взаимной информации, а после обучил модель. Но при новом запуске легко перепутать порядок или случайно применить один из этапов ко всем данным. В [шаге 53](#step-53) ты видел, почему это приводит к утечке.

В scikit-learn селекторы можно соединить с моделью в один `Pipeline`:

```python
from sklearn.pipeline import Pipeline
from sklearn.feature_selection import (
    VarianceThreshold,
    SelectKBest,
    mutual_info_classif,
)
from sklearn.linear_model import LogisticRegression

pipeline = Pipeline([
    ("variance", VarianceThreshold(threshold=0.01)),
    ("mi", SelectKBest(mutual_info_classif, k=10)),
    ("model", LogisticRegression(max_iter=1000)),
])

pipeline.fit(X_train, y_train)
predictions = pipeline.predict(X_test)
```

У каждого промежуточного шага одинаковый рабочий интерфейс: `fit` изучает обучающие данные, а `transform` сокращает набор колонок. `Pipeline` сам передаёт результат дальше, как в последовательности из [шага 54](#step-54). Последняя модель получает уже отобранные признаки.

Здесь есть важная деталь: `mutual_info_classif` сама возвращает только оценки признаков. Обёртка `SelectKBest` превращает эти оценки в полноценный селектор с `fit` и `transform`. `RFE` и `SelectFromModel` уже поддерживают такой интерфейс, поэтому их тоже можно поставить перед моделью.

Теперь отбор — не отдельная подготовительная операция, которую легко забыть, а часть самой процедуры обучения и прогноза.

> 🎒 **На пальцах.** Представь папку с заявкой, которая проходит несколько кабинетов. В первом выбрасывают пустые листы, во втором оставляют десять самых содержательных, в третьем принимают решение. Тебе не приходится переносить бумаги вручную и помнить маршрут: папка движется по заранее заданной цепочке. `Pipeline` хранит этот маршрут, а каждый селектор отвечает только за свой кабинет.
