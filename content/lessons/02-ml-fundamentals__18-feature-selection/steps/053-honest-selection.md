title: 'Отбор обучают только на train, чтобы не подсмотреть test'
source_anchor: '## Use It'
---

Ты разделил данные на train и test, а затем по всей таблице выбрал 20 признаков с наибольшей взаимной информацией. Модель обучалась только на train — значит, всё честно?

Нет. При отборе ты уже использовал ответы из test: они повлияли на баллы признаков и на состав двадцатки. Среди сотен шумовых колонок случайно найдутся такие, которые хорошо совпали именно с тестовыми ответами. Модель ещё не видела строки test напрямую, но ты заранее подсказал ей, на какие колонки выгодно смотреть. Это **утечка данных**: информация из будущей проверки незаметно проникла в обучение.

Правильный порядок такой: сначала раздели данные, затем настрой метод отбора только на train. Например, порог дисперсии, баллы mutual information, ранги RFE или коэффициенты L1 вычисляются по обучающей части. Получив список оставшихся колонок, примени без пересчёта ту же маску и к train, и к test.

Даже методы без `y`, например фильтр низкой дисперсии из [шага 8](#step-8), безопаснее настраивать только на train: test должен изображать новые данные, о распределении которых ты заранее ничего не знаешь. При кросс-валидации правило повторяется внутри каждого разбиения: отбор обучается на его train-части, а не один раз на всей таблице.

Иначе test перестаёт быть закрытой проверкой — часть его ответа уже зашита в выбранные признаки.

> 🎒 **На пальцах.** Представь экзамен с тысячей возможных вопросов. Ты заглянул в итоговый вариант, нашёл темы, которые там встретились, и только после этого составил программу подготовки. На самом экзамене ты честно не открываешь ответы, но результат уже завышен: содержание проверки повлияло на обучение. Честный порядок — составить программу по учебным заданиям, а экзаменационный конверт открыть только после подготовки.
