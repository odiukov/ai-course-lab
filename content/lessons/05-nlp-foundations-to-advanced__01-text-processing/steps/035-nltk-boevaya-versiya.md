Твой конвейер из трёх шагов остаётся тем же — меняются только исполнители. Регулярка на пробелах падает на `don't`, `U.S.`, кавычках-ёлочках и дефисах; ручной стеммер обрезает пару окончаний и останавливается. NLTK нужен ровно затем, чтобы эти пограничные случаи были обработаны не тобой, а людьми, которые собирали правила годами.

Боевые версии называются так:

```python
from nltk.tokenize import word_tokenize
from nltk.stem import PorterStemmer, WordNetLemmatizer
from nltk import pos_tag
```

`word_tokenize` знает про сокращения и Unicode. `PorterStemmer` прогоняет все пять фаз алгоритма, а не одну. `WordNetLemmatizer` ищет слово в WordNet — это большой словарь английского, где для каждой формы записана её начальная форма.

И тут первая практическая ловушка: у NLTK код и данные едут отдельно. Сам пакет ставится через `pip`, а словари и модели надо скачать один раз руками:

```python
import nltk
nltk.download("punkt_tab")
nltk.download("wordnet")
nltk.download("averaged_perceptron_tagger_eng")
```

`punkt_tab` — данные для токенизатора, `wordnet` — словарь для лемматизации, `averaged_perceptron_tagger_eng` — модель для `pos_tag`, определителя части речи. Забудешь скачать — получишь `LookupError` при первом же вызове, причём не при импорте, а позже, уже внутри обработки текста.

> 🎒 **На пальцах.** `pip install nltk` привозит тебе пустой шкаф с ящиками и инструкцией, как в них искать. Словари и модели — это папки, которые в ящики надо положить. `nltk.download(...)` их и раскладывает. Шкаф без папок выглядит исправным: импорты проходят, ошибка вылезает в момент, когда ты впервые дёрнул ящик.
