Ты запускаешь первый шаг и видишь правдоподобное изменение параметров. Но есть ловушка: неправильный порядок вычислений тоже выдаёт числа — просто Adam уже работает не так, как задуман.

Твоя `adam_step` должна обработать один набор градиентов. Если состояния `m` и `v` ещё не созданы, подготовь для каждого параметра по нулю. Затем увеличь `t` ровно один раз за вызов — не один раз для каждого параметра.

Для каждого градиента обнови две «памяти»: `m` накапливает направление, а `v` — квадрат градиента и его типичный масштаб. После этого примени `bias_correct` из [шага 30](#step-30) отдельно к `m` с `beta1` и к `v` с `beta2`. Оба исправления используют одно и то же текущее значение `t`.

Особенно внимательно следи за переменными `m_hat` и `v_hat`. Это временные исправленные значения для расчёта шага. Не записывай их обратно в `m` и `v`: следующему обновлению нужны исходные скользящие средние, а не уже исправленные копии.

Последним измени каждый параметр по правилу из [шага 32](#step-32). Проверь порядок: сначала новые моменты, затем bias correction, затем обновление параметра. Если переставить эти действия, функция останется исполняемой, но перестанет быть шагом Adam.

> 🎒 **На пальцах.** Представь метеостанцию с двумя журналами: в одном записывают устойчивое направление ветра, в другом — силу порывов. Перед прогнозом сотрудник поправляет обе оценки, потому что утром записей ещё мало. Но исправленные числа он пишет только в прогноз, а не поверх журналов. Иначе следующий прогноз начнётся уже с однажды скорректированной истории.
