В [шаге 11](#step-11) мини-батч дал тебе не точный градиент всего датасета, а его шумную оценку. Теперь нужно воспроизвести это поведение в функции `noisy_grad`.

Посмотри на её параметры в заготовке. Один задаёт «настоящий» градиент, другой — силу шума. При каждом вызове функция должна брать случайную поправку, масштабировать её указанной силой и добавлять к исходному градиенту. Вернуть нужно получившуюся шумную оценку, не изменяя входное значение.

Проверь три вещи. При нулевой силе шума результат должен совпадать с исходным градиентом. При положительной силе повторные вызовы обычно дают разные числа. При этом поправка не должна всё время тянуть результат только вверх или только вниз: случайные отклонения возникают по обе стороны от исходного значения.

Не пытайся внутри `noisy_grad` обновлять вес или применять learning rate. Это уже задача оптимизатора из [шага 8](#step-8). Здесь функция лишь имитирует градиент, который мог бы получиться на случайном мини-батче.

> 🎒 **На пальцах.** Представь весы, на которых лежит посылка массой ровно 5 кг. Из-за дрожащего стола дисплей показывает то 4,9, то 5,1 кг. `noisy_grad` делает то же самое: берёт исходное значение и добавляет случайное отклонение. Параметр силы шума определяет, насколько сильно «дрожит стол».
