title: Шаги обучения в PyTorch выполняются в строгом порядке

Ты запускаешь цикл обучения, код не падает, но loss ведёт себя странно. Причина может быть не в AdamW и не в данных: те же команды стоят в неверном порядке. Здесь каждая операция готовит данные для следующей.

Сначала `optimizer.zero_grad()` очищает место для новых градиентов. Затем модель делает `forward`: получает входные данные и выдаёт предсказания. По ним вычисляется `loss` — число, показывающее величину ошибки. Вызов `loss.backward()` проходит по выполненным вычислениям назад и записывает градиенты в параметры модели.

Только теперь градиенты существуют, поэтому именно здесь при необходимости вызывают `clip_grad_norm_`. После этого `optimizer.step()` читает готовые градиенты и обновляет параметры. Для AdamW он также обновляет внутренние состояния, которые ты сохранял в [шаге 35](#step-35).

Последним идёт `scheduler.step()`: он меняет learning rate из [шага 45](#step-45) для следующего обновления. Если вызвать scheduler раньше оптимизатора, текущий шаг может получить не тот learning rate, который ты ожидал.

Запомни цепочку: `zero_grad` → `forward` → `loss` → `backward` → необязательный `clip` → `optimizer.step` → необязательный `scheduler.step`. Это не стиль оформления, а порядок зависимостей.

> 🎒 **На пальцах.** Представь пробную выпечку хлеба. Ты очищаешь журнал, замешиваешь тесто, выпекаешь буханку, оцениваешь результат, рассчитываешь поправку и только затем меняешь настройку печи. После этого задаёшь температуру для следующей буханки. Если сначала изменить печь, а потом рассчитывать поправку по старому хлебу, действия формально выполнены, но относятся уже к разным попыткам.
