Ты запускаешь Adam на двух последовательных мини-батчах. Во втором градиент оказался таким же, как в первом, но обновление параметров может отличаться. Ошибка? Нет: Adam учитывает не только текущий градиент, но и накопленную историю.

После каждого обновления должны сохраниться три части состояния: список первых моментов `m`, список вторых моментов `v` и общий номер шага `t`. Для сети из исходного примера параметров 33, значит, в `m` и `v` тоже должно быть по 33 значения — по отдельной паре для каждого параметра. Порядок обязан совпадать с `params` и `grads`, иначе память одного веса начнёт управлять другим.

В начале обучения `m` и `v` заполняются нулями, а `t` равен нулю. Затем на каждом обновлении номер шага увеличивается, `m` и `v` пересчитываются и остаются доступными для следующего вызова. Если создавать их заново внутри каждого обновления, Adam будет постоянно «забывать» прошлое. Более того, поправка из [шага 29](#step-29) каждый раз будет вести себя так, будто обучение только началось.

Поэтому состояние принадлежит всему запуску оптимизатора, а не одному мини-батчу. Параметры меняются — и память Adam движется вместе с ними.

> 🎒 **На пальцах.** Представь бариста, который для каждого из 33 постоянных клиентов ведёт две заметки: привычную крепость напитка и то, насколько сильно заказ обычно меняется. Рядом стоит общий счётчик обслуженных заказов. Если после каждого клиента выбрасывать блокнот и обнулять счётчик, бариста формально продолжит работать, но каждый заказ снова будет для него первым.
