Перед тобой два списка одинаковой длины: в `params` лежат текущие параметры, а в `grads` — соответствующие им градиенты. Здесь легко допустить тихую ошибку: применить один градиент не к тому параметру. Поэтому двигайся по спискам синхронно — элемент с индексом `i` обновляется только градиентом с тем же индексом.

Допиши функцию:

```python
def sgd_step(params, grads, lr):
    # Обнови каждый элемент params
    pass
```

Внутри нужен цикл по индексам параметров. На каждой итерации возьми текущий параметр и его градиент, примени правило из [шага 1](#step-1), а результат запиши обратно в `params[i]`. Как обсуждалось на [шаге 7](#step-7), один и тот же `lr` используется для всех пар.

Обрати внимание именно на запись обратно. Если просто вычислить новое значение во временной переменной, исходный список `params` не изменится — оптимизатор сделает расчёт, но модель останется на месте. Функция должна обновлять переданный список, а не только создавать числа внутри цикла.

Проверь ещё две вещи: цикл должен обработать каждый параметр ровно один раз, а знак обновления должен вести против направления градиента. Историю прошлых шагов хранить не нужно: функция использует только текущие `params`, `grads` и `lr`.

> 🎒 **На пальцах.** Представь ряд горшков и такой же ряд карточек с указаниями, сколько воды убрать или добавить. Ты идёшь слева направо: первая карточка относится только к первому горшку, вторая — ко второму. Недостаточно посчитать нужный объём в уме — воду действительно надо налить. Так и `sgd_step`: сопоставляет элементы по позиции и записывает изменения обратно в параметры.
