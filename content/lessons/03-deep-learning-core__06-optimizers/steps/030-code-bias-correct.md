Ты вызываешь `bias_correct` для текущего момента, получаешь исправленное значение — и хочется сразу записать его обратно в `m` или `v`. Но тогда на следующем шаге скользящее среднее смешается уже не с прежней «сырой» памятью, а с искусственно увеличенным числом. История Adam начнёт искажаться.

Поэтому функция должна только вычислить и вернуть исправленную копию. Сам накопленный момент она не меняет.

Передай ей три значения: текущий момент `value`, коэффициент памяти `beta` и номер шага `t`. Поправку бери из [шага 29](#step-29). В Python степень записывается через `**`, а весь знаменатель нужно заключить в скобки: сначала вычислить степень, затем вычесть её из единицы и только после этого выполнить деление.

Обрати внимание на счётчик: первый вызов соответствует `t = 1`, а не нулю. При `t = 0` знаменатель окажется нулевым. Отдельные версии функции для `m` и `v` не нужны: различие задаёт переданный `beta`.

Твоя функция должна отвечать на один вопрос: «каким было бы это среднее без стартового занижения?» — и не переписывать саму память оптимизатора.

> 🎒 **На пальцах.** Представь счётчик посетителей, который после включения сначала замечает лишь часть входящих людей. Ты хранишь его исходные показания, но для отчёта применяешь поправку на разогрев. Если записать исправленное число обратно в счётчик, следующий отчёт поправит уже поправленные данные. `bias_correct` готовит отчёт, а не вмешивается в показания прибора.
