Ты запускаешь три одинаковые модели и меняешь только learning rate. На экране — три кривые loss. Слева она резко прыгает вверх, по центру уверенно снижается, справа почти лежит на месте. Хотя модели начали из одной точки, через одинаковое число шагов результаты совсем разные.

В левом режиме learning rate слишком большой. Каждое обновление перебрасывает параметры через подходящую область, следующие обновления становятся ещё резче, и обучение расходится. Loss может взорваться, а веса — превратиться в `NaN`: числовое значение, с которым уже нельзя продолжать вычисления.

Справа learning rate слишком маленький. Направление обновлений может быть верным, но за отведённое время модель проходит лишь крошечную часть пути. Loss медленно уменьшается, вычисления тратятся, а результат остаётся посредственным. Это не поломка — просто обучение почти не успевает состояться.

Посередине шаг достаточно велик, чтобы заметно двигаться, но не настолько, чтобы перескакивать через хорошие области. Loss снижается устойчиво, и модель достигает хорошего минимума. Именно поэтому learning rate из [шага 45](#step-45) проверяют первым.

Важно: «подходящее число» зависит от оптимизатора. Для SGD обычный масштаб — `0.01–0.1`, а для Adam и AdamW — примерно `0.0001–0.0003`. Сравнивай не сами числа, а поведение loss.

> 🎒 **На пальцах.** Ты паркуешь машину, ориентируясь по камере. Слишком сильно крутишь руль — мечешься между бордюрами и можешь врезаться. Поворачиваешь едва заметно — парковочное место приближается мучительно медленно. Подходящее движение руля достаточно заметно меняет траекторию, но оставляет тебе возможность исправить следующий манёвр. Так выглядят три режима learning rate.
