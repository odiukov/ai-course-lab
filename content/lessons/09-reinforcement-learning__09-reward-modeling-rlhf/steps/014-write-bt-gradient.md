Ты запускаешь обучение и замечаешь странность: после обновления выбранный ответ получает меньший балл. Скорее всего, перепутаны два похожих действия — вычисление градиента и изменение весов.

В `bt_gradient` не нужно обучать модель напрямую. Функция должна вернуть градиент потери: набор поправок той же формы, что и `w`. Позже обучающий код вычтет эти поправки из весов с учётом скорости обучения.

Сначала получи баллы обоих ответов через `reward_score`, затем преврати их разницу в вероятность с помощью `sigmoid` из [шага 8](#step-8). Чем ближе эта вероятность к единице, тем слабее должна быть поправка: модель уже уверенно ставит выбранный ответ выше.

Дальше для каждого признака сравни его количество в выбранном и отклонённом ответах. Эту разницу умножь на коэффициент ошибки, разобранный в [шаге 13](#step-13), и собери результаты в градиент. Если признак встречается только в одном ответе, считай его количество во втором равным нулю.

Особенно внимательно следи за знаком. `bt_gradient` возвращает направление роста потери, а обучающий шаг затем идёт в противоположную сторону. Поэтому не переноси буквально знаки из прямого обновления весов в исходном примере. И не изменяй `w` внутри функции: иначе один вызов незаметно повлияет на следующий.

> 🎒 **На пальцах.** Представь кладовщика, который составляет ведомость расхождений между двумя коробками. Он только записывает: здесь на две детали больше, там на одну меньше. Сам он ничего не перекладывает. Позже рабочий читает ведомость и двигает детали в обратную сторону, исправляя ошибку. `bt_gradient` составляет такую ведомость, а обновление весов применяет её.
