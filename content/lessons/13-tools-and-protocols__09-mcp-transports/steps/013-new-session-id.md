Сядем писать функцию. Задача с виду на одну строку: вернуть строку, которая станет значением `Mcp-Session-Id` из [шага 11](#step-11). Рука сама тянется к `random` — модуль есть в стандартной библиотеке, `random.getrandbits(128)` выглядит буквально как то, что просили в [шаге 12](#step-12): 128 бит, случайных.

Только «случайных» тут значит не то, что нужно. `random` — генератор для игр, симуляций и перемешивания списков: он раскручивается из внутреннего состояния, и по нескольким выданным числам это состояние восстанавливается. Тому, кто уже видел пару твоих session id, следующий можно не угадывать — его можно вычислить.

Поэтому в стандартной библиотеке лежит отдельный модуль ровно для токенов, паролей и ключей: он берёт байты у операционной системы, у того же источника, откуда их берёт TLS. Найди его и дальше смотри на одну вещь — сколько байт ты просишь. 16 байт = 128 бит, и в шестнадцатеричной записи это 32 символа. Попросишь 16 hex-символов — получишь 64 бита, вдвое меньше требуемого минимума, и функция формально пройдёт твои тесты, а спецификацию — нет.

Контракт простой: аргументов нет, возвращается `str`, длина 32, только символы `0-9a-f`, и два вызова подряд обязаны дать разные строки. Никаких счётчиков, времени и pid внутри — это значение поедет в HTTP-заголовок, где угадываемость и есть вся дыра.

Проверь себя так: вызови функцию пять раз и посмотри на список. Если у строк совпадает начало или видна арифметика — ты взял не тот модуль.

> 🎒 **На пальцах.** Фокусник на сцене «тасует» колоду и предлагает тебе вытянуть карту. Для зала порядок случайный. Для него — известный: он сам его и заложил. Это `random`. А лотерейный барабан крутят при нотариусе именно потому, что предсказать шар не может даже тот, кто его крутит. Session id тянут из барабана, не из рук фокусника.
