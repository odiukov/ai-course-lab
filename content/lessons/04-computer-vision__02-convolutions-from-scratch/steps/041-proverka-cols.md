    options:

      - >-
        Потому что для каждого входного канала создаётся отдельное положение

      - Потому что число каналов определяет шаг перемещения окна

    explanation: >-
      Окно охватывает не только kh × kw пространственных координат, но и все

      которые занимают один столбец cols.
  - question: >-
      Разработчик по ошибке записал развёрнутые окна в строки cols, хотя фильтры
      подготовлены для умножения слева как матрица формы (число фильтров, объём

    options:
      - >-
        Внутренняя ось cols будет обозначать положения окна, а должна обозначать
        элементы одного окна
      - Каждый фильтр начнёт использовать только один входной канал
      - Padding будет применён повторно при матричном умножении
      - Stride автоматически станет равен размеру ядра
    correct: 0
    explanation: >-
      Для произведения матрицы фильтров на cols совпадающая внутренняя
      размерность должна быть объёмом окна c_in × kh × kw. Поэтому элементы окна
      располагают по строкам cols, а разные пространственные положения — по
      столбцам.

Здесь важно связать две идеи: содержимое одного окна из [шага 37](#step-37) задаёт число строк, а количество положений окна — число столбцов. Частая ошибка — поменять эти измерения местами или забыть умножить размер окна на число каналов. Проверяй себя так: один столбец должен целиком вмещать одно окно, развёрнутое функцией из [шага 40](#step-40).

> 🎒 **На пальцах.** Представь шкаф с одинаковыми папками. В каждой папке лежат все карточки из одного окна: их количество определяет высоту папки. Сколько раз окно приложили к изображению, столько папок поставили рядом. Высота одной папки — строки `cols`, число папок — столбцы.
