Ты запускаешь функцию для входа высотой 10, ядра 3, padding 0 и stride 2 — и получаешь `4.5`. Такое число сразу выдаёт ошибку: половины позиции ядра не бывает. Значит, формулу из [шага 9](#step-9) недостаточно просто перенести в программу — нужно сохранить порядок вычислений и правильно отбросить неполный последний шаг.

Дополни функцию `conv_output_size(H, K, P, S)`. Она принимает четыре целых числа и возвращает одно целое: количество положений ядра вдоль выбранного измерения. Для ширины используется та же функция, только с шириной вместо `H`.

Сначала вычисли доступное расстояние с учётом размера ядра и padding. Затем раздели его на stride целочисленно: остаток должен исчезнуть. И лишь после этого прибавь позицию, с которой движение начинается. В Python для такого деления подходит оператор `//`.

Проверь реализацию на нескольких примерах:

```python
assert conv_output_size(10, 3, 0, 2) == 4
assert conv_output_size(7, 3, 1, 1) == 7
assert conv_output_size(12, 4, 0, 3) == 3
```

Особенно внимательно посмотри на первый пример: обычное деление дало бы дробь, а округление до ближайшего целого могло бы ошибочно добавить окно, которое уже не помещается. Здесь требуется именно округление вниз.

> 🎒 **На пальцах.** Представь аппарат, который ставит печати на бумажной ленте. Оператор вводит длину ленты, ширину печати, добавленные поля и расстояние между нажатиями. Аппарат должен сообщить целое число полных отпечатков. Если для следующего осталась только часть места, он не считает её отпечатком — поэтому дробный результат всегда отбрасывается вниз.
