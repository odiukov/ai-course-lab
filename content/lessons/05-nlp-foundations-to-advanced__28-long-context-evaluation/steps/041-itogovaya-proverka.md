    options:
      - Её рабочий контекст равен 128 тысячам токенов для любых задач
      - 'Поиск работает до большей длины, чем рассуждение по связанным фактам'

      - Эти результаты доказывают только эффект lost in the middle

      NIAH подтверждает способность извлекать отдельный факт, но не гарантирует
      прохождение цепочки зависимостей. В этом случае retrieval-effective length
      выше reasoning-effective length.
  - question: >-
      Ты проверяешь помощника, который ведёт длинные диалоги и отвечает по
      нескольким загруженным документам. Какая батарея наиболее уместна?
    options:
      - >-
        MRCR для связей в диалоге, LongBench v2 для разнообразных длинных задач

      - Только одна иголка NIAH в начале контекста
      - Только проверка заявленного размера окна
      - Только измерение времени до первого токена
    correct: 0
    explanation: >-
      MRCR проверяет сохранение связей между упоминаниями в длинном диалоге,
      LongBench v2 покрывает разнообразные задачи, а собственные данные
      показывают пригодность модели для конкретного продукта.
  - question: >-
      При выбранном пороге качества результат остаётся приемлемым на первых двух
      проверенных длинах контекста, но опускается ниже порога на следующей. Как
      определить измеренную effective length?
    options:
      - Взять максимальный размер окна из спецификации модели
      - >-
        Взять последнюю проверенную длину, на которой результат ещё достигал
        порога
      - Взять первую проверенную длину независимо от результата
      - Выбрать длину с минимальным временем до первого токена
    correct: 1
    explanation: >-
      Effective length — максимальная проверенная длина с результатом не ниже
      выбранного порога. В исходном измерении 88 процентов на 32 тысячах ещё
      проходят порог 85 процентов, а 79 процентов на 64 тысячах — уже нет.
  - question: >-

      регрессионный контракт?
    options:
      - Указать только retrieval-effective length как большее значение
      - Усреднить обе длины в одну метрику
      - Хранить два отдельных порога и проверять каждый своим набором задач
      - Заменить обе метрики заявленным окном контекста
    correct: 2
    explanation: >-
      Извлечение и рассуждение могут деградировать на разных длинах. Раздельные

      модели.

Перед тобой два отчёта: у первой модели идеальная NIAH-карточка, у второй лучше результаты RULER, LongBench и MRCR. Выбрать победителя по одной строке нельзя. Тебе понадобятся различия между поиском и рассуждением из [шага 2](#step-2), две effective length из [шага 30](#step-30) и продуктовая батарея из [шага 39](#step-39). Главная ловушка — принять заявленное окно или единичный успех за рабочую ёмкость.

> 🎒 **На пальцах.** Представь отбор спасателей: один кандидат быстро находит один маяк, другой удерживает переговоры с группой и строит маршрут по нескольким сводкам. Один норматив не определяет лучшего спасателя. Сначала уточни предстоящую работу, затем выбери подходящие испытания и отметь дистанцию, после которой результат становится неприемлемым.
