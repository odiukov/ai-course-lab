Модель ответила: «Первое слово — amber, второе — cedar», но пропустила третье — violet. Если считать совпадения по отдельности, получится два успеха из трёх. Однако по правилу из [шага 18](#step-18) весь прогон должен получить `0`: вопрос требовал полный набор.

Тебе нужно написать `score_multi_needle`, которая принимает ответ модели и список ожидаемых фактов, а возвращает только `1` или `0`. Для каждого факта выполни ту же нормализацию текста, что использовал `score_needle` в [шаге 9](#step-9): различия в регистре не должны превращать правильный ответ в ошибку. Затем проверь присутствие каждого нормализованного факта в нормализованном ответе.

Здесь легко случайно ослабить условие. Проверка «нашёлся хотя бы один факт» неверна: она пропустит неполный ответ. Сумма совпадений тоже меняет смысл метрики, потому что начнёт возвращать `2` или `3`. Даже доля найденных фактов вроде `0.67` не подходит: один прогон multi-needle должен остаться бинарным.

Посмотри на три случая: все факты присутствуют — результат `1`; отсутствует хотя бы один — `0`; факты перечислены в другом порядке — всё равно `1`. Порядок ответа не важен, полнота важна. В тестах также используй непустой список ожидаемых фактов, иначе стандартная проверка «все элементы подходят» может неожиданно считать пустой список успешным.

> 🎒 **На пальцах.** Представь паспортный контроль перед посадкой: сотрудник ищет три обязательные отметки — визу, штамп въезда и разрешение на выезд. Их порядок на страницах не важен, но двух отметок недостаточно. `score_multi_needle` работает так же: просматривает весь ответ, сверяет каждый обязательный пункт и зажигает зелёный сигнал только после полного комплекта.
