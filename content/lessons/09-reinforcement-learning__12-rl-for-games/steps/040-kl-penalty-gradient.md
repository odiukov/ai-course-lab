После нескольких обновлений один ответ получает слишком большую вероятность, и политика заметно отдаляется от референсной. Тебе нужно вычислить отдельный «возвращающий» сигнал для каждого логита — именно это должна делать `kl_penalty_gradient`.

Функция принимает два списка одинаковой длины: текущие вероятности `probs` и референсные `probs_ref`. Сначала вычисли одно общее значение KL-расхождения по всем ответам. Затем для каждого индекса собери компонент градиента по правилу, полученному на [шаге 39](#step-39): текущую вероятность умножь на разность между логарифмом отношения текущей и референсной вероятностей и общим KL.

Обрати внимание на порядок вычислений: KL нужен целиком до расчёта отдельных компонентов. Если пересчитывать или подменять его локальным слагаемым для одного ответа, получится другой градиент.

Верни список той же длины. Не включай в него `beta` и не меняй логиты внутри функции: коэффициент штрафа и вычитание градиента относятся уже к обучающему обновлению следующего шага. Здесь твоя функция только сообщает направление роста KL.

Для самопроверки сложи все компоненты результата. Сумма должна быть близка к нулю, хотя из-за округления может остаться крошечная погрешность. Это важный сигнал: одинаковый сдвиг всех логитов не меняет softmax, поэтому градиент не должен толкать их все разом в одну сторону. Логарифмы безопасны для вероятностей, полученных через `softmax`: они положительны.

> 🎒 **На пальцах.** Представь ряд сообщающихся сосудов с водой. Ты не добавляешь воду во всю систему и не выливаешь её целиком — только перераспределяешь между сосудами, возвращая уровень ближе к контрольной отметке. Компоненты градиента работают так же: одни логиты подталкиваются вверх, другие вниз, а их общий сдвиг остаётся почти нулевым.
