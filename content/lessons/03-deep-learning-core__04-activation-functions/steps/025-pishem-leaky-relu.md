В [шаге 24](#step-24) ты увидел правило Leaky ReLU. Теперь преврати его в функцию `leaky_relu(x, alpha=0.01)`: она получает число `x` и коэффициент наклона `alpha`, а возвращает одно число.

Главное место, где легко ошибиться, — отрицательная ветка. Если `x = -4`, функция не меняет знак и не возвращает просто `alpha`. Она умножает вход на коэффициент: при `alpha = 0.01` результат должен быть `-0.04`.

Проверь будущую функцию на трёх случаях:

```python
leaky_relu(3.0)             # 3.0
leaky_relu(-4.0)            # -0.04
leaky_relu(-4.0, alpha=0.1) # -0.4
```

Положительное число должно пройти без изменений. Для нуля обе ветки всё равно дают `0.0`, поэтому достаточно аккуратно записать условие из предыдущего шага. Импортировать `math` здесь не потребуется.

Обрати внимание на параметр по умолчанию: если второй аргумент не передан, Python использует `0.01`. Но вызывающий функцию человек может выбрать другой наклон, как в третьей проверке. Значит, не стоит вшивать `0.01` внутрь вычисления — используй именно значение `alpha`.

> 🎒 **На пальцах.** Представь кассу с двумя тарифами доставки. Посылки с положительной отметкой проходят по обычному тарифу один к одному. Посылки с отрицательной отметкой не выбрасывают: их стоимость уменьшают в `100` раз. Параметр `alpha` — настройка этого льготного тарифа. Поменяешь его с `0.01` на `0.1` — отрицательная величина уменьшится уже в `10` раз.
