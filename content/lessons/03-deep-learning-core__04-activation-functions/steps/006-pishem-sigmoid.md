Запусти функцию на числе `-1000`. Если сразу передать его в экспоненту, Python попытается вычислить невероятно большое значение и может остановиться с ошибкой переполнения. Хотя математически sigmoid для такого входа просто почти равен нулю.

Поэтому функция должна выполнить два действия. Сначала ограничить вход диапазоном от `-500` до `500`, используя `min` и `max`. Затем вычислить sigmoid по формуле из [шага 5](#step-5), взяв экспоненту через `math.exp`. Ограничивай именно локальное значение внутри функции: вызывающий код не должен неожиданно получить изменённый аргумент.

После реализации проверь несколько ориентиров:

- при `x = 0` результат должен быть `0.5`;
- положительный вход должен дать число между `0.5` и `1`;
- отрицательный — между `0` и `0.5`;
- даже для `-1000` и `1000` функция должна вернуть число, а не упасть.

Обрати внимание на знак перед `x` внутри экспоненты. Потерять минус легко: программа продолжит работать, но положительные и отрицательные входы поменяются ролями. Полезная быстрая проверка — результат для `2` должен быть больше результата для `-2`.

Ограничение до `500` не меняет практический смысл крайних ответов: они и без того настолько близки к `0` или `1`, что разница исчезает в вычислительной точности. Зато функция остаётся устойчивой на любых входах.

> 🎒 **На пальцах.** Представь сортировочную машину, которая принимает посылки весом только до 500 кг. Посылку с отметкой 1000 кг ты не пытаешься затолкнуть внутрь: ставишь на ленту безопасный эквивалент в 500 кг. Для нужного решения обе отметки означают одно — «крайне тяжёлая», но машина теперь не ломается.
