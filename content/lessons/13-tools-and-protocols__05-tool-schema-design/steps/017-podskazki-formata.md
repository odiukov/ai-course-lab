Имя выбрано по всем правилам, описание начинается с «Use when», конкурент отсечён строкой «Do not use for» — и модель наконец берёт нужный инструмент. Ты смотришь в лог вызова и видишь:

```
get_weather(city="Мюнхен")
```

Ответ: `404 city not found`. Инструмент взят правильно. Инструмент провалился.

Почему? Потому что твой API принимает названия городов только по-английски, а модель об этом узнать не могла. Пользователь написал «какая погода в Мюнхене» — модель аккуратно скопировала слово из вопроса в параметр. Она вела себя разумно. Просто в описании не было ни слова о том, как этот параметр выглядит внутри.

И тут же вторая половина той же дырки: твой API возвращает `18`. Восемнадцать чего? Модель не знает и договаривает сама — иногда «прохладно, 18 градусов», иногда «мягко, около 18 по Фаренгейту, возьмите куртку». Число одно, ответ пользователю разный.

Лечится одной дописанной парой фраз прямо в описании:

```
Accepts city names in English.
Returns temperature in Celsius unless `units` says otherwise.
```

Теперь модель переводит «Мюнхен» в `Munich` до вызова и читает `18` как Цельсий после. Первая фраза говорит, во что превратить слова пользователя на входе; вторая — как понимать цифру на выходе. По [шагу 16](#step-16) у тебя ещё остаётся запас до 1024 символов — эти две строки в него влезают легко.

Инструмент выбран верно, но заполнен вслепую — это тоже провал, просто на шаг позже.

> 🎒 **На пальцах.** Печёшь по рецепту из американской книги: «запекать при 350 градусах». Ставишь 350 — через десять минут дом в дыму. Рецепт не врал, он просто не написал «по Фаренгейту», то есть 175 по Цельсию. Ты подставила единицы своей духовки, как модель подставляет свои догадки. Одна пометка рядом с числом — и никакого дыма.
