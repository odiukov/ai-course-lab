title: Строка «Do not use for» убирает монетку
source_anchor: '### Description pattern'
---

Возьми два инструмента из своего реестра: `get_current_weather` и `get_weather_forecast`. У первого описание по шаблону из [шага 14](#step-14): «Use when the user asks about current conditions for a specific city». У второго — «Use when the user asks about weather for upcoming days». Приходит запрос: «какая погода в Праге?». Прогоняешь его сто раз и считаешь, сколько раз модель взяла первый инструмент. Около пятидесяти.

Почему ровно половина, а не девяносто?

Посмотри на описания глазами модели. Слово «погода» есть в обоих. Город есть в обоих. Ни одно из двух условий не запрещает второе — они не спорят, они пересекаются. Модель не выбирает между «подходит» и «не подходит», ей приходится выбирать между «подходит» и «тоже подходит». Это и есть монетка — тот самый провал из [шага 2](#step-2), когда взят не тот инструмент.

Теперь допиши первому инструменту вторую строку:

```
Do not use for historical weather or multi-day forecasts.
```

Пересечение исчезло. У первого инструмента появилась граница, и она названа не абстрактно («не для других запросов»), а конкретными соседями по реестру: история и прогноз на несколько дней. Именно так и надо писать второе предложение — перечисляй тех, с кем тебя реально путают.

Первое предложение говорит, куда идти. Без второго модель не знает, где остановиться, — и половину времени идёт в соседнюю дверь.

> 🎒 **На пальцах.** На столе два чёрных пульта, у обоих кнопка включения. На первом наклейка «телевизор» — и ты всё равно берёшь наугад, потому что второй тоже похож на пульт от телевизора. Допиши на первом: «не для приставки». Всё, рука тянется без раздумий. Ты не добавил новой функции пульту — ты отобрал у него двойника.
