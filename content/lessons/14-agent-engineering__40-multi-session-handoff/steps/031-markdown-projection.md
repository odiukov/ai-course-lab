Ты открываешь `handoff.json` и видишь два риска в строгом порядке: сначала упавший тест, затем незакрытое замечание ревью. Рядом в `handoff.md` написано: «Есть несколько проблем, стоит разобраться». Читать приятно, но продолжать работу опасно: исчезли и сами факты, и их порядок.

В [шаге 30](#step-30) у двух файлов появился один источник. Теперь Markdown должен быть не пересказом JSON, а его детерминированным представлением — результатом фиксированных правил преобразования. Поле `next_action` всегда попадает в один и тот же раздел, каждый элемент `open_risks` становится отдельным пунктом, а порядок элементов сохраняется. Пустое значение тоже отображается заранее выбранным способом, например фразой «Открытых рисков нет», а не исчезает по настроению автора.

Здесь нет места редакторской свободе. Нельзя заменить конкретное действие более гладкой формулировкой, объединить похожие риски или добавить полезное предположение. Иначе человек прочитает одну передачу, а агент загрузит другую. Если возникает расхождение, основной остаётся JSON: Markdown можно заново получить из него, но нельзя исправлять JSON по удачной фразе из Markdown.

Представь простой тест: ты указываешь пальцем на строку Markdown и можешь назвать поле JSON, из которого она появилась. Если источник строки найти нельзя, в человеческую версию, вероятно, просочинился новый факт. Красивое оформление допустимо; новое содержание — нет.

> 🎒 **На пальцах.** В бюро переводов есть заверенная анкета и удобная памятка для клиента. В памятке адрес разбит на строки, даты подписаны словами, пункты сгруппированы заголовками — читать легче. Но переводчик не сокращает фамилию и не уточняет профессию от себя. Анкета хранит факты, а памятка лишь раскладывает те же факты по полкам.
