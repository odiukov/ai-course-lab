Промпт уже занял всё контекстное окно, а тебе нужно дописать ещё пять токенов. Если передать модели всю растущую последовательность, она вскоре получит больше позиций, чем умеет обрабатывать. Но если обрезать сам результат, исчезнет начало промпта. Значит, здесь нужны две разные последовательности: полная история для ответа и короткое скользящее окно для очередного вызова модели.

Дополни `quick_generate`, сохраняя полную копию промпта отдельно от входа модели. На каждом из ровно `n` проходов бери из накопленной истории не больше последних `context_length` токенов. Из полученных логитов смотри только на последнюю позицию: именно она предсказывает следующий токен. Выбирай индекс с наибольшим значением — это жадная генерация, без случайной выборки — и добавляй его к полной истории.

Следи за формой выбранного токена: он должен оставаться столбцом из одного элемента, чтобы его можно было присоединить вдоль длины последовательности. Сам `prompt` менять нельзя, поэтому работа начинается с его копии.

Особенно важна граница `n = 0`. В этом случае модель вообще не вызывается, цикл не делает ни одного шага, а результат содержит исходный промпт без добавлений. При `n = 3` длина обязана увеличиться ровно на три — не «до трёх» и не на четыре из-за ошибки в границах цикла. Получившийся список затем можно использовать в сквозном сравнении из [шага 8](#step-8).

> 🎒 **На пальцах.** Представь длинную кассовую ленту и сканер, который видит только последние несколько строк. Новая покупка определяется по видимому хвосту, но сама лента продолжает хранить всё напечатанное раньше. Ты печатаешь ровно `n` новых строк; если `n = 0`, чек выходит таким же, каким вошёл.
