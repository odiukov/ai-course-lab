  - question: >-
      В каком направлении должна работать карта имён при загрузке опубликованных
      весов в локальную модель?
    options:
      - От имени в файле весов к имени параметра локальной модели
      - От имени локального параметра к форме его градиента
      - От размера тензора к индексу блока
      - От токена промпта к имени выходного слоя
    correct: 0
    explanation: >-
      Загрузчик читает исходный ключ из файла и по нему выбирает локальный
      параметр, которому предназначен тензор.
  - question: >-
      В файле весов встретился ключ, которого нет в карте имён. В какую часть
      LoadReport он должен попасть?
    options:
      - loaded
      - missing
      - unexpected
      - shape_mismatch
    correct: 2
    explanation: >-
      unexpected содержит исходные ключи, для которых загрузчик не нашёл
      допустимого назначения. missing, напротив, описывает ожидаемые локальные
      параметры, которые не были загружены.
  - question: >-
      После загрузки значения tok_embed.weight и lm_head.weight полностью равны.
      Достаточно ли этого, чтобы подтвердить weight tying?
    options:
      - 'Да, равенство значений всегда означает общий параметр'
      - 'Нет, нужно также убедиться, что веса разделяют одно хранилище памяти'
      - 'Да, если оба тензора имеют одинаковую форму'
      - 'Нет, связанные веса должны быть транспонированы друг относительно друга'
    correct: 1
    explanation: >-
      Две независимые копии тоже могут временно содержать одинаковые числа. При
      настоящем weight tying изменение через одно имя сразу видно через другое,
      потому что оба ссылаются на общую память.
  - question: >-
      В LoadReport есть успешно загруженные пары, но список missing не пуст. Как
      интерпретировать такой отчёт?
    options:
      - Загрузка покрыла только часть ожидаемых параметров
      - 'Все параметры загружены, а missing содержит необязательные комментарии'
      - Файл обязательно повреждён на уровне формата safetensors
      - Загрузчик выполнил лишнее транспонирование каждого тензора
    correct: 0
    explanation: >-
      Непустой loaded подтверждает отдельные присваивания, но непустой missing
      показывает, что некоторые локальные параметры остались без загруженного
      источника. Полного покрытия нет.

Дальше тебе понадобится привычка проверять не отдельное присваивание, а весь шов целиком: покрытие карты из [шага 3](#step-3), точный transpose-on-load из [шага 5](#step-5), атомарность из [шага 7](#step-7), общий вес эмбеддингов и головы, а затем наблюдаемое поведение генерации из [шагов 8](#step-8)–[9](#step-9). Чаще всего ошибка прячется там, где каждый фрагмент выглядит разумно по отдельности, но их контракты не сходятся вместе.
