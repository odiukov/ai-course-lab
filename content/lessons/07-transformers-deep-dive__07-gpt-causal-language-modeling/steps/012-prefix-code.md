Цикл `out[i] = X[:i+1].mean(0)` работает, но он честно ползёт по позициям: 512 токенов — 512 итераций, и каждая тянет за собой срез. То же самое можно посчитать одним умножением матриц, если заранее собрать таблицу весов `A` из [шага 11](#step-11).

Твоя задача — функция, которая по одному числу `n` возвращает эту таблицу: массив `n × n`, где строка `i` содержит `i+1` одинаковых чисел `1/(i+1)`, а правее диагонали — нули.

Собирается она в два движения. Сначала — нижнетреугольная заготовка из единиц: у numpy для этого есть готовая функция, которая обнуляет всё выше диагонали. Потом каждую строку нужно поделить на её собственную сумму, то есть на количество единиц в ней.

И вот здесь легко промахнуться.

Сумму надо брать по строкам, а не по столбцам, и результат должен остаться столбиком формы `(n, 1)`, а не сплющиться в плоский вектор длины `n`. Если он сплющится, numpy молча растянет его по другой оси и поделит по столбцам — ошибки не будет, матрица получится, только неправильная.

Поэтому смотри не на то, что код отработал, а на числа. Первая строка — `[1, 0, 0, …]`. Последняя — сплошные `1/n`. Сумма каждой строки — ровно `1.0`. Всё, что выше диагонали, — нули. Если хоть одна строка суммируется не в единицу, ты поделил не по той оси, и это единственное, что здесь ломается.

> 🎒 **На пальцах.** Строка `A` — рецепт коктейля. Для позиции 2 в рецепте написано: возьми по трети ингредиента 0, 1 и 2. Ингредиенты 3 и дальше в бланке просто не упомянуты — не «запрещены», а не существуют в этом рецепте. Проверка одна: доли в любом рецепте складываются в целый стакан. Если складываются в полтора — ты читал бланк по столбцам, а не по строкам.
