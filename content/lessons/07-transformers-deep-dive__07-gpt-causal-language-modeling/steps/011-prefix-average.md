Возьми последовательность из четырёх токенов и попробуй сделать для каждой позиции честную сводку прошлого — без единой хитрости. Самое тупое, что вообще можно придумать: пусть позиция будет средним всего, что до неё уже прочитано, включая её саму. Позиция 0 — это просто она сама. Позиция 3 — среднее четырёх.

В виде цикла это одна строчка: `out[i] = X[:i+1].mean(0)`. Идёшь по позициям, для каждой берёшь срез от начала и усредняешь. Работает. Но ты перебираешь позиции по очереди, и для каждой заново режешь массив — а треугольник из [шага 5](#step-5) выглядел как одна цельная картинка, а не как четыре отдельных среза.

А что, если посчитать все позиции разом?

Оказывается, весь этот цикл — одно матричное умножение. Собери матрицу $A$ размера $n \times n$, где $n$ — длина последовательности. Правило простое:

$$A_{ij} = \frac{1}{i+1} \text{ при } j \le i, \quad A_{ij} = 0 \text{ при } j > i$$

Здесь $i$ — номер строки (позиция, для которой считаем результат), $j$ — номер столбца (позиция, из которой берём вклад). Строка 0 = `[1, 0, 0, 0]`. Строка 3 при `n = 4` = `[0.25, 0.25, 0.25, 0.25]`. Каждая строка говорит: с какими весами сложить все позиции последовательности, чтобы получить результат для этой позиции.

И теперь посмотри, где в этой матрице нули. Над диагональю. Ровно тот же треугольник, что в [шаге 3](#step-3) — только мы его не рисовали и ничего не запрещали. Будущее не маскировали: его просто не было в сумме.

> 🎒 **На пальцах.** Часы на пробежке показывают средний темп с начала дистанции. На первом километре это один замер, на пятом — среднее пяти. Часы не «скрывают» от тебя километры, которые ты ещё не пробежал: их нечего скрывать, они не существуют. Запиши веса каждого показания в строку — и километры впереди получат ноль сами собой. Не запрет, а пустота.
