Тебе приходит словарь: `{"cuisine": "japanese", "day": "friday", "people": "2"}`. Выглядит правдоподобно: ключи и значения читаются, структура не сломана. Но пропускать его нельзя. Кухни `japanese` нет среди разрешённых, а количество гостей записано строкой, не числом.

Напиши `validate_state`, которая возвращает `True` только тогда, когда каждый переданный slot соответствует схеме из [шага 25](#step-25). Проверяй словарь по очереди:

1. Ключ должен быть известным slot. Даже безобидное поле вроде `comment` делает состояние невалидным: бэкенд не знает, что с ним делать.
2. Значение `None` допустимо для любого известного slot — так обозначается пустое поле.
3. Для `cuisine`, `area` и `price` значение должно входить ровно в свой список разрешённых вариантов.
4. Для `people` требуется целое число. Обрати внимание на `True`: в Python оно ведёт себя почти как число, хотя количеством гостей быть не должно.
5. Для `day` подходит любая строка, потому что это свободное значение, а не enum.

Останавливай проверку при первой ошибке и возвращай `False`. Если все переданные пары прошли фильтр — возвращай `True`. Отсутствующие slot не считаются ошибкой: состояние может быть заполнено лишь частично.

Проверь функцию на нескольких контрастных примерах: разрешённая кухня и число гостей должны пройти; неизвестный ключ, `"2"` вместо `2` и кухня вне списка — не пройти. Здесь важен не размер словаря, а соответствие каждой его части своему правилу из [шага 26](#step-26).

> 🎒 **На пальцах.** Представь контролёра перед посадкой на самолёт. Пустой карман чемодана его не тревожит, но каждый найденный предмет он сверяет со своим правилом: документы лежат в отделении для документов, жидкость имеет допустимый объём, неизвестный контейнер не пропускается. Один подозрительный предмет останавливает весь багаж — именно так `validate_state` относится к одной неверной паре slot-значение.
