У тебя уже есть `update_state` из [шага 18](#step-18), но она обрабатывает только одну реплику. Теперь передай ей весь диалог по очереди. Если каждый раз подставлять пустой словарь, фраза «лучше на юге» забудет выбранную ранее итальянскую кухню.

Функция `track_dialogue` получает список реплик и возвращает историю состояний — по одному словарю после каждого turn. Начни с пустого состояния. Затем для каждой реплики:

1. вызови `update_state`, передав текущее состояние и реплику;
2. сохрани полученное состояние в истории;
3. используй его как исходное для следующей реплики.

Например, после двух реплик история должна содержать два состояния:

```python
[
    {"area": "north"},
    {"area": "north", "cuisine": "italian"},
]
```

Не вызывай отдельно `extract_slots` или `is_negated`: нужный порядок действий уже спрятан внутри `update_state`. Задача нового уровня — не повторить эту логику, а правильно протянуть её результат через весь список.

Обрати внимание на два граничных случая. Пустой диалог должен дать пустую историю. А число состояний должно совпадать с числом реплик: даже если очередная реплика ничего не изменила, состояние после неё всё равно является частью истории.

> 🎒 **На пальцах.** Представь эстафету, где вместо палочки передают карточку с настройками. Каждый участник читает одну реплику, вносит только нужные изменения и передаёт обновлённую карточку дальше. `track_dialogue` следит за порядком участников и фотографирует карточку после каждого этапа. Если выдать каждому новую пустую карточку, накопленного состояния не получится.
