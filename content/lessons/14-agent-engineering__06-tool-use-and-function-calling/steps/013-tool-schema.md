Ты дал модели два инструмента: `search` с описанием «Search» и `lookup` с описанием «Look something up». Спрашиваешь про вчерашний матч — модель зовёт `lookup`, получает мусор, отвечает мимо. Ты меняешь местами порядок в списке — она зовёт `search`. Странно: код инструментов не менялся, менялась только их подпись.

Так и есть. Модель не видит ни твоих функций, ни того, что внутри. Она видит ровно три строки на каждый инструмент:

```
name: string
description: string (что делает, когда применять)
input_schema: JSON Schema (properties, required, types, enums)
```

Это весь контракт. Имя — как модель его позовёт. Схема входа — какие аргументы и какого типа она обязана положить. А описание — единственное место, откуда она узнаёт, в какой ситуации инструмент вообще уместен.

Разница между провайдерами тут меньше, чем кажется: Anthropic называет третий ключ `input_schema`, OpenAI — `function.parameters`, а JSON Schema внутри одна и та же. Переезд с одного на другой — переименование ключа, не переписывание контракта.

Теперь сравни два описания одного и того же поиска: «Search» и «Use when the user asks about events after your knowledge cutoff». Первое говорит, что инструмент существует. Второе говорит, когда его звать — и, что важнее, когда НЕ звать. Модель читает эту фразу как инструкцию, а не как комментарий для коллеги.

Отсюда и правило: плохие описания — причина №1 провалов «выбран не тот инструмент». Это не мелочь оформления, а тот самый шаг «выбор инструмента» из чек-листа отладки в [шаге 12](#step-12).

> 🎒 **На пальцах.** Оставь другу связку из трёх одинаковых ключей и записку «ключ». Он будет тыкать все три в замок по очереди — примерно как модель перебирала твои `search` и `lookup`. Подпиши: «верхний замок», «нижний, поворачивать до упора», «подвал — только если верхний заело». Ключи те же, металл тот же. Промахов больше нет, потому что подпись теперь говорит не «что это», а «когда брать».
