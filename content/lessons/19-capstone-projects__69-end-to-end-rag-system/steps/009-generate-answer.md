Представь: поиск вернул три подходящих фрагмента, но первый набрал лишь `0.12` при пороге `0.35`. Из них можно собрать гладкий ответ — только он будет опираться на слабую находку. Поэтому функция должна сначала решить, имеет ли она право отвечать, и лишь затем выбирать цитаты.

На вход она получает запрос и ранжированный список пар «чанк — оценка». Пустой список или оценка первого чанка ниже `REFUSE_THRESHOLD` означают отказ: верни `REFUSE_TEXT` и пустой список источников. Не путай эту оценку с пересечением токенов: первая управляет отказом, второе — выбором материала для уже разрешённого ответа.

Если порог пройден, возьми первые три результата. Для каждого посчитай, сколько значимых токенов запроса встречается в его тексте. Отсортируй кандидатов сначала по этому пересечению, затем по исходной оценке — оба раза от большего к меньшему. Выбери максимум два чанка с ненулевым пересечением. Если пересечение везде нулевое, оставь один лучший кандидат: уверенность поиска уже разрешила ответ.

Из каждого выбранного чанка понадобится только первое предложение. Сразу после него поставь якорь в квадратных скобках, например `[d3:2]`, продолжая ограничение контекстом из [шага 8](#step-8). Функция возвращает две согласованные части: собранный текст и отдельный список тех же якорей без скобок. Проверь, что у каждого утверждения есть адрес, а при отказе нет ни ответа, ни фиктивных цитат.

> 🎒 **На пальцах.** Представь эксперта в суде. Сначала он проверяет, достаточно ли надёжна лучшая улика, чтобы вообще давать заключение. Затем из трёх верхних папок выбирает не больше двух, ближе всего связанных с вопросом, и после каждой фразы ставит номер дела. Если надёжной улики нет, честный отказ лучше убедительной версии без доказательств.
