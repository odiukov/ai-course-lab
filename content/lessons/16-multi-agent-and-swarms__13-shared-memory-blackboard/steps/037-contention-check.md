  Какую схему выбрать при медленных LLM-вызовах и какую — при независимых
  владельцах тем?
source_anchor: '### Write-contention patterns'
check:
  - question: >-
      LLM-вызовы занимают секунды, записи короткие, а агенты работают с общей
      темой. Какую схему тебе разумнее выбрать?
    options:
      - 'Sequential writer: пропускать записи через одну очередь'
      - 'Optimistic concurrency: проверять версию перед каждой записью'
      - 'Topic partitioning: создать отдельную тему для каждого агента'
    correct: 0
    explanation: >-
      При медленных LLM настоящие пересечения редки, поэтому простой sequential
      writer обычно не становится заметным узким местом.
  - question: >-
      У каждого агента есть своя независимая тема и постоянное право записывать
      в неё. Какая схема лучше использует это разделение?
    options:
      - Один sequential writer для всех тем
      - Optimistic concurrency внутри общего раздела
      - Topic partitioning по владельцам тем
    correct: 2
    explanation: >-
      Разделение по темам устраняет конкуренцию между независимыми владельцами,
      хотя не защищает от ошибок внутри темы.
---

Здесь легко выбрать самую «продвинутую» схему просто на всякий случай. Смотри не на название, а на источник конкуренции. Если агенты долго ждут ответы LLM и лишь изредка дописывают общий журнал, достаточно очереди из [шага 34](#step-34): сложная проверка версий почти ничего не даст. Если же темы действительно независимы и у каждой есть свой владелец, используй разделение из [шага 36](#step-36).

> 🎒 **На пальцах.** Представь радиостудию. Если ведущие долго готовят реплики и редко подходят к одному микрофону, достаточно общей очереди. Но если спортивный и музыкальный редакторы постоянно работают каждый в своей кабинке, разумнее закрепить за ними отдельные микрофоны. Выбор зависит не от числа людей, а от того, где они способны столкнуться.
