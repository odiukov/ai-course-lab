id: 031-verifier-check
type: check
title: Почему верификатор не должен сам возвращать исправления в проверяемый пул?
source_anchor: '### The unwritable verifier'
check:
  - question: >-
      Верификатор обнаружил, что значение в первоисточнике не совпадает со
      значением в общем пуле. Как ему поступить?
    options:
      - Записать значение из источника прямо в проверяемый пул
      - >-
        Передать сведения о расхождении по отдельному каналу решающему
        компоненту
      - Удалить спорную запись из пула
      - Добавить к спорной записи собственное подтверждение
    correct: 1
    explanation: >-
      Верификатор только сообщает о расхождении. Решение об исправлении и запись
      новой версии выполняет другой компонент, поэтому проверка остаётся
      независимой.
  - question: >-
      Почему верификатору нельзя записывать собственные исправления в тот же
      пул, который он проверяет?
    options:
      - Исправления неизбежно замедляют чтение пула
      - После исправления невозможно сохранить provenance исходной записи
      - >-
        Результат одной проверки может стать входом следующей и выглядеть как
        независимое подтверждение
      - Верификатор перестанет иметь доступ к внешним источникам
    correct: 2
    explanation: >-
      Обратная запись замыкает цикл: верификатор начинает проверять память, уже
      содержащую его собственные выводы, и может ошибочно принять их за
      независимое свидетельство.
---

Здесь важно различить обнаружение ошибки и изменение общей памяти. В [шаге 27](#step-27) верификатор читает пул, но сверяется с внешним источником. Если он сам вернёт исправление в пул, следующая проверка может принять его собственный вывод за независимое подтверждение. Поэтому расхождение уходит по отдельному каналу, а решение о новой записи принимает другой компонент, как в [шаге 29](#step-29).
