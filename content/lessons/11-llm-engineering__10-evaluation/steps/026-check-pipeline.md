  - question: >-
      Команда переписала промпт, прогнала 60 тестовых случаев, LLM-судья

      Какой шаг конвейера они пропустили?
    options:
      - Score — оценки не были выставлены
      - Compare — оценку не сравнили с базовой линией
      - Run — модель не прогнали по случаям
      - Prompt — тестовые случаи не были заданы
    correct: 1
    explanation: >-
      4,3 сами по себе ничего не значат: у старой версии могло быть 4,5. Без

      воздухе.
  - question: >-

    options:
      - 'Ничего, 4,3 больше 4,1 — этого достаточно'
      - >-
        Одного прогона мало: разброс самого судьи может быть больше, чем эта
        разница в 0,2
      - 'Нужно было сохранить метаданные, тогда разница стала бы больше'

    correct: 1
    explanation: >-
      Один прогон не даёт понять, насколько оценки шатаются сами по себе. Если
      тот же случай даёт то 3, то 5, разница в 0,2 — шум, а не улучшение.

Здесь проверяется одна вещь: умеешь ли ты по описанию чужого прогона найти выпавшее звено конвейера из [шага 21](#step-21) и [шага 22](#step-22).

Спотыкаются обычно на двух местах. Первое — пропускают Compare: видят красивое среднее и принимают его за результат, хотя без базовой линии из [шага 25](#step-25) число не с чем сопоставить. Второе — считают, что раз сравнение сделано, дело закрыто, и забывают про повторные прогоны из [шага 23](#step-23): маленькая разница может целиком лежать внутри разброса судьи.

Читай сценарий и спрашивай себя: чего в этом рассказе просто нет?
