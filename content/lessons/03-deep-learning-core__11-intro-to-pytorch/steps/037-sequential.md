title: nn.Sequential передаёт результат каждого слоя следующему по порядку

Ты собрал три слоя и теперь пишешь `forward`: вызвать первый, сохранить результат, передать его во второй, снова сохранить… Для короткой модели это терпимо, но при перестановке слоёв легко забыть одну строку или передать дальше не тот тензор.

PyTorch может записать такую последовательность прямо в структуре модели:

```python
model = nn.Sequential(
    nn.Linear(20, 8),
    nn.ReLU(),
    nn.Linear(8, 3),
)
```

Когда ты вызываешь `model(x)`, `nn.Sequential` берёт `x` и передаёт его первому слою. Получившийся тензор становится входом `nn.ReLU()`, а результат ReLU — входом последнего `nn.Linear`. Возвращается только итог последнего слоя. Это тот же прямой проход, что и несколько последовательных присваиваний в `forward`, но порядок теперь виден в одном месте.

Здесь важна стыковка форм. Первый `Linear` выдаёт для каждого примера 8 чисел. ReLU сохраняет эту форму, поэтому последний `Linear` получает именно ожидаемые 8 чисел и превращает их в 3. Если один слой выдаст форму, которую следующий принять не умеет, ошибка возникнет именно при передаче между ними.

Слои внутри `nn.Sequential` остаются полноценными зарегистрированными модулями: их параметры попадут в `model.parameters()` по механизму из [шага 35](#step-35). `Sequential` не создаёт новый способ вычислений — он аккуратно фиксирует маршрут тензора: слой за слоем, строго в указанном порядке.

> 🎒 **На пальцах.** Представь эстафету: первый бегун получает палочку `x`, пробегает свой участок и передаёт изменившийся результат второму. Тот передаёт его третьему, а на финише остаётся результат последнего участника. `nn.Sequential` хранит порядок бегунов и следит за передачей, но каждый участок по-прежнему выполняет свой отдельный слой.
