title: Eager execution выполняет операцию сразу в обычном Python-коде

---

Ты подаёшь модели фотографию и пишешь `y = model(x)`. Что находится в `y` после этой строки — готовый результат или лишь обещание посчитать его позже?

В PyTorch результат уже посчитан. Такой режим называют **eager execution** — «немедленное выполнение», похожее на кассу, где каждый товар пробивают сразу, а не складывают список покупок для будущего расчёта. Python доходит до операции, выполняет её и только затем переходит к следующей строке.

Поэтому код читается в том же порядке, в каком происходят вычисления:

```python
y = model(x)
print(y)
```

Сначала модель обрабатывает `x`, затем `print` получает настоящий `y`. Можно добавить обычный `if/else`: например, один путь для слишком тёмного изображения, другой — для светлого. Условие проверится прямо во время этого запуска, поэтому последовательность операций может зависеть от конкретных входных данных.

В старом подходе похожая запись сначала только добавляла операцию в заранее строящуюся схему. Отдельный запуск выполнял всю схему позже. Изменить порядок действий по ходу вычисления было заметно сложнее.

Немедленное выполнение не отменяет `backward` из [шага 2](#step-2): PyTorch запоминает выполненные операции по мере работы. Разница в том, что вычисление не откладывается — строка с моделью действительно запускает модель здесь и сейчас.

> 🎒 **На пальцах.** Представь кассира, который сразу называет новую сумму после каждого товара. Если цена выглядит странно, ты замечаешь это именно у нужной покупки. Старый режим больше похож на передачу закрытой корзины в подсобку: итог появится позднее, а чтобы понять, где возникла ошибка, придётся восстанавливать весь список действий.
