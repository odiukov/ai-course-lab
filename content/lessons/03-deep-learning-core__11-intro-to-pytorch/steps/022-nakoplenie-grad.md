title: 'Градиенты накапливаются, поэтому перед новым шагом их обнуляют'

Ты запускаешь два отдельных прямых прохода с одним параметром `w`. В каждом производная равна 3, поэтому после второго запуска ожидаешь снова увидеть 3:

```python
w = torch.tensor(2.0, requires_grad=True)

loss_1 = w * 3
loss_1.backward()
print(w.grad)  # tensor(3.)

loss_2 = w * 3
loss_2.backward()
print(w.grad)  # tensor(6.)
```

Откуда взялась шестёрка? `backward()` не заменяет старое значение в `w.grad`, а прибавляет к нему новый градиент. После первого прохода там было 3, после второго добавилось ещё 3. Вычислительная лента для `loss_2` новая, но поле `w.grad` принадлежит самому листовому тензору из [шага 20](#step-20) и сохраняет накопленное число.

Такое поведение полезно, когда ты намеренно хочешь собрать градиент из нескольких проходов. Но при обычном обучении каждый новый шаг должен опираться только на свежий расчёт. Иначе `step()` из знакомого цикла [шага 2](#step-2) изменит параметры с учётом остатков от предыдущих шагов.

Поэтому цикл обычно начинается с очистки:

```python
optimizer.zero_grad()
loss = model(x)
loss.backward()
optimizer.step()
```

`zero_grad()` очищает градиенты параметров, которыми управляет оптимизатор. Он не отменяет уже сделанное обновление и не обнуляет сами параметры — лишь освобождает место для следующего результата `backward()`. Новый шаг начинается с чистого счётчика.

> 🎒 **На пальцах.** Представь счётчик кругов на беговой дорожке. Ты пробежал три круга — на табло 3. Затем начал новую тренировку и пробежал ещё три, но не сбросил табло: оно покажет 6. Счётчик работает правильно, просто считает итог за обе тренировки. `zero_grad()` нажимает кнопку сброса перед новым забегом, чтобы старые круги не влияли на новый результат.
