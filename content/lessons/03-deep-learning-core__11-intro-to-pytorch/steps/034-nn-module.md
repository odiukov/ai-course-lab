Ты подаёшь один и тот же тензор сначала в `nn.ReLU`, а затем в модель из трёх слоёв. Внутри они делают совершенно разную работу, но вызываются одинаково:

```python
activation = nn.ReLU()
model = MLP(784, 256, 10)

y1 = activation(x)
y2 = model(x)
```

Почему Python позволяет обращаться с маленьким слоем и целой сетью одинаково? Оба объекта наследуются от `nn.Module` — базового класса с общим интерфейсом. Здесь слово «интерфейс» означает соглашение: любой такой объект можно вызвать, передав ему входные данные, и получить результат.

Конкретное вычисление ты описываешь в методе `forward`. У `ReLU` это обнуление отрицательных значений, у `MLP` — последовательный вызов нескольких слоёв. Сам `nn.Module` не решает, каким должно быть вычисление: он лишь задаёт общую форму работы.

```python
class MLP(nn.Module):
    def __init__(self):
        super().__init__()
        # здесь создаются части модели

    def forward(self, x):
        # здесь описывается путь данных
        return x
```

Строка `model(x)` запускает служебную механику `nn.Module`, которая затем обращается к `forward`. Поэтому обычно не пишут `model.forward(x)` напрямую. Знакомый прямой проход из [шага 2](#step-2) никуда не исчез — теперь PyTorch предоставляет ему единый стандартный вход.

В итоге большой модуль может вызывать внутри себя маленькие модули, оставаясь для внешнего кода таким же объектом: получил тензор, вернул тензор.

> 🎒 **На пальцах.** Представь гитарные педали со стандартными разъёмами. Одна добавляет эхо, другая искажает звук, а несколько педалей можно соединить в целую цепочку. Для гитариста и отдельная педаль, и вся цепочка выглядят одинаково: подай сигнал на вход, забери результат с выхода. `nn.Module` задаёт именно такой общий разъём, а `forward` определяет эффект внутри.
