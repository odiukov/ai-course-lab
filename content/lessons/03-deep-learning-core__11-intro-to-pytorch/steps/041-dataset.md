Ты сохранил 60 000 изображений MNIST и столько же меток, как в [шаге 40](#step-40). Теперь циклу обучения понадобилась картинка с индексом `17`. Откуда ему знать, где она лежит и какая цифра на ней изображена?

`Dataset` задаёт единый способ получить ответ. Это абстрактный класс — договор-шаблон: конкретный набор данных сам решает, где хранить примеры, но обязательно поддерживает две операции.

```python
class MNISTDataset(Dataset):
    def __init__(self, images, labels):
        self.images = images
        self.labels = labels

    def __len__(self):
        return len(self.labels)

    def __getitem__(self, idx):
        return self.images[idx], self.labels[idx]
```

Когда ты пишешь `len(dataset)`, Python вызывает `__len__` и получает число примеров. Здесь размер берётся по меткам: одной метке должна соответствовать одна картинка.

Запись `dataset[17]` вызывает `__getitem__(17)`. Метод достаёт ровно один пример и возвращает пару: изображение с индексом `17` и его метку. Это ещё не группа изображений и не случайный выбор — только ответ на запрос по конкретному индексу.

Благодаря такому договору код обучения не интересуется, лежат ли данные в тензорах, файлах или создаются на лету. Ему достаточно знать размер выборки и уметь запросить один согласованный пример.

> 🎒 **На пальцах.** Представь музыкальный автомат с пронумерованными треками. `len(dataset)` сообщает, сколько кнопок доступно, а `dataset[17]` нажимает кнопку 17 и выдаёт одну запись вместе с её названием. Автомату не нужно объяснять, как устроен внутренний накопитель: снаружи важны только количество треков и точная выдача по номеру.
