title: 'requires_grad и листовые тензоры определяют, где сохраняются градиенты'

Ты создаёшь коэффициент `w`, умножаешь его на 3 и получаешь `scaled`. Оба тензора связаны с вычислением, но место для сохранения градиента PyTorch приготовит не каждому.

```python
w = torch.tensor(2.0, requires_grad=True)
scaled = w * 3

print(w.is_leaf)       # True
print(scaled.is_leaf)  # False
print(scaled.requires_grad)  # True
```

`w` — **листовой тензор**: ты создал его напрямую, а не получил как результат другой операции. Несмотря на название, «лист» здесь находится у начала вычислительного графа из [шага 18](#step-18). Обучаемые параметры модели обычно именно такие.

`scaled` создан операцией `w * 3`, поэтому он не листовой. Его `requires_grad` тоже равен `True`: PyTorch должен учитывать эту операцию, чтобы проследить влияние результата обратно к `w`. Но отдельное значение градиента в `scaled.grad` по умолчанию не сохраняется — это временная остановка на маршруте, а не параметр, который нужно обновлять.

Получаются два независимых вопроса:

- `requires_grad=True` — нужно ли отслеживать участие тензора в вычислениях;
- `is_leaf=True` — был ли тензор создан напрямую.

Постоянным данным, например входному `x`, часто не нужен градиент, поэтому у него оставляют `requires_grad=False`. А для изменяемых параметров `w` и `b` включают этот флаг. Именно сочетание **листовой тензор + `requires_grad=True`** означает: «сохрани рассчитанный градиент в поле `.grad`».

> 🎒 **На пальцах.** Представь гардероб: `w` приходит с номерком, поэтому для него выделена собственная ячейка. `scaled` появляется позже, когда содержимое временно объединяют в комплект. Комплект участвует во всём дальнейшем маршруте, но отдельную ячейку ему не дают. `requires_grad` включает участие в маршруте, а листовой статус определяет, кому в конце положен личный результат.
