Ты запускаешь обучение на первом батче из 64 изображений: модель ошибается, получает поправку и немного меняет параметры. Приходит следующий батч — и нужно проделать тот же путь заново. Но какие действия повторять и в каком порядке?

Внутри цикла по батчам остаются пять операций:

```python
optimizer.zero_grad()
outputs = model(inputs)
loss = criterion(outputs, targets)
loss.backward()
optimizer.step()
```

Сначала `zero_grad()` очищает градиенты, оставшиеся от предыдущего батча. Без этого они сложатся с новыми — такое накопление мы разбирали в [шаге 22](#step-22). Затем `model(inputs)` делает прямой проход и выдаёт предсказания. `criterion(outputs, targets)` сравнивает их с правильными ответами; для классификации цифр это может быть `CrossEntropyLoss` из [шага 44](#step-44).

После `loss.backward()` autograd вычисляет, как каждый параметр повлиял на ошибку. Наконец, `optimizer.step()` применяет эти градиенты и обновляет параметры выбранным оптимизатором из [шага 45](#step-45).

Порядок здесь важнее конкретной архитектуры. Если вызвать `step()` до `backward()`, у оптимизатора ещё нет новых градиентов. Если забыть `zero_grad()`, следующий батч невольно продолжит поправку предыдущего. Один такой проход ты уже собирал вручную в [шаге 30](#step-30); теперь он просто повторяется для каждого батча из `DataLoader`.

> 🎒 **На пальцах.** Представь настройщика пианино, который проверяет по одному аккорду. Перед новой проверкой он сбрасывает записи прошлого замера, играет аккорд, слышит отклонение, выясняет, какие струны его создали, и подкручивает колки. Пропусти измерение — нечего исправлять. Не сбрось старую запись — станешь настраивать новый аккорд по смеси двух замеров. Пять действий образуют один законченный рабочий такт.
