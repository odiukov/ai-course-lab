title: Планировщик изменяет learning rate после завершённого шага оптимизатора
source_anchor: '### Learning Rate Scheduling'
---

В начале обучения большой `learning rate` помогает параметрам двигаться заметными шагами. Но ближе к хорошему решению та же величина может стать помехой: loss уже снизился, а модель продолжает перескакивать через удачные значения. Можно менять скорость вручную после каждой эпохи, но легко забыть нужный момент или ошибиться в расчётах.

Планировщик делает это автоматически. Он не обновляет веса — этим по-прежнему занимается оптимизатор из [шага 45](#step-45). Планировщик лишь изменяет `learning rate`, который оптимизатор использует при следующих обновлениях.

```python
scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(
    optimizer, T_max=10
)

for epoch in range(10):
    train_one_epoch(model, train_loader, criterion, optimizer, device)
    scheduler.step()
```

Здесь внутри `train_one_epoch` оптимизатор уже много раз выполнил `optimizer.step()`: по одному разу на каждый батч. Только после завершения эпохи вызывается `scheduler.step()`, и `CosineAnnealingLR` готовит новую скорость для следующей эпохи. Если переставить вызовы, расписание сдвинется: планировщик изменит скорость раньше, чем оптимизатор использует текущее значение.

Частота зависит от выбранного планировщика. `CosineAnnealingLR` в этом примере шагает раз за эпоху, `OneCycleLR` обычно — после каждого батча, а `ReduceLROnPlateau` получает значение метрики. Но порядок сохраняется: сначала состоявшееся обновление параметров, затем изменение скорости будущего обновления.

> 🎒 **На пальцах.** Представь бегуна с тренером и секундомером. Бегун сначала завершает круг в текущем темпе. Затем тренер смотрит на расписание и назначает темп следующего круга. Если тренер переключит темп до завершения текущего круга, один режим окажется пропущен. Планировщик так же не двигает параметры сам — он только задаёт оптимизатору скорость на следующий участок.
