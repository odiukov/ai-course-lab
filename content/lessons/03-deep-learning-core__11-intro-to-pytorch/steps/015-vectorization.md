title: Операции над целым тензором заменяют ручные циклы по числам
source_anchor: '### Tensors'

Ты хочешь сделать изображение светлее. В тензоре хранятся значения пикселей, и каждое нужно умножить на одно число. Можно добраться до каждого элемента вручную:

```python
for image in range(2):
    for channel in range(3):
        for row in range(224):
            for column in range(224):
                pixels[image, channel, row, column] *= 1.2
```

Здесь четыре цикла, множество индексов и несколько мест, где легко перепутать оси. А ведь действие простое: применить один множитель ко всему тензору.

```python
brighter = pixels * 1.2
```

PyTorch понимает такую запись поэлементно: берёт каждое число из `pixels`, умножает его на `1.2` и складывает результаты в новый тензор той же формы. Исходный `pixels` при этом не меняется. Аналогично работают `pixels + 10`, `pixels - correction` и многие другие операции.

Вычисления над всеми элементами называют **векторизованными**: ты описываешь преобразование целиком, а не порядок обхода отдельных чисел. Цикл никуда не исчезает физически — работу всё равно нужно выполнить для каждого элемента. Но его запускает не Python-код, а оптимизированное ядро PyTorch, о котором шла речь в [шаге 3](#step-3). Оно само распределяет однотипные вычисления между процессорными ядрами или потоками GPU.

Поэтому строка `pixels * 1.2` — не просто сокращённая запись. Она точнее выражает намерение: изменить весь тензор одинаковым способом, не управляя каждым числом вручную.

> 🎒 **На пальцах.** Представь фоторедактор с ползунком яркости. Ты не открываешь таблицу пикселей и не исправляешь сотни тысяч значений по одному — сдвигаешь один ползунок для всего снимка. Программа всё равно пересчитывает каждый пиксель, но берёт обход на себя. Операция над тензором работает так же: ты задаёшь общее действие, а PyTorch выполняет повторяющуюся работу.
