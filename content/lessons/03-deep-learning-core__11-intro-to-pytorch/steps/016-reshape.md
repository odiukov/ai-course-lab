Модель ждёт таблицу из двух строк по 12 признаков, а у тебя тензор формы `(2, 3, 4)`. В нём уже лежат нужные 24 числа — пересчитывать их незачем. Нужно лишь договориться, как читать их расположение. Форму и смысл осей ты разбирал в [шаге 8](#step-8).

```python
x = torch.randn(2, 3, 4)

a = x.view(2, 12)
b = x.reshape(6, 4)
```

Обе операции сохраняют число элементов. `view` создаёт новое представление тех же данных, но требует, чтобы они лежали в памяти непрерывно. После некоторых преобразований это условие нарушается. `reshape` удобнее: если новое представление возможно, он использует его, а при необходимости незаметно копирует данные.

`permute` решает другую задачу: не объединяет размеры, а меняет порядок осей.

```python
c = x.permute(2, 0, 1)  # форма (4, 2, 3)
```

Теперь первой стала бывшая третья ось. Это важно: числа не исчезли, но смысл позиции изменился.

`unsqueeze` добавляет ось длины 1, например превращает `(2, 3, 4)` в `(1, 2, 3, 4)`. `squeeze` удаляет только такие единичные оси. Поэтому с ним будь внимателен: у батча из одного объекта `squeeze()` может убрать и ось батча. Безопаснее указать конкретную ось: `squeeze(0)`.

Все эти методы возвращают новый тензор. Исходный `x` сам не изменится, пока ты не присвоишь результат.

> 🎒 **На пальцах.** Представь лоток с 24 конфетами и съёмными перегородками. `view` и `reshape` переставляют перегородки, `permute` поворачивает правила чтения рядов, `unsqueeze` помещает весь лоток в одну внешнюю коробку, а `squeeze` снимает такую коробку. Конфет остаётся 24 — меняется способ добраться до нужной.
