Ты запускаешь умножение большой матрицы и хочешь использовать ускоритель. Но где сейчас лежат числа: в обычной памяти компьютера или в памяти видеочипа? Свойство `device`, упомянутое в [шаге 7](#step-7), как раз хранит этот «адрес вычислений».

У PyTorch есть три распространённых варианта: `cpu` — центральный процессор, `cuda` — видеокарты NVIDIA, `mps` — графический процессор современных Mac с Apple Silicon. Подходящее устройство можно выбрать с запасным вариантом:

```python
if torch.cuda.is_available():
    device = torch.device("cuda")
elif torch.backends.mps.is_available():
    device = torch.device("mps")
else:
    device = torch.device("cpu")

x = torch.randn(3, 4, device=device)
```

Устройство не меняет форму или значения тензора — оно определяет, где PyTorch будет выполнять операции над ним. Уже созданный тензор можно перенести:

```python
x = x.to(device)
x = x.cpu()
```

Обрати внимание на присваивание: `.to(device)` возвращает тензор на выбранном устройстве, поэтому результат нужно сохранить.

А что произойдёт, если `x` лежит на GPU, а второй тензор — на CPU? PyTorch не станет незаметно переносить данные и остановится с сообщением `Expected all tensors to be on the same device`. Перед операцией её участники должны оказаться вместе. Перенос тоже занимает время, поэтому постоянно гонять тензоры между CPU и GPU невыгодно.

> 🎒 **На пальцах.** Представь две кухни в разных зданиях: на одной лежит тесто, на другой — начинка. Повар не сможет собрать пирог, пока продукты не окажутся на одной кухне. `device` сообщает, где лежит каждый ингредиент, а `.to(device)` организует доставку. CUDA и MPS могут готовить быстрее, но каждая лишняя поездка всё равно требует времени.
