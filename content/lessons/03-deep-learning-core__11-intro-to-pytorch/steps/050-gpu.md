title: Модель и каждый батч нужно переносить на одно и то же устройство
source_anchor: '### GPU Training'
---

Ты запускаешь знакомый цикл из [шага 46](#step-46): модель уже перенесена на CUDA, но на первом же `model(inputs)` PyTorch сообщает, что тензоры находятся на разных устройствах. Почему GPU не забрал данные автоматически?

`model.to(device)` переносит только содержимое модели: все её параметры и служебные буферы, включая вложенные слои. А `DataLoader` из [шага 42](#step-42) обычно выдаёт очередной батч в памяти CPU. Получается конфликт: веса модели лежат на GPU, а изображения — на CPU. Выполнить одну операцию над ними нельзя, потому что вычисление должно происходить в одном месте.

Поэтому модель переносят один раз, а каждый новый батч — внутри цикла:

```python
device = torch.device(
    "cuda" if torch.cuda.is_available() else "cpu"
)
model = model.to(device)

for inputs, targets in loader:
    inputs = inputs.to(device)
    targets = targets.to(device)

    outputs = model(inputs)
    loss = criterion(outputs, targets)
```

Обрати внимание на присваивание: `inputs.to(device)` возвращает тензор на выбранном устройстве, поэтому результат нужно сохранить. Метки `targets` тоже переносятся: функция потерь сопоставляет их с `outputs`, которые модель создала там же, где находятся её параметры.

Если CUDA недоступна, `device` станет CPU — код не изменится и продолжит работать. Выбор устройства делается один раз, а затем последовательно применяется ко всем участникам вычисления.

> 🎒 **На пальцах.** Представь футбольный матч: модель — команда, а батч — мяч и судейские карточки. Отправить команду на поле недостаточно, если мяч остался в раздевалке. `model.to(device)` выводит игроков, а вызовы `.to(device)` для каждого батча каждый раз приносят на то же поле мяч и карточки. Только тогда матч может начаться.
