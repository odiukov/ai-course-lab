Ты запускаешь готовые функции по отдельности — числа выглядят разумно. Но после нескольких эпох PPO внезапно теряет смысл: если внутри цикла пересчитать старые логарифмы или преимущества, следующие минибатчи уже будут сравниваться с движущейся точкой отсчёта.

Напиши `ppo_update`, которая получает один завершённый ролаут и проводит по нему заданное число эпох. В начале она должна использовать уже сохранённые `log_pi_old` из [шага 20](#step-20) и один раз подготовленные нормированные преимущества из [шага 21](#step-21). Затем на каждой эпохе перемешай индексы переходов, раздели их на минибатчи и для каждого вызови `ppo_actor_step` из [шага 30](#step-30). Здесь же обновляй критика по целевым значениям и учитывай энтропийный бонус, не меняя данные исходного ролаута.

Функция должна вернуть обновлённые параметры и сводные показатели всего обновления: средний loss, clip fraction из [шага 25](#step-25) и approximate KL из [шага 27](#step-27). Усредняй их по числу обработанных переходов, а не просто по минибатчам: последний минибатч может оказаться меньше остальных.

Главная проверка: эпох много, политика меняется после каждого минибатча, но `log_pi_old`, advantages и targets во всех проходах остаются тем же снимком из [шага 31](#step-31). Именно эта неподвижная опора превращает повторное использование ролаута в PPO-обновление.

> 🎒 **На пальцах.** Представь лабораторию, куда принесли один запечатанный образец почвы. Ты можешь несколько раз исследовать его разными приборами и после каждого измерения настраивать оборудование. Но нельзя незаметно подменить образец или переписать исходный протокол: тогда результаты разных проходов уже не относятся к одной точке отсчёта. Ролаут — тот самый образец, а `ppo_update` организует повторные измерения.
