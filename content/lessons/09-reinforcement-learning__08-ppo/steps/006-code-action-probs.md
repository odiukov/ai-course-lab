Ты передаёшь состоянию `s` параметры политики `theta` и получаешь несколько чисел — по одному для каждого возможного действия. Пока это лишь `logits`: они могут быть отрицательными и не обязаны складываться в единицу. Выбирать действие по ним напрямую нельзя.

Твоя задача — написать `action_probs(theta, s)`. Функция должна:

- получить признаки состояния через `state_features(s)`;
- вычислить `logits(theta, ...)`;
- превратить логиты с помощью `softmax` в массив вероятностей;
- вернуть весь массив, а не только вероятность самого вероятного действия.

Проверь результат на простом состоянии. Число элементов должно совпадать с количеством действий, каждое значение должно лежать между 0 и 1, а их сумма — быть близкой к 1. Действие с большим логитом должно получить большую вероятность, но функция не должна сама выбирать победителя: выбор позже сделает `sample`.

Зачем возвращать весь массив? Во время ролаута из него сначала выбирается действие `a`, а затем сохраняется именно `log(probs[a] + 1e-12)`. Это и есть неизменяемый снимок старой политики, о котором шла речь в [шаге 5](#step-5). Добавка `1e-12` нужна в момент вычисления логарифма: она не даёт случайному нулю превратиться в минус бесконечность.

Главная проверка простая: одна и та же выдача `action_probs` должна служить и для выбора действия, и для записи вероятности этого выбранного действия.

> 🎒 **На пальцах.** Представь пульт с тремя кнопками доставки: велосипед, машина и пешком. Политика выставляет каждой кнопке вес, а `action_probs` переводит веса в доли общего шанса — например, 20%, 70% и 10%. Курьер выбирает одну кнопку случайно по этим долям, после чего ты записываешь шанс именно нажатой кнопки. Остальные шансы были нужны для выбора, но в снимок ролаута не попадают.
