В редакторе тебя ждёт один переход: признаки состояния `x`, выбранное действие, сохранённый `log_pi_old` и замороженный `advantage`. Нужно изменить матрицу весов актёра `theta` ровно на один шаг. Главная ловушка — посчитать PPO-цель, но обновить веса обычным градиентом, забыв, что клиппинг иногда полностью выключает переход.

Сначала получи вероятности текущей политики через функцию из [шага 6](#step-6), затем найди новый логарифм вероятности выбранного действия и передай его в `importance_ratio` из [шага 8](#step-8). Старый логарифм бери только из аргумента: пересчитывать или изменять его нельзя, как разобрано в [шаге 20](#step-20).

Дальше `surrogate_gradient_scale` из [шага 17](#step-17) должен решить, насколько сильно этот переход влияет на актёра. Если выгодное действие уже достигло верхней границы либо невыгодное — нижней, масштаб станет нулём. Обрати внимание на сами границы: при `ratio == 1 + eps` для положительного преимущества и `ratio == 1 - eps` для отрицательного обновление уже остановлено.

Для градиента логарифма политики используй разность между one-hot-вектором выбранного действия и текущими вероятностями. Каждый вес получает произведение четырёх частей: `lr`, масштаба PPO, соответствующего элемента этого градиента и признака `x[j]`. Здесь нужен подъём по цели, поэтому прибавляй изменение к `theta`. Функция меняет только актёра: критик, энтропия, эпохи и минибатчи пока остаются за её пределами.

> 🎒 **На пальцах.** Представь набор стрелок железнодорожной развязки. Вероятности показывают, как часто поезд направляют на каждый путь, а один записанный рейс предлагает слегка переставить все стрелки. `surrogate_gradient_scale` играет роль стоп-сигнала: пока изменение допустимо, команда проходит к каждой стрелке с учётом признаков состояния. Если нужная граница уже достигнута, загорается красный — и вся команда для этого рейса превращается в ноль.
