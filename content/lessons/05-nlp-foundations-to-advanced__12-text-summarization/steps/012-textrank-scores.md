У тебя есть список предложений и таблица их похожести, но все оценки пока равны `1.0`. Если просто один раз передать вес соседям, результат будет зависеть лишь от ближайших связей. Нужно повторять передачу: важные предложения постепенно усиливают связанные с ними, а оценки перестают заметно меняться.

Напиши `textrank_scores`, которая принимает список `sentences`, параметры `damping`, `iterations` и `epsilon`, а возвращает оценки в том же порядке, что и предложения.

Сначала создай квадратную матрицу похожести. На пересечении предложения с самим собой оставь ноль, для остальных пар вызови `similarity` из [шага 9](#step-9). Затем задай каждому предложению начальную оценку `1.0`.

На каждом раунде собирай новый список оценок с нуля — точнее, с базового значения `1 - damping`, смысл которого разобран в [шаге 11](#step-11). Для предложения `i` посчитай сумму всех исходящих похожестей. Его текущий вес нужно распределить между связанными предложениями пропорционально силе каждой связи и умножить на `damping`. Важно: весь раунд использует старый список `scores`. Если обновлять его по ходу обхода, поздние предложения окажутся в более выгодном положении.

После раунда найди максимальное изменение одной оценки. Если оно меньше `epsilon`, можно остановиться раньше; иначе продолжай, но не более `iterations` раз. Для пустого списка сразу верни пустой результат, а для строки без связей не допускай деления на ноль.

> 🎒 **На пальцах.** Представь сеть резервуаров, соединённых трубами разной ширины. На каждом такте каждый резервуар распределяет накопленную воду по своим трубам: через широкую уходит больше, через узкую — меньше. Сначала уровни скачут, затем почти перестают меняться. `epsilon` — отметка на линейке: если самый большой сдвиг уже меньше неё, следующий такт почти ничего не изменит.
