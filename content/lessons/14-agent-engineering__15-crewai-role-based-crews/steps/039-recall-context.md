В новом прогоне приходит задача: «Подготовь условия возврата для клиента “Север”». В памяти есть десятки похожих случаев, а отдельно — точные факты о «Севере». Если просто вставить всё в промпт, важная строка утонет в шуме. Если искать только по словам задачи, можно получить чужие правила возврата.

Допиши `recall_context` так, чтобы она собирала контекст именно для текущего запроса. Функция должна принимать текст задачи и, если он известен, ключ сущности. Затем она делает два разных обращения: ищет несколько подходящих фрагментов long-term memory по смысловой близости и получает факты entity memory по точному ключу. Разницу между этими поисками ты разбирал в [шагах 35](#step-35) и [37](#step-37).

На выходе нужен один компактный текст, который позже можно добавить в промпт. Раздели найденное по источникам, не выводи пустой раздел и сохрани найденные факты без пересказа. Если ничего нет, верни нейтральный пустой результат, а не придумывай сведения.

Обрати внимание на границу ответственности: `recall_context` не выполняет задачу агента и не сохраняет новые воспоминания — этим занималась `remember` из [шага 36](#step-36). Она только извлекает подходящее в момент сборки промпта. Именно это превращает несколько хранилищ в contextual memory, описанную в [шаге 38](#step-38): контекст появляется по запросу, а не едет в каждом промпте целиком.

> 🎒 **На пальцах.** Представь гардеробщика с двумя системами поиска. По описанию «длинное тёмное пальто» он просматривает похожие вещи, а по номерку `184` идёт к одной точной вешалке. `recall_context` принимает оба результата, убирает пустые руки и передаёт тебе только подходящую одежду. Она ничего не шьёт и не кладёт в гардероб — лишь достаёт нужное к этому моменту.
