Твоя функция получила кандидата `x`, но сразу возвращать его нельзя: в областях, где `proposal_sample()` выдаёт значения чаще нужного, результат исказится. Поэтому каждый кандидат проходит отдельную проверку из [шага 11](#step-11).

Создай `rejection_sample(target_pdf, proposal_sample, proposal_pdf, M)`. Она должна повторять один и тот же цикл, пока не появится принятый кандидат:

1. Вызвать `proposal_sample()` и сохранить предложенное значение `x`.
2. Получить случайное число `u` от 0 до 1.
3. Вычислить порог принятия как отношение `target_pdf(x)` к `M * proposal_pdf(x)`.
4. Вернуть `x`, только если `u` меньше порога. Иначе начать следующую попытку.

Обрати внимание: при отказе функция ничего не возвращает. `return` должен находиться только в ветке принятия, а сам цикл — продолжаться без заранее заданного числа попыток.

Параметр `M` должен быть выбран так, чтобы `M * proposal_pdf(x)` нигде не опускалась ниже `target_pdf(x)` на рассматриваемом диапазоне. Тогда порог остаётся не больше 1. Если у предложения нулевая плотность там, где целевая плотность положительна, такое предложение для задачи не подходит: деление на ноль здесь лишь обнаруживает более глубокую ошибку выбора распределения.

Для проверки вызови функцию много раз и построй гистограмму результатов. При усечённой нормали за границами разрешённого интервала не должно быть ни одного значения, а внутри должна проявиться форма нормального распределения. Несколько отдельных результатов этого не покажут — смотри именно на всю выборку.

> 🎒 **На пальцах.** Представь турникет с меняющейся строгостью проверки. `proposal_sample()` подводит следующего посетителя, а отношение плотностей задаёт высоту планки для его пропуска. Случайное `u` — номер на жетоне посетителя. Если номер ниже планки, турникет открывается и функция возвращает `x`; если выше, посетитель уходит, а очередь подводит нового.
