В [шаге 14](#step-14) ты уже расписал, что делает $M_k$ с вектором: каждая строка матрицы даёт одно число на выходе. Теперь это надо превратить в код на голом Python — ни numpy, ни оператора `@` в игрушке нет, только списки.

Первый вопрос, который придётся решить: как вообще лежит матрица. Договоримся хранить её как список строк — `M[j]` это j-я строка, а `M[j][m]` — число на пересечении строки j и столбца m. Тогда `matvec(M, x)` должна вернуть список, где j-й элемент — сумма произведений `M[j][m] * x[m]` по всем m. Длина ответа равна числу строк, а длина каждой строки обязана совпадать с длиной `x`.

Вот тут и живёт главная ловушка. В игрушечной версии два источника складываются, а не склеиваются, поэтому вектор остаётся длины h, и матрица получается квадратной — h на h. Если ты случайно напишешь внешний цикл по столбцам, а внутренний по строкам, программа не упадёт: длины сойдутся, на выход приедет список правильного размера, просто с числами транспонированной матрицы. Ошибка будет тихой.

Как её поймать? Возьми единичную матрицу 3 на 3 — единицы по диагонали, нули вокруг — и `x = [1, 2, 3]`. Результат обязан быть ровно `[1, 2, 3]`. Потом подставь несимметричную матрицу 2 на 3: если перепутал индексы, код упадёт на длине — и это лучший исход.

Симметричный тест ничего не проверяет — проверяет только кривая матрица.

> 🎒 **На пальцах.** Матрица — меню кофейни. Каждая строка — рецепт напитка: сколько ложек кофе, молока, сиропа. Вектор `x` — сколько у тебя каждого ингредиента. Идёшь по рецептам сверху вниз, внутри каждого — по ингредиентам, и получаешь по числу на напиток. Перепутаешь порядок циклов — пройдёшь по ингредиентам как по рецептам. Список выйдет той же длины, а напитки в нём чужие.
