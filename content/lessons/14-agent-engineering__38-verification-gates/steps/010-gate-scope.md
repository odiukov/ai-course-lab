В отчёте есть три списка: затронутые файлы, запрещённые записи и изменения вне разрешённой области. Например, агент изменил `src/app.py`, хотя ему разрешили только `tests/test_app.py`. Сам отчёт уже обнаружил расхождение; твоя функция не должна повторно исследовать файловую систему.

Напиши `gate_scope` так, чтобы она читала готовый `scope_report` и превращала нарушения в находки формата из [шага 6](#step-6). Смотри отдельно на:

- `forbidden_writes` — записи в явно запрещённые места;
- `off_scope_writes` — изменения за пределами задания;
- соответствие реально затронутых файлов списку `scope.allowed_files`.

Не смешивай эти случаи: их различие разобрано в [шаге 9](#step-9). Для каждого непустого списка создай понятную находку со стабильным кодом, описанием проблемы и конкретными путями в evidence. Запрещённая запись должна иметь severity `block`, несовпадение затронутых и разрешённых файлов — `warn`. Для изменений вне области используй переданную функции строгость: политика может считать их предупреждением или блокирующей ошибкой.

Пустой список означает, что нарушение не найдено: добавлять «успешную находку» не нужно. И не выставляй общий `passed` внутри `gate_scope` — сейчас функция только собирает факты. Итоговый вердикт появится позже, когда все находки встретятся в одном месте.

> 🎒 **На пальцах.** Представь реставратора, которому разрешили работать только с одной картиной. Журнал показывает: раму он починил, соседнюю витрину передвинул, а дверь хранилища просверлил. `gate_scope` не ходит осматривать музей заново — он раскладывает записи журнала по карточкам: выход за участок, запрещённое действие и несовпадение с разрешённым списком.
