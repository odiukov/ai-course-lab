В списке приёмки три команды. В журнале есть записи только о двух: первая завершилась с кодом `0`, у второй код выхода `null`. Можно ли пропустить отсутствующую команду и считать `null` успехом? Нет: это два разных провала, и `gate_feedback` должна заметить оба.

Функция не запускает команды повторно — реальный запуск уже разобран в [шаге 7](#step-7). Она сравнивает ожидаемые приёмочные команды с записями в `feedback_record.jsonl` и возвращает список находок:

- для каждой ожидаемой команды должна существовать запись о запуске;
- у найденной записи код выхода не должен быть `null`;
- числовой код выхода должен равняться `0`.

Не смешивай эти случаи. Отсутствующая запись означает «нет доказательства запуска». `null` означает «запись есть, но результат неизвестен». Ненулевой код, например `1`, означает «команда действительно завершилась ошибкой». Для каждого нарушения создай отдельную находку через функцию `finding` из [шага 6](#step-6) с серьёзностью `block` и понятным сообщением: какая команда и что именно с ней не так.

Пройди по ожидаемым командам, найди соответствующую запись и последовательно проверь эти условия. Если все команды присутствуют и у каждой код `0`, верни пустой список: отсутствие находок здесь и есть успешный результат проверки.

Не считай лишнюю запись заменой пропущенной ожидаемой команды. Гейт проверяет не количество строк, а наличие доказательства для каждой конкретной команды.

> 🎒 **На пальцах.** Представь механика перед автогонкой: в чек-листе указаны тормоза, шины и рулевое управление. Две подписи вместо трёх не означают, что машина проверена «на две трети». Пустая графа говорит, что проверку не подтвердили, пометка «результат неизвестен» тоже не разрешает выпуск. Только отдельное подтверждение «исправно» напротив каждого пункта открывает выезд.
