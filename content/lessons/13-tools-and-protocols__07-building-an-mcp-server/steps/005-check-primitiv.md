  - question: >-
      Ты добавляешь в сервер заметок возможность «notes_delete» — удалить
      заметку по номеру. В какой ящик она ложится?
    options:
      - 'Resource: она работает с конкретной заметкой по её номеру'
      - 'Tool: она меняет состояние, после неё заметки больше нет'
      - 'Prompt: она описывает действие, которое хочет человек'
      - 'Сразу в два: tool и resource, потому что нужен номер заметки'
    correct: 1
    explanation: >-
      Признак инструмента — не наличие аргумента, а изменение мира: после вызова
      хранилище заметок другое. Номер заметки тут просто параметр.
  - question: >-
      Клиент хочет получить текст заметки номер 14 и ничего в ней не менять.
      Какая форма для этого правильная?
    options:
      - 'Инструмент notes_read, потому что чтение — тоже действие сервера'
      - 'Промпт read_note, потому что запрос идёт от человека'
      - 'Ресурс notes://14, потому что это чтение данных по адресу'
      - 'Любая из трёх: разница только в названии'
    correct: 2
    explanation: >-
      Чтение без изменений — это ресурс, и адресуется он как notes://14.
      Инструмент понадобился бы, только если бы вызов что-то менял.
---

К этому моменту ты должен уметь взять любую новую возможность сервера заметок и, не заглядывая в спецификацию, сказать, в какой из трёх ящиков она ложится, — по разбору из [шага 4](#step-4).

Спотыкаются обычно на двух местах. Первое: наличие аргумента путают с изменением состояния. «Ей нужен номер заметки, значит это ресурс» — нет; спрашивать надо, изменился ли мир после вызова. Второе: чтение записывают в инструменты, потому что «сервер же что-то делает». Делает, но ничего не меняет — и тогда это адрес вида `notes://14`, а не `notes_read`.

Проверь себя на двух вопросах ниже.
