type: check
title: 'Проверка: tool, resource или prompt'
source_anchor: '## The Problem'
check:
  - question: >-
      Ты добавляешь в сервер заметок возможность «notes_delete» — удалить
      заметку по идентификатору. К какому примитиву MCP она относится?
    options:
      - 'Resource: операция обращается к конкретной заметке'
      - 'Tool: операция изменяет состояние хранилища'
      - 'Prompt: операция описывает намерение пользователя'
      - 'Одновременно tool и resource: заметка имеет идентификатор'
    correct: 1
    explanation: >-
      Удаление изменяет состояние сервера, поэтому это tool. Идентификатор
      заметки — лишь аргумент операции и не превращает её в resource.
  - question: >-
      Клиенту нужно получить содержимое существующей заметки, не изменяя
      хранилище. Какая форма MCP подходит для этого?
    options:
      - 'Инструмент notes_read, поскольку сервер выполняет операцию чтения'
      - 'Промпт read_note, поскольку запрос может исходить от пользователя'
      - 'Ресурс с URI вида notes://{id}, поскольку клиент читает данные по адресу'
      - 'Любой из примитивов: их назначение различается только названиями'
    correct: 2
    explanation: >-
      Данные, доступные для чтения по URI без изменения состояния, представляют
      как resource. Tool предназначен для действий, а prompt — для
      предоставления шаблона сообщений.
---

К этому моменту ты должен уметь взять любую новую возможность сервера заметок и, не заглядывая в спецификацию, сказать, в какой из трёх ящиков она ложится, — по разбору из [шага 4](#step-4).

Спотыкаются обычно на двух местах. Первое: наличие аргумента путают с изменением состояния. «Ей нужен номер заметки, значит это ресурс» — нет; спрашивать надо, изменился ли мир после вызова. Второе: чтение записывают в инструменты, потому что «сервер же что-то делает». Делает, но ничего не меняет — и тогда это адрес вида `notes://14`, а не `notes_read`.

Проверь себя на двух вопросах ниже.
