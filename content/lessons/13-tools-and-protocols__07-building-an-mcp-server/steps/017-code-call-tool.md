У тебя в словаре три заметки. Модель зовёт `notes_get` с `{"id": 999}` — такой заметки нет. Что делать функции: бросить исключение и уронить процесс? Вернуть `None`? Написать в stdout «не нашёл»?

Ни то, ни другое, ни третье. Вспомни форму ответа из [шага 13](#step-13): `tools/call` отдаёт `{content: [...], isError: bool}` — и отдаёт её всегда. Удачный поиск и промах по id выходят из функции одинаково устроенными, разница только в значении флага и в тексте внутри блока. Именно поэтому `call_tool` не имеет права падать: если исключение вылетит наружу, диспетчер из [шага 6](#step-6) останется без ответа на `id`, а клиент — висеть в ожидании.

Твоя задача: написать `call_tool`, которая принимает имя инструмента и словарь аргументов, а возвращает готовый результат. Внутри — разбор по имени: `notes_search` идёт в поиск, `notes_get` достаёт заметку по id. Блоки контента не собирай руками, у тебя для этого уже есть `tool_content` из [шага 15](#step-15).

На что смотреть. `arguments` может прийти пустым или вообще отсутствовать — обращение по ключу без страховки уронит функцию раньше, чем начнётся работа. `content` — список даже для одного блока. Промах по id — это `isError: true` с человекочитаемым текстом, а не молчание (различие — в [шаге 16](#step-16)). И никаких `print` для отладки: stdout занят, правило из [шага 7](#step-7).

Провал инструмента — это тоже результат, просто с другой отметкой.
