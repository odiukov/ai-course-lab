Досчитай строки в `code/main.py` — их около 180. Цикл чтения строк, разбор, таблица методов, сборка `initialize`-ответа, блоки контента, аннотации. А теперь посмотри, как та же самая логика выглядит на FastMCP:

```python
from fastmcp import FastMCP
app = FastMCP("notes")

@app.tool()
def notes_search(query: str, limit: int = 10) -> list[dict]:
    ...
```

Шесть строк вместо ста восьмидесяти. И у TypeScript SDK форма ровно такая же.

Обидно? Первая реакция обычно такая: значит, две трети урока были потрачены зря, надо было сразу брать SDK.

Но посмотри внимательнее на строку `query: str, limit: int = 10`. Схема входа, которую ты вручную выкладывал в `inputSchema` из [шага 13](#step-13), здесь не написана нигде — SDK читает её прямо из аннотаций типов Python. Он же собирает конверт с `id`, он же превращает возвращённый список словарей в типизированные блоки контента из [шага 14](#step-14), он же отвечает на `initialize` и объявляет capabilities. Всё это никуда не исчезло. Оно просто спряталось под декоратор `@app.tool()`.

И вот тут выясняется, зачем были 180 строк. В какой-то момент FastMCP отдаст хосту ответ, который тебя удивит: клиент скажет, что инструмента нет, или покажет пустой результат там, где данные точно есть. Человек, начавший с декораторов, увидит только магию, которая не сработала. Ты увидишь конкретный JSON-RPC-конверт — и сможешь спросить, где именно он разошёлся с ожидаемым.

Переходить на SDK можно в любой момент. Понятия при переходе не меняются — меняется только то, кто печатает строки.

> 🎒 **На пальцах.** Учиться водить на механике: сцепление, передачи, ручник на подъёме. Потом садишься за автомат — коробка делает это сама, ты только газ и тормоз. Но когда на крутом подъёме автомат замешкается перед переключением, ты понимаешь, что там сейчас происходит, а не просто злишься на машину. Декораторы — это автомат. Твои 180 строк — механика.
