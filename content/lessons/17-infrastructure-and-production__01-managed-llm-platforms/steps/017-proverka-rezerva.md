check:
  - question: >-
      При полной загрузке on-demand стоил бы 1200 евро в месяц, а резерв — 600
      евро. Нагрузка держится около 70%. Какой вариант дешевле?
    options:
      - 'Резерв: on-demand при такой загрузке обойдётся примерно в 840 евро'
      - 'On-demand: резерв выгоден только при полной загрузке'
      - 'Стоимость одинакова, потому что оба варианта обслуживают одну модель'
    correct: 0
    explanation: >-
      Точка окупаемости равна 600 / 1200 = 50%. При устойчивой загрузке 70%
      стоимость on-demand достигает примерно 840 евро и превышает фиксированную
      цену резерва.
  - question: >-
      У двух сервисов одинаковый высокий пик нагрузки. Первый работает близко к
      этому уровню большую часть расчётного периода, а у второго пик возникает
      лишь изредка. Для какого сервиса PTU экономически перспективнее?
    options:
      - >-
        Для первого, потому что его зарезервированная мощность используется
        устойчивее
      - >-
        Для второго, потому что редкий пик сам по себе гарантирует окупаемость
        резерва
      - 'Для обоих одинаково, поскольку для выбора важен только максимальный пик'
    correct: 0
    explanation: >-
      Одинаковый пик определяет требуемую мощность, но не её окупаемость. Резерв
      экономически привлекательнее при высокой устойчивой загрузке, а не при
      редких всплесках.
---

Сравнивая варианты, смотри не только на пик, но и на устойчивую загрузку. Граница из [шага 15](#step-15) разделяет два случая: выше неё фиксированный резерв экономит деньги, ниже — ты чаще платишь за неиспользованную мощность. Типичная ошибка — увидеть большой краткий пик и сразу выбрать PTU, хотя большую часть времени резерв может простаивать.
