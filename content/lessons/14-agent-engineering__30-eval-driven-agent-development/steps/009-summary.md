После запуска `run_suite` из [шага 8](#step-8) ты видишь: пройдено 18 случаев из 20. Выглядит отлично — 90%. Но затем замечаешь распределение: benchmark прошёл 10 из 10, custom — 8 из 8, online — 0 из 2. Общий балл верен, однако он спрятал целиком провалившийся слой.

Поэтому сводка должна отвечать сразу на два разных вопроса. Первый: «Каков результат всего набора?» Здесь нужны общее число пройденных и проваленных случаев и итоговая доля прохождения. Второй: «Где именно возникла проблема?» Для этого те же показатели группируются по трём категориям из [шага 2](#step-2): benchmark, custom и online.

Важно показывать даже слой без запущенных случаев. Пустая категория — не то же самое, что успешная: запись «online: 0 случаев» сообщает об отсутствии данных, тогда как «online: 2 из 2» сообщает о прохождении проверки. Если молча пропустить пустой слой, читатель может принять отсутствие проверки за зелёный результат.

Такая сводка не заменяет список отдельных случаев. Список называет конкретную поломку, состояние слоя показывает её область, а общий результат даёт быстрый ответ для гейта. Тебе не приходится выбирать между краткостью и диагностикой: верхняя строка сообщает итог, следующие строки объясняют, из чего он сложился.

> 🎒 **На пальцах.** Представь табло поезда с тремя вагонами. Надпись «занято 90% мест» полезна диспетчеру, но не говорит, что в третьем вагоне вообще не работает освещение. Строка по каждому вагону сразу обнаруживает перекос. Общая цифра отвечает «как поезд в целом», а разбивка — «где нужно вмешаться».
