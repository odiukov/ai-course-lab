В реестре уже лежат случаи из трёх категорий. Ты запускаешь первый — он проходит. На втором агент ошибается. Что делать с третьим: остановиться или всё-таки проверить? Для eval suite нужен второй вариант: провал одного случая не должен скрывать результаты остальных.

Допиши `run_suite` в `code/main.py`. Функция должна пройти по переданным случаям в порядке реестра, для каждого вызвать `run_case` из [шага 6](#step-6) и собрать результаты в один список. Сам агент при этом передаётся во все запуски одинаково: меняется тестовый случай, а не проверяемый объект.

Обрати внимание на две границы ответственности. Во-первых, `run_suite` не повторяет проверку ожидаемого результата — этим уже занимается `run_case`. Во-вторых, она не должна останавливать цикл, когда очередной результат содержит `passed = False`. Такой результат — полезная запись о провале, а не команда прервать программу.

Сохрани порядок результатов тем же, что и в реестре из [шага 7](#step-7). Тогда строку результата легко сопоставить с исходным случаем, а категории `benchmark`, `custom` и `online` не потеряются. Пока не вычисляй общий балл, регрессию или вердикт CI: задача этой функции — полностью выполнить набор и вернуть сырые результаты каждого запуска.

Если после одного провала ты всё ещё видишь состояние остальных случаев, цикл собран правильно.

> 🎒 **На пальцах.** Представь конвейер с пятью чемоданами и контролёра, который записывает результат досмотра каждого. Если во втором чемодане найден запрещённый предмет, конвейер не выключают: оставшиеся всё равно проверяют. `run_case` досматривает один чемодан, а `run_suite` проводит через контроль всю очередь и сохраняет журнал в исходном порядке.
