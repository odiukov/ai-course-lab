Ты прогнал через `select_experts` из [шага 15](#step-15) сто токенов подряд. На экране сто строчек по восемь номеров. И глазами тут не увидишь ничего: перекос из [шага 9](#step-9) может быть чудовищным, а список всё равно выглядит просто как список номеров.

Поэтому и нужен счётчик, про который шла речь в [шаге 28](#step-28) — теперь напишем его сами.

Функция принимает то, что вернул `select_experts` (по каждому токену — список из `k` номеров), и общее число экспертов `E`. Отдаёт один список длиной `E`: на позиции `e` лежит, сколько токенов выбрали эксперта `e`.

Главное — с чего начинать. Заведи список из `E` нулей, потом пройди по всем токенам и по всем их `k` номерам, добавляя единицу в нужную ячейку. Соблазн будет собрать словарь только из тех номеров, которые реально встретились. Тогда эксперт, которого не выбрали ни разу, просто исчезнет из результата — а ведь именно его ты и ищешь. Нули должны быть видны.

Две проверки на выходе. Сумма всех чисел равна `N × k`, а не `N`: каждый токен голосует `k` раз. И идеальная загрузка — тоже `N × k / E`: при 100 токенах, `k=8` и `E=256` это примерно три попадания на эксперта.

И не сортируй результат по убыванию, как просится для красивого отчёта. Позиция в списке — это удостоверение эксперта. Дальше понадобится не «кто лидер», а «сколько досталось именно эксперту 3».

Веса гейта из [шага 17](#step-17) здесь не участвуют вообще: считаем срабатывания, а не вклад.

> 🎒 **На пальцах.** Это подсчёт голосов на выборах с 256 кандидатами, где каждый избиратель ставит в бюллетене восемь галочек. Комиссия не выписывает в протокол только тех, за кого хоть раз проголосовали: строка есть на каждого кандидата, и нули в этих строках — самое интересное место документа. А галочек в сумме в восемь раз больше, чем избирателей, иначе арифметика не сойдётся.
