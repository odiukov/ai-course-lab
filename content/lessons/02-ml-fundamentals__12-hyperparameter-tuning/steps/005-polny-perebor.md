title: Grid search проверяет декартово произведение значений

Ты подготовил для модели три значения скорости обучения: `0.01`, `0.1` и `1.0`. Для максимальной глубины дерева тоже есть три варианта: `3`, `5` и `7`. Можно было бы проверить только три пары: сначала первые значения из обоих списков, затем вторые и третьи. Но тогда, например, сочетание скорости `0.01` с глубиной `7` вообще не попадёт в эксперимент.

Grid search действует иначе: он берёт каждое значение из первого списка и соединяет с каждым значением из второго. Такой полный набор сочетаний называется **декартовым произведением**. Поэтому при трёх скоростях обучения и трёх глубинах получится девять запусков.

Посмотри на порядок перебора. Для скорости `0.01` модель обучится трижды — с глубиной `3`, затем `5`, затем `7`. После этого те же три глубины будут проверены со скоростью `0.1`, а потом со скоростью `1.0`. Ни одна допустимая пара не пропускается.

Если добавить ещё один гиперпараметр, его значения тоже должны сочетаться со всеми уже полученными парами. Именно поэтому число запусков быстро увеличивается, как ты видел в [шаге 4](#step-4): новый список не просто добавляет несколько проверок, а размножает весь существующий набор сочетаний.

Grid search перебирает не значения по очереди, а все возможные способы собрать из них полную настройку модели.

> 🎒 **На пальцах.** Представь шкафчик с тремя рубашками и тремя парами брюк. Ты не складываешь первую рубашку только с первыми брюками, вторую — со вторыми. Чтобы примерить весь гардероб, ты надеваешь каждую рубашку с каждой парой брюк. Девять нарядов и есть декартово произведение двух наборов.
