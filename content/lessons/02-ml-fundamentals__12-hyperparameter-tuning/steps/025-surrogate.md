У тебя уже накопились проверенные конфигурации и их оценки, а перед тобой — новые кандидаты. Обучать настоящую модель для каждого дорого, поэтому суррогат из [шага 24](#step-24) должен вернуть два массива: ожидаемое качество `mu` и неопределённость `var` для каждой новой точки.

Дополни метод `_fit_gp(X_new)`. Он должен:

1. Превратить `X_observed` и `y_observed` в массивы NumPy.
2. Вычесть из оценок их среднее. Так суррогату проще моделировать отклонения, а перед возвратом среднее нужно добавить обратно.
3. Построить матрицу сходства наблюдений через `_kernel`. К её диагонали добавь `1e-4`: эта маленькая поправка защищает вычисления от численной ошибки.
4. Разложить матрицу с помощью `np.linalg.cholesky`, а затем через `np.linalg.solve` получить коэффициенты прогноза. Не вычисляй обратную матрицу напрямую: это менее устойчиво.
5. Посчитать `mu` для всех строк `X_new`.
6. Отдельно вычислить `var` и ограничить её снизу значением `1e-6`, чтобы погрешность округления не оставила отрицательную дисперсию.

Следи за размерами: если в `X_new` лежит 500 кандидатов, и `mu`, и `var` должны содержать ровно 500 чисел. Здесь легко случайно перепутать строки со столбцами — проверяй формы промежуточных массивов. Готовый метод ничего не выбирает: он только сообщает прогноз и степень сомнения для каждого кандидата.

> 🎒 **На пальцах.** Представь оценщика квартир. У него есть цены уже проданных квартир и список из 500 новых адресов. Он сначала сравнивает новые квартиры с известными, затем для каждой записывает две цифры: предполагаемую цену и насколько оценка шаткая. Сам оценщик ещё не решает, какую квартиру покупать, — он лишь готовит аккуратные оценки для следующего решения.
