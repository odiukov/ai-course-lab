Ты проверил первую комбинацию настроек и получил оценку `0.81`. Следующая дала `0.84`. Хочется сразу запомнить второй результат — но впереди ещё несколько вариантов, и любой из них может оказаться лучше.

Допиши `grid_search`, чтобы функция перебрала все комбинации из `param_grid`, обучила отдельную модель для каждой и вернула три результата: лучшие настройки, их оценку и число запусков.

Список комбинаций создай с помощью `itertools.product`. Он выполняет декартово произведение из [шага 5](#step-5). Обрати внимание на соответствие: порядок названий гиперпараметров должен совпадать с порядком списков их значений. Тогда из очередной комбинации можно собрать словарь вроде `{"depth": 3, "learning_rate": 0.1}`.

Для каждой комбинации:

1. Создай новую модель через `model_fn`, передав ей выбранные настройки.
2. Обучи её на `X_train` и `y_train`.
3. Получи оценку на `X_val` и `y_val` через `evaluate`.
4. Увеличь `n_evals`.
5. Если оценка лучше текущего рекорда, одновременно обнови `best_score` и `best_params`.

Не переиспользуй уже обученную модель: иначе следующий запуск начнётся не с чистого листа, и сравнение станет нечестным. Начальную лучшую оценку задай ниже любого возможного результата — тогда первая проверенная комбинация обязательно станет временным победителем. Здесь считается, что большее значение `score` лучше.

В конце проверь: `n_evals` должен совпасть с числом комбинаций в сетке, а возвращённые параметры — принадлежать этой сетке. Функция не угадывает победителя; она честно доводит турнир до последнего участника.

> 🎒 **На пальцах.** Представь дегустацию чая: ты по очереди соединяешь каждый сорт с каждой температурой воды. Для каждой пары завариваешь новую чашку, ставишь оценку и делаешь отметку в счётчике. Табличку «лучший чай» меняешь только при более высокой оценке. Когда сочетания закончились, на табличке остаётся победитель, а счётчик показывает, сколько чашек ты попробовал.
