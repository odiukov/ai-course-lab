Ты провёл несколько запусков и получил список конфигураций. Теперь нужно понять не только их общее число, но и сколько разных значений встретилось у каждого гиперпараметра — именно этот показатель мы обсуждали на [шаге 18](#step-18).

Напиши функцию `count_unique`, которая принимает список словарей с конфигурациями и возвращает словарь с количеством уникальных значений каждого гиперпараметра.

Например, для таких данных:

```python
[
    {"learning_rate": 0.01, "max_depth": 3},
    {"learning_rate": 0.1,  "max_depth": 3},
    {"learning_rate": 0.01, "max_depth": 5},
]
```

результат должен быть таким:

```python
{
    "learning_rate": 2,
    "max_depth": 2,
}
```

Хотя запусков было три, значение `learning_rate=0.01` повторилось, поэтому оно считается только один раз. То же происходит с `max_depth=3`.

Сначала подготовь для каждого ключа отдельную коллекцию, которая не хранит дубликаты. Затем пройди по конфигурациям, добавляя туда соответствующие значения. В конце замени каждую коллекцию её размером.

Главная ловушка — посчитать количество запусков вместо количества разных значений. Повторение увеличивает бюджет поиска, но не расширяет покрытие параметра.

> 🎒 **На пальцах.** Представь альбом с почтовыми штемпелями. Ты получил пять конвертов, но на трёх стоит один и тот же штемпель Лиссабона. Конвертов пять, а разных штемпелей меньше. `count_unique` словно раскладывает штемпели по городам, отбрасывает повторы и сообщает, сколько отдельных образцов оказалось в альбоме.
