Перед тобой три одинаковых поля: по горизонтали меняется `learning_rate`, по вертикали — `max_depth`. На каждом поле можно поставить ровно 28 точек — провести 28 замеров синтетической функции из [шага 33](#step-33). Настоящий максимум известен заранее, поэтому видно не только лучший результат, но и куда ушёл весь бюджет.

Grid search раскладывает точки строгими рядами: четыре значения `learning_rate` сочетаются с семью значениями глубины. Получаются все 28 комбинаций. В этот раз одна из них совпадает с максимумом, потому что нужные значения заранее оказались в списках сетки. Это удачное устройство примера, а не способность grid search угадывать.

Random search тоже делает 28 попыток, но не привязан к четырём вертикальным линиям. Он берёт новые значения независимо, поэтому покрывает больше разных участков пространства. Некоторые точки оказываются близко друг к другу, зато метод может попасть между узлами сетки.

У Bayesian search первые пять точек нужны для начального знакомства с поверхностью. Затем каждый новый результат меняет суррогат из [шага 24](#step-24), а следующая точка выбирается с учётом уже увиденного. Поэтому поздние замеры чаще собираются возле перспективной области, хотя часть бюджета всё ещё уходит на проверку неизведанных мест.

Число точек одинаковое; различается то, сколько информации метод извлекает из каждой следующей точки.

> 🎒 **На пальцах.** Представь три команды, которым выдали по 28 флажков для поиска самой высокой точки на острове. Первая ставит их по клеткам карты. Вторая разбрасывает по всему острову. Третья сначала ставит пять флажков в разных местах, а потом переносит внимание туда, где предыдущие замеры обещают подъём. Бюджет один, но маршруты расходуют его по-разному.
