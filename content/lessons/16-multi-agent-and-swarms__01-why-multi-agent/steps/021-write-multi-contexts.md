У тебя есть список ролей и общая лента сообщений. Если просто склеить всю ленту для каждого агента, снова получится единый перегруженный промпт — только размноженный несколько раз. Нужно собрать отдельный контекст для каждой роли.

Допиши `multi_agent_contexts`: функция должна пройти по всем ролям и для каждой получить только адресованные ей сообщения. Фильтрацию заново писать не нужно — используй `inbox`, созданный на [шаге 19](#step-19). Результатом должна стать коллекция, где по имени роли можно найти её готовый контекст.

Следи за тремя деталями:

- каждая переданная роль присутствует в результате;
- сообщения сохраняют исходный порядок;
- если агенту ничего не отправили, его контекст остаётся пустым, а не исчезает.

Например, при ролях `researcher`, `coder` и `reviewer` функция создаёт три независимых контекста. Сообщение для `coder` не должно оказаться у `reviewer`, даже если лежит рядом с ним в общей ленте. Именно это разделение было разобрано на [шаге 20](#step-20); теперь ты превращаешь его в работающую функцию.

После реализации мысленно добавь роль без единого сообщения. Если для неё всё равно появляется пустой контекст, а остальные получают только свою почту, границы проведены правильно.

> 🎒 **На пальцах.** Представь гардероб с отдельным крючком для каждого посетителя. Гардеробщик перебирает вещи в порядке поступления и вешает каждую на крючок с нужным номером. Даже если человек ничего не сдал, его крючок существует и остаётся пустым. `multi_agent_contexts` делает то же самое: создаёт место для каждой роли и раскладывает туда только адресованные ей сообщения.
