Ты получаешь замеры трёх стадий: исследование заняло 12 секунд, написание кода — 8, ревью — 5. Что должна показать система пользователю: 12, 8 или 25 секунд?

Реализуй `pipeline_seconds`. Функция принимает список длительностей отдельных стадий и возвращает полное время выполнения pipeline. Используй правило из [шага 27](#step-27): следующая стадия начинает работу только после завершения предыдущей, поэтому учитывается время каждой стадии.

Проверь себя на нескольких случаях:

- для `[12, 8, 5]` результат должен быть `25`;
- одна стадия `[7]` занимает `7` секунд;
- пустой pipeline `[]` занимает `0` секунд;
- одинаковые значения тоже считаются отдельно: `[4, 4, 4]` дают `12`, а не `4`.

Не привязывай функцию к трём агентам: список может содержать любое количество стадий. Также не нужно разбираться, какая длительность относится к исследователю, кодеру или ревьюеру. Для расчёта важны только числа и их последовательное выполнение.

Если одна стадия занимает дольше остальных, она увеличивает итог, но не заменяет собой остальные. Pipeline заканчивается лишь тогда, когда прошла вся цепочка.

> 🎒 **На пальцах.** Представь передачу срочного документа через несколько кабинетов. Секретарь тратит 3 минуты, юрист — 10, директор — 2. Документ нельзя сразу положить на стол директору: каждый получает его только после предыдущего. Поэтому ты считаешь весь путь документа, включая короткие и длинные остановки.
