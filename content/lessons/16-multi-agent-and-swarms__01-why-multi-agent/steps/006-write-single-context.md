Теперь тебе предстоит превратить механику из [шага 5](#step-5) в функцию `single_agent_context`. Представь три стадии работы: исследование, написание кода и ревью. После каждой стадии появляется новый текст, но следующий вызов получает не только его — в промпт снова попадает всё накопленное ранее.

Внутри функции заведи одну общую коллекцию для результатов стадий. После исследования добавь в неё первый результат. Перед написанием кода собери содержимое коллекции в один текст и передай его следующему вызову. Полученный код тоже сохрани. Для ревью повтори то же действие: склей уже два результата и добавь инструкцию проверить решение.

Обрати внимание на порядок операций. Сначала вызывается модель, затем её ответ попадает в общий контекст, и только после этого начинается следующая стадия. Если добавить результат слишком поздно, следующая стадия его не увидит. Если заменить коллекцию новым ответом, исчезнет накопление, ради которого мы пишем эту функцию.

В конце верни объединённое содержимое, суммарное число использованных токенов и общее количество вызовов инструментов. Эти счётчики увеличивай после каждой стадии данными соответствующего ответа. Здесь важна не хитрая конструкция, а точное воспроизведение перегруженного цикла: один контекст хранит всю историю и становится входом для каждой следующей работы.

> 🎒 **На пальцах.** Представь монтажёра, который перед каждой новой правкой экспортирует весь фильм целиком. Сначала в файле одна сцена, затем две, потом три. Новая сцена действительно учитывает предыдущие, но вместе с полезной связностью растёт и объём повторно обрабатываемого материала. `single_agent_context` должна воспроизвести именно такой монтажный процесс.
