В журнале лежат три сообщения: исследователь пишет кодеру, кодер — ревьюеру, а ревьюер — оркестратору. Ты вызываешь `inbox(messages, "reviewer")`. Что должно вернуться? Не весь журнал, а только текст, адресованный ревьюеру:

```text
[From coder]: Проверь обработку пустого списка
```

Твоя задача — написать функцию `inbox`. Она принимает массив сообщений с контрактом из [шага 17](#step-17) и имя получателя, а возвращает строку для входного контекста этого агента.

```typescript
function inbox(
  messages: AgentMessage[],
  recipient: string
): string {
  // Твоя реализация
}
```

Собери результат в три действия: оставь сообщения, у которых поле `to` точно совпадает с `recipient`; преврати каждое в строку формата `[From отправитель]: содержимое`; соедини строки символом переноса строки. Именно такой почтовый ящик был разобран в [шаге 18](#step-18).

Обрати внимание на две детали. Порядок сообщений должен остаться тем же, что и в исходном массиве: более раннее письмо не должно внезапно оказаться после позднего. Поля `timestamp` и `to` в итоговый текст не входят — они помогают доставить сообщение, но агенту достаточно видеть отправителя и содержание.

Проверь и пустой случай: если получателю ничего не адресовано, функция должна вернуть пустую строку, а не `undefined` и не пояснение от себя. Так один общий журнал превращается в аккуратный вход ровно для одного агента.

> 🎒 **На пальцах.** Представь кухню ресторана: на стойке стоят блюда для столиков 3, 7 и 12. Официант столика 7 забирает только тарелки с цифрой 7, сохраняя порядок подачи. Если таких тарелок нет, он уходит с пустым подносом — не берёт чужой заказ и не придумывает блюдо сам.
