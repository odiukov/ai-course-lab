title: 'Почему независимая работа, выполненная по очереди, становится узким местом'

---

Тебе нужно проверить три независимые части проекта: настройки авторизации, тесты оплаты и документацию внешнего API. Ни одна проверка не ждёт результатов другой. Но один агент сначала читает настройки, делает запрос к модели и запускает инструмент; затем повторяет этот круг для тестов; потом — для документации.

Допустим, каждый круг занимает пять секунд. Первая проверка закончится через пять секунд, вторая — через десять, третья — через пятнадцать. Полезной работы здесь три раза по пять секунд, но для тебя важна другая величина — сколько времени прошло до готового результата. Это время называют задержкой выполнения.

Почему агент не переключается между задачами быстрее? Один агентный цикл в каждый момент продолжает только одну цепочку действий. Даже если задачи независимы, остальные стоят в очереди. Именно это и есть последовательное узкое место, упомянутое в [шаге 3](#step-3): скорость всей работы ограничена скоростью одного исполнителя.

Важно не перепутать независимость с порядком. Если тесты можно запускать только после изменения кода, ожидание оправданно: вторая задача зависит от первой. Но когда три проверки не используют результаты друг друга, очередь не добавляет точности — она лишь складывает их длительности. Возможность сократить ожидание появляется именно в таких местах: независимые ветви можно выполнять одновременно.

> 🎒 **На пальцах.** Представь автомойку с одним постом и тремя машинами. На каждую нужно пять минут, поэтому последняя выедет через пятнадцать. Машины никак не связаны: мойка первой не помогает мойке второй. Если открыть три поста одновременно, объём работы останется тем же — пятнадцать машино-минут, — но все водители получат машины уже через пять минут.
