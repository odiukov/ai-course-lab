Ты запускаешь маршрут из [шага 24](#step-24), исследователь уже подготовил факты — и тут писатель получает пустой контекст. Значит, одного фиксированного порядка мало: `run_static` должна не только вызвать агентов по очереди, но и связать каждый вызов с общим состоянием.

Работай с параметрами, которые уже указаны в заготовке функции. Для каждого агента статического маршрута выполни три действия:

1. Получи его представление общего состояния через написанную в [шаге 19](#step-19) функцию `project`.
2. Передай эту проекцию политике агента и получи новое сообщение.
3. Добавь результат в `SharedState` через `post` из [шага 16](#step-16).

Здесь особенно важен порядок. Если сначала запустить всех агентов, а сообщения сохранить потом, писатель не увидит результат исследователя, а рецензент — черновик писателя. Публикация должна происходить сразу после каждого вызова: следующий участник читает уже обновлённое состояние.

Не выбирай агента по содержанию ответа и не завершай маршрут из-за фразы вроде «работа готова». В статическом режиме последовательность задана заранее, поэтому каждый участник должен отработать ровно в указанном порядке. После последнего агента функция возвращает накопленное состояние в форме, предусмотренной заготовкой.

Проверь себя на тройке `research → write → review`: в пуле должны появиться три новых сообщения в том же порядке, а повторный запуск с одинаковым начальным состоянием должен дать такой же маршрут.

> 🎒 **На пальцах.** Представь поезд с заранее напечатанным расписанием. На каждой станции сотрудник читает записи в путевом журнале, добавляет свою отметку и сразу кладёт журнал обратно в вагон. Если собрать отметки лишь в конце пути, следующая станция не узнает, что произошло на предыдущей. `run_static` ведёт журнал вместе с поездом, не меняя расписание.
