Ты запускаешь `research`, ожидая привычную цепочку из трёх агентов, но после первого ответа выполнение вдруг заканчивается. Это не обязательно ошибка цикла: в handoff-driven режиме списка обязательных остановок нет. Текущий агент сам сообщает, кому передать управление — или не передаёт его вовсе, как описано в [шаге 26](#step-26).

В `run_handoff` собери цикл с переменной `current`, которая хранит текущего агента. На каждом проходе функция должна:

1. Получить для `current` подходящий контекст через написанную в [шаге 19](#step-19) функцию `project`.
2. Запустить политику этого агента.
3. Добавить его ответ в общее состояние через `post` из [шага 16](#step-16).
4. Проверить результат handoff: если указан следующий агент, сделать его новым `current`; если передачи нет — завершить прогон.

Обрати внимание на порядок: сначала ответ попадает в `SharedState`, и лишь затем управление переходит дальше. Иначе новый исполнитель получит проекцию, в которой отсутствует только что сделанная работа.

Не подменяй handoff статическим маршрутом. После `research` нельзя автоматически выбирать `write`, а после `write` — `review`: следующий исполнитель берётся только из решения текущего агента. Добавь также ограничение числа переходов, чтобы ошибочные взаимные передачи не создали бесконечный цикл.

Главная проверка проста: маршрут должен рождаться по ходу выполнения, а общий поток сообщений — сохранять каждый уже выполненный шаг.

> 🎒 **На пальцах.** Представь квест с несколькими комнатами. В каждой комнате ты находишь записку: она либо называет следующую дверь, либо сообщает, что квест окончен. `run_handoff` не носит заранее напечатанную карту маршрута — он читает очередную записку, сохраняет найденную подсказку в журнале и идёт только туда, куда она направляет. Ограничение переходов не даёт двум комнатам отправлять тебя друг к другу бесконечно.
