Ты запускаешь трёх агентов и замечаешь странность: после первого ответа программа останавливается, хотя selector уже умеет назвать следующего участника. Одного выбора недостаточно — нужен цикл, который будет снова спрашивать selector после каждого хода. Именно его ты соберёшь в `run_selector`.

Ориентируйся на контракт из [шага 32](#step-32): функция вызывает selector, запускает выбранного агента, сохраняет его сообщение в общем состоянии и повторяет процесс. Перед первым выбором последнего говорившего ещё нет, поэтому `last_speaker` должен начинаться с пустого значения. После успешного запуска запиши туда выбранного агента — иначе `round_robin_selector` из [шага 31](#step-31) будет каждый раз видеть один и тот же вход.

Проследи за четырьмя деталями:

- selector получает актуальное общее состояние и `last_speaker`;
- агент работает с подходящей ему проекцией состояния из [шага 19](#step-19);
- результат добавляется через уже написанный `post` из [шага 16](#step-16);
- цикл заканчивается, когда selector не возвращает следующего агента или достигнут лимит шагов.

Лимит нужен даже для корректного selector: ошибка политики может заставить агентов ходить бесконечно. При этом повторный выбор одного и того же агента сам по себе не ошибка — `run_selector` исполняет решение, а не исправляет его.

Не зашивай в функцию порядок `research → write → review`. Тогда она перестанет быть универсальным исполнителем selector-политики. Её задача проще: спросить, запустить, записать, обновить последнего говорившего — и снова спросить.

> 🎒 **На пальцах.** Представь ведущего викторины. Перед первым вопросом ещё никто не отвечал. Ведущий выбирает участника, выслушивает ответ, записывает его на табло и только затем решает, кому дать следующий вопрос. `run_selector` ведёт игру, а selector принимает решения. Если ведущий сам начнёт всегда выбирать игроков по кругу, сменить правила викторины уже не получится.
