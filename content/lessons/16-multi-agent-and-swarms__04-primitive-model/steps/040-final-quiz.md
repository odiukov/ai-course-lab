    options:

      - >-
        Исполнители — агенты, blackboard — handoff, возврат имени — shared

    correct: 0

      послушно идущий за этим возвратом, реализует handoff-driven маршрутизацию.
  - question: >-
      Полную историю сообщений заменили отдельным отфильтрованным видом для
      каждой роли, не трогая конфигурации агентов и порядок их запуска. Что
      изменилось в архитектуре?
    options:
      - Только режим shared state
      - Только handoff
      - Agent и orchestrator одновременно
      - Все четыре примитива
    correct: 0
    explanation: >-
      Message pool и projected state — два режима одного примитива: меняется,
      что участник видит, а не кто он и в каком порядке ходит. Маршрутизация и
      конфигурации исполнителей остаются прежними.
  - question: >-
      Агент пишет в общий поток «Теперь пусть работает редактор», но следующего
      говорящего по-прежнему назначает round-robin-селектор. Кто определит
      следующего исполнителя?
    options:
      - Фраза сработает как handoff и вызовет редактора
      - 'Селектор, потому что текст сообщения сам по себе не передаёт право хода'
      - 'Общий поток, который в этот момент становится оркестратором'
      - 'Никто: система завершит работу из-за противоречия'

    explanation: >-
      Handoff — структурированный сигнал, который понимает механизм запуска.
      Просьба в свободном тексте остаётся данными в состоянии; порядок
      исполнителей принадлежит политике выбора.
  - question: >-
      Queue-driven система опустошила очередь, хотя часть ожидаемых результатов
      ещё не получена, и теперь ждёт бесконечно. Где прежде всего искать
      проблему?
    options:
      - В имени последнего отработавшего агента
      - В выбранной модели агентов
      - >-
        В условиях ожидания, завершения и обнаружения дедлока у queue-driven
        оркестратора
      - В выборе между полной историей и проекцией состояния
    correct: 2
    explanation: >-
      Пустая очередь не равна завершённой работе. Отвечает за это оркестратор:
      ему нужны явные условия окончания и детектор «очередь пуста и никто не
      занят дольше порога».
