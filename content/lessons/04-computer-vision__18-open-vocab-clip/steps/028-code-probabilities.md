У тебя есть две картинки и пять названий классов. После сравнения получается таблица оценок размером `2 × 5`, но её числа ещё нельзя читать как вероятности: они не обязаны быть положительными и не складываются в единицу. Теперь допиши `zero_shot_probabilities`, которая превратит каждую строку этой таблицы в отдельное распределение по классам.

Внутри функции собери уже знакомые операции в правильном порядке:

1. Нормализуй строки обоих наборов embeddings с помощью функции из [шага 7](#step-7).
2. Получи все попарные cosine scores функцией из [шага 9](#step-9).
3. Примени переданный масштаб к scores. Если аргумент хранит логарифм масштаба, сначала верни сам масштаб через экспоненту — это различие разобрано в [шаге 12](#step-12).
4. Примени `softmax` по последней оси, то есть по классам внутри каждой строки.

Именно последняя ось здесь критична. Картинки не должны конкурировать друг с другом: для каждой картинки нужна своя сумма вероятностей, равная единице. Поэтому форма результата остаётся `число картинок × число классов`.

При проверке посмотри не только на форму. Сумма каждой строки должна быть близка к `1`, а более высокий score должен давать более высокую вероятность. Не выбирай победивший класс внутри этой функции: сейчас она возвращает все вероятности, а сопоставление лучшего индекса имени класса будет следующим отдельным действием.

> 🎒 **На пальцах.** Представь пульт звукорежиссёра: каждая строка — отдельная песня, а ползунки в ней отвечают за пять музыкальных жанров. Ты усиливаешь различия между показаниями, затем переводишь их в доли общей громкости ровно для этой песни. Настраивать все песни одним общим регулятором нельзя — у каждой должен получиться собственный набор долей с суммой 100%.
