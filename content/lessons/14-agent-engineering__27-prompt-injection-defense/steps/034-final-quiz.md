  - question: >-
      Агент нашёл на странице команду перевести деньги, хотя ты просил только
      сравнить цены. Как должна отреагировать PVE-защита?
    options:
      - 'Исполнить перевод, а затем проверить журнал действий'
      - 'Разрешить перевод, если сайт входит в allowlist'
      - >-
        Отклонить вызов: он возник из недоверенного контента и не соответствует
        цели пользователя
      - >-
        Записать команду в память и запросить подтверждение при следующем
        запуске
    correct: 2
    explanation: >-
      Allowlist разрешает посещение адреса, но не делает инструкции со страницы
      доверенными. Валидатор должен сопоставить вызов с твоей целью до любого
      внешнего эффекта.
  - question: >-
      Страница содержит полезную цену и скрытую инструкцию сохранить секрет в
      долгосрочную память. Что безопаснее сделать?
    options:
      - 'Сохранить весь текст, но пометить память как подозрительную'
      - >-
        Сохранить только проверенный факт с источником, а исходный контент
        оставить во внешнем хранилище
      - 'Удалить источник после извлечения цены, чтобы память не разрасталась'
      - 'Сохранить всё, если маркеры инъекции ничего не нашли'
    correct: 1
    explanation: >-
      Запись в память пересекает новую границу доверия. В память проходит только
      проверенный факт с происхождением, а исходник сохраняется отдельно для
      расследования.
  - question: Какое разделение ролей лучше защищает опасный инструмент?
    options:
      - 'Один агент предлагает вызов, сам проверяет его и сразу исполняет'
      - >-
        Браузер блокирует подозрительные слова, после чего любой вызов считается
        безопасным
      - >-
        Proposer предлагает вызов, независимый validator решает его судьбу,
        executor исполняет только одобренное
      - >-
        Executor сначала выполняет вызов в тестовом режиме, а validator
        оценивает результат
    correct: 2
    explanation: >-
      PVE не позволяет одному и тому же рассуждению незаметно превратить
      найденный текст во внешний эффект. Executor получает только вызов,
      прошедший отдельную проверку.
  - question: >-
      После запуска защиты все атаки блокируются, но треть обычных запросов тоже
      получает отказ. Что это означает?
    options:
      - 'Защита готова: безопасность важнее любых отказов'
      - Нужно тестировать только более сложные атаки
      - >-
        Правила слишком широки: измерение хорошего трафика выявило высокую долю
        ложных отказов
      - >-
        Следует убрать происхождение контента, чтобы validator видел меньше

    correct: 2
    explanation: >-
      Защиту оценивают не только по заблокированным атакам, но и по сохранённой

Тебе предстоит собрать меры урока в одну границу безопасности: браузер приносит контент вместе с происхождением, память принимает только проверенные факты, а опасный инструмент остаётся за PVE. Не перепутай сигналы с решениями: маркер инъекции повышает подозрение, allowlist ограничивает адреса, но ни то ни другое само по себе не разрешает действие. Решение появляется только после проверки цели, источника и чувствительности вызова — до исполнения.

> 🎒 **На пальцах.** Представь съёмочную площадку с пиротехникой. Сценарист может предложить взрыв, инспектор отдельно сверяет сцену и условия, а техник нажимает кнопку только по подписанному допуску. Записка, найденная среди декораций, не становится частью сценария лишь потому, что выглядит убедительно.
