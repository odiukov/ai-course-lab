У тебя уже есть две заготовки: `patchify` из [шага 6](#step-6) извлекает содержимое патчей, а `position_embedding` из [шага 8](#step-8) кодирует их координаты. Теперь попробуй соединить их — и легко получить ошибку формы: содержимое патча может занимать сотни чисел, а позиционный вектор иметь размер скрытого представления трансформера.

В функции `patch_tokens` сначала вызови `patchify`. Получится последовательность формы `[N, patch_dim]`, где `N` — число патчей, а `patch_dim` — количество значений внутри одного распрямлённого патча. Затем пропусти каждый патч через переданный линейный слой `projection`. Он должен заменить `patch_dim` признаков на `d_model` признаков, не меняя количество патчей: ожидаемая форма станет `[N, d_model]`.

После этого запроси позиционные векторы для тех же `N` патчей и сложи их с проекциями, как обсуждалось в [шаге 9](#step-9). Здесь сложение должно быть попарным: первый патч получает позицию первого патча, второй — второго. Проверь, что оба тензора перед сложением имеют одинаковую форму `[N, d_model]`. Если один вектор неожиданно добавился ко всем строкам, значит сработало автоматическое растягивание размеров, а соответствие позиций потерялось.

Верни именно получившуюся последовательность токенов. Простая самопроверка: `N` сохраняется на всём пути, а последняя размерность меняется с `patch_dim` на `d_model`.

> 🎒 **На пальцах.** Представь стопку анкет нестандартного размера. `projection` перепечатывает каждую анкету на карточку единого формата, а `position_embedding` добавляет адрес её места в картотеке. Складывать данные с адресом можно лишь после перепечатки: карточки должны совпадать по размеру. Число карточек при этом не меняется — меняется только язык, на котором записано содержимое.
