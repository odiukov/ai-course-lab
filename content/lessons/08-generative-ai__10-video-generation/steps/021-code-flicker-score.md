У тебя уже есть `frame_deltas` из [шага 19](#step-19): она возвращает последовательность локальных скачков между соседними кадрами. Теперь представь, что для одного клипа она выдала несколько чисел. Сравнивать две модели по таким спискам неудобно: один клип может быть спокойнее в начале, другой — в конце. Нужна одна итоговая оценка.

Допиши `flicker_score`, которая принимает видео формы `[T, C, H, W]`, передаёт его в `frame_deltas` и усредняет полученные значения. Результатом должен быть один скаляр: чем он меньше, тем плавнее клип меняется от кадра к кадру.

Обрати внимание на границу ответственности функций. `frame_deltas` уже усреднила разницу по каналам и пикселям, поэтому повторно обрабатывать размеры `C`, `H` и `W` не нужно. Твоя функция работает только со списком переходов. Не сравнивай каждый кадр с первым и не дели результат на число кадров: переходов между кадрами на один меньше.

Проверь себя на двух простых случаях. У полностью одинаковых кадров оценка должна быть нулевой. Если увеличить один из скачков, итоговая оценка должна вырасти. После этого числа вроде `joint=0.61` и `independent=1.31` становятся сопоставимыми: каждое описывает весь клип, а не отдельный переход.

> 🎒 **На пальцах.** Представь контролёра в вагоне метро: после каждого перегона он записывает, насколько сильно трясло. Отдельные записи показывают проблемные участки, но для сравнения двух маршрутов нужна одна оценка поездки. Контролёр складывает значения и находит среднее. `frame_deltas` даёт записи по перегонам, а `flicker_score` превращает их в итоговую «тряскость» клипа.
