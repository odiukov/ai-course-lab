Ты автор сервера. Алгоритм у тебя в голове уже готов: обойти дерево файлов, выбрать пять самых важных, прочитать их, потом одним запросом собрать описание. Двух вызовов модели хватит. Осталось решить, кто эти два вызова оплатит.

Из [шага 2](#step-2) один ответ уже отпал: свой ключ — свой счёт, 1000 пользователей по два вызова из твоего кармана. Из [шага 3](#step-3) отпал второй: отдать сырьё наружу дёшево, но твоё «сначала пять файлов, потом описание» уезжает в чужой промпт, и порядком шагов управляешь больше не ты.

Неудобно: платить не хочется, а логику отдавать тоже.

И вот тут есть третья дорога. Сервер не зовёт модель сам и не сваливает работу целиком — он посылает клиенту запрос `sampling/createMessage`: «вот текст, спроси свою модель, верни мне ответ». Клиент подставляет свой ключ, свою модель, свой лимит, при желании показывает пользователю, что именно спросили. Ответ приходит серверу, и сервер продолжает свой цикл: получил список из пяти файлов — читает их, потом отправляет второй запрос, уже на описание.

Посчитай тот же счёт заново. Тысяча пользователей, по два вызова каждый — сервер платит ноль, каждый расходует свой лимит. Ключей у сервера нет вообще никаких, а решение «какие файлы и в каком порядке» осталось там, где его написали. Это и есть sampling: ум сервера, кошелёк клиента.

> 🎒 **На пальцах.** Инструктор по вождению без своей машины. Он не покупает автомобиль и не заливает бензин — садится справа и говорит: «третья передача, теперь направо». Маршрут, порядок команд, разбор ошибок — всё его. Машина, бензин и права — твои. Отбери у него автомобиль — он ничего не потеряет, потому что его и не было. Ровно так сервер работает без ключей: маршрут его, топливо твоё.
