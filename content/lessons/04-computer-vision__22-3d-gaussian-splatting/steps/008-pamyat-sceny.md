check:
  - question: >-
      Почему gaussian_float_count для степени SH 3 и без дополнительных
      признаков должна складывать точные размеры всех атрибутов, а не возвращать
      типичную округлённую оценку?
    options:
      - >-
        Точный результат нужен для расчёта размеров массивов и памяти, а ошибка
        на одной гауссиане накапливается по всей сцене
      - Округление нарушает нормализацию кватерниона
      - Степень SH меняется после каждого вызова функции
      - Видеокарта не умеет хранить неокруглённое число параметров
    correct: 0
    explanation: >-
      Атрибуты дают ровно 59 float: 48 цветовых коэффициентов и 11 остальных
      параметров. Значение 60 подходит для грубой прикидки, но завышает точный
      размер каждого элемента сцены.
  - question: >-
      Какая схема правильно переводит результат gaussian_float_count в объём
      памяти всей сцены?
    options:
      - >-
        Умножить число гауссиан на точное число скаляров одной гауссианы и на
        размер одного скаляра в байтах
      - Умножить число гауссиан только на размер одного скаляра в байтах
      - Считать результат gaussian_float_count уже выраженным в байтах
      - >-
        Учитывать только коэффициенты цвета, поскольку остальные параметры
        памяти не занимают
    correct: 0
    explanation: >-
      Для 5 миллионов гауссиан по 59 float сначала получается 295 миллионов
      скаляров. При 4 байтах на float32 это 1,18 миллиарда байт, или примерно
      1,18 ГБ в десятичной записи.
---

Теперь ты связываешь результат функции из [шага 7](#step-7) с размером всей сцены. Сначала получи точное число float на гауссиану, затем умножь его на число гауссиан и размер одного float в байтах. Чаще всего здесь принимают округлённые 60 float за точный ответ или забывают, что float32 занимает 4 байта.

> 🎒 **На пальцах.** Представь заказ из пяти миллионов одинаковых коробок. Надпись «59 деталей» говорит, сколько лежит внутри одной коробки, но грузовику важен общий вес. Поэтому ты сначала считаешь все детали, а затем переводишь их количество в байты. Округлять коробку до 60 удобно для прикидки, но не для точного подсчёта.
