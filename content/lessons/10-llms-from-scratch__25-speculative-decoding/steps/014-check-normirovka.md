id: 014-check-normirovka
type: check
title: 'Проверка: почему переоценённый черновиком токен получает ноль'
source_anchor: '### The Exactness Rule'
check:
  - question: >-
      Черновик даёт токену «и» вероятность 0.8, а target — 0.2. После отказа
      строится остаточное распределение. Какую вероятность в нём получит токен
      «и»?
    options:
      - Ровно ноль
      - 0.2 — вероятность этого токена у target
      - 0.25 — отношение вероятностей target и черновика
      - 0.6 — разность вероятностей черновика и target
    correct: 0
    explanation: >-
      Для этого токена p − q = 0.2 − 0.8 < 0. Положительная часть разности равна
      нулю, поэтому после нормировки токен не получает вероятности в ветке
      замены.
  - question: >-
      Почему при q(x) > p(x) токен x должен получить нулевой вес в остаточном
      распределении?
    options:
      - Черновые токены после любого отказа запрещено выдавать
      - >-
        Через принятие токен уже получает безусловную вероятность p(x), поэтому
        дополнительная масса из ветки замены исказила бы результат
      - Отрицательные веса допустимы только до завершения раунда
      - >-
        Вероятность токена у target после отказа автоматически становится равной
        нулю
    correct: 1
    explanation: >-
      Когда q(x) > p(x), безусловная вероятность выдать x через принятие равна
      q(x) · p(x) / q(x) = p(x). Вся требуемая масса target уже набрана, поэтому
      в ветке замены этому токену ничего добавлять нельзя.
---

После двух предыдущих экранов у тебя должен быть готов ответ на конкретный вопрос: почему токен, которому черновик дал больше, чем target, вообще не может выйти в качестве замены. Проверь себя не на определении, а на счёте — возьми пару чисел, посмотри, что положительная часть разности обнулилась, и скажи вслух, где этот токен свою вероятность уже забрал.

Спотыкаются обычно в двух местах. Первое: путают ноль в остатке с «токен запрещён навсегда» — он не запрещён, его канал выдачи просто другой. Второе: пытаются проверять баланс по одной ветке, забыв, что итог складывается из принятия и замены вместе.
