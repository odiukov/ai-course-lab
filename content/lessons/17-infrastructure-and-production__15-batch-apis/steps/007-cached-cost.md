Ты запускаешь расчёт для одного документа и замечаешь странность: кэш пока ничего не экономит. Это не ошибка. Первый запрос должен передать общий префикс целиком — только после этого следующие запросы смогут читать его по кэшированной ставке.

В `cached_cost` раздели вход так, как подготовлено в [шаге 6](#step-6): общий префикс и уникальную часть каждого запроса. Общий префикс оплачивается дважды по разным правилам: один раз по полной входной ставке, затем `N - 1` раз по ставке кэшированного чтения. Если запрос всего один, вторая часть естественно становится нулевой.

Уникальный вход не кэшируется: умножь его объём на количество запросов и полную входную ставку. Выход тоже посчитай для всех запросов по обычной выходной ставке. Для перевода токенов в деньги используй тот же принцип расчёта за миллион токенов, что и в функции `sync_cost` из [шага 5](#step-5).

Затем сложи три стоимости: общий префикс, уникальный вход и выход. Функция должна вернуть итог в долларах. Проверь себя на двух случаях: при `N = 1` результат совпадает с обычным расчётом без выгоды от кэша; при росте `N` дешевеет только повторяющийся префикс.

Скидку batch здесь не применяй — она появится позже. Сейчас функция отвечает только на вопрос: сколько стоит синхронная обработка с кэшем.

> 🎒 **На пальцах.** Представь музей с платным оформлением группового пропуска. Для первого посетителя сотрудник заносит все данные группы и берёт полную плату. Остальным достаточно показать уже созданную запись — это дешевле. Но личный билет и аудиогид каждого посетителя всё равно оплачиваются отдельно. Кэш экономит на общей записи, а не превращает весь визит в льготный.
