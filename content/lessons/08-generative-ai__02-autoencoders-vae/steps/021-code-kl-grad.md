В функции KL из [шага 19](#step-19) получается одно число, но кодировщику этого мало: ему нужны отдельные указания, как изменить каждый элемент `mu` и `log_sigma2`. Напиши функцию, которая строит эти указания аналитически — напрямую по производным из [шага 20](#step-20), без сэмплирования `z` и случайных чисел.

Начни с каркаса:

```python
def kl_grad(mu, log_sigma2):
    grad_mu = []
    grad_log_sigma2 = []

    for m, lv in zip(mu, log_sigma2):
        # вычисли обе производные для этой координаты
        ...

    return grad_mu, grad_log_sigma2
```

На каждой итерации `m` и `lv` относятся к одной латентной координате. Добавь соответствующую производную в каждый список. Для градиента по `log_sigma2` понадобится `math.exp(lv)`: важно использовать именно логарифм дисперсии, а не принимать `lv` за саму дисперсию.

Проверь три ориентира. При `m = 0` градиент по среднему должен исчезнуть. При `lv = 0` должен исчезнуть градиент по логарифму дисперсии, потому что это соответствует единичной дисперсии. Длины обоих результатов должны совпадать с длиной входных векторов.

Функция возвращает градиент только самой KL-дивергенции. Если позднее он участвует в полной функции потерь из [шага 17](#step-17), его ещё умножают на `beta`. Здесь этого делать не нужно: иначе коэффициент окажется спрятан внутри вычисления KL.

> 🎒 **На пальцах.** Представь теплицу с несколькими грядками. Для каждой грядки датчики записали два числа: насколько смещён разбрызгиватель и насколько неверна ширина полива. Тебе нужен не общий сигнал «что-то не так», а две ведомости поправок по всем грядкам. `grad_mu` и `grad_log_sigma2` — именно такие ведомости: по одной конкретной команде для каждого параметра.
