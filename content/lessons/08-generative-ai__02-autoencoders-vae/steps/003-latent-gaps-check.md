      Обычный автокодировщик точно восстанавливает обучающие цифры, но случайный

    options:
      - >-

      - Любое случайное число необратимо повреждает веса декодера
      - 'Случайный код обязательно имеет меньшую размерность, чем код энкодера'

    correct: 0
    explanation: >-
      Коды обычного автокодировщика могут занимать отдельные нерегулярные
      области с пустотами между ними. Поведение декодера внутри такой пустоты не
      обязано быть осмысленным.
  - question: >-
      Какого свойства не хватает обычному автокодировщику, чтобы надёжно
      генерировать изображения из выборок z ~ N(0, I)?
    options:
      - 'Гарантии, что коды обучающих данных распределены согласованно с N(0, I)'
      - 'Гарантии, что каждый пиксель восстанавливается строго без ошибки'
      - Запрета на использование дробных координат в латентном коде
      - Отдельного энкодера для каждой генерируемой выборки
    correct: 0
    explanation: >-
      Для генерации выборки из приора должны попадать в освоенные декодером
      области. Обычный автокодировщик не заставляет распределение кодов
      совпадать с N(0, I), поэтому такой способ сэмплирования не обоснован.
---

Здесь важно не перепутать два обещания модели. Как обсуждалось на [шаге 1](#step-1), точное восстановление означает: декодер освоил коды, которые ему показывал кодировщик. Оно не означает, что декодер обучен на любой случайной точке. Поэтому низкая ошибка восстановления ещё не даёт права сэмплировать откуда угодно.

> 🎒 **На пальцах.** Представь несколько камней для перехода через ручей. Ты уверенно наступаешь на каждый отмеченный камень, но случайный шаг между ними может попасть в воду. Обычный автокодировщик учится держать тебя на известных камнях — прочного настила между ними никто не строил.
