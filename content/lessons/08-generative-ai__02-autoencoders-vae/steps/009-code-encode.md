Ты подаёшь в кодировщик один объект `x`, а получить должен сразу два результата. Если случайно построить два независимых маршрута от самого входа, кодировщик будет дважды искать одни и те же признаки. Если же сначала вычислить общую скрытую часть, обе головы смогут работать с одним набором признаков.

Собери функцию `encode(x, enc)` по такому каркасу:

```python
def encode(x, enc):
    # вычисли общее скрытое представление h

    # получи mu из h

    # получи log_sigma2 из того же h

    # верни оба результата
```

Сначала примени знакомое по [шагу 5](#step-5) полносвязное преобразование с параметрами `W1` и `b1`, а затем `tanh`. Получится `h` — общая внутренняя запись входа.

После неё маршруты расходятся, как обсуждалось в [шаге 8](#step-8). Первая голова использует собственные `W_mu` и `b_mu`, чтобы вычислить `mu`. Вторая берёт **то же самое** `h`, но использует `W_sig` и `b_sig`, получая `log_sigma2`. Между головами нет последовательности: `log_sigma2` не вычисляется из `mu`, и наоборот.

На выходах голов `tanh` не ставь: здесь нужны обычные результаты полносвязных преобразований. Верни их парой именно в порядке `mu, log_sigma2`. Проверь три детали: обе головы читают `h`, у каждой свои веса и смещения, а функция возвращает два значения. Один общий анализ входа — два разных описания латентного облака.

> 🎒 **На пальцах.** Представь эксперта, который один раз осматривает квартиру и заполняет общую карточку: площадь, свет, состояние стен. Затем карточку получают два оценщика. Один называет ожидаемую цену, другой — степень неопределённости оценки. Они смотрят на одни признаки, но пользуются разными правилами расчёта. Именно так общее `h` расходится в две независимые головы.
