id: 026-kv-correctness-check
type: check
title: Находим ошибку в обновлении позиции KV-кэша
source_anchor: '### Step 2: Attention with KV Cache'
check:
  - question: >-
      Почему проверка `seq_len == 1` внутри `forward` каждого слоя не защищает
      общий указатель KV-кэша от лишних сдвигов?
    options:
      - >-
        Каждый слой независимо видит однотокенный вход и выполняет сдвиг общего
        указателя
      - Условие становится истинным только после обработки последнего слоя
      - Длина входа автоматически сбрасывает указатель перед каждым слоем
    correct: 0
    explanation: >-
      Один и тот же decode-токен последовательно проходит через все слои.
      Поэтому условие истинно в каждом вызове слоя, и размещённый там `advance`
      выполняется многократно.
  - question: >-
      Какой инвариант должен соблюдаться при записи одного decode-токена в
      послойный KV-кэш?
    options:
      - Каждый слой должен самостоятельно выбрать следующую свободную позицию
      - >-
        Все слои должны записать данные токена в одну логическую позицию до
        сдвига общего указателя
      - Позиция должна сдвигаться перед вычислением key и value в каждом слое
    correct: 1
    explanation: >-
      Key и value одного токена во всех слоях относятся к одной позиции
      последовательности. Общий указатель следует сдвигать во внешнем цикле лишь
      после завершения обработки токена всеми слоями.
---

В функции из [шага 24](#step-24) один decode-токен проходит через все слои модели. Но `advance(1)` находится внутри `forward` слоя: при четырёх слоях общая позиция сдвинется четыре раза, хотя появился только один токен. Проверка `seq_len == 1` этого не спасает — условие истинно в каждом слое.

Позиция относится к токену, а не к слою. Все слои сначала обновляют свои части кэша на одной позиции, затем внешний цикл генерации сдвигает её ровно один раз.
