Возьми промпт из шести токенов и попроси модель добавить ещё три. В `generate_no_cache` из [шага 19](#step-19) на каждом круге в модель снова уходила вся растущая последовательность. Теперь математику модели и способ выбора токена менять не нужно — меняется только организация вызовов.

Дополни `generate_with_cache` так, чтобы она выполняла две фазы из [шага 23](#step-23):

1. Создай пустой KV-кэш с запасом как минимум под промпт и новые токены.
2. Один раз передай в модель весь промпт. Это `prefill`: модель заполнит кэш для всех его позиций, а логиты последней позиции позволят выбрать первый новый токен.
3. Добавь выбранный токен к результату.
4. Для каждого следующего шага передавай в модель только последний выбранный токен. Это `decode`: прошлые key и value уже лежат в кэше, поэтому повторно обрабатывать весь текст не требуется.

Обрати внимание на границу между фазами: первый новый токен выбирается уже из результата `prefill`. Повторно подавать весь промпт ради него не надо.

Проверь поведение на коротком примере. Полная последовательность должна попасть в модель ровно один раз, а каждый последующий вход должен иметь длину один. После `prefill` занятая часть кэша равна длине промпта; затем она увеличивается на одну позицию после каждого однотокенного вызова. Все слои должны записать данные текущих токенов до перехода к следующей позиции.

> 🎒 **На пальцах.** Представь партию в настольную игру. Сначала ты один раз записываешь исходную расстановку фигур. Затем после каждого хода дописываешь в журнал только одно новое действие. Чтобы понять следующий ход, ты читаешь журнал и добавляешь строку — не расставляешь заново все фигуры и не переигрываешь партию с начала.
