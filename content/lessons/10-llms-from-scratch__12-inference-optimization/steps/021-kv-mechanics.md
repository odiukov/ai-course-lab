title: Сохраняем key и value каждого прошлого токена
source_anchor: '### KV Cache'
---

Ты генерируешь тысячный токен и снова берёшь самый первый токен контекста. Его представление не изменилось, веса модели тоже. Но без специальной памяти модель заново получает для него key и value — уже в 999-й раз. Именно это повторение росло на каждом ходе в [шаге 20](#step-20).

Можно ли один раз выполнить эти проекции и оставить результат до конца генерации? Так появляется KV-кэш — область памяти, где для каждого прошедшего токена сохраняются его key и value на каждом слое модели. Формы этих объектов мы зафиксировали в [шаге 16](#step-16).

При появлении нового токена модель вычисляет только его собственные key и value и добавляет их в кэш. Затем текущий query сравнивается с сохранёнными keys, а найденные веса используются для смешивания сохранённых values — ровно по логике attention из [шага 17](#step-17).

Почему кэш называется именно KV, а не QKV? Query нужен текущему токену, чтобы один раз задать вопрос прошлому контексту. На следующем ходе появится уже другой query. А keys и values прошлых токенов понадобятся снова, поэтому хранить выгодно именно их.

Мы не уменьшаем длину контекста и не меняем ответ attention. Мы просто перестаём повторно изготавливать неизменные данные: один раз посчитали key и value токена — дальше берём их из памяти.

> 🎒 **На пальцах.** Представь гардеробщика, который записывает для каждой вещи номер крючка и её описание. Когда приходит новый посетитель, не нужно заново осматривать все уже принятые вещи: старые записи лежат в картотеке, добавляется только новая. Текущий запрос сверяется со всей картотекой, но сами прошлые карточки повторно не создаются.
