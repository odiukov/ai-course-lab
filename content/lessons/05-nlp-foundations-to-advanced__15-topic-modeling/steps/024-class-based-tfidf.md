У тебя есть три кластера по десятку текстов. Если считать TF-IDF для каждого текста отдельно, слова будут описывать отдельные документы, а не темы. Поэтому `class_based_tfidf` сначала должна склеить все документы одного кластера в один большой «классовый документ» — именно на нём работает идея из [шага 23](#step-23).

Функция получает тексты и соответствующие им метки кластеров. Внутри ей предстоит:

1. Собрать документы по меткам, сохранив однозначный порядок кластеров.
2. Объединить тексты каждого кластера.
3. Построить общий словарь и матрицу счётчиков: строки соответствуют кластерам, столбцы — словам.
4. Нормализовать каждую строку по общему числу слов в этом кластере.
5. Рассчитать вес редкости по формуле из [шага 23](#step-23) и умножить его на нормализованные частоты.
6. Вернуть матрицу c-TF-IDF вместе со словарём и порядком меток.

Следи прежде всего за формами данных. Для четырёх кластеров и словаря из 120 слов результат должен иметь форму `(4, 120)`. Число исходных документов здесь уже не задаёт число строк: после объединения одна строка представляет целую тему.

Ещё одна частая ошибка — нормализовать столбцы. Делить нужно счётчики внутри каждой строки, потому что тебя интересует доля слова в конкретном кластере. У крупного кластера иначе все веса окажутся выше просто из-за большего количества текста.

> 🎒 **На пальцах.** Представь четыре редакции, каждая выпустила стопку заметок. Ты склеиваешь заметки каждой редакции в отдельную длинную полосу, затем отмечаешь характерные слова. Размер стопки не должен давать преимущество: важна доля слова внутри полосы и то, насколько редко оно встречается у остальных редакций. Одна полоса — одна строка результата.
