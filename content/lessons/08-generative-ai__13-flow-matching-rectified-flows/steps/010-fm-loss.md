Внутри `flow_matching_loss` легко случайно сравнить не те величины: например, выход модели — с конечной точкой `x_1`. Такой код запустится, но научит модель угадывать шум, а не скорость движения.

Собери один обучающий пример по цепочке. Возьми данные `x_0` и шум `x_1`, выбери для каждого элемента батча своё время `t`, а затем передай их в `interpolate` из [шага 5](#step-5). Получившуюся точку `x_t` вместе со временем отправь модели: её результат — предсказанная скорость.

Эталонную скорость вычисли через `flow_target` из [шага 7](#step-7). После этого сравни предсказание и цель среднеквадратичной ошибкой, как в [шаге 9](#step-9), и усредни результат по батчу и остальным измерениям.

Особенно внимательно посмотри на формы тензоров. У изображения может быть форма `[batch, channels, height, width]`, а у времени — всего `[batch]`. Для интерполяции `t` должно расширяться вдоль остальных измерений; эту работу уже умеет выполнять написанная тобой функция. При вызове модели сохраняй тот формат времени, которого ожидает её интерфейс.

Проверь себя: итог функции должен быть одним числом, а не отдельной ошибкой для каждого пикселя или объекта. Если поменять выход модели, значение лосса должно измениться; если модель точно вернёт `flow_target`, лосс должен стать нулевым.

> 🎒 **На пальцах.** Представь дегустацию партии супов. Для каждой тарелки технолог задаёт эталонную солёность, а повар называет свою оценку. Ты находишь ошибку для каждой тарелки, возводишь её в квадрат, чтобы промахи не погасили друг друга, и берёшь среднее. Одно итоговое число показывает, насколько повар ошибся по всей партии — так же `flow_matching_loss` оценивает предсказанные скорости батча.
