check:
  - question: >-
      Проверка статьи завершилась ошибкой, а в выходном каталоге остались файлы
      от прошлого запуска. Как должен поступить писатель?
    options:
      - 'Перезаписать только те файлы, которые удалось подготовить'
      - Не изменять ни один выходной файл
      - Удалить старые файлы и сохранить сообщение об ошибке вместо статьи
    correct: 1
    explanation: >-
      Все проверки выполняются до первой записи. При ошибке старые результаты не
      смешиваются с частично созданными файлами нового запуска.
  - question: >-
      Два рисунка получили одинаковый идентификатор. Почему проверка должна
      остановить обработку?
    options:
      - Перекрёстная ссылка по этому идентификатору становится неоднозначной
      - 'LaTeX требует, чтобы пути ко всем изображениям различались'
      - Число рисунков обязано совпадать с числом источников
    correct: 0
    explanation: >-
      Идентификатор задаёт цель перекрёстной ссылки. Если он повторяется, ссылка
      уже не определяет единственный рисунок.
---

После конвейера из [шага 1](#step-1) у тебя есть цельный скелет статьи, но его ещё нельзя безоговорочно отдавать дальше. Проверь четыре условия: заголовок и аннотация не пусты, идентификаторы рисунков не повторяются, а каждая ссылка из `cites` ведёт к ключу библиографии статьи. Обычно спотыкаются на том, что файл начинают создавать раньше проверок: тогда ошибка оставляет смесь новых и старых результатов.
