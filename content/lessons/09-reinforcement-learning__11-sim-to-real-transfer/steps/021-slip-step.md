У тебя уже есть функция `perpendicular` из [шага 19](#step-19): она находит действия, направленные вбок относительно выбранного. Теперь собери вокруг неё `slip_step` — один переход симулятора с возможным проскальзыванием.

Функция должна получить обычное действие и значение `slip`. Сначала сделай ровно один случайный бросок: число от 0 включительно до 1 не включительно. Затем сравни его со `slip`.

Если выпавшее число меньше `slip`, исходное действие выполнять нельзя. Возьми перпендикулярные варианты, выбери среди них один случайно и верни его. В противном случае верни исходное действие без изменений.

Обрати внимание на два частых промаха. Первый — случайно выбирать новое направление даже тогда, когда проскальзывания не произошло: обычная ветка обязана сохранить действие. Второй — вызывать генератор несколько раз для одного перехода. Тогда решение о проскальзывании начинает зависеть от нескольких бросков, хотя по модели из [шага 20](#step-20) нужен один.

Проверь функцию серией вызовов, временно выводя исходное действие, случайное число и результат. Так ты увидишь не только ответ, но и причину, по которой сработала конкретная ветка. После проверки отладочный вывод можно убрать.

> 🎒 **На пальцах.** Представь официанта с подносом, который делает один шаг по кухне. Перед каждым шагом он один раз проверяет плитку: скользкая она сейчас или нет. Если нет — идёт туда, куда собирался. Если да — его сносит в одну из двух боковых сторон. `slip_step` воспроизводит именно этот единичный момент выбора, а не всю прогулку целиком.
