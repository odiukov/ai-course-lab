У тебя есть две Q-таблицы: одна обучается с рандомизированным `slip`, другая — только при `slip = 0.0`. Но сравнивать их по одному запуску нечестно: обе политики должны пройти один и тот же набор испытаний.

Функция `sweep` сначала обучает обе политики с помощью `train_q` из [шага 28](#step-28). Для узкой политики передай диапазон, в котором обе границы равны нулю. Затем перебери тестовые значения `slip` и для каждого вызови `evaluate` из [шага 30](#step-30) дважды: один раз с DR-таблицей, второй — с узкой.

На выходе сохрани два списка средних возвратов в том же порядке, что и входные значения `slip`. Тогда результаты можно сопоставлять позиция к позиции.

Главная ловушка — поместить обучение внутрь цикла проверки. Тогда политика будет заново приспосабливаться к каждому тестовому `slip`, а это уже не zero-shot оценка из [шага 29](#step-29). Обучение происходит один раз; во время sweep меняются только условия испытания.

> 🎒 **На пальцах.** Ты готовишь двух пловцов: первый тренируется в бассейне с разным течением, второй — только в спокойной воде. На экзамене оба по очереди плывут по одной и той же серии дорожек. Если перед каждой дорожкой разрешить им потренироваться именно на ней, сравнение потеряет смысл: ты проверишь подстройку, а не перенос навыка.
