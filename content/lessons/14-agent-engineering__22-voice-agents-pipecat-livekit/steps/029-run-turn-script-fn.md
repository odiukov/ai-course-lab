Перед тобой два сценария из [шага 28](#step-28): в первом агент спокойно заканчивает ответ, во втором пользователь перебивает его во время озвучивания. Отдельные функции уже работают, но сами по себе они не создают разговор. `run_turn_script` должна последовательно проиграть события сценария и собрать результат каждого действия в одну трассу.

Смотри на функцию как на координатора. Она не должна заново решать, достаточно ли надёжен транскрипт, закончилась ли реплика или пора остановить звук. Для этого уже написаны `gate_transcript` из [шага 20](#step-20), `is_end_of_turn` из [шага 22](#step-22), `turn_transition` из [шага 25](#step-25) и `play_tts` из [шага 27](#step-27). Твоя задача — вызвать нужную функцию в нужный момент и передать ей текущее состояние.

Главная ловушка — обрабатывать каждое событие независимо. После начала ответа агент владеет ходом; после перебивания владение меняется, а TTS получает отмену. Поэтому состояние после одного события должно стать входом для следующего. Не переставляй события ради удобства: порядок сценария и есть порядок реального разговора.

В возвращаемой трассе сохраняй результаты по мере их появления. По ней должно быть видно, какие решения принял каждый этап, но сейчас не пытайся дополнительно объяснять или «улучшать» эти решения. Если тест ожидает точные поля и значения, придерживайся заданного формата буквально.

> 🎒 **На пальцах.** Представь дирижёра с партитурой. Он не играет вместо скрипки, трубы и барабана — лишь вовремя показывает, кому вступить, и помнит, кто сейчас звучит. Если зритель внезапно подаёт сигнал остановки, дирижёр сначала гасит текущую партию, а затем передаёт очередь дальше. `run_turn_script` делает то же самое с функциями и состоянием разговора.
