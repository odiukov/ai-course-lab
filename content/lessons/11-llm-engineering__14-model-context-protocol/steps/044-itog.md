  - question: >-
      У тебя четыре готовых MCP-сервера. Команда добавляет ещё один хост — новое
      LLM-приложение. Сколько серверов придётся дописать?
    options:
      - >-
        Ни одного: хост поднимает по клиенту на каждый сервер и говорит с ними
        по той же спецификации
      - 'Четыре: под каждый сервер нужна прокладка для нового хоста'
      - 'Один: общий адаптер между новым хостом и всеми четырьмя серверами'
      - 'Два: по одному на чтение и на запись'
    correct: 0
    explanation: >-
      Именно это и схлопывает матрица N×M: сервер написан один раз под
      спецификацию, а новый хост стоит одного клиента на сервер, а не новой
      интеграции на каждый инструмент.
  - question: >-
      Нужно дать модели заглянуть в содержимое конкретного файла по его адресу —
      без побочных эффектов и без того, чтобы что-то поменялось. Какой примитив
      тут твой?
    options:
      - 'Tool: любое обращение к файлу — это действие'
      - >-
        Resource: контент с адресацией по URI, который хост запрашивает на
        чтение
      - 'Prompt: шаблон подставит путь и отдаст текст'
      - 'Ни один: чтение файлов вне протокола'
    correct: 1
    explanation: >-
      Resource адресуется по URI и отдаёт данные на чтение, а решение достать
      его принимает хост. Tool — это действие, prompt — шаблон, который вызывает
      человек.
  - question: >-
      Сервер получил tools/call с id 7, но в аргументах вместо числа приехала
      строка. Что должен отправить сервер?
    options:
      - 'Ничего: молча упасть с исключением, хост переспросит'
      - 'Ответ с result и текстом ошибки внутри, id 7'
      - Ошибку с кодом -32602 и тем же id 7
      - Ошибку с кодом -32601 без id
    correct: 2
    explanation: >-
      Ошибка — это тоже полноценный ответ: тот же id, чтобы хост сопоставил его
      с запросом, и -32602 именно про неверные аргументы (-32601 — про
      неизвестный метод).
  - question: >-
      В stdio-сервере ты добавил print для отладки внутри обработчика. Что
      случится?
    options:
      - 'Ничего: хост покажет эту строку в логах'
      - >-
        Строка уедет в stdout вместе с JSON-RPC, и хост споткнётся на разборе
        сообщения
      - 'Сервер станет медленнее, но соединение выживет'
      - Хост вернёт -32602 на следующий вызов
    correct: 1
    explanation: >-
      В stdio транспортом служит сам stdout: любая лишняя строка попадает в
      поток сообщений и ломает разбор. Логи — только в stderr.

Дальше в курсе ты будешь поднимать серверы и подключать их к хостам — и туда переезжает почти всё из этого урока: три примитива и вопрос «кто решает, что дёрнуть» (шаги [5](#step-5)–[7](#step-7), [21](#step-21)), конверт с `id` (шаг [9](#step-9)) и шесть методов (шаг [15](#step-15)), расстановка host/client/server (шаг [17](#step-17)).

Спотыкаются обычно в двух местах. Первое — примитивы: resource кажется «инструментом чтения», хотя достать его решает хост, а не модель. Второе — что ошибка и есть ответ: код вместо исключения, тот же `id`, и никаких print в stdout.

Ответь на четыре вопроса — если где-то промахнёшься, вернись по ссылке ровно в тот шаг.
