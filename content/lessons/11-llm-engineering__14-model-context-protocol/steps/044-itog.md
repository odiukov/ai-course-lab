      - 'Четыре: под каждый сервер нужна прокладка для нового хоста'

    correct: 0
    explanation: >-

  - question: >-
      Нужно дать модели заглянуть в содержимое конкретного файла по его адресу —
      без побочных эффектов и без того, чтобы что-то поменялось. Какой примитив
      тут твой?
    options:
      - 'Tool: любое обращение к файлу — это действие'
      - >-
        Resource: контент с адресацией по URI, который хост запрашивает на
        чтение
      - 'Prompt: шаблон подставит путь и отдаст текст'
      - 'Ни один: чтение файлов вне протокола'
    correct: 1
    explanation: >-
      Resource адресуется по URI и отдаёт данные на чтение, а решение запросить
      его принимает хост.
  - question: >-
      Сервер получил вызов инструмента с аргументами, не соответствующими его
      схеме. Какой ответ JSON-RPC должен вернуть сервер?
    options:
      - 'Ничего: молча завершить обработчик и дождаться повторного вызова'
      - Успешный result с текстом ошибки внутри
      - Ошибка Invalid params с тем же идентификатором запроса
      - Ошибка Method not found без идентификатора
    correct: 2
    explanation: >-
      Несоответствие аргументов схеме — это ошибка Invalid params. Сервер
      возвращает её как JSON-RPC error с тем же id, чтобы хост сопоставил ответ
      с запросом.
  - question: >-
      В stdio-сервере ты добавил print для отладки внутри обработчика. Что
      случится?
    options:
      - 'Ничего: хост покажет эту строку в логах'
      - >-
        Строка уедет в stdout вместе с JSON-RPC, и хост споткнётся на разборе
        сообщения
      - 'Сервер станет медленнее, но соединение выживет'
      - Хост вернёт -32602 на следующий вызов
    correct: 1
    explanation: >-
      В stdio stdout содержит поток JSON-RPC-сообщений. Отладочные сообщения
      нужно писать в stderr, иначе они нарушат разбор протокола.

Дальше в курсе ты будешь поднимать серверы и подключать их к хостам — и туда переезжает почти всё из этого урока: три примитива и вопрос «кто решает, что дёрнуть» (шаги [5](#step-5)–[7](#step-7), [21](#step-21)), конверт с `id` (шаг [9](#step-9)) и шесть методов (шаг [15](#step-15)), расстановка host/client/server (шаг [17](#step-17)).

Спотыкаются обычно в двух местах. Первое — примитивы: resource кажется «инструментом чтения», хотя достать его решает хост, а не модель. Второе — что ошибка и есть ответ: код вместо исключения, тот же `id`, и никаких print в stdout.

Ответь на четыре вопроса — если где-то промахнёшься, вернись по ссылке ровно в тот шаг.
