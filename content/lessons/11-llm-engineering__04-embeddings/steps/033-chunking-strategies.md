Ты уже режешь документ по 512 токенов с перекрытием ([шаг 32](#step-32)). Возьми конкретный текст — инструкцию по возврату товара с заголовками, абзацами и списком — и посмотри, где именно прошёл нож.

Ровно на 512-м токене граница легла внутрь фразы: «Срок возврата составляет 14» | «дней с момента получения». Перекрытие эту мысль подберёт. Но обидно рубить вслепую, когда в тексте уже есть готовые швы.

Их можно использовать — вопрос, насколько глубоко ты готов копать.

Самый простой способ — **fixed-size**: каждые N токенов, и всё. Быстро, предсказуемо, отлично для логов и текста без структуры. **Sentence-based**: набираешь предложения целиком, пока не упрёшься в лимит; ни одна мысль не разрублена пополам. Для статей и писем этого обычно хватает. **Recursive** сначала пробует резать по заголовкам разделов, потом по абзацам, потом по предложениям, потом уже по символам — то есть спускается от крупного шва к мелкому, пока фрагмент не влезет. Это `RecursiveCharacterTextSplitter` из LangChain, и он хорош на Markdown и HTML. **Semantic** идёт дальше всех: кодирует каждое предложение отдельно и склеивает соседей, пока их косинусная близость держится выше порога. Как только тема поехала — новый фрагмент. Качество лучшее, но ты платишь эмбеддингом за каждое предложение.

А размер? Возьмёшь 50 токенов — фрагмент останется без контекста. Возьмёшь 4000 — вернёшься к усреднённому «похожему ни на что» из [шага 31](#step-31). Рабочая середина: 256-512 токенов, перекрытие 50.

> 🎒 **На пальцах.** Раскрой длинного фильма на клипы. Можно резать каждые три минуты — попадёшь в середину реплики. Можно резать по склейкам кадров. Можно сначала по сериям, потом по сценам, потом по кадрам. А можно смотреть целиком и резать там, где меняется настроение — дольше всего, зато каждый клип про одно. Один и тот же фильм, четыре разных ножа.
