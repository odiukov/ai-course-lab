Перед тобой результаты аудита: секрет провайдера лежит в переменной CI, в промпты попадают телефоны клиентов, сервис может обращаться к любому адресу, а журнал разрешает редактировать старые записи. Команда предлагает исправлять всё параллельно. Но если ресурсов хватает только на одну миграцию за раз, что ставить первым?

В `outputs/skill-llm-security-plan.md` расположи работы по цене возможной ошибки. Сначала перенеси секреты в единое хранилище по модели из [шага 4](#step-4): украденный ключ может сразу открыть доступ к провайдеру и данным. Затем включи PII-очистку до отправки запроса, используя подход из [шага 15](#step-15). Даже разрешённый получатель не должен получать лишние персональные данные.

Третьей волной ограничь egress белым списком из [шага 19](#step-19). Теперь очищенный запрос сможет уйти только к заранее одобренным системам. После этого переведи аудит в неизменяемый режим: цепочка хешей и append-only запись из [шага 25](#step-25) позволят обнаруживать переписывание прошлого.

Для каждой волны зафиксируй текущий пробел, целевое состояние, ответственного, срок и проверяемый признак завершения. Требование «внедрить vault» расплывчато; «приложение получает секрет по IAM-роли, статического ключа в CI больше нет» уже можно проверить. Так список пожеланий превращается в маршрут миграции, где следующий рубеж начинается после подтверждения предыдущего.

> 🎒 **На пальцах.** Представь переезд химической лаборатории. Сначала опасные реактивы запирают в специальном шкафу. Затем с образцов снимают имена пациентов. Потом курьерам оставляют только утверждённые маршруты. Наконец, каждую передачу заносят в прошитый журнал, из которого нельзя незаметно вырвать страницу. Если начать с журнала, реактивы всё это время продолжат лежать на открытом столе.
