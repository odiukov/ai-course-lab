      API-ключ скопирован в сорок конфигов. Какое изменение лучше всего сократит

    options:
      - Зашифровать каждый конфиг отдельным паролем и обновлять их вручную
      - >-
        Хранить ключ в едином хранилище, выдавать сервису по роли и менять не

      - Перенести ключ во внутреннюю документацию с ограниченным доступом

    correct: 1
    explanation: >-
      Единое хранилище убирает копии секрета, роль ограничивает доступ, а

  - question: >-
      Пользователь отправил промпт с email и попросил модель обратиться к
      неизвестному домену. Как должен поступить защищённый сервис?
    options:
      - 'Передать промпт модели, а подозрительный домен отметить в журнале'
      - 'Удалить весь промпт, потому что частичная очистка всегда небезопасна'
      - >-
        Заменить PII стабильной заглушкой, заблокировать домен по
        egress-политике и записать безопасные метаданные
      - 'Разрешить домен, если пользователь вошёл через MFA'
    correct: 2
    explanation: >-
      Очистка защищает PII, egress-политика управляет сетевым выходом независимо
      от личности пользователя, а аудит не должен сохранять исходный промпт.
  - question: >-
      Сканер нашёл действующий ключ в старом коммите. Какой план действительно
      закрывает утечку?
    options:
      - Удалить ключ из текущего файла и сделать новый коммит
      - Сделать репозиторий приватным и оставить ключ действующим
      - >-
        Отозвать ключ, удалить его из истории git и включить сканирование

      - 'Переименовать ключ, чтобы сканер больше не узнавал шаблон'
    correct: 2
    explanation: >-
      Старое значение могло быть скопировано, поэтому его нужно отозвать;
      очистка истории и постоянное сканирование уменьшают риск повторной утечки.
  - question: >-
      Из середины append-only журнала удалили запись. Что даст проверка цепочки

    options:

      - >-
        Обнаружит разрыв, если есть доверенная точка сравнения, но сама не
        докажет сохранность полностью переписанного журнала
      - 'Ничего не заметит, потому что хеши обнаруживают только изменение текста'
      - Автоматически перенесёт журнал в холодное хранилище
    correct: 1
    explanation: >-
      Удаление меняет связь между соседними записями. Однако злоумышленник может
      пересчитать всю цепочку, если её последняя доверенная точка нигде отдельно
      не закреплена.

Здесь тебе понадобится не запомнить отдельные функции, а собрать их в одну систему: путь безопасного вызова из [шага 30](#step-30), границы цепочки хешей из [шага 29](#step-29) и уровни хранения из [шага 32](#step-32). Чаще всего ошибаются, выбирая одну сильную меру вместо нескольких независимых барьеров.

> 🎒 **На пальцах.** Представь техосмотр автомобиля: новые замки не заменяют тормоза, а исправные тормоза — журнал обслуживания. Проверка пройдена лишь тогда, когда каждый узел выполняет свою задачу и неисправность одного не открывает весь путь сразу.
