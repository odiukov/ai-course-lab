Ты обрабатываешь два фрагмента промпта: в одном встретился номер `123-45-6789`, а через несколько строк — тот же номер снова. Если каждый раз создавать новую заглушку, модель увидит двух разных людей. Если оставить часть номера внутри заглушки, чувствительные данные всё ещё смогут попасть наружу.

Твоя задача — написать `placeholder_for`, которая выдаёт безопасное обозначение найденной сущности. Консистентность из [шага 13](#step-13) должна соблюдаться: одинаковое чувствительное значение получает одинаковую заглушку, а разные значения — разные.

Обрати внимание на три свойства функции:

- заглушка содержит тип сущности, например `SSN`, чтобы текст оставался понятным модели;
- исходное значение не появляется в результате даже частично;
- функция запоминает уже созданные соответствия и повторно использует их.

Для первого нового SSN может получиться обозначение вроде `[SSN_TOKEN_1]`, для следующего — `[SSN_TOKEN_2]`. Важно не конкретное оформление номера, а связь: повторный вызов с первым SSN обязан снова вернуть `[SSN_TOKEN_1]`.

Проверь функцию минимум на трёх вызовах: значение A, значение B и снова A. Первый и третий результаты должны совпасть, второй — отличаться. Ещё посмотри, что в заглушке нигде не осталось исходного значения. Здесь ты создаёшь только один безопасный идентификатор; заменять им все совпадения в тексте будет следующий шаг.

> 🎒 **На пальцах.** Представь камеру хранения на вокзале. Ты сдаёшь чемодан и получаешь жетон №1. Если позже предъявляешь тот же чемодан для учёта, сотрудник использует тот же номер, а другому чемодану выдаёт №2. На жетоне нет ни твоего имени, ни содержимого багажа — только устойчивое обозначение, сохраняющее связь.
