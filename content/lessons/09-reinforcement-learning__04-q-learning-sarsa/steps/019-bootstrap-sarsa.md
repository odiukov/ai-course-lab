В переходе агент уже выбрал `next_action` через ε-жадную стратегию. Теперь легко случайно испортить SARSA: снова найти лучшее действие через `max`. Тогда функция незаметно превратится в вариант Q-learning из [шага 16](#step-16).

```python
def bootstrap_sarsa(Q, next_state, next_action, reward, gamma, done):
    # Верни TD-цель для SARSA
    pass
```

Для обычного перехода возьми из таблицы `Q` оценку именно пары `next_state`, `next_action` и добавь её к награде с коэффициентом `gamma`. Это действие уже выбрано стратегией — функция не должна выбирать его заново. Используй цель из [шага 18](#step-18), не повторяя поиск действия.

Отдельно обработай `done`. Если эпизод завершён, функция должна вернуть только `reward`: следующего действия нет, поэтому `next_action` может быть равен `None`. Проверяй завершение до обращения к `Q[next_state][next_action]`, иначе код либо прочитает бессмысленную ячейку, либо завершится с ошибкой.

Проверь себя по трём признакам:

- внутри нет `max`;
- при `done=True` таблица `Q` для следующего шага не используется;
- при `done=False` берётся оценка переданного `next_action`, даже если другое действие имеет более высокую оценку.

Именно последний пункт сохраняет SARSA on-policy: цель следует за тем действием, которое агент действительно собирается выполнить.

> 🎒 **На пальцах.** Ты сдал чемодан на пересадочный рейс, и на бирке уже указан следующий самолёт. Сотрудник оценивает маршрут именно через этот самолёт, даже если соседний рейс прилетает раньше. Искать самый быстрый рейс заново нельзя — это изменит маршрут. А если ты уже в конечном городе, пересадки вообще нет: остаётся только результат последнего перелёта.
