Открой `code/main.py` и представь, что делаешь всё вручную. Имя инструмента ты пишешь в одном месте, текст описания — в другом, схему — в третьем, а функция-исполнитель вообще живёт отдельным `def` где-то ниже. Работает. Пока не переименуешь параметр.

Ты правишь в схеме `"city"` на `"location"` — а исполнитель по-прежнему читает `city`. Кто тебе об этом скажет? Никто. Модель составит аргументы строго по схеме, валидатор их пропустит, и падёт только исполнитель, в момент вызова, с `KeyError`. Четыре части инструмента разъехались, потому что ничто не держало их вместе.

Вот это «вместе» и есть работа `make_tool`. Одна функция, четыре аргумента — имя, описание, схема, исполнитель — и на выходе один объект (в Python проще всего словарь). Дальше по коду инструмент существует только целиком: нельзя случайно взять схему без исполнителя.

На что смотреть, когда пишешь:

- Проверяй на входе, а не потом. Имя — непустая строка (правила из [шага 7](#step-7)); описание — непустая строка; схема — словарь, у которого `type` равен `"object"` и есть `properties` ([шаг 9](#step-9)); исполнитель — что-то вызываемое, `callable(...)`. Кривой инструмент должен ломаться при сборке, когда стек ещё указывает на строку с опечаткой, а не через три хода цикла.
- Исполнитель складывай ссылкой, не вызывай. `make_tool` ничего не выполняет — она только упаковывает.
- Ключи словаря выбери раз и не меняй: их будет читать код и печати, и вызова.

И держи в голове несоответствие, о котором говорилось в [шаге 11](#step-11): полей четыре, а «тройкой» инструмент называют потому, что четвёртое — исполнитель — модели не достаётся.

> 🎒 **На пальцах.** Нотариус не отдаёт четыре листа по одному — он сшивает их и ставит печать на сшивку. Не потому что бумаги стали важнее, а потому что теперь один лист нельзя подменить незаметно. `make_tool` — эта сшивка: после неё имя, описание, схема и исполнитель ездят по коду одним пакетом, и переименованный параметр не может уехать без своего исполнителя.
