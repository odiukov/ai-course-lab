Попробуй прямо сейчас взять реестр из [шага 13](#step-13) и отправить его модели: `json.dumps(registry)`. Питон ответит `TypeError: Object of type function is not JSON serializable`. Внутри каждого инструмента лежит исполнитель — живая функция, и в JSON она не превращается никак.

Значит, объявление нужно собирать, а не пересылать целиком. Этим и займётся `describe_registry` — первый из четырёх шагов цикла ([шаг 5](#step-5)).

Что она должна делать: принять реестр и вернуть список объявлений, по одному на инструмент, где у каждого ровно три поля — `name`, `description`, `input_schema` из [шага 12](#step-12). Исполнитель не выбрасывается — он просто не попадает в результат и остаётся у хоста, чтобы вызвать его на шаге execute. Ничего в самом реестре функция не меняет: она читает.

На что смотреть, когда напишешь.

Порядок инструментов должен быть один и тот же при каждом вызове: реестр перебирается предсказуемо, а не как повезёт. Если порядок скачет, ты не сможешь сравнить два прогона между собой.

Проверка простая: прогони результат через `json.dumps` и распечатай. Если он сериализуется без ошибки — ты отдал модели ровно то, что она может прочитать. Если снова падает с `TypeError` — где-то в объявление просочилась функция.

Та самая ошибка про function is not JSON serializable — не досадная мелочь, а граница: всё, что за неё не проходит, модель и не должна видеть.

> 🎒 **На пальцах.** Официант зачитывает тебе блюдо и состав — гречка, грибы, без глютена. Он не выносит в зал сковороду и не показывает, кто у плиты. Ты выбираешь по описанию, готовят на кухне. `describe_registry` — этот вынос в зал: наружу идут название, описание и форма заказа, а исполнитель остаётся за дверью.
