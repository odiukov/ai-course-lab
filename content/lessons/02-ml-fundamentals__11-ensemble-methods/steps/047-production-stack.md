Ты прогнозируешь цены квартир по таблице и получаешь два результата: XGBoost — 12,4% ошибки, LightGBM — 12,7%. Кажется, победитель найден. Но после другого разбиения данных цифры меняются местами. Как понять, какая модель действительно надёжнее?

Начни с обеих моделей с параметрами по умолчанию и оценивай их кросс-валидацией: раздели данные на несколько частей, по очереди оставляй одну для проверки, а на остальных обучай модель. Сравнивай среднюю ошибку по всем проверкам, а не лучший отдельный результат. Так один особенно удачный или неудачный набор строк меньше влияет на выбор.

Затем настраивай небольшой набор параметров. `n_estimators` задаёт число деревьев, `learning_rate` — размер каждой поправки, знакомый по [шагу 39](#step-39). `max_depth` ограничивает сложность деревьев, а `min_child_weight` не позволяет создавать ветви на слишком слабой опоре из данных. Меняй их осмысленными группами: маленький `learning_rate` обычно требует больше деревьев, а глубокие деревья легче подгоняются под шум. Здесь помогает и early stopping из [шага 40](#step-40).

Stacking из [шага 43](#step-43) стоит добавлять лишь после такого устойчивого базового решения: дополнительная сложность оправдана, когда тебе действительно важен небольшой прирост. Для табличных данных сильный первый маршрут обычно прост: boosting, несколько разумных настроек и честная кросс-валидация.

> 🎒 **На пальцах.** Ты выбираешь новый сорт краски для пяти комнат. Проверка только на одной стене может обмануть: там другое освещение или поверхность. Поэтому ты по очереди пробуешь краски в разных комнатах и сравниваешь средний результат. Кросс-валидация делает то же с моделью: победителем становится не случайный фаворит одной проверки, а вариант, который стабильно работает на разных частях таблицы.
