title: Out-of-bag объекты дают бесплатную проверку модели
source_anchor: '### Bagging (Bootstrap Aggregating)'
---

Ты обучил ансамбль и хочешь понять, насколько хорошо он работает. Проверять модели на строках, которые они видели при обучении, нечестно: знакомые примеры могут создать слишком оптимистичную оценку. Но если отложить отдельную проверочную часть, для обучения останется меньше данных.

Здесь помогают пропуски, замеченные в [шаге 13](#step-13). Для каждой bootstrap-выборки некоторые исходные объекты не выпадают ни разу. Их называют **out-of-bag**, или OOB-объектами: для конкретной модели это незнакомые примеры, хотя они входят в общий обучающий набор.

Возьми одну строку данных и найди все модели, в чьи bootstrap-выборки она не попала. Попроси только эти модели сделать прогноз, объедини их ответы голосованием и сравни результат с правильным ответом. Затем повтори это для остальных строк. Доля ошибок даст OOB-оценку ансамбля.

Важно не подключать к голосованию модель, которая обучалась на проверяемой строке: иначе ответ уже нельзя считать независимой проверкой. Поэтому у разных объектов будет разный набор голосующих моделей.

Так ансамбль проверяется на данных, которые уже есть, но которых конкретные участники проверки раньше не видели. Отдельный тестовый набор всё ещё полезен для финальной оценки, однако OOB-оценка позволяет следить за качеством, не отрезая часть данных перед обучением.

> 🎒 **На пальцах.** Представь несколько репетиторов, каждому из которых досталась своя стопка задач для подготовки ученика. Некоторые задачи случайно не попали конкретному репетитору. Именно ими ты его экзаменуешь. Для каждой задачи проверяющими становятся только те репетиторы, которые её раньше не видели, — поэтому экзамен получается честным без отдельной пачки заданий.
