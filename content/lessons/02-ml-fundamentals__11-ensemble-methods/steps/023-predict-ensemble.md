После [шага 21](#step-21) у тебя есть список обученных stump-моделей. Теперь четыре объекта проходят через три модели, и каждая возвращает свой ряд меток:

```text
модель 1:  1,  1, -1,  1
модель 2:  1, -1, -1,  1
модель 3: -1, -1, -1,  1
```

Здесь легко сделать незаметную ошибку: передать все ряды в `majority_vote` одним куском. Тогда голоса разных объектов смешаются, хотя голосовать должны модели — отдельно за каждый объект.

Напиши `predict_ensemble(models, X)`. Функция получает список моделей из `fit_bagging` и признаки объектов `X`. Для каждой модели вызови `predict_stump` из [шага 19](#step-19), чтобы собрать её прогнозы. Затем двигайся по объектам: возьми одну метку от каждой модели, передай этот набор в `majority_vote` из [шага 4](#step-4) и сохрани победившую метку.

Для примера выше результат должен быть таким:

```text
1, -1, -1, 1
```

Проверь форму результата: на каждый объект из `X` приходится ровно одна итоговая метка, независимо от числа моделей. Правило разрешения ничьей придумывать заново не нужно — используй поведение уже написанной `majority_vote`. Именно такое объединение прогнозов завершает bagging из [шага 22](#step-22): модели смотрят на одни и те же объекты, но каждый объект получает собственное голосование.

> 🎒 **На пальцах.** Представь четыре конверта и трёх экспертов. Каждый эксперт кладёт по одному жетону в каждый конверт. Нельзя высыпать все двенадцать жетонов на стол и выбрать общий цвет: конверты относятся к разным решениям. Ты открываешь их по очереди, считаешь три голоса внутри и записываешь один ответ для каждого конверта.
