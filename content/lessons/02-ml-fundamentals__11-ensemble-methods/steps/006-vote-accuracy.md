Ты собираешь комиссию из 21 модели, каждая из которых права в 60% случаев. Функция `majority_vote` из [шага 4](#step-4) объединит их конкретные ответы, но не скажет, насколько точной будет такая комиссия в среднем. Это и должна вычислять `vote_accuracy`.

Функция принимает число моделей `n` и точность одной модели `p`, а возвращает вероятность правильного решения большинства. Используй сумму из [шага 5](#step-5), не выводя её заново.

Сначала найди минимальное число правильных голосов, необходимое для победы: `n // 2 + 1`. Для 21 модели это 11. Затем перебери все подходящие количества правильных ответов — от этого порога до `n` включительно. Для каждого количества вычисли биномиальный коэффициент через `math.comb`, умножь его на соответствующие степени `p` и `1 - p`, а получившиеся вероятности сложи.

Особенно внимательно проверь границы диапазона: значение `n` должно попасть в перебор, а ровно половина голосов не считается большинством. Для чётного `n` ничья поэтому не добавляется к точности.

Хорошая самопроверка: при `n = 1` функция должна вернуть `p`, а для 21 модели с `p = 0.6` результат должен быть около `0.74`. Возвращай вероятность от 0 до 1, а не процент и не округлённое целое число.

> 🎒 **На пальцах.** Представь мешок с лотерейными билетами: на каждом записано, сколько моделей ответили правильно. Тебе подходят только билеты, где правильных голосов больше половины. `vote_accuracy` подсчитывает вероятность каждого подходящего билета и складывает их. Билет с ничьёй остаётся в мешке: победы большинства на нём нет.
