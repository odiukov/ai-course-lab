  - question: >-
      Объект попал в bootstrap-выборку второй модели, но не попал в выборку
      первой. Как его можно использовать при OOB-проверке?
    options:
      - Для проверки только первой модели
      - Для проверки обеих моделей
      - Для проверки только второй модели
    correct: 0
    explanation: >-
      Первая модель не обучалась на этом объекте, поэтому для неё он является
      out-of-bag. Вторая модель объект видела, и её OOB-оценка не должна
      учитывать результат на нём.
  - question: >-
      Почему объединение прогнозов моделей, обученных на разных
      bootstrap-выборках, делает bagging менее чувствительным к случайным
      особенностям обучающих данных?
    options:
      - Случайные отклонения разных моделей частично компенсируют друг друга
      - Bootstrap автоматически уменьшает глубину каждой модели
      - >-
        Все модели получают одинаковые обучающие объекты и сходятся к одному
        прогнозу
    correct: 0
    explanation: >-
      Базовые модели переобучаются на разные случайные особенности своих
      выборок. При объединении прогнозов несовпадающие отклонения ослабляются,
      поэтому variance ансамбля снижается.
---

Здесь важно связать три идеи в одну цепочку: bootstrap создаёт разные обучающие наборы, пропущенные строки проверяют конкретную модель, а объединение разных прогнозов снижает чувствительность к случайностям данных. Частая ошибка — считать OOB единой общей выборкой: у каждой модели свой набор невиденных объектов, как в [шаге 14](#step-14).

> 🎒 **На пальцах.** Несколько редакторов получают разные случайно собранные пачки черновиков. Непопавшие в пачку тексты проверяют редактора честно: он их раньше не видел. Каждый редактор может случайно переоценить отдельный стиль, но совместная оценка сглаживает такие перекосы — именно так снижается variance.
