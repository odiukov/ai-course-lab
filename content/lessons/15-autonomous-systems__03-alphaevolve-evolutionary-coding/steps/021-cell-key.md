Перед тобой два кандидата с одинаково низкой ошибкой, но разной глубиной: один — короткое выражение, другой — цепочка из множества вложенных операций. Если сохранить только победителя по MSE, второй путь поиска исчезнет. Поэтому архиву нужен точный «адрес» для каждого кандидата.

Напиши функцию `cell_key`. Она должна принять выражение, получить его глубину с помощью `depth` из [шага 15](#step-15) и вернуть ключ ячейки архива в виде кортежа. Кортеж нужен даже при одном признаке: архив сможет использовать его как единый формат ключа, а позже к нему можно будет добавить другие измеримые признаки.

Обрати внимание на две детали. Во-первых, функция возвращает не само выражение и не его качество: MSE решает, кто лучше внутри ячейки, а `cell_key` — в какую ячейку кандидат попадёт. Во-вторых, кандидаты одинаковой глубины должны получать совершенно одинаковые ключи, какими бы разными ни были их операции и числа.

Проверь себя на нескольких выражениях из прошлых шагов: одиночное значение, одна операция и вложенная операция должны разойтись по ячейкам согласно результату `depth`. А два разных выражения одной глубины — встретиться в одной ячейке. Так архив сохраняет по лучшему представителю каждого типа структуры, а не просто складывает всех кандидатов в одну гонку.

> 🎒 **На пальцах.** Представь камеру хранения, где номер секции зависит от размера рюкзака. Содержимое рюкзака и его цена не определяют секцию — только размер. Два разных рюкзака одинакового размера попадут к одной дверце, а сотрудник уже оставит там более ценный. `cell_key` печатает номер дверцы; оценка выбирает, что за ней хранить.
