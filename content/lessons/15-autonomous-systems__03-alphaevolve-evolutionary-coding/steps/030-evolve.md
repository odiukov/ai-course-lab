Один вызов поколения уже работает, но попробуй повторить его сто раз вручную — легко потерять лучшего кандидата, забыть сохранить удачную мутацию или случайно выбрать родителя из старого состояния архива. Теперь собери весь поиск в `evolve`: функция должна управлять поколениями, а уже написанные функции выполнять отдельные операции.

Сначала оцени программу-затравку через `mse` из [шага 17](#step-17) и помести её в архив функцией `archive_insert` из [шага 26](#step-26). Это важно: даже если первая мутация окажется неудачной, поиск должен сохранить корректную исходную программу.

Дальше для каждого поколения повторяй цикл из [шага 29](#step-29):

1. Выбери родителя среди текущих обитателей архива.
2. Получи потомка через `mutate` из [шага 23](#step-23).
3. Вычисли его ошибку и ячейку через `cell_key` из [шага 21](#step-21).
4. Попробуй вставить потомка в архив.

После завершения поколения найди лидера через `best_of` из [шага 28](#step-28) и добавь его оценку в историю. Следи за направлением сравнения: здесь меньшая MSE означает лучший результат. Ещё одна частая ошибка — выбирать всех родителей заранее. Тогда новые удачные кандидаты не смогут стать родителями до следующего поколения, хотя архив уже успел измениться.

Функция должна вернуть данные, предусмотренные её заготовкой: итоговый архив, лучшего кандидата и историю качества. Не дублируй внутри `evolve` логику оценки или замены — вызывай готовые функции, чтобы каждое правило поиска оставалось в одном месте.

> 🎒 **На пальцах.** Представь теплицу со стеллажом подписанных горшков. Сначала ты ставишь туда исходное растение. Затем берёшь одно из уже растущих, выводишь новый сорт, измеряешь урожай и ставишь его в подходящий горшок лишь при улучшении. `evolve` — это садовник с календарём: он повторяет процедуру сезон за сезоном и записывает лучший урожай после каждого сезона.
