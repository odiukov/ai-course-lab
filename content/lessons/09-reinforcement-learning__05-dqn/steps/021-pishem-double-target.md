Перед тобой две сети и четыре оценки следующего состояния. Online-сеть выдаёт `[1.2, 2.8, 2.1, 0.5]`, поэтому выбирает действие с индексом `1`. Но в target-сети наибольшее число может стоять совсем в другом месте. Брать её максимум нельзя: тогда получится обычная DQN-цель из [шага 18](#step-18), а разделение ролей из [шага 20](#step-20) исчезнет.

В `double_dqn_target` сделай два отдельных прохода `forward` для `next_state`:

1. Получи оценки online-сети и найди индекс лучшего действия через `argmax`.
2. Получи оценки target-сети, но не ищи среди них максимум.
3. Возьми из target-оценок только значение по индексу, выбранному online-сетью.
4. Прибавь его к награде с коэффициентом `gamma`.

Особенно внимательно следи за `done`. Если переход завершил эпизод, следующего действия уже нет: функция должна вернуть только `reward`, не используя ни одну будущую Q-оценку. Удобно обработать этот случай сразу — так сложнее случайно добавить ценность состояния после финиша.

Главная ловушка здесь выглядит невинно: вызвать `max` для результата target-сети. Проверяй себя словами: **online выбирает индекс, target оценивает значение по этому индексу**. Сети могут не согласиться, и именно это нам нужно.

> 🎒 **На пальцах.** Представь музыкальный автомат с четырьмя пластинками. Ты просишь одного слушателя выбрать номер композиции, а другого — поставить выбранной композиции оценку. Второй слушатель не может заменить выбор своей любимой песней: он сообщает балл строго для названного номера. Если вечер уже закончился (`done`), следующую пластинку вообще не включают — остаётся только полученная награда.
