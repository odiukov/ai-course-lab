Ты вызываешь `effective_horizon(0.8)` и ожидаешь получить `5`. Но стоит передать `1`, и обычное вычисление заканчивается делением на ноль. Значит, функции мало просто подставить число в правило из [шага 13](#step-13): сначала ей нужно проверить вход.

Функция получает один аргумент — `gamma`. Для значений от `0` включительно до `1` исключительно она возвращает приблизительное число шагов, на протяжении которых будущие награды остаются значимыми. Результат может быть дробным: округлять его внутри функции не нужно. Например, при `gamma = 0.6` горизонт равен `2.5`. Это оценка, а не буквальное количество целых действий.

Обрати внимание на границы:

- `gamma = 0` допустима: агент учитывает только ближайший шаг;
- при приближении `gamma` к `1` результат быстро растёт;
- `gamma = 1` для этой формулы недопустима: горизонт становится неограниченным;
- отрицательное значение и число больше `1` тоже нужно отклонить, например через `ValueError`.

После реализации проверь не только знакомые значения, но и границы: `0`, число вроде `0.6` и некорректные входы. Особенно легко случайно разрешить `1`, написав проверку с неверным знаком сравнения.

> 🎒 **На пальцах.** Представь настройку дальности света у фонаря. Значение `gamma` чуть меньше единицы позволяет оценить, докуда дотянется луч. При `gamma = 1` фонарь будто должен освещать бесконечную дорогу — конечного расстояния уже нет. Поэтому функция сначала проверяет ручку настройки и лишь затем считает дальность.
