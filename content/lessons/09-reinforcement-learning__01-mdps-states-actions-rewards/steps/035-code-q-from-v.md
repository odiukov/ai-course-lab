У тебя уже есть оценки клеток `V`: например, одна стоит `8`, другая `3`. Но агент выбирает не клетку, а действие. Если из текущей позиции кнопка «вправо» иногда приводит в первую клетку, а иногда — во вторую, одного значения `V` недостаточно: нужно собрать отдельную оценку этой кнопки.

В функции `q_from_v` преврати таблицу ценностей состояний в таблицу ценностей пар «состояние, действие». Для каждой такой пары перебери все возможные исходы перехода. У каждого исхода возьми немедленную награду, добавь дисконтированную ценность следующего состояния и умножь результат на вероятность исхода. Затем сложи вклады всех исходов — именно это вычисление разобрано в [шаге 34](#step-34).

Следи за тремя местами, где легко ошибиться:

- создавай отдельное Q-значение для каждого доступного действия, даже если несколько действий ведут в одну клетку;
- умножай на вероятность весь результат ветки, а не только награду;
- не подмешивай вероятности политики: действие здесь уже выбрано, поэтому усреднять нужно только случайные переходы среды.

У детерминированного перехода будет одна ветка с вероятностью `1`. У случайного — несколько, и их вклады должны сложиться. Терминальное состояние не обещает продолжения: используй предусмотренную в заготовке нулевую ценность после завершения.

Проверь себя на простом случае: если возможен только один исход, результат функции должен совпасть с оценкой этой единственной ветки.

> 🎒 **На пальцах.** Ты выбираешь кнопку кофейного автомата. После кнопки «капучино» автомат с вероятностью 90% наливает хороший кофе, а с вероятностью 10% — водянистый. Цена кнопки зависит не от среднего качества всех напитков автомата, а только от возможных исходов именно этой кнопки. `q_from_v` так же оценивает каждое действие отдельно, взвешивая его исходы по вероятностям.
