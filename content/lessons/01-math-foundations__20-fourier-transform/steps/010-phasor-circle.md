Поставь `N = 8` и следи за точкой, которую возвращает `twiddle` из [шага 9](#step-9). При `n = 0` она всегда начинает справа, в точке `1`. Но дальше точка не скользит по окружности плавно: каждый новый отсчёт мгновенно переносит её на следующую разрешённую позицию. Почему иногда она идёт по соседним делениям, а иногда будто перескакивает через них?

Выбери `k = 1`. При увеличении `n` точка каждый раз делает один шаг по часовой стрелке: за восемь отсчётов она обходит окружность один раз. Направление задаёт минус в множителе из [шага 8](#step-8).

Теперь поставь `k = 2`. Один отсчёт — уже два деления, поэтому полный оборот укладывается в четыре шага, а затем те же позиции повторяются. За все восемь отсчётов получится два оборота. При `k = 3` прыжок равен трём делениям: соседние значения `n` окажутся далеко друг от друга, хотя направление вращения останется тем же.

А при `k = 0` точка вообще не двигается: каждый отсчёт получает один и тот же множитель.

Значит, `n` считает шаги, `k` задаёт размер каждого прыжка, а `N` делит окружность на доступные позиции. Меняя `k`, ты не меняешь сам круг — ты меняешь скорость его дискретного обхода.

> 🎒 **На пальцах.** Представь курьера, который развозит письма по восьми домам вокруг круглой площади. При `k = 1` он заезжает в каждый следующий дом. При `k = 2` перескакивает через один и быстро возвращается к знакомым адресам. При `k = 3` маршрут выглядит запутаннее, но правило неизменно: номер шага умножается на длину прыжка, а после последнего дома счёт продолжается с первого.
