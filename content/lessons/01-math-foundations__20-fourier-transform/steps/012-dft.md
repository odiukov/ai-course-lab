У тебя уже есть три детали: сложение комплексных чисел из [шага 5](#step-5), умножение из [шага 7](#step-7) и поворачивающий множитель из [шага 9](#step-9). Теперь нужно собрать из них `dft(x)`.

Допустим, в `x` четыре отсчёта. Может показаться, что достаточно один раз пройти по ним и получить один ответ. Но в [шаге 11](#step-11) каждый индекс `k` задавал отдельный вопрос сигналу. Значит, функция должна вернуть четыре комплексных результата — по одному для каждого `k`.

Сначала определи `N` как длину `x` и подготовь пустой список результатов. Затем организуй два вложенных прохода:

- внешний перебирает `k` от `0` до `N - 1`;
- внутренний перебирает все отсчёты `n`;
- для каждой пары `k` и `n` вычисляется `twiddle(k, n, N)`;
- значение `x[n]` переводится в комплексное число с нулевой мнимой частью, если оно обычное;
- произведение отсчёта и множителя прибавляется к накопленной сумме.

Особенно внимательно выбери места для двух действий. Сумму нужно обнулять в начале каждого нового `k`, иначе результаты разных частот смешаются. Добавлять сумму в итоговый список нужно только после завершения внутреннего прохода.

Для быстрой проверки возьми `x = [1, 0, 0, 0]`. Функция должна вернуть четыре результата, каждый примерно равный `Complex(1, 0)`. Небольшие хвосты вроде `1e-16` допустимы: это погрешность вычислений.

> 🎒 **На пальцах.** Представь проверяющего с четырьмя отдельными бланками. Для каждого `k` он берёт чистый бланк, обходит все четыре образца `n` и складывает их оценки. Закончив обход, кладёт заполненный бланк в папку. Если не взять новый бланк или положить его в папку слишком рано, ответы неизбежно смешаются.
