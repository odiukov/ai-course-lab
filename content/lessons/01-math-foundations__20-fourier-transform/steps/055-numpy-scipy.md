Ты записал секунду звука с частотой дискретизации 256 Гц и вызвал `np.fft.fft`. В ответ пришли 256 комплексных чисел — но где среди них герцы? Если подписать корзины их индексами, пик `5` легко принять просто за пятый элемент массива.

NumPy связывает преобразование и правильную частотную шкалу двумя вызовами:

```python
import numpy as np

fs = 256
t = np.arange(256) / fs
signal = np.sin(2 * np.pi * 5 * t)

spectrum = np.fft.fft(signal)
freqs = np.fft.fftfreq(len(signal), d=1 / fs)
power = np.abs(spectrum) ** 2

mask = freqs >= 0
positive_freqs = freqs[mask]
positive_power = power[mask]
```

Аргумент `d` — время между соседними отсчётами. Поэтому `fftfreq` переводит индексы в герцы по правилу из [шага 13](#step-13), а маска убирает зеркальную отрицательную половину из [шага 15](#step-15). Максимум окажется около 5 Гц.

Если края записи не состыкуются, перед FFT умножь сигнал на окно:

```python
from scipy.signal import windows

windowed = signal * windows.hann(len(signal))
```

Окно уменьшит растекание, но изменит высоту и ширину пика — это тот компромисс, который ты видел в [шаге 37](#step-37).

Когда важно ещё и время появления частоты, один FFT заменяется STFT:

```python
from scipy.signal import stft

f, times, Zxx = stft(signal, fs=fs, nperseg=64)
spectrogram = np.abs(Zxx) ** 2
```

У `spectrogram` строки соответствуют частотам `f`, столбцы — моментам `times`. Теперь числа уже подписаны осями, и матрица получает смысл из [шага 54](#step-54).

> 🎒 **На пальцах.** Представь шкаф с образцами красок. FFT раскладывает запись по банкам, но номера банок ещё не говорят, какой это оттенок. `fftfreq` приклеивает понятные этикетки в герцах, окно смягчает резкий край образца, а STFT ставит рядом несколько таких шкафов — по одному для каждого короткого момента записи.
