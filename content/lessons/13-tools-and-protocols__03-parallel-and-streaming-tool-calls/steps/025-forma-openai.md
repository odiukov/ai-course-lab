Ты включил стрим у OpenAI и печатаешь каждый чанк как есть. Ждёшь в них `id` — тот самый, по которому в [шаге 4](#step-4) результат сопоставлялся с вызовом. Первый чанк: `tool_calls[0]`, внутри `id: "call_a1"`, имя функции, пустая строка аргументов. Второй: `tool_calls[0].function.arguments` = `{"ci`. Третий: `tool_calls[1].function.arguments` = `{"da`. И дальше — десятки кусков, в которых `id` нет вообще.

Чем тогда склеивать?

Посмотри, что в каждом куске всё-таки есть: `index`. Это номер вызова в списке — 0, 1, 2 — и он не меняется до конца стрима. Полный путь до куска строки такой: `choices[0].delta.tool_calls[i].function.arguments`, где `i` и есть этот index. Значит накопитель [из шага 19](#step-19) ты завёшь не на id, а на index: три ячейки с номерами, и каждый пришедший кусок дописывается в свою.

А `id` приходит один раз — в том самом первом чанке, где index появился впервые. Его нужно поймать и положить рядом с ячейкой, потому что склеивать куски ты будешь по index, а вот отправлять результат назад — только по id. Имя функции ведёт себя так же: сказано однажды, потом молчок.

Когда звать `json.loads`, ты уже знаешь из [шага 23](#step-23): по сигналу `finish_reason = "tool_calls"`.

То есть index держит куски вместе, пока стрим идёт, а id нужен после — иначе соберёшь безупречный JSON, который некуда приложить.

> 🎒 **На пальцах.** Мастер разбирает три механизма и раскладывает детали в три пронумерованных лотка. Помощник, подавая винтик, не повторяет каждый раз «это от будильника» — он говорит коротко: «во второй». Название прозвучало один раз, когда лоток заняли; дальше хватает номера. У OpenAI так же: index — номер лотка, `id` — название, произнесённое однажды. Не записал его тогда — в конце у тебя три полных лотка деталей без хозяев.
