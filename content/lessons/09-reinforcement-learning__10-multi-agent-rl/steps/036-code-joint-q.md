Ты запускаешь эпизод и видишь четыре направления для первого агента и четыре для второго. Как выбрать действие из централизованной таблицы? Здесь один вариант — не отдельное движение, а целая пара: например, `(вправо, вверх)`. Поэтому на каждом ходе `train_joint_q` сравнивает все 16 пар из `joint_actions`, написанной в [шаге 26](#step-26).

Собери цикл обучения так:

1. Создай одну Q-таблицу. Её ключ должен включать совместное состояние и пару действий.
2. В начале каждого эпизода установи стартовое совместное состояние.
3. Сделай один ε-жадный выбор среди пар действий: при исследовании возьми случайную пару целиком, иначе найди пару с наибольшим Q-значением.
4. Передай выбранную пару в `joint_step` из [шага 24](#step-24).
5. Обнови одну запись Q общей наградой. Функцию из [шага 31](#step-31) можно переиспользовать: для неё пара действий остаётся обычным ключом, а список следующих действий теперь содержит пары.
6. Перейди в новое состояние и продолжай до завершения эпизода.
7. После всех эпизодов верни обученную таблицу.

Особенно проверь терминальный переход: если `done=True`, будущая ценность не добавляется — это условие уже разобрано в [шаге 30](#step-30). Ещё одна частая ошибка — случайно завести по таблице на агента. Здесь решение хранится только в одной таблице: значение относится ко всей паре движений сразу.

> 🎒 **На пальцах.** Представь сейф с двумя ручками. Комбинация «левая на 2, правая на 7» проверяется целиком: нельзя отдельно оценить, насколько хороша двойка, не зная положения второй ручки. `train_joint_q` перебирает и запоминает именно такие комбинации. Общая награда сообщает, удачной ли оказалась вся пара, а не каждое движение по отдельности.
