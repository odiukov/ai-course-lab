Представь переход, после которого агент добрался до цели и получил `10`. Если функция всё равно добавит ценность следующего состояния, итоговая оценка окажется завышенной: после завершения эпизода агент уже не может получить будущую награду.

Тебе нужно написать `q_learning_update`, которая принимает Q-таблицу и один переход: состояние `s`, выбранное действие `a`, награду `r`, следующее состояние `s_next` и признак `done`, а также `alpha` и `gamma`. Правило обновления уже разобрано в [шаге 30](#step-30), поэтому здесь сосредоточься на его аккуратном переносе в функцию.

Сначала определи целевое значение. Если `done` истинно, используй только полученную награду. Иначе найди максимальную Q-оценку среди действий в `s_next` и учти её с коэффициентом `gamma`. Затем измени ячейку `Q[s][a]`: приблизь старое значение к цели на долю `alpha`.

Проверь три детали:

- обновляется только действие `a` в состоянии `s`;
- остальные ячейки таблицы не меняются;
- для терминального перехода функция не обращается к будущей оценке.

Последний пункт особенно важен с `defaultdict`: даже простое чтение `Q[s_next]` может незаметно создать лишнюю запись. Значит, проверка `done` должна произойти раньше поиска максимума.

> 🎒 **На пальцах.** Ты закрываешь счёт в кафе. Пока заказ продолжается, к текущей сумме можно прибавить ожидаемую стоимость следующего блюда. Но после оплаты продолжения уже нет: в итог попадает только последний чек. Если всё равно добавить «будущее блюдо», которого никто не заказывал, сумма станет неверной — так же терминальный переход нельзя дополнять будущей Q-оценкой.
