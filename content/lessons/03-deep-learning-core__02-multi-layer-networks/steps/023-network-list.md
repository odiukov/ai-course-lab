title: Сеть — это упорядоченный список совместимых слоёв

У тебя есть два готовых слоя сети 2–3–1. Один принимает два числа и выдаёт три, другой принимает три и выдаёт одно. Кажется, можно просто сложить их в коллекцию — ведь оба всё равно принадлежат одной сети. Но если поставить слой 3→1 первым, он сразу получит два числа вместо трёх и не сможет выполнить вычисление.

Значит, недостаточно знать, **какие** слои есть в сети. Важно ещё и **в каком порядке** они стоят. Для сети 2–3–1 список начинается со слоя 2→3, а заканчивается слоем 3→1. Перестановка меняет не оформление списка, а саму конструкцию сети.

У соседних слоёв есть ещё одно обязательное условие: их размеры должны стыковаться. Число выходов первого слоя должно совпадать с числом входов второго. Здесь первый слой создаёт три значения, и именно три значения ожидает следующий. Формы весов помогают проверить такую совместимость заранее — ты уже разбирал это в [шаге 20](#step-20) и вычислял их с помощью `layer_shapes` в [шаге 21](#step-21).

Поэтому сеть удобно хранить как **упорядоченный список совместимых слоёв**. Порядок задаёт маршрут вычисления, а совместимость гарантирует, что на каждой соседней паре размеры сходятся. Если хотя бы одно из этих условий нарушено, цепочка перестаёт быть рабочей сетью.

> 🎒 **На пальцах.** Представь набор переходников для зарядного кабеля: USB-C → USB-A, затем USB-A → розетка. Оба переходника полезны, но соединить их можно только в подходящем порядке. Если развернуть цепочку или вставить переходник с другим разъёмом, электричеству просто некуда идти. Слои собираются по тому же принципу: выходной «разъём» одного должен подходить входному «разъёму» следующего.
