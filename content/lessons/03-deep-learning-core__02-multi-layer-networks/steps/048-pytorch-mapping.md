После функций из [шага 19](#step-19) и [шага 25](#step-25) код PyTorch может показаться подозрительно коротким:

```python
model = nn.Sequential(
    nn.Linear(2, 8),
    nn.Sigmoid(),
    nn.Linear(8, 1),
    nn.Sigmoid(),
)
```

Куда исчезли матрицы, смещения и передача результатов между слоями? Никуда — знакомые тебе действия просто получили готовые имена.

`nn.Linear(2, 8)` принимает два числа и выдаёт восемь. Внутри него находятся матрица весов формы `(8, 2)` и восемь смещений. По правилу из [шага 44](#step-44) это 24 настраиваемых параметра. Следующий `nn.Sigmoid()` поэлементно преобразует все восемь результатов, как функция из [шага 11](#step-11).

Затем `nn.Linear(8, 1)` превращает восемь чисел в одно и хранит ещё 9 параметров. Последняя сигмоида делает ответ мягким — от 0 до 1.

`nn.Sequential(...)` отвечает только за порядок: берёт выход одного элемента и передаёт следующему, повторяя логику [шага 24](#step-24). Если подать сразу четыре примера XOR формой `(4, 2)`, модель вернёт четыре ответа формой `(4, 1)`.

PyTorch ускоряет вычисления на GPU и умеет автоматически готовить градиенты для обучения. Но сам прямой проход остался тем же — знакомая конструкция лишь упакована в удобные детали.

> 🎒 **На пальцах.** Представь набор модулей для обработки фотографий. Первый создаёт из двух исходных настроек восемь промежуточных, второй меняет каждую по одной кривой, третий сводит восемь значений к одному. `Sequential` — сохранённый порядок модулей: ты нажимаешь одну кнопку, но фотография всё равно проходит каждый этап по очереди.
