Возьми BoW-вектор документа `[2, 0, 1]`. Если просто вернуть эти числа, функция ничего не изменит: длинные документы по-прежнему будут получать большие значения. Твоя задача — превратить каждый счётчик в долю от длины документа, используя правило из [шага 12](#step-12).

Напиши функцию `term_frequency(doc_bow, doc_length)`. Она получает:

- `doc_bow` — одну строку BoW-матрицы, то есть счётчики слов в документе;
- `doc_length` — общее количество слов в исходном документе.

Функция должна вернуть новый список той же длины. Для `[2, 0, 1]` и длины `3` результатом будут значения `[2 / 3, 0 / 3, 1 / 3]`. Исходный список менять не нужно.

Обрати внимание на пустой документ. Если `doc_length` равен нулю, делить на него нельзя. В этом случае для каждой позиции верни `0`. Список должен сохранить размер `doc_bow`: пустой документ не отменяет словарь и его фиксированные координаты.

После реализации проверь три вещи: число элементов не изменилось, нулевые счётчики остались нулями, а ненулевые значения стали долями. Именно деление на общую длину убирает преимущество, которое один документ получил лишь потому, что в нём больше слов.

> 🎒 **На пальцах.** Представь две одинаковые по размеру формы для льда. В первой заполнены две ячейки из четырёх, во второй — четыре из восьми. Сырые числа разные: `2` и `4`. Но доля одинакова — половина формы. `term_frequency` делает похожее: смотрит не только на количество слова, но и на размер всего документа.
