Ты копируешь чекпойнт с сетевого диска, запускаешь обучение и видишь странность: loss не падает, хотя файлы открылись без ошибок. Один шард мог загрузиться лишь на 99%, а формат файла всё равно оказался достаточно правдоподобным для чтения. Значит, успешное открытие ещё не доказывает целостность.

Точкой отсчёта служит индекс из [шага 8](#step-8). В нём зафиксированы ожидаемое число шардов, имена файлов и их SHA-256 — короткие контрольные отпечатки содержимого. Такой же отпечаток записан для `meta`, где лежит остальное состояние обучения из [шага 5](#step-5).

Перед восстановлением загрузчик должен сверить опубликованный набор с индексом: все ли файлы на месте, совпадает ли число шардов и тот ли отпечаток получается у каждого файла. Для этого SHA-256 вычисляют заново по фактически прочитанным байтам. Изменился, пропал или оборвался хотя бы один файл — весь чекпойнт считается непригодным.

Почему нельзя просто пропустить повреждённый шард? Тогда часть параметров пришла бы из прошлого прогона, часть отсутствовала бы, а ошибка могла проявиться лишь странными числами спустя сотни шагов. Гораздо безопаснее остановиться сразу с понятным сообщением, ещё до изменения состояния модели.

Итак, возобновление начинается не с загрузки весов, а с доказательства, что опубликованный комплект дошёл целиком.

> 🎒 **На пальцах.** Представь доставку мозаики для реставрации: по накладной должны приехать шесть пронумерованных коробок, а на каждой указан контрольный вес. Если коробок шесть, но одна легче на килограмм, мастер не начинает выкладывать стену «из того, что есть». Он останавливает приёмку: иначе недостающие фрагменты обнаружатся только посреди рисунка, когда исправлять уже дорого.
