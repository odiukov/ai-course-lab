Представь: обучение дошло до 8 000-го шага, и ты сохраняешь чекпойнт прямо поверх предыдущего. В этот момент процесс падает. Старый файл уже повреждён, новый не дописан — возобновляться не из чего, хотя содержимое прошло проверку из [шага 2](#step-2).

Тебе нужно реализовать `atomic_save`: финальный путь должен появляться только после успешной записи всего файла. Сначала создай родительскую директорию, если её ещё нет. Затем подготовь временный файл рядом с будущим чекпойнтом — именно в той же директории. Закрой его перед передачей в `torch.save`, чтобы библиотека могла самостоятельно открыть путь и записать payload.

Пока идёт запись, финальный файл не трогай. Если процесс оборвётся, по прежнему имени останется доступна старая целая версия. И только когда `torch.save` завершится без ошибки, замени старый файл временным через `os.replace`. Для наблюдателя это одна операция: он увидит либо прежний чекпойнт, либо уже полностью записанный новый, но не промежуточную половину.

Обрати внимание и на неудачный путь выполнения. Временный файл нужно попытаться удалить независимо от того, успешно прошли сохранение и замена или возникло исключение. При этом отсутствие файла во время уборки не должно создавать новую ошибку: после успешной замены временного пути уже нет. В конце функция возвращает финальный `Path`.

Смысл шва простой: долго готовим файл под черновым именем, а публичное имя меняем одним коротким движением.

> 🎒 **На пальцах.** В кафе не переписывают меню на вывеске, пока посетители его читают. Новую версию полностью печатают за стойкой, проверяют, а затем одним движением ставят на место старой. Если принтер зажевал бумагу, снаружи всё ещё висит прежнее целое меню; испорченный черновик остаётся только убрать.
