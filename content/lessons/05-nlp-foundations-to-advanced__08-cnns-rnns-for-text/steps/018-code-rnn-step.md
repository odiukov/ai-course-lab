Ты подаёшь функции embedding текущего слова и прошлое скрытое состояние. Оба выглядят как наборы чисел, поэтому легко случайно сложить их напрямую. Но размеры могут различаться: например, у `x_t` — 4 числа, а у `h_prev` — 3. Сначала каждый вход нужно преобразовать своей матрицей весов.

Напиши `rnn_step`, который выполняет одно обновление из [шага 17](#step-17). Функция должна:

1. умножить `x_t` на `W`;
2. отдельно умножить `h_prev` на `U`;
3. сложить два результата и `b`;
4. применить функцию активации;
5. вернуть новое состояние `h_t`.

Здесь важен именно один шаг: функция не принимает весь текст и не запускает цикл по токенам.

Следи за формами данных. Если размер embedding равен `4`, а размер hidden state — `3`, то после обоих умножений должны получиться векторы из `3` чисел. Только тогда к ним можно прибавить `b`, в котором тоже `3` числа. В качестве активации используй `tanh`: она применяется поэлементно и оставляет форму результата неизменной.

Для самопроверки временно замени `tanh` функцией, которая просто возвращает вход. Тогда ты сможешь вручную проверить сложение преобразованных векторов. После возвращения `tanh` каждое число в `h_t` должно лежать между `-1` и `1`.

> 🎒 **На пальцах.** Представь кассу, которая пересчитывает текущую сумму покупки. Цена нового товара проходит через одно правило скидок, прежний итог — через другое правило пересчёта. Затем касса складывает оба результата, добавляет фиксированную поправку и ограничивает показание допустимым диапазоном. `rnn_step` делает ровно один такой пересчёт и выдаёт обновлённый итог.
