title: Когда последовательная память полезна в потоковой обработке

В чате поддержки сообщение появляется по частям: «Не могу войти… деньги списались… дважды». Если ждать последней точки, система поздно заметит срочный случай. А если заново прогонять весь накопившийся текст после каждого нового слова, работа будет повторяться.

Здесь полезна последовательная память RNN. После очередного токена модель сохраняет hidden state — компактную сводку прочитанного, знакомую по [шагу 16](#step-16). Когда приходит следующий токен, обработка продолжается с этой сводки, а не начинается с нуля. Именно полный проход из [шага 20](#step-20) теперь растянут во времени: один шаг вычисления выполняется при каждом новом фрагменте.

Так можно постоянно обновлять оценку: например, повышать вероятность категории «проблема с оплатой» ещё до завершения сообщения. Задержка мала, а хранить всю историю для повторной обработки не обязательно. Это удобно для живых расшифровок речи, чатов и непрерывных текстовых журналов.

Есть и цена: модель видит только прошлое. Слово, которое придёт через секунду, пока не может исправить смысл текущего токена. Поэтому потоковая RNN особенно уместна, когда решение нужно обновлять немедленно и допустимо уточнять его по мере поступления текста. Память выигрывает не потому, что знает будущее, а потому, что не перечитывает прошлое.

> 🎒 **На пальцах.** Представь секретаря у телефона. После каждой реплики он дописывает короткую заметку: «клиент не вошёл, возможно списание». Следующую реплику он понимает с учётом этой заметки, не прослушивая разговор с начала. Но знать, чем собеседник закончит фразу, секретарь не может — его вывод всегда основан только на уже услышанном.
