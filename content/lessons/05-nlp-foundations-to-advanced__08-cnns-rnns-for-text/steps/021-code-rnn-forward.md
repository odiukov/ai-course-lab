Ты передаёшь функции embeddings пяти токенов и ожидаешь пять новых hidden states. Но если на каждой итерации случайно снова брать начальное состояние, RNN увидит пять отдельных слов вместо одной последовательности. Значит, главная задача `rnn_forward` — не просто вызвать `rnn_step` несколько раз, а правильно передавать результат одного вызова в следующий.

Возьми `h0` как состояние до первого токена. Затем двигайся по входу строго слева направо. Для очередного embedding вызови написанную в [шаге 18](#step-18) функцию `rnn_step`, передав ей текущее состояние. Полученный `h` сохрани и используй как предыдущее состояние для следующего токена. Веса при этом остаются одними и теми же на всех итерациях — именно это обсуждалось в [шаге 19](#step-19).

Функция должна вернуть hidden state для каждого токена, собранные в исходном порядке. Если вход содержит `T` токенов, в результате тоже должно быть `T` строк; ширина каждой строки равна размеру hidden state. Обрати внимание: `h0` помогает начать вычисление, но не становится дополнительной строкой результата.

Проверь себя на трёх местах: состояние не сбрасывается внутри цикла, результаты не перезаписываются одним последним `h`, а список состояний в конце превращается в единый массив. Тогда `rnn_forward` действительно реализует последовательный проход из [шага 20](#step-20): каждый следующий результат несёт след предыдущих токенов.

> 🎒 **На пальцах.** Представь экскурсанта, который после каждой комнаты делает новую запись в путевом журнале. Первая запись опирается на пустую стартовую страницу, а каждая следующая — на уже заполненный журнал. `rnn_forward` проводит экскурсанта через все комнаты по порядку и сохраняет снимок записи после каждой. Если каждый раз выдавать чистый журнал, связь между комнатами исчезнет.
