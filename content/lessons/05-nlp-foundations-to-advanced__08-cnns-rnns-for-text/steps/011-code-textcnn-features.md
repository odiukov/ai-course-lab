У тебя уже есть карты признаков для окон ширины 2, 3 и 4. Но склеить их сразу не получится: в каждой карте разное число позиций. Значит, сначала нужно превратить каждую карту в компактный набор самых сильных откликов, а уже потом объединять результаты.

В `textcnn_features` собери детали из предыдущих шагов в одну операцию. Для каждой ширины фильтра:

1. Передай embeddings и соответствующий набор фильтров в `conv1d` из [шага 6](#step-6).
2. Примени предусмотренную в заготовке функцию активации: она оставит полезные положительные отклики.
3. Сожми карту признаков через `global_max_pool` из [шага 9](#step-9).
4. Сохрани получившийся набор оценок.

После обработки всех ширин склей сохранённые результаты по оси признаков. Следи, чтобы строки батча не перемешивались: первая строка результата должна целиком относиться к первому тексту, вторая — ко второму и так далее. Частая ошибка — объединить массивы по оси батча или попытаться склеить карты до pooling.

Проверь себя на маленьком примере: для каждого текста в результате должны подряд идти признаки от всех групп фильтров — сначала одной ширины, затем следующей. Сами позиции слов после pooling уже не нужны.

> 🎒 **На пальцах.** Представь три команды кладоискателей с ситами разного размера. Каждая команда проходит свой участок и находит много камешков, но в штаб приносит только самые крупные находки каждого типа. В штабе не смешивают находки разных участков: для каждого участка их складывают в один подписанный ящик. `textcnn_features` как раз организует такой сбор и упаковку результатов.
