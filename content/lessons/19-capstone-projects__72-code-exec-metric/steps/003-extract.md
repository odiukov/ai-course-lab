В генерации модель может прислать не только программу, но и пояснение: «Вот решение», затем блок кода и ещё пару фраз. Если передать весь ответ дальше, обычный русский текст окажется внутри Python-файла — и выполнение сломается ещё до проверок из [шага 2](#step-2).

Тебе нужно дописать `extract_code`, которая отделяет код от оформления ответа. Сначала поищи фрагмент, заключённый в тройные обратные кавычки. Для этого уже подготовлено регулярное выражение `CODE_BLOCK_RE`. Если подходящий блок найден, функция должна вернуть только его содержимое: без самих кавычек и без текста вокруг.

Но есть неприятный пограничный случай. В тексте встречаются тройные кавычки, а полноценный блок распознать не удалось — например, модель забыла закрывающую границу. Возвращать весь ответ опасно: служебные слова могут замаскироваться под программу. Здесь ожидается `None`, то есть честный сигнал «код извлечь не получилось».

Наконец, модель иногда отвечает чистым кодом вообще без Markdown-обёртки. Если тройных кавычек в тексте нет, функция должна принять весь текст как кандидата и вернуть его без изменений.

При реализации проверь именно порядок этих трёх случаев. Наличие сломанной разметки важнее запасного варианта с «чистым кодом»: иначе повреждённый ответ ошибочно пройдёт дальше. На этом шаге ты только выбираешь безопасный фрагмент; запускать его пока не нужно.

> 🎒 **На пальцах.** Представь посылку с наклейкой «содержимое здесь». Если внутри есть аккуратно закрытый пакет, ты достаёшь только его. Если видишь разорванную упаковку, посылку откладываешь: непонятно, где заканчивается содержимое. А если упаковки вовсе нет и перед тобой один предмет, берёшь его целиком. Так `extract_code` отличает оформленный код, повреждённый ответ и чистый код.
