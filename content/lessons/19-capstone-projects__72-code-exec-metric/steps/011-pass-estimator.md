Ты получил результаты трёх задач: для каждой лежит свой список `True` и `False`, а в `ks` указаны режимы сравнения — например, 1, 5 и 10 попыток. Нужно вернуть словарь, где каждому `k` соответствует один итоговый `float`.

Не смешивай все попытки в общую кучу. Такая склейка даст больший вес задаче с длинным списком кандидатов. Вместо этого для каждого `k` создай отдельный набор оценок по задачам. У каждой задачи посчитай `n` — число кандидатов — и `c` — число значений `True`, а затем передай их функции `pass_at_k` из [шага 9](#step-9). Граничные случаи внутри этой функции повторно обрабатывать не надо.

Когда оценки всех задач для текущего `k` готовы, усредни их способом из [шага 10](#step-10) и запиши результат в словарь под ключом `k`. Затем проделай то же для следующего значения. Важно каждый раз начинать новый список оценок: иначе результат для `k=5` случайно захватит числа, рассчитанные для `k=1`.

Обрати внимание и на пустой вход. Если задач нет, среднее считать не из чего, поэтому для каждого запрошенного `k` функция должна вернуть `0.0`. Проверь контракт на простом примере: число ключей совпадает с числом различных значений `k`, а каждое значение отражает среднее по задачам, не по отдельным кандидатам.

> 🎒 **На пальцах.** Представь дегустацию нескольких сортов чая. Для каждого сорта ты завариваешь несколько чашек и сначала оцениваешь шанс получить хотя бы одну удачную среди `k` чашек. Только после этого усредняешь оценки сортов. Если свалить все чашки вместе, сорт с большим числом завариваний начнёт решать за остальные — именно эту ошибку предотвращает сводка по задачам.
