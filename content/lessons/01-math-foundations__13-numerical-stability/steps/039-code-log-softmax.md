Ты подаёшь в функцию логиты `[1000, 1001, 1002]`. Если сначала вызвать `softmax`, а затем взять логарифм, можно снова получить числовые проблемы из [шага 38](#step-38). Поэтому задача здесь другая: вычислить логарифмы вероятностей напрямую, не создавая сами вероятности как промежуточный результат.

Напиши `log_softmax(x, axis=-1)`. Для выбранной оси функция должна найти устойчивый `logsumexp` из [шага 30](#step-30), а затем вычесть этот общий нормализатор из каждого соответствующего логита. Не реализуй внутри цепочку `log(softmax(x))`: она теряет весь смысл отдельной функции.

Особенно внимательно следи за формой нормализатора. Для матрицы каждая строка должна обрабатываться независимо, если `axis=-1`. Сохрани вычисленную ось размером 1, чтобы вычитание корректно распространилось по исходному массиву. Иначе на векторе всё сработает, а на батче либо появится ошибка формы, либо строки смешаются.

Проверь три свойства:

- для `[1000, 1001, 1002]` результат конечный и примерно равен `[-2.4076, -1.4076, -0.4076]`;
- экспоненты результатов суммируются примерно в 1 вдоль `axis`;
- прибавление одного и того же числа ко всем логитам не меняет ответ, как и у `softmax` из [шага 34](#step-34).

Если эти проверки проходят и для вектора, и для матрицы, функция действительно нормализует по нужной оси.

> 🎒 **На пальцах.** Представь три ценника, записанные не в рублях, а как наценки относительно общего базового тарифа. Тебе незачем сначала вычислять огромные полные цены, затем превращать их в доли и только потом брать логарифм. Вычти общий тариф прямо из каждого ценника: относительные различия сохранятся, а опасные промежуточные числа вообще не появятся.
