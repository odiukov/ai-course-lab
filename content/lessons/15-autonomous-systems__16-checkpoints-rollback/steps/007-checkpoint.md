Представь: workflow прошёл три перехода — `created → paid`, `paid → packed`, `packed → shipped`, — а в хранилище появились только первая и последняя записи. Всё выглядит почти правильно, но момент упаковки потерян. Значит, функция не должна решать, какой переход «достаточно важен»: один её вызов соответствует одному сохранённому переходу.

Допиши функцию записи checkpoint в редакторе. При каждом вызове она должна:

- получить данные текущего перехода;
- создать снимок состояния функцией из [шага 5](#step-5);
- связать этот снимок с конкретным переходом, как разобрано в [шаге 6](#step-6);
- добавить получившийся checkpoint в переданное хранилище;
- вернуть именно созданный checkpoint.

Обрати внимание на порядок действий. Сначала нужен снимок состояния, относящийся к этому переходу, и только затем — запись, которая связывает их. Не сохраняй само рабочее состояние по ссылке: после следующего изменения старый checkpoint не должен незаметно измениться вместе с ним.

Не добавляй условия вроде «сохранять только при оплате» или «пропускать промежуточные состояния». Если функция вызвана для перехода, запись должна появиться. Тогда после трёх вызовов в хранилище окажутся три отдельных checkpoint, каждый со своим снимком и описанием перехода.

> 🎒 **На пальцах.** Представь монтаж фильма: после каждой правки монтажёр сохраняет кадр и подписывает, какое действие только что сделал — «обрезал сцену», «добавил звук», «исправил цвет». Если записывать лишь некоторые правки, между двумя подписями останется провал. Checkpoint — это такая подписанная фиксация, и новая запись нужна после каждой правки.
