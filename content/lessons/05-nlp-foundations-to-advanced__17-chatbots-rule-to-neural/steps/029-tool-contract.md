Ты просишь агента узнать погоду в Лиссабоне на субботу. Модель понимает запрос, но сама не заглядывает в метеосервис. Фраза «сейчас проверю» тоже ничего не запускает. Как же перейти от намерения к настоящему действию из цикла, описанного в [шаге 28](#step-28)?

Модель формирует специальное сообщение — **tool call**, то есть заявку на вызов инструмента. В ней есть две главные части:

```json
{
  "name": "get_weather",
  "arguments": {
    "city": "Lisbon",
    "date": "2026-08-15"
  }
}
```

`name` — имя функции, которую нужно найти среди доступных инструментов. `arguments` — словарь аргументов: у каждого параметра есть ключ и значение. Это не команда на человеческом языке вроде «посмотри погоду послезавтра», а структура, которую среда может разобрать без догадок.

Важно разделять роли. Модель **предлагает вызов**, но не исполняет функцию внутри себя. Среда получает имя `get_weather`, находит соответствующую функцию в своём наборе `tools` и передаёт ей значения `city` и `date`. Поэтому модель может работать только с теми инструментами, которые среда заранее ей показала.

Получается чёткая граница: модель решает, **что вызвать и с какими данными**, а среда действительно выполняет действие.

> 🎒 **На пальцах.** Представь пульт сцены. Ты передаёшь технику карточку: «световая_сцена» и параметры «цвет: синий», «яркость: 60». Техник не толкует длинную просьбу на слух: он находит на пульте нужную программу и выставляет указанные значения. Tool call — такая же карточка: имя выбирает действие, а словарь точно задаёт его настройки.
