  - question: >-
      У команды две задачи: восстановить происхождение и жизненный цикл выборки,
      а затем показать сведения о данных разным аудиториям с разной глубиной.
      Какие документы лучше соответствуют этим задачам?
    options:
      - 'Сначала Datasheet, затем многослойная Data Card'
      - 'Сначала Model Card, затем System Card'
      - 'Сначала System Card, затем Datasheet'
      - Для обеих задач достаточно Model Card
    correct: 0
    explanation: >-
      Datasheet фиксирует происхождение и жизненный цикл датасета, а Data Card
      представляет сведения о данных на нескольких уровнях глубины для разных
      читателей.
  - question: >-
      В Model Card указана общая точность 91%, но для одной значимой группы она
      равна 64%. Какое действие делает карточку содержательной?
    options:
      - 'Оставить только 91%, чтобы не перегружать читателя'
      - Удалить обе метрики и описать качество словами
      - Показать разбивку по группам и связать разрыв с ограничениями применения
      - Перенести групповую метрику только в Datasheet
    correct: 2
    explanation: >-
      Общая точность 91% скрывает результат 64% для значимой группы. Разбивка и
      явно указанные ограничения дают читателю сведения, необходимые для решения
      о применении модели.
  - question: >-
      В System Card перечислены фильтры и модерация, но ничего не сказано об
      инцидентах и границах системы. Как оценить документ?
    options:
      - 'Карточка полна, потому что защиты названы'
      - >-
        Карточка неполна: перечисление защит не заменяет сведения об инцидентах
        и границах
      - Это дефект только Model Card
      - Недостающие сведения относятся исключительно к Datasheet
    correct: 1
    explanation: >-
      System Card должна описывать не только предусмотренные защиты, но и их
      проверку, известные инциденты и границы всей развёрнутой системы.
  - question: >-
      Компания утверждает, что проверила ограничение модели. Что сильнее всего
      превращает это утверждение в проверяемую аттестацию?
    options:
      - Более уверенная формулировка в карточке
      - Подпись автора модели без приложенных результатов
      - Ссылка на популярность и число скачиваний
      - Связь утверждения с доказательством и указанием проверяющей стороны
    correct: 3
    explanation: >-
      Проверяемость появляется, когда читатель может сопоставить конкретное
      утверждение с доказательством, установить его целостность и понять, какая
      сторона выполнила проверку.

Дальше тебе пригодится не запоминание названий, а умение найти масштаб пробела: данные, модель или развёрнутая система. Чаще всего сбивают заполненные заголовки без свидетельств, средняя метрика без групповой разбивки и перечень защит без результатов проверок. В каждом случае спрашивай: какое решение должен принять читатель и чем оно подтверждено?
