Перед тобой два тензора: логарифмы вероятностей предпочитаемых и отвергнутых ответов. Простое вычитание здесь не подходит: ORPO сравнивает не вероятности, а **шансы**, как разобрано в [шаге 25](#step-25). Значит, внутри `orpo_loss` тебе сначала нужно превратить каждый `logp` в логарифм шансов.

У тебя уже есть $\log p$. Вторую часть, $\log(1-p)$, вычисляй численно устойчиво через операции над `logp`, не переводя всё сначала в обычные вероятности. У длинных ответов они могут быть настолько малы, что округлятся до нуля. Также помни: корректный `logp` не больше нуля; значение около нуля требует защиты от попытки взять логарифм нулевого $1-p$.

Затем вычти логарифм шансов отвергнутого ответа из логарифма шансов предпочитаемого. Полученный разрыв передай в отрицательный `logsigmoid`: это предпочтительная часть потерь. SFT-часть проще — отрицательный `chosen_logp`. Объедини обе части с коэффициентом `lambda_` и усредни по батчу.

Проверь функцию на трёх свойствах:

- при `lambda_ = 0` остаётся только SFT-потеря;
- чем увереннее chosen опережает rejected по шансам, тем меньше предпочтительный штраф;
- результат остаётся конечным даже для очень отрицательных `logp`.

Не перепутай уровень усреднения: сначала получи полную потерю для каждой пары, затем верни одно среднее число.

> 🎒 **На пальцах.** Представь редактора с двумя ручками. Первая делает выбранную фразу заметнее сама по себе — это SFT-якорь. Вторая увеличивает её преимущество над отбракованной фразой — это отношение шансов. `lambda_` задаёт, насколько сильно редактор крутит вторую ручку. Функция должна свести обе настройки в один показатель, не потеряв слабые сигналы из-за округления.
