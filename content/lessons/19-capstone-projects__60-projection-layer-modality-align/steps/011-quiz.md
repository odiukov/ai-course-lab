check:
  - question: >-
      Какой результат теста подтверждает, что таблица текстовых эмбеддингов
      действительно заморожена?
    options:
      - 'Параметры таблицы получают градиенты, но их нормы остаются небольшими'
      - Среди параметров таблицы нет параметров с requires_grad=True
      - Оптимизатор обновляет только смещения таблицы
      - >-
        После обратного прохода веса таблицы изменяются вместе с весами
        проектора
    correct: 1
    explanation: >-
      Тест считает параметры таблицы с включённым requires_grad и требует ровно
      ноль. Так замороженная часть не попадёт в обучение.
  - question: >-
      Проектор принимает тензор формы B × D_vision и настроен на выходную
      размерность D_text. Какую форму должен подтвердить тест?
    options:
      - D_text без оси batch
      - B × D_vision независимо от настройки проектора
      - B × D_text
      - D_text × B
    correct: 2
    explanation: >-
      Проектор заменяет последнюю размерность признаков на out_dim, сохраняя
      ведущую размерность batch.
  - question: >-
      После обратного прохода как проверить, что функция потерь действительно
      связана с обучаемым проектором?
    options:
      - >-
        Хотя бы у одного обучаемого параметра проектора появился ненулевой
        градиент
      - У всех параметров проектора поле grad осталось пустым
      - Градиенты появились только у замороженной таблицы эмбеддингов
      - Количество параметров проектора уменьшилось
    correct: 0
    explanation: >-
      Ненулевой градиент показывает, что вычислительный граф ведёт от потери к
      проектору. Без него оптимизатор не сможет обучать проекцию.
  - question: >-
      Какой результат одновременно подтверждает правильный смысл косинусной
      потери и работоспособность цикла обучения?
    options:
      - >-
        Противоположные направления штрафуются слабее совпадающих, а потеря
        растёт
      - 'Все направления получают одинаковый штраф, который не меняется'
      - Штраф определяется только длинами эмбеддингов и не зависит от проектора
      - >-
        Совпадающие направления штрафуются слабее противоположных, а итоговая
        потеря становится ниже начальной
    correct: 3
    explanation: >-
      Для совпадающих направлений ожидается потеря 0, для противоположных — 2.
      Снижение между шагами 0 и 200 показывает, что градиенты полезно обновляют
      проектор.

Дальше тебе понадобится проверять не отдельные детали, а весь путь сразу: контракт пары из [шага 4](#step-4), маскирование padding из [шага 6](#step-6), форму проекции из [шага 8](#step-8) и поведение потери из [шага 10](#step-10). Чаще всего всё ломается тихо: форма выглядит правдоподобно, но batch исчез, замороженные параметры обучаются или градиент не доходит до проектора.
