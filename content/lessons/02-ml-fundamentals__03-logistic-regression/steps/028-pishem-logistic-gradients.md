Представь пакет из трёх объектов, у каждого по два признака. Модель уже выдала три вероятности, но для обучения мало знать, что она ошиблась: нужно понять, какой сигнал передать каждому из двух весов и смещению.

Допиши `logistic_gradients(X, y, w, b)`. Сначала получи вероятности через `predict_proba` из [шага 12](#step-12), затем найди промахи `p - y`, разобранные в [шаге 26](#step-26). После этого собери градиенты по правилу из [шага 27](#step-27).

Обрати внимание на размеры. Если в `X` три строки и два столбца, функция должна вернуть:

- `dw` — массив из двух чисел: по одному градиенту для каждого признака;
- `db` — одно число: общий градиент смещения.

Для `dw` каждый промах должен быть связан с признаками именно своего объекта. Удобно мыслить так: столбцы `X` собирают влияние по отдельным признакам, а усреднение по числу строк не даёт размеру пакета искусственно увеличивать градиент. Для `db` признаки не нужны — достаточно среднего промаха.

Не меняй внутри функции `w` и `b`: сейчас её задача только измерить направление и величину необходимых изменений. Проверь также, что деление выполняется на число объектов, а не на число признаков. Хороший контрольный признак — длина `dw` совпадает с длиной `w`, а `db` остаётся скаляром.

> 🎒 **На пальцах.** Представь редактора, который проверяет три анкеты с двумя полями. По каждому полю он складывает замечания, учитывая содержимое именно этого поля, — так получаются два числа `dw`. Отдельно он считает общий перекос ответов, не привязанный ни к одному полю, — это `db`. Затем все суммы делятся на три, чтобы размер стопки анкет не менял строгость редактора.
