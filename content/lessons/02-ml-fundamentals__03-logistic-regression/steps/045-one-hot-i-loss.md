Ты сортируешь фотографию по трём папкам: «кошка», «собака», «лиса». Правильный ответ — «лиса», но слово нельзя напрямую сопоставить с тремя вероятностями модели. Поэтому метку записывают как список переключателей в фиксированном порядке:

\[
[0,\ 0,\ 1]
\]

Такую запись называют **one-hot меткой**: единица стоит только у истинного класса, остальные позиции равны нулю. Если порядок классов — «кошка, собака, лиса», переставлять позиции нельзя.

Допустим, softmax из [шага 42](#step-42) выдал вероятности \([0{,}15,\ 0{,}25,\ 0{,}60]\). С ними сопоставляют one-hot метку с помощью **categorical cross-entropy** — многоклассового варианта функции потерь:

\[
L=-\sum_{k=1}^{K} y_k\log(p_k)
\]

Здесь \(K\) — число классов, \(y_k\) — значение one-hot метки для класса \(k\), а \(p_k\) — предсказанная для него вероятность.

Посмотри, что делает one-hot запись: слагаемые для кошки и собаки умножаются на ноль и исчезают. Остаётся только \(-\log(0{,}60)\) — штраф за вероятность, отданную настоящему классу. Если модель назначит лисе всего \(0{,}01\), штраф резко вырастет. Значит, loss не требует высокой вероятности у всех классов сразу: он проверяет, сколько модель отдала правильному.

> 🎒 **На пальцах.** Представь пульт викторины с тремя кнопками. Ведущий подсвечивает одну правильную кнопку — это one-hot метка. Модель раскладывает сто жетонов между всеми кнопками. Проверяющий смотрит только на подсвеченную: много жетонов — маленький штраф, почти ни одного — большой. Нули у остальных кнопок не объявляют их вероятности; они лишь показывают, какой ответ считать правильным.
