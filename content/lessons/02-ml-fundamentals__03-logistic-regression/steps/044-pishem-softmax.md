Ты передаёшь функции три балла: `1000`, `1001` и `1002`. Если сразу вычислять экспоненты, программа может получить слишком большие числа, хотя сами различия между баллами совсем небольшие. Поэтому функция `softmax(scores)` должна сначала выполнить защитный шаг из [шага 43](#step-43): найти максимальный балл и вычесть его из каждого элемента. Получится `-2`, `-1`, `0` — безопасные числа с теми же отношениями между классами.

Затем для каждого сдвинутого балла нужно вычислить экспоненту через `math.exp`. Сложи получившиеся значения, а после раздели каждое из них на общую сумму. Так ты реализуешь преобразование из [шага 42](#step-42), не повторяя проблему с огромными числами.

Функция должна вернуть список вероятностей в том же порядке, в котором пришли баллы. Если третий балл был самым большим, третья вероятность тоже должна оказаться самой большой. Не округляй значения внутри функции: округление пригодно для красивого вывода, но здесь только снижает точность.

Проверь реализацию на нескольких свойствах:

- количество вероятностей совпадает с количеством баллов;
- каждое значение находится между `0` и `1`;
- сумма результатов очень близка к `1`;
- одинаковые баллы дают одинаковые вероятности;
- большие входы вроде `1000`, `1001`, `1002` не вызывают переполнения.

Из-за погрешности вычислений сумма может быть не буквально `1.0`, а, например, `0.9999999999999999`. Это нормальный результат, поэтому сравнивай её с единицей с небольшим допуском.

> 🎒 **На пальцах.** Представь забег трёх спортсменов. Тебе важны не огромные числа на секундомере, а отставание каждого от лидера. Ты ставишь результат лидера за ноль, сохраняешь разрывы между участниками, а затем распределяешь весь призовой фонд пропорционально их шансам. Вычитание лидирующего результата делает расчёт удобным, а деление на общую сумму гарантирует: весь фонд распределён без остатка.
