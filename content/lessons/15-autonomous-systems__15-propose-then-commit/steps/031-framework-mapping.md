title: Три API реализуют одну и ту же инженерную форму

Ты открываешь документацию трёх фреймворков и видишь три непохожих команды. LangGraph предлагает `interrupt()`: будто нужно просто остановиться. Microsoft Agent Framework создаёт `RequestInfoEvent`: будто агент задаёт вопрос. Cloudflare вызывает `waitForApproval()`: будто речь только о кнопке согласия. Легко решить, что перед тобой три разных подхода.

Но сравни не названия, а момент, в котором оказывается агент. До вызова он подготовил предложение и показал человеку существенные детали. На вызове выполнение приостанавливается **до побочного эффекта**. Ответ человека сохраняется, после чего агент продолжает работу с этой точки и только тогда получает возможность выполнить Commit.

Это одна инженерная форма из [шага 6](#step-6), выраженная тремя словарями. `interrupt()` подчёркивает паузу, `RequestInfoEvent` — обмен информацией, `waitForApproval()` — условие продолжения. Во всех случаях требуется граница: «предложение уже можно проверить, действие ещё не совершено».

Сами эти API не гарантируют качественного надзора. Можно вызвать паузу без нужных метаданных, принять бессмысленное одобрение или после возобновления дважды выполнить эффект. Поэтому поверх точки ожидания всё равно нужны состояния из [шага 7](#step-7), защита Commit из [шага 25](#step-25) и последующая Verify из [шага 27](#step-27). API предоставляет место для ворот; надёжными ворота делает твой протокол.

> 🎒 **На пальцах.** Представь три театра. В одном режиссёр кричит «Стоп!», во втором помощник поднимает табличку «Нужно решение», в третьем пульт показывает «Ждём разрешения». Слова разные, но сцена замирает в одной точке: декорации готовы, зритель ещё ничего не увидел, а ответственный человек должен проверить постановку и разрешить продолжение.
