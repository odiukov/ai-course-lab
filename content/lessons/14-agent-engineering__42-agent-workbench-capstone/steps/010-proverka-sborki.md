check:
  - question: >-
      Ты запускаешь assemble_pack дважды с одинаковыми исходными файлами. Какой
      результат доказывает идемпотентность?
    options:
      - >-
        Оба запуска завершаются без ошибки, но второй добавляет резервные копии
        файлов
      - >-
        После обоих запусков совпадают набор относительных путей и содержимое
        каждого файла, лишних артефактов не появилось
      - >-
        Второй запуск работает быстрее первого, потому что часть файлов уже на
        месте
      - Оба запуска печатают дерево одинаковой длины
    correct: 1
    explanation: >-
      Идемпотентность подтверждает равенство самого пака: те же пути, те же
      байты и никаких накопившихся следов повторного запуска. Скорость и длина
      вывода о состоянии каталога ничего не говорят.
  - question: >-
      После второго запуска напечатано то же дерево пака, но содержимое README
      отличается от первого результата. Какой вывод верен?
    options:
      - 'Идемпотентность доказана: совпадение путей — достаточное условие'
      - 'Идемпотентность доказана: README на месте, значит сборка отработала'
      - >-
        Идемпотентность не доказана: сравнивать нужно и пути, и содержимое
        файлов
      - >-
        Идемпотентность не доказана, потому что README вообще нельзя
        перезаписывать
    correct: 2
    explanation: >-
      Совпадения имён файлов мало: результат изменился на уровне данных, значит
      пак уже не тот же самый. Перезапись README по тому же пути допустима —
      недопустимо, чтобы его содержимое отличалось при тех же входах.
---

После функции из [шага 9](#step-9) тебе нужно отличить стабильный результат от просто успешного запуска. Нулевой код выхода и одинаково напечатанное дерево ещё ничего не доказывают: внутри файл мог измениться, а рядом — накопиться копия. Проверяй снимок всего результата: набор относительных путей и байты каждого файла. При неизменных входах первый и повторный снимки должны совпасть — именно это свойство идемпотентности из [шага 8](#step-8).
