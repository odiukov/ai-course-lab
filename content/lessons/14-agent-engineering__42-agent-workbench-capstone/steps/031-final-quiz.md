  - question: >-
      В пак-кандидаты попали универсальная схема состояния, текущая задача

    options:
      - >-
        Оставить схему, вызов вендора заменить универсальным адаптером, а
        текущую задачу вынести наружу
      - 'Включить всё, иначе пак не будет готов к работе сразу'
      - 'Вынести всё, потому что пак должен содержать только документацию'
      - 'Оставить схему и текущую задачу, а вызов SDK удалить без замены'
    correct: 0
    explanation: >-
      Пак хранит переносимые контракты, а проектные данные остаются в

  - question: >-
      Ты изменил схему состояния и поправил одну инструкцию. Как подготовить
      следующий выпуск?
    options:
      - 'Поднять только патч, потому что изменён документ'
      - >-
        Поднять мажор, повторить детерминированную сборку и провести релизный
        аудит
      - 'Не менять версию, если число файлов осталось прежним'
      - Поднять мажор только после первой жалобы пользователя

    explanation: >-
      Изменение схемы ломает совместимость установленных копий и требует

      мажором, а не правкой документа. Воспроизводимая сборка и аудит
      подтверждают, что выпуск согласован целиком.
  - question: >-
      В исходном паке указана версия 4, а установочный лок репозитория хранит
      версию 2. Что должно произойти?
    options:
      - >-
        Линтер должен сообщить, что установленный слепок отстаёт, и направить к
        обновлению через установщик
      - Линтер должен молча заменить лок на версию 4
      - Исходный пак нужно откатить до версии установленной копии
      - 'Разницу можно игнорировать, если документы открываются'
    correct: 0
    explanation: >-
      Расхождение идентификаторов — признак невыполненной работы: файлы могли
      остаться прежними, а миграция не проходила. Правка лока уничтожила бы
      единственный видимый след дрейфа, поэтому значение перезаписывает только
      установщик после реальной установки.
  - question: >-
      После удаления пака в репозитории есть поставленные им скрипты и
      накопленное пользовательское состояние. Что удалить?
    options:
      - Весь каталог workbench вместе с пользовательскими данными
      - >-
        Только файлы из манифеста поставки, сохранив пользовательское состояние
        и выходные артефакты
      - 'Ничего, потому что безопасное удаление невозможно'
      - 'Только файл версии, чтобы скрыть установленный пак'
    correct: 1
    explanation: >-
      Граница удаления проходит по восстановимости: то, что установщик
      воссоздаст, убирается; то, что заново не появится, остаётся. Состояние и
      выходы принадлежат пользователю, а не дистрибутиву.

Дальше тебе пригодится не конкретное дерево файлов, а привычка связывать границу пака, версию, установочный лок и владение файлами. На проверке сверяй решения с [шагом 3](#step-3), правилами версии из [шага 11](#step-11), обнаружением дрейфа из [шага 20](#step-20) и безопасным удалением из [шага 23](#step-23). Частая ошибка — рассматривать выпуск, обновление и удаление как независимые команды: их согласованность подтверждает релизный аудит из [шага 30](#step-30).

> 🎒 **На пальцах.** Представь набор садовых инструментов по подписке. Поставщик пломбирует коробку номером выпуска, при обновлении сверяет бирку, а при возврате забирает только свои инструменты. Посаженные тобой растения остаются в саду. Если пломба и бирка расходятся, коробку не «исправляют на глаз» — её переустанавливают по описи.
