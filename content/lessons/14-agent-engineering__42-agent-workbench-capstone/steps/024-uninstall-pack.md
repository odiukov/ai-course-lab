В целевом репозитории уже появились новые записи в `agent_state.json`, задачи в `task_board.json` и результаты в `outputs/`. Теперь ты запускаешь удаление пака. Если функция начнёт стирать файлы сразу, а опасность заметит посередине, репозиторий останется наполовину разобранным.

Поэтому `uninstall_pack` сначала выполняет полную проверку и лишь затем что-либо меняет. Передай ей путь к репозиторию и флаг `keep_agents_md`. Она должна убедиться, что репозиторий существует, а защищённые файлы состояния не содержат незакоммиченных изменений. Для проверки можно получить статус Git только для этих путей. Если найдено изменение, функция прекращает работу с понятным сообщением — до первого удаления.

После успешной проверки функция удаляет только поставляемые паком пути из канонического списка, связанного с деревом из [шага 7](#step-7): документы, схемы, рантайм, установочные метаданные и созданные точки входа для агентов. Используй точные пути, а не широкие маски и не рекурсивное удаление каталогов. Каталог разрешено убрать лишь тогда, когда после удаления управляемых файлов он пуст.

С `keep_agents_md=True` файл `AGENTS.md` остаётся на месте. Остальные созданные для инструментов ссылки удаляются отдельно, причём функция должна проверять, что перед ней именно ожидаемая ссылка, а не пользовательский файл с тем же именем. Повторный запуск не считается ошибкой: отсутствующий управляемый файл уже достиг нужного состояния.

Главная граница из [шага 23](#step-23) здесь превращается в порядок действий: сначала доказать безопасность всего удаления, затем удалить только то, чем владел пак.

> 🎒 **На пальцах.** Представь арендованную теплицу на твоём участке. Рабочие могут забрать каркас, полки и свои инструменты, но не рассаду и ящики с собранными помидорами. Перед разборкой они проверяют, не привязаны ли растения к каркасу. Если привязаны — останавливаются до первого открученного болта. Флаг `keep_agents_md` похож на просьбу оставить одну полезную полку.
