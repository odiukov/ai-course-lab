Ты запускаешь установку в репозитории, где уже лежит настроенный пак. Простое копирование молча заменит файлы — вместе с чужими командами приёмки и правилами. Поэтому `install_pack(pack_dir, repo_dir, force=False)` должна сначала проверить целевой путь, а копировать только после решения, что установка безопасна.

Возьми каноническое дерево из [шага 6](#step-6) и результат `assemble_pack` из [шага 9](#step-9). Реализуй функцию по четырём этапам:

1. Определи, куда внутри `repo_dir` устанавливается пак. Если эта директория уже существует и `force` выключен, прекрати работу с понятной ошибкой. Не удаляй и не изменяй существующие файлы.
2. Если установка разрешена, перенеси в целевую директорию весь собранный пак, сохраняя относительные пути. При `force=True` старый слепок можно заменить, но результат не должен смешивать файлы двух версий.
3. Проверь наличие `.github/workflows/` в целевом репозитории. Только тогда добавь подготовленный workflow пака: отсутствие GitHub Actions — допустимая ситуация, а не ошибка.
4. После успеха верни или напечатай короткий список следующих действий: заполнить доску, задать команды приёмки и запустить init-скрипт.

Обрати внимание на порядок: сначала все проверки, затем изменения. Иначе функция может успеть скопировать половину файлов, а потом обнаружить конфликт. Для ошибок выбери один наблюдаемый контракт — например, исключение с сообщением, — чтобы вызывающий скрипт мог завершиться с ненулевым кодом.

> 🎒 **На пальцах.** Представь службу доставки, которая привезла новый холодильник. Курьер сначала проверяет, свободна ли ниша, и только потом распаковывает груз. Если там уже стоит холодильник, он не начинает разбирать его без твоего явного согласия. А после установки оставляет не коробку деталей, а записку: подключить питание, выставить температуру и дождаться первого охлаждения.
