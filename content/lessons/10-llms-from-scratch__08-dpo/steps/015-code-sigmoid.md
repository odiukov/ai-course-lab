Ты передаёшь функции значения `[-1000, 0, 1000]`. В середине всё спокойно, но на `-1000` прямое вычисление знакомой sigmoid требует получить `exp(1000)` — настолько огромное число, что компьютер может сообщить о переполнении. При этом правильный ответ должен быть просто близок к нулю.

В [шаге 14](#step-14) мы выбрали две равносильные формы sigmoid. Теперь тебе нужно перенести этот выбор в функцию `sigmoid(x)`.

Функция должна принимать отдельное число или NumPy-массив и возвращать значения той же формы в диапазоне от 0 до 1. Через `np.where` раздели элементы по условию `x >= 0`:

- для неотрицательных значений используй вариант с `exp(-x)`;
- для отрицательных — вариант с `exp(x)`.

Так в выбранной ветке экспонента получает неположительное число и не пытается создать гигантский промежуточный результат.

После реализации проверь несколько ориентиров: на нуле должно получиться ровно `0.5`, на `1000` — значение около `1`, на `-1000` — около `0`. Ещё одна полезная проверка: результаты для `1` и `-1` должны в сумме давать `1`. Если функция сохраняет порядок значений и не возвращает `nan`, переключение ветвей работает правильно.

> 🎒 **На пальцах.** Представь двусторонний вход на стадион. Зрителей слева и справа можно провести к одному сектору, но заставлять всех обходить стадион по одной стороне неудобно: путь для части людей станет огромным. Ты открываешь ближайший вход в зависимости от стороны. Формулы приводят к тому же месту — вероятности sigmoid, — но без опасного обхода через громадные числа.
