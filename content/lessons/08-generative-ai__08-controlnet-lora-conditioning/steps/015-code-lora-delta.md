Возьми две маленькие матрицы и попробуй получить поправку обычным поэлементным умножением. Сразу возникает проблема: у \(A\) две строки, а у \(B\) — три. Их элементы даже нельзя однозначно поставить друг напротив друга.

Твоя функция должна выполнить именно матричное умножение из [шага 11](#step-11): принять матрицы \(A\) и \(B\), вычислить их произведение в порядке \(B\) на \(A\) и вернуть готовую матрицу поправки. Не добавляй её к базовым весам и не применяй масштаб — здесь мы получаем только саму дельту.

Проверь функцию на таком примере:

```text
A = [[1, 0,  2],
     [0, 1, -1]]

B = [[1,  0],
     [0,  2],
     [1, -1]]
```

У \(A\) размер \(2 \times 3\), у \(B\) — \(3 \times 2\). Внутренние размеры совпадают: две строки \(A\) соответствуют двум столбцам \(B\). Поэтому результат должен иметь размер \(3 \times 3\):

```text
[[1,  0,  2],
 [0,  2, -2],
 [1, -1,  3]]
```

Обрати внимание на порядок операндов: \(A\) на \(B\) даст матрицу другого размера, а оператор поэлементного умножения вообще выполняет не ту операцию. Получившиеся девять чисел — компактно построенная поправка к девяти позициям большой матрицы.

> 🎒 **На пальцах.** Представь мастерскую мозаики. В \(A\) лежат два узких базовых узора, а каждая строка \(B\) говорит, в каких пропорциях их смешать для очередной полосы панно. Три рецепта дают три новые полосы. Ты не перемножаешь плитки, стоящие на одинаковых местах: ты собираешь каждую полосу как комбинацию готовых узоров.
