Ты запускаешь слой и получаешь странный результат: при `alpha=0` ответ всё равно отличается от базового. Значит, LoRA-поправка попала не туда — например, масштаб применила ко всему выходу, а не только к добавке.

Твоя функция `lora_forward` должна аккуратно собрать уже готовые детали. Сначала передай `W_frozen` и `x` в написанное на [шаге 13](#step-13) матрично-векторное умножение. Это базовый ответ, который нельзя менять при отключённой LoRA.

Затем тем же помощником последовательно выполни два преобразования из [шага 14](#step-14): сначала пропусти `x` через `A`, потом полученный промежуточный вектор — через `B`. Не вычисляй заранее полную матрицу `B @ A`: прямой проход может сразу использовать компактную пару матриц.

Остаётся пройти по элементам базового ответа и LoRA-поправки. Для каждого элемента прибавь поправку, предварительно умноженную на `alpha`, как разобрано на [шаге 16](#step-16). Проверь два ориентира: при `alpha=0` функция возвращает ровно базовый ответ, а при увеличении `alpha` меняется только вклад LoRA. Параметр `W_frozen` здесь используется для вычисления, но сама функция его не переписывает.

> 🎒 **На пальцах.** Представь типографию: основной тираж уже отпечатан, а к каждому экземпляру прикладывают узкую полоску с правкой. Сначала `A` записывает правку в коротком служебном формате, затем `B` разворачивает её до размера страницы. `alpha` задаёт насыщенность только этой накладки. При нулевой насыщенности перед тобой остаётся исходная печать без изменений.
