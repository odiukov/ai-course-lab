После прямого прохода функция потерь сообщает слою: «первый выход увеличь, второй уменьши». Но менять всю матрицу `W` нельзя — она заморожена. Тебе нужно распределить эту подсказку только между `A` и `B`.

Напиши функцию `lora_gradients`, которая получает `x`, матрицы `A` и `B`, масштаб `alpha` и градиент выхода `grad_y`. Она должна вернуть две матрицы: `grad_A` той же формы, что `A`, и `grad_B` той же формы, что `B`. Правило цепочки для них уже разобрано в [шаге 24](#step-24); здесь твоя задача — превратить его в вычисления с циклами.

Сначала снова вычисли промежуточный вектор `Ax`: он понадобится для градиента `B`. Каждый элемент `grad_B` связывает одну подсказку из `grad_y` с одним числом из узкого представления `Ax`. Для `grad_A` подсказку сначала нужно провести назад через `B`, а затем связать получившиеся `r` чисел с исходным входом `x`.

Следи за тремя вещами:

- размеры результатов должны точно совпасть с размерами обучаемых матриц;
- `alpha` влияет на оба градиента;
- градиент для `W` вычислять и возвращать не нужно.

Полезная проверка: если `B` заполнена нулями, первая обратная подсказка для `A` тоже получится нулевой. Это не ошибка — сигнал пока не может пройти назад через нулевую `B`. При этом `B` уже может начать изменяться благодаря ненулевым `A`, `x` и `grad_y`.

> 🎒 **На пальцах.** Представь двух переводчиков: `A` переводит длинную записку в короткий набор условных знаков, а `B` разворачивает их обратно. Редактор отмечает ошибки только в итоговом тексте. Чтобы исправить `B`, достаточно сопоставить пометки с короткими знаками. Чтобы добраться до `A`, пометки сначала приходится пропустить назад через словарь `B`. Замороженная база в этой редактуре вообще не участвует.
