Добавь продуктовый финал цикла: после того как план завершён и проверки прошли, агент получает актуальные `git status` и `git diff`, создаёт коммит, отправляет ветку `agent/$TASK_ID` и обращается к GitHub API для открытия pull request. Используй GitHub App с fine-grained token, область которого ограничена целевым репозиторием. Harness не должен использовать широкий пользовательский токен или публиковать изменения до подтверждённого успеха проверок.

Тело pull request включает итоговый план и краткую сводку diff, чтобы ревьюер видел намерение и фактические изменения. Результат команды содержит URL созданного PR, число ходов, токены, стоимость и ссылку либо идентификатор trace bundle. Сбой push или API-вызова проходит через recover и сохраняется в трассе; он не должен ошибочно помечать задачу успешной. Повторное завершение возобновлённой сессии не должно создавать несколько PR для одной ветки.

До публикации проверь, что diff относится только к task worktree и не содержит неожиданных файлов состояния или секретов. После сохранения URL и финальной трассы выполни предусмотренный cleanup песочницы. Граница этапа — реальный удалённый репозиторий и настоящий GitHub API, а не локальный commit. Типичные ошибки — PR до успешных тестов, включение `.agent`-артефактов в diff, токен с избыточными правами, потеря trace bundle при ошибке API и teardown до завершения push.
