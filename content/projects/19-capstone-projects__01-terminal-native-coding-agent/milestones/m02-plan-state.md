Определи строгую TodoWrite-схему для цели и списка пунктов со статусами `pending`, `in_progress` и `done`, а также заметками. План является самостоятельным состоянием сессии, а не текстовым фрагментом в истории сообщений. На каждом ходе модель должна возвращать полный новый объект через структурированный tool call. Harness валидирует его и атомарно заменяет предыдущую версию; частичные операции добавления или изменения пунктов запрещены, потому что они усложняют восстановление и оставляют неоднозначное состояние.

После каждого принятого переписывания сохраняй план в `.agent/state.json` внутри task worktree. Запись должна переживать падение процесса и позволять повторному запуску продолжить ту же задачу с последнего валидного состояния. Восстановление включает цель, пункты, статусы и заметки, но не должно слепо считать прерванный инструмент успешно завершённым. Покажи текущую версию в верхней панели TUI и включай её в контекст следующего модельного хода.

Граница этого этапа — управление планом и его долговечность; реализация конкретных файловых инструментов относится к следующему этапу. Используй локальный Python-эталон только для проверки формы полного переписывания и читаемого summary. Типичные ошибки — мутация отдельных пунктов, сохранение после запуска инструмента вместо принятия плана, невалидные статусы, повреждение JSON при аварии и восстановление из файла без проверки схемы.
