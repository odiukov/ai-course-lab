Создай отдельный tool dispatcher с шестью контрактами: `read_file`, `edit_file`, `ripgrep`, `tree_sitter_symbols`, `run_shell` и `git`. `edit_file` обязан показывать diff preview до применения изменения. `run_shell` получает явный timeout и возвращает код выхода вместе со stdout и stderr. Инструмент `git` ограничивается операциями status, diff, commit и push. `ripgrep` выполняет быстрый текстовый поиск, а `tree_sitter_symbols` использует подготовленные парсеры для структурного обзора кода.

Опубликуй инструменты через MCP StreamableHTTP ревизии 2026, чтобы harness зависел от схем и транспорта, а не от внутренних функций выполнения. Входы и выходы должны быть типизированы, ошибки — представлены как наблюдения, пригодные для recover-ветки. Каждый результат обрезается до эквивалента 4 тысяч токенов на вызов. Сохраняй сведения о том, что вывод был усечён, иначе модель может принять неполный результат за полный. Особенно проверь широкий `ripgrep`, большие diff и команды с интенсивным stderr.

Все пути и команды уже проектируй для исполнения внутри песочницы, хотя её создание завершается на следующем этапе. Не разрешай произвольные git-подкоманды через обход схемы. Локальные функции чтения и shell из Python-эталона задают минимальный контракт результата, но не заменяют MCP-сервер и остальные четыре инструмента. Типичные ошибки — подсчёт лимита в байтах вместо токенов без контроля фактического размера, потеря exit code, зависшая команда после timeout и diff, применённый без preview.
