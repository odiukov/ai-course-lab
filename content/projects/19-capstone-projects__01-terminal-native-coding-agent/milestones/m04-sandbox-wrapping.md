Подключи E2B через JavaScript SDK и сделай создание песочницы обязательной частью запуска задачи. Harness не должен выполнять ни чтение, ни shell, ни git непосредственно на хосте. Для каждой задачи создай уникальный идентификатор, свежую ветку `agent/$TASK_ID` и отдельный checkout через `git worktree add -b agent/$TASK_ID`. Этот worktree монтируется в песочницу read-write и становится единственным рабочим корнем для MCP-инструментов.

Все пути разрешай относительно корня worktree после канонизации. Проверки строкового префикса недостаточно, если они не учитывают переходы `..` и ссылки. Сетевые, процессные и файловые ограничения должны задаваться средой E2B и политикой harness, а не обещанием модели. Хостовая файловая система остаётся недоступной даже при ошибочном или враждебном вызове инструмента.

Определи единый cleanup-путь для успеха, ошибки, превышения бюджета и пользовательской отмены. Worktree и облачная среда должны уничтожаться во всех четырёх случаях, при этом итоговые трассы и сведения, необходимые для pull request, сохраняются до teardown. Не подменяй этот этап локальной временной директорией: цель — настоящий облачный sandbox. Типичные ошибки — выполнение подготовительных git-команд на неподходящем хостовом пути, повторное использование среды между задачами, утечка worktree после исключения и передача абсолютного пути в инструмент без проверки принадлежности рабочему корню.
