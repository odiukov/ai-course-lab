Заверши проект официальным набором `mcp-conformance-tests` из репозитория Model Context Protocol. Проверяй отдельно основной read-only сервер и destructive-сервер по их развернутым StreamableHTTP-адресам. Цель — пройти все обязательные разделы, относящиеся к транспортному протоколу и опубликованным возможностям, а не ограничиться собственными unit-тестами или демонстрацией одного `tools/call`.

Перед прогоном зафиксируй конфигурацию клиента, OAuth-доступ и адреса серверов. Сохрани полный отчёт первого запуска, классифицируй каждое падение по уровню JSON-RPC, StreamableHTTP, описанию инструментов, обработке ошибок или capability metadata, затем устраняй причины в соответствующем слое. После исправлений повторяй полный suite для обоих серверов, чтобы изменение одного контура не создало регрессию в другом. Capability-манифесты также должны оставаться согласованными с фактической поверхностью.

Не отключай обязательные проверки и не подменяй удалённый сервер локальным эталоном. Типичные ошибки — показывать только итоговую зелёную строку без команды и полного лога, тестировать один из двух серверов или помечать протокольное расхождение как ожидаемое. Дополнительные тесты OAuth, OPA, аудита и Slack нужны проекту, но не заменяют официальный suite. Финальный артефакт должен позволять проверяющему воспроизвести запуск и сопоставить результаты с конкретными развернутыми endpoint-ами.
