Tester принимает только изменения, прошедшие Reviewer. Для каждого запуска он создаёт чистую изолированную среду, получает зафиксированную staging-ветку и запускает полный набор тестов репозитория. Роль работает на Gemini 2.5 Pro как отдельный LangGraph-подграф и Kubernetes Deployment. Результатом становится `test_passed` либо `test_failed`; сообщение содержит сохранённые артефакты и, при падении, stacktrace.

Успешный результат разрешает открыть готовый к слиянию PR. Неуспешный результат возвращается кодеру, который владеет падающей подзадачей. Для этого Tester использует происхождение объединённых изменений и границы из плана, а не всегда выбирает первого работника. После исправления изменение снова проходит слияние и reviewer gate, прежде чем попасть на повторный тест.

Защити этап от гонки: тестирование начинается после окончательной фиксации одобренного состояния и не читает worktree, куда ещё пишет кодер. Артефакты должны позволять отличить настоящий дефект от flaky test, поскольку tester flake является отдельной категорией посмертного анализа. Не своди проверку к модельному предположению о корректности diff — тестовый набор действительно исполняется внутри sandbox. Типичные ошибки здесь — повторное использование загрязнённой среды, отсутствие stacktrace, запуск только тестов одной подзадачи вместо полного suite, обход повторного ревью после исправления и открытие PR по одному лишь `approved`.
