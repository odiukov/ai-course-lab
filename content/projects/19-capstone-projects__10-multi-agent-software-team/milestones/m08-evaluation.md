Зафиксируй набор из 50 задач SWE-bench Pro и прогони на каждой два режима. Первый — полная мультиагентная фабрика с архитектором, N параллельными кодерами, merge coordinator, reviewer и tester. Второй — baseline: один Claude Sonnet 4.7 выполняет ту же задачу в одном worktree. Подмножество должно быть совпадающим, иначе pass@1, стоимость и время нельзя честно сопоставить.

Для обоих режимов собирай pass@1, wall-clock, общие токены и стоимость. Основное сравнение стоимости — доллары на одну решённую задачу; сравнение скорости — реальное время выполнения относительно baseline. Не исключай неуспешные запуски из знаменателя и не заменяй SWE-bench Pro синтетическими локальными задачами. Сценарии SWE-AF и HumanEval++ остаются дополнительными частями исходного eval-стека, но не подменяют обязательные 50 issue.

Запуски должны использовать заявленные облачные модели, Daytona и развёрнутые роли. Сохраняй связь каждой строки результата с issue, trace и тестовым исходом, чтобы цифры можно было проверить. Типичные ошибки — разные задачи для режимов, последовательный запуск кодеров при измерении ускорения, учёт только успешных токенов, смешивание повторных попыток с pass@1 и сравнение локальной заглушки с облачной командой. Результатом этапа становится воспроизводимая таблица matched trials, а не один показательный пример.
