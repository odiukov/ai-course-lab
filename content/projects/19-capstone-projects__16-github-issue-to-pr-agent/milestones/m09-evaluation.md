Финальный этап превращает работающий pipeline в измеренный инженерный результат. Подготовь 30 seeded internal issues разной сложности и прогони каждую через полный внешний путь: GitHub trigger, Lambda, SQS, dispatcher, ECS Fargate, sandbox, agent loop, verification и публикацию PR либо зафиксированный отказ. Для каждого issue сохрани итоговый статус, стоимость, wall-clock latency, размер diff, style conformance и coverage delta.

Основная метрика pass rate считается по end-to-end успеху: CI зелёный и coverage соответствует gate. Качество PR оценивается по размеру diff, изменению покрытия и соблюдению стиля. Стоимость и задержка считаются на resolved issue, а safety-проверка охватывает scoped token, per-repo budget, запрет force-push и credential hygiene. Также проверь операторский UX: rationale, retry affordance и `@agent` follow-up.

На тех же issues выполни сравнение с Cursor Background Agents и AWS Remote SWE Agents. Не меняй постановку задач между инструментами и покажи, где каждый вариант выигрывает по стоимости и pass rate. Не заменяй benchmark случайной локальной симуляцией из Python-эталона: она полезна для проверки формы состояний и лимитов, но не измеряет облачную систему или hosted-конкурентов. Итогом должен стать воспроизводимый отчёт и deliverable `outputs/skill-issue-to-pr.md`, связанный с реальными issue, PR, trace и агрегированными метриками.
