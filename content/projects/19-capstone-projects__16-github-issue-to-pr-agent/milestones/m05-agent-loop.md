Подключи к подготовленной sandbox реальный цикл mini-swe-agent либо SWE-agent v2 поверх Claude Opus 4.7 или GPT-5.4-Codex. На вход агент получает issue и рабочее дерево репозитория. Для навигации предоставь tree-sitter repo-map и `ripgrep`; для действий — `read_file`, `edit_file`, `run_tests` и безопасные git-операции. Рабочий ритм должен оставаться наблюдаемым: прочитать относящийся к задаче код, сформировать исправление, применить patch, запустить тесты и при необходимости повторить цикл.

Каждый запуск имеет три жёстких предела из исходного брифа: не более $20, 30 минут wall-clock и 30 agent turns. Эти пределы исполняет harness независимо от обещаний модели. При достижении любого из них выполнение останавливается с отдельной причиной, а worker не продолжает бесконтрольно тратить ресурсы. Сохраняй ходы и стоимость в Langfuse trace, потому что они войдут в PR и итоговую оценку.

На этом этапе агент ещё не имеет права считать собственный тестовый вызов окончательной проверкой и самостоятельно публиковать PR. После его завершения управление обязательно передаётся отдельному verification gate. Не расширяй инструменты до произвольного доступа вне репозитория и не разрешай force-push. Локальный `run_agent` фиксирует форму ограниченного цикла и его исходы, но готовность означает работу выбранного agent framework и модели внутри настоящей облачной sandbox на реальном issue.
