Dispatcher — финансовая и операционная граница проекта. Он извлекает задачу из SQS, определяет репозиторий и до запуска sandbox проверяет два дневных ограничения: долларовый потолок и максимальное число PR. Также учитывай предел стоимости одной задачи — $20. Дорогая ECS Fargate task не должна стартовать, если работа уже не помещается в разрешённый бюджет репозитория.

При допуске учитывай возможный расход до полного per-task cap, а после завершения записывай фактическую стоимость и факт открытия PR. Это предотвращает ситуацию, когда несколько задач допускаются по оптимистичной оценке и вместе превышают дневной потолок. Учёт должен оставаться раздельным для каждого репозитория: активность одного проекта не расходует лимит другого. Заявленный дневной лимит числа PR равен пяти, а долларовый потолок задаётся политикой dispatcher.

Для разрешённой работы запусти отдельную ECS Fargate task и передай ей repo URL, issue body и данные для создания свежей Daytona sandbox. Для запрещённой работы сохрани явную причину отказа и не переходи к agent loop. Не переноси проверку бюджета внутрь модели или в конец запуска: к этому моменту расходы уже возникнут. Локальные `BudgetLedger` и `dispatch` задают проверяемый архитектурный шов, но результат этапа — действительный запуск Fargate из очереди и действительный отказ при исчерпанном лимите.
