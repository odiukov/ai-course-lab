Проведи credential hygiene через весь жизненный цикл worker. Каждая Fargate task должна получать короткоживущий GitHub App installation token для конкретного репозитория и использовать его только для разрешённых GitHub-операций. Постоянный пользовательский token не должен становиться частью sandbox, конфигурации агента или архивируемого trace. Истечение token обязано прекращать операцию публикации, а не обходиться повторным использованием старого credential.

Перед архивированием scrubber обрабатывает логи agent loop, вывод инструментов, тестов и git-команд. Его задача — удалить секреты до отправки данных в Langfuse и до появления ссылки на trace в публичном или командном PR. Проверь путь данных целиком: значение может попасть в вывод команды или сообщение об ошибке, даже если ты не печатаешь token намеренно. При этом очищенный trace должен сохранять полезные сведения о ходе, стоимости, тестах и причине завершения.

Не ограничивайся маскированием token в интерфейсе PR: к этому моменту необработанный лог уже мог оказаться в архиве. Не полагайся только на prompt, запрещающий модели читать credentials; контроль выполняется инфраструктурой worker и обработчиком логов. Этот этап не расширяет permissions приложения и не отменяет branch protection или проверку diff — все защитные слои работают совместно. Готовность подтверждается реальным облачным прогоном с безопасно подставленным тестовым секретом и проверкой сохранённого Langfuse trace.
