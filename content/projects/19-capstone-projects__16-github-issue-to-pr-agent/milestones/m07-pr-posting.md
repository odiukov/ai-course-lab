После разрешающего вердикта verification worker пушит только агентскую ветку и открывает PR через GitHub App. Сформируй заголовок и обязательное тело PR из результатов запуска. В нём должны находиться rationale — что было исправлено и почему, сводка diff, ссылка на Langfuse trace, итоговая стоимость и число agent turns. Это не служебный дамп рассуждений, а компактный материал для оператора, который должен понять изменение до чтения каждой строки diff.

Если coverage delta упал более чем на 2%, добавь `needs-review` согласно решению предыдущего gate. Красный CI не должен доходить до этого этапа вообще. Перед push повторно примени политику разрешённых путей и GitHub-операций: никаких изменений `.github/workflows`, прямой записи в `main` или force-push. Открытие PR выполняется только действующим installation token.

Сохрани связь PR с исходным issue и поддержи предусмотренный операторский цикл: ревьюер может обратиться к агенту через `@agent` для follow-up. Не считай обычный commit или удалённую ветку готовым результатом — capstone требует review-ready PR с объяснением. Не публикуй PR до полного CI ради красивой демонстрации. Локальный `open_pr` отражает финальный safety check, однако этап подтверждается реальным PR в GitHub, созданным приложением после облачного прогона.
