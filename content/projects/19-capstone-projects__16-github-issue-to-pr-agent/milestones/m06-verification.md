Verification — отдельная обязательная стадия, которой нельзя доверять агенту как части его рассуждения. После завершения agent loop заново запусти полный набор CI-проверок репозитория внутри той же изолированной sandbox. Если CI остаётся красным, останови workflow и не открывай PR. Сохрани в trace команду, статус и причину отказа, чтобы оператор мог отличить неверное исправление от нестабильного теста.

Затем вычисли покрытие для базовой ветки и агентской ветки подходящим инструментом: `coverage.py` для Python либо jacoco там, где он используется. Рассчитай coverage delta как изменение процента покрытия относительно базы. Падение более чем на 2% не запрещает открыть PR, но такой PR обязан получить метку `needs-review`. При меньшем падении или росте покрытия проверка считается пройденной без этого специального основания для маркировки.

Не проверяй только тест, добавленный агентом, и не принимай частичный набор за полный CI: критерий capstone — end-to-end зелёный результат. Одновременно не превращай нестабильность в скрытый успех; flaky failure должен быть виден как отдельный исход запуска. Локальная функция `run_verify` показывает границу решения, но доказательство требует реального CI в облачной sandbox и настоящего отчёта покрытия. Этап заканчивается структурированным вердиктом, который однозначно разрешает публикацию, запрещает её или требует `needs-review` из-за coverage regression.
