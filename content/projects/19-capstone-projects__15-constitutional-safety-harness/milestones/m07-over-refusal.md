Безопасность нельзя оценивать только долей заблокированных атак: контур может получить высокий block rate, отказывая всем подряд. Подключи XSTest как отдельный benign prompt suite и прогоняй его через тот же внешний интерфейс, те же rails, классификаторы и версию модели, которые использовались в adversarial evaluation. Для каждого benign запроса сохрани итог ответа и слой, вызвавший отказ, если он произошёл.

Рассчитай false-positive rate и benign pass rate, затем сопоставь их с attack block rate. Такое сравнение показывает реальный trade-off между безопасностью и полезностью. Повтори измерение для конфигураций, которые сравниваются в проекте, включая состояние после конституционного SFT, чтобы изменение harmlessness не скрывало регрессию полезности. Не изменяй политику между adversarial и benign прогонами без явной фиксации конфигурации.

Локальный список банковских вопросов демонстрирует только форму вычисления доли отказов. Он не заменяет XSTest и не даёт достаточного benchmark результата. Типичная ошибка — считать любой осторожный ответ блокировкой либо, наоборот, считать формальный отказ полезным ответом; используй единое правило оценки для всего suite. Заверши этап отчётом, где видны решения по примерам, агрегированный false-positive rate и связь каждого ошибочного отказа с конкретным защитным слоем.
