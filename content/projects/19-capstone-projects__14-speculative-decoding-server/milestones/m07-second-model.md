Добавь вторую целевую модель — Qwen3-Coder-30B MoE — и повтори для неё тот же pipeline: подготовку и размещение target, подключение согласованного draft, baseline, EAGLE-3, P-EAGLE и раздельные traffic-прогоны. Сохрани общую методику, чтобы результат можно было сопоставить с Llama 3.3 70B, но используй draft, действительно предназначенный для Qwen, а не артефакт первой модели.

Особое внимание удели MoE-маршрутизации. Шум выбора экспертов способен усложнить согласование draft с target, поэтому acceptance rate необходимо рассматривать рядом с throughput и p99. Зафиксируй, где поведение Qwen отличается от Llama и какие наблюдения подтверждают связь с более сложным draft для MoE. Не превращай это объяснение в предположение без метрик.

Инварианты — одинаковые benchmark-наборы и определения метрик, отдельные baseline для каждой модели, сопоставимые параметры качества и корректная пара target/draft. Нельзя использовать baseline Llama как знаменатель ускорения Qwen. Типичные ошибки: сравнивать абсолютный throughput моделей как speedup speculation, скрывать отличия аппаратного размещения, использовать несовместимый draft и сводить результаты всех доменов в один acceptance rate.

Этап считается завершённым только после реального GPU-прогона. Локальный scheduler не воспроизводит MoE routing, стоимость экспертов или согласование скрытых состояний и потому не может подтвердить результат. После этого этапа требование ускорения 2,5x+ при сопоставимом качестве должно оцениваться уже для обеих целевых моделей.
