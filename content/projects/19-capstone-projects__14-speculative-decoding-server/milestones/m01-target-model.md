Начни с полноценного target-сервиса без спекулятивного декодирования. Подготовь веса Llama 3.3 70B, выполни FP8-квантизацию через Marlin и зафиксируй, какой вариант размещения используешь: один H100 или два GPU, объединённых tensor parallelism. Результатом этапа должен быть доступный inference endpoint vLLM 0.7, а не локальная имитация модели.

Сначала проверь совместимость формата весов, токенизатора и конфигурации модели. Затем определи параметры размещения, достаточные для загрузки весов и выполнения запросов в целевых batch size. Если выбран tensor parallelism, обе части модели должны стартовать как один логический сервер и корректно использовать назначенные GPU. Сохрани фактическую команду запуска и YAML-конфигурацию: дальнейшие режимы baseline, EAGLE-3 и P-EAGLE должны отличаться только осознанными настройками speculation.

Инвариант этапа — ответы генерирует именно Llama 3.3 70B FP8, обслуживаемая vLLM, а не уменьшенная локальная модель. Не подменяй проверку успешной загрузкой процесса: отправь реальный запрос, дождись потокового ответа и проверь метрики GPU. Типичные ошибки — несовместимый quantized checkpoint, неверное число tensor-parallel shard, нехватка памяти из-за параметров serving и незаметный запуск другой ревизии модели.

Локальный Python scaffold можно использовать только для понимания границы target scheduler. Он не подтверждает загрузку весов, работу Marlin, распределение по GPU или готовность облачного endpoint.
