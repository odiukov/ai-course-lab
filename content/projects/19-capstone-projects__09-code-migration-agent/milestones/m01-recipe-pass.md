Начни с воспроизводимого детерминированного слоя для обоих предусмотренных направлений миграции: Java 8 → Java 17 и Python 2 → Python 3.12. Для Java организуй запуск OpenRewrite, для Python — libcst. Этот этап должен выполняться над настоящей веткой репозитория и завершаться до первого модельного исправления. Его задача — забрать безопасную механическую работу: изменения импортов и сигнатур, замены устаревших API, преобразования ресурсов и другие случаи, покрываемые выбранными рецептами.

Сохраняй результат отдельным коммитом с ролью `recipe`. В журнале запуска перечисляй применившиеся рецепты и число преобразований, а diff делай доступным для последующего аудита. Это принципиальная граница проекта: в итоговой аналитике должно быть возможно установить, какие изменения создал детерминированный инструмент, а какие позднее написал агент. Не смешивай оба источника изменений в одном коммите и не разрешай модели заранее переписывать файлы.

Обрабатывай отсутствие подходящих преобразований как допустимый результат, а ошибки самого recipe engine — как диагностируемый сбой, сохраняющий журнал и текущее состояние ветки. Типичная ошибка этапа — считать успешный запуск рецептов успешной миграцией. Здесь ещё не доказывается ни сборка, ни прохождение тестов: этап лишь создаёт безопасную, быструю и повторяемую исходную точку для следующих проверок.
