Заверши проект настоящим прогоном по 50-репозиторному подмножеству Amazon MigrationBench для перехода Java 8 → Java 17. Для корректного сравнения каждый репозиторий должен пройти два режима: OpenRewrite-only baseline без агентного слоя и полный двухслойный конвейер. Используй одинаковые цели миграции и критерии зелёной сборки, тестов и покрытия, чтобы разница отражала вклад агента, а не разные условия эксперимента.

Для полного прогона собери pass@1, среднюю дельту покрытия относительно базовых веток, стоимость одного успешно мигрированного репозитория и долю исправлений, выполненных OpenRewrite и агентом. Агрегируй количества по классам отказов и свяжи категории с показательными diff. Отдельно выдели случаи, где детерминированный baseline не прошёл, а полный конвейер открыл успешный PR: именно они показывают практическую ценность агентного слоя.

Публикуй результаты на дашборде и в итоговом материале `outputs/skill-migration-agent.md`. Не заменяй benchmark синтетической выборкой из локального эталона и не исключай неудобные репозитории после запуска. Не смешивай стоимость неуспешных попыток с метрикой стоимости на passing runs. Типичные ошибки — сообщить только общий pass rate, потерять связь агрегатов с исходными трассами или сравнить режимы на разных наборах. Итог должен позволять независимо проверить числитель и знаменатель каждой метрики.
