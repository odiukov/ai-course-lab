После того как сборка стала зелёной, запусти полный тестовый набор в Daytona sandbox. Для Java собирай покрытие через JaCoCo, для Python — через coverage.py. Сначала тебе нужна сопоставимая базовая величина исходного репозитория, затем результат мигрированной ветки. Вычисляй изменение в процентных пунктах и сохраняй оба значения вместе с командами и журналами тестов.

Шлюз пропускает ветку дальше только при полном прохождении тестов и допустимом изменении покрытия. Если итоговое покрытие упало более чем на два процентных пункта относительно базы, заверши запуск классом `coverage_regression`. Такое падение нельзя скрывать зелёной сборкой или общим успехом тестового процесса. Если сами тесты падают, ветка также не считается готовой: диагностика должна вернуться в предусмотренный агентный цикл либо завершиться соответствующим неуспешным исходом в пределах бюджета.

Сравнивай одинаково определённые показатели, полученные реальными инструментами проекта. Не подменяй покрытие числом прошедших тестов и не используй случайные значения локального эталона как результат проекта. Сохраняй доказательства так, чтобы среднее изменение покрытия позднее можно было рассчитать по всему benchmark. Типичные ошибки — измерить только мигрированную ветку, перепутать проценты с процентными пунктами, разрешить PR при неполном тестовом прогоне или классифицировать допустимое снижение ровно в два пункта как нарушение порога.
