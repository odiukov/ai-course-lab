Начни с входного контура реального корпуса, а не с заранее подготовленного демонстрационного списка сцен. Команда или API должны принимать YouTube URL и локальные MP4. Загруженный либо переданный файл становится устойчивым входом дальнейшего облачного конвейера: присвой ему `video_id`, сохрани фактический путь и передай эту запись следующим стадиям. Если исходное разрешение выше необходимого, подготовь версию 720p; не заменяй оригинальную длительность коротким фрагментом ради удобства локального запуска.

Раздели получение источника и последующую обработку. На этом этапе не нужно выполнять сегментацию, распознавание речи или индексацию, однако выход должен быть пригоден для каждого из этих потребителей. Для URL сохрани достаточно информации, чтобы связать полученный файл с исходным видео. Для загруженного MP4 проверь, что конвейер работает с реальным файлом, а не только с URL. Ошибка загрузки или преобразования не должна создавать запись, которая выглядит готовой к дальнейшему ingest.

Сохраняй именно контракт `{video_id, file_path}` и проверяй доступность результирующего файла перед передачей дальше. Типичные ошибки здесь — считать URL локальным путём, потерять соответствие между исходником и преобразованной копией, начать обработку до завершения загрузки или незаметно обрезать видео. Масштаб проекта остаётся прежним: этот walker должен обслуживать корпус в 100 часов, даже если первый внешний прогон выполняется на одном полном видео.
