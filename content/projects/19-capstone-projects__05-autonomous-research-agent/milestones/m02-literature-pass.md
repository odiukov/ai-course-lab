Подключи настоящий литературный контур к Semantic Scholar Graph API и OpenAlex. Для заданной области сформируй запросы, объедини результаты и выбери 50 наиболее цитируемых релевантных работ. Сохраняй происхождение каждой записи, чтобы позже можно было объяснить, откуда взялись название, аннотация и библиографические данные. Аннотации должны попасть в локальный FAISS-кэш, который будет доступен планировщику и функции оценки новизны на протяжении всего прогона.

На основе корпуса подготовь одностраничный domain digest. Он должен обозначить основные линии работ, употребимые baseline, известные абляции и свободное пространство для seed-гипотезы. Digest не заменяет корпус: агенту нужны как краткая карта области, так и возможность находить ближайшие аннотации для конкретного экспериментального узла. Свяжи идентификаторы записей в кэше с исходными API-ответами, чтобы выводы о новизне оставались проверяемыми.

Продумай повторный запуск. Кэш должен исключать ненужные повторные запросы, но не смешивать документы из другой предметной области. Обрабатывай неполные аннотации и дубликаты так, чтобы итоговый набор действительно содержал 50 работ, а не 50 повторяющихся записей. Не подменяй реальные API заранее составленным локальным списком и не объявляй близость в embedding-пространстве доказательством научной новизны: это только эвристика, штрафующая гипотезы, слишком похожие на найденные работы.
