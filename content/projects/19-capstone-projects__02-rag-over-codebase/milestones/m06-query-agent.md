Собери query agent из трёх явно наблюдаемых узлов LangGraph. `retrieve` параллельно запускает плотный поиск и BM25, получает кандидатов обеих модальностей и дедуплицирует их по `(repo, path, symbol)`. Используй граф символов для релевантного расширения через импорты, вызовы и наследование, особенно когда ответ требует перехода между репозиториями. Объединённый набор не должен терять provenance: у каждого кандидата сохраняются источник поиска, score и anchor.

Узел `rerank` передаёт top-50 пар запрос–кандидат в Cohere rerank-3 либо самостоятельно размещённый bge-reranker-v2-gemma-2b и оставляет top-10. Локальные `rrf` и `rerank` задают проверяемую форму слияния и второго ранга, но промышленная реализация должна использовать реальные индексы и cross-encoder. Не сравнивай несопоставимые raw scores плотного и BM25-поиска как одну шкалу.

Узел `synth` формирует контекст из переранжированных chunks и вызывает Claude Sonnet 4.7 с контекстом 1M. Повторяемый системный префикс должен использовать prompt caching, а инструкция — требовать ссылки `repo/path:start-end` для каждого утверждения. TypeScript API возвращает ответ, цитаты и данные, необходимые UI для превью. Запиши Langfuse spans для retrieval, reranking и synthesis. Типичные ошибки — последовательный запуск индексов, top-k до объединения, потеря межрепозиторных результатов, синтез из непереранжированных chunks и отсутствие связи latency с конкретным этапом.
