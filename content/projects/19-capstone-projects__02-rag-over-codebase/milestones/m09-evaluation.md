Сформируй набор из 100 вручную размеченных межрепозиторных вопросов с эталонными файлами и диапазонами строк. Вопросы должны требовать поиска по реальной fleet, включая случаи, где правильный ответ связывает несколько репозиториев. Отдели held-out набор от примеров, которыми ты настраивал веса, prompts и параметры retrieval, чтобы итоговые значения не отражали подгонку.

Для retrieval вычисли MRR@10 и nDCG@10 по переранжированному списку. Для ответа измерь citation faithfulness как долю утверждений, чьи anchors можно проверить чтением указанного span. Для эксплуатационной части собери p50 и p99 query latency, а также время от git push до поисковой доступности изменений. Рубрика дополнительно оценивает p95 при 10k QPS на индексированном размере корпуса, поэтому нагрузочный прогон должен охватывать эту точку, не уменьшая корпус до локального sample.

Сохраняй результаты с конфигурацией embedding-модели, reranker, индексов и ревизией корпуса, иначе сравнение вариантов будет невоспроизводимым. Покажи ошибки по отдельным вопросам: потерянный gold chunk, неверный порядок, неподтверждённый тезис или устаревший индекс. Не заменяй benchmark несколькими красивыми запросами и не считай наличие любой цитаты доказательством faithfulness. Итоговый отчёт должен позволять проверить все пять критериев Ship It: retrieval quality, citation faithfulness, latency and scale, incremental correctness и UX выдачи.
