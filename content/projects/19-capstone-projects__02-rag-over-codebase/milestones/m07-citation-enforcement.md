Помести после `synth` отдельный слой проверки, а не полагайся только на инструкцию модели. Разбери ответ на утверждения и связанные ссылки формата `(repo/path:start-end)`. Каждая ссылка должна разрешаться в индексируемый репозиторий, существующий файл текущей ревизии и диапазон строк, который действительно был передан синтезатору. Утверждение без anchor помечается для повторного запроса или удаляется; пользователю возвращается только cited-only версия ответа.

Проверка должна различать наличие синтаксически похожей ссылки и содержательную подтверждаемость. Рассчитай citation faithfulness как долю утверждений с проверяемыми anchors и сохрани результат рядом с Langfuse trace. Не разрешай модели ссылаться на произвольный путь вне retrieved context и не исправляй выдуманные номера строк догадкой. При повторном запросе передай модели конкретный список неподтверждённых утверждений и допустимых фрагментов, сохраняя исходный вопрос.

Интегрируй результат с TypeScript API и UI: цитата должна быть кликабельной, открывать превью соответствующего span и явно показывать репозиторий. Локальная функция `answer` демонстрирует форму выдачи anchors, но не проверяет фактическую поддержку тезисов и потому остаётся только контрактом. Типичные ошибки — одна ссылка на целый абзац с несколькими независимыми тезисами, доверие к несуществующему диапазону, подсчёт faithfulness по числу ссылок вместо утверждений и возврат непроверенного первоначального ответа после неудачного re-ask.
