Свяжи git webhook со всеми индексами через diff на уровне символов. Сначала определи изменённые файлы между ревизиями, затем повторно разбери их и сравни прежние и новые chunks. Повторная суммаризация и embedding разрешены только для символов, текст которых изменился. Неизменённые функции в затронутом файле должны сохранить существующие представления. Добавленные символы создаются, удалённые очищаются из плотного, BM25- и графового слоёв, а переименования не должны оставлять активную старую запись.

Отдельно сравни импорты и структурные связи. Рёбра symbol graph пересчитываются для chunks, чьи импорты или разрешаемые вызовы изменились, без полного обхода 2 млн строк. Обновление разных хранилищ должно приводить систему к одной ревизии: пользователь не должен получать новый dense hit со старым BM25-документом или удалённым графовым соседом. Зафиксируй состояние push и возможность безопасно повторить доставку без дубликатов.

Целевой внешний сценарий — commit, изменяющий 50 файлов в индексируемой fleet. Измеряй wall-clock от git push до момента, когда новые символы доступны запросу; требование исходного брифа — менее 60 секунд. Проверь не только скорость, но и корректность: изменённый код находится, удалённый исчезает, неизменённый не получает новый embedding. Типичные ошибки — diff только по файлам, полная переиндексация затронутого репозитория, преждевременная публикация частичного состояния и измерение времени локального scaffold вместо реального облачного контура.
