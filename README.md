# ai-course-lab

Локальная платформа для прохождения курса ai-engineering-from-scratch: теория
мелкими шагами, интерактивные визуализации, чат в контексте шага, уточнения,
которые остаются в теории навсегда, редактор с упражнениями и тестами,
замером и разбором кода, квизы и прогресс в SQLite.

## Запуск

```bash
cp .env.example .env.local   # прописать COURSE_REPO — только для импорта
npm install
npm run import -- 01-math-foundations__02-vectors-matrices-operations
npm run dev                  # поднимает Next.js и мост pyright
```

Нужны локально установленные и залогиненные `claude` и `codex` — без них не
работают генерация шагов, чат и разбор кода после тестов; API-ключи не
используются. `python3` с `pytest` нужен для прогона тестов и замера.
`pyright` ставится как devDependency вместе с `npm install`, отдельно ничего
делать не надо. `uvx` с `ruff` необязателен — без него замер просто не
покажет находок линтера.

Если `python`, `pytest` или мост pyright недоступны, на шагах практики
появляется плашка с тем, что именно сломано — проверка идёт один раз при
открытии страницы. Недоступность `claude`/`codex` так не показывается:
ошибка «агент не найден» всплывает только в момент попытки — в чате, в
генерации следующих шагов или в разборе кода после тестов.

Уроки переезжают в `source/` по одному, командой `npm run import`. Уже
импортированные уроки читаются без `COURSE_REPO`.

## Что где

- `source/` — материалы импортированных уроков, правятся руками
- `source/learning-exercises/<slug>/exercise.py` — твой код, единственная
  правда для тестов и замера
- `content/lessons/<slug>/steps/` — сгенерированные шаги, лежат в git
- `content/lessons/<slug>/clarifications/` — ответы из чата, оставленные в теории
- `data/progress.db` — прогресс, чаты, прогоны тестов и попытки квиза; в git не лежит
- `src/lib/source` — чтение и импорт материалов урока
- `src/lib/content` — файлы шагов, планы уроков, слой уточнений
- `src/lib/exercise` — файл упражнения: чтение, запись, границы функций, вставка кода из recall
- `src/lib/practice` — прогон pytest, вопросы check/quiz, проверка инструментов
- `src/lib/lsp` — кадры, клиент и перевод ответов pyright в понятия Monaco
- `src/lib/agent` — запуск CLI-агентов и разбор их вывода
- `src/lib/generate` — генерация плана, тел шагов, ответов чата и разбора кода
- `src/lib/progress` — SQLite: состояние шагов, чаты, прогоны тестов и попытки квиза
- `scripts/lsp-bridge.mts` — мост WebSocket ⟷ pyright-langserver (порт
  `LSP_PORT`); `npm run dev:lsp` поднимает его отдельно, `npm run lsp:probe`
  проверяет его без браузера
- `scripts/bench.py` — замер `exercise.py` против `solution.py`, печатает
  JSON, рядом гоняет ruff через `uvx`
- `prompts/` — четыре промпта (план урока, тело шага, чат, разбор кода),
  правятся без пересборки
- `supabase/schema.sql` — схема облачного прогресса статического сайта,
  накатывается руками через SQL Editor в консоли Supabase

## Как это работает

- Позиция в уроке — в адресе (`/lesson/<slug>?step=N`). База отвечает на вопрос
  «куда открыть» только когда параметра в адресе нет.
- Шаг теории считается прочитанным в момент нажатия «Дальше» на нём (у последнего
  шага — «Закончить урок»). Ни таймеров, ни эвристик.
- Код правится в браузере и сохраняется на диск через секунду после последнего
  нажатия; правка того же файла в IDE подтягивается обратно за пару секунд.
- Кнопка Run гоняет `pytest -k <функция>` — только тесты текущего шага. Если
  фильтр не выбрал ни одного теста, гоняется весь файл и об этом пишется прямо.
- Зелёные тесты открывают замер против `solution.py` и разбор кода агентом.
  Разбор остаётся в чате шага навсегда, как и уточнения.
- Шаг становится `passed` от зелёных тестов или от полностью верного набора
  вопросов `check`/`quiz`; `failed` — от красного прогона или неверного ответа.
  Полоска урока на главном экране считает `read` и `passed`.
- Правильные ответы итогового квиза (`quiz.json`) живут только на сервере и не
  приезжают в браузер до ответа. У вопросов `check` правильный ответ едет
  вместе с шагом — они проверяют понимание внутри уже пройденного материала,
  а не защищены от подсказки; так решено осознанно.
- Уточнение всегда принадлежит тому шагу, на котором задан вопрос, и дописывается
  в `clarifications/<step-id>.md`. Текст шага не меняется никогда.
- В промпт следующих шагов уходит дайджест: до 12 вопросов и одно последнее
  уточнение целиком. Урок с сорока уточнениями не раздувает промпт.
- Одновременно работает ровно один агент: чат, генерация и разбор кода после
  тестов стоят в общей очереди.
- Агенту физически нечем тронуть курс: `claude` запускается с `--tools ""` и
  `--strict-mcp-config`, `codex` — с выключенными `shell_tool`, `browser_use` и
  `computer_use` и песочницей только на чтение.

## Аккаунты на опубликованном сайте

Опубликованная статика умеет вход через GitHub и хранит прогресс в Supabase:
прочитанные шаги, состояние практики и текст упражнений. Без входа всё
работает как раньше — прогресс живёт в `localStorage` этого браузера.

При первом входе прогресс из браузера вливается в аккаунт, а не заменяется
облачным: прочитанные шаги объединяются, `passed` не сбрасывается в `failed`,
а разошедшийся код упражнения уступает облачному с сохранением копии в ключе
`:local-backup`.

Сборка с входом требует `SUPABASE_URL` и `SUPABASE_ANON_KEY` — публичный ключ проекта. Эти переменные можно прописать в окружении или в `.env.local`; с `.env.local` на месте `npm run site:build` подхватывает их автоматически. Без них сайт собирается без кнопки входа. Схема базы — `supabase/schema.sql`, накатывается руками через SQL Editor.

## Ограничения текущего среза

- Сгенерированные шаги уроков пока не несут вопросов `check` во фронтматтере
  ни на одном шаге: вопросный UI умеет спрашивать и проверять ответ, но
  раскрывать ему пока нечего — вопросы появятся только после перегенерации
  шагов урока.
- Вопросы итогового квиза приезжают из `quiz.json` по-английски и не переводятся.
- «Перейти к определению» и «переименовать» в редакторе не подключены: клиент LSP
  тонкий и умеет ровно автокомплит, hover, подсказку аргументов и ошибки.
- Уточнение нельзя перенести на другой шаг из интерфейса — только правкой файла.
- Подбор визуализаций по номеру урока корректен только для первой фазы.
- Импорт урока — командой в терминале; кнопки в интерфейсе нет.
- Генерация новых визуализаций агентом, ремоушен-видео, экспорт в `LEARNING.md`,
  интервальные повторения и поиск по курсу — вне этого среза.
